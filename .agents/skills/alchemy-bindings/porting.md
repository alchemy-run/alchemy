# A binding generator for another provider

Every provider's bindings come from the same loop, so every provider's
generator keeps the same contract. Port `scripts/generate-gcp-bindings.ts`
to `scripts/generate-<cloud>-bindings.ts`; change only what the cloud's
spec and permission model force.

## The contract

**Inputs.**

- the distilled service modules, `submodules/distilled/packages/<cloud>/src/services/*.ts`,
  and whatever spec distilled built them from (GCP discovery docs, AWS
  Smithy models, Cloudflare's converted Smithy models);
- `packages/<cloud>/bindings/<Service>.json`, one per service, holding
  only what can't be derived: which resource each operation targets, the
  permission it checks, the grant, the name, and skips with reasons;
- shared lookup tables in `packages/<cloud>/bindings/` (`roles.json` on
  GCP), each generated by a flag on the generator, never by hand.

**Outputs**, all starting with
`// @generated by scripts/generate-<cloud>-bindings.ts from packages/<cloud>/bindings/<Service>.json. Do not edit.`:

- `packages/<cloud>/src/<Service>/<Op>.ts` per binding: the
  `Binding.Service` contract, its `<Op>Http` layer, JSDoc naming the
  grant, `@binding` / `@layer` / `@provides` tags;
- `packages/<cloud>/src/<Service>/generated.ts`, the barrel, re-exported
  once from the service `index.ts`;
- with `probes`, `packages/integration-tests/test/<Cloud>/<Service>/Generated.test.ts`
  and its host fixture.

It deletes generated files whose operation no longer generates, refuses
to overwrite a hand-written file, and formats what it writes.

**Classification.** Every operation in every configured service is
exactly one of `binding`, `lifecycle`, `covered`, `internal`, `skip`,
`project`, or `needs-permission` (SKILL.md, Commands). An operation a
hand-written binding already calls is `covered`: detect it by the
file's distilled imports, counting only files with an `@provides`
layer or `*Http.ts` scaffolding.

**Flags.** `--report <Svc>`, `<Svc>…`, no argument for everything,
`--changes`, `--check`, plus a refresh flag per lookup table. Same
meanings as GCP, so the skill's loops work unchanged. Add a
`<cloud>:bindings:check` script to the root `package.json` and run it in
CI.

**Generated layers are one call.** Put everything shared in the
service's unexported `BindingHttp.ts` (or the provider's `HttpBinding.ts`)
so a generated layer is data:

```ts
export const SendMessageHttp = Layer.effect(
  SendMessage,
  makeQueueUrlHttpBinding({
    tag: "AWS.SQS.SendMessage",
    operation: sqs.sendMessage,
    actions: ["sqs:SendMessage"],
  }),
);
```

## What changes per cloud

| | GCP | AWS | Cloudflare |
| --- | --- | --- | --- |
| Operation source | discovery doc methods | Smithy operations in distilled's AWS models | Smithy operations in distilled's Cloudflare models |
| Target resource | the method's `name` pattern matched against `resources.*.pattern` | the request member carrying the resource's identity (`QueueUrl`, `TableName`, `Bucket`) mapped to the resource attribute that fills it (`queue.queueUrl`) | path parameters (`account_id`, `zone_id`, `bucket_name`) mapped to resource attributes |
| Permission | `<service>.<collection>.<verb>`, overrides in `permissions` | IAM action `<prefix>:<Operation>` (prefix from the sigv4 signing name, as `scripts/generate-iam-actions.ts` derives it), on the resource ARN attribute | the API token permission group for the operation |
| Grant | smallest role from `roles.json` on the resource's IAM policy | a policy statement on the bound resource's ARN | a scoped `AccountApiToken` (the existing `*Http.ts` scaffolding) |
| Existing bindings | all generated | 2,091 generated (`scripts/generate-aws-bindings.ts`); the rest hand-written | hand-written; native Worker bindings (`*Binding`) stay hand-written |
| Least-privilege data | `roles.json` from `gcloud iam roles list` | each distilled operation's `iam`, from AWS's Service Authorization Reference in the spec mirror, corrected by distilled patches | none yet |

The config keys follow from the table. AWS's (`packages/aws/bindings/<Service>.json`)
keep each service's hand-written builders in `BindingHttp.ts` as the
protocol: a binding names its `operation`, bound `resource`, `request`
shape (`mode`, `omit`, `interface`), `builder`, and builder options
(`with` for literals, `withTs` plus `imports` for expressions). Builders
declare where they grant (`grants: "resource" | "*"`) and whether they take
`arns`. The config holds no grants: the actions and ARNs come from the
distilled operation's `iam` (SKILL.md, loop D). Docs live in
`<Service>.md`, one `## <Binding>` section each.

Put a cloud's permission data in its distilled SDK, not in the bindings:
mirror the provider's own description of what each operation needs (AWS's
Service Authorization Reference, GCP's IAM permissions) into the spec
mirror, join it to the operations at codegen, and correct it with patches.

## Porting a provider with hand-written bindings

1. Fold split pairs first:
   `node scripts/codemods/merge-binding-http.ts packages/<cloud>/src`.
   It moves each `<Op>Http.ts` layer into `<Op>.ts`, rewrites imports
   across the repo, and reports cycles it exposes (a scaffold importing a
   value from a merged contract: move the value into a `<X>Types.ts`).
   Type-check and run the service suites before going on.
2. Write the generator and configs so they **reproduce** the existing
   bindings (AWS's configs were derived from the code by a one-time
   extraction, then checked by comparing every regenerated file with the
   hand-written one after normalizing whitespace, comments, and import
   style: 2,091 identical). Run it on a service, and read `git diff`: every difference
   is either a config gap (fix the config) or a hand-written improvement
   the generator can't express (leave that binding hand-written; it
   becomes `covered`). Delete a hand-written binding only when the
   generated one is identical in contract, grant, and behaviour.
3. Then generate the bindings that don't exist yet, and run loops B and C
   from SKILL.md as for GCP.
4. Keep the binding's public surface stable: same tag, same export
   names, same request type. A generated binding that would rename an
   export gets a `names` override instead.
