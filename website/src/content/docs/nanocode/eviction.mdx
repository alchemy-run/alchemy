---
title: Surviving eviction
description: A Durable Object can be evicted or redeployed at any time. nanocode journals every step of a turn in the object's SQLite, and a submitted prompt is continued from the object's alarm.
---

Cloudflare can stop a Durable Object instance at any time: when it has been idle, on a deploy, or when it moves the object. What is in memory is lost. What the object wrote to its storage is kept, and its alarm still fires.

## The journal is kept

nanocode writes every model call and tool call of a turn to the object's SQLite as it happens. A new instance opens the same session and finds every finished turn, and any turn that was left part way.

## A prompt that is cut off

`session.prompt` runs inside the request that called it. If the instance stops while it is running, the request fails. The turn is still in the journal, and the session's next call finishes it first.

## Submit a prompt instead

`session.submit` records the prompt, arms the object's alarm, and returns. The turn runs in the background:

```typescript title="src/Sessions.ts"
return Effect.gen(function* () {
  return {
    start: (name: string, text: string, requestId: string) =>
      harness.session(name).submit(text, { requestId }).pipe(Effect.orDie),
    result: (name: string, requestId: string) =>
      harness.session(name).submitted(requestId).pipe(Effect.orDie),
  };
});
```

`submitted` returns `{ status: "running" }`, `{ status: "done", message }` or `{ status: "failed", message }`, and `undefined` for an id nothing was submitted under.

## What happens after a stop

If the instance stops before a submitted turn ends, the alarm wakes a new instance, which continues the turn from the journal.

Model calls and tool calls that finished before the stop are read back from the journal and not made again. A tool call that was running when the instance stopped has no result: nanocode tells the model the call was lost, and the model decides whether to call the tool again.

## The same request twice

`requestId` identifies a submitted prompt within its session. Submitting it again does not start a second turn, so a caller that retries after a timeout is safe.
