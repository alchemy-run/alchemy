---
title: Storage
description: What each Rivet Durable Object instance keeps — key-value entries, a SQL database and one alarm — and how to change it safely.
---

Every room keeps its own data. Nothing else can read it, and it outlives the room going to sleep, the node it ran on, and every deploy.

This chapter covers the three ways a room uses its storage: key-value entries for small values, a SQL database for anything with structure, and one alarm to wake itself later. It ends with how to keep a change correct when two calls reach a room at once.

All three come from the room's state:

```typescript title="src/room.ts"
const state = yield* Rivet.DurableObjectState;
```

## Keep small values as keys

A room's visitor count is one number. A key holds it:

```typescript title="src/room.ts"
yield* state.storage.put("visitors", 3);
const visitors = yield* state.storage.get<number>("visitors");
```

`get` returns `undefined` for a key the room never set, so a new room starts from nothing without any setup. A value can be anything you'd put in a variable: numbers, strings, objects, arrays, even a `Date` or a `Map`.

`delete` removes a key and says whether it was there:

```typescript title="src/room.ts"
const existed = yield* state.storage.delete("visitors");
```

## List keys by prefix

Keys sort as strings, so a shared prefix groups them. A room that keeps a draft per author can list them all:

```typescript title="src/room.ts"
const drafts = yield* state.storage.list<string>({ prefix: "draft:" });
for (const [key, text] of drafts) {
  // ...
}
```

`list` returns a `Map` in key order. `start` and `end` narrow it to a range, `limit` caps it, and `reverse: true` walks it backwards.

`deleteAll` empties every key at once. The room's SQL tables stay.

## Keep structured data in SQL

A room's messages have an author, a text, and an order. That's a table:

```typescript title="src/room.ts"
yield* (yield* state.storage.sql.exec(
  "CREATE TABLE IF NOT EXISTS messages (author TEXT NOT NULL, text TEXT NOT NULL)",
)).toArray();
```

Each room has its own SQLite database, so the lobby's `messages` table holds only the lobby's messages. There's no room column to filter by, and no other room's rows to skip.

`exec` takes the query and then one value for each `?`:

```typescript title="src/room.ts"
yield* (yield* state.storage.sql.exec(
  "INSERT INTO messages (author, text) VALUES (?, ?)",
  author,
  text,
)).toArray();
```

`exec` returns a cursor, and the statement runs as you read it. `toArray` reads every row, so call it even on a statement that returns none.

The type argument describes each row:

```typescript title="src/room.ts"
const rows = yield* state.storage.sql.exec<{ author: string; text: string }>(
  "SELECT author, text FROM messages",
);
const messages = yield* rows.toArray();
```

`one` reads the only row instead, and fails with `SqlRowCountMismatch` when there are none or several.

## Create tables when the room starts

The inner Effect runs before a room's first call, so it's where the room sets up its tables:

```typescript title="src/room.ts"
return Effect.gen(function* () {
  const state = yield* Rivet.DurableObjectState;
  yield* (yield* state.storage.sql.exec(
    "CREATE TABLE IF NOT EXISTS messages (author TEXT NOT NULL, text TEXT NOT NULL)",
  )).toArray();
  return {
    // ...
  };
});
```

`IF NOT EXISTS` makes it safe to run every time the room wakes. When a later version of the room needs a new column, add an `ALTER TABLE` the same way, guarded so it runs once.

## Set an alarm

A room has one alarm: a time at which Rivet calls the room's `alarm` handler, whether or not anyone calls the room. The chat room uses it to clear its messages an hour after the last one:

```typescript title="src/room.ts"
const now = yield* Effect.sync(() => Date.now());
yield* state.storage.setAlarm(now + 60 * 60 * 1000);
```

The time is in milliseconds since the epoch. Setting the alarm again moves it, so setting it on every post keeps pushing it back until the room has been quiet for an hour.

When it fires, Rivet runs `alarm`:

```typescript title="src/room.ts"
alarm: () =>
  Effect.gen(function* () {
    yield* (yield* state.storage.sql.exec("DELETE FROM messages")).toArray();
  }),
```

`getAlarm` returns when the alarm is due, or `null`. `deleteAlarm` cancels it. A room that needs several timers keeps them in a table and sets the alarm to the earliest.

## Keep a change in one step

A room can run more than one call at once: while one call waits on storage, another can start. So a change written as a read and then a write can lose an update.

```typescript title="src/room.ts"
const visitors = ((yield* state.storage.get<number>("visitors")) ?? 0) + 1;
yield* state.storage.put("visitors", visitors);
```

Two joins at the same moment can both read 2, and both write 3. One visitor goes uncounted.

Make the change a single SQL statement, and the database applies it in one step:

```typescript title="src/room.ts"
yield* (yield* state.storage.sql.exec(
  "CREATE TABLE IF NOT EXISTS counts (name TEXT PRIMARY KEY, n INTEGER NOT NULL)",
)).toArray();

const row = yield* (yield* state.storage.sql.exec<{ n: number }>(
  `INSERT INTO counts (name, n) VALUES ('visitors', 1)
   ON CONFLICT (name) DO UPDATE SET n = n + 1
   RETURNING n`,
)).one();
```

Each join adds one, however many arrive together, and gets back the count after its own.
