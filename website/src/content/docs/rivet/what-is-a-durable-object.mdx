A Durable Object is a way to build a stateful service out of many small, named pieces. Instead of one server that holds every chat room in memory, or a database every request has to go through, each room is its own small program with its own data. You call a room by its name, and Rivet makes sure there's exactly one of it.

This page introduces the ideas one at a time, with the chat rooms the [tutorial](/rivet/tutorial/part-1) builds as the example.

## A class and its instances

A Durable Object starts as a class. `Room` is a class: it says what a room can do, like let someone join.

```typescript title="src/room.ts"
import * as Rivet from "@alchemy.run/rivet";
import * as Effect from "effect/Effect";
import { Default } from "./cluster.ts";

export default class Room extends Rivet.DurableObject<Room>()(
  "Room",
  { main: import.meta.url },
  Effect.gen(function* () {
    return Effect.gen(function* () {
      const state = yield* Rivet.DurableObjectState;
      return {
        join: () =>
          Effect.gen(function* () {
            const visitors = ((yield* state.storage.get<number>("visitors")) ?? 0) + 1;
            yield* state.storage.put("visitors", visitors);
            return visitors;
          }),
      };
    });
  }).pipe(Effect.provide(Default)),
) {}
```

`"Room"` names the class, and `join` is what every room can do. [Durable Object](/rivet/durable-objects) explains each part.

An **instance** is one room. The lobby is an instance, and so is the kitchen. Every instance runs the same code, and each one has its own state.

```typescript title="src/api.ts"
const rooms = yield* Room;
const lobby = rooms.getByName("lobby");
const kitchen = rooms.getByName("kitchen");
```

You never create an instance. Every name exists from the start, and the first call to a name brings its instance to life.

## One instance per name

However many callers ask for the lobby, from however many servers, they all reach the same instance. There's never a second lobby with a different idea of who's in it.

That's what makes a Durable Object useful. The lobby can count its visitors, or keep its messages in order, without coordinating with anything else, because it's the only thing that knows about the lobby.

## State that lives with the instance

Each instance has its own storage: keys and values, and a SQL database. The lobby's messages live in the lobby's database, and nobody else's.

```typescript title="src/room.ts"
yield* state.storage.put("visitors", visitors);
```

Because the data sits with the instance, a room doesn't fetch its state from somewhere else on every call. It reads its own. When an instance goes quiet, Rivet puts it to sleep; the next call wakes it, and its data is still there.

An instance can also set an **alarm**: a time at which Rivet calls it again, whether or not anyone else does. A room uses one to clear itself after an hour of silence. See [Storage](/rivet/storage).

## Methods and the calls that reach them

An instance answers calls through its methods. `join` is a method; so is `post`. A caller anywhere, a Cloudflare Worker, a Lambda, another Durable Object, calls one by naming the instance and the method:

```typescript title="src/api.ts"
const visitors = yield* rooms.getByName("lobby").join();
```

The call is typed from the class, so a caller can't ask a room for a method it doesn't have. See [Calling a Durable Object](/rivet/calling).

## One instance, many calls

An instance runs in one place, but it can take more than one call at once. While one call waits, on storage or on another call, the next one can start.

So a method that reads a value and writes it back can see another call's write land in between. When that matters, keep the read and the write in one SQL statement, or in a single step that doesn't wait in the middle. See [Storage](/rivet/storage#keep-a-change-in-one-step).

## The control plane and the pool

Two things run your Durable Objects.

The **control plane** keeps every instance's data, knows where each instance is running, and routes each call to it. The **pool** is a group of nodes, the machines that run your code. When a call arrives for a sleeping room, the control plane starts it on one of the pool's nodes.
