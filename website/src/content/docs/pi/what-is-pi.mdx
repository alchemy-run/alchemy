Pi is a coding agent, and Pi Durable is the engine that runs its agent loop. The engine writes every step to storage before it acts on it: an input that was submitted, a model request, a tool call and its result. A **harness** is one copy of that engine with its storage. Only one process may own a storage at a time, so a harness fits a Durable Object exactly: one object, one SQLite database, one owner.

Take one small app: a `Session` Durable Object for the user `sam`, with two conversations. `pr-142` is fixing a test, and `notes` is a chat. Both live in the object's SQLite. `pr-142` uses the coding tools, so it has a sandbox on Boat. A Worker reaches the object by name and submits inputs to it.

## The harness

The **harness** is the engine: the models conversations may run on, the tools they may use, and the storage they are kept in. You yield it in a Durable Object's outer Effect and list what it has.

```typescript
const harness = yield* Pi.Harness({ models: [Fast], tools: [Add, AI.CodingTools] });
```

Every model and tool listed becomes a requirement of the harness, so a Layer left out is a compile error.

## Storage

The harness's **storage** holds everything it knows. `PiCloudflare.DurableObjectStorage` keeps it in the SQLite of the Durable Object that yields the harness, so each object has its own conversations and no other object can read them.

```typescript
const HarnessLive = Layer.mergeAll(FastLive, AddLive, PiCloudflare.DurableObjectStorage);
```

On a long-lived machine the storage is a SQLite file instead. See [Other hosts](/pi/other-hosts).

## Conversations

A **conversation** is a transcript and what it runs with: a model, tools, instructions, extensions. You create it with a name of your choosing and reach it by that name from any later call.

```typescript
const conversation = yield* harness.createConversation({ name: "pr-142", tools: [Add] });
```

See [Conversations](/pi/conversations).

## Submissions

A **submission** is one input to a conversation. Submitting stores the input and returns; the run that answers it goes on in the object. You can wait for the answer, or come back later and read the conversation.

```typescript
const submission = yield* conversation.submit({ type: "input", content: "Fix the login test." });
const settled = yield* submission.wait;
```

A `requestId` makes a submission exactly-once, so a retried call never starts a second run.

## Tools

A conversation's **tools** are the ones the harness lists: your own, an MCP server's, and the coding tools. Each call runs in the Durable Object, as an Effect.

See [Tools](/pi/tools).

## Sandboxes

A Durable Object can't run a process, so the coding tools work in a **sandbox**. The harness opens one for each conversation, the first time a tool needs it, and runs Pi's own daemon there.

See [Sandboxes](/pi/sandboxes).

## Extensions and skills

An **extension** adds prompt sections, tools and hooks that a conversation selects by name. A **skill** is instructions the model loads when a task calls for them.

See [Extensions](/pi/extensions) and [Skills](/pi/skills).

## Code mode

In **code mode** the model writes a JavaScript program that calls the conversation's tools, and only the program's output goes back to the model.

See [Code mode](/pi/code-mode).

## Durability

Because every step is stored first, a harness that stops mid-run knows what was in flight. A Durable Object can be evicted at any time. The harness keeps the object's alarm set while there is work, and the alarm wakes a fresh instance that continues every unfinished run.

See [Surviving a crash](/pi/durability).

## How @alchemy.run/pi models these concepts

`Pi.Harness` is an Effect you yield where its Layers are provided. Models, tools, MCP servers, skills and sandboxes are the [`@alchemy.run/ai`](/ai) declarations, unchanged. `Pi.Extension` and `Pi.CodeMode` are Pi's own. The storage, the coding tools and the code mode runtime are Layers, so the same harness moves from a Durable Object to a machine by changing them.
