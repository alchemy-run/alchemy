---
title: drift
description: Detect infrastructure drift by re-observing the cloud, and optionally repair it back to the last deployed state.
---

```sh
alchemy drift [options]
```

Re-observe every deployed resource and compare the live cloud state
against what alchemy last persisted. The result renders exactly like a
deploy plan: unchanged resources are no-ops, out-of-band edits show as
**drifted**, and resources deleted behind alchemy's back show as
**missing**.

By default `drift` only detects — nothing is changed. Pass `--repair`
to converge drifted and missing resources back to the last deployed
state: the plan is shown, you approve it (or pass `--yes`), and the
repair pass re-observes the cloud again before applying so it never
acts on a stale snapshot.

## Flags

| Option              | Description                                                        |
| ------------------- | ------------------------------------------------------------------ |
| `--repair`          | Repair detected drift after showing and confirming the plan        |
| `--stage <name>`    | Stage to check (defaults to `dev_$USER`)                           |
| `--yes`             | Skip the repair confirmation prompt                                |
| `--profile <name>`  | Auth profile to use (defaults to `$ALCHEMY_PROFILE`, the stored default, or `default`) |
| `--env-file <path>` | Load environment variables from a file                             |
| `--config, -c <file>` | Stack file to check (defaults to `alchemy.run.ts`)               |

## Examples

```sh
# Report drift for the default stage
alchemy drift

# Check production
alchemy drift --stage prod

# Repair drift without an interactive prompt (e.g. a scheduled job)
alchemy drift --stage prod --repair --yes
```
