Every resource on Render belongs to an **owner workspace** (`tea-...` for teams or `usr-...` for personal accounts). An API key grants access to one or more workspaces that your Render account belongs to.

## How Alchemy chooses a workspace

Alchemy resolves `ownerId` in this order:

1. An explicit `ownerId` property passed on a resource.
2. The `ownerId` saved on your active `Render` profile (or `RENDER_OWNER_ID` in CI).
3. Auto-discovery from `GET /owners` when your token sees a single workspace. If your token belongs to multiple workspaces, specify `ownerId` explicitly so deployments never target the wrong team.

```typescript
// src/project.ts
import * as Render from "@alchemy.run/render";

export const project = Render.Project("Site", {
  ownerId: "tea-xxxxxxxxxxxxxxxxxxxx",
  environments: {
    staging: { name: "staging", protectedStatus: "unprotected" },
  },
});
```

## Separate production from staging

Create separate Render profiles (or separate team API keys in CI) when production and staging live in isolated workspaces:

<PackageManagers
  script={`{run} alchemy profile create prod
{run} alchemy profile edit --profile prod --add Render
{run} alchemy deploy --stage prod --profile prod`}
/>

In CI (`CI=true`), export `RENDER_API_KEY` and `RENDER_OWNER_ID` in your workflow environment. See [CI](/environments/ci).
