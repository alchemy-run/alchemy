An Api is the interface a model publishes. It lists what one kind of client may reach: the commands it may send, and the views and aggregates it may read. Everything else in the model stays private.

An Api has no handlers of its own. Aggregates already decide commands and views already answer reads, so an Api only chooses which of them to expose. This page covers declaring one, serving it, and calling it.

## List what a client may reach

The tutorial's bank exposes registration, deposits, withdrawals and the account summary.

```typescript title="src/BankApi.ts"
export class BankApi extends Domain.Api(
  "BankApi",
  RegisterCustomer,
  DepositMoney,
  WithdrawMoney,
  AccountSummary,
) {}
```

Leaving something out is how you keep it internal. `OpenAccount` isn't listed, because only the `MainAccountProvisioning` policy opens accounts. No client can send it, however it's built.

## Give each kind of client its own Api

Different clients need different surfaces. In the example bank, customers and support agents use the same model through two Apis.

```typescript title="src/SupportApi/SupportApi.ts"
export class SupportApi extends Domain.Api(
  "SupportApi",
  FreezeAccount,
  ChangeOwner,
  ApproveTransfer,
  AccountSummary,
  AccountActivity,
) {}
```

`FreezeAccount` and `ChangeOwner` are on the support Api and not the customer one. `AccountSummary` is on both.

Being on an Api doesn't mean anyone may use an entry for anything. Each entry still guards itself. A command's middleware establishes who's calling and its `decide` checks whether they may; a view's middleware and `validate` decide what they may see. So `AccountSummary` can sit on both Apis, and a customer still reads only their own accounts.

## Serve it

`httpEffect` turns an Api into an HTTP handler. Mount it on a route in whatever serves your app.

```typescript title="src/BankWorker.ts"
const customerApi = yield* CustomerApi.httpEffect;
const supportApi = yield* SupportApi.httpEffect;
```

The handler needs the hosted model, plus implementations of any middleware its entries declare, such as the session check. Commands, `get` and `list` are plain requests. Live reads, `watch` and `events`, are upgraded to WebSockets connected to the aggregate or view that owns the key, which pushes each change as it commits.

## Call it with a typed client

`Api.client` builds a client typed from the Api's entries. Each command is a method that takes the target and the input together. Each view or aggregate is a namespace with its reads.

```typescript
// test/depositAndWatch.ts
import * as Effect from "effect/Effect";
import * as Stream from "effect/Stream";
import { AccountId } from "../src/Account/AccountId.ts";
import { CustomerApi } from "../src/CustomerApi/CustomerApi.ts";

export const depositAndWatch = Effect.gen(function* () {
  const bank = yield* CustomerApi.client;
  const accountId = AccountId.make("c-1-main");
  const { reply } = yield* bank.DepositMoney({ target: accountId, amount: 1_000 });
  yield* Effect.log(`balance ${reply.balance}`);
  yield* bank.AccountSummary.watch(accountId).pipe(
    Stream.take(2),
    Stream.runForEach((summary) => Effect.log(`balance is now ${summary?.balance}`)),
  );
});
```

The client needs to know how to reach the server. `Domain.protocolWebSocket(url)` sends commands and one-off reads over HTTP and opens a WebSocket for each live read; if the connection drops, the client reconnects and resumes from the last change it saw. `Domain.protocolHttp(url)` uses HTTP for everything, streaming live reads as long-running responses.

## Handle what can go wrong

Every call's error type says exactly what can fail. It's one of the rejections the entry declares, like `InsufficientFunds`; an error from its middleware, like `Unauthorized`; or an `RpcClientError` when the server can't be reached. Because each is a tagged error, `Effect.catchTag` handles the cases you expect and leaves the rest to propagate.

## Provide the client to an app

An app usually wants one client for its whole lifetime. `CustomerApi.Client` is the client as a service, and `CustomerApi.layerClient` provides it. Code that sends commands depends on `CustomerApi.Client` and leaves the connection details to whoever provides the Layer. See [Integrate with foldkit](/domain/foldkit) for a full browser app.

To test an Api end to end, including its middleware and every rejection, see [Testing an Api](/domain/testing-apis).
