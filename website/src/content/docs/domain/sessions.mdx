title: Sessions and middleware
description: Authenticate every request, carry who is asking into the domain, and sign browsers in with a cookie.

Every command and read starts with a question: who is asking? Middleware answers it before the request reaches the domain, and provides the answer as a request context that `decide` and `validate` read.

## Declare who is asking

A request context is a service that travels with the request into the domain. It has a schema, because a command carries it to wherever its aggregate runs.

```typescript
// packages/domain/src/CurrentActor.context.ts
import * as Domain from "@alchemy.run/domain";
import { Actor } from "./Actor.ts";

/**
 * Who is making the current request. `Session` provides it; commands read it
 * in `decide` and views in `validate`. Senders without a session (policies)
 * provide it themselves.
 */
export class CurrentActor extends Domain.RequestContext<CurrentActor>()(
  "Bank/CurrentActor",
  Actor,
) {}
```

```typescript
// packages/domain/src/Actor.ts
import * as Schema from "effect/Schema";
import { CustomerId } from "./Customer/Customer.id.ts";

/**
 * Who is acting. `Session` provides it as the `CurrentActor` of each
 * request; events that need an audit trail record it as `by`.
 */
export const Actor = Schema.Union([
  Schema.TaggedStruct("Customer", { customerId: CustomerId }),
  Schema.TaggedStruct("Agent", { agentId: Schema.String }),
  Schema.TaggedStruct("System", { name: Schema.String }),
]);
export type Actor = typeof Actor.Type;

export const customer = (customerId: string): Actor => ({
  _tag: "Customer",
  customerId: CustomerId.make(customerId),
});
export const agent = (agentId: string): Actor => ({ _tag: "Agent", agentId });
export const system = (name: string): Actor => ({ _tag: "System", name });
```

## Authenticate with middleware

`Session` is middleware that provides `CurrentActor`. Browsers send a session cookie; scripts and tests send an `Authorization` header.

```typescript
// packages/domain/src/Session.middleware.ts
import * as Headers from "effect/http/Headers";
import * as RpcMiddleware from "effect/rpc/RpcMiddleware";
import * as Schema from "effect/Schema";
import { CurrentActor } from "./CurrentActor.context.ts";

/** The request has no session. */
export class Unauthorized extends Schema.TaggedError<Unauthorized>()("Unauthorized", {}) {}

/** The cookie that carries a customer's session in a browser. */
export const SESSION_COOKIE = "bank_session";

/**
 * Authenticates a request, from a customer or a support agent, and provides
 * who is making it as the {@link CurrentActor}. Authorization is up to each
 * command's `decide` and each view's `validate`.
 *
 * Browsers authenticate with the session cookie, which also reaches live
 * reads: a WebSocket upgrade carries cookies, never a header a client sets.
 * Other clients (tests, support tooling) send `Authorization` instead.
 */
export class Session extends RpcMiddleware.Service<Session, { provides: CurrentActor }>()(
  "Bank/Session",
  { error: Unauthorized },
) {}

/** Client side, for clients that are not browsers: send this token with every call. */
export const sessionClient = (token: string) =>
  RpcMiddleware.layerClient(Session, ({ request, next }) =>
    next({ ...request, headers: Headers.set(request.headers, "authorization", `Bearer ${token}`) }),
  );
```

The Worker that serves the Api provides `SessionLive`. A client that isn't a browser adds `sessionClient` to attach its header.

## Guard commands and views

List the middleware on each command and view that needs it. Middleware runs in order, and what it provides is what `decide` and `validate` may read.

```typescript
// packages/domain/src/Account/SetNickname.command.ts
import * as Domain from "@alchemy.run/domain";
import * as Schema from "effect/Schema";
import { Session } from "../Session.middleware.ts";
import { AccountId } from "./Account.id.ts";
import { NotOwner } from "./NotOwner.rejection.ts";

export class NicknameSet extends Domain.Event("NicknameSet", { nickname: Schema.String }) {}

export class SetNickname extends Domain.Command("SetNickname", {
  target: AccountId,
  middleware: [Session],
  input: { nickname: Schema.String },
  events: [NicknameSet],
  rejects: [NotOwner],
}) {}
```

`decide` then checks the actor against the account. See [Aggregate](/domain/aggregate#decide).

## Check who may call it at all

Some rules need only the caller: support tools are for agents, whatever the account. Put such a rule in `access`. It runs with what the middleware provides, before the input reaches `decide`, and fails with one of the entry's `rejects`.

```typescript
// packages/domain/src/Account/FreezeAccount.command.ts
import * as Domain from "@alchemy.run/domain";
import * as Effect from "effect/Effect";
import { CurrentActor } from "../CurrentActor.context.ts";
import { Forbidden } from "../Forbidden.rejection.ts";
import { Session } from "../Session.middleware.ts";
import { AccountId } from "./Account.id.ts";

export class AccountFrozen extends Domain.Event("AccountFrozen") {}

export const agentsOnly = Effect.gen(function* () {
  const actor = yield* CurrentActor;
  if (actor._tag !== "Agent") return yield* new Forbidden({ reason: "for support agents" });
});

export class FreezeAccount extends Domain.Command("FreezeAccount", {
  target: AccountId,
  middleware: [Session],
  events: [AccountFrozen],
  rejects: [Forbidden],
  access: agentsOnly,
}) {}
```

A view, a stream and an aggregate's `read` take `access` too. It runs before the read reaches any key, so it suits a rule like "agents only". A rule that needs the key or the state stays in `validate`, and one that needs the input stays in `decide`. Without `access`, every caller the middleware lets through may call the entry, as before.

## List what a caller may use

A tool list, CLI help or a menu should show only what this caller may use. `visible` answers that without calling anything. It runs each entry's middleware against the request's headers, then its `access`, and returns the entries that pass.

```typescript
// packages/server/src/tools.ts
const request = yield* HttpServerRequest;
const entries = yield* SupportApi.visible({ headers: request.headers });
```

Entries with the same middleware share one pass through it, so a session is resolved once for the list. An entry whose middleware refuses the caller is left out; it does not fail the list. The Api runs the same checks again on every call, so a hidden entry stays closed to a caller who calls it anyway.

## Sign browsers in with a cookie

`sessionRoute` sets the session cookie. `HttpOnly` keeps it from scripts, and `SameSite=Strict` keeps it off requests from other sites, WebSocket upgrades included. The Worker sends `/api/session` to it.

Cookies only work when the app and the Api share an origin. The app's Worker serves the page and forwards `/api` to the bank.

```typescript
// packages/web/src/worker.ts
interface Fetcher {
  fetch(request: Request): Promise<Response>;
}

/**
 * The app's Worker: the client build, plus `/api` forwarded to the bank over
 * a service binding. One origin for both, so the session cookie is
 * first-party and reaches every call and every live read's WebSocket.
 */
export default {
  fetch(request: Request, env: { readonly ASSETS: Fetcher; readonly BANK: Fetcher }) {
    const { pathname } = new URL(request.url);
    return pathname.startsWith("/api") ? env.BANK.fetch(request) : env.ASSETS.fetch(request);
  },
};
```

```typescript
// alchemy.run.ts
import BankWorker from "@bank/server/BankWorker";
import * as Alchemy from "alchemy";
import * as Axiom from "@alchemy.run/axiom";
import * as Cloudflare from "@alchemy.run/cloudflare";
import * as Stripe from "@alchemy.run/stripe";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";

export default Alchemy.Stack(
  "CloudflareDomainExample",
  {
    providers: Layer.mergeAll(Cloudflare.providers(), Stripe.providers(), Axiom.providers()),
    state: Alchemy.localState(),
  },
  Effect.gen(function* () {
    const bank = yield* BankWorker;
    // The foldkit app, built with Vite. Its Worker serves the build and
    // forwards /api to the bank, so the app and the Api share one origin.
    const app = yield* Cloudflare.Website.Foldkit("BankApp", {
      rootDir: "packages/web",
      main: "src/worker.ts",
      env: { BANK: bank },
      assets: { runWorkerFirst: ["/api", "/api/*"] },
    });
    return { url: bank.url.as<string>(), app: app.url.as<string>() };
  }),
);
```

`env: { BANK: bank }` gives the app's Worker a binding to the bank, and `runWorkerFirst` sends `/api` through it.

## Keep tokens out of URLs

A browser can't set headers on a WebSocket, and a URL ends up in logs. A live read authenticates with what its WebSocket upgrade carries: in a browser, the session cookie. Scripts and tests send `Authorization`, which they can set on their WebSockets too. See [Testing an Api](/domain/testing-apis#test-a-deployment).

## Ask for a second factor

Add middleware for anything that needs more than a session. `WithdrawMoney` lists `[Session, MfaChallenge]`, so a withdrawal needs both.

```typescript
// packages/domain/src/MfaChallenge.middleware.ts
import * as RpcMiddleware from "effect/rpc/RpcMiddleware";
import * as Schema from "effect/Schema";

/** The request lacks a valid second factor. */
export class MfaRequired extends Schema.TaggedError<MfaRequired>()("MfaRequired", {}) {}

/** Requires a second factor for sensitive operations. */
export class MfaChallenge extends RpcMiddleware.Service<MfaChallenge>()("Bank/MfaChallenge", {
  error: MfaRequired,
}) {}
```

## Act without a session

A policy has no request, so it provides `CurrentActor` itself before sending a command that needs one, usually as the system. See [Policy](/domain/policy#react-to-a-view).
