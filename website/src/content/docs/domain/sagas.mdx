title: Sagas and compensation
description: Move a process across several aggregates in steps, record where it got to, and undo a step when a later one fails.

A transfer debits one account and credits another. No transaction spans two accounts, so the transfer runs as a **saga**: a series of steps, each committed on its own, where a later step that fails undoes an earlier one.

A saga is made of two building blocks you already know. An aggregate remembers how far the process got, and a policy takes each step.

## Remember the progress in an aggregate

The transfer is an aggregate, and its state is where the process stands:

```typescript title="src/Transfer/Transfer.ts"
state: Schema.Union([
  Schema.TaggedStruct("New", {}),
  Schema.TaggedStruct("AwaitingApproval", Details),
  Schema.TaggedStruct("Pending", Details),
  Schema.TaggedStruct("Completed", {}),
  Schema.TaggedStruct("Failed", { reason: Schema.String }),
]),
```

Every in-between state is part of the model, so anyone can see a transfer that's still pending, and support can approve one that's waiting.

The saga reports each outcome back to the transfer as a command. Reporting can't be refused: a transfer that's no longer pending records nothing.

```typescript title="src/Transfer/Transfer.ts"
CompleteTransfer: (s, _, { id }) =>
  s._tag === "Pending" ? [new TransferCompleted({ transferId: id })] : [],
FailTransfer: (s, cmd, { id }) =>
  s._tag === "Pending" ? [new TransferFailed({ transferId: id, reason: cmd.reason })] : [],
```

## Take each step from a policy

A policy reacts once the transfer may run, and sends each step to the aggregate it touches.

```typescript title="src/Transfer/TransferExecution.ts"
export class TransferExecution extends Domain.Policy("TransferExecution", {
  from: Transfer,
  on: [TransferRequested, TransferApproved],
}) {}
```

The first step debits the source account. If the account refuses, the refusal is a typed rejection, and the policy records it on the transfer as a failure:

```typescript title="src/Transfer/TransferExecution.ts"
const debited = yield* accounts
  .send(from, new DebitTransfer({ transferId, amount, requestedBy }))
  .pipe(
    Effect.as(true),
    Effect.catchTags({
      NotOpen: () => fail("source account not open"),
      NotOwner: () => fail("not your account"),
      Frozen: (r) => fail(`source frozen: ${r.reason}`),
      InsufficientFunds: () => fail("insufficient funds"),
    }),
  );
if (!debited) return;
```

## Take the step you can't undo first

Debit before you credit. If the credit then fails, the money is refunded, so it can be in flight but never created out of nothing. In the same way, registration claims the username before the customer counts as registered: see [Unique values](/domain/unique-values).

## Compensate a failed step

A step that fails after an earlier one succeeded undoes the earlier one. Here the credit fails when the destination account isn't open, so the policy refunds the debit and then fails the transfer.

/>

```typescript title="src/Transfer/TransferExecution.ts"
yield* accounts.send(to, new CreditTransfer({ transferId, amount })).pipe(
  Effect.andThen(transfers.send(source, new CompleteTransfer())),
  Effect.asVoid,
  Effect.catchTag("NotOpen", () =>
    accounts
      .send(from, new RefundTransfer({ transferId, amount }))
      .pipe(Effect.andThen(fail("destination account not open")), Effect.asVoid),
  ),
);
```

## Follow it

`TransferStatus` is a view of the transfer and both accounts. A client watches it to see the saga finish.

```typescript
// test/followTransfer.ts
import * as Effect from "effect/Effect";
import * as Stream from "effect/Stream";
import { TransferId } from "../src/Transfer/TransferId.ts";
import { TransferStatus } from "../src/Transfer/TransferStatus.ts";
import type { CustomerClient } from "./flows.ts";

export const followTransfer = Effect.fn(function* (bank: CustomerClient, transferId: string) {
  yield* bank.TransferStatus.watch(TransferId.make(transferId)).pipe(
    Stream.takeUntil((status) => status?.completedAt !== null || status?.failedReason !== null),
    Stream.runForEach((status) =>
      Effect.log(status === null ? "pending" : TransferStatus.computed.status(status)),
    ),
  );
});
```

## Test it

A story runs the whole saga in memory: the request, every step, and the compensation.

```typescript title="test/transfers.test.ts"
it.effect("a transfer to a closed account is refunded and fails", () =>
  story(
    Story.given(from, opened("c-1"), new MoneyDeposited({ amount: 100, balanceAfter: 100 })),
    Story.given(to, opened("c-2"), new AccountClosed()),
    Story.provide(CurrentActor, sam),
    Story.when(transfer, new RequestTransfer({ from: from.id, to: to.id, amount: 40 })),
    Story.then(transfer, requested),
    Story.then(
      from,
      new TransferDebited({ transferId: transfer.id, amount: 40, balanceAfter: 60 }),
      new TransferRefunded({ transferId: transfer.id, amount: 40, balanceAfter: 100 }),
    ),
    Story.then(
      transfer,
      new TransferFailed({ transferId: transfer.id, reason: "destination account not open" }),
    ),
  ),
);
```
