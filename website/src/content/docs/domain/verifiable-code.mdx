---
title: What can be verified
description: The TypeScript, the Effect helpers and the schemas that Verify supports, and what happens to code outside that set.
---

`Verify` proves a rule from the code of your `decide`, `evolve`, `keyOf` and rules. It supports a subset of TypeScript and of Effect. Code outside it is never guessed at: the report names the file, the line and what it met, and the rule is not proved.

```text
Not supported
  Label.aggregate.ts:23  reads .localeCompare of a string
```

What a handler returns has to depend only on what it is given: the state, the command and the context. It can return a value or an Effect, written with `Effect.gen` or `Effect.fn`.

In the snippets, `a` and `b` are whole numbers, `flag` is a boolean, `text` and `other` are strings and `items` is a list of numbers, each a field of the state or the command.

## Numbers

A whole number is exact, and a `bigint` is exact with no limit. A number is assumed to stay within ±2^53, which the report lists under what it assumes.

```typescript title="Supported"
a + b * 2 - 1;
a % 3;
10n + BigInt(a) * 2n;

a / 4; // a division by a whole number the code writes
a / 4 < 1;
Math.floor(a / 2);
Math.ceil(a / 2);
Math.trunc(a / 2);

Math.abs(a);
Math.max(a, b, 0);
Math.min(a, b, 0);

Number.sum(a, b); // effect/Number and effect/BigInt are the same operators as functions
Number.clamp(a, { minimum: 0, maximum: 9 });
```

```typescript title="Not supported"
a / b; // a division by a number an input holds
a % b;

a / 3 + 0.5; // arithmetic on a number that may not be whole
(a / 3) * 3;
a * 0.5;

Math.round(a / 2);
Math.sqrt(a);
Math.pow(a, 2);
Number.isInteger(a);
```

JavaScript rounds a number that is not whole and a solver does not, so `0.1 + 0.2 === 0.3` is true to one and false to the other. Keep money in whole cents, or in a [decimal](#decimals).

## Decimals

A `BigDecimal` is exact, and so is the solver's arithmetic, so a rule about money written in decimals is proved as written:

```typescript
invariants: {
  NeverRefundedMoreThanCharged: (ledger) =>
    BigDecimal.isLessThanOrEqualTo(ledger.refunded, ledger.charged),
  TheFeesAreATenthOfTheCharges: (ledger) =>
    BigDecimal.equals(ledger.fees, BigDecimal.multiply(ledger.charged, FEE)),
},
```

Here `amount` and `fee` are decimals of the state or the command, and `RATE` is one the code writes.

```typescript title="Supported"

BigDecimal.subtract(amount, fee);
BigDecimal.multiply(amount, RATE);
BigDecimal.isLessThan(amount, fee); // and the other comparisons, and equals
BigDecimal.min(amount, fee);
BigDecimal.max(amount, fee);
BigDecimal.clamp(amount, { minimum: fee, maximum: RATE });
BigDecimal.abs(amount);
BigDecimal.negate(amount);
BigDecimal.floor(amount);
BigDecimal.ceil(amount);
BigDecimal.truncate(amount);

BigDecimal.divide(RATE, BigDecimal.fromNumberUnsafe(4)); // a division between decimals the code writes
```

```typescript title="Not supported"
BigDecimal.divide(amount, fee); // the library rounds a division that does not end, and the solver does not
```

A list of the state or a command has no known length, so it is tried with every length up to two items more than its schema asks for. A rule that passes that way is `Checked`, not `Proved`, and the report says how long the lists were.

## Hash sets and hash maps

A `HashSet` and a `HashMap` of the state or a command are tried like a list: with up to two items, no two of them equal.

```typescript title="Supported"
HashSet.has(roster.members, person); // for every value
HashMap.get(roster.points, person);
HashMap.every(roster.points, (_points, person) => HashSet.has(roster.members, person));
HashMap.reduce(roster.points, 0, (sum, points) => sum + points);
HashSet.size(roster.members);
Equal.equals(roster.members, other.members); // two sets, two maps, two decimals, two objects: by what they hold

for (const person of roster.members) seen.push(person); // in order: tried in every order, for up to four items
[...roster.members];
HashMap.keys(roster.points);
```

The library gives the items of a set and the pairs of a map in the order of their hashes, which the code did not choose. A rule about code that takes them in order is proved only if it holds in every order.

## Schemas

The state, each command's input and each request context start as any value their schema allows.

```typescript title="Supported"

```

```typescript title="Supported checks"

Schema.Int.check(Schema.isBetween({ minimum: 0, maximum: 9 }));
Schema.Int.check(Schema.isMultipleOf(5));

Schema.BigDecimal.check(Schema.isGreaterThanBigDecimal(ZERO)); // and the other four BigDecimal checks
```

```typescript title="Not supported"

Schema.Rational; // make a fraction from whole numbers with Rational.make
Schema.String.check(Schema.isPattern(/^[a-z]+$/)); // a check not listed above: reported, never assumed
```

A check that is not supported is not assumed and not dropped in silence. The report lists it under "Schema checks not proved kept", with the command that writes the field.

A field that may be left out, a union and an `Option` are each a choice, and a proof takes every choice in turn. The choice is made when the code first uses the field, so a field no handler or rule uses adds nothing.

- **`effect/Redacted`:** `make`, `value`, `isRedacted`.
- **`effect/Console`:** `log`, `error`, `warn`, `info`, `debug`, which a handler's result does not depend on.
- **`effect/Ordering` and `effect/UndefinedOr`:** `Ordering.reverse`, `match`; `UndefinedOr.map`, `match`, `getOrThrow`.
- **`effect/Function`:** `pipe`, `flow`, `compose`, `identity`, `constant`, `constTrue`, `constFalse`, `constNull`, `constUndefined`, `constVoid`, `apply`, `tupled`, `untupled`, `flip`, `dual`, `satisfies`, `cast`, and `.pipe` on a value of the library's.
- **`effect/Stream`:** see [Streams](#streams).
- **`effect/Optic`:** `id`, `modify`, `replace`, and an optic's `key` and `tag`.
- **`effect/DateTime`:** `make`, `makeUnsafe`, `toEpochMillis`, `isLessThan`, `isLessThanOrEqualTo`, `isGreaterThan`, `isGreaterThanOrEqualTo`, `between`, `min`, `max`, `distance`, `addDuration`, `subtractDuration`, `add` and `subtract` (in milliseconds, seconds, minutes, hours, days and weeks), `now`, `isPast`, `isFuture`, `formatIsoDate`, `formatIsoDateUtc`, `Order`.
- **`effect/Duration`:** `millis`, `seconds`, `minutes`, `hours`, `days`, `weeks`, `zero`, `toMillis`, `toSeconds`, `toMinutes`, `toHours`, `toDays`, `toWeeks`, `sum`, `subtract`, `times`, `negate`, `abs`, `min`, `max`, `clamp`, `between`, `equals`, `isZero`, `isNegative`, `isPositive`, `isLessThan`, `isLessThanOrEqualTo`, `isGreaterThan`, `isGreaterThanOrEqualTo`, `Order`. Where a function takes a duration, a number of milliseconds and text such as `"7 days"` are supported too.
- **`effect/Clock`:** `currentTimeMillis`, `currentTimeNanos`.
- **`Math`:** `floor`, `ceil`, `trunc`, `abs`, `max`, `min`.
- **`Object`:** `keys`, `values`, `entries`.

## The rest of Effect

Every module of Effect is either supported as above, run as it is, or not supported on purpose.

**Run as it is, on values the code writes.** A pure function that is not on the list above is computed by the library itself when every argument is known: a constant, or something made from constants. That covers `SemVer`, `SemVerRange`, `ByteSize`, `Trie`, `TextDiff`, `JsonPatch`, `JsonPointer`, `Glob`, `RegExp.escape`, `Formatter`, `LogLevel`, `Cron.parse` and `Cron.match`, and the functions of the modules above that are not listed, such as `Array.rotate`, `String.camelToSnake` and `Duration.format`.

```typescript
const MINIMUM = SemVer.parseUnsafe("1.9.3");
const LIMIT = ByteSize.mebibytes(5);
```

Called on a value from the state or a command, or given a function of yours, such a function is not supported, and the report names it. `Combiner` and `Reducer` are made from functions, and `Bytes` works on byte arrays, so they are not supported: write the fold.

Every name on these lists has a line in a table the tests run: each call is tried on values the code writes and on values of a command, and both have to be what the real code gives. The language is a list of the same kind, one entry for each way a piece of it is written, marked as supported or not. A test fails when a function, a method or a form of the language has no line in a table, and when a table is written with a form the list does not have.

**Not supported.** A call to one of these is reported with its name, and the rule is not proved.

- **The outside world.** `Random`, `Config`, `ConfigProvider`, `FileSystem`, `Path`, `Terminal`, `Stdio`, `Effect.promise`, and the packages under `effect/http`, `effect/sql`, `effect/rpc`, `effect/ai`, `effect/cluster`, `effect/workflow` and the others. A handler is a function of the state, the command and the time. What it needs from outside comes in as a field of the command.
- **Time passing and things running together.** `Effect.sleep`, `timeout`, `retry`, `repeat`, `race` and `fork`, `Schedule`, `Scheduler`, `Fiber`, `FiberHandle`, `FiberMap`, `FiberSet`, `Deferred`, `Latch`, `Semaphore`, `PartitionedSemaphore`, `Queue`, `PubSub`, `Pool`, `Cache`, `ScopedCache`, `Request`, `RequestResolver`, `Channel`, `Pull`, `Take`, `SubscriptionRef`, `SynchronizedRef`, `ExecutionPlan` and the `Tx` modules. Which of two things happens first is not something a handler decides, and a handler does not wait. `Cron.next`, `prev` and `sequence` read the clock when they are given no time.
- **Wiring.** `Layer`, `LayerMap`, `LayerRef`, `Context`, `References`, `Scope`, `ScopedRef`, `RcMap`, `RcRef`, `Resource`, `Runtime`, `ManagedRuntime`, `Logger`, `Tracer`, `Metric`, `ErrorReporter`. They say how a program is put together and watched, not what it decides. A request context a handler yields is supported, as above.
- **Schemas as code.** `Schema.decode`, `encode`, `is`, and `SchemaAST`, `SchemaGetter`, `SchemaIssue`, `SchemaParser`, `SchemaRepresentation`, `SchemaTransformation`, `ChannelSchema`, `JsonSchema`, `StandardSchema`, `Arbitrary`. A schema is supported where it describes the state, a command or an event. Decoding with one inside a handler is not.
- **Values changed in place, or known by where they are.** `Graph`, `HashRing`, `MutableList`, and `Hash`. A graph and a ring are built by changing one, and a hash of an object is where it sits in memory. Put a call to one in an exported function, which is then [opaque](#opaque-functions).
- **Nothing to run.** `Types`, `HKT`, `Unify`, `Utils`, `Pipeable`, `Effectable`, `Differ`, `PlatformError`, `Redactable`, `Version`, and `Newtype` and `Brand` beyond the two functions above.

## Effects and failures

```typescript title="Supported"
Pack: Effect.fn(function* (parcel, command) {
  const grams = yield* Effect.succeed(command.grams); // an effect
  const [x, y] = yield* Effect.all([weigh(command.first), weigh(command.second)]);
  const user = yield* CurrentUser; // a request context: any value its schema allows
  const now = yield* DateTime.now; // the time the command is handled at

  if (grams <= 0) return yield* new Empty(); // a rejection: rejects the command
  if (grams > 100) return yield* new Overweight({ over: grams - 100 }); // a Data.TaggedError or Schema.TaggedError: fails with it

  const total = yield* Effect.fromResult(fits(parcel.grams, grams)).pipe(
    Effect.mapError((error) => new TooHeavy({ over: error.over })), // a failure becomes a rejection where the code makes it one
  );
  for (const item of command.items) yield* weigh(item); // in a loop, a branch or a switch
  return [new Packed({ grams: total })];
}),
```

```typescript title="Not supported"
yield* Effect.promise(() => fetch(url)); // the outside world
yield* Effect.tryPromise(() => fetch(url));
yield* Effect.sleep("1 second"); // time passing: sleep, delay, timeout, retry, repeat, race, fork
yield a; // yield without the star
yield* Option.some(a); // an Option or a Result in Effect.gen: use Option.gen, Result.gen, Effect.fromOption, Effect.fromResult
```

A defect is not a failure. After `Effect.die`, `Effect.orDie` or a `getOrThrow` on nothing, the command fails and records nothing, and no `catch` after it handles it.

`Effect.all`, `forEach` and the others run one effect after another. Their `concurrency` option changes nothing a handler can see, since nothing in a handler waits.

## Streams

A stream is supported where it is a list worked through in order: made from values the code has, changed one item at a time, and run to a value.

```typescript title="Supported"
const kept = yield* Stream.fromIterable(command.readings).pipe(
  Stream.filter((reading) => reading >= 0),
  Stream.mapEffect(checked),
  Stream.take(2),
  Stream.runCollect,
);
```

A step that runs an effect for each item takes the items one at a time, so a stream that stops early runs the effects the real one runs and no others: above, a reading after the second is never checked, and a failure it would have given never happens.

- **Made with:** `make`, `succeed`, `empty`, `fromIterable`, `fromArray`, `fromEffect`, `fromArrayEffect`, `fromIterableEffect`, `sync`, `suspend`, `unwrap`, `fail`, `die`, `range`, `iterate`, `unfold`, `paginate`.
- **Changed with:** `map`, `as`, `filter`, `filterMap`, `filterEffect`, `mapEffect`, `tap`, `flatMap`, `take`, `takeWhile`, `takeUntil`, `takeRight`, `drop`, `dropWhile`, `scan`, `mapAccum`, `concat`, `prepend`, `zip`, `zipWith`, `zipWithIndex`, `changes`, `changesWith`, `rechunk`, `grouped`, `drain`.
- **Failures:** `catch`, `catchTag`, `catchTags`, `catchIf`, `orElseSucceed`, `mapError`, `orDie`.
- **Run with:** `runCollect`, `runFold`, `runFoldEffect`, `runForEach`, `runForEachWhile`, `runHead`, `runLast`, `runCount`, `runSum`, `runDrain`, `mkString`, and `run` into a sink.
- **Sinks:** `Sink.collect`, `count`, `sum`, `drain`, `head`, `last`, `take`, `reduce`, `fold`, `every`, `some`, `find`, `forEach`, `succeed`, `fail`, `map`. A sink that has what it wants pulls nothing more.

```typescript title="Not supported"
Stream.iterate(1, (n) => n + 1).pipe(Stream.runCollect); // a stream with no end: cut it with Stream.take(3)
Stream.take(stream, command.count); // a count an input decides
Stream.tick("1 second"); // a stream of time: tick, debounce, throttle, a schedule
Stream.fromQueue(queue); // of a queue or a pub-sub
Stream.merge(first, second); // which item comes first is not something the code decides
Stream.mapEffect(stream, checked, { concurrency: 2 });
```

## Your own files

A name a handler uses is found where its file declares or imports it, and the file it comes from is held to the same list.

```typescript title="Supported"
import { canClose, limit as LIMIT } from "./rules.ts";
import * as Rules from "./rules.ts"; // Rules.hidden is undefined for a name rules.ts does not export
import byDefault from "./rules.ts";
import type { Ticket } from "./Ticket.aggregate.ts";

export { canClose as mayClose } from "./rules.ts";
export * from "./rules.ts";
export * as rules from "./rules.ts";

const SETTINGS = { step: 5, bounds: [0, 100] };
const { step, bounds: [low, high] } = SETTINGS; // a pattern at the top of a file
let calls = 0;

export const isDue = (n: number) => n % step === 0 && within(n); // a function can use what is declared below it
function within(n: number) {
  return n >= low && n <= high;
}
export default isDue;

export class Overweight extends Data.TaggedError("Overweight")<{ over: number }> {} // a class of effect/Data or effect/Schema that adds nothing
export enum Kind { Good, Gift } // an exported enum or namespace
```

```typescript title="Not supported"
enum Local { Good, Gift } // an enum or a namespace the file does not export
class Parcel {
  grams = 0; // a class with a body
}
```

Two files can import each other.

## Your own packages

Rules that several aggregates share often live in a package of their own. Its code is held to the same list as the files of the model:

```typescript title="packages/domain/src/Ticket.aggregate.ts"
import { canClose } from "@acme/rules";

decide: {
  Close: (ticket) => (canClose(ticket) ? [new Closed({})] : []),
},
```

An import is found the way Node finds it: in the nearest `node_modules`, through the `exports` of the package's `package.json`. The code it leads to is held to everything above. Effect and Alchemy are never read this way: the prover knows their functions from the list above.

## Opaque functions

A hash, a parser or a string helper is not code the prover reads, and a rule about something else should not wait on it. Put it in a function your file exports:

```typescript title="packages/domain/src/hash.ts"
import { createHash } from "node:crypto";

export const idOf = (seq: number) => createHash("sha256").update(String(seq)).digest("hex");
```

```typescript title="packages/domain/src/Ticket.aggregate.ts"
evolve: {
  Started: (ticket, _event, envelope) => ({ ...ticket, lastRun: idOf(envelope.seq) }),
  Closed: (ticket) => ({ ...ticket, open: false }),
},
transitions: {
  AClosedTicketStaysClosed: ({ before, after }) => before.open || !after.open,
},
```

The prover cannot read the body of `idOf`, so it does not look inside it. A call gives a value that can be kept in the state, put in an event and passed along. Two calls on the same arguments are the same value, so `idOf(a) === idOf(a)` is true. A condition on the result, as in `if (isValid(command.email))`, is tried both ways.

The result is also taken for what the code uses it as. Where the solver picks a value for it, the real function is run on the same arguments, and an answer the real function does not give is ruled out.

```typescript title="packages/domain/src/Transfer.decision.ts"
export class Pay extends Domain.Decision(PayRef, {
  reads: { from: Account, to: Account },
  keyOf: (cmd) => ({ from: nameOf(cmd.from), to: nameOf(cmd.to) }),
  decide: ({ from, to }, cmd) =>
    nameOf(cmd.payee) === from.id
      ? new SelfPay()
      : Option.isNone(versionOf(cmd.ref))
        ? new BadRef()
        : cmd.amount > from.state.balance
          ? new Short()
          : [
              from.record(new Debited({ amount: cmd.amount })),
              to.record(new Credited({ amount: cmd.amount })),
            ],
}) {}
```

In `keyOf`, what `nameOf` returns is an id: the accounts read are the ones it names. Compared with `from.id` it is text, and next to a number or a boolean it is one of those. `Option.isNone(versionOf(cmd.ref))` takes the result for an `Option`: a `None` on one path, and a `Some` of a value the prover does not look inside on another.

A result that is spread, looped over, or read with an array's `map`, `filter` and the like is a list of up to two items, so `keyOf: (cmd) => ({ to: [...partsOf(cmd.to)] })` reads one account for each. Its rule is then checked for short lists only. A number is any number: nothing says the function gives a whole one. It is compared with `<` and `===`, and a sum or a product of it is not supported.

A rule that reads into the result any other way is not proved, and the report says which function stands in the way, and why:

```text
Not supported
  Ticket.aggregate.ts:32  reads .length of what idOf returned, which the prover does not look inside: idOf reads .update of what createHash returned, which the prover does not look inside: createHash is a function of node:crypto, which is not code the prover reads
```

Where the prover runs your real code, to confirm a counterexample or to check its own reading, it calls the real function. A counterexample is always one the real `idOf` produces.

This takes the function to be pure: the same result for the same arguments, and nothing changed. The report lists each such function under what it assumes. A function is never taken to be pure when what stops the prover could make it otherwise: a global such as `Date` or `Math.random`, a package function the prover has no model for, or a change to a value it was given. That code is reported.

Where you know such a function is pure, name it. A function the prover could read can be named too, to keep its body out of the proof:

```typescript title="packages/domain/test/Ticket.test.ts"
import * as DateTime from "effect/DateTime";

Verify.aggregate(Ticket, { opaque: [DateTime.formatIso] });
```

## What a handler is given

```typescript
decide: {
  // the state, the command, and the context: id, now, commandId, stream and version
  Renew: (lease, command, { id, now, commandId, stream, version }) => [new Renewed({ until: now })],
},
evolve: {
  // the state, the event and its envelope
  Renewed: (lease, event, envelope) => ({ ...lease, until: event.until, renewals: envelope.seq }),
},
```

`now` is any time, so a rule that depends on the clock is proved for every time.

The clock inside `decide` is that same `now`. `yield* DateTime.now` and `yield* Clock.currentTimeMillis` give the time the command is handled at, in the proof and when the command runs:

```ts
Renew: Effect.fn(function* (lease) {
  const now = yield* DateTime.now;
  if (DateTime.isLessThanOrEqualTo(lease.until, now)) return yield* new Lapsed();
  return [Renewed.make({ until: DateTime.addDuration(lease.until, "30 days") })];
}),
```

A time is compared and moved in whole milliseconds. A month and a year are not one length, so `DateTime.add(time, { months: 1 })` is not supported, and neither is the clock anywhere but `decide`, where it is not the time of a command.

A request context a handler yields is any value its schema allows. Middleware is not run, so a rule is proved for every caller, including ones your middleware would turn away.

## When code is not supported

A rule whose command meets unsupported code is not proved, and the verification fails. The line in the report says what to change:

```text
Not supported
  Label.aggregate.ts:23  reads .localeCompare of a string
```

Rewrite the line with what is supported, or put it in an exported function, which is then [opaque](#opaque-functions). You can also move it out of the handler: compute it where the command is built and pass the result in as a field. What `decide` then checks is the field.

A policy's or a saga's handler is held to the same list when the model is searched. One the search cannot follow fails the check until it is allowed by name:

```typescript
Verify.model(Bank, {
  apis: [CustomerApi],
  allow: { skipped: ["FraudReview"] },
});
```
