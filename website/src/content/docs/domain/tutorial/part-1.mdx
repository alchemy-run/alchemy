Build a bank in six parts, starting with an account that opens, takes deposits and refuses overdrafts. This part runs on your machine: no cloud account needed yet.

If commands, aggregates and events are new to you, read [What is Domain-Driven Design?](/domain/what-is-ddd) first.

## Name account ids

```typescript
// src/Account.id.ts
import * as Schema from "effect/Schema";

export const AccountId = Schema.String.pipe(Schema.brand("AccountId"));
```

A branded id keeps an account id from being mixed up with any other string. The commands and the account all use it, so it gets a file of its own.

## Record that an account opened

```typescript
// src/OpenAccount.command.ts
import * as Domain from "alchemy/Domain";
import * as Schema from "effect/Schema";

export class AccountOpened extends Domain.Event("AccountOpened", { owner: Schema.String }) {}
```

An event is a fact, named in the past tense. Everything the account knows will come from its events.

Each command gets a file named after it, with a `.command.ts` suffix, holding the command, the events it records and the rejections only it returns. This event is what `OpenAccount` records, so it starts `src/OpenAccount.command.ts`.

## Declare the account

```typescript
// src/Account.aggregate.ts
import * as Domain from "alchemy/Domain";
import * as Schema from "effect/Schema";
import { AccountId } from "./Account.id.ts";
import { AccountOpened, AlreadyOpen, OpenAccount } from "./OpenAccount.command.ts";

const State = Schema.Union([
  Schema.TaggedStruct("Unopened", {}),
  Schema.TaggedStruct("Open", { owner: Schema.String, balance: Schema.Int }),
]);
type State = typeof State.Type;

export class Account extends Domain.Aggregate("Account", {
  id: AccountId,
  state: State,
  initial: { _tag: "Unopened" },
  commands: [OpenAccount],
  decide: {
    OpenAccount: (s, cmd) =>
      s._tag !== "Unopened" ? new AlreadyOpen() : [new AccountOpened({ owner: cmd.owner })],
  },
  evolve: {
    AccountOpened: (_, e) => ({ _tag: "Open" as const, owner: e.owner, balance: 0 }),
  },
}) {}
```

The account is an aggregate. `decide` takes a command and the current state, and returns events or a rejection. `evolve` folds each event into the next state.

## Group it in a model

```typescript
// src/Bank.model.ts
import * as Domain from "alchemy/Domain";
import { Account } from "./Account.aggregate.ts";

export class Bank extends Domain.Model("Bank", {
  aggregates: [Account],
}) {}
```

A model is everything you host together. You'll add views and policies to it in the next parts.

## Test opening an account

```typescript
// test/Account.test.ts
import { it } from "@effect/vitest";
import { Story } from "alchemy/Domain/Story";
import { Account } from "../src/Account.aggregate.ts";
import { Bank } from "../src/Bank.model.ts";
import { AccountOpened, AlreadyOpen, OpenAccount } from "../src/OpenAccount.command.ts";

const story = Story.make(Bank);
const account = Account.ref("a-1");

it.effect("opens an account", () =>
  story(
    Story.when(account, new OpenAccount({ owner: "sam" })),
    Story.then(account, new AccountOpened({ owner: "sam" })),
  ),
);

it.effect("refuses to open an account twice", () =>
  story(
    Story.given(account, new AccountOpened({ owner: "sam" })),
    Story.when(account, new OpenAccount({ owner: "sam" })),
    Story.rejected(new AlreadyOpen()),
  ),
);
```

A story runs your model in memory. `given` sets up history, `when` sends a command, and `then` and `rejected` check the outcome.

```sh
bun vitest run
```

Both stories pass.

## Decide deposits

```diff lang="typescript"
// src/Account.aggregate.ts
import * as Schema from "effect/Schema";
import { AccountId } from "./Account.id.ts";
+import { DepositMoney, MoneyDeposited } from "./DepositMoney.command.ts";
+import { NotOpen } from "./NotOpen.rejection.ts";
import { AccountOpened, AlreadyOpen, OpenAccount } from "./OpenAccount.command.ts";

```

```diff lang="typescript"
// src/Account.aggregate.ts
type State = typeof State.Type;

+// An event can only follow an open account; anything else is a bug.
+const mustBeOpen = (s: State) => {
+  if (s._tag !== "Open") throw new Error(`expected an open account, got ${s._tag}`);
+  return s;
+};
+
export class Account extends Domain.Aggregate("Account", {
  id: AccountId,
  state: State,
  initial: { _tag: "Unopened" },
-  commands: [OpenAccount],
+  commands: [OpenAccount, DepositMoney],
  decide: {
    OpenAccount: (s, cmd) =>
      s._tag !== "Unopened" ? new AlreadyOpen() : [new AccountOpened({ owner: cmd.owner })],
+    DepositMoney: (s, cmd) =>
+      s._tag !== "Open"
+        ? new NotOpen()
+        : [new MoneyDeposited({ amount: cmd.amount, balanceAfter: s.balance + cmd.amount })],
  },
  evolve: {
    AccountOpened: (_, e) => ({ _tag: "Open" as const, owner: e.owner, balance: 0 }),
+    MoneyDeposited: (s, e) => ({ ...mustBeOpen(s), balance: e.balanceAfter }),
+  },
+  reply: {
+    DepositMoney: (s) => ({ balance: mustBeOpen(s).balance }),
  },
}) {}
```

`evolve` never refuses an event, because it already happened. An event that can't follow the current state is a bug, so `mustBeOpen` throws and the command that caused it is rolled back. `reply` answers from the state after the deposit.

## Withdraw money

```typescript
// src/WithdrawMoney.command.ts
import * as Domain from "alchemy/Domain";
import * as Schema from "effect/Schema";
import { AccountId } from "./Account.id.ts";
import { NotOpen } from "./NotOpen.rejection.ts";

export class MoneyWithdrawn extends Domain.Event("MoneyWithdrawn", {
  amount: Schema.Int,
  balanceAfter: Schema.Int,
}) {}

export class InsufficientFunds extends Domain.Rejection("InsufficientFunds", {
  balance: Schema.Int,
  requested: Schema.Int,
}) {}

export class WithdrawMoney extends Domain.Command("WithdrawMoney", {
  target: AccountId,
  input: { amount: Schema.Int },
  events: [MoneyWithdrawn],
  rejects: [NotOpen, InsufficientFunds],
  reply: { balance: Schema.Int },
}) {}
```

A withdrawal follows the same shape as a deposit, with one more way to say no: `InsufficientFunds` carries the balance and the amount asked for.
