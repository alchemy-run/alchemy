Every command, event, view and policy in the bank already records a span. Send them to [Axiom](/axiom), and follow a click in the app through every Durable Object it reaches. You need a [configured Axiom profile](/axiom/setup).

## Add the Axiom provider

```sh
bun add @alchemy.run/axiom
```


Axiom resources now deploy in the same stack as the bank.

## Declare where telemetry goes

```typescript
// src/Observability.ts
import * as Axiom from "@alchemy.run/axiom";

export const Traces = Axiom.Dataset("Traces", { name: "bank-traces", kind: "otel:traces:v1" });

export const Logs = Axiom.Dataset("Logs", { name: "bank-logs", kind: "otel:logs:v1" });

export const Ingest = Axiom.ApiToken("Ingest", {
  name: "bank-ingest",
  datasetCapabilities: {
    "bank-traces": { ingest: ["create"] },
    "bank-logs": { ingest: ["create"] },
  },
});
```

One dataset holds traces and one holds logs. The token may write to those two datasets and nothing else.

:::note
Dataset names are global to your Axiom org. If you deploy more than one stage, give each its own datasets: see [per-stage datasets](/axiom/data/ingest#per-stage-datasets).
:::

## Follow a deposit

```sh
bun alchemy deploy
```

Open the app, deposit, and query `bank-traces` in Axiom. The deposit is one trace, from the Worker into the account's Durable Object and on to the views it updates:

```text
Domain.send Account.DepositMoney         the bank's Worker, where the Api received it
└─ Domain.decide Account.DepositMoney    the account's Durable Object: decide and commit
   │   event MoneyDeposited              one span event per committed event
   ├─ Domain.view AccountSummary
   └─ Domain.view Statement
```

Each event carries the span that committed it, so the views and policies that react to it continue the same trace.

## See how each command ended

A decide span records the outcome in `domain.outcome`: `accepted`, or the tag of its rejection. Withdraw more than the balance with Part 5's script and the span reads `InsufficientFunds`. A rejection is an answer, not a failure, so the span ends cleanly; only a defect marks it as failed.

## Follow a flow across traces

Registering a customer opens their account through `MainAccountProvisioning`. The policy runs after the registration commits, in its own trace, linked to the span that caused it.

Every span carries `domain.correlation_id`, the id of the first command in the flow. Query on it to find the registration, the policy and the account opening together.

## Record the amount

```diff lang="typescript"
// src/WithdrawMoney.command.ts
export class WithdrawMoney extends Domain.Command("WithdrawMoney", {
  target: AccountId,
  middleware: [Session],
  input: { amount: Schema.Int },
  events: [MoneyWithdrawn],
  rejects: [NotOpen, NotOwner, InsufficientFunds],
  reply: { balance: Schema.Int },
+  attributes: (cmd) => ({ "bank.amount": cmd.amount }),
}) {}
```

Nothing from a command's input is recorded unless you ask. `attributes` adds `bank.amount` to every span the withdrawal makes. Events and rejections accept it too, and a `Redacted` value is always recorded as `<redacted>`.

## Relay the browser's spans

```diff lang="typescript"

-import { SessionLive, sessionRoute } from "./Session.middleware.ts";
+import { SessionLive, sessionRoute, signedIn } from "./Session.middleware.ts";
```

```diff lang="typescript"
// src/BankWorker.ts
  Effect.gen(function* () {
    const api = yield* BankApi;
+    const telemetry = Telemetry.relay({
+      authorize: Effect.map(HttpServerRequest, (request) =>
+        Option.isSome(signedIn(request.headers)),
+      ),
+    });
    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const path = new URL(request.url, "http://localhost").pathname;
-        return path === "/api/session" ? yield* sessionRoute : yield* api.fetch;
+        if (path === "/api/session") return yield* sessionRoute;
+        if (path.startsWith("/api/telemetry/")) return yield* telemetry;
+        return yield* api.fetch;

```

`Telemetry.relay` receives OTLP from the browser and forwards it to Axiom with the Worker's token, so no token ever reaches a browser. It lives under `/api`, so the app's Worker already forwards it.

## Follow a click

```sh
bun alchemy deploy
```

Deposit again. The trace now starts in the browser:

```text
Deposit                                     the app: foldkit's command
└─ Domain.send Account.DepositMoney         the bank's Worker
   └─ Domain.decide Account.DepositMoney    the account's Durable Object
      │   event MoneyDeposited
      ├─ Domain.view AccountSummary
      └─ Domain.view Statement
```

One trace shows the click, the command it sent, and everything it changed.

:::note
The rest of what a model records, such as metrics, logs from handlers, and turning off view spans, is in [Observability](/domain/observability). Alerts on top of these datasets are in [Monitors & Alerting](/axiom/guides/alerting).
:::
