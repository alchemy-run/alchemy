Build a browser app with [Effect UI](https://ui.effect.website): sign in, open your account, deposit, and see the balance change as it happens. Effect UI tests a component the way the domain tests a model: as a story of messages in and effects out.

## Install

<PackageManagers add="@effect/ui @effect/platform-browser" dev="vite" />

Effect UI is in public preview and isn't on npm yet: install a snapshot build as its [README](https://github.com/Effect-TS/ui#snapshots) describes.

## Add the browser's types

The app runs in a browser. Add `"DOM"` to `lib` in your `tsconfig.json`, so `document` and `location` type-check:

```json
{
  "compilerOptions": {
    "lib": ["ESNext", "DOM"]
  }
}
```

## Configure Vite

```typescript
// vite.config.ts
```

The app runs in the browser alone, so it needs no Vite plugin. `include` pre-bundles the Effect modules, so the browser loads one copy of Effect.

## Derive the bank's commands and view


`BankUI` has one Effect UI Command per Api command and one query per view. `BankUI.layer` runs them on the bank client, which the app provides when it starts.

The signed-in customer is the component's props. A click runs a domain command and maps its outcome to a message: a rejection, a refused session or a lost reply becomes `Failed` with its tag. The balance never changes on success: it comes from the bank, through the next step.

## Test the app

```typescript
// test/Bank.app.test.ts
import { HtmlLocator, HtmlScene } from "@effect/ui/html/testing";
import { Story } from "@effect/ui/testing";
import { describe, expect, it } from "@effect/vitest";
import * as Effect from "effect/Effect";
import * as Option from "effect/Option";
import { CustomerId } from "../src/Customer.id.ts";
import { NotOpen } from "../src/NotOpen.rejection.ts";
import { BankMessage, BankNoDeps, BankUI } from "../src/web/Bank.ts";

const props = { customerId: CustomerId.make("c-2") };
const summary = (owner: string | null, balance: number) => ({
  state: Option.some({ owner, balance }),
  cursor: 1,
});

describe("the bank app", () => {
  it.effect("opens the customer's account", () =>
    Effect.gen(function* () {
      const s = yield* Story.make(BankNoDeps, props);
      s.loaded("summary", { state: Option.none(), cursor: 0 })
        .send(BankMessage.ClickedOpen())
        .expectExact(BankUI.RegisterCustomer);
      expect(s.pending[0]!.command.args).toMatchObject({ input: { customerId: "c-2", name: "c-2" } });
      s.resolve(BankUI.RegisterCustomer, {
        commandId: "page:0",
        reply: undefined,
        receipt: { stream: "Customer/c-2", version: 1 },
        commits: [{ stream: "Customer/c-2", version: 1 }],
      });
      expect(s.model.error).toBeNull();
    }),
  );

  it.effect("deposits, and shows the balance the view reports", () =>
    Effect.gen(function* () {
      const s = yield* HtmlScene.make(BankNoDeps, props);
      s.loaded("summary", summary("c-2", 0))
        .expect(HtmlLocator.label("Balance"))
        .toHaveText("Balance: 0.00")
        .click(HtmlLocator.role("button", { name: "Deposit 10.00" }))
        .resolve(BankUI.DepositMoney, {
          commandId: "page:0",
          reply: { balance: 1_000 },
          receipt: { stream: "Account/c-2-main", version: 2 },
          commits: [{ stream: "Account/c-2-main", version: 2 }],
        })
        // The balance comes from the view, not from the command's reply.
        .expect(HtmlLocator.label("Balance"))
        .toHaveText("Balance: 0.00")
        .loaded("summary", summary("c-2", 1_000))
        .expect(HtmlLocator.label("Balance"))
        .toHaveText("Balance: 10.00");
    }),
  );

  it.effect("shows why a deposit was refused", () =>
    Effect.gen(function* () {
      const s = yield* HtmlScene.make(BankNoDeps, props);
      s.loaded("summary", summary("c-2", 0))
        .click(HtmlLocator.role("button", { name: "Deposit 10.00" }))
        .fail(BankUI.DepositMoney, { _tag: "Rejected", commandId: "page:0", rejection: new NotOpen() })
        .expect(HtmlLocator.role("alert"))
        .toHaveText("Rejected");
    }),
  );
});
```

A Story drives the component's `update` and a Scene drives its view, with no browser or server. Like the domain's stories, each test says what happened and what came back: every command a step runs stays pending until the test resolves or fails it, and the view's query has no value until the test loads one.

## Start the app

```typescript
// src/web/entry.ts
import * as Domain from "@alchemy.run/domain";
import { BrowserHost } from "@effect/ui/html";
import * as Effect from "effect/Effect";
import * as FetchHttpClient from "effect/http/FetchHttpClient";
import * as HttpClient from "effect/http/HttpClient";
import * as HttpClientRequest from "effect/http/HttpClientRequest";
import * as Layer from "effect/Layer";
import * as Socket from "effect/socket/Socket";
import { BankApi } from "../BankApi.api.ts";
import { CustomerId } from "../Customer.id.ts";
import { Bank } from "./Bank.ts";

// A stand-in for a login page: `?customer=c-2` picks who you are.
const customerId = CustomerId.make(new URLSearchParams(location.search).get("customer") ?? "c-1");

// Sign in, so the browser holds the session cookie for every call and watch.
const signIn = Effect.gen(function* () {
  const client = HttpClient.filterStatusOk(yield* HttpClient.HttpClient);
  yield* client.execute(
    HttpClientRequest.post("/api/session").pipe(HttpClientRequest.bodyJsonUnsafe({ customerId })),
  );
});

const BankConnection = Layer.unwrap(
  signIn.pipe(
    Effect.orDie,
    Effect.as(
      BankApi.layerClient.pipe(
        Layer.provide(Domain.protocolWebSocket(`${location.origin}/api`)),
        Layer.provide(Socket.layerWebSocketConstructorGlobal),
      ),
    ),
  ),
).pipe(Layer.provide(FetchHttpClient.layer));

const Main = BrowserHost.mount(Bank, { customerId }, document.getElementById("root")!).pipe(
  Layer.provide(BankConnection),
);

Layer.launch(Main).pipe(Effect.runFork);
```

The app signs in first, then mounts with the customer as its props and connects to the Api on its own origin. `Domain.protocolWebSocket` sends commands over HTTP and opens a WebSocket for each live read.

## Serve the app and the Api from one origin

```typescript
// src/web/worker.ts
interface Fetcher {
  fetch(request: Request): Promise<Response>;
}

// Serve the app, and forward /api to the bank: one origin, so the session cookie is first-party.
export default {
  fetch(request: Request, env: { readonly ASSETS: Fetcher; readonly BANK: Fetcher }) {
    const { pathname } = new URL(request.url);
    return pathname.startsWith("/api") ? env.BANK.fetch(request) : env.ASSETS.fetch(request);
  },
};
```

The app's Worker serves the built page and forwards `/api` to the bank. Sharing one origin keeps the session cookie first-party, so browsers send it.
