---
title: View
description: Fold events into read models per key, emit events of your own, and read them live.
---

A view answers a question: what's the balance, what moved today, what happened to this transfer. It folds events into state per key and keeps up as new events arrive.

## Declare a view

Say which aggregates or views it reads `from`, which aggregate its `key` belongs to, and how each event changes its state.

```typescript
// src/Account/AccountSummary.ts
import * as Domain from "alchemy/Domain";
import * as Effect from "effect/Effect";
import * as Schema from "effect/Schema";
import { CustomerId } from "../Customer/CustomerId.ts";
import { Cents } from "../Money.ts";
import { Session } from "../Session.ts";
import { Account } from "./Account.ts";
import { mustOwn } from "./mustOwn.ts";
import { NotOwner } from "./NotOwner.ts";

const setBalance = <V extends { balance: number }>(
  v: V,
  e: { readonly balanceAfter: number },
): V => ({
  ...v,
  balance: e.balanceAfter,
});

/**
 * The current balance and status of one account. It declares no events, so
 * it emits every event it applies, each with the summary after it.
 */
export class AccountSummary extends Domain.View("AccountSummary", {
  from: [Account],
  key: Account,
  middleware: [Session],
  rejects: [NotOwner],
  state: Schema.Struct({
    customerId: Schema.NullOr(CustomerId),
    owner: Schema.NullOr(Schema.String),
    balance: Cents,
    frozen: Schema.Boolean,
    closed: Schema.Boolean,
  }),
  initial: { customerId: null, owner: null, balance: 0, frozen: false, closed: false },
  evolve: {
    AccountOpened: (v, e) => ({ ...v, customerId: e.customerId, owner: e.owner }),
    OwnerChanged: (v, e) => ({ ...v, customerId: e.customerId }),
    MoneyDeposited: setBalance,
    MoneyWithdrawn: setBalance,
    TransferDebited: setBalance,
    TransferCredited: setBalance,
    TransferRefunded: setBalance,
    SettlementReceived: setBalance,
    AccountFrozen: (v) => ({ ...v, frozen: true }),
    AccountClosed: (v) => ({ ...v, closed: true }),
  },
  // Re-run on every change while watched: a reassigned account ends the watch with NotOwner.
  validate: Effect.fn(function* (_request, summary) {
    yield* mustOwn(summary?.customerId ?? null);
  }),
}) {}
```

Each account gets its own summary. A view only handles the events it names in `evolve`; the rest pass it by. `validate` decides who may read it. See [Views as security boundaries](/domain/view-security).

## Emit events

A view can record events of its own. Every money movement on an account becomes one `StatementLine`.

```typescript
// src/Account/Statement.ts
import * as Domain from "alchemy/Domain";
import * as Effect from "effect/Effect";
import * as Schema from "effect/Schema";
import { CustomerId } from "../Customer/CustomerId.ts";
import { Cents } from "../Money.ts";
import { Session } from "../Session.ts";
import { Account } from "./Account.ts";
import { mustOwn } from "./mustOwn.ts";
import { NotOwner } from "./NotOwner.ts";

/** One movement of money on an account. */
export class StatementLine extends Domain.Event("StatementLine", {
  data: {
    kind: Schema.Literals([
      "deposit",
      "withdrawal",
      "transfer-in",
      "transfer-out",
      "refund",
      "settlement",
    ]),
    amount: Cents,
    balance: Cents,
  },
}) {}

const line =
  (kind: StatementLine["kind"]) =>
  (e: { readonly amount: number; readonly balanceAfter: number }) =>
    new StatementLine({ kind, amount: e.amount, balance: e.balanceAfter });

/**
 * Every movement of money on an account, oldest first: six events become
 * one. It keeps the account's owner so it can authorize reads.
 */
export class Statement extends Domain.View("Statement", {
  from: [Account],
  key: Account,
  middleware: [Session],
  rejects: [NotOwner],
  state: Schema.Struct({ customerId: Schema.NullOr(CustomerId) }),
  initial: { customerId: null },
  evolve: {
    AccountOpened: (_, e) => ({ customerId: e.customerId }),
    OwnerChanged: (_, e) => ({ customerId: e.customerId }),
  },
  validate: Effect.fn(function* (_request, statement) {
    yield* mustOwn(statement?.customerId ?? null);
  }),
  events: [StatementLine],
  emit: {
    MoneyDeposited: line("deposit"),
    MoneyWithdrawn: line("withdrawal"),
    TransferCredited: line("transfer-in"),
    TransferDebited: line("transfer-out"),
    TransferRefunded: line("refund"),
    SettlementReceived: line("settlement"),
  },
}) {}
```

Each emitted event comes with the view's state after it. Other views and policies can consume a view's events, like `CustomerDashboard` building on `AccountSummary`, or `FraudReview` reacting to `DailyOutflow`.

## Route one event to several keys

`keyOf` decides which keys an event updates. Give it named routes when one event must reach several keys and do something different at each.

```typescript
// src/Transfer/AccountTransfers.ts
import * as Domain from "alchemy/Domain";
import * as Effect from "effect/Effect";
import * as Schema from "effect/Schema";
import { Account } from "../Account/Account.ts";
import { mustOwn } from "../Account/mustOwn.ts";
import { NotOwner } from "../Account/NotOwner.ts";
import { CustomerId } from "../Customer/CustomerId.ts";
import { Cents } from "../Money.ts";
import { Session } from "../Session.ts";
import { type TransferRequested } from "./RequestTransfer.ts";
import { Transfer } from "./Transfer.ts";
import { TransferId } from "./TransferId.ts";

/** Money moved in or out of an account by a transfer. */
export class TransferMoved extends Domain.Event("TransferMoved", {
  data: {
    transferId: TransferId,
    amount: Cents,
    direction: Schema.Literals(["in", "out"]),
  },
}) {}

const moved = (direction: "in" | "out") => (e: TransferRequested) =>
  new TransferMoved({ transferId: e.transferId, amount: e.amount, direction });

/**
 * Transfers touching an account. One request is routed to both accounts, so
 * the recipient sees incoming transfers here. It keeps the account's owner so
 * it can authorize reads.
 */
export class AccountTransfers extends Domain.View("AccountTransfers", {
  from: [Transfer, Account],
  key: Account,
  middleware: [Session],
  rejects: [NotOwner],
  state: Schema.Struct({ customerId: Schema.NullOr(CustomerId) }),
  initial: { customerId: null },
  evolve: {
    AccountOpened: (_, e) => ({ customerId: e.customerId }),
    OwnerChanged: (_, e) => ({ customerId: e.customerId }),
  },
  validate: Effect.fn(function* (_request, transfers) {
    yield* mustOwn(transfers?.customerId ?? null);
  }),
  keyOf: {
    TransferRequested: {
      out: ({ event }) => Account.ref(event.from),
      in: ({ event }) => Account.ref(event.to),
    },
  },
  events: [TransferMoved],
  emit: {
    TransferRequested: { out: moved("out"), in: moved("in") },
  },
}) {}
```

One `TransferRequested` updates both accounts: the sender's as `out`, the recipient's as `in`.

## Read it

Through an Api, a view has four ways to read one key.

```typescript
// test/readSummary.ts
import * as Effect from "effect/Effect";
import * as Stream from "effect/Stream";
import type { AccountId } from "../src/Account/AccountId.ts";
import type { CustomerClient } from "./flows.ts";

export const readSummary = Effect.fn(function* (bank: CustomerClient, accountId: AccountId) {
  // The current state, or null if the account has no summary yet.
  const summary = yield* bank.AccountSummary.get(accountId);
  yield* Effect.log(`balance ${summary?.balance}`);

  // A page of the statement's lines, newest first.
  const page = yield* bank.Statement.list(accountId, { order: "desc", take: 10 });
  yield* Effect.log(`${page.entries.length} recent lines`);

  // The state now, then after every change.
  yield* bank.AccountSummary.watch(accountId).pipe(
    Stream.take(3),
    Stream.runForEach((s) => Effect.log(`balance ${s?.balance}`)),
  );

  // Every line, history first, then new ones as they happen.
  yield* bank.Statement.events(accountId).pipe(
    Stream.take(3),
    Stream.runForEach(({ event }) => Effect.log(`${event.kind} ${event.amount}`)),
  );
});
```

## Read your own write

A view catches up shortly after a command commits. Pass the command's receipt as `atLeast`, and `get` waits until the view has applied it.

```typescript
// test/depositThenRead.ts
import * as Effect from "effect/Effect";
import type { AccountId } from "../src/Account/AccountId.ts";
import type { CustomerClient } from "./flows.ts";

export const depositThenRead = Effect.fn(function* (bank: CustomerClient, accountId: AccountId) {
  const receipt = yield* bank.DepositMoney({ target: accountId, amount: 500 });
  const summary = yield* bank.AccountSummary.get(accountId, {
    atLeast: { stream: receipt.stream, version: receipt.version },
  });
  return summary?.balance;
});
```

## Filter what you read

`where` narrows a read you're allowed to make. A filtered-out state reads as `null`, and filtered-out events are skipped.

```typescript
// test/largeDeposits.ts
import * as Effect from "effect/Effect";
import * as Stream from "effect/Stream";
import type { AccountId } from "../src/Account/AccountId.ts";
import type { CustomerClient } from "./flows.ts";

export const largeDeposits = Effect.fn(function* (bank: CustomerClient, accountId: AccountId) {
  yield* bank.Statement.events(accountId, {
    where: { kind: "deposit", amount: { gte: 10_000 } },
  }).pipe(Stream.runForEach(({ event }) => Effect.log(`large deposit: ${event.amount}`)));
});
```

A filter never grants access. `validate` decides whether you may read the key at all.
