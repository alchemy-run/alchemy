Alchemy's agent runtime turns the pattern behind IaC on language
itself: an **agent is prose with capabilities spliced in**, and an
organization of agents is a typed, composable Effect program.

```typescript
import * as AI from "alchemy/AI";

export class Reviewer extends AI.Agent<Reviewer>()("Reviewer") {}

export const ReviewerLive = Reviewer.make`
  You review each ${pr} against its originating ${issue} — the diff
  and the spec; you did not write this code and never saw its
  author's reasoning. Verdict via ${Approve} or changes via ${Comment}.`;
```

That template is not a system prompt in a string — every `${...}`
splice is a **term** (a tool, a skill, another agent), and mentioning
it is what grants it:

- **Mention is presence.** The tools an agent holds are exactly the
  ones its prose mentions — and the requirements ride Effect's type
  system, so a missing implementation is a compile error, not a
  runtime surprise.
- **Capability by omission.** This Reviewer cannot merge — not because
  a rule says so, but because no merge tool appears in its charter.
  `rg '\$\{MergePullRequest\}'` audits the whole org.
- **Physics by composition.** The same charter runs against local
  shell tools today and different physics tomorrow, because
  implementations are [Layers](/infrastructure-as-effects/layers)
  chosen at the entrypoint.

Agents are **perpetual actors**, not one-shot chains: each run is a
conversation keyed by a world entity (`org/repo#123`), it parks when
its work is done, and the next event — a comment, a review, a
reminder it set itself — wakes it with its context intact.

:::caution
The agent runtime is **experimental**. The surface documented here is
real and runs today on the in-memory kernel; durable kernels
(Cloudflare Durable Objects) are in active development. Expect
breaking changes between beta releases.
:::

## The worked example

These docs quote a real system throughout: **alchemy-org**, a software
factory that manages a GitHub repository end to end — issues are
triaged by an owner agent, an engineer builds the fix in its own git
worktree, a reviewer verifies it in the same checkout, and the merge
is ratified against an approvals ledger. Every pattern documented
here is load-bearing there.
