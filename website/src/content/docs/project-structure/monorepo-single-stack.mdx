This guide deploys a backend Worker and a Vite frontend from one
`alchemy.run.ts` at the workspace root. It follows
[`examples/monorepo-single-stack`](https://github.com/alchemy-run/alchemy/tree/main/examples/monorepo-single-stack):

```sh
.
├── package.json          # workspaces: ["frontend", "backend"]
├── alchemy.run.ts        # the one stack, deploys both apps
├── backend/
│   └── src/
│       └── Service.ts    # the Worker, this file is its own entry
└── frontend/
    ├── index.html        # Vite app
    └── src/
        └── main.tsx
```

To split the deploy per package instead, see
[Deploy a monorepo with many stacks](/project-structure/monorepo-multi-stack).

## Declare the backend Worker

Each app declares its own Worker in its own package:

```typescript
// backend/src/Service.ts
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

export default class Service extends Cloudflare.Worker<Service>()(
  "Service",
  { main: import.meta.url }, // this file is the entry
  Effect.gen(function* () {
    return {
      fetch: Effect.succeed(HttpServerResponse.text("Hello from the backend")),
    };
  }),
) {}
```

`main: import.meta.url` is a file URL, so it is absolute by construction.
The root `alchemy.run.ts` can import `Service` from anywhere and bundling
still finds the right module.

The example serves a typed `HttpApi` in place of a plain `fetch` handler
and shares its typed client with the frontend. See
[Effect HTTP API](/cloudflare/apis/effect-http-api) for that pattern.

## Deploy both apps from the root stack

The root stack yields the Worker and builds the frontend with
`Cloudflare.Website.Vite`:

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import { Path } from "effect/Path";
import Service from "./backend/src/Service.ts";

export default Alchemy.Stack(
  "Monorepo",
  {
    providers: Cloudflare.providers(),
    state: Cloudflare.state(),
  },
  Effect.gen(function* () {
    const backend = yield* Service;
    const path = yield* Path;

    const website = yield* Cloudflare.Website.Vite("Website", {
      // Vite's `root`: index.html, vite.config.ts, and the app source.
      // Defaults to process.cwd(), which is the workspace root here.
      rootDir: path.resolve(import.meta.dirname, "frontend"),
      env: {
        // An Output: the Worker deploys first, then the build bakes in its URL.
        VITE_API_URL: backend.url.as<string>(),
      },
    });

    return {
      backendUrl: backend.url.as<string>(),
      websiteUrl: website.url.as<string>(),
    };
  }),
);
```

The frontend reads the URL like any other Vite env var:

```typescript
// frontend/src/main.tsx
const API_URL = import.meta.env.VITE_API_URL;
```

The frontend reads the backend's URL from the in-memory Output. You need
no cross-stack references and no deploy order.

## Anchor every path

:::caution
`alchemy deploy` and `alchemy dev` run from the workspace root, so relative
paths resolve from the root. They do not resolve from the file that
declares the resource. A Worker declared in `backend/` with
`main: "src/worker.ts"` resolves to `<root>/src/worker.ts`, which doesn't
exist.
:::

Anchor every path to the file that declares it with `import.meta`:

- **A Worker whose defining file is its entry**: `main: import.meta.url`.
- **A Worker with a separate entry file**:
  `main: new URL("./src/worker.ts", import.meta.url).href`.
- **A Vite website in a subdirectory**:
  `rootDir: path.resolve(import.meta.dirname, "frontend")`.
- **A custom Worker entry inside a Vite app**: `main: "src/worker.ts"`.
  This path resolves from `rootDir`, so it means `frontend/src/worker.ts`.

`import.meta.url` and `import.meta.dirname` always point at the file being
evaluated. The resource resolves the same way no matter which directory
`alchemy` runs from.

deploy together, and `alchemy destroy` removes both together. `alchemy dev`
also runs from the root.

## Add more apps

Declare each app's Worker in its own package with an anchored `main`
(see [Anchor every path](#anchor-every-path)). Import it into the one
stack and `yield*` it next to `Service`:

```typescript
// apps/api/Api.ts
import * as Cloudflare from "alchemy/Cloudflare";

export const Api = Cloudflare.Worker("Api", {
  main: new URL("./src/worker.ts", import.meta.url).href, // separate entry file
});

// alchemy.run.ts
const api = yield* Api;
```
