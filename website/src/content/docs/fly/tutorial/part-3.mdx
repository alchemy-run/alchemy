Your Service from [Part 2](/fly/tutorial/part-2) is stateless —
anything it writes to the Machine's root disk dies with the Machine.
In this part you'll attach a **Volume** — Fly's region-local block
storage — and mount it into the Service so files survive deploys.

:::caution[One Volume, one Machine]
A Fly Volume attaches to **one** Machine. Two Services cannot mount
the same Volume. Keep the mount on this API Service (or move it to a
dedicated worker later).
:::

## Declare a Volume

Add a Volume next to the App in `src/app.ts`. The region must match
the Service's:

```diff lang="typescript"
// src/app.ts
import * as Fly from "alchemy/Fly";

export const Site = Fly.App("Site");

export const PublicIp = Fly.IpAssignment("Shared", {
  app: Site,
  type: "shared_v4",
});
+
+export const Data = Fly.Volume("data", {
+  app: Site,
+  region: "iad",
+  sizeGb: 1,
+});
```

`sizeGb` is in GB (1 is the minimum) and can **grow in place** —
Fly cannot shrink a Volume. Pass the `Site` declaration directly;
resource-valued props accept the resource or an Effect producing it.

## Mount it into the Service

Inside the Service's init, bind the Volume with `Fly.MountVolume` —
pass the declaration directly, no yielding required:

```diff lang="typescript"
// src/api.ts
import * as Fly from "alchemy/Fly";
import * as Effect from "effect/Effect";
import { HttpServerRequest } from "effect/unstable/http/HttpServerRequest";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";
-import { Site } from "./app.ts";
+import { Data, Site } from "./app.ts";

export default class Api extends Fly.Service<Api>()(
  "Api",
  { app: Site, main: import.meta.url, region: "iad", port: 3000 },
  Effect.gen(function* () {
+    const mount = yield* Fly.MountVolume(Data, { path: "/data" });

    return {
      fetch: /* ... */,
    };
  }),
) {}
```

`MountVolume` is a **binding**: at deploy time it tells the Service
"put this Volume in `config.mounts` at `/data`", and at runtime it
hands you the resolved `mount.path` and `mount.volumeId`.

## Provide the binding layer

Bindings declare a capability; layers implement it. Provide
`MountVolumeLive` on the Service's init Effect:

```diff lang="typescript"
  Effect.gen(function* () {
    const mount = yield* Fly.MountVolume(Data, { path: "/data" });

    return {
      fetch: /* ... */,
    };
-  }),
+  }).pipe(Effect.provide(Fly.MountVolumeLive)),
) {}
```

## Write files with `PUT /:name`

Now use the mount from the handler. The runtime provides Effect's
`FileSystem` service, so the Volume is just a directory:

```diff lang="typescript"
// src/api.ts
+import * as FileSystem from "effect/FileSystem";
// ...
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const url = new URL(request.url, "http://service");
        if (url.pathname === "/health") {
          return HttpServerResponse.json({ ok: true });
        }
+        const fs = yield* FileSystem.FileSystem;
+        const file = `${mount.path}${url.pathname}`;
+
+        if (request.method === "PUT") {
+          const body = yield* request.text;
+          yield* fs.writeFileString(file, body).pipe(Effect.orDie);
+          return HttpServerResponse.empty({ status: 204 });
+        }
+
        return HttpServerResponse.text("Hello from Fly!");
      }),
```

## Read files with `GET /:name`

Add the read branch, turning a missing file into a 404:

```diff lang="typescript"
if (request.method === "PUT") {
  const body = yield* request.text;
  yield* fs.writeFileString(file, body).pipe(Effect.orDie);
  return HttpServerResponse.empty({ status: 204 });
}

+if (request.method === "GET") {
+  const text = yield* fs.readFileString(file).pipe(
+    Effect.catchAll(() => Effect.succeed(undefined)),
+  );
+  if (text === undefined) {
+    return HttpServerResponse.text("Not found", { status: 404 });
+  }
+  return HttpServerResponse.text(text);
+}

return HttpServerResponse.text("Hello from Fly!");
```

During the Service's deploy, Alchemy writes the Volume into the
Machine's `config.mounts` at `/data`. The Volume must already exist
in `iad` — same region as the Machine.

## Try it out

```sh
# Store a file on the Volume
curl -X PUT https://myapp-site-dev-a1b2c3d4.fly.dev/hello.txt -d 'Hello, Volume!'

# Read it back
curl https://myapp-site-dev-a1b2c3d4.fly.dev/hello.txt
# → Hello, Volume!
```

Ship another code change and deploy — the file is still there. The
Volume is a separate resource with its own lifecycle: even if the
Machine is replaced, the Volume re-attaches on the next deploy.

## Recap

You now have:

- A 1 GB Volume in `iad` mounted at `/data` on the API Machine
- A Service reading and writing it through Effect's `FileSystem` —
  no SDK, just files
- Data that outlives deploys and Machine replacement

and read it from the Service, then tear the stack down.
