[Foldkit](https://foldkit.dev) is an Elm-architecture frontend framework
built on Effect. This integration supports browser-only SPAs, server rendering,
and prerendered pages with request-time fallback. Foldkit's Vite plugin generates
the handler and assets; Alchemy packages them for Fly.

## Install

The build integration is not bundled with alchemy. Install
`@alchemy.run/frontend-frameworks`; the resource loads its `/foldkit`
and `/foldkit/node` exports from your project at deploy time. It is only
used at build time, so a dev dependency is enough:

## Configure Vite

Your Vite config stays what Foldkit's setup gives you. Vite plugins
like Tailwind go in `plugins` as usual:

```typescript
// vite.config.ts
import { foldkit } from "@foldkit/vite-plugin";
import tailwindcss from "@tailwindcss/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [foldkit(), tailwindcss()],
  optimizeDeps: {
    entries: ["src/entry.ts"],
  },
});
```

Alchemy runs Vite programmatically on the project root. The Foldkit
plugin and the rest of your setup are preserved as-is.

:::note[Pinned Effect versions]
Foldkit pins its `effect` peer dependency to an exact version.
Alchemy runs your app's own Vite build with your app's own
`node_modules`, so that pin is between Foldkit and your package
manager — Alchemy imposes no Effect version on your frontend.
:::

## Declare the Website

Declare the site as a module-level const (rather than inline in the
Stack):

```typescript
// alchemy.run.ts
import * as Fly from "alchemy/Fly";

export const Website = Fly.Website.Foldkit("Website");
```

For an app in a subdirectory of a monorepo, point `rootDir` at it:

```typescript
export const Website = Fly.Website.Foldkit("Website", {
  rootDir: "applications/web",
});
```

## Add it to the Stack

Yield the site from your Stack and return its URL:

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Effect from "effect/Effect";

export default Alchemy.Stack(
  "MyFoldkitSite",
  {
    providers: Fly.providers(),
    state: Alchemy.localState(),
  },
  Effect.gen(function* () {
    const site = yield* Website;
    return { url: site.url };
  }),
);
```

`site.url` is `https://{app}.fly.dev`. The site also exposes `app`,
`service`, `ip`, and `certificate` — they are `undefined` under
`alchemy dev`.

## Add environment variables

A Foldkit SPA has no server of its own, so anything it needs from
the rest of your Stack is baked into the bundle at build time — pass
a `VITE_`-prefixed key in top-level `env`. Values must be strings (or
`Redacted`); resolve other resources' URLs before passing them.

```diff lang="typescript"
// alchemy.run.ts
export const Website = Fly.Website.Foldkit("Website", {
+  env: {
+    VITE_API_URL: "https://api.example.com",
+  },
});
```

The values are copied onto `process.env` before the Vite build and
onto the Machine. Client code reads the inlined value:

```typescript
// src/vite-env.d.ts
/// <reference types="vite/client" />

interface ImportMetaEnv {
  readonly VITE_API_URL: string;
}
```

```typescript
const apiUrl = import.meta.env.VITE_API_URL;
```

## Deep links

A browser-only Foldkit app that uses URL routing (`Runtime.makeApplication` with
`route`, `onUrlRequest`, and `onUrlChange`) resolves routes on the
client, so a deep link like `/counter/42` arrives as a request for a
file that doesn't exist.

For browser-only builds, `Foldkit` defaults `assets.notFoundHandling` to
`"single-page-application"`, which returns `index.html` (200) for
unmatched paths so the Foldkit runtime can resolve the route. Use
`"404-page"` to serve a real 404 instead:

```typescript
export const Website = Fly.Website.Foldkit("Website", {
  assets: { notFoundHandling: "404-page" },
});
```

## Server rendering and prerendering

Use Foldkit 0.167.0, `@foldkit/vite-plugin` 0.27.0 and Effect 4.0.0. Keep rendering
configuration in your app's `vite.config.ts`:

```typescript
import { foldkit } from "@foldkit/vite-plugin";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [foldkit({
    ssr: {
      serverEntry: "/src/entry.server.ts",
      clientEntry: "/src/entry.ts",
      build: { prerender: true },
    },
  })],
});
```

Import CSS from the client entry and export `renderDocument = Server.renderDocument`
alongside `renderPage` in the server entry. SSR/SSG builds generate their complete
HTML documents from code; remove the source `index.html`. Export `prerenderPaths`
when prerendering is enabled. Use `build: true` for SSR without prerendering. See
[Foldkit's server rendering guide](https://foldkit.dev/core/server-rendering)
for the application contract.

The same Website declaration detects the generated handler automatically.
GET and HEAD requests serve assets and prerendered pages first, including `/`
when it was prerendered. Remaining requests go to Foldkit's handler; POST
requests bypass static assets. SSG deployments retain the generated handler
for paths that were not prerendered, matching the SvelteKit/TanStack Start path.

Browser-only builds keep SPA fallback. An explicit `assets.notFoundHandling`
override takes precedence. Avoid SPA fallback on SSR apps unless intentional:
a prerendered `index.html` would then answer unmatched page requests.

Server code reads private runtime values from `process.env`; `VITE_*` values
remain public build-time browser configuration. Custom Foldkit client/server
output directories are read from the completed build metadata and packaged
together. `vite.outDir`, when supplied, places SSR outputs under `client/` and
`server/` in that directory.

## Local dev

`alchemy dev` runs Vite's own dev server (Foldkit's live reload
and devtools) instead of deploying; `site.url` is the local address and
no Fly App, Service, IP, or certificate is created. Wrap the site in
`Alchemy.remote()` to deploy the live Service even during dev.

Pin the dev server's address when several apps run in one Stack:

```typescript
export const Website = Fly.Website.Foldkit("Website", {
  dev: { host: "127.0.0.1", port: 5180, strictPort: true },
});
```

## Custom domain

Pass a hostname to request ACME (`Fly.Certificate`) on the App.
`url` becomes `https://{domain}`. v1 expects that DNS already points
at the App.

```typescript
const site = yield* Fly.Website.Foldkit("Web", {
  domain: "app.example.com",
});
```
