`Fly.Website.Vinext` deploys a [vinext](https://vinext.dev) app to
Fly as a long-running Node process. It runs `vinext build`, then
vinext's production server (`startProdServer`) on port 3000:

- one [`Fly.App`](/fly/compute/apps) (created if `app` is omitted)
  and a [`Fly.Service`](/fly/compute/services) running Node on a
  Machine
- `dist/` baked into the image; `vinext` installed unbundled

This is **not** OpenNext and **not** the Cloudflare Worker path.
Server components and route handlers read `process.env`.

Register `vinext()` in `vite.config.ts`. Do **not** add
`@cloudflare/vite-plugin` or `@vinext/cloudflare` adapters.

ISR / `"use cache"` persist in Redis — not Cloudflare KV. Register
`redisAdapter()` and pass a `Fly.Redis` to the site so Alchemy writes
`REDIS_URL` as an App secret. Missing URL (local `vinext start`) falls
back to memory.

```typescript
import { redisAdapter } from "@alchemy.run/frontend-frameworks/vinext/cache/redis";
import { defineConfig } from "vite";
import vinext from "vinext";

export default defineConfig({
  plugins: [vinext({ cache: { data: redisAdapter() } })],
});
```

```typescript
import * as Fly from "alchemy/Fly";

const redis = yield* Fly.Redis("Cache", { eviction: true });
export const Website = Fly.Website.Vinext("Website", {
  redis,
  env: {
    GREETING: "Hello from vinext on Fly!",
  },
});
```

```typescript
// app/api/hello/route.ts
export function GET() {
  return Response.json({ hello: "world" });
}
```

`alchemy dev` runs `vinext dev`; no Fly resources are created.
