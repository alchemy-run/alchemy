A [`Fly.App`](/providers/fly/app) is a global namespace in your
account. It contains Machines, Services, Secrets, IPs, and
certificates.

## Create an App

Alchemy generates a unique name unless you pass one.

```typescript
const site = yield* Fly.App("Site");
```

Pass `name` when you need a stable `fly.dev` hostname.

```typescript
const site = yield* Fly.App("Site", {
  name: "my-site",
  orgSlug: "my-org",
  enableSubdomains: true,
});
```

`url` is `https://{appName}.fly.dev`. Nothing answers there until a
[Service](/fly/compute/services) or
[Machine](/fly/compute/machines) publishes a proxy service and the
App has an [IP assignment](/fly/networking).

## Module-scope declarations

Declare the App once. Pass it into every child.

```typescript
// src/app.ts
import * as Fly from "alchemy/Fly";

export const Site = Fly.App("Site");
```

Resource-valued props accept the resource or an Effect producing
it. Do not unwrap it just to pass it along.

## Reconcile

Changing `name`, `orgSlug`, or `network` replaces the App. A
same-name replace deletes the old App first. Fly cannot have two
Apps with the same name.

`enableSubdomains: true` turns on `*.{appName}.fly.dev`. It is
create-only. Flipping it later is ignored.

Org defaults to the current token. Isolated `network` is an
optional 6PN name.

Fly Apps have no labels. Alchemy stamps ownership into generated
names (and into Machine metadata and Secret names) so `list()` and
nuke only see rows we created. Prefer omitting `name` in tests and
CI.

`alchemy destroy` deletes children, then the App.
