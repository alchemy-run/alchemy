Google Cloud is a public cloud for compute, storage, databases, networking, data analytics and AI, in regions around the world. It's strongest at data and machine learning, with BigQuery, Spanner, and Vertex AI with Gemini, and at Kubernetes, with GKE.

Everything lives in a project, and IAM grants each identity, including the service accounts your code runs as, a role on each resource.

## A taste

A Firestore database is a declaration:

```typescript title="src/links.ts"
import * as GCP from "@alchemy.run/gcp";

export const Links = GCP.Firestore.Database("Links", { type: "FIRESTORE_NATIVE" });
```

A Cloud Run service binds it, and reads and writes documents as plain objects. The binding grants the service's account access to that one database:

```typescript title="src/api.ts"
import * as GCP from "@alchemy.run/gcp";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/http/HttpServerResponse";
import { Links } from "./links.ts";

export default class Api extends GCP.Function<Api>()(
  "Api",
  { main: import.meta.url, invokerIamDisabled: true },
  Effect.gen(function* () {
    const db = yield* GCP.Firestore.ReadWriteDatabase(Links);
    return {
      fetch: Effect.gen(function* () {
        yield* db.set("links/demo", { url: "https://alchemy.run" });
        const link = yield* db.get("links/demo");
        return yield* HttpServerResponse.json(link?.fields ?? {});
      }).pipe(Effect.orDie),
    };
  }).pipe(Effect.provide(GCP.Firestore.ReadWriteDatabaseHttp)),
) {}
```

And the Stack deploys it to the project your profile names:

```typescript title="alchemy.run.ts"
import * as Alchemy from "alchemy";
import * as GCP from "@alchemy.run/gcp";
import * as Effect from "effect/Effect";
import Api from "./src/api.ts";

export default Alchemy.Stack(
  "MyApp",
  { providers: GCP.providers(), state: GCP.state() },
  Effect.gen(function* () {
    const api = yield* Api;
    return { url: api.uri };
  }),
);
```

## Where to start

**New to Google Cloud?** [What is GCP?](/gcp/what-is-gcp) walks through projects, APIs, regions, IAM, runtimes, events and networks, once each, and shows how Alchemy models every one.

**Want to build one?** The [tutorial](/gcp/tutorial/part-1) goes from an empty folder to a tested service deployed from CI, one step at a time. Start with [Setup](/gcp/setup) to connect your project.

**Want the whole picture?** The chapters follow the shape of Google Cloud itself. Start with who may do what: [IAM & bindings](/gcp/security/iam), [Secret Manager & KMS](/gcp/security/secrets-kms) and [Federated identity](/gcp/security/federated-identity). Then where code runs: [Choosing a runtime](/gcp/compute/choosing-a-runtime), [Cloud Run](/gcp/compute/cloud-run), [Cloud Run jobs](/gcp/compute/jobs), [Worker pools](/gcp/compute/worker-pools), [Cloud Functions](/gcp/compute/cloud-functions) and [GKE](/gcp/compute/gke). Then what it stores: [Firestore](/gcp/data/firestore), [Cloud Storage](/gcp/data/storage), [Cloud SQL](/gcp/data/cloud-sql), [BigQuery](/gcp/data/bigquery) and [Memorystore](/gcp/data/memorystore). Then how work flows: [Pub/Sub](/gcp/messaging/pubsub), [Cloud Scheduler](/gcp/messaging/scheduler), [Storage events](/gcp/messaging/storage-events) and [Eventarc](/gcp/messaging/eventarc). And finally the network and how you watch it: [VPC & private networking](/gcp/networking/vpc), [Private services](/gcp/networking/private-services) and [Logging & Monitoring](/gcp/observability/monitoring).

**Building a website or an API?** [Websites](/gcp/frontend/websites) covers every supported framework on Cloud Run. [Effect HTTP API](/gcp/apis/effect-http-api) and [Effect RPC](/gcp/apis/effect-rpc) serve typed APIs. [Vertex AI](/gcp/ai/vertex-ai) calls Gemini with no API key.

Every resource is in the generated [API reference](/providers). Alchemy manages infrastructure, not people's content, so APIs whose objects are a person's data, like Gmail, Drive or Calendar, aren't resources, and neither are the advertising APIs that need a user's OAuth consent.
