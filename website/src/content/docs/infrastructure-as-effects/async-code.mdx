---
title: Calling Effect from Async Code
description: Expose Effect services as plain Promise functions to an existing app, a server Alchemy doesn't deploy, an async handler, or a browser, and call Promise libraries from inside Effect.
---

Not every caller is an Effect. An existing Express app, a Next.js route,
or a browser callback wants to `await` a function and get a value back:

```typescript
await enqueueMail({ to, subject, text });
```

This page shows how to keep Effect inside a module and hand callers a
plain Promise API. It also covers where Alchemy
[Bindings](/infrastructure-as-effects/binding) work and where they
don't, since that decides how the module reaches your cloud resources.

## Build one runtime per process

A `ManagedRuntime` builds a Layer once and runs Effects against it. Make
it at module scope, so every call shares the same services:

```typescript
// mail.ts
import * as Context from "effect/Context";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import * as ManagedRuntime from "effect/ManagedRuntime";

export interface Mail {
  to: string;
  subject: string;
  text: string;
}

class Mailer extends Context.Service<
  Mailer,
  { enqueue: (mail: Mail) => Effect.Effect<void> }
>()("Mailer") {}

const MailerLive = Layer.succeed(Mailer, {
  enqueue: (mail) => Effect.log(`queued mail to ${mail.to}`),
});

const runtime = ManagedRuntime.make(MailerLive);
```

The Layer is built lazily, on the first call, and reused after that.
Don't make a runtime per call: you'd rebuild every service, and
connections, each time.

## Export functions, not the runtime

Wrap each operation in a function that returns `runtime.runPromise(...)`.
Callers see only Promises:

```typescript
// mail.ts (continued)
export const enqueueMail = (mail: Mail) =>
  runtime.runPromise(
    Effect.gen(function* () {
      const mailer = yield* Mailer;
      yield* mailer.enqueue(mail);
    }),
  );
```

```typescript
// routes.ts
import { enqueueMail } from "./mail.ts";

app.post("/signup", async (req, res) => {
  await enqueueMail({ to: req.body.email, subject: "Welcome", text: "Hi!" });
  res.sendStatus(202);
});
```

Effect, Layers, and Alchemy stay inside `mail.ts`. Nothing in the app
imports `effect`.

## Release the runtime on shutdown

`dispose` runs the Layer's finalizers, which closes pools and sockets the
services opened. Call it when the process stops:

```typescript
// mail.ts (continued)
process.on("SIGTERM", () => {
  void runtime.dispose();
});
```

In a test or script, `await using` disposes it for you when the block
exits:

```typescript
await using runtime = ManagedRuntime.make(MailerLive);
```

## Handle failures across the boundary

`runPromise` rejects when the Effect fails. A typed failure rejects with
the error value itself, such as a tagged error with its `_tag`:

```typescript
try {
  await enqueueMail({ to, subject, text });
} catch (error) {
  console.error("enqueue failed", error);
}
```

When the caller should handle failures as values instead of exceptions,
export the `Exit` with `runPromiseExit`:

```typescript
export const tryEnqueueMail = (mail: Mail) =>
  runtime.runPromiseExit(
    Effect.gen(function* () {
      const mailer = yield* Mailer;
      yield* mailer.enqueue(mail);
    }),
  );
```

```typescript
const exit = await tryEnqueueMail({ to, subject, text });
if (exit._tag === "Failure") {
  console.error(exit.cause);
}
```

## Bindings need an Alchemy Runtime

Bindings like `AWS.SQS.SendMessage(queue)` only work inside a
[Runtime](/infrastructure-as-effects/runtime) that Alchemy deploys: a
Lambda Function, ECS Task, Web Function, Worker, and so on. A binding
attaches itself to that host. At deploy time it grants `sqs:SendMessage`
on the host's IAM role and records the queue URL in the host's
environment. At runtime it reads the URL back from that environment.

A process Alchemy didn't deploy has no host, so there's nowhere to
grant the permission and nothing to read the URL from. Building the
binding's Layer there fails with an unmet `RuntimeContext` requirement.

## Call AWS from an app Alchemy doesn't deploy

From your own server, call the cloud API directly with
[distilled](https://github.com/alchemy-run/distilled), the Effect SDK
Alchemy is built on, and pass the resource's identifiers in as config.
Return the queue URL from the Stack:

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as AWS from "@alchemy.run/aws";
import * as Effect from "effect/Effect";

export default Alchemy.Stack(
  "MyApp",
  { providers: AWS.providers(), state: AWS.state() },
  Effect.gen(function* () {
    const queue = yield* AWS.SQS.Queue("Mail");
    return { mailQueueUrl: queue.queueUrl };
  }),
);
```

`alchemy deploy` prints the outputs, and
[`alchemy state read`](/cli/state#state-read) prints them as JSON for
scripts. Give the URL to your app as `MAIL_QUEUE_URL`.

Then send with distilled's SQS client instead of a binding. Install
`@distilled.cloud/aws` and provide an HTTP client, region, and
credentials:

```typescript
// mail.ts
import { Credentials, Region } from "@distilled.cloud/aws";
import * as sqs from "@distilled.cloud/aws/sqs";
import * as Config from "effect/Config";
import * as Effect from "effect/Effect";
import * as FetchHttpClient from "effect/http/FetchHttpClient";
import * as Layer from "effect/Layer";
import * as ManagedRuntime from "effect/ManagedRuntime";

export interface Mail {
  to: string;
  subject: string;
  text: string;
}

const AwsLive = Layer.mergeAll(
  FetchHttpClient.layer,
  Region.fromEnv(),
  Credentials.fromChain(),
);

const runtime = ManagedRuntime.make(AwsLive);

const send = Effect.fn("enqueueMail")(function* (mail: Mail) {
  const QueueUrl = yield* Config.String("MAIL_QUEUE_URL");
  return yield* sqs.sendMessage({
    QueueUrl,
    MessageBody: JSON.stringify(mail),
  });
});

export const enqueueMail = (mail: Mail) => runtime.runPromise(send(mail));

process.on("SIGTERM", () => {
  void runtime.dispose();
});
```

`Credentials.fromChain()` uses the standard AWS credential chain:
environment variables, profiles, SSO, or the role of the machine the
app runs on. That identity needs `sqs:SendMessage` on the queue. You
grant it yourself, because Alchemy doesn't know about the app.

Failures are typed. `sendMessage` fails with tags like
`QueueDoesNotExist` and `RequestThrottled`, so you can retry or recover
inside `send` before the Promise boundary:

```typescript
const send = Effect.fn("enqueueMail")(function* (mail: Mail) {
  const QueueUrl = yield* Config.String("MAIL_QUEUE_URL");
  return yield* sqs.sendMessage({
    QueueUrl,
    MessageBody: JSON.stringify(mail),
  }).pipe(
    Effect.retry({
      while: (error) => error._tag === "RequestThrottled",
      times: 3,
    }),
  );
});
```

If you'd rather Alchemy own the permission, move the code that sends
mail into an Alchemy Runtime and use the binding there. See
[Bindings](/infrastructure-as-effects/binding).

## Async handlers Alchemy deploys

A Runtime doesn't have to be an Effect. A Cloudflare Worker can be a
plain `async fetch` with its bindings on the `env` prop, typed with
`InferEnv`. See
[Effect handlers vs async handlers](/infrastructure-as-effects/runtime#effect-handlers-vs-async-handlers).

On AWS, a [Web Function](/aws/compute/web-functions#bring-an-existing-server)
runs your existing server as it is. It receives plain `env` values, such
as a queue URL, but not bindings, so call AWS from it with distilled as
shown above.

## Inside a Cloudflare Worker, build per request

A module-scope runtime is right for a long-lived process. In a Worker,
sockets and streams belong to the request that opened them, and another
request can't use them. If the Layer opens connections, such as a
WebSocket RPC client or a database pool, provide it inside each request:

```typescript
// src/worker.ts
import * as Effect from "effect/Effect";
import { CounterClient, CounterClientLive } from "./counter-client.ts";

export default {
  async fetch() {
    const title = await Effect.runPromise(
      Effect.gen(function* () {
        const counter = yield* CounterClient;
        return yield* counter.getTitle({});
      }).pipe(Effect.provide(CounterClientLive)),
    );
    return new Response(title);
  },
};
```

The connection opens when the Effect starts and closes when it
finishes. `CounterClient` comes from
[Connect over a WebSocket](/cloudflare/apis/effect-rpc#connect-over-a-websocket).

## In the browser

A browser session is a long-lived process too. Keep one `ManagedRuntime`
for the session and dispose it on teardown. See
[Keep a client for a browser session](/cloudflare/apis/effect-rpc#keep-a-client-for-a-browser-session).

## Call Promise libraries from Effect

The other direction comes up inside every Runtime: an SDK that returns
Promises. Wrap the call with `Effect.tryPromise` and turn the rejection
into a tagged error:

```typescript
import * as Data from "effect/Data";
import * as Effect from "effect/Effect";

class FetchFailed extends Data.TaggedError("FetchFailed")<{
  readonly cause: unknown;
}> {}

const getJson = (url: string) =>
  Effect.tryPromise({
    try: (signal) => fetch(url, { signal }).then((res) => res.json()),
    catch: (cause) => new FetchFailed({ cause }),
  });
```

Pass `signal` through. When the Effect is interrupted, Effect aborts the
signal and the request is cancelled.
