A **sink** is a [binding](/infrastructure-as-effects/binding) for
writing. It exposes a resource as an Effect
[`Sink`](https://effect.website/docs/sink/introduction/) that drains a
`Stream` into the resource's batch API, such as `SendMessageBatch`,
`PublishBatch`, or `PutRecords`. An
[event source](/infrastructure-as-effects/event-sources) is the read-side
dual.

## A sink in a constructor

Like every binding, you declare a sink in the
[Effectful Constructor](/infrastructure-as-effects/runtime#the-effectful-constructor)
and use it in the handlers it returns:

```typescript
import * as AWS from "alchemy/AWS";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import * as Stream from "effect/Stream";
import { HttpServerRequest } from "effect/unstable/http/HttpServerRequest";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";
import { OutboundQueue } from "./queue.ts";

export default class Publisher extends AWS.Lambda.Function<Publisher>()(
  "Publisher",
  { main: import.meta.url, functionUrl: true },
  Effect.gen(function* () {
    const sink = yield* AWS.SQS.QueueSink(OutboundQueue);
    // → Sink<void, QueueSinkEntry, readonly QueueSinkEntry[], QueueSinkError>
    // → policy: sqs:SendMessage + sqs:SendMessageBatch on OutboundQueue's ARN

    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const body = (yield* request.json) as { messages: string[] };

        yield* Stream.fromIterable(body.messages).pipe(
          // a SendMessageBatchRequestEntry without its Id
          Stream.map((message) => ({ MessageBody: message })),
          Stream.run(sink),
        );

        return yield* HttpServerResponse.json({ count: body.messages.length });
      }),
    };
  }).pipe(
    Effect.provide(
      // QueueSinkHttp implements QueueSink over the SendMessageBatch contract
      AWS.SQS.QueueSinkHttp.pipe(
        Layer.provideMerge(AWS.SQS.SendMessageBatchHttp),
      ),
    ),
  ),
) {}
```

You don't read a `QUEUE_URL` env var or chunk `SendMessageBatchCommand`
calls by hand. The sink assigns each batch entry's `Id`, and the layer
attaches least-privilege statements scoped to the queue's ARN.

`AWS.SNS.TopicSink` and `AWS.Kinesis.StreamSink` work the same way. The
generated [SQS](/providers/AWS/SQS), [SNS](/providers/AWS/SNS), and
[Kinesis](/providers/AWS/Kinesis) reference pages list each sink's
element type, batch limits, and IAM actions.

## Batching and failures

A sink drains its input chunk by chunk. It splits each chunk into
batches that fit the API's limits, sends them one at a time in order,
and checks the per-entry results:

- **Transient failures** are resent up to five times, with exponential
  backoff from 200 ms. For SQS and SNS these are entries with
  `SenderFault: false`, and Kinesis treats every failed record as
  transient.
- **Permanent rejections** are dropped with a warning log. Only
  `QueueSink` and `TopicSink` drop entries, and only those with
  `SenderFault: true`.
- **Exhausted retries** fail the sink with a `BatchRetryExhaustedError`
  whose `entries` field holds the stranded entries.
- **A failed API call** fails the sink with the batch API's own error,
  such as `SendMessageBatchError`.

A sink never makes a batch larger than the chunk it receives. Rechunk
the stream to send smaller batches:

```typescript
yield* Stream.fromIterable(messages).pipe(
  Stream.map((message) => ({ MessageBody: message })),
  Stream.rechunk(5), // at most 5 messages per SendMessageBatch call
  Stream.run(sink),
);
```

## Source → transform → sink

A sink composes with an [event source](/infrastructure-as-effects/event-sources).
Every step is a `Stream` or a `Sink`, so the whole pipeline is one
expression inside the constructor:

```typescript
// Alchemy does not unmarshall DynamoDB records, so describe the raw shape
type OrderImage = { id: { S: string }; status: { S: string } };

export default class OrderRelay extends AWS.Lambda.Function<OrderRelay>()(
  "OrderRelay",
  { main: import.meta.url },
  Effect.gen(function* () {
    const sink = yield* AWS.SQS.QueueSink(OutboundQueue);

    yield* AWS.DynamoDB.consumeTableChanges<OrderImage>(
      OrdersTable,
      { streamViewType: "NEW_AND_OLD_IMAGES", startingPosition: "LATEST" },
      (records) =>
        records.pipe(
          Stream.map((r) => r.dynamodb.NewImage),
          // the type guard also drops records with no NewImage, such as deletes
          Stream.filter(
            (image): image is OrderImage => image?.status.S === "PAID",
          ),
          Stream.map((image) => ({
            MessageBody: JSON.stringify({ orderId: image.id.S }),
          })),
          Stream.run(sink),
          Effect.orDie,
        ),
    );
  }).pipe(
    Effect.provide(
      Layer.mergeAll(AWS.Lambda.TableEventSource, AWS.SQS.QueueSinkHttp).pipe(
        Layer.provideMerge(AWS.SQS.SendMessageBatchHttp),
      ),
    ),
  ),
) {}
```

An event-source handler's error type is `never`. End the pipeline with
`Effect.orDie`, or handle every error the sink can fail with, for
example `Effect.catchTag("BatchRetryExhaustedError", ...)` to decide
what happens to stranded entries.

The provided layers attach both sides of the policy to the Function's
role and wire the event-source mapping:

- `dynamodb:DescribeStream`, `GetRecords`, and `GetShardIterator` on
  `OrdersTable`'s stream.
- `sqs:SendMessage` and `SendMessageBatch` on `OutboundQueue`.

`Effect.retry`, `Stream.throttle`, `Stream.groupedWithin`, and
`Stream.mapEffect` drop in anywhere along the chain, the same as in a
plain Effect program.
