Every Alchemy runtime has OpenTelemetry export built in. To ship the
spans, logs, and metrics your Effect code already emits, provide an
exporter layer on the runtime. Without one, nothing exports, and
Effect's default no-op tracer keeps instrumentation free.

## Export to an OTLP endpoint

`Alchemy.Telemetry.layerOtlp` sends every signal to any OTLP/HTTP
backend. Merge it into the runtime's single `Effect.provide` next to
your other binding layers:

```typescript
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Config from "effect/Config";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";

const Honeycomb = Layer.unwrap(
  Effect.gen(function* () {
    // Redacted values bind as secrets, never as plaintext.
    const key = yield* Config.Redacted("HONEYCOMB_API_KEY");
    return Alchemy.Telemetry.layerOtlp({
      url: "https://api.honeycomb.io", // /v1/{traces,logs,metrics} is appended
      headers: { "x-honeycomb-team": key },
      serviceName: "checkout", // default: the Worker's physical name
    });
  }),
);

export default Cloudflare.Worker(
  "Worker",
  { main: import.meta.url },
  Effect.gen(function* () {
    // ...
  }).pipe(
    Effect.provide(
      Layer.mergeAll(Cloudflare.R2.ReadWriteBucketBinding, Honeycomb),
    ),
  ),
);
```

`layerOtlp` is a [binding](/infrastructure-as-effects/binding) layer.
At deploy time it binds the URL and headers onto the host, and at
runtime the exporter reads them back.

### Send each signal to its own endpoint

URLs and header values accept plain values, `Redacted` values, or
resource [Outputs](/infrastructure-as-code/outputs). A per-signal entry
takes precedence over the base `url` and its `headers`:

```typescript
Alchemy.Telemetry.layerOtlp({
  // a per-signal entry sends only its own headers
  traces: { url: collector.tracesUrl, headers: { authorization: token } },
  logs: { url: collector.logsUrl, headers: { authorization: token } },
  // no base url and no metrics entry, so metrics don't export
});
```

## Export to Axiom

`Axiom.Telemetry` wraps `layerOtlp`. It takes an ingest `ApiToken` and
one `Dataset` per signal, and builds the endpoints and auth headers:

```typescript
import * as Axiom from "alchemy/Axiom";
import { Ingest, Logs, Traces } from "./observability.ts";

Effect.provide(
  Layer.mergeAll(
    Cloudflare.R2.ReadWriteBucketBinding,
    // omit a signal (here metrics) to skip exporting it
    Axiom.Telemetry({ token: Ingest, traces: Traces, logs: Logs }),
  ),
);
```

See [Ship Worker telemetry to Axiom](/cloudflare/observability/axiom-observability)
to declare the datasets and a least-privilege token.

On Cloudflare, [`Cloudflare.Telemetry()`](/cloudflare/observability/workers-tracing)
mirrors Effect spans into Workers Observability instead, and Cloudflare
owns sampling and export.

## Send to several destinations

Exporter layers compose, and every destination receives the signals
it configures. Telemetry is serialized once, so trace and span IDs
match across backends:

```typescript
Effect.provide(
  Layer.mergeAll(
    Cloudflare.R2.ReadWriteBucketBinding,
    // traces and logs
    Axiom.Telemetry({ token: Ingest, traces: Traces, logs: Logs }),
    // all three signals
    Alchemy.Telemetry.layerOtlp({
      url: "https://collector.internal.example.com",
      headers: { "x-api-key": apiKey },
    }),
  ),
);
```

A destination that rejects an export is logged and skipped. One
healthy destination keeps the exporter running. If the platform sets
the standard `OTEL_EXPORTER_OTLP_*` variables, they add one more
destination.

## What gets exported

- **Spans**: from `Effect.withSpan` and `Effect.fn`.
- **Logs**: from `Effect.log` and its level variants.
- **Metrics**: every `Metric` update.
- **HTTP request spans**: each fetch handler gets an `http.server`
  root span with the method, URL, status, and headers. An incoming
  `traceparent` header continues the caller's trace, and `HttpClient`
  requests propagate it onward.
- **Resource attributes**: `service.name` comes from `serviceName`,
  then the deployed Function or Worker's physical name, then the stack
  name. Every signal also carries `alchemy.stack` and `alchemy.stage`,
  so one backend can tell stages apart.

Spans you add nest under the request span:

```typescript
const object = yield* bucket
  .get(key)
  .pipe(Effect.withSpan("bucket.get", { attributes: { key } }));
```

## When telemetry flushes

Per-event runtimes build the exporters into each event's request
scope and flush when that scope closes. This covers Worker fetch,
queue, cron, and RPC handlers, Durable Object calls, Workflow runs,
and Lambda invocations.

- **Cloudflare**: the flush runs in `ctx.waitUntil` after the response
  is sent, so it adds no latency.
- **Lambda**: the flush settles inline before the invocation returns.
- **Server runtimes** (Cloudflare Containers, ECS Tasks, EC2 hosts,
  Lambda microVMs): exporters start once per process, batch on the
  standard intervals, and flush at graceful shutdown.

On workerd, timers and fetches are pinned to the request that created
them, so a process-global batching exporter would stop when that
request ends. See [Phases](/infrastructure-as-effects/phases#instance-scope-vs-request-scope)
for instance and request scope.

## Use a custom exporter

`Alchemy.Telemetry.layer` installs any layer that provides a `Tracer`,
loggers, or metric exporters, such as Effect's
`effect/unstable/observability` modules. It is built per event, so it
flushes on scope close like the built-in exporter:

```typescript
import * as FetchHttpClient from "effect/unstable/http/FetchHttpClient";
import * as OtlpSerialization from "effect/unstable/observability/OtlpSerialization";
import * as OtlpTracer from "effect/unstable/observability/OtlpTracer";

Alchemy.Telemetry.layer(
  OtlpTracer.layer({
    url: "https://collector.example.com/v1/traces",
    // A periodic export mid-event races the scope close and drops the batch.
    exportInterval: "1 hour",
  }).pipe(
    Layer.provide([OtlpSerialization.layerJson, FetchHttpClient.layer]),
  ),
);
```

Custom loggers and metric exporters merge with the OTLP destinations.
A custom `Tracer` replaces the built-in one, because Effect has a
single tracer service.
