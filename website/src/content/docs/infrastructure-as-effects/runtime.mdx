A **runtime** is a [resource](/infrastructure-as-code/resource) that
carries the code it runs, such as a Cloudflare Worker, Lambda Function,
ECS Task, Container, or Server. The props are the cloud configuration,
and the Effect is the code. This page takes apart the running example
from [What is Alchemy?](/what-is-alchemy):

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

export const Uploads = Cloudflare.R2.Bucket("Uploads");

export default Cloudflare.Worker(
  "Api",
  // bundle this file's default export (the Worker itself) as the script
  { main: import.meta.url },
  Effect.gen(function* () {
    const bucket = yield* Cloudflare.R2.ReadWriteBucket(Uploads);

    return {
      fetch: Effect.gen(function* () {
        const obj = yield* bucket.get("hello.txt");
        return obj
          ? HttpServerResponse.text(yield* obj.text())
          : HttpServerResponse.text("Not found", { status: 404 });
      }),
    };
  }).pipe(Effect.provide(Cloudflare.R2.ReadWriteBucketBinding)),
);
```

One deploy ships both the infrastructure and the code. Most runtimes
need no props beyond `main`, because everything else they depend on
comes in through bindings.

## The effectful constructor

Every runtime is declared with the same Effect. It binds the resources
it needs, then returns the interface it exposes:

```typescript
Effect.gen(function* () {
  // Construction phase: runs at deploy time and again at cold start
  const bucket = yield* Cloudflare.R2.ReadWriteBucket(Uploads);

  return {
    // Runtime phase: runs per request inside the deployed runtime
    fetch: Effect.gen(function* () {
      /* use bucket */
    }),
  };
});
```

This is the **Effectful Constructor**. A Worker or Lambda Function
returns its handlers, a Durable Object returns its RPC methods, and a
Workflow returns its run function. [Phases](/infrastructure-as-effects/phases)
covers exactly when each half runs.

Each `yield*` at the top is either a [binding](/infrastructure-as-effects/binding),
which connects a resource and hands back a client, or a service built
by a [layer](/infrastructure-as-effects/layers). A layer owns its own
resources and bindings, so providing it brings them into the deploy.

## What the constructor returns

`fetch` serves HTTP. It is a per-request Effect that yields
`HttpServerRequest` and returns an `HttpServerResponse`:

```typescript
import * as Effect from "effect/Effect";
import { HttpServerRequest } from "effect/unstable/http/HttpServerRequest";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

Effect.gen(function* () {
  return {
    fetch: Effect.gen(function* () {
      const request = yield* HttpServerRequest;
      return HttpServerResponse.text(`hello from ${request.url}`);
    }),
  };
});
```

Any other method that returns an `Effect` or a `Stream` becomes an RPC
method. A resource that binds this Worker calls `greet` through a typed
client:

```typescript
export default class Greeter extends Cloudflare.Worker<Greeter>()(
  "Greeter",
  { main: import.meta.url },
  Effect.gen(function* () {
    return {
      greet: (name: string) => Effect.succeed(`hello ${name}`),
      fetch: Effect.gen(function* () {
        return HttpServerResponse.text("ok");
      }),
    };
  }),
) {}
```

The call has no schema and no runtime validation. This is
[Schemaless RPC](/apis/schemaless), the default for internal calls, and
that page shows the calling side. The [APIs](/apis) section adds
schema'd surfaces for trust boundaries.

## Three ways to declare a runtime

### Inline

The inline form is enough when nothing else needs to reference the
Worker by name:

```typescript
export default Cloudflare.Worker("Api", { main: import.meta.url }, effect);
```

### Class

A class makes the type nominal, so hovers, errors, and stack outputs
say `Api` instead of an anonymous shape:

```typescript
export default class Api extends Cloudflare.Worker<Api>()(
  "Api",
  { main: import.meta.url },
  effect,
) {}
```

### Tag and layer

The third form splits identity from implementation. The class declares
only a **Tag**, and `.make(props, effect)` produces the implementation
layer:

```typescript
// src/Api.ts
export class Api extends Cloudflare.Worker<Api, {}>()("Api") {}

export default Api.make(
  { main: import.meta.url },
  Effect.gen(function* () {
    /* the Effectful Constructor */
  }),
);
```

You provide the layer to the stack, not to another Worker:

```typescript
// alchemy.run.ts
import ApiLive, { Api } from "./src/Api.ts";

export default Alchemy.Stack(
  "MyApp",
  { providers: Cloudflare.providers(), state: Cloudflare.state() },
  Effect.gen(function* () {
    const api = yield* Api;
    return { url: api.url };
  }).pipe(Effect.provide(ApiLive)),
);
```

Other runtimes bind to the Tag. Importing a Tag pulls in no runtime
code, so a Worker that binds `Api` doesn't bundle `Api`'s
implementation, which may target a different runtime.

One Tag can also have several implementations, and each consumer
provides the one that fits. This split also makes
[circular bindings](/infrastructure-as-effects/circular-bindings)
possible.

## Async handlers

A Cloudflare Worker can also run a plain `async fetch` module. You
declare its bindings on the `env` prop, and `Cloudflare.InferEnv` types
the handler's `env`. See
[Workers › Async Workers](/cloudflare/compute/workers#async-workers).

Both styles deploy through the same provider and produce the same
artifact. The Effect style adds typed errors, composable retries, and
swappable layers, and the async style fits existing handler code.
