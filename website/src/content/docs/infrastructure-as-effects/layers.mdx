A [**layer**](https://effect.website/docs/requirements-management/layers/)
is Effect's unit of service construction. It defines how to build a
service, so you can swap in a different storage backend or a different
cloud without touching the code that uses it.

In Alchemy, a layer can contain [resources](/infrastructure-as-code/resource)
and [bindings](/infrastructure-as-effects/binding). A shared service
then carries its own infrastructure and permissions, whether you share
it within your codebase, across packages, or on npm.

## The contract

A service is a `Context.Service`, a typed tag that names a capability:

```typescript
import * as Alchemy from "alchemy";
import * as Context from "effect/Context";
import * as Data from "effect/Data";
import * as Effect from "effect/Effect";

export interface Job {
  id: string;
  status: string;
}

export class JobError extends Data.TaggedError("JobError")<{
  cause: unknown;
}> {}

export class JobService extends Context.Service<
  JobService,
  {
    getJob(id: string): Effect.Effect<Job, JobError, Alchemy.RuntimeContext>;
  }
>()("JobService") {}
```

Consumers write `yield* JobService` and get this typed object. The
signature mentions nothing cloud-specific, so every implementation must
map its storage errors to `JobError`. `Alchemy.RuntimeContext` is
covered [below](#the-types-hold-the-boundary).

## The implementation

`Layer.effect(JobService, …)` builds the service. This one declares a
KV Namespace, binds it, and implements the contract against the client:

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";

export const JobServiceKV = Layer.effect(
  JobService,
  Effect.gen(function* () {
    // a real KV Namespace, owned by this layer
    const MyKV = yield* Cloudflare.KV.Namespace("MyKV");
    // a typed client for reading and writing it at runtime
    const kv = yield* Cloudflare.KV.ReadWriteNamespace(MyKV);

    return {
      getJob: Effect.fn(function* (id: string) {
        // Job | null, fails with the KV NamespaceError
        const job = yield* kv
          .get<Job>(id, "json")
          .pipe(Effect.mapError((cause) => new JobError({ cause })));
        if (job === null) {
          return yield* new JobError({ cause: `job ${id} not found` });
        }
        return job;
      }),
    };
  }),
);
```

## The consumer

A Worker yields the service and provides the layer:

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

export default Cloudflare.Worker(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const jobs = yield* JobService;

    return {
      fetch: Effect.gen(function* () {
        return yield* HttpServerResponse.json(yield* jobs.getJob("job-1"));
      }),
    };
  }).pipe(
    Effect.provide(
      // satisfies JobServiceKV's KV binding privately
      JobServiceKV.pipe(Layer.provide(Cloudflare.KV.ReadWriteNamespaceBinding)),
    ),
  ),
);
```

Providing the layer brings the infrastructure in. On the next deploy,
the `MyKV` namespace is created in the [stack](/infrastructure-as-code/stack)
and bound to this Worker. The handler sees only `JobService`.

## Reuse across Workers

A layer is a value. Provide `JobServiceKV` to a second Worker, such as
`Admin`, with the same line:

```typescript
Effect.provide(
  JobServiceKV.pipe(Layer.provide(Cloudflare.KV.ReadWriteNamespaceBinding)),
)
```

`KV.Namespace("MyKV")` has a stable logical ID, so the stack ends up
with one `MyKV` namespace bound to both `Api` and `Admin`.

## Swapping implementations

A second layer can implement `JobService` over different storage. Say
`JobServiceDynamo` declares an `AWS.DynamoDB.Table` and binds it with
`AWS.DynamoDB.GetItem`. An `AWS.Lambda.Function` runs the same handler
on top of it:

```typescript
import * as AWS from "alchemy/AWS";

export default AWS.Lambda.Function(
  "Api",
  { main: import.meta.url, functionUrl: true },
  Effect.gen(function* () {
    const jobs = yield* JobService;

    return {
      fetch: Effect.gen(function* () {
        return yield* HttpServerResponse.json(yield* jobs.getJob("job-1"));
      }),
    };
  }).pipe(
    Effect.provide(
      // was: JobServiceKV.pipe(Layer.provide(Cloudflare.KV.ReadWriteNamespaceBinding))
      // on deploy, GetItemHttp grants dynamodb:GetItem on the table to the role
      JobServiceDynamo.pipe(Layer.provide(AWS.DynamoDB.GetItemHttp)),
    ),
  ),
);
```

A swap works only when every binding inside the layer supports the
host. `AWS.DynamoDB.GetItemHttp` needs AWS `Credentials` and `Region`
and grants IAM to AWS hosts such as Lambda Functions and ECS Tasks, so
`JobServiceDynamo` can't back a Cloudflare Worker. Some AWS bindings
do support a Worker host, such as `AWS.S3.GetObjectHttp` (see the
[S3 reference](/providers/AWS/S3)).

Alchemy's own bindings follow the same tag and layer split. See
[Bindings › A contract and a Layer](/infrastructure-as-effects/binding#a-contract-and-a-layer).

## The types hold the boundary

A layer that needs an environment the host can't supply is a compile
error:

```typescript
export default Cloudflare.Worker(
  "Api",
  { main: import.meta.url },
  handler.pipe(
    Effect.provide(
      JobServiceDynamo.pipe(Layer.provide(AWS.DynamoDB.GetItemHttp)),
    ),
  ),
  // ✗ Type error: the layer requires AWS `Credentials` and `Region`,
  //   which a Cloudflare Worker can't provide
);
```

`Alchemy.RuntimeContext` marks methods that only work inside a deployed
handler (see [Phases](/infrastructure-as-effects/phases)):

```typescript
Effect.gen(function* () {
  const jobs = yield* JobService;

  yield* jobs.getJob("job-1");
  // ✗ Type error: `RuntimeContext` only exists inside handlers

  return {
    fetch: Effect.gen(function* () {
      return yield* HttpServerResponse.json(yield* jobs.getJob("job-1")); // ✓
    }),
  };
});
```

## Composing layers

A typical app provides one layer per capability. Each brings its own
resources into the stack and its own typed service into scope:

```typescript
.pipe(
  Effect.provide(
    // Layer.mergeAll combines independent services
    Layer.mergeAll(
      JobServiceKV,         // provides JobService
      BetterAuthD1,         // provides BetterAuth
      RateLimiterDurable,   // provides RateLimiter
    ).pipe(
      // Layer.provide satisfies their dependencies without exposing them
      Layer.provide(Cloudflare.KV.ReadWriteNamespaceBinding),
    ),
  ),
)
```
