An **event source** is a [binding](/infrastructure-as-effects/binding)
that runs your Function when something happens on a resource, such as a
message on a queue, an object in a bucket, or a changed row in a table.
You name the resource and a handler, and the events arrive as an Effect
`Stream`:

```typescript
import * as AWS from "alchemy/AWS";
import * as Effect from "effect/Effect";
import * as Stream from "effect/Stream";

export const Orders = AWS.SQS.Queue("Orders");

export default AWS.Lambda.Function(
  "OrderProcessor",
  { main: import.meta.url },
  Effect.gen(function* () {
    yield* AWS.SQS.consumeQueueMessages(Orders, (records) =>
      records.pipe(
        Stream.map((record) => record.body),
        Stream.runForEach((body) => Effect.log(`order: ${body}`)),
      ),
    );
  }).pipe(Effect.provide(AWS.Lambda.QueueEventSource)),
);
```

A pure consumer returns nothing from its constructor. It only declares
what it listens to.

## What one call wires

`consumeQueueMessages` replaces the policy, the event-source mapping,
and the handler that unpacks raw events:

- **Permissions**: at deploy time it attaches `sqs:ReceiveMessage`,
  `sqs:DeleteMessage`, and `sqs:GetQueueAttributes` to the Function's
  role, scoped to the queue's ARN.
- **Mapping**: at deploy time it creates the event-source mapping that
  points the queue at this Function.
- **Handler**: at runtime it registers the listener that turns each
  invocation's batch into `records`.

`consumeQueueMessages` is the contract and `AWS.Lambda.QueueEventSource`
is the layer that satisfies it, the same split every binding has. See
[Bindings › A contract and a Layer](/infrastructure-as-effects/binding#a-contract-and-a-layer).

## It's a real Effect Stream

`records` is the same `Stream` as in any Effect program, so every
combinator composes:

```typescript
yield* AWS.SQS.consumeQueueMessages(Orders, (records) =>
  records.pipe(
    Stream.map((record) => JSON.parse(record.body) as { id: string }),
    Stream.groupedWithin(50, "1 second"), // collect up to 50 per second
    Stream.runForEach((orders) => Effect.log(`${orders.length} orders`)),
  ),
);
```

To write a stream into another resource, run it into a
[sink](/infrastructure-as-effects/sinks), the write-side dual of an
event source.

## The same shape on Cloudflare

Consume a Cloudflare Queue the same way. The consumer settings go on
the call, and the handler receives a `Stream` of typed messages:

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import * as Stream from "effect/Stream";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

export const Orders = Cloudflare.Queues.Queue("Orders");

export default Cloudflare.Worker(
  "OrderProcessor",
  { main: import.meta.url },
  Effect.gen(function* () {
    yield* Cloudflare.Queues.consumeQueueMessages<{ text: string }>(
      Orders,
      { batchSize: 10, maxRetries: 3, retryDelay: "1 second" },
      (stream) =>
        Stream.runForEach(stream, (msg) => Effect.log(msg.body.text)),
    );

    return {
      fetch: Effect.gen(function* () {
        return HttpServerResponse.text("ok");
      }),
    };
  }).pipe(Effect.provide(Cloudflare.Queues.EventSourceLive)),
);
```

There is no IAM here. At deploy time the call creates the queue
consumer that dispatches batches to this Worker. At runtime it
registers the `queue` listener.

Batch size, batching windows, retries, and dead-letter queues are
options on each `consume*` call. See
[`QueueEventSource`](/providers/AWS/SQS#queueeventsource) for SQS
batching, [`TableEventSource`](/providers/AWS/DynamoDB#tableeventsource)
for isolating a failing stream record, and
[Queues](/cloudflare/messaging/queues) for Cloudflare retries,
dead-lettering, and per-message `ack()` and `retry()`.

## Not every source is a Stream

A source that delivers one event at a time hands your handler the event
directly. A cron trigger passes one `controller` per fire:

```typescript
export default Cloudflare.Worker(
  "Nightly",
  { main: import.meta.url },
  Effect.gen(function* () {
    yield* Cloudflare.Workers.cron("0 12 * * *", (controller) =>
      Effect.log(`scheduled at ${controller.scheduledTime}`),
    );

    return {
      fetch: Effect.gen(function* () {
        return HttpServerResponse.text("ok");
      }),
    };
  }).pipe(Effect.provide(Cloudflare.Workers.CronEventSourceLive)),
);
```

At deploy time the cron expression is attached to the Worker. At
runtime the `scheduled` listener is registered. GitHub works the same
way, because `consumeRepositoryEvents` creates a repository webhook
that points at the Worker's URL and verifies each delivery's HMAC
signature before calling your handler.

## Every event source

The shape never changes. Only the `consume*` call, the record type,
and the layer you provide on the Function or Worker differ:

- [SQS](/aws/messaging/sqs): `AWS.SQS.consumeQueueMessages(queue, fn)`
  with `AWS.Lambda.QueueEventSource`.
- [Kinesis](/aws/messaging/kinesis):
  `AWS.Kinesis.consumeStreamRecords(stream, props, fn)` with
  `AWS.Lambda.StreamEventSource`.
- [DynamoDB Streams](/aws/messaging/dynamodb-streams):
  `AWS.DynamoDB.consumeTableChanges(table, props, fn)` with
  `AWS.Lambda.TableEventSource`.
- [S3 Events](/aws/messaging/s3-events):
  `AWS.S3.consumeBucketEvents(bucket, fn)` with
  `AWS.Lambda.BucketEventSource`.
- [SNS](/aws/messaging/sns):
  `AWS.SNS.consumeTopicNotifications(topic, fn)` with
  `AWS.Lambda.TopicEventSource`.
- [EventBridge](/aws/messaging/eventbridge):
  `AWS.EventBridge.consumeBusEvents(bus, pattern, fn)` with
  `AWS.Lambda.EventSource`.
- [Cloudflare Queues](/cloudflare/messaging/queues):
  `Cloudflare.Queues.consumeQueueMessages(queue, fn)` with
  `Cloudflare.Queues.EventSourceLive`.
- [Cron](/cloudflare/messaging/cron):
  `Cloudflare.Workers.cron(expression, fn)` with
  `Cloudflare.Workers.CronEventSourceLive`.
- [GitHub Events](/cloudflare/messaging/github-events):
  `GitHub.consumeRepositoryEvents(props, fn)` with
  `Cloudflare.Workers.GitHubRepositoryEventSourceLive`.

EventBridge can also route matching events to another resource instead
of consuming them locally:

```typescript
yield* AWS.EventBridge.events(bus, { source: ["my.app"] }).toQueue(queue);
```
