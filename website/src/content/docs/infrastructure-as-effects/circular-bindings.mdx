---
title: Bind two runtimes to each other
description: Model two runtimes that reference each other, such as Worker A and Worker B or two Lambda Functions, with tagged classes and layers.
type: how-to
---

Use this pattern when two runtimes call each other, such as a web
Worker that calls an auth Worker which calls back for billing. Each
side needs the other's URL, so neither can be created first. You break
the cycle by importing only each runtime's Tag across files and keeping
its implementation in a layer that the stack provides.

This guide builds two Workers, `A` and `B`, that call each other over
RPC. It assumes you know [Bindings](/infrastructure-as-effects/binding)
and [Layers](/infrastructure-as-effects/layers). If your runtimes form
no cycle, declare each one inline instead (see
[Runtime › Three ways to declare a runtime](/infrastructure-as-effects/runtime#three-ways-to-declare-a-runtime)).

```
GET /  →  A  ──rpc──▶  B
              ◀──rpc───
```

## Declare both tags

Declare each Worker as a class with no implementation. The second type
parameter declares the shape its runtime exposes, here a `work` method:

```typescript
// src/A.ts
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";

export class A extends Cloudflare.Worker<A, { work: () => Effect.Effect<string> }>()("A") {}
```

```typescript
// src/B.ts
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";

export class B extends Cloudflare.Worker<B, { work: () => Effect.Effect<string> }>()("B") {}
```

`A` and `B` are now Tags. Each carries its Worker's type but no
runtime code, so the two files can import each other without side
effects.

## Add `A`'s runtime, binding `B`

Attach A's implementation with `A.make(...)`. `bindWorker(B)` imports
only B's Tag and returns a [typed RPC stub](/apis/schemaless):

```diff lang="typescript"
  // src/A.ts
  import * as Cloudflare from "alchemy/Cloudflare";
  import * as Effect from "effect/Effect";
+ import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";
+ import { B } from "./B.ts";

  export class A extends Cloudflare.Worker<A, { work: () => Effect.Effect<string> }>()("A") {}

+ export default A.make(
+   { main: import.meta.url },
+   Effect.gen(function* () {
+     // deploy time: registers the service binding
+     // runtime: b.work() is a native RPC call to B's deployed Worker
+     const b = yield* Cloudflare.Workers.bindWorker(B);
+     return {
+       fetch: Effect.gen(function* () {
+         return HttpServerResponse.text(yield* b.work());
+       }),
+       // B calls back into this method
+       work: () => Effect.succeed("A handled its half"),
+     };
+   }),
+ );
```

## Add `B`'s runtime, binding `A`

Mirror the pattern in `B.ts`. Neither file needs the other's `.make()`
to be evaluated:

```diff lang="typescript"
  // src/B.ts
  import * as Cloudflare from "alchemy/Cloudflare";
  import * as Effect from "effect/Effect";
+ import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";
+ import { A } from "./A.ts";

  export class B extends Cloudflare.Worker<B, { work: () => Effect.Effect<string> }>()("B") {}

+ export default B.make(
+   { main: import.meta.url },
+   Effect.gen(function* () {
+     const a = yield* Cloudflare.Workers.bindWorker(A);
+     return {
+       fetch: Effect.gen(function* () {
+         return HttpServerResponse.text(yield* a.work());
+       }),
+       work: () => Effect.succeed("B handled its half"),
+     };
+   }),
+ );
```

## Wire both into the stack

The stack yields both Tags and provides both layers from the default
exports:

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import ALive, { A } from "./src/A.ts";
import BLive, { B } from "./src/B.ts";

export default Alchemy.Stack(
  "AB",
  { providers: Cloudflare.providers(), state: Cloudflare.state() },
  Effect.gen(function* () {
    const a = yield* A;
    const b = yield* B;
    return { aUrl: a.url, bUrl: b.url };
  }).pipe(Effect.provide(Layer.mergeAll(ALive, BLive))),
);
```

If you forget a layer, the plan fails before anything deploys with a
`MissingImplementationError`. Its message names the class and shows the
`.make(...)` layer to provide:

```text
Cloudflare.Worker<A> was yielded without its implementation.
```

TypeScript does not catch this case. Yielding a bare Tag only requires
the resource's providers, so a missing layer still type-checks.

At deploy time, each provider's `precreate` reserves its Worker and URL
before either side reconciles, which breaks the deadlock.
[Resource lifecycle › Cycles](/infrastructure-as-code/resource-lifecycle#cycles) covers
how the engine converges the cycle. The same pattern works for
Lambda↔Lambda, Worker↔Container, or any mix, because every runtime
supports the Tag and layer split.
