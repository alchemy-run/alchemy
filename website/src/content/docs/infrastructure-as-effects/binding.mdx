A **Binding** connects a [Resource](/infrastructure-as-code/resource)
to a Worker, Lambda Function, or Container. You yield the resource and
get back a typed client. The permissions and configuration that client
needs are generated for you.

Let's look at how they work.

## The declaration

Start with a Worker and a bucket:

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

export const Uploads = Cloudflare.R2.Bucket("Uploads");

export default Cloudflare.Worker(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    return {
      fetch: Effect.gen(function* () {
        // TODO: write to the bucket
        return HttpServerResponse.text("ok");
      }),
    };
  }),
);
```

Bind the bucket with read-write access. `bucket` comes back with `get`,
`put`, `list`, and `delete`:

```diff lang="typescript"
 export default Cloudflare.Worker(
   "Api",
   { main: import.meta.url },
   Effect.gen(function* () {
+    const bucket = yield* Cloudflare.R2.ReadWriteBucket(Uploads);
+
     return {
       // ...
     };
   }),
 );
```

Call `put` from the handler:

```diff lang="typescript"
     return {
       fetch: Effect.gen(function* () {
-        // TODO: write to the bucket
+        yield* bucket.put("hello.txt", "world");
         return HttpServerResponse.text("ok");
       }),
     };
```

## The implementation

Provide `ReadWriteBucketBinding` to implement it:

```diff lang="typescript"
   Effect.gen(function* () {
     const bucket = yield* Cloudflare.R2.ReadWriteBucket(Uploads);
     // ...
-  }),
+  }).pipe(Effect.provide(Cloudflare.R2.ReadWriteBucketBinding)),
 );
```

This Layer registers a native `r2_bucket` binding on the Worker. On the
next deploy, the `Uploads` bucket is created in the
[Stack](/infrastructure-as-code/stack) and bound to this Worker, so
`bucket.put` works inside its handlers.

## A contract and a Layer

`ReadWriteBucket` is a `Binding.Service`. It names the capability and
the client it returns, and nothing about how it's implemented:

```typescript
export interface ReadWriteBucket extends Binding.Service<
  ReadWriteBucket,
  "Cloudflare.R2.ReadWriteBucket",
  (bucket: Bucket) => Effect.Effect<ReadWriteBucketClient>
> {}
```

Swap the Layer and the same `bucket` calls R2 over HTTP instead:

```diff lang="typescript"
-  }).pipe(Effect.provide(Cloudflare.R2.ReadWriteBucketBinding)),
+  }).pipe(Effect.provide(Cloudflare.R2.ReadWriteBucketHttp)),
```

`ReadWriteBucketHttp` mints a scoped API token at deploy time. The
handler code does not change.

[Layers](/infrastructure-as-effects/layers) builds on this same
tag/Layer split, one level up.

## The types hold the boundary

`ReadWriteBucketBinding` needs a Cloudflare Worker to run in. Providing
it to a Lambda Function is a compile error:

```typescript
export default AWS.Lambda.Function(
  "Api",
  { main: import.meta.url },
  handler.pipe(Effect.provide(Cloudflare.R2.ReadWriteBucketBinding)),
  // ✗ Type error: the Layer requires `WorkerEnvironment` and `Worker`,
  //   which a Lambda Function can't provide
);
```

## The same shape on AWS

Bind a DynamoDB table to a Lambda Function the same way. `getItem`
comes back with the table name already filled in:

```typescript
import * as AWS from "alchemy/AWS";
import * as Effect from "effect/Effect";

export const Jobs = AWS.DynamoDB.Table("Jobs", { partitionKey: "pk" });

export default AWS.Lambda.Function(
  "Api",
  { main: import.meta.url, functionUrl: true },
  Effect.gen(function* () {
    const getItem = yield* AWS.DynamoDB.GetItem(Jobs);

    return {
      fetch: Effect.gen(function* () {
        const job = yield* getItem({ Key: { pk: { S: "job-1" } } });
        // ...
      }),
    };
  }).pipe(Effect.provide(AWS.DynamoDB.GetItemHttp)),
);
```

`GetItemHttp` adds one IAM statement to the Function's role, scoped to
this table and this action:

```json
{
  "Effect": "Allow",
  "Action": ["dynamodb:GetItem"],
  "Resource": ["arn:aws:dynamodb:us-east-1:123456789012:table/Jobs-a1b2c3"]
}
```

Bind several tables at once and the statement lists each of them:

```typescript
const batchGet = yield* AWS.DynamoDB.BatchGetItem(Jobs, Audit);
// the statement lists both table ARNs
```

## Plan-time invokes

A binding can also run at plan time, before anything is deployed.
Terraform calls this a data source, Pulumi an invoke. Call it directly
and you get back an [`Output`](/infrastructure-as-code/outputs) to pass
into resource props:

```typescript
// Output<ec2.Image | undefined>
const image = AWS.EC2.getAmi({ owners: ["amazon"], name: ["al2023-ami-2023.*"] });

// a helper built on it. Output<string>, fails when nothing matches
imageId: AWS.EC2.amazonLinux2023(),
```

Constructing the Output does nothing on its own, so this is safe in code
that also runs inside a deployed bundle. The same capability bound
inside a Function with `yield* AWS.EC2.GetAmi(...)` still grants its
IAM and runs at runtime. The cloud `providers()` layers include every
plan-executable capability.

## Event Sources and Sinks

An [Event Source](/infrastructure-as-effects/event-sources) runs your
Function when something happens on a resource. Consume a queue and the
messages arrive as a `Stream`:

```typescript
yield* AWS.SQS.consumeQueueMessages(Inbound, (records) =>
  Stream.runForEach(records, (record) => Effect.log(record.body)),
);
```

A [Sink](/infrastructure-as-effects/sinks) is the write side. Bind a
queue as a `Sink` and run a `Stream` into it:

```typescript
const sink = yield* AWS.SQS.QueueSink(Outbound);
```

Both wire their own permissions, like every other binding.

## How it works under the hood

The deploy-time wiring lives in the binding's setup Effect, behind a
guard:

```typescript
if (!globalThis.__ALCHEMY_RUNTIME__) {
  // deploy time only: register IAM / native bindings / env on the host
  yield* host.bind`${resource}`(/* … */);
}
// always: return the typed runtime client
```

[Phases](/infrastructure-as-effects/phases#the-__alchemy_runtime__-guard)
covers the guard in depth.

## All of Effect, on every binding

Every call on a client is an `Effect`, so retries, timeouts, and typed
error handling compose onto it:

```typescript
const sendWithRetry = sendMessage({ MessageBody: msg }).pipe(
  Effect.retry({ times: 3, schedule: Schedule.exponential("100 millis") }),
  Effect.timeout("5 seconds"),
  Effect.catchTag("ThrottlingException", () => Effect.succeed(undefined)),
);
```

Every binding has the same shape, so you can hide one behind a service
interface and swap implementations without touching handler code. That
is what [Layers](/infrastructure-as-effects/layers) are for. Two
Functions can even bind each other, see
[Circular Bindings](/infrastructure-as-effects/circular-bindings).
