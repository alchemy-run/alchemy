A **binding** connects a [resource](/infrastructure-as-code/resource)
to a [runtime](/infrastructure-as-effects/runtime) such as a Worker,
Lambda Function, Container, or Server. Inside the runtime's
constructor, you yield the resource and get back a typed client:

```typescript
import * as AWS from "alchemy/AWS";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

export const Jobs = AWS.DynamoDB.Table("Jobs", { partitionKey: "pk" });

export default AWS.Lambda.Function(
  "Api",
  { main: import.meta.url, functionUrl: true },
  Effect.gen(function* () {
    const getItem = yield* AWS.DynamoDB.GetItem(Jobs); // the binding

    return {
      fetch: Effect.gen(function* () {
        const job = yield* getItem({ Key: { pk: { S: "job-1" } } }); // the client
        return yield* HttpServerResponse.json(job.Item);
      }),
    };
  }).pipe(Effect.provide(AWS.DynamoDB.GetItemHttp)), // the implementation
);
```

A Function that reads a table needs permission to call the API, the
table's name at runtime, and a client to call it with. In traditional
IaC those live in a policy, an environment variable, and an SDK call,
and nothing checks that they agree. The binding generates all three
from the one `Jobs` declaration.

## Permissions

At deploy time the binding attaches an IAM statement to the Function's
role. It grants the one action the client can make, on the one table
it was bound to:

```json
{
  "Effect": "Allow",
  "Action": ["dynamodb:GetItem"],
  "Resource": ["arn:aws:dynamodb:us-east-1:123456789012:table/Jobs-a1b2c3"]
}
```

Least privilege follows from the shape. Each extra binding adds one
statement for its own action and tables:

```typescript
const getItem = yield* AWS.DynamoDB.GetItem(Jobs);
const putItem = yield* AWS.DynamoDB.PutItem(Jobs); // + dynamodb:PutItem

// several tables: the statement lists each ARN
const batchGet = yield* AWS.DynamoDB.BatchGetItem(Jobs, Audit);
```

## Configuration

The client needs the table's physical name. The binding serializes the
`Jobs.tableName` [Output](/infrastructure-as-code/outputs) into the
Function's environment:

```sh
Jobs_tableName=Jobs-a1b2c3
```

`getItem` reads it back and fills in `TableName` on every request. You
never touch `process.env`, and the name can't drift from the policy.

## The client

`getItem` is the DynamoDB operation with the table already filled in.
It returns an `Effect` with a typed error channel, so retries, timeouts,
and error handling compose onto it:

```typescript
const job = yield* getItem({ Key: { pk: { S: "job-1" } } }).pipe(
  Effect.retry({ times: 3, schedule: Schedule.exponential("100 millis") }),
  Effect.timeout("5 seconds"),
  Effect.catchTag("ResourceNotFoundException", () => Effect.succeed(undefined)),
);
```

## A contract and a Layer

`GetItem` names the capability, and `GetItemHttp` decides how it's
satisfied. A Cloudflare Worker binds an R2 Bucket with the same shape:

```typescript
import * as Cloudflare from "alchemy/Cloudflare";

export const Uploads = Cloudflare.R2.Bucket("Uploads");

export default Cloudflare.Worker(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    // access level is in the name: ReadBucket, WriteBucket, ReadWriteBucket
    const bucket = yield* Cloudflare.R2.ReadWriteBucket(Uploads);

    return {
      fetch: Effect.gen(function* () {
        yield* bucket.put("hello.txt", "world");
        return HttpServerResponse.text("ok");
      }),
    };
    // Cloudflare has no IAM. This layer registers a native r2_bucket binding
  }).pipe(Effect.provide(Cloudflare.R2.ReadWriteBucketBinding)),
);
```

The contract is a `Binding.Service`. It names the capability and the
client it returns, and says nothing about the platform:

```typescript
export interface ReadWriteBucket extends Binding.Service<
  ReadWriteBucket,
  "Cloudflare.R2.ReadWriteBucket",
  (bucket: Bucket) => Effect.Effect<ReadWriteBucketClient>
> {}
```

So a different layer can satisfy the same contract. Swap the layer and
`bucket` calls R2 over HTTP with a scoped API token minted at deploy
time. The handler doesn't change:

```diff lang="typescript"
-  }).pipe(Effect.provide(Cloudflare.R2.ReadWriteBucketBinding)),
+  }).pipe(Effect.provide(Cloudflare.R2.ReadWriteBucketHttp)),
```

Cloudflare capabilities ship up to three implementations of the same
contract:

- `*Binding` (for example `ReadWriteBucketBinding`): registers a native
  binding on the Worker and calls it at runtime.
- `*Http` (for example `ReadWriteBucketHttp`): mints a scoped API token
  at deploy time and calls the Cloudflare HTTP API with it.
- `*Local` (for example `ReadWriteBucketLocal`): calls the HTTP API
  with the credentials the CLI already deploys with. It registers
  nothing on a host and mints no token, so it suits
  [Actions](/infrastructure-as-code/action#binding-resources) and other
  deploy-time code.

All three return the same runtime client, so the same `bucket.put(...)`
code runs in a deployed Worker and in an Action:

```typescript
import * as Alchemy from "alchemy";

const Seed = Alchemy.Action(
  "Seed",
  Effect.gen(function* () {
    const bucket = yield* Cloudflare.R2.ReadWriteBucket(Uploads);
    return Effect.fn(function* () {
      yield* bucket.put("seed.txt", "hello");
    });
    // under `alchemy dev`, talks to the local simulator when Uploads is
    // emulated (its id starts with `dev:`), and to the real cloud when
    // Uploads is piped through Alchemy.remote()
  }).pipe(Effect.provide(Cloudflare.R2.ReadWriteBucketLocal)),
);
```

See [Local development](/environments/local-development#local-by-default-live-on-demand)
for how dev mode picks between the simulator and the cloud.

`*Local` layers exist for every Cloudflare capability with an HTTP data
plane:

- D1, KV, R2, and Queues
- DNS, Vectorize, and Tunnel
- AI Search, Flagship, and Browser Rendering

Worker-runtime-only bindings, such as Rate Limiting, Version Metadata,
and service bindings, have no `*Local` variant. AWS bindings have none
either.

A layer that needs a platform the host can't supply is a compile
error. For example, `ReadWriteBucketBinding` requires
`WorkerEnvironment` and `Worker`, which a Lambda Function can't
provide. See
[Layers › The types hold the boundary](/infrastructure-as-effects/layers#the-types-hold-the-boundary).

## Plan-time invokes

A binding can also run before anything is deployed. Terraform calls
this a data source, and Pulumi calls it an invoke. Call it directly
and you get back an [Output](/infrastructure-as-code/outputs) to pass
into resource props:

```typescript
// Output<ec2.Image | undefined>
const image = AWS.EC2.getAmi({ owners: ["amazon"], name: ["al2023-ami-2023.*"] });

// helpers built on it return Output<string> and fail when nothing matches
const instance = yield* AWS.EC2.Instance("web", {
  imageId: AWS.EC2.amazonLinux2023(), // or AWS.EC2.ubuntu2404()
  instanceType: "t3.micro",
  subnetId: subnet.subnetId,
});
```

`getAmi` is `GetAmi.execute`. Any binding whose client takes no
arguments has an `.execute(...)` that runs it at plan time and returns
an `Output`. The call is hostless, so no IAM or environment is attached.

`.execute` is the higher-level form of
[`Output.fromEffect`](/infrastructure-as-code/outputs#fromeffect), which
lifts any plan-time Effect into an Output:

```typescript
import * as Output from "alchemy/Output";

// the Effect runs during plan with the stack's services, never at runtime.
// It must not fail (E = never), so die with a descriptive error instead.
const imageId = Output.fromEffect(lookupLatestAmi()); // Output<string>
```

- Its implementation layer must be registered on the stack. The cloud
  `providers()` layers include the plan-executable ones.
- A failure fails the plan.
- Bound inside a Function with `yield* AWS.EC2.GetAmi(...)`, the same
  capability still grants its IAM and runs at runtime.

## Bundle size and least privilege

Every binding has its own layer, and each layer carries exactly one
client and registers exactly one grant. Provide the two you use and you
get two clients in the bundle and two statements on the role:

```typescript
Effect.provide(
  Layer.mergeAll(
    AWS.DynamoDB.GetItemHttp, // ships getItem, grants dynamodb:GetItem
    AWS.DynamoDB.PutItemHttp, // ships putItem, grants dynamodb:PutItem
  ),
)
```

The deploy-time registration inside each layer sits behind the
[`__ALCHEMY_RUNTIME__` guard](/infrastructure-as-effects/phases#the-__alchemy_runtime__-guard),
which the bundler removes from the runtime bundle. The binding never
imports the resource's provider either. The stack supplies providers
once through `providers()`, so the heavy infrastructure code stays out
of your runtime.
