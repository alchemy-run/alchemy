Stripe Connect is for platforms and marketplaces — apps that onboard
other businesses, take payments on their behalf, and route payouts to
those businesses. Use it when each merchant needs its own Stripe
identity instead of sharing yours.

A working end-to-end example lives in `examples/stripe-connect`. It
onboards a merchant and records the connected-account id in a D1
database. This guide walks through its Stripe parts.

## Create the account at runtime

Merchants arrive one at a time, so you create their accounts from a
request handler, not as a fixed Stack resource. `CreateAccount` is the
runtime binding:

```typescript
const createAccount = yield* Stripe.CreateAccount();

// inside a Worker route
const account = yield* createAccount({
  type: "express",
  country: "US",
  email: "merchant@example.com",
});
```

`type` selects the onboarding flow (`standard`, `express`, or
`custom`).

## Send them through onboarding

A new Express account cannot take payments until the merchant
completes hosted onboarding. `CreateAccountLink` returns the URL to
hand them:

```typescript
const createAccountLink = yield* Stripe.CreateAccountLink();

const link = yield* createAccountLink({
  account: account.id,
  type: "account_onboarding",
  return_url: "https://your-app.example.com/onboarded",
});
// redirect the merchant to link.url
```

`return_url` is where Stripe sends the merchant after onboarding
completes.

## Record the account id

Persist the account id so later requests know which merchant they are
serving. The example keeps them in D1:

```typescript
const db = yield* Cloudflare.D1.QueryDatabase(Database);

yield* db
  .prepare("INSERT INTO connected_accounts (id, email) VALUES (?, ?)")
  .bind(account.id, body.email)
  .run();
```

Provide the bindings on the Worker Effect:

```typescript
}).pipe(
  Effect.provide([
    Cloudflare.D1.QueryDatabaseBinding,
    Stripe.CreateAccountHttp,
    Stripe.CreateAccountLinkHttp,
  ]),
)
```

## People and external accounts

Accounts you already know can be modeled declaratively as Stack
resources. `AccountPerson` is a director, executive, owner, or
representative; `AccountExternalAccount` is the bank account or card
that receives payouts.

```typescript
const person = yield* Stripe.AccountPerson("Owner", {
  account: merchant.id,
  firstName: "Jane",
  lastName: "Diaz",
  relationship: { representative: true, title: "CEO" },
});

const payoutBank = yield* Stripe.AccountExternalAccount("PayoutBank", {
  account: merchant.id,
  externalAccount: "btok_…", // single-use bank-account token
});
```

Retrieve bindings take both the parent account and the nested id.

## Onboarding required

Connect is a platform feature: the Stripe account that owns these
resources must first complete [Connect onboarding](https://dashboard.stripe.com/connect)
in the Dashboard. Without it, Stripe rejects creating connected
accounts. Issuing cards and cardholders similarly require
[Issuing onboarding](https://dashboard.stripe.com/issuing/overview).
