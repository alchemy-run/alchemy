title: Connect
description: Onboard merchants and manage their payout details with connected accounts.

Stripe Connect is for platforms and marketplaces — apps that onboard
other businesses, take payments on their behalf, and route payouts to
those businesses' bank accounts. Use it when each of your merchants
needs its own Stripe identity rather than sharing yours.

Connect is modeled in three layers:

- `Account` — the connected merchant's Stripe account.
- `AccountPerson` — a person on that account (director, executive,
  owner, or representative).
- `AccountExternalAccount` — the bank account or debit card that
  receives payouts.

## Account

```typescript
const merchant = yield* Stripe.Account("Merchant", {
  type: "express",
  country: "US",
  capabilities: {
    card_payments: { requested: true },
    transfers: { requested: true },
  },
});
```

`type` selects the onboarding flow (`standard`, `express`, or
`custom`). `capabilities` requests the payments the account can take —
requesting one does not activate it; Stripe activates each capability
once the account's requirements are met.

## People

```typescript
const owner = yield* Stripe.AccountPerson("Owner", {
  account: merchant.id,
  firstName: "Jane",
  lastName: "Diaz",
  email: "jane@example.com",
  relationship: { representative: true, title: "CEO" },
});
```

Name, email, phone, relationship, and metadata update in place.

## External accounts

```typescript
const payoutBank = yield* Stripe.AccountExternalAccount("PayoutBank", {
  account: merchant.id,
  externalAccount: "btok_…", // single-use bank-account token
  accountHolderName: "Jane Diaz",
  defaultForCurrency: true,
});
```

`externalAccount` is a single-use Stripe token (`btok_…` or `tok_…`)
representing the bank account or debit card.

Retrieve bindings take both the parent account and the nested id — see
[Sell from a Worker](/stripe/guides/sell-from-a-worker).

## Onboarding

Connect is a platform feature: the Stripe account that owns these
resources must first complete [Connect onboarding](https://dashboard.stripe.com/connect)
in the Dashboard. Without it, Stripe rejects creating connected
accounts.

Issuing cards and cardholders (`IssuingCard`, `IssuingCardholder`,
`IssuingPersonalizationDesign`) are a separate Stripe feature and
likewise require [Issuing onboarding](https://dashboard.stripe.com/issuing/overview)
before the API accepts them.
