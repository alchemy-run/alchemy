---
title: Handle webhook events
description: WebhookEndpoint lifecycle plus consumeEvents — one Effect per Stripe delivery.
---

Two pieces: a **resource** that owns the Stripe endpoint, and
**`consumeEvents`** that runs one Effect per POST. That matches
GitHub `consumeRepositoryEvents` and SQS `consumeQueueMessages`.

## Subscribe on the Worker

Call `consumeEvents` during Worker init. Pass event **classes** — not
`"customer.created"` strings. The handler `event` is the union of
those classes.

```typescript
// src/api.ts
yield* Stripe.consumeEvents(
  "Events",
  {
    events: [Stripe.CustomerCreated, Stripe.InvoicePaid],
  },
  Effect.fn(function* (event) {
    // event: CustomerCreated | InvoicePaid
    yield* Effect.log(event.type);
  }),
);
```

Provide `Stripe.ConsumeEventsLive` on the Worker Effect:

```typescript
}).pipe(
  Effect.provide([
    Stripe.RetrieveProductHttp,
    Stripe.ConsumeEventsLive,
  ]),
),
```

`consumeEvents` yields a `WebhookEndpoint` pointed at this Worker
and verifies `Stripe-Signature` with the endpoint secret.

## Endpoint resource

Manage the endpoint yourself when you need a URL you already have:

```typescript
const webhook = yield* Stripe.WebhookEndpoint("Events", {
  url: Output.interpolate`${api.url}/webhooks/stripe`,
  enabledEvents: ["customer.created"],
});
```

Prefer `consumeEvents` for a Worker that handles the deliveries.
