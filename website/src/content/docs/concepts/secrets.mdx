A **Secret** is a value bound into a Worker's `env` that the
platform deploys as `secret_text` instead of `plain_text` — the
value never round-trips through logs, plans, or the bundle. A
**Variable** is the same idea without the redaction: bound into
`env` as `plain_text` or `json`.

Both are built on top of [`Output<T>`](/concepts/outputs) so they
participate in the dependency graph and re-evaluate when their
upstream changes — an `Output<Redacted<string>>` is just an Output
that happens to carry a `Redacted` payload, and the Worker
serialiser does the right thing.

## `Alchemy.Secret`

The smallest possible secret pulls a value from a `Config` and
binds it under that name:

```typescript
import * as Alchemy from "alchemy";

const apiKey = yield* Alchemy.Secret("API_KEY");
//    ^? Output<Redacted<string>>
```

`Alchemy.Secret(name)` is sugar for
`Alchemy.Secret(name, Config.redacted(name))` — the active
[ConfigProvider](https://effect.website/docs/configuration) (env
vars, `.env`, JSON, …) resolves the value at deploy time. The
binding id placed into the Worker's `env` is the `name` you passed.

Four input shapes are accepted:

```typescript
Alchemy.Secret("API_KEY");                                 // Config.redacted("API_KEY")
Alchemy.Secret("API_KEY", "sk-123");                       // string literal
Alchemy.Secret("API_KEY", Redacted.make("sk-123"));        // already redacted
Alchemy.Secret("API_KEY", Effect.succeed("sk-123"));       // Effect<string | Redacted>
Alchemy.Secret("API_KEY", Config.string("OPENAI_KEY"));    // Config<string | Redacted>
```

Anything that isn't already `Redacted` gets wrapped — by the time
the value reaches the Worker provider it's a `Redacted<string>` and
deploys as `secret_text`.

## `Alchemy.Variable`

Same shape, no redaction. Use when the value is fine to log and
ship as plain text:

```typescript
const host = yield* Alchemy.Variable("HOST");                // Config.string("HOST")
const port = yield* Alchemy.Variable("PORT", 3000);          // number → json binding
const flags = yield* Alchemy.Variable("FLAGS", { beta: true }); // object → json binding
```

The Worker provider serialises strings as `plain_text` and
everything else as a `json` binding (Cloudflare parses the JSON
back into the original JS value at runtime).

## Yielding twice — deploy and runtime

Both helpers return `Output<…>`. `yield*`-ing one in the **init**
phase registers the binding and hands you back an **accessor** —
an `Effect` that, when yielded inside `fetch`, returns the resolved
value. This is the same shape `Output.bind` uses, so existing
`Output<Redacted<string>>` code (e.g. the value of a Cloudflare
Secrets Store entry) works the same way.

```typescript
export default Cloudflare.Worker(
  "Worker",
  { main: import.meta.path },
  Effect.gen(function* () {
    // init phase — binding is recorded, accessor is returned
    const apiKey = yield* Alchemy.Secret("API_KEY");

    return {
      fetch: Effect.gen(function* () {
        // runtime phase — read the value
        const value = yield* apiKey;
        // value is Redacted<string> — Redacted.value(value) to unwrap
      }),
    };
  }),
);
```

See [Phases](/concepts/phases) for why the outer and inner
generators run at different times.

## What the Worker provider sees

For each entry placed into a Worker's `env` the provider chooses
the binding type based on the resolved value:

| Resolved value         | Binding `type` |
| ---------------------- | -------------- |
| `Redacted<string>`     | `secret_text`  |
| `string`               | `plain_text`   |
| any other JSON value   | `json`         |

So `Alchemy.Secret(...)` always lands as `secret_text` and
`Alchemy.Variable(...)` lands as `plain_text` or `json` depending
on the payload. You can mix both freely:

```typescript
yield* Cloudflare.Worker("Api", {
  main: import.meta.path,
  env: {
    HOST: yield* Alchemy.Variable("HOST"),                  // plain_text
    PORT: yield* Alchemy.Variable("PORT", 3000),            // json
    OPENAI_API_KEY: yield* Alchemy.Secret("OPENAI_API_KEY"),// secret_text
  },
});
```

## When to reach for something else

`Alchemy.Secret` is for values that live next to your stack — env
vars, `.env` files, CI secrets — and get baked into the Worker's
config on every deploy. For shared, account-wide secrets that you
want to manage out of band (rotate independently, share across
many stacks, use from non-Alchemy Workers), use the heavier
**Cloudflare Secrets Store** resources directly:

```typescript
const store = yield* Cloudflare.SecretsStore("Store");
const apiKey = yield* Cloudflare.Secret("ApiKey", {
  store,
  value: Redacted.make("sk-123"),
});
```

Both paths produce an `Output<Redacted<string>>` you can drop into
a Worker's `env`; the difference is where the ciphertext lives and
who manages its lifecycle.

## Cheat sheet

| You want to…                                          | Use                                                            |
| ----------------------------------------------------- | -------------------------------------------------------------- |
| Pull `API_KEY` from `Config`/env and bind as a secret | `Alchemy.Secret("API_KEY")`                                    |
| Bind a literal secret                                 | `Alchemy.Secret("API_KEY", "sk-…")`                            |
| Bind a secret produced by an Effect                   | `Alchemy.Secret("API_KEY", Effect.succeed(...))`               |
| Bind a non-secret env var                             | `Alchemy.Variable("HOST", "localhost")`                        |
| Bind a structured (JSON) env var                      | `Alchemy.Variable("FLAGS", { beta: true })`                    |
| Persist a secret in Cloudflare's Secrets Store        | `Cloudflare.SecretsStore` + `Cloudflare.Secret`                |
| Read the value at runtime                             | `const v = yield* apiKey` inside `fetch`                       |

For the step-by-step "wire up `OPENAI_API_KEY` from `.env`" walk,
see [Guides › Secrets and env vars](/guides/secrets).
