The bot answers an issue once. A person who replies should reach the same session, with everything OpenCode already read. OpenCode should be able to look at other issues, without a GitHub token in its sandbox. And an issue that closes should stop costing anything.

## Mark the bot's own comments

The bot's comments are comments too, and GitHub will deliver them. Mark each one with a hidden HTML comment, so the Worker can tell them apart:

```typescript title="src/tools.ts"
export const MARKER = "<!-- issue-bot -->";
```

```diff lang="typescript"
import { Sandbox } from "./Sandbox.ts";
+import { MARKER } from "./tools.ts";
```

```diff lang="typescript"
const reply = yield* session.prompt(job.text, { requestId: job.deliveryId });
-yield* createComment({ issue_number: job.issue, body: reply.text });
+yield* createComment({
+  issue_number: job.issue,
+  body: `${reply.text}\n\n${MARKER}`,
+});
```

## Consume comments

Subscribe to `issue_comment` as well. A reply is another `ask` on the same Durable Object, so it is another prompt in the same session:

```diff lang="typescript"
import Issue from "./Issue.ts";
import { owner, repository } from "./Repo.ts";
+import { MARKER } from "./tools.ts";
```

```diff lang="typescript"
yield* GitHub.consumeRepositoryEvents(
-  { owner, repository, events: ["issues"] },
+  { owner, repository, events: ["issues", "issue_comment"] },
  Effect.fn(function* (event) {
-    const { action, issue } = event.payload;
-    if (action === "opened") {
-      yield* issues
-        .getByName(String(issue.number))
-        .ask(issue.number, `Issue #${issue.number}: ${issue.title}\n\n${issue.body ?? ""}`, event.id);
-    }
+    const { number, title } = event.payload.issue;
+    const issue = issues.getByName(String(number));
+    if (event.name === "issues") {
+      const { action, issue: opened } = event.payload;
+      if (action === "opened") {
+        yield* issue.ask(number, `Issue #${number}: ${title}\n\n${opened.body ?? ""}`, event.id);
+      }
+      return;
+    }
+    const { action, comment } = event.payload;
+    if (action === "created" && !comment.body.includes(MARKER)) {
+      yield* issue.ask(number, comment.body, event.id);
+    }
  }, Effect.orDie),
);
```

`event.name` says which event arrived, and narrows `event.payload` to its type. The session's transcript is on the sandbox's disk, so OpenCode still has the issue, the files it read and its first answer.

## Declare a tool of your own

OpenCode's tools work in the sandbox. A tool of yours runs in the Durable Object, where the GitHub token is. Declare one that searches the repository's issues:

```diff lang="typescript"
+import * as AI from "@alchemy.run/ai";
+import * as Schema from "effect/Schema";
+
export const MARKER = "<!-- issue-bot -->";
+
+export class SearchIssues extends AI.Tool<SearchIssues>()("search_issues", {
+  description:
+    "Search this repository's issues and pull requests. Use it to find duplicates or related work.",
+  parameters: Schema.Struct({ query: Schema.String }),
+  success: Schema.Struct({
+    issues: Schema.Array(
+      Schema.Struct({ number: Schema.Number, title: Schema.String, state: Schema.String }),
+    ),
+  }),
+}) {}
```

## Implement it with a GitHub binding

```diff lang="typescript"
import * as AI from "@alchemy.run/ai";
+import * as GitHub from "@alchemy.run/github";
+import * as Effect from "effect/Effect";
+import * as Layer from "effect/Layer";
import * as Schema from "effect/Schema";
+import { Repo } from "./Repo.ts";
```

```diff lang="typescript"
    issues: Schema.Array(
      Schema.Struct({ number: Schema.Number, title: Schema.String, state: Schema.String }),
    ),
  }),
}) {}
+
+export const SearchIssuesLive = SearchIssues.make(
+  Effect.gen(function* () {
+    const search = yield* GitHub.SearchIssues(yield* Repo);
+
+    return Effect.fn(function* ({ query }) {
+      const found = yield* search({ q: query, per_page: 10 }).pipe(Effect.orDie);
+      return {
+        issues: found.items.map((issue) => ({
+          number: issue.number,
+          title: issue.title,
+          state: issue.state,
+        })),
+      };
+    });
+  }),
+).pipe(Layer.provide(GitHub.SearchIssuesHttp));
```

+  SearchIssuesLive,

```diff lang="typescript"

  models: [Fast],
-  tools: [AI.CodingTools],
+  tools: [AI.CodingTools, SearchIssues],
  cwd: "/home/user/repo",
});
```

```diff lang="typescript"
const session = harness.session("issue", {
-  tools: [AI.Bash, AI.Read, AI.Grep],
+  tools: [AI.Bash, AI.Read, AI.Grep, SearchIssues],

```

OpenCode sees the tool as `alchemy_search_issues`. When it calls it, the call waits in the sandbox while the handler runs in the Durable Object, and only the result goes back.

## What you built

- A Durable Object for each issue, driving an OpenCode session in a sandbox of its own.
- A sandbox for each issue, started from a snapshot of the repository and removed when the issue closes.
- A model and a GitHub tool that run in the Durable Object, so the sandbox holds no key and no token.
- An event source that turns issues and replies into jobs, each run from the object's alarm.
