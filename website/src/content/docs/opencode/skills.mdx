---
title: Skills
description: Give OpenCode sessions skills. Each AI.Skill becomes an OpenCode skill, which the model loads with OpenCode's own skill tool.
---

An OpenCode harness takes [`AI.Skill`](/ai/skills) declarations. OpenCode has skills of its own: it lists each skill's name and description to the model, and the model loads one with OpenCode's `skill` tool. The harness registers your skills with OpenCode when it starts.

## List a skill

Skills go in the harness's `skills`, and every session has them:

```typescript title="src/skills.ts"
import * as AI from "@alchemy.run/ai";

export class Releasing extends AI.Skill<Releasing>()("releasing", {
  description: "Cut and upload a release. Use when the user asks to ship.",
  instructions: "Run the tests, bump the version, build, then call alchemy_deploy.",
}) {}
```

```typescript
const harness = yield* OpenCode.Harness({
  models: [Fast],
  tools: [AI.CodingTools, Deploy],
  skills: [Releasing],
});
```

Instructions that name one of your tools use the name the model sees, `alchemy_deploy`.

## The skill tool

A harness with skills switches on OpenCode's `skill` tool for every prompt, including one that names its `tools`. Without it the model could see a skill's description and never load it.

## Skills change with a deploy

Skills are registered each time OpenCode starts in the Durable Object. A deploy that edits a skill reaches every session on its next prompt, and transcripts stay.

A skill's `instructions` are what OpenCode loads. OpenCode has no file system in a Durable Object, so a skill's extra `files` are not available to it.

Skills are for the whole harness. To give different sessions different skills, use two harnesses, each with its own `name`.
