OpenCode is a coding agent built as a server. The server keeps **sessions**, each a transcript on its own disk. It ships its own tools, which read and change files and run commands on the machine it is on. For each answer it calls a model provider over HTTP. It is a program that needs a machine, so on Alchemy each session's OpenCode runs in a sandbox of its own, and the Durable Object that owns the session drives it from outside.

Take one small app: a `Coder` Durable Object with a session `pr-142`. The session's sandbox on Boat runs OpenCode and a small **bridge**. OpenCode's own `bash` runs in the sandbox. Its model requests, and its calls to your `deploy` tool, go to the bridge, and the harness answers them from the Durable Object, where the `Fast` model's Layer and the tool's handler are.

## The harness

The **harness** is your side of OpenCode: the models sessions may run on, the tools and skills they may use, and where their sandboxes run. You yield it in a Durable Object's outer Effect.

```typescript
const harness = yield* OpenCode.Harness({ models: [Fast], tools: [AI.CodingTools, Deploy] });
```

## Sessions

A **session** is one OpenCode session in one sandbox. You name it, and the harness finds its sandbox by that name. Nothing runs until the session is used: its first call opens the sandbox, installs OpenCode there and starts it.

```typescript
const session = harness.session("pr-142");
```

See [Sessions & prompts](/opencode/sessions).

## Prompts

A **prompt** is one message to a session. It returns when OpenCode has answered, through every tool call that took.

```typescript
const reply = yield* session.prompt("Fix the failing test.", { requestId: "msg-81" });
```

## The bridge

OpenCode is configured with one model provider, and it points at the **bridge**: a small server on the sandbox's own loopback address. The bridge holds each request until the harness answers it. The harness follows the bridge over the sandbox's `exec`, the same call that runs any command there.

See [Model requests](/opencode/model-requests).

## Tools

OpenCode ships its own coding tools and runs them in the sandbox. Your tools run in the Durable Object: OpenCode calls them through the bridge, and the model sees each as `alchemy_<name>`.

See [Tools](/opencode/tools).

## Skills

An `AI.Skill` becomes an OpenCode skill, which the model loads with OpenCode's own `skill` tool.

See [Skills](/opencode/skills).

## The sandbox

The session's transcript is OpenCode's own, on the sandbox's disk. Suspending the sandbox keeps the session, and removing it deletes both.

See [The session's sandbox](/opencode/sandbox).

## How @alchemy.run/opencode models these concepts

`OpenCode.Harness` is an Effect you yield where its Layers are provided. Models, tools, MCP servers, skills and sandboxes are the [`@alchemy.run/ai`](/ai) declarations, unchanged. `OpenCode.CodingTools` provides OpenCode's own tools for the shared names. A session's sandbox is found by a key made from the Durable Object's id and the session's name, so the object can be evicted and find its sessions again.
