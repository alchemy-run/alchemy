---
title: The session's sandbox
description: Each OpenCode session runs in its own sandbox, which holds OpenCode, the bridge and the session's transcript. Suspend it to keep the session, remove it to delete both.
---

Each session has a sandbox of its own. It holds three things: OpenCode's server, the bridge, and OpenCode's data, which includes the session's transcript. The files OpenCode works on are there too. What happens to the sandbox happens to the session.

## Where sandboxes run

An [`AI.Sandboxes`](/ai/sandboxes) Layer says where: E2B, Daytona, Modal, Boat or Archil. An OpenCode harness always requires one.

```typescript
const HarnessLive = Layer.mergeAll(
  FastLive,
  Sandbox,
  OpenCode.CodingTools,
  OpenCodeCloudflare.DurableObjectInstance,
);
```

## The working directory

Sessions work in the sandbox user's home directory. `cwd` sets another, such as a repository your image already has:

```typescript
const harness = yield* OpenCode.Harness({
  models: [Fast],
  tools: [AI.CodingTools],
  cwd: "/home/user/repo",
});
```

## What happens on first use

The first call on a session opens its sandbox, downloads OpenCode from npm, checks it against a known hash, writes its configuration and starts it with the bridge. That can take a minute on a new sandbox. Every later call finds OpenCode running.

A session's sandbox is found by a key made from the Durable Object's id and the session's name. `session.sandboxKey` is that key, for finding the sandbox on the platform yourself.

## Suspend

`suspendSandbox` stops the sandbox and keeps its disk, where the platform can:

```typescript
yield* harness.session("pr-142").suspendSandbox;
```

The transcript is on that disk. The session's next prompt resumes the sandbox, starts OpenCode again and continues the same session, with its files as they were.

## Remove

`removeSandbox` deletes the sandbox, and the session with it:

```typescript
yield* harness.session("pr-142").removeSandbox;
```

The next prompt on that name starts a new sandbox and an empty session.

## Platforms that delete idle sandboxes

A platform that deletes a sandbox takes its session too. On Modal, which has no pause, a session lasts as long as its sandbox stays busy. Choose a platform that keeps a stopped sandbox's disk when sessions should last. See [Sandbox platforms](/ai/sandbox-platforms).

## After a deploy

A deploy that changes the harness's models, tools or skills changes OpenCode's configuration. A running session picks it up on its next call: the harness rewrites the configuration in the sandbox and restarts OpenCode there.
