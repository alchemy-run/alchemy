A **resource** is a cloud entity that Alchemy manages, such as a
bucket, database, queue, function, or DNS record. You declare
resources inside a [stack](/infrastructure-as-code/stack), and Alchemy
creates, updates, and deletes them to match your code.

## Declaring a resource

You declare a resource with a **logical ID** and optional **input
properties**:

```typescript
// logical ID only: many resources need no properties
const bucket = yield* Cloudflare.R2.Bucket("Bucket");

// logical ID + input properties
const queue = yield* AWS.SQS.Queue("Jobs", {
  fifo: true,
});
```

## Logical ID

The **logical ID** names the resource within its stack. Alchemy uses
it to track the resource in state across deploys:

- **Stable across deploys**: keep the same ID and Alchemy keeps
  updating the same cloud resource.
- **Independent of your code layout**: rename the variable, change the
  TypeScript class, or move the file. Alchemy still recognizes the
  resource as long as the logical ID stays the same.
- **Rename means replace**: a new logical ID is a new resource, and
  Alchemy deletes the old one on the next deploy. To keep the
  resource, declare the rename with
  [`renamedFrom`](/infrastructure-as-code/renaming).

## Fully qualified names

Alchemy stores each resource under its **fully qualified name** (FQN).
The FQN is the logical ID prefixed with the path of any namespaces the
resource was declared in, joined with `/`. `Namespace.push` runs an
Effect inside a namespace:

```typescript
import * as Namespace from "alchemy/Namespace";

const assets = yield* Cloudflare.R2.Bucket("Assets");
// FQN: "Assets"

const siteAssets = yield* Cloudflare.R2.Bucket("Assets").pipe(
  Namespace.push("Site"),
);
// FQN: "Site/Assets"
```

Both buckets use the logical ID `"Assets"`, but their FQNs differ, so
they are two separate resources. Logical IDs only need to be unique
within a namespace. Namespaces nest, so a resource inside
`Namespace.push("Api")` inside `Namespace.push("Site")` has the FQN
`"Site/Api/<id>"`.

Use the FQN wherever you name a resource from outside its declaration,
such as [references](/infrastructure-as-code/references),
[renames](/infrastructure-as-code/renaming), and the
[state store](/state-store).

## Outputs and the dependency graph

Every resource has two sides:

- **Input properties**: the desired configuration you pass in, such as
  `fifo: true`.
- **Output attributes**: the values the cloud produces, such as
  `queueUrl` and `queueArn`.

Each attribute is an [`Output`](/infrastructure-as-code/outputs), a
lazy, typed reference that resolves once the resource exists. Passing
an output from one resource as input to another adds an edge to the
dependency graph:

```typescript
const Bucket = yield* Cloudflare.R2.Bucket("Bucket");
const Sessions = yield* Cloudflare.KV.Namespace("Sessions");

const Queue = yield* AWS.SQS.Queue("Queue", {
  tags: { bucket: Bucket.bucketName }, // Output<string> → edge Bucket → Queue
});

const Worker = yield* Cloudflare.Worker("Worker", {
  main: import.meta.url,
  env: { Bucket, Sessions, Queue },
});
```

Alchemy reads the outputs in each resource's props and builds this
graph:

<DAG
  nodes={[
    { id: "Bucket", type: "Cloudflare.R2.Bucket" },
    { id: "Sessions", type: "Cloudflare.KV.Namespace" },
    { id: "Queue", type: "AWS.SQS.Queue" },
    { id: "Worker", type: "Cloudflare.Worker", tone: "accent" },
  ]}
  edges={[
    { from: "Bucket", to: "Queue" },
    { from: "Bucket", to: "Worker" },
    { from: "Sessions", to: "Worker" },
    { from: "Queue", to: "Worker" },
  ]}
/>

It then deploys in topological order:

1. `Bucket` and `Sessions` have no dependencies, so Alchemy creates
   them in parallel.
2. `Queue` waits for `Bucket.bucketName`, then Alchemy creates it.
3. `Worker` depends on all three, so Alchemy creates it last.

[Bindings](/infrastructure-as-effects/binding) also attach resources to
runtimes. When bindings form a cycle, such as two Workers that call
each other, see
[Circular Bindings](/infrastructure-as-effects/circular-bindings).

## Physical name

The **physical name** is the name the cloud sees. Unless you pass a
name prop, most providers generate one from four parts:

```text
{stack-name}-{logical-id}-{stage}-{instance-id suffix}

# stack "myapp", logical ID "Bucket", stage "live_sam":
myapp-bucket-live-sam-k3m7q2xw9pdt4vna
#                     ^ 16 base32 characters from the instance ID
```

Characters other than letters, digits, and `-` become `-`, and some
providers lowercase the name (R2 does). Names over the provider's
length limit (64 characters unless the provider sets its own) are
truncated with a short hash so they stay distinct.

The **instance ID** is 16 random bytes Alchemy generates the first time
it creates the resource. Different stages produce different names from
the same code. A [replacement](/infrastructure-as-code/resource-lifecycle#replace)
gets a new instance ID, so it gets a new physical name.

## Resources are Effects

A resource declaration like `Cloudflare.R2.Bucket("Bucket")` is an
`Effect`. Building it and `yield*`-ing it inside a stack make no cloud
calls. It registers the resource on the stack and returns
[`Output`](/infrastructure-as-code/outputs) references to its
attributes:

```typescript
// 1. Build the Effect. No API calls, no state mutation.
const Bucket = Cloudflare.R2.Bucket("Bucket");

// 2. Register it on the stack. Still no API calls. Alchemy only
//    collects the desired-state graph.
export default Alchemy.Stack(
  "MyApp",
  { providers: Cloudflare.providers(), state: Cloudflare.state() },
  Effect.gen(function* () {
    const bucket = yield* Bucket;
    return { name: bucket.bucketName };
  }),
);
```

Alchemy calls the cloud later, when `alchemy deploy` runs the collected
graph through plan and apply. See
[Resource Lifecycle](/infrastructure-as-code/resource-lifecycle).

### Sharing across files

The declaration is a value, so you can `export` it and import it from
handlers, layers, and other resources:

```typescript
// src/bucket.ts
export const Bucket = Cloudflare.R2.Bucket("Bucket");
```

```typescript
// alchemy.run.ts
import { Bucket } from "./src/bucket.ts";

export default Alchemy.Stack(
  "MyApp",
  { providers: Cloudflare.providers(), state: Cloudflare.state() },
  Effect.gen(function* () {
    yield* Bucket;
  }),
);
```

Alchemy keys resources by FQN, so a resource registers once however
many modules `yield*` it. The same applies to two different
declarations that share an FQN. The second `yield*` returns the
resource the first one registered and ignores its props, so give each
distinct resource its own logical ID.
