An **action** is a node in the stack's dependency graph that runs an
Effect during apply. It runs again only when its resolved input
changes. Use one for reproducible deploy-time work, such as seeding a
database, posting a release notification, uploading a generated
artifact, invalidating a CDN cache, or running a migration check.

An action has no provider lifecycle, so there is no replace, read, or
delete. This page builds on [Inputs & Outputs](/infrastructure-as-code/outputs)
and [Resource Lifecycle](/infrastructure-as-code/resource-lifecycle).

## Binding resources

An action's body often calls resources in your stack. This action
seeds a D1 database after the database exists:

```typescript
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";

// inside the stack's Effect.gen
const database = yield* Cloudflare.D1.Database("Db");

const Seed = Alchemy.Action(
  "Seed",
  Effect.gen(function* () {
    const db = yield* Cloudflare.D1.QueryDatabase(database);
    return Effect.fn(function* (input: { version: number }) {
      yield* db.exec("CREATE TABLE IF NOT EXISTS users (id TEXT, name TEXT)");
      yield* db
        .prepare("INSERT INTO users (id, name) VALUES (?, ?)")
        .bind("1", "Ada")
        .run();
    });
  }).pipe(
    // calls D1 over HTTP with your CLI credentials, since an Action
    // has no Worker to host a native binding
    Effect.provide(Cloudflare.D1.QueryDatabaseLocal),
  ),
);

yield* Seed({ version: 1 }); // change the input to seed again
```

The runtime client is the same one a deployed Worker gets, so
`db.prepare(...).run()` works in both places. See
[Bindings › A contract and a Layer](/infrastructure-as-effects/binding#a-contract-and-a-layer) for the `*Local` layers
and which capabilities have one.

### Reading a resource's outputs

Inside the constructor, `yield*` a resource
[output](/infrastructure-as-code/outputs) to get an accessor that
resolves at apply time:

```typescript
const Seed = Alchemy.Action(
  "Seed",
  Effect.gen(function* () {
    const databaseId = yield* database.databaseId; // accessor, not the value yet
    return Effect.fn(function* () {
      const id = yield* databaseId; // resolved during apply
      yield* Effect.log(`seeding ${id}`);
    });
  }),
);
```

Capturing an output makes the action depend on that resource, the same
edge you get from passing `database.databaseId` as input. It works in
both the inline and the tagged `.make` forms.

## When an action runs

Each deploy either runs an action (`λ`) or skips it (`·`). The engine
skips it only when all of these hold:

- The previous run finished. A failed or unfinished run always runs
  again.
- `--force` is not set. `alchemy deploy --force` flips every skip to a
  run, including actions.
- The hash of the resolved input matches the persisted `inputHash`.
  The hash is `sha256(JSON.stringify(input))`. Keys aren't sorted, so
  reordering an object's keys also causes a run.

If the input depends on a resource that this deploy creates or changes,
the plan shows `run` because its outputs aren't known yet. At apply
time the engine hashes the resolved input and still skips the body if
the hash matches the last completed run.

Actions share the FQN namespace with resources, and the engine orders
them in the same graph:

- An action can take resource outputs as input (`{ table: bucket.name }`)
  or capture them in its constructor. See
  [Reading a resource's outputs](#reading-a-resources-outputs).
- A resource can take an action's result, the `Output<Out>` from
  `yield* MyAction(...)` or a property of it, as a prop. The resource
  waits for the action before it reconciles.
- An action can reference other actions.
- The plan rejects cycles, the same as resource cycles.

When you remove an action from the stack, the engine drops its
persisted state without running the body.

## Declaring an action

Define an action with its type name and a runner, then call it inside a
stack. `yield*` returns an `Output<Out>` you can pass to downstream
nodes. Any outputs in the input resolve before the body runs:

```typescript
const Sync = Alchemy.Action(
  "Sync",
  Effect.fn(function* (input: { table: string }) {
    yield* Effect.log(`syncing ${input.table}`);
    return { rows: 42 };
  }),
);

// the default form uses the type name as the logical ID
const rows = yield* Sync({ table: bucket.name });
//    ^ Output<{ rows: number }>
rows.rows; // Output<number>
```

### Constructor (pulling in dependencies)

Pass an Effect that returns the runner to `yield*` services. They show
up as requirements at the call site, and the constructor runs at most
once per process:

```typescript
const Sync = Alchemy.Action(
  "Sync",
  Effect.gen(function* () {
    const db = yield* Database;
    const logger = yield* Logger;
    return Effect.fn(function* (input: { table: string }) {
      yield* logger.info(`syncing ${input.table}`);
      return { rows: yield* db.count(input.table) };
    });
  }),
);

// `yield* Sync({...})` now requires `Database | Logger | Stack`
```

### Multiple instances

Pass an explicit logical ID to register more than one instance of the
same definition:

```typescript
const nightly = yield* Sync("nightly", { table: usersBucket.name });
const hourly = yield* Sync("hourly", { table: eventsBucket.name });
```

### Tagged form (service + layer)

To split the contract from the implementation, declare the type with an
`interface` and build the value with the no-argument overload. Then
supply the runner with `.make`, which accepts a runner or a constructor
Effect:

```typescript
export interface Sync extends Alchemy.Action<"Sync", { table: string }, { rows: number }> {}
export const Sync = Alchemy.Action<Sync, { table: string }, { rows: number }>()("Sync");

export const SyncLive = Sync.make(
  Effect.gen(function* () {
    const db = yield* Database;
    return Effect.fn(function* (input) {
      return { rows: yield* db.count(input.table) };
    });
  }),
);

// In a stack. This requires `Sync`: add `SyncLive` to the stack's
// providers, or provide it locally with `Effect.provide(SyncLive)`.
const rows = yield* Sync({ table: bucket.name });
```

## What actions are not

- **A resource**: an action has no `diff`, `read`, `reconcile`, or
  `delete`. Model a cloud entity that needs lifecycle management as a
  resource.
- **Runtime code**: an action runs at deploy time. To run code in a
  deployed Worker or Lambda, see
  [Runtime](/infrastructure-as-effects/runtime).
- **Idempotent for free**: the engine runs the body only when the input
  changes, and it persists the `running` state but not the body's side
  effects. The body must tolerate a retry after an interrupted apply.
