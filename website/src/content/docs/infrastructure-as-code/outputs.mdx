A [resource](/infrastructure-as-code/resource)'s **inputs** are the
props you pass in, and its **outputs** are the attributes the cloud
returns. Each output is an `Output<T>`, a lazy, typed reference that
resolves during deploy, once the upstream resource exists.

```typescript
const bucket = yield* Cloudflare.R2.Bucket("Bucket");

bucket.bucketName;
// ^? Output<string>
```

Alchemy evaluates every output during plan and apply, so the deploy
graph is exactly the set of dependencies your outputs declare. See
[Resources](/infrastructure-as-code/resource#outputs-and-the-dependency-graph)
for how they draw the graph.

## Operators at a glance

- `resource.attr`: reference an attribute that doesn't exist yet.
- [`Output.interpolate`](#interpolate): build a string from Outputs.
- [`Output.map`](#map): transform an Output.
- [`Output.all`](#all): combine several Outputs.
- [`output.as<T>()`](#as): narrow an output's type.
- [`Output.mapEffect`](#mapeffect): transform with an Effect.
- [`Output.flatMap`](#flatmap): transform into another Output.
- [`Output.literal`](#literal): wrap a constant as an Output.
- [`Output.asOutput`](#asoutput): lift a value, Effect, or output into an output.
- [`Output.fromEffect`](#fromeffect): lift a plan-time Effect into an Output.
- [`Output.of`](#of): turn a resource or a reference into an Output.
- [`Output.stackRef`](#stackref): read another stack's outputs without its typed handle.

To read a resource from another stack or stage, use `Resource.ref`.
See [References](/infrastructure-as-code/references).

To inspect dependencies from a custom provider, use the helpers
`Output.upstream`, `Output.hasOutputs`, `Output.isOutput`, and
`Output.toEnvKey`. Each is documented on its export in
[`Output.ts`](https://github.com/alchemy-run/alchemy/blob/main/packages/alchemy/src/Output.ts).

## Passing outputs as props

Pass an `Output`, or any structure containing outputs, as a prop of
another resource. Alchemy walks the structure, collects the upstream
dependencies, and waits for them before it calls the provider:

```typescript
const queue = yield* AWS.SQS.Queue("Jobs", {
  tags: {
    bucket: bucket.bucketName,              // Output<string>
    region: Output.literal("us-west-2"),    // Output<string>
  },
  redrivePolicy: {
    deadLetterTargetArn: dlq.queueArn,      // Output nested in an object
    maxReceiveCount: 5,                     // plain value
  },
});
```

## Property access

Reading a property off a resource, or off any `Output`, returns another
`Output`:

```typescript
bucket.bucketName;   // Output<string>
bucket.accountId;    // Output<string>
bucket.publicDomain; // Output<string | undefined>
```

Nested access such as `expr.nested.deep` walks down the object without
forcing the value.

## `interpolate`

`Output.interpolate` is a tagged template literal that builds a string
from outputs:

```typescript
import * as Output from "alchemy/Output";

const arn = Output.interpolate`arn:aws:s3:::${bucket.bucketName}/objects/*`;
// Output<string>

const dsn = Output.interpolate`postgres://${db.host}:${db.port}/${db.name}`;
// nullish values render as ""
```

It expands to `Output.all(...args).pipe(Output.map(...))`, so it wires
up the dependency graph for you.

:::caution
An output's value isn't known yet, so JS coercion of an output throws
`Cannot coerce Output<…> to a string via JS coercion`. Use
`` Output.interpolate`…` `` or `Output.map` instead:

```typescript
`s3://${bucket.bucketName}`; // ✗ throws
bucket.bucketName + "/key";  // ✗ throws
+db.port;                    // ✗ arithmetic throws the same way
```
:::

## `map`

`Output.map` transforms an `Output<A>` into an `Output<B>`. The
function runs once per evaluation, after every upstream output is
ready:

```typescript
// pipeable
const upper = bucket.bucketName.pipe(
  Output.map((name) => name.toUpperCase()),
);
// Output<string>

// data-first
Output.map(bucket.bucketName, (name) => name.toUpperCase());
```

## `all`

`Output.all` zips several outputs into one that resolves to a tuple
with the same shape and types:

```typescript
const both = Output.all(bucket.bucketName, queue.queueUrl);
// Output<[string, string]>

const url = both.pipe(
  Output.map(([name, queue]) => `s3://${name}?dlq=${queue}`),
);

Output.all(...urls); // urls: Output<string>[] → Output<string[]>
```

## `as`

`.as<T>()` changes the type of an output without changing its value.
Use it when you know more about the resolved type than TypeScript
does:

```typescript
// `url` is `string | undefined` because some Workers have no URL.
// A Worker served on workers.dev or a custom domain always has one.
const url = worker.url.as<string>();
// Output<string>
```

It is a type cast only. Nothing is checked or converted at runtime.

## `mapEffect`

`Output.mapEffect` works like `map`, but the function returns an
`Effect`. Use it when the transform does real work, such as reading a
file or calling an API:

```typescript
import * as Effect from "effect/Effect";
import * as FileSystem from "effect/FileSystem";

const config = bucket.bucketName.pipe(
  Output.mapEffect((name) =>
    Effect.gen(function* () {
      const fs = yield* FileSystem.FileSystem;
      return yield* fs.readFileString(`config/${name}.json`);
    }).pipe(Effect.orDie), // the error type must be `never`
  ),
);
// Output<string, FileSystem.FileSystem>
```

- The Effect must not fail. Handle errors inside it or turn them into
  defects with `Effect.orDie`.
- The output carries the Effect's requirements (`R`). Provide them
  wherever the output is evaluated.
- It has only the pipeable form. There is no data-first
  `Output.mapEffect(output, fn)`.

## `flatMap`

`Output.flatMap` runs a function that returns another output, then
resolves that output too:

```typescript
const upper = bucket.bucketName.pipe(
  Output.flatMap((name) => Output.literal(name.toUpperCase())),
);
// Output<string>

Output.flatMap(bucket.bucketName, (name) => Output.literal(name)); // data-first
```

:::caution
Dependency edges come only from the source Output. Alchemy does not
look inside the output your function returns when it builds the graph.
Don't return an output of a resource that isn't already upstream of the
source, or it may not be deployed yet when the function runs.
:::

## `literal`

`Output.literal` wraps a value you already know. Use it as a default
for an optional output, or as a placeholder in templates and
`Output.all` calls:

```typescript
Output.literal("hello");      // Output<string>
Output.literal(42);           // Output<number>
Output.literal({ a: 1 });     // Output<{ a: number }>
```

## `asOutput`

`Output.asOutput` lifts a plain value, an `Effect`, or an existing
output into an output. Use it in helpers that accept any of the three:

```typescript
Output.asOutput("foo");                  // wraps as a literal
Output.asOutput(Effect.succeed(123));    // wraps the Effect
Output.asOutput(existingOutput);         // returns it unchanged
```

## `fromEffect`

`Output.fromEffect` lifts a plan-time Effect into an Output. The Effect
runs when the stack resolves the output, with the stack's services
(credentials, region) provided. It never runs inside a deployed
runtime:

```typescript
const fromEffect: <A, Req = never>(
  effect: Effect.Effect<A, never, Req>, // must not fail: die on unresolvable lookups
) => ToOutput<A, Req>; // an Output<A, Req>
```

It is the low-level form behind lookup helpers such as the AMI finders.
See [Bindings › Plan-time invokes](/infrastructure-as-effects/binding#plan-time-invokes)
for the higher-level `.execute(...)` form. Constructing the Output is
inert, so these helpers need no
[`__ALCHEMY_RUNTIME__` guard](/infrastructure-as-effects/phases#the-__alchemy_runtime__-guard).

## `of`

`Output.of` turns a resource into an output of its attributes. You
rarely need it, because resources already act like Outputs. Its main
use is to turn a reference built with `Alchemy.ref` into a typed output
when the resource constructor isn't in scope:

```typescript
import * as Alchemy from "alchemy";
import * as Output from "alchemy/Output";

const bucketOut = Output.of(bucket); // Output of the bucket's attributes

const shared = Output.of(
  // the type parameter is the resource's interface type,
  // not `typeof` its constructor
  Alchemy.ref<Cloudflare.R2.Bucket>("Bucket", {
    stack: "shared-infra",
    stage: "prod",
  }),
);
```

## `stackRef`

`Output.stackRef` reads another stack's persisted output record when
its typed stack handle isn't in scope. It returns an Effect, so you
`yield*` it:

```typescript
const backend = yield* Output.stackRef<{ url: string }>("Backend", {
  stage: "prod", // optional, defaults to the current stage
});
backend.url; // Output<string>
```

Prefer `yield* MyStack` from
[References](/infrastructure-as-code/references#depend-on-a-stacks-outputs),
which does the same lookup with real type bindings.

## Redacted values

Alchemy preserves `Redacted<T>`, Effect's secret wrapper, through
evaluation. Logs and console output show `<redacted>` in place of the
value:

```typescript
import * as Config from "effect/Config";

const webhook = yield* Cloudflare.Alerting.NotificationWebhook("Alerts", {
  url: "https://example.com/hooks/cloudflare",
  secret: yield* Config.redacted("WEBHOOK_SECRET"), // stays Redacted in state and logs
});
```
