---
title: Inputs & Outputs
description: Output<T> is alchemy's lazy reference type. Outputs flow between resources. You compose them with .pipe, map and interpolate them, and they resolve during deploy.
---

A [Resource](/infrastructure-as-code/resource)'s **inputs** are the props you pass
in. Its **outputs** are the attributes the cloud returns after
creation. Outputs don't exist when you write the code. They only
exist after the resource is deployed.

Alchemy bridges this with **`Output<T>`**, a lazy, typed reference
that resolves once the upstream resource has run. You can read
properties off it, transform it with `pipe`, combine it with other
outputs, and feed it as input to the next resource. The resource
graph is built from these dependencies.

This page is a reference for every operator. For the bigger picture
of how the graph deploys, see
[Resource Lifecycle](/infrastructure-as-code/resource-lifecycle).

## What an Output is

```typescript
const bucket = yield* Cloudflare.R2.Bucket("Bucket");

bucket.bucketName;
// ^? Output<string>
```

Three things to know:

1. **Lazy.** `bucket.bucketName` doesn't have a value yet. It
   describes "the bucket's name once it's created."
2. **Typed.** TypeScript still knows it's `string`, even though
   you can't `console.log` it directly.
3. **Tracked.** Passing it as input to another resource registers
   a dependency edge. Alchemy uses these edges to deploy in the
   right order.

You almost never construct an `Output` yourself. Resource
declarations and the operators below create them.

## Property access

Reading a property off a resource (or any `Output`) returns another
`Output`:

```typescript
const bucket = yield* Cloudflare.R2.Bucket("Bucket");

bucket.bucketName;   // Output<string>
bucket.accountId;    // Output<string>
bucket.publicDomain; // Output<string | undefined>
```

Nested access works too. `expr.nested.deep` walks down the object
without forcing the value.

## `literal`

Use this when you need an `Output` shape but already know the value:

```typescript
import * as Output from "alchemy/Output";

Output.literal("hello");      // Output<string>
Output.literal(42);           // Output<number>
Output.literal({ a: 1 });     // Output<{ a: number }>
```

It is useful as a default for an optional output, or as a placeholder
in templates and `Output.all` calls.

## `asOutput`

Lifts a plain value, an `Effect`, or an existing `Output` into an
`Output`:

```typescript
Output.asOutput("foo");                  // wraps as a literal
Output.asOutput(Effect.succeed(123));    // wraps as an EffectExpr
Output.asOutput(existingOutput);         // returns it unchanged
```

Use this when writing helpers that should accept "anything output-y."

## `fromEffect`

Lifts a plan-time Effect into an `Output`. The effect runs when the
stack resolves the Output during plan/deploy, with the stack's
services (cloud credentials, region, ...) provided. It never runs
inside a deployed runtime:

```typescript
Output.fromEffect(lookupLatestAmi());   // Output<string>
```

This is the low-level seam for lookup helpers that read cloud state to
produce a prop value. Constructing the Output is inert, so these
helpers are safe to call from composition code that re-executes
inside a deployed Function, Worker, or Instance bundle. They need no
`__ALCHEMY_RUNTIME__` guard. The higher-level form is
[`Capability.execute`](/infrastructure-as-effects/binding#plan-time-invokes),
which invokes a binding as a plan-time data source. The AMI finders
(`AWS.EC2.getAmi`, `AWS.EC2.amazonLinux2023()`,
`AWS.EC2.ubuntu2404()`, ...) are built on it:

```typescript
const instance = yield* AWS.EC2.Instance("web", {
  imageId: AWS.EC2.amazonLinux2023(),
  instanceType: "t3.micro",
  subnetId: subnet.subnetId,
});
```

The effect must not fail (`E = never`). For unresolvable lookups, die
with a descriptive error.

## `map`

`Output.map` transforms an `Output<A>` into an `Output<B>` without
forcing it. The function runs once, after the upstream resource
resolves:

```typescript
import * as Output from "alchemy/Output";

const upper = bucket.bucketName.pipe(
  Output.map((name) => name.toUpperCase()),
);
// Output<string>
```

It also supports a data-first form when you don't want to use
`pipe`:

```typescript
Output.map(bucket.bucketName, (name) => name.toUpperCase());
```

`map` composes. Pipe several together to build a chain:

```typescript
const slug = bucket.bucketName.pipe(
  Output.map((s) => s.toLowerCase()),
  Output.map((s) => s.replaceAll("_", "-")),
);
```

The function runs once per evaluation, and only after every upstream
`Output` is ready. It can't run before the resource exists.

## `mapEffect`

`Output.mapEffect` works the same way, but the transform returns an
`Effect`. Use it when the transformation does real work, such as
reading a file, calling an API, or decoding a JWT, and you want that
work to live in the Effect graph.

```typescript
const decoded = secret.value.pipe(
  Output.mapEffect((s) =>
    Effect.gen(function* () {
      const result = yield* JwtDecoder.decode(s);
      return result.payload;
    }).pipe(Effect.orDie),
  ),
);
// Output<Payload>
```

The Effect you return must not fail. Its error type is `never`, so
handle errors inside the function or turn them into defects with
`Effect.orDie`, as above.

Chain them like `map`:

```typescript
Output.literal("a").pipe(
  Output.mapEffect((s) => Effect.succeed(s + "b")),
  Output.mapEffect((s) => Effect.succeed(s + "c")),
);
// resolves to "abc"
```

`mapEffect` only has the pipeable form. There is no data-first
`Output.mapEffect(output, fn)` overload like the one `map` has.

The resulting `Output` tracks the requirements (the `R` channel) of
the inner Effects. You must provide anything those Effects need
wherever the Output is finally evaluated.

## `flatMap`

`Output.flatMap` runs a function that returns another `Output`, then
resolves that `Output` too. Use it when the next value is itself an
`Output`:

```typescript
const upper = bucket.bucketName.pipe(
  Output.flatMap((name) => Output.literal(name.toUpperCase())),
);
// Output<string>
```

Like `map`, it has both a pipeable form and a data-first form
(`Output.flatMap(output, fn)`).

:::caution
Dependency edges come only from the source `Output`. Alchemy does not
look inside the `Output` your function returns when it builds the
graph. Don't return an `Output` of a resource that isn't already
upstream of the source, or it may not be deployed yet when the
function runs.
:::

## `as`

`.as<T>()` changes the type of an `Output` without changing its
value. Use it when you know more about the resolved type than
TypeScript does. A Worker's `url` is typed `string | undefined`
because some Workers have no URL, but a Worker you serve on
`workers.dev` or a custom domain always has one:

```typescript
const url = worker.url.as<string>();
// Output<string>
```

It is a type cast only. Nothing is checked or converted at runtime.

## `all`

`Output.all` zips several `Output`s into one. The result resolves
to a tuple that preserves the input shape and types:

```typescript
const both = Output.all(bucket.bucketName, queue.queueUrl);
// Output<[string, string]>

const url = both.pipe(
  Output.map(([name, queue]) => `s3://${name}?dlq=${queue}`),
);
```

If you pass an array of `Output<T>` of unknown length, the result
is `Output<T[]>` instead of a fixed tuple.

## `interpolate`

The most common use of `all` + `map` is building a string from
outputs. `Output.interpolate` is a tagged template literal for
that:

```typescript
const arn = Output.interpolate`arn:aws:s3:::${bucket.bucketName}/objects/*`;
// Output<string>

const dsn = Output.interpolate`postgres://${db.host}:${db.port}/${db.name}`;
```

Nullish interpolated values render as the empty string.

This expands to `Output.all(...args).pipe(Output.map(...))`, so the
dependency graph is wired up automatically.

:::caution
Don't use a plain template literal or `+` with an Output. JS coercion
of an Output throws `Cannot coerce Output<…> to a string via JS
coercion`, because the value isn't known yet. Use
`` Output.interpolate`…` `` or `Output.map` instead. Arithmetic on an
Output (`+output`, `output * 2`) throws the same way.
:::

## `of`

Alchemy uses this internally to convert resources to `Output`s. You
rarely call it directly because resources already act like
`Output`s:

```typescript
import * as Alchemy from "alchemy";
import * as Output from "alchemy/Output";

const bucketOut = Output.of(bucket); // Output of the bucket's attributes

const refOut = Output.of(
  Alchemy.ref<Cloudflare.R2.Bucket>("Bucket", {
    stack: "shared-infra",
    stage: "prod",
  }),
);
```

The second form turns a reference built with `Alchemy.ref` into a
typed `Output`. See [`ref`](#ref) below.

## `ref`

To read a deployed resource's attributes from another stack or
stage, use the resource's own `.ref`:

```typescript
const bucket = yield* Cloudflare.R2.Bucket.ref("Bucket", {
  stack: "shared-infra",
  stage: "prod",
});
```

When the resource constructor isn't in scope, build the reference
with `Alchemy.ref<Type>(id, { stack, stage })` and wrap it in
`Output.of`, as in the previous section. See
[References](/infrastructure-as-code/references) for the full reference
surface (`Resource.ref`, `Alchemy.ref`, `Output.stackRef`,
`Stack.stage`) and how each is resolved.

## How Outputs compose in props

You can pass an `Output` (or any structure containing Outputs) as
the input prop of another resource. Alchemy walks the structure,
collects upstream dependencies, and waits for them to resolve
before calling the provider.

```typescript
const queue = yield* AWS.SQS.Queue("Jobs", {
  tags: {
    bucket: bucket.bucketName,
    region: Output.literal("us-west-2"),
  },
  redrivePolicy: {
    deadLetterTargetArn: dlq.queueArn,
    maxReceiveCount: 5,
  },
});
```

Plain values, Outputs, nested objects, and arrays are all valid. The
engine evaluates them recursively.

## Helpers

| Helper                 | Returns                                       |
| ---------------------- | --------------------------------------------- |
| `Output.isOutput(v)`   | `true` if `v` is an `Output<T>`               |
| `Output.isExpr(v)`     | `true` for any internal expression node       |
| `Output.upstream(o)`   | Map of upstream resources `o` depends on      |
| `Output.hasOutputs(v)` | `true` if `v` (or anything inside) is lazy    |
| `Output.toEnvKey(id, suffix)` | `"my-bucket" + "name"` → `"MY_BUCKET_NAME"` |

`upstream` and `hasOutputs` power the dependency graph. Most code
won't call them directly, but they're useful when writing custom
providers.

## Redacted values

Alchemy preserves `Redacted<T>` (Effect's secret wrapper) through
evaluation. Logs and console output show `<redacted>` in place of
the underlying value:

```typescript
import * as Redacted from "effect/Redacted";

const apiKey = Redacted.make(env.API_KEY);

yield* MyService("svc", {
  apiKey, // stays Redacted in state and logs
});
```

## Evaluation semantics

When alchemy needs the actual value of an `Output`, it runs
`Output.evaluate(expr, upstream)`. It needs the value to call a
provider, to print outputs at the end of a deploy, or to satisfy a
binding. Evaluation works like this:

1. **Resource expressions** look up the resolved attributes of
   their upstream resource.
2. **Property expressions** evaluate their parent and read the
   property.
3. **Apply / EffectExpr** evaluate the parent first, then run the
   user function.
4. **All** evaluates its children in parallel.
5. **Ref** reads from the state store using the target's stack,
   stage, and fully qualified name.
6. **Plain values** (objects, arrays, primitives) are walked
   recursively so Outputs inside them get evaluated too.
7. **`Redacted`** values are preserved as-is.

You normally never call `Output.evaluate` yourself. Alchemy invokes
it during plan and apply. Understanding the ordering still helps.
Every Output is lazy until alchemy decides to resolve it, and the
deploy graph is exactly the set of dependencies your Outputs
declared.

## Cheat sheet

| You want to…                                | Use                                          |
| ------------------------------------------- | -------------------------------------------- |
| Reference an attribute that doesn't exist yet | `resource.attr`                            |
| Wrap a constant as an Output                | `Output.literal(value)`                      |
| Coerce a value / Effect / Output to Output  | `Output.asOutput(x)`                         |
| Transform an Output                         | `output.pipe(Output.map(fn))`                |
| Transform with an Effect                    | `output.pipe(Output.mapEffect(fn))`          |
| Transform into another Output               | `output.pipe(Output.flatMap(fn))`            |
| Narrow an Output's type                     | `output.as<T>()`                             |
| Combine several Outputs                     | `Output.all(a, b, c)`                        |
| Build a string from Outputs                 | `` Output.interpolate`a/${b}/c` ``           |
| Read a resource from another stack          | `yield* X.ref("id", { stack, stage })`       |
| Inspect dependencies                        | `Output.upstream(output)`                    |
