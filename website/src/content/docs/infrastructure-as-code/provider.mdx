title: Providers
description: Providers implement the lifecycle operations for a resource type, such as reconcile, delete, diff, and read.

A **Provider** implements the lifecycle operations for a resource
type. When you `yield*` a resource inside a Stack, alchemy looks up
the provider for that resource's type and calls the matching
lifecycle method. The provider gives meaning to a
[Resource](/infrastructure-as-code/resource) declaration. The engine plans and the
provider acts.

## Provider layers

Providers are registered as Effect Layers. `Cloudflare.providers()`
and `AWS.providers()` return Layers bundling every built-in provider
for that cloud:

```typescript
Alchemy.Stack(
  "MyApp",
  { providers: Cloudflare.providers(), state: Cloudflare.state() },
  Effect.gen(function* () {
    yield* Cloudflare.R2.Bucket("Bucket");
  }),
);
```

The type system enforces this. Using a Cloudflare resource without
`Cloudflare.providers()` raises a compile-time error.

## Multiple providers

A stack can use any number of providers. Providers are Layers, so
you combine them with `Layer.mergeAll`:

```typescript
import * as Layer from "effect/Layer";

Alchemy.Stack(
  "MyApp",
  {
    providers: Layer.mergeAll(Cloudflare.providers(), AWS.providers()),
  },
  Effect.gen(function* () {
    yield* Cloudflare.R2.Bucket("Bucket");
    yield* AWS.SQS.Queue("Jobs");
  }),
);
```

This works for as many providers as you need. Built-in providers
(`Cloudflare`, `AWS`, `Neon`, `Planetscale`, `Docker`, …) and
[custom providers](/infrastructure-as-code/custom-provider) merge
the same way:

```typescript
providers: Layer.mergeAll(
  Cloudflare.providers(),
  AWS.providers(),
  Neon.providers(),
  StripeProviders, // your own custom provider layer
),
```

The type system tracks requirements per resource. Each resource you
`yield*` requires its own provider from the merged layer. A missing
provider is a compile-time error, so it never surprises you at
deploy time.

## Lifecycle operations

A provider is an object that implements some subset of these
operations. `reconcile` and `delete` are required. The rest are
optional hooks that alchemy uses for richer behavior.

### `reconcile`

Required. Alchemy calls it for every "make it so" intent. That
covers first-time provisioning, routine updates, and adoption
takeovers. It returns the **output attributes** that downstream
resources can reference.

A reconciler is a single observe → ensure → sync → return flow:

```typescript
reconcile: Effect.fn(function* ({ news, output }) {
  let live = yield* observe(output);          // read live cloud state
  if (!live) live = yield* create(news);      // ensure it exists
  if (drifted(live, news)) {
    live = yield* update(live.id, news);      // sync only the delta
  }
  return toAttributes(live);                  // fresh attributes
}),
```

The provider receives `output: Attributes | undefined` and
`olds: Props | undefined`:

| `output`    | `olds`      | Meaning                              |
| ----------- | ----------- | ------------------------------------ |
| `undefined` | `undefined` | Greenfield: no prior resource        |
| defined     | defined     | Routine update                       |
| defined     | `undefined` | Adoption: engine adopted via `read`  |

The reconciler must work for all three combinations. **Do not
branch the body on `output === undefined`**. That only renames the
old `create`/`update` split. Trust observed cloud state over `olds`.

`reconcile` must be **idempotent**, because alchemy may retry it
after a state persistence failure. With deterministic physical names
and the observe step, a retry finds the existing resource and
re-syncs any drifted fields.

The [custom provider guide](/infrastructure-as-code/custom-provider#implement-reconcile)
builds a real reconciler against the Stripe API step by step:
observe, ensure, sync, return.

### `delete`

Required. Alchemy calls it when a resource is removed from code,
when it is replaced, or when you run `alchemy destroy`. Like
`reconcile`, it must be **idempotent**. Treat "already deleted" as
success.

```typescript
delete: ({ output }) =>
  Effect.promise(() => stripe.products.del(output.productId));
```

### `diff`

Optional. Alchemy calls it during planning to decide what kind of
change is needed when properties differ. It returns a tagged `Diff`
that describes the action:

```typescript
diff: Effect.fn(function* ({ news, olds }) {
  if (news.region !== olds.region) {
    return { action: "replace" } as const;
  }
  if (news.name !== olds.name) {
    return { action: "update" } as const;
  }
  return { action: "noop" } as const;
}),
```

The shape is one of:

- **`{ action: "noop" }`**: the properties differ trivially. Don't
  call `update`.
- **`{ action: "update", stables?: [...] }`**: apply an in-place
  update. `stables` lists props that are guaranteed not to change
  during this update.
- **`{ action: "replace", deleteFirst?: boolean }`**: destroy and
  recreate (see [Resource Lifecycle › Replace](/infrastructure-as-code/resource-lifecycle#replace)).
  Set `deleteFirst: true` for resources that can't coexist with
  their replacement (e.g. unique-name constraints).
- **`void` / `undefined`**: fall back to the default behavior,
  which treats the change as an `update`.

A provider can also declare top-level `stables` for attributes that
are immutable across all updates (e.g. ARNs, resource IDs).

To compare nested objects, use the `deepEqual` and
`anyPropsAreDifferent` helpers from `alchemy/Diff`. An input might
still be an unresolved `Output` when `diff` runs. In that case,
guard with `isResolved` first and return `undefined` so the default
path handles it.

### `read`

Optional. The engine calls `read` whenever a resource has no prior
state. This covers **state recovery** (state lost between create and
persist) and **adoption** (a fresh state store deploying against
existing cloud infrastructure). It is the single source of truth for
"does this resource exist, and is it ours?".

```typescript
read: Effect.fn(function* ({ id, olds, output }) {
  const stripe = yield* StripeClient;
  if (!output?.productId) return undefined;
  const product = yield* Effect.tryPromise(() =>
    stripe.products.retrieve(output.productId),
  ).pipe(Effect.catchAll(() => Effect.succeed(undefined)));
  if (!product) return undefined;
  return { productId: product.id, name: product.name };
}),
```

`read` returns one of three values:

- **`undefined`**: the resource doesn't exist. The engine drives a
  normal `create`.
- **plain attributes**: the resource exists and we own it. The
  engine adopts it silently. It persists the attributes as the
  initial `created` state and lets ordinary `diff` decide whether
  the next deploy is a noop or update.
- **`Unowned(attributes)`**: the resource exists but we don't
  own it. By default the engine fails with `OwnedBySomeoneElse`
  so you don't accidentally clobber a production resource.
  Re-running with `--adopt` (or scoping the effect with
  `adopt(true)`) allows a takeover.

`Unowned` is a brand from `alchemy/AdoptPolicy`. It is a hidden
symbol on the attributes object, so there is no wrapper to unwrap:

```typescript
import { Unowned } from "alchemy/AdoptPolicy";

read: Effect.fn(function* ({ id, olds }) {
  const live = yield* lookup(olds.name);
  if (!live) return undefined;
  const attrs = { productId: live.id, name: live.name };
  return ownsResource(id, live.tags) ? attrs : Unowned(attrs);
}),
```

**Inputs.** `read` may be called for an existence/adoption probe with
`output: undefined` (no prior state). Resources whose live lookup
requires a previously-persisted ID (e.g. `output.productId`) should
return `undefined` in that case. They cannot find the resource
without it.

**Ownership detection.** Resources with no notion of ownership (e.g.
"the cloud API gives us a single global object by name") should
always return plain attributes. The engine treats them as owned and
adopts them silently by default, so `--adopt` is unnecessary.
Resources with tag-based or naming-based ownership (most cloud
resources) should brand foreign-owned attributes with `Unowned`.

> **Lifecycle methods don't gate on ownership.** Once `read` clears a
> resource for write, `reconcile` can assume it's safe to proceed.
> Don't repeat the ownership check inside `reconcile`. That hides
> the policy decision from the engine.

### `precreate`

Optional. Reserves a physical name (or stub resource) before
`create` runs. This enables [circular
bindings](/infrastructure-as-effects/circular-bindings). Worker A can know Worker B's
URL before either is fully created.

### `list`

Enumerates every existing resource of this type in the ambient
scope (account, region, or zone). It returns the same `Attributes`
shape that `read` produces, so you can pass each item directly to
`delete`. This powers account-wide operations like
[`alchemy unsafe nuke`](/cli/nuke). It must paginate exhaustively.
Resources with no enumeration API (singletons, existence-only
resources) return an empty array. Providers can opt out of nuke
with `nuke.singleton` (delete only resets always-present config)
or `nuke.skip` (the resource can never be deleted).

### `tail` / `logs`

Optional. Powers `alchemy logs --tail` (live log streaming) and
`alchemy logs` (historical fetch). Each returns a `Stream` or
`Effect` of `LogLine` values respectively.

## Plan and apply

Alchemy combines every provider's lifecycle operations into a single
**plan**, then **applies** it.

- **Plan**: for each declared resource, alchemy compares the
  desired props against persisted state. It uses `diff` to decide
  whether the change is a `create`, `update`, `replace`, or `noop`.
  Anything in state that is no longer declared is marked for `delete`.
- **Apply**: alchemy walks the plan in dependency order and calls
  the matching lifecycle operation on each provider. It surfaces the
  results as `Output`s for downstream resources.

See [Resource Lifecycle](/infrastructure-as-code/resource-lifecycle) for how a
resource moves through these phases over time.

## Authoring a custom provider

Providers are Layers. To add a new cloud or third-party API, declare
a [Resource type](/infrastructure-as-code/resource) and implement a
Layer. Then merge it alongside `Cloudflare.providers()` or
`AWS.providers()`. The [custom provider guide](/infrastructure-as-code/custom-provider)
builds a Stripe `Product` provider end-to-end.
