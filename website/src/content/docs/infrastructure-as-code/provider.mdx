A provider implements the lifecycle operations for one resource type.
The engine plans a deploy and then calls these operations on the
provider. This page lists what each operation receives, returns, and
must guarantee.

- To register providers on a stack, see [Stacks › Multiple providers](/infrastructure-as-code/stack#multiple-providers).
- To build your first provider step by step, see [Custom Provider](/infrastructure-as-code/custom-provider).
- For how plan and apply call these operations, see [Resource lifecycle › Apply](/infrastructure-as-code/resource-lifecycle#apply).

## Lifecycle operations

A provider is an object passed to `Provider.succeed` or
`Provider.effect` from `alchemy/Provider`:

```typescript
import * as Provider from "alchemy/Provider";

export const ProductProvider = () =>
  Provider.succeed(
    Product,
    Product.Provider.of({
      stables: ["productId"], // optional
      reconcile: Effect.fn(function* ({ news, olds, output, bindings }) { /* ... */ }),
      delete: Effect.fn(function* ({ output }) { /* ... */ }),
      list: () => Effect.succeed([]),
      // optional: diff, read, precreate, tail, logs
    }),
  );
```

- [`reconcile`](#reconcile): required. Called for every create,
  update, and adoption. Returns the attributes.
- [`delete`](#delete): required. Called on removal, replacement, and
  `alchemy destroy`. Returns `void`.
- [`list`](#list): required by `Product.Provider.of(...)`. Defaults to
  an empty list when you pass a plain object. Called by
  `alchemy unsafe nuke`. Returns an array of attributes.
- [`diff`](#diff): optional. Called on every plan of a resource that
  has state. Returns a `Diff` or `undefined`.
- [`read`](#read): optional. Called when a resource has no prior
  state. Returns attributes, `Unowned(attributes)`, or `undefined`.
- [`precreate`](#precreate): optional, but required for resources in a
  dependency cycle. Called before the first `reconcile` of a new
  resource. Returns stub attributes.
- [`tail` / `logs`](#tail--logs): optional. Called by `alchemy logs`.
  Returns log lines.

### `reconcile`

`reconcile` converges the cloud to the desired props in `news` and
returns the output attributes that downstream resources reference.
One observe, ensure, sync, return flow handles every case:

```typescript
reconcile: Effect.fn(function* ({ news, output }) {
  let live = yield* observe(output);          // read live cloud state
  if (!live) live = yield* create(news);      // ensure it exists
  if (drifted(live, news)) {
    live = yield* update(live.id, news);      // sync only the delta
  }
  return toAttributes(live);                  // fresh attributes
}),
```

The values of `output` (the last attributes) and `olds` (the last
props) tell the cases apart:

- **Greenfield**: `output` and `olds` are both `undefined`. No prior
  resource exists.
- **Routine update**: `output` and `olds` are both defined.
- **Adoption**: `output` is defined and `olds` is `undefined`. The
  engine adopted the resource through [`read`](#read).

Rules for the body:

- Write one flow that works for all three cases. Don't branch on
  `output === undefined`, because that only renames the old
  `create`/`update` split.
- Trust observed cloud state over `olds`. Treat `output` as a cache of
  identifiers. It doesn't prove that the resource still exists.
- Treat an "already exists" error from the create call as a race.
  Observe the resource again and continue with the sync step.
- Make it idempotent. The next deploy runs `reconcile` again after a
  crash or a failed state write. With physical names built from the
  instance ID, a re-run finds the existing resource and re-syncs it.
- Don't check ownership. The engine has already cleared the resource
  through `read` before `reconcile` runs.
- Read `bindings` if the resource is a binding target. It holds the
  data that upstream bindings and event sources attached, such as IAM
  grants or queue subscriptions. See [Bindings](/infrastructure-as-effects/binding).

The input also carries `id`, `fqn`, `instanceId`, and a `session` for
progress reporting. The [Custom Provider guide](/infrastructure-as-code/custom-provider#implement-reconcile)
builds a full reconciler against the Stripe API.

### `delete`

`delete` removes the cloud resource. It receives the last `output`,
`olds`, and `bindings`.

- Make it idempotent. Persistence can fail after the cloud call
  succeeds, so the next run calls `delete` again. Treat "not found" as
  success.
- `force` is set only by `alchemy unsafe nuke`. Nuke passes attributes
  as `olds`, and `force` allows destructive steps that a normal destroy
  gates behind a prop, such as emptying a bucket.

See [Custom Provider › Implement delete](/infrastructure-as-code/custom-provider#implement-delete)
for a handler that catches a missing object.

### `diff`

`diff` decides what kind of change a plan makes. It returns a `Diff`
from `alchemy/Diff`, or `undefined` to let the engine decide:

```typescript
import { isResolved } from "alchemy/Diff";

diff: Effect.fn(function* ({ news, olds }) {
  if (!isResolved(news)) return undefined; // news may hold unresolved Outputs
  if (news.region !== olds.region) {
    return { action: "replace" } as const;
  }
  return undefined; // the engine plans update or noop
}),
```

The return shapes:

- **`undefined`**: the engine compares old and new props and
  bindings. It plans `update` if anything changed, otherwise `noop`.
  Return this for most changes.
- **`{ action: "update", stables?: [...] }`**: an in-place update.
  `stables` lists attributes that this update does not change.
- **`{ action: "replace", deleteFirst?: boolean }`**: create a new
  resource and delete the old one. Set `deleteFirst: true` when the two
  can't coexist, for example under a unique-name constraint. See
  [Resource lifecycle › Replace](/infrastructure-as-code/resource-lifecycle#replace).
- **`{ action: "noop" }`**: ignore this change on purpose. This is
  rare. Returning it as a fallback makes the engine ignore every
  change your `diff` doesn't check.

`diff` runs at plan time, so `news` and `newBindings` may still contain
unresolved `Output`s. Guard with `isResolved` and return `undefined`
when you can't decide. To compare nested values, use `deepEqual` and
`anyPropsAreDifferent` from `alchemy/Diff`.

A top-level `stables` array on the provider lists attributes that
never change across any update, such as an ARN or an ID.
`alchemy deploy --force` upgrades every `noop` to `update`, whether
the engine or your `diff` decided it.

### `read`

`read` answers whether a resource exists and whether it is yours. The
engine calls it whenever a resource has no prior state, which covers
two cases:

- **State recovery**: a create succeeded but its state write failed.
- **Adoption**: a fresh state store deploys against existing cloud
  resources. See [Adopting resources](/cli/adopting-resources).

It returns one of three values:

```typescript
import { Unowned } from "alchemy/AdoptPolicy";

read: Effect.fn(function* ({ id, olds, output }) {
  const live = yield* lookup(output?.productId ?? olds.name);
  if (!live) return undefined;                   // engine creates it
  const attrs = { productId: live.id, name: live.name };
  return ownsResource(id, live.tags)
    ? attrs                                      // engine adopts silently
    : Unowned(attrs);                            // engine fails with OwnedBySomeoneElse
}),
```

- **`undefined`**: the resource doesn't exist. The engine plans a
  create.
- **Plain attributes**: the resource exists and you own it. The engine
  adopts the attributes as `created` state and runs `diff`. A `noop`
  is upgraded to `update`, so `reconcile` re-syncs the resource with
  your props.
- **`Unowned(attributes)`**: the resource exists but you don't own it.
  The engine fails with `OwnedBySomeoneElse` so it doesn't overwrite a
  resource another stack manages. `--adopt`, or `adopt(true)` from
  `alchemy/AdoptPolicy`, allows the takeover.

`Unowned` brands the attributes with a hidden symbol, so there is no
wrapper to unwrap. Other rules:

- `output` is `undefined` for an adoption probe. A resource that can
  only be found by a saved ID returns `undefined` in that case.
- A resource with no notion of ownership, such as a global object
  looked up by name, always returns plain attributes. The engine adopts
  it without `--adopt`.
- A resource with tag-based or name-based ownership brands foreign
  attributes with `Unowned`. Once `read` clears a resource, the
  lifecycle operations don't repeat the ownership check.

### `precreate`

`precreate` creates a stub, or reserves a physical name, before the
first `reconcile` of a new resource. It returns stub attributes so dependents can start
early, which lets Worker A know Worker B's URL before either is fully
created.

Every resource in a dependency cycle must implement `precreate`. See
[Circular bindings](/infrastructure-as-effects/circular-bindings).

### `list`

`list` enumerates every existing resource of this type in the ambient
scope (account, region, or zone). It takes no input and returns the
same attributes shape as `read`, so each item can go straight to
`delete`. It powers [`alchemy unsafe nuke`](/cli/nuke).

- Paginate exhaustively so the array is complete.
- Return an empty array when the API has no enumeration, as for
  singletons and existence-only resources.
- `Provider.succeed` and `Provider.effect` default `list` to
  `() => Effect.succeed([])` when you pass a plain object. The typed
  `Resource.Provider.of({...})` constructor requires it, so write the
  empty stub there.

To change how nuke treats the type, set `nuke` on the provider:

```typescript
Product.Provider.of({
  nuke: {
    singleton: true,              // delete only resets always-present config
    // skip: true,                // the resource can never be deleted
    // dependsOn: ["AWS.IAM.Role"], // types that must outlive this one's teardown
  },
  // ...
});
```

### `tail` / `logs`

`tail` returns a `Stream` of `LogLine` values for
`alchemy logs --tail`. `logs` returns an `Effect` of `LogLine[]` for
`alchemy logs`, with optional `since` and `limit` options.
