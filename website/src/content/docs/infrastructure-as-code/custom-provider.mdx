This guide builds a provider for a Stripe `Product`, so you can manage
an API that Alchemy doesn't cover yet. You declare the resource type,
implement its lifecycle, bundle it into a `providers()` layer, and test
it. Stripe is the example, and the same steps apply to any API.

You need a Stripe test-mode secret key (`sk_test_...`) and the `stripe`
npm package. The [Provider contract](/infrastructure-as-code/provider)
lists every rule the operations below follow.

## Declare props and attributes

A resource has input properties that you pass in and output attributes
that the API returns. See [Resources](/infrastructure-as-code/resource)
for the concept. Start with two plain TypeScript types in
`src/stripe/Product.ts`:

```typescript
// src/stripe/Product.ts
export interface StripeProductProps {
  name: string;
  description?: string;
  active?: boolean;
}

export interface StripeProductAttributes {
  productId: string;
  created: number;
}
```

## Declare the resource type

A `Resource<Type, Props, Attributes>` is a phantom type that ties a
string `Type` to its props and attributes. Alchemy uses the string
(here `"Stripe.Product"`) to find the provider at plan time, so it must
be globally unique.

:::note
Alchemy ships a full Stripe provider in `alchemy/Stripe` that already
uses `"Stripe.Product"`. This guide rebuilds a small version to teach
the pattern. In your own project, pick a type string no built-in uses,
such as `"MyCo.Product"`.
:::

```diff lang="typescript"
// src/stripe/Product.ts
+import { Resource } from "alchemy";
+
export interface StripeProductProps {
  name: string;
  description?: string;
  active?: boolean;
}

export interface StripeProductAttributes {
  productId: string;
  created: number;
}
+
+export type StripeProduct = Resource<
+  "Stripe.Product",
+  StripeProductProps,
+  StripeProductAttributes
+>;
```

## Declare the resource constructor (the "tag")

`Resource<T>(type)` returns the value users call, such as
`StripeProduct("Pro", { ... })`. It is also the **tag** that the
provider layer registers against. By convention, the type and the value
share a name.

```diff lang="typescript"
// src/stripe/Product.ts
import { Resource } from "alchemy";

// ... props / attributes / type unchanged ...

export type StripeProduct = Resource<
  "Stripe.Product",
  StripeProductProps,
  StripeProductAttributes
>;
+
+export const StripeProduct = Resource<StripeProduct>("Stripe.Product");
```

You can use this constructor in a stack already. With no provider
registered, planning fails with `Provider not found for Stripe.Product`.
The next step fixes that.

## Scaffold the provider layer

`Provider.succeed(ResourceClass, service)` turns an object of lifecycle
handlers into a `Layer<Provider<R>>`. Start with stubs so the types
compile:

```diff lang="typescript"
// src/stripe/Product.ts
-import { Resource } from "alchemy";
+import * as Provider from "alchemy/Provider";
+import { Resource } from "alchemy";
+import * as Effect from "effect/Effect";

// ... props / attributes / type / constructor unchanged ...

export const StripeProduct = Resource<StripeProduct>("Stripe.Product");
+
+export const StripeProductProvider = () =>
+  Provider.succeed(
+    StripeProduct,
+    StripeProduct.Provider.of({            // types every handler against the resource
+      reconcile: () => Effect.die("not implemented"), // required
+      delete: () => Effect.die("not implemented"),    // required
+      list: () => Effect.succeed([]),                 // required by Provider.of
+    }),
+  );
```

Use `Provider.effect` instead when the service needs a dependency
resolved once at construction, such as `FileSystem`. Don't resolve
credentials there, because provider layers build before any credentials
exist.

## Credentials

The handlers need a Stripe API key. Declare a credentials service whose
value is a lazy `Effect`, so nothing reads the key until an operation
runs:

```typescript
// src/stripe/Credentials.ts
import * as Config from "effect/Config";
import * as Context from "effect/Context";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import * as Redacted from "effect/Redacted";

export class StripeCredentials extends Context.Service<
  StripeCredentials,
  Effect.Effect<{ apiKey: Redacted.Redacted<string> }>
>()("StripeCredentials") {}

// Reads STRIPE_API_KEY when a handler runs, not when the layer builds.
export const fromEnv = () =>
  Layer.succeed(
    StripeCredentials,
    Config.Redacted("STRIPE_API_KEY").pipe(
      Effect.map((apiKey) => ({ apiKey })),
      Effect.orDie,
    ),
  );
```

To read the key from an Alchemy profile with `alchemy profile edit`,
replace `fromEnv()` with the auth provider from
[Custom Auth Provider](/environments/custom-auth-provider). Providers
that wrap an unauthenticated API skip this step.

## Implement `reconcile`

`reconcile` converges Stripe to the desired props in `news`. It runs
for creates, updates, and adoptions, so you write one observe, ensure,
sync, and return flow. See
[Provider contract › reconcile](/infrastructure-as-code/provider#reconcile)
for the rules this flow follows.

### Resolve the client

```diff lang="typescript"
+import * as Redacted from "effect/Redacted";
+import Stripe from "stripe";
+import { StripeCredentials } from "./Credentials.ts";
+
Provider.succeed(StripeProduct, StripeProduct.Provider.of({
-  reconcile: () => Effect.die("not implemented"),
+  reconcile: Effect.fn(function* ({ news, output }) {
+    const { apiKey } = yield* yield* StripeCredentials;
+    const stripe = new Stripe(Redacted.value(apiKey));
+  }),
  delete: () => Effect.die("not implemented"),
  list: () => Effect.succeed([]),
}));
```

The first `yield*` gets the lazy Effect from the service, and the second
runs it. The provider layer builds without reading the key.

### Observe

```diff lang="typescript"
 reconcile: Effect.fn(function* ({ news, output }) {
   const { apiKey } = yield* yield* StripeCredentials;
   const stripe = new Stripe(Redacted.value(apiKey));
+
+  let product = output?.productId
+    ? yield* Effect.tryPromise(() =>
+        stripe.products.retrieve(output.productId),
+      ).pipe(Effect.catch(() => Effect.succeed(undefined)))
+    : undefined;
 }),
```

If a previous run saved a `productId`, look up the live product. A failed
`retrieve` means it is missing, because `output` only caches identifiers.

:::tip[Use `Effect.tryPromise`, not `Effect.promise`]
`Effect.tryPromise` surfaces SDK errors as Effect failures that the
engine reports cleanly. `Effect.promise` turns rejections into defects.
:::

### Ensure

```diff lang="typescript"
   let product = output?.productId
     ? // ... observe ...
     : undefined;
+
+  if (!product) {
+    product = yield* Effect.tryPromise(() =>
+      stripe.products.create({
+        name: news.name,
+        description: news.description,
+        active: news.active,
+      }),
+    );
+  }
 }),
```

Create only when observation comes back empty. A greenfield create and a
saved ID that points at nothing both recover through this branch.

### Sync

```diff lang="typescript"
   if (!product) {
     // ... ensure ...
   }
+
+  if (
+    product.name !== news.name ||
+    product.description !== (news.description ?? null) ||
+    product.active !== (news.active ?? true)
+  ) {
+    product = yield* Effect.tryPromise(() =>
+      stripe.products.update(product!.id, {
+        name: news.name,
+        description: news.description,
+        active: news.active,
+      }),
+    );
+  }
 }),
```

Compare each mutable field of the observed product against `news`, and
write only when something drifted. A deploy with no drift makes zero
write calls.

### Return fresh attributes

```diff lang="typescript"
   if (/* drifted */) {
     // ... sync ...
   }
+
+  return {
+    productId: product.id,
+    created: product.created,
+  };
 }),
```

Alchemy persists the returned attributes to state. They become the next
run's `output`.

## Implement `delete`

`delete` runs when you remove the resource from code, when it is
replaced, and on `alchemy destroy`. It must be idempotent, so treat
"not found" as success:

```diff lang="typescript"
Provider.succeed(StripeProduct, StripeProduct.Provider.of({
  reconcile: Effect.fn(function* ({ news, output }) { /* ... */ }),
-  delete: () => Effect.die("not implemented"),
+  delete: Effect.fn(function* ({ output }) {
+    const { apiKey } = yield* yield* StripeCredentials;
+    const stripe = new Stripe(Redacted.value(apiKey));
+    yield* Effect.tryPromise({
+      try: () => stripe.products.del(output.productId),
+      catch: (error) => error as { code?: string }, // keep the SDK error
+    }).pipe(
+      Effect.catch((e) =>
+        e.code === "resource_missing" ? Effect.void : Effect.fail(e),
+      ),
+    );
+  }),
  list: () => Effect.succeed([]),
}));
```

Without a `catch` option, `Effect.tryPromise` wraps every rejection in an
`UnknownError` with a generic message. The `catch` option keeps Stripe's
error so you can match `resource_missing`, its code for a missing object.

## Implement `diff` (optional)

Some changes can't be applied in place. Suppose a Stripe product's
`description` can't change (hypothetically). Return a replacement for
that prop and let the engine decide everything else:

```diff lang="typescript"
+import { isResolved } from "alchemy/Diff";
+
// ...

Provider.succeed(StripeProduct, StripeProduct.Provider.of({
+  diff: Effect.fn(function* ({ news, olds }) {
+    if (!isResolved(news)) return undefined; // props may be unresolved Outputs at plan time
+    if (news.description !== olds.description) {
+      return { action: "replace" } as const;
+    }
+    return undefined; // the engine plans update or noop
+  }),
  reconcile: Effect.fn(function* ({ news, output }) { /* ... */ }),
  delete: Effect.fn(function* ({ output }) { /* ... */ }),
  list: () => Effect.succeed([]),
}));
```

Declare attributes that never change across updates, such as the
product ID, in a top-level `stables` array. `stables` never triggers a
replacement:

```diff lang="typescript"
Provider.succeed(StripeProduct, StripeProduct.Provider.of({
+  stables: ["productId"],
  diff: Effect.fn(function* ({ news, olds }) { /* ... */ }),
  // ...
}));
```

See [Provider contract › diff](/infrastructure-as-code/provider#diff)
for every return shape, including `deleteFirst` and `noop`.

## Implement `read` (optional, for recovery and adoption)

The engine calls `read` when a resource has no prior state. It recovers
from an interrupted reconcile and imports existing products into a
fresh state store. Returning `undefined` means the product doesn't
exist:

```diff lang="typescript"
Provider.succeed(StripeProduct, StripeProduct.Provider.of({
  stables: ["productId"],
  diff: Effect.fn(function* ({ news, olds }) { /* ... */ }),
+  read: Effect.fn(function* ({ output }) {
+    if (!output?.productId) return undefined; // no saved ID, nothing to find
+    const { apiKey } = yield* yield* StripeCredentials;
+    const stripe = new Stripe(Redacted.value(apiKey));
+    const product = yield* Effect.tryPromise(() =>
+      stripe.products.retrieve(output.productId),
+    ).pipe(
+      Effect.catch(() => Effect.succeed(undefined)),
+    );
+    if (!product) return undefined;
+    return { productId: product.id, created: product.created };
+  }),
  reconcile: Effect.fn(function* ({ news, output }) { /* ... */ }),
  delete: Effect.fn(function* ({ output }) { /* ... */ }),
  list: () => Effect.succeed([]),
}));
```

If your provider can find a resource from props alone, through tags or
deterministic names, brand foreign ones with `Unowned`. See
[Provider contract › read](/infrastructure-as-code/provider#read).

## Implement `list`

`list` returns every product in the account in the same shape as
`read`. It powers [`alchemy unsafe nuke`](/cli/nuke), so it must
paginate to the end:

```diff lang="typescript"
Provider.succeed(StripeProduct, StripeProduct.Provider.of({
  stables: ["productId"],
-  list: () => Effect.succeed([]),
+  list: Effect.fn(function* () {
+    const { apiKey } = yield* yield* StripeCredentials;
+    const stripe = new Stripe(Redacted.value(apiKey));
+    const products = yield* Effect.tryPromise(() =>
+      stripe.products.list({ limit: 100 }).autoPagingToArray({ limit: 10_000 }),
+    );
+    return products.map((p) => ({ productId: p.id, created: p.created }));
+  }),
  // ...
}));
```

A resource with no enumeration API, such as a singleton, keeps the
`Effect.succeed([])` stub.

## Bundle into a `providers()` layer

Give users the same one-line setup as `Cloudflare.providers()`. Bundle
the resource collection, each provider, and the credentials layer into
one layer:

```typescript
// src/stripe/Providers.ts
import * as Provider from "alchemy/Provider";
import * as Layer from "effect/Layer";
import * as Credentials from "./Credentials.ts";
import { StripeProduct, StripeProductProvider } from "./Product.ts";

export class Providers extends Provider.ProviderCollection<Providers>()(
  "Stripe",
) {}

export const providers = () =>
  Layer.effect(Providers, Provider.collection([StripeProduct])).pipe(
    Layer.provide(StripeProductProvider()),     // wire each provider privately
    Layer.provideMerge(Credentials.fromEnv()),  // meet the handlers' StripeCredentials
  );
```

Re-export the public surface without the service prefix, so callers
write `Stripe.Product`:

```typescript
// src/stripe/index.ts
export { StripeProduct as Product } from "./Product.ts";
export { Providers, providers } from "./Providers.ts";
```

Users plug your providers in like any built-in. The stack code holds no
API key, and the deploy reads `STRIPE_API_KEY` from the environment:

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Effect from "effect/Effect";
import * as Stripe from "./src/stripe";

export default Alchemy.Stack(
  "MyApp",
  { providers: Stripe.providers(), state: Alchemy.localState() },
  Effect.gen(function* () {
    const pro = yield* Stripe.Product("Pro", {
      name: "Pro plan",
      description: "Everything in Free, plus...",
    });
    return { productId: pro.productId };
  }),
);
```

To use Stripe next to another cloud, merge the layers with
`Layer.mergeAll(Cloudflare.providers(), Stripe.providers())`. See
[Stacks › Multiple providers](/infrastructure-as-code/stack#multiple-providers).

To let users connect Stripe with `alchemy profile edit`, swap
`fromEnv()` for an auth provider as shown in
[Custom Auth Provider › Bundle into providers()](/environments/custom-auth-provider#bundle-into-providers).

## Test the lifecycle

`test.provider` gives each test a private scratch stack for driving
create, update, and destroy. See
[Test harness › Scratch stacks](/testing/test-harness#scratch-stacks)
for how scratch state works, and
[Testing Providers](/testing/testing-providers) for cleanup. Create
`test/Product.test.ts`:

```typescript
// test/Product.test.ts
import * as Test from "alchemy/Test/Vitest";
import { expect } from "@effect/vitest";
import * as Effect from "effect/Effect";
import Stripe from "stripe";
import * as StripeProvider from "../src/stripe";

// Configure providers once per file. The handlers read STRIPE_API_KEY.
const { test } = Test.make({ providers: StripeProvider.providers() });

const stripe = new Stripe(process.env.STRIPE_API_KEY!);

test.provider(
  "create, update, delete a product",
  (stack) => Effect.gen(function* () {
    // Create
    const created = yield* stack.deploy(
      Effect.gen(function* () {
        return yield* StripeProvider.Product("TestProduct", {
          name: "v1",
          description: "first version",
        });
      }),
    );
    expect(created.productId).toBeDefined();

    const live1 = yield* Effect.tryPromise(() =>
      stripe.products.retrieve(created.productId),
    );
    expect(live1.name).toBe("v1");

    // Update in place: same logical ID, new name
    const updated = yield* stack.deploy(
      Effect.gen(function* () {
        return yield* StripeProvider.Product("TestProduct", {
          name: "v2",
          description: "first version",
        });
      }),
    );
    expect(updated.productId).toBe(created.productId);

    const live2 = yield* Effect.tryPromise(() =>
      stripe.products.retrieve(updated.productId),
    );
    expect(live2.name).toBe("v2");

    // Destroy
    yield* stack.destroy();
  }),
  { timeout: 180_000 },
);
```

To verify a replacement, change `description`, which the `diff` above
answers with `{ action: "replace" }`. Then assert that
`updated.productId !== created.productId`. See
[Verify replacement](/testing/testing-providers#verify-replacement).
