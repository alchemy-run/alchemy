beta.77 rebuilds the CLI. Profiles are redesigned: `alchemy login`
is replaced by `alchemy profile`, a dashboard where you connect
Cloudflare, AWS, and other providers to a profile and use it from
every stack. `deploy`, `destroy`, `plan`, and `dev` share one plan view,
the prompts are redesigned, exit codes are script-safe, and
output is plain wherever there is no terminal. `alchemy dev`
reloads only when a file the stack depends on changes. Also in
this release: cron schedules on Workflows, `Cloudflare.Telemetry()`
for Workers Observability, and provisioned ElastiCache on AWS.

:::caution
**Breaking changes**

- **`alchemy deploy` defaults to `live_$USER`**
  ([#1421](https://github.com/alchemy-run/alchemy/pull/1421)) —
  `plan`, `destroy`, `logs`, and `drift` follow; `alchemy dev`
  keeps `dev_$USER`. A bare `alchemy deploy` will not update an
  existing `dev_sam` stack — pass `--stage dev_sam` to keep the
  old target. And the stage env var is now **`ALCHEMY_STAGE`**;
  `STAGE` is no longer consulted
  ([#1433](https://github.com/alchemy-run/alchemy/pull/1433)).
- **Commands moved**
  ([#1234](https://github.com/alchemy-run/alchemy/pull/1234),
  [#1235](https://github.com/alchemy-run/alchemy/pull/1235),
  [#1429](https://github.com/alchemy-run/alchemy/pull/1429)) —
  `alchemy login` is `alchemy profile`, the positional stack file
  is `--config`, `tail` is `logs --follow`, `sync` is
  `drift --repair`, `destroy --dry-run` is `plan --destroy`, and
  top-level `aws` / `cloudflare` are `provider aws` /
  `provider cloudflare`. `profile show|edit|refresh` take
  `--profile <name>` instead of a positional. The old names print
  a migration hint instead of running. See
  [below](#one-command-map).
- **The AWS `local` auth method is removed**
  ([#1480](https://github.com/alchemy-run/alchemy/pull/1480)) —
  `alchemy dev` wires the local emulator itself, so the profile
  method was redundant.
- **Custom auth providers** — `StackServices` lists `Interaction`
  instead of `CliKit`, and `configure`/`login`/`logout`/`details`
  require `Interaction` at call time
  ([#1430](https://github.com/alchemy-run/alchemy/pull/1430)). See
  [Custom Auth Providers](/environments/custom-auth-provider).
- **distilled operations are `verbNoun`**
  ([#1517](https://github.com/alchemy-run/alchemy/pull/1517)) —
  if you call a distilled client directly, `railway.serviceCreate`
  is now `railway.createService`, `volumeDelete` is
  `deleteVolume`, and so on. Alchemy's own resources are already
  renamed.
:::

## Profiles

Profiles are redesigned
([#1234](https://github.com/alchemy-run/alchemy/pull/1234),
[#1475](https://github.com/alchemy-run/alchemy/pull/1475),
[#1480](https://github.com/alchemy-run/alchemy/pull/1480)). A
profile is still a bundle of connected provider accounts —
Cloudflare via OAuth, AWS via SSO, GitHub via `gh`, a pasted token
for Neon. What changes: `alchemy login` and its wizard are replaced
by `alchemy profile`, a built-in `default` profile always exists
(like the AWS CLI) so there is no create step and no stored
"current profile" to switch, and every command uses `default`
unless you name another:

```sh
alchemy profile                  # dashboard: connect, refresh, switch
alchemy deploy                   # uses `default`
alchemy deploy --profile work    # or ALCHEMY_PROFILE=work
```

`alchemy profile` with no subcommand opens the dashboard: profiles
as tabs, one row per connected provider with its method and
credential status, and single-key actions — `e` edit, `r`
refresh, `n` new, `R` rename, `d` delete. Editing a profile is one
menu: Space cycles each provider through add / re-configure /
remove, Enter runs the queued flows in order, and OAuth opens your
browser.

Credentials are stored per profile. Each provider writes one
typed document under `~/.alchemy/credentials/<profile>/` at mode
`0600`, refreshes hold a cross-process lock so two concurrent
deploys can't both rotate the same OAuth token, and a stored file
that fails schema validation is backed up and reported with a
`--reconfigure` hint rather than silently loaded.

Logging in only happens through `profile` commands.
`deploy`, `plan`, and `dev` never open a surprise wizard — a
missing credential fails with a `CredentialsRequired` error that
names the demanding resources and the exact `alchemy profile edit
--add …` to run.

Scripts and agents skip the prompts entirely. `--method` picks the
provider's configure method and `--set` fills its fields, with
values from a literal, an env var, or stdin so secrets stay out of
shell history:

```sh
alchemy profile edit --add cloudflare --method stored \
  --set apiToken=env:CLOUDFLARE_API_TOKEN \
  --set accountId=0123456789abcdef0123456789abcdef

op read op://vault/neon/key | alchemy profile edit --add neon --method stored --set apiKey=-
```

Environment variables take precedence over an implicit profile. Outside
CI, explicit provider env vars (`CLOUDFLARE_API_TOKEN`,
`AWS_ACCESS_KEY_ID`, …) take precedence over an *implicit* profile,
decided per provider — so Cloudflare from env and AWS from the
profile works — and the CLI logs which variables it used, once
([#1520](https://github.com/alchemy-run/alchemy/pull/1520)). An
explicit `--profile` is always authoritative. In CI, profiles are
never read; `alchemy provider check-env` verifies the required
variables up front.

Pre-overhaul stores migrate on first read
([#1429](https://github.com/alchemy-run/alchemy/pull/1429),
[#1475](https://github.com/alchemy-run/alchemy/pull/1475)): the
old manifest and credential files move to
`~/.alchemy/.v0-profiles-<timestamp>/` for recovery, every
profile/provider entry is kept, and providers whose stored secrets
can't be reused report a clean `NeedsReauth` with the command to
fix it.

Docs: [profile](/cli/profile) · [Profiles](/environments/profiles)
· [Auth Providers](/environments/auth-providers) ·
[CI](/environments/ci).

## One command map

The CLI is reorganized around nouns
([#1235](https://github.com/alchemy-run/alchemy/pull/1235)):

```text
alchemy
├─ deploy | plan | destroy
├─ drift [--repair]
├─ dev
├─ logs [--follow]
├─ profile create|rename|edit|refresh|current|list|show|delete
├─ state list|read|delete
├─ unsafe nuke
└─ provider
   ├─ check-env
   ├─ aws bootstrap|teardown
   └─ cloudflare bootstrap|teardown|token|state logs
```

| Old                             | New                                  |
| ------------------------------- | ------------------------------------ |
| `alchemy login`                 | `alchemy profile`                    |
| `alchemy login --configure`     | `alchemy profile edit`               |
| `alchemy profile clear`         | `alchemy profile delete`             |
| `alchemy deploy ./stack.ts`     | `alchemy deploy --config ./stack.ts` |
| `alchemy tail`                  | `alchemy logs --follow`              |
| `alchemy sync`                  | `alchemy drift --repair`             |
| `alchemy destroy --dry-run`     | `alchemy plan --destroy`             |
| `alchemy aws` / `cloudflare`    | `alchemy provider aws` / `cloudflare` |

Exit codes are script-safe — `0` completed, `1` failure or a
declined plan, `130` cancelled — and every run writes a pruned
debug log with the full failure cause under `~/.alchemy/logs`.
Bare `profile` and `state` open their dashboards on a terminal and
print help everywhere else.

Docs: [CLI](/cli).

## One plan, everywhere

`deploy`, `destroy`, `plan`, and `dev` render through the same
reactive plan tree
([#1458](https://github.com/alchemy-run/alchemy/pull/1458),
[#1492](https://github.com/alchemy-run/alchemy/pull/1492)):
totals at the top, the plan in the middle — bounded to your
terminal, following the active row — and progress or controls at
the bottom. Under `alchemy dev` the plan is a live widget that
stays out of your scrollback: `↑/↓` scrolls it, `←/→` flips
between the plan and the stack's output, `p` hides it, and the
choice survives the next hot reload.

Without a TTY — CI, a redirected pipe, or a coding agent
(`CLAUDECODE`, `CURSOR_AGENT`, `CODEX_CLI`, …) — the same commands
print append-only lines
([#1423](https://github.com/alchemy-run/alchemy/pull/1423),
[#1426](https://github.com/alchemy-run/alchemy/pull/1426)). Build
output and asset-upload progress stream as they happen instead of
being held until the resource settles, and long lines are written
whole instead of wrapping at column 80. Plain mode on a real
terminal still prompts for approval; `--no-input` disables prompts
and fails instead of hanging.

Slow shutdowns show progress
([#1427](https://github.com/alchemy-run/alchemy/pull/1427)) —
silent under 200ms, otherwise a spinner or periodic status line,
and a second Ctrl+C force-quits with exit `130`:

```text
^C
Shutting down — waiting for cleanup to finish (Ctrl+C again to force quit)
Still shutting down (5s)
```

Underneath, every surface is built on **CliKit**
([#1233](https://github.com/alchemy-run/alchemy/pull/1233)), a
terminal UI layer on
[`@alchemy.run/sigil`](https://npmx.dev/package/@alchemy.run/sigil),
our renderer fork — one root per output stream, serialized prompt
sessions, stdio capture that keeps logs ordered around live
regions, Unicode/ASCII fallbacks, and a lazily loaded runtime so
non-interactive commands never import React. Clack and the legacy
Ink renderer are gone. A later Sigil fix
([#1545](https://github.com/alchemy-run/alchemy/pull/1545)) stops
terminal capability replies from leaking into text inputs on slow
terminals and in Cursor.

## A redesigned TUI

Prompts and the profile dashboard drew nested vertical rails — a
rail on the frame *and* a rail on the focused row — so the focused
option read as `│ │ OAuth`
([#1547](https://github.com/alchemy-run/alchemy/pull/1547)). The
rails are gone. Focus and grouping are carried by glyphs and
indentation instead:

```diff
-› Cloudflare authentication method
-
-│ ❯ OAuth · recommended — browser-based login
-│   API Token or API Key · use an API token
+◆ Cloudflare authentication method
+  ❯ OAuth                 recommended — browser-based login
+    API Token or API Key  use an API token
```

`❯` is the one focus glyph everywhere — prompts, the edit-accounts
list, the dashboard's profile and provider rows — painted in the
brand color together with its label, so the pointer and the thing
it points at read as one block. The active prompt heading is `◆`,
so `❯` is the only chevron on screen; answered steps keep `✓`.
Labels and descriptions are aligned columns; searchable lists get
an fzf-style `/ query  3 of 12` row. The dashboard renders
providers as a table — `name  method  status` with `key  value`
details beneath — and virtualizes the list to the terminal height
so the tabs and header never scroll off
([#1533](https://github.com/alchemy-run/alchemy/pull/1533)).

## `alchemy dev` reloads

Dev reloads are owned by the exec child and are dependency-aware
([#1461](https://github.com/alchemy-run/alchemy/pull/1461),
[#1477](https://github.com/alchemy-run/alchemy/pull/1477)). The
watcher tracks the complete project-local import graph from your
entrypoint — sibling `infra/` and `src/` trees included — debounces
events, and compares content fingerprints, so a timestamp-only or
identical-content save does nothing. When a reload does fire, the
CLI logs which files' changed contents caused it. One Node process
stays alive and imports each stack generation under a fresh module
namespace; Bun respawns only the exec child and keeps the sidecar.

Node runs TypeScript through Alchemy's Oxc loader
(`@alchemy.run/node-utils/register-oxc`) instead of Node's
strip-only support: TSX, tsconfig `paths`, extensionless imports,
JSON imports, and inline source maps all work. Node `22.15+` /
`23.5+` / `24+` is required for the `module.registerHooks` it
relies on.

`alchemy dev` runs without credentials it does not use
([#1480](https://github.com/alchemy-run/alchemy/pull/1480),
[#1430](https://github.com/alchemy-run/alchemy/pull/1430)): the
AWS environment resolves lazily, and only `Alchemy.remote()` rows
ask for a profile at plan time.

Docs: [dev](/cli/dev).

## Workflows: native cron schedules

Cloudflare Workflows take wrangler-compatible `schedules`, so a
cron expression creates instances natively — no Worker Cron
Trigger calling `workflow.create()`
([#1491](https://github.com/alchemy-run/alchemy/pull/1491)):

```typescript
export default class Hourly extends Cloudflare.Workflow<Hourly>()(
  "Hourly",
  { schedules: ["0 * * * *"] },
  Effect.gen(function* () {
    return Effect.fn(function* () {
      const event = yield* Cloudflare.Workflows.WorkflowEvent;
      return event.schedule?.cron;
    });
  }),
) {}
```

Async Workers take the same array on the binding; `schedules: []`
clears.

## `Cloudflare.Telemetry`

A native tracing Layer for Workers Observability
([#1444](https://github.com/alchemy-run/alchemy/pull/1444)),
matching `Axiom.Telemetry`. Providing it enables
`observability.traces` on the host Worker and installs a per-event
Effect Tracer over `tracing.startActiveSpan`; Cloudflare owns
sampling and export, so there is no OTLP URL or flush to
configure:

```typescript
export default Cloudflare.Worker(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    return {
      fetch: handleRequest().pipe(Effect.withSpan("handle")),
    };
  }).pipe(Effect.provide(Cloudflare.Telemetry())),
);
```

Requires a compatibility date of `2026-07-28` or later — the
deploy fails early otherwise. Compose it with `Axiom.Telemetry`
(omit `traces` there) to land the same waterfall in both.

## Provisioned ElastiCache

`AWS.ElastiCache` adds `SubnetGroup`, `ReplicationGroup` (Valkey
and Redis OSS, with replicas, Multi-AZ, shard and tag updates in
place), and `CacheCluster` (Memcached) alongside the existing
serverless cache
([#1422](https://github.com/alchemy-run/alchemy/pull/1422)).
`ConnectReplicationGroup` / `ConnectCacheCluster` publish the
endpoint to a Lambda and can attach it to the cache's subnets and
security groups in the same call. Thanks
[Henning Pokriefke](https://github.com/henningpokriefke)!

```typescript
const cache = yield* AWS.ElastiCache.ReplicationGroup("Cache", {
  engine: "valkey",
  nodeType: "cache.t4g.micro",
  subnetGroupName: subnetGroup.subnetGroupName,
  securityGroupIds: [sg.groupId],
  replicasPerNodeGroup: 1,
  automaticFailoverEnabled: true,
  multiAzEnabled: true,
});

// inside the Lambda: endpoint env + VPC attachment
const conn = yield* AWS.ElastiCache.ConnectReplicationGroup(cache, {
  subnetIds: vpc.privateSubnetIds,
  securityGroupIds: [sg.groupId],
});
```

## Railway: private services, pre-deploy, local contexts

Three additions to `Railway.Service`, all from
[Dallen Pyrah](https://github.com/dallenpyrah) — thanks!

- **`publicDomain: false`**
  ([#1439](https://github.com/alchemy-run/alchemy/pull/1439)) —
  private-mesh only (`{name}.railway.internal`, no `url`).
- **`preDeploy: { command }`**
  ([#1438](https://github.com/alchemy-run/alchemy/pull/1438)) —
  a one-shot job between image build and process start, for
  migrations and seeds. `{ command: null }` clears.
- **`context: "./api"`**
  ([#1440](https://github.com/alchemy-run/alchemy/pull/1440)) —
  deploy a local Docker context through Railway's upload path,
  with Docker ignore semantics and a content hash as the
  deployment identity.

```typescript
const worker = yield* Railway.Service("Worker", {
  project,
  context: "./worker",
  preDeploy: { command: "bun migrate" },
  publicDomain: false,
});
```

Railway CLI-login tokens also resolve their workspace again
([#1479](https://github.com/alchemy-run/alchemy/pull/1479)) — the
generated `me` query no longer selects an admin-only field.
