_`alchemy profile` → `alchemy dev` → `alchemy deploy` → `alchemy drift` → `alchemy destroy`._

:::caution
**Breaking changes**

| Old                          | New                                   |
| ---------------------------- | ------------------------------------- |
| `alchemy login`              | `alchemy profile`                     |
| `alchemy login --configure`  | `alchemy profile edit`                |
| `alchemy profile clear`      | `alchemy profile delete`              |
| `alchemy deploy ./stack.ts`  | `alchemy deploy --config ./stack.ts`  |
| `alchemy tail`               | `alchemy logs --follow`               |
| `alchemy sync`               | `alchemy drift --repair`              |
| `alchemy destroy --dry-run`  | `alchemy plan --destroy`              |
| `alchemy aws` / `cloudflare` | `alchemy provider aws` / `cloudflare` |
| `STAGE=…`                    | `ALCHEMY_STAGE=…`                     |

- `alchemy deploy` (and `plan`, `destroy`, `logs`, `drift`) now targets `live_$USER`; `alchemy dev` keeps `dev_$USER`. Pass `--stage dev_sam` to keep deploying to an old target ([#1421](https://github.com/alchemy-run/alchemy/pull/1421), [#1433](https://github.com/alchemy-run/alchemy/pull/1433)).
- The AWS `local` auth method is gone — `alchemy dev` wires the emulator itself ([#1480](https://github.com/alchemy-run/alchemy/pull/1480)).
- Custom auth providers: `StackServices` lists `Interaction` instead of `CliKit` ([#1430](https://github.com/alchemy-run/alchemy/pull/1430)). See [Custom Auth Providers](/environments/custom-auth-provider).
- distilled operations are `verbNoun`: `railway.serviceCreate` → `railway.createService` ([#1517](https://github.com/alchemy-run/alchemy/pull/1517)). Only affects direct distilled callers.
:::

## `alchemy profile`

One dashboard for every connected account ([#1234](https://github.com/alchemy-run/alchemy/pull/1234), [#1235](https://github.com/alchemy-run/alchemy/pull/1235), [#1547](https://github.com/alchemy-run/alchemy/pull/1547)):

```text
◆ default   work

❯ default · active

  Cloudflare  oauth  ✓ configured
    accountId  2b29022c…
    expires    in 59m
  AWS         sso    ✓ configured
    ssoProfile my-org

←/→ switch profile · ↑/↓ focus provider · e edit · r refresh · n new · q quit
```

Every key has a subcommand, and the subcommands never prompt — built for CI and coding agents:

```sh
alchemy profile create work
alchemy profile edit --profile work --add cloudflare        # opens the OAuth flow
alchemy profile edit --profile work --add aws --method sso --set ssoProfile=my-org
alchemy profile refresh --provider cloudflare
alchemy profile rename work staging
alchemy profile delete staging --yes
```

Secrets come from flags, the environment, or stdin — never shell history:

```sh
alchemy profile edit --add cloudflare --method stored \
  --set apiToken=env:CLOUDFLARE_API_TOKEN \
  --set accountId=0123456789abcdef0123456789abcdef

op read op://vault/neon/key | alchemy profile edit --add neon --method stored --set apiKey=-
```

Profiles are now plain files — no central `profiles.json`, no separate credentials tree. Existing installs migrate on first run ([#1429](https://github.com/alchemy-run/alchemy/pull/1429)):

```text
~/.alchemy/profiles/
├─ default/
│  ├─ cloudflare.json
│  └─ aws.json
└─ work/
   └─ cloudflare.json
```

`deploy`, `plan`, and `dev` never log in for you. A missing credential fails with the exact `alchemy profile edit --add …` to run.

Docs: [profile](/cli/profile) · [Profiles](/environments/profiles) · [CI](/environments/ci).

## `alchemy dev`

Logs scroll above; the widget at the bottom shows the stack's output or the last plan. `←/→` flips, `p` hides it ([#1458](https://github.com/alchemy-run/alchemy/pull/1458), [#1492](https://github.com/alchemy-run/alchemy/pull/1492)).

![alchemy dev with the plan open](/blog/beta-77/dev-plan.png)

Reloads follow the import graph — sibling `infra/` and `src/` trees included — and only fire when file contents actually change. The CLI names the files that caused it ([#1461](https://github.com/alchemy-run/alchemy/pull/1461), [#1477](https://github.com/alchemy-run/alchemy/pull/1477)).

## Everywhere else

Prompts lost their rails ([#1547](https://github.com/alchemy-run/alchemy/pull/1547)):

```diff
-› Cloudflare authentication method
-
-│ ❯ OAuth · recommended — browser-based login
-│   API Token or API Key · use an API token
+◆ Cloudflare authentication method
+  ❯ OAuth                 recommended — browser-based login
+    API Token or API Key  use an API token
```

Without a TTY — CI, a pipe, a coding agent — every command prints plain append-only lines, build output streams as it happens, and exit codes are `0` done / `1` failed or declined / `130` cancelled ([#1423](https://github.com/alchemy-run/alchemy/pull/1423), [#1426](https://github.com/alchemy-run/alchemy/pull/1426)). Every run writes a debug log under `~/.alchemy/logs`.

```text
^C
Shutting down — waiting for cleanup to finish (Ctrl+C again to force quit)
Still shutting down (5s)
```

Docs: [CLI](/cli).

## `Cloudflare.Telemetry()`

Effect spans from a Worker land in [Workers Observability](https://developers.cloudflare.com/workers/observability/) — no OTLP endpoint, no exporter ([#1444](https://github.com/alchemy-run/alchemy/pull/1444)):

```typescript
export default Cloudflare.Worker(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    return {
      fetch: Effect.gen(function* () {
        const user = yield* kv.get("user:1").pipe(Effect.withSpan("load.user"));
        return yield* respond(user);
      }).pipe(Effect.withSpan("handle")),
    };
  }).pipe(Effect.provide(Cloudflare.Telemetry())),
);
```

```text
http.server GET
└─ handle
   ├─ load.user
   │  └─ kv_get
   └─ respond
```

Composes with `Axiom.Telemetry` for the same waterfall in both. Needs a compatibility date of `2026-07-28` or later.

Docs: [Native Workers tracing](/cloudflare/observability/workers-tracing).

## Workflows: cron schedules

([#1491](https://github.com/alchemy-run/alchemy/pull/1491))

```typescript
export default class Hourly extends Cloudflare.Workflow<Hourly>()(
  "Hourly",
  { schedules: ["0 * * * *"] },
  Effect.gen(function* () {
    return Effect.fn(function* () {
      const event = yield* Cloudflare.Workflows.WorkflowEvent;
      return event.schedule?.cron;
    });
  }),
) {}
```

## Provisioned ElastiCache

`SubnetGroup`, `ReplicationGroup` (Valkey / Redis OSS), and `CacheCluster` (Memcached) join the serverless cache ([#1422](https://github.com/alchemy-run/alchemy/pull/1422)). Thanks [Henning Pokriefke](https://github.com/henningpokriefke)!

```typescript
const cache = yield* AWS.ElastiCache.ReplicationGroup("Cache", {
  engine: "valkey",
  nodeType: "cache.t4g.micro",
  subnetGroupName: subnetGroup.subnetGroupName,
  securityGroupIds: [sg.groupId],
  replicasPerNodeGroup: 1,
  automaticFailoverEnabled: true,
});

// inside the Lambda: endpoint env + VPC attachment
const conn = yield* AWS.ElastiCache.ConnectReplicationGroup(cache, {
  subnetIds: vpc.privateSubnetIds,
  securityGroupIds: [sg.groupId],
});
```

## Railway

Private services, pre-deploy commands, and local Docker contexts ([#1439](https://github.com/alchemy-run/alchemy/pull/1439), [#1438](https://github.com/alchemy-run/alchemy/pull/1438), [#1440](https://github.com/alchemy-run/alchemy/pull/1440)). Thanks [Dallen Pyrah](https://github.com/dallenpyrah)!

```typescript
const worker = yield* Railway.Service("Worker", {
  project,
  context: "./worker",                    // build from a local directory
  preDeploy: { command: "bun migrate" },  // runs between build and start
  publicDomain: false,                    // {name}.railway.internal only
});
```
