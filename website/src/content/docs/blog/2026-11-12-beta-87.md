beta.87 is 162 pull requests from 26 contributors: 68 features and 68 bug
fixes.

**Alchemy Domain models now run on Rivet and Effect Cluster**, as well as on
Cloudflare. Which platform hosts the model is one Layer, and your model code
stays the same. On every platform, `watch` and `events` are pushed over
WebSockets as each change commits. Both platforms are new packages, **`@alchemy.run/rivet`** and
**`@alchemy.run/effect-cluster`**, and both deploy to Docker, AWS, GCP, Fly,
Hetzner, Kubernetes and more.

The release also adds **six sandbox providers** for running untrusted code:
**E2B, Daytona, Modal, Archil, Boat and AWS ECS**, where each sandbox is a
Nitro Sandbox in your own account. Each one creates sandboxes from any
Worker, Lambda or container, and they share one handle (`exec`, `start`,
`files`, `pty`, `getTcpPort`), so you can pick a provider by providing its
Layer.
**`Resource.lookup`** now binds resources your stack doesn't manage, on
every provider, and **`RemovalPolicy.protect()`** refuses any plan that would
replace or delete a resource.

<summary><strong>Breaking changes (20)</strong></summary>

- **Domain declarations are pure; handlers and read checks are Layers.** Clients no longer read aggregates. `validate` on a view or stream moves to its `toLayer`, a query becomes one handler, and `attributes` becomes `Effect.annotateCurrentSpan` ([below](#handlers-live-on-layers)):

  ```diff lang="typescript"
  export class AccountSummary extends Domain.View("AccountSummary", {
    // ...
  -  validate: Effect.fn(function* (_request, summary) { /* ... */ }),
  }) {}
  +export const AccountSummaryLive = AccountSummary.toLayer(
  +  Effect.succeed(Effect.fn(function* (_request, summary) { /* ... */ })),
  +);
  ```

  In-model reads are renamed to `get` (`accounts.state(ref)` → `accounts.get(ref)`, `summaries.query(ref)` → `summaries.get(ref)`), and clients read `bank.AccountSummary.get(id)` instead of `bank.Account.get(id)` ([#3078](https://github.com/alchemy-run/alchemy/pull/3078)).
- **The Cloudflare Domain adapter moved into `@alchemy.run/domain`**, and a Stack that hosts a model on Cloudflare registers its providers, which run the deploy-time backfill ([#3161](https://github.com/alchemy-run/alchemy/pull/3161)):

  ```diff lang="typescript"
  // alchemy.run.ts
  -import * as DomainCloudflare from "@alchemy.run/cloudflare/Domain";
  +import * as DomainCloudflare from "@alchemy.run/domain/Cloudflare";

  -providers: Cloudflare.providers(),
  +providers: Layer.mergeAll(
  +  Cloudflare.providers(),
  +  DomainCloudflare.providers(),
  +),
  ```

- **The first deploy moves every Domain model on Cloudflare into one Durable Object class per model**, `Bank.Domain`. It runs while the Worker serves and deletes the old classes ([below](#one-durable-object-class-per-model)).
- **`legacyData` defaults to `true`.** If two models in one Worker shared a class, the ones that should start empty opt out, or the deploy fails with `DurableObjectRenameConflict` ([#3165](https://github.com/alchemy-run/alchemy/pull/3165)):

  ```diff lang="typescript"
  // BankLive.ts
  -Billing.layer(BillingHandlers, { legacyData: true });
  -Audit.layer(AuditHandlers);
  +Billing.layer(BillingHandlers);
  +Audit.layer(AuditHandlers, { legacyData: false });
  ```

- **`toHttpApi`, `toMcp`, `toToolkit` and `toCli` publish nothing unless it's listed in `expose`** ([#2950](https://github.com/alchemy-run/alchemy/pull/2950)).
- **Cloudflare lookups use `Resource.lookup`**: `Hyperdrive.lookup("Id", props)` is `Hyperdrive.Connection.lookup(props)`, `Access.getIdentityProvider` is `Access.IdentityProvider.lookup`, and `VpcServiceLookup` is `VpcService.VpcService.lookup` ([#2991](https://github.com/alchemy-run/alchemy/pull/2991), [#3002](https://github.com/alchemy-run/alchemy/pull/3002), [#2974](https://github.com/alchemy-run/alchemy/pull/2974)).
- **A nested Durable Object `storage.transaction` is a savepoint**: it no longer joins the outer transaction, so an inner failure undoes only the inner writes ([#3110](https://github.com/alchemy-run/alchemy/pull/3110)).
- **`Docker.Image` moves `cacheFrom` / `cacheTo` into `build.cache`**, and Cloudflare Containers no longer keep a `:buildcache` by default. Add `build: { cache: true }` to keep it ([below](#a-layer-cache-for-every-image-build)).
- **`Cloudflare.Ssl.CertificatePack`** drops `status` and `primaryCertificate` from its attributes ([#3108](https://github.com/alchemy-run/alchemy/pull/3108)).
- **Cloudflare DNS MX and URI records require `priority`** ([#3073](https://github.com/alchemy-run/alchemy/pull/3073)).
- **`AWS.Route53.HostedZone` adopts a zone only by `hostedZoneId`**, never by name ([#3100](https://github.com/alchemy-run/alchemy/pull/3100)).
- **Fly Service RPC drops `rpcToken`**: callers are authorized by their signed `Fly-Src` App ([#3042](https://github.com/alchemy-run/alchemy/pull/3042)).
- **`Prisma.PrismaEnvironment` holds an Effect**: wrap the value in `Effect.succeed`, and read it with `PrismaEnvironment.current` ([#3122](https://github.com/alchemy-run/alchemy/pull/3122), [#3101](https://github.com/alchemy-run/alchemy/pull/3101)).
- **GitHub error classes** come from `@distilled.cloud/github/Errors`, and a rate-limited 403 is `TooManyRequests` ([#3132](https://github.com/alchemy-run/alchemy/pull/3132)).

## Actors outside of Cloudflare

<!-- OUTLINE: Durable Objects and entities on any cloud, two new packages. -->

Two new packages run actors, stateful objects addressed by name, on any
cloud: Rivet's Durable Objects and Effect Cluster's entities.

### Rivet

<!-- OUTLINE: what Rivet is in one line; the deployable is the DO; the
control plane and pool are Layers per cloud; call it by name from any
runtime. -->

`@alchemy.run/rivet` deploys Durable Objects to [Rivet](https://rivet.dev)
control planes. The Durable Object is what you deploy. The control plane and
the pool its nodes run in are Layers, so moving to another cloud changes two
lines ([#2849](https://github.com/alchemy-run/alchemy/pull/2849)):

```diff lang="typescript"
// src/cluster.ts
-export const Cluster = RivetDocker.SwarmControlPlane("Rivet");
-export const Default = RivetDocker.SwarmPool("Default").pipe(
+export const Cluster = RivetAWS.Ec2ControlPlane("Rivet");
+export const Default = RivetAWS.EcsPool("Default").pipe(
  Layer.provide(Cluster),
);
```

```typescript
// src/room.ts
export default class Room extends Rivet.DurableObject<Room>()(
  "Room",
  { main: import.meta.url },
  Effect.gen(function* () {
    return Effect.gen(function* () {
      const state = yield* Rivet.DurableObjectState;
      return {
        join: () =>
          state.storage.transaction(
            Effect.gen(function* () {
              const n = ((yield* state.storage.get<number>("n")) ?? 0) + 1;
              yield* state.storage.put("n", n);
              return n;
            }),
          ),
      };
    });
  }).pipe(Effect.provide(Default)),
) {}
```

Any runtime calls an instance by name: a Worker, a Lambda, a container or
another Durable Object.

```typescript
const rooms = yield* Room;
const visitors = yield* rooms.getByName("lobby").join();
```

<!-- OUTLINE: every control plane + pool, as the two lines you'd write.
Self-hosted gateways serve HTTPS without a domain; engines have no public
address. -->

Every cloud has a control plane and a pool, and a pool can join a control
plane on another cloud:

```typescript
// Docker Swarm, on your machine or a server
RivetDocker.SwarmControlPlane("Rivet");
RivetDocker.SwarmPool("Default");

// AWS
RivetAWS.Ec2ControlPlane("Rivet"); // or EcsControlPlane
RivetAWS.EcsPool("Default"); // or Ec2Pool

// GCP
RivetGCP.ComputeEngineControlPlane("Rivet");
RivetGCP.CloudRunPool("Default"); // or ComputeEnginePool

// Fly Machines
RivetFly.MachineControlPlane("Rivet");
RivetFly.MachinePool("Default");

// Hetzner
RivetHetzner.ServerControlPlane("Rivet");
RivetHetzner.ServerPool("Default");

// Kubernetes: EKS, GKE, kind or any cluster
RivetKubernetes.StatefulSetControlPlane("Rivet", { cluster: Eks });
RivetKubernetes.DeploymentPool("Default");

// Railway, against a control plane on another cloud
RivetRailway.ServicePool("Default");

// Rivet Cloud
RivetCloud.ControlPlane("Rivet");
RivetCloud.Pool("Default");

// a control plane you already run
Rivet.ControlPlane("Rivet", { endpoint, token });
```

A self-hosted control plane serves its gateway over HTTPS without a domain
of your own, and its engines have no public address.

<!-- OUTLINE: Durable Streams (schema-typed append/read/tail). -->

**Durable Streams** are typed logs next to your objects:

```typescript
export class ChatLog extends Rivet.DurableStream<ChatLog>()("ChatLog", {
  schema: Schema.Struct({ user: Schema.String, text: Schema.String }),
  ttl: "7 days",
}) {}

const log = yield* ChatLog;
yield* log.append("lobby", { user: "sam", text: "hello" });
const live = log.tail("lobby"); // a Stream that reconnects from its offset
```

The wire format is a Layer. Use `StreamFormat.Json`, `StreamFormat.Ndjson`,
or `StreamFormat.SchemaBinary()` for Effect's compact binary codec, derived
from the stream's Schema:

```typescript
Effect.provide(Layer.mergeAll(Default, Services, StreamFormat.SchemaBinary()));
```

<!-- OUTLINE: Rust Actors (#3118) — rivetkit crate, cargo-chef layers,
cross-compiled, runs on every pool. -->

**Rust Actors** written with Rivet's `rivetkit` crate deploy on every pool.
Alchemy compiles the crate into the pool's node image, with dependencies in
their own cached layer
([#3118](https://github.com/alchemy-run/alchemy/pull/3118)):

```typescript
export const Counter = Rivet.DurableObject("Counter", {
  crate: "./crates/counter",
  build: { toolchain: "1.85", runtimePackages: ["libssl3"] },
}).pipe(Effect.provide(Counters));
```

A Durable Object's `fetch` can **accept WebSockets** with `Rivet.upgrade()`.
A caller passes the upgrade along with `room.fetch(request)`, and Rivet's
gateway carries the socket to the instance that owns the name
([#3294](https://github.com/alchemy-run/alchemy/pull/3294)):

```typescript
return {
  fetch: Effect.gen(function* () {
    const [response, socket] = yield* Rivet.upgrade({ tags: ["chat"] });
    yield* socket.send(`welcome to ${state.id.name}`);
    return response;
  }),
  webSocketMessage: (socket: Rivet.WebSocket, message: string | Uint8Array) =>
    Effect.gen(function* () {
      for (const peer of yield* state.getWebSockets("chat")) yield* peer.send(message);
    }),
};
```

Rivet 3 doesn't hibernate WebSockets yet, so an instance holding open
sockets stays awake. Hibernatable WebSockets are coming soon.

### Effect Cluster

<!-- OUTLINE: Effect Cluster entities, singletons, crons and workflows
declared like any other runtime; the database and pool are Layers per host. -->

`@alchemy.run/effect-cluster` deploys [Effect
Cluster](https://effect.website) entities, singletons, crons and workflows.
The database the runners coordinate through and the pool they run in are
Layers, so moving to another host changes two lines
([#2924](https://github.com/alchemy-run/alchemy/pull/2924)):

```diff lang="typescript"
// src/Cluster.ts
-export const Database = ClusterDocker.Database("Cluster");
-export const Default = ClusterDocker.SwarmPool("Default").pipe(
+export const Database = ClusterAWS.Database("Cluster"); // RDS
+export const Default = ClusterAWS.EcsPool("Default").pipe( // Fargate
  Layer.provide(Database),
);
```

An entity is declared like Effect Cluster's `Entity.make`, and implemented as
a Layer:

```typescript
// src/Counter.ts
export const Increment = Rpc.make("Increment", {
  payload: { amount: Schema.Int },
  success: Schema.Int,
});

export class Counter extends Cluster.Entity<Counter>()("Counter", [
  Increment,
]) {}

// src/CounterLive.ts
export default Counter.make(
  { main: import.meta.url },
  Effect.gen(function* () {
    return Effect.gen(function* () {
      const count = yield* Ref.make(0);
      return Counter.of({
        Increment: ({ payload }) =>
          Ref.updateAndGet(count, (n) => n + payload.amount),
      });
    });
  }).pipe(Effect.provide(Default)),
);
```

Any runtime calls it through the pool's gateway:

```typescript
const counters = yield* Counter;
const counter = yield* counters.getByName("visits");
yield* counter.Increment({ amount: 1 });
```

<!-- OUTLINE: every host as the two lines you'd write; Workflows/Singleton/
Cron; existing Effect Cluster programs run as-is; 20 conformance cases on
every host. -->

Every host is a database and a pool:

```typescript
// Docker Swarm, on your machine or a server
ClusterDocker.Database("Cluster");
ClusterDocker.SwarmPool("Default");

// AWS: RDS and ECS Fargate
ClusterAWS.Database("Cluster");
ClusterAWS.EcsPool("Default");

// GCP: Compute Engine
ClusterGCP.Database("Cluster");
ClusterGCP.ComputeEnginePool("Default");

// Fly Machines
ClusterFly.Database("Cluster");
ClusterFly.MachinePool("Default");

// Hetzner
ClusterHetzner.Database("Cluster");
ClusterHetzner.ServerPool("Default");

// Kubernetes: EKS, GKE, kind or any cluster
ClusterKubernetes.Database("Cluster", { cluster: Eks });
ClusterKubernetes.DeploymentPool("Default");

// Cloudflare Durable Objects: no database
ClusterCloudflare.DurableObjectPool("Default");

// a Postgres you already run: Neon, PlanetScale, RDS
Cluster.Database.fromUrl({ url: Config.Redacted("DATABASE_URL") });
```

`Cluster.Workflow`, `Cluster.Singleton` and `Cluster.Cron`
work the same way, and an existing Effect Cluster program runs as it is on a
pool of its own. Every host passes the same 20 conformance cases.

## Alchemy Domain

### Run a model on Rivet or Effect Cluster

<!-- OUTLINE: the payoff of the two sections above. One model, three hosts, one Layer each. -->

A Domain model used to run on Cloudflare Durable Objects. It now runs on
Rivet Durable Objects and on Effect Cluster entities too. The model, its
handlers and its Apis don't change. The host is one Layer
([#3143](https://github.com/alchemy-run/alchemy/pull/3143),
[#3161](https://github.com/alchemy-run/alchemy/pull/3161)):

```typescript
// src/BankLive.ts: the model on Cloudflare Durable Objects
export default Bank.layer(BankHandlers).pipe(
  Layer.provide(DomainCloudflare.layerDurableObjects()),
);
```

```diff lang="typescript"
// src/BankLive.ts: the same model on Rivet
export default Bank.layer(BankHandlers).pipe(
-  Layer.provide(DomainCloudflare.layerDurableObjects()),
+  Layer.provide(
+    DomainRivet.layerDurableObjects({
+      name: "Bank",
+      main: import.meta.url,
+      pool: Default,
+    }),
+  ),
);
```

`DomainCluster.layerEntities` takes the same options for Effect Cluster. The
pool's nodes load the file's default export and host the model there.

<!-- OUTLINE: "Serve the Api from anywhere" — a Worker/Lambda/container
provides BankLive; deploying it deploys the class, the pool and (Cluster)
the database. Snippet from /domain/rivet#serve-the-api-from-anywhere. -->

Provide `BankLive` wherever you serve the Api: a Cloudflare Worker, a Lambda
or a container. On Rivet and Effect Cluster, that caller deploys the class and
reaches it through the pool's gateway, so it needs no database access or
route into the pool.

```typescript
// src/BankWorker.ts
import BankLive from "./BankLive.ts";

export default class BankWorker extends Cloudflare.Worker<BankWorker>()(
  "BankWorker",
  { main: import.meta.url },
  Effect.gen(function* () {
    const api = yield* CustomerApi;
    return { fetch: api.fetch };
  }).pipe(Effect.provide(BankLive)),
) {}
```

Every aggregate instance, view key and policy runs as its own Rivet actor or

### Live reads are pushed on every platform

A client on `Domain.protocolWebSocket` opens a WebSocket for each `watch` and
`events` read, and the object that owns the key pushes every change as it
commits. That was Cloudflare-only. Now Rivet, Effect Cluster and
`Domain.InMemory` push too, so a live read never polls
([#3294](https://github.com/alchemy-run/alchemy/pull/3294)):

```typescript
const bank = yield* CustomerApi.clientWebSocket(`${location.origin}/api`);
const summaries = bank.AccountSummary.watch(accountId); // pushed on every commit
```

On Rivet the socket travels through the control plane's gateway to the actor
that owns the key. On Effect Cluster the runtime serving the Api holds the
socket, and the entity pushes to it over a streamed call through the pool's
gateway, which now delivers streamed RPCs as they go instead of when they end.

Docs: [Choose a protocol](/domain/api#choose-a-protocol) ·
[Domain on Rivet](/domain/rivet#watch-without-polling) ·
[Domain on Effect Cluster](/domain/effect-cluster#watch-without-polling).

### One Durable Object class per model

<!-- OUTLINE: #3049. A model is one class, so a Worker stays under
Cloudflare's 100-class upload limit; the deploy moves existing objects for
you; users should know it happens and what it looks like. -->

On Cloudflare, a model now lives in one Durable Object class named after it,
instead of one class per aggregate, view, policy and saga. Every instance is
still its own object, named by what it holds. A Worker declares one class
per model however many definitions it has, so it stays far from Cloudflare's
limit of 100 classes per upload
([#3049](https://github.com/alchemy-run/alchemy/pull/3049)):

```diff lang="text"
Worker
-  class  Bank.AccountAggregate
-  class  Bank.AccountSummaryView
-  class  Bank.OpenAccountWorkflow
+  class  Bank.Domain
```

```text
Bank.Domain / "Bank.AccountAggregate/a-1"
Bank.Domain / "Bank.AccountSummaryView/a-1"
Bank.Domain / "Bank.OpenAccountWorkflow/s-1"
```

You don't migrate anything. The next deploy moves every object of the old
classes into its model's class while the Worker keeps serving, then deletes
the old classes. A deploy killed partway leaves every key served, and the
next deploy finishes the move:

```text
Moving 2538 Domain objects of 4 classes to Bank.Domain ...
Moved 2538 Domain objects to Bank.Domain
Deleting 4 old Domain classes: every object of theirs has moved.
```

Classes from before beta.85 move the same way, without a rename
([#3165](https://github.com/alchemy-run/alchemy/pull/3165)). If two models in
one Worker listed the same aggregate, they shared its class back then. The
old data goes to every model by default, so the models that should start
empty say so:

```typescript
export const AuditLive = Audit.layer(AuditHandlers, { legacyData: false });
```

### Handlers live on Layers

<!-- OUTLINE: #3078. Declarations are pure (decide/evolve/reply stay);
anything that reads services or authorizes reads is a Layer building one
Effect.fn. Aggregates decide, never read by clients; read through views,
streams, queries. Show the View + toLayer pair and the client table. -->

Every Domain declaration is now plain data plus, where it needs one, a Layer.
Rules that only compute stay on the declaration. Code that reads services or
checks who may read lives on a Layer
([#3078](https://github.com/alchemy-run/alchemy/pull/3078)):

```typescript
export class AccountSummary extends Domain.View("AccountSummary", {
  from: [Account],
  key: Account,
  middleware: [Session],
  rejects: [NotOwner],
  state: Summary,
  initial,
  evolve: { MoneyWithdrawn: setBalance },
}) {}

export const AccountSummaryLive = AccountSummary.toLayer(
  Effect.succeed(
    Effect.fn(function* (_request, summary) {
      yield* mustOwn(summary?.customerId ?? null);
    }),
  ),
);
```

`Bank.layer(handlers)` is a type error until every guarded view and stream
has its Layer. Clients never read an aggregate. They read views, streams and
queries.

Docs: [View security](/domain/view-security) · [Aggregate](/domain/aggregate).

### Queries

<!-- OUTLINE: #2803 + #3012. Domain.Query: typed reads across keys from a
projection's store; paging; atLeast receipts (one or many); served on
HTTP as QUERY, CLI subcommand, MCP tool. -->

`Domain.Query` is a typed read across keys, answered from a store a
projection writes. After its own command, a client passes the receipt, and
the query waits until that write is in the store
([#2803](https://github.com/alchemy-run/alchemy/pull/2803),
[#3012](https://github.com/alchemy-run/alchemy/pull/3012)). Thanks
[Taras Kornichuk](https://github.com/artile)!

```typescript
export class AccountLedger extends Domain.Query("AccountLedger", {
  input: { account: AccountId },
  success: LedgerRow,
  paged: true,
  waitsFor: [Ledger],
  middleware: [Session],
  rejects: [NotOwner],
}) {}

const receipt = yield* bank.WithdrawMoney(accountId, { amount: 30 });
const page = yield* bank.AccountLedger(
  { account: accountId },
  { atLeast: receipt, take: 20 },
);
```

A paged query also streams every entry, fetching each page on demand, so
`Stream.take` stops early
([#3174](https://github.com/alchemy-run/alchemy/pull/3174)):

```typescript
const latest = yield* bank.AccountLedger.entries(input, { take: 100 }).pipe(
  Stream.take(10),
  Stream.runCollect,
);
```

Queries are served over HTTP (as `QUERY /AccountLedger`), the CLI and MCP.

```sh
$ bank account-ledger --account a-1 --take 20
```

Docs: [Query](/domain/query).

```typescript
const BankHttp = DomainHttp.toHttpApi(CustomerApi, {

DomainAi.toMcp(CustomerApi, { expose: ["AccountSummary.watch"] });
```

### Stories run every order of concurrent work

<!-- OUTLINE: #3144. A story runs each order that can change the outcome;
anyOrder/inOrder; flaky ordering becomes a deterministic failure with the
order that broke it. -->

A story now runs every order of its concurrent work that can change the
outcome, and every run must pass. When the model doesn't order two events,
say so with `Story.anyOrder`
([#3144](https://github.com/alchemy-run/alchemy/pull/3144)):

```typescript
story(
  Story.when(subject, new Request()),
  Story.then(subject, new Requested(), new Settled()),
  Story.then(
    registry,
    Story.anyOrder(new Recorded(), new Admitted({ payloadHash })),
  ),
);
// runs twice, policy first and saga first; both must pass
```

A `then` that holds in only some orders fails every time, and names the
order that broke it, instead of flaking.

Docs: [Story](/domain/story).

## Sandboxes for untrusted code

<!-- OUTLINE: the second headline. Agents, code interpreters, CI, previews:
run code you didn't write in a VM you can throw away. Six providers, one
handle, create from any runtime, each binding gets its own scoped key, and
sandboxes a host creates are labeled and cleaned up on destroy. -->

Six new providers create sandboxes: VMs you can throw away, for code you
didn't write. Use them for agents, code interpreters, CI jobs and previews:
[E2B](/e2b), [Daytona](/daytona), [Modal](/modal), [Archil](/archil),
[Boat](/boat) and [AWS ECS](/aws/compute/ecs-sandboxes)
([#2930](https://github.com/alchemy-run/alchemy/pull/2930),
[#2931](https://github.com/alchemy-run/alchemy/pull/2931),
[#2934](https://github.com/alchemy-run/alchemy/pull/2934),
[#2933](https://github.com/alchemy-run/alchemy/pull/2933),
[#3156](https://github.com/alchemy-run/alchemy/pull/3156),
[#3242](https://github.com/alchemy-run/alchemy/pull/3242)).

Each provider builds what its sandboxes start from at deploy, and a runtime
binds to it and starts a sandbox per request
([#3171](https://github.com/alchemy-run/alchemy/pull/3171)).

<!-- OUTLINE: lead with the six providers as ### headings so they show in
the TOC; how they're used the same way follows. -->

### E2B

E2B builds a template from a Dockerfile and snapshots it after setup.
Sandboxes start from the snapshot in about a second, pause idle with their
memory, and resume on the next call:

```typescript
// src/Sandbox.ts: built once, at deploy
export const Node = E2B.Template("Node", {
  dockerfile: Dockerfile.inline`
    FROM node:22-bookworm
    RUN apt-get update && apt-get install -y git
  `,
});
export const Warm = E2B.Snapshot("Warm", {
  template: Node,
  run: ["git clone --depth 1 https://github.com/sindresorhus/is repo"],
});
```

```typescript
// src/Api.ts: a Cloudflare Worker here; any Alchemy runtime works
export default class Api extends Cloudflare.Worker<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const sandboxes = yield* E2B.CreateSandbox(Warm);
    return {
      fetch: Effect.gen(function* () {
        const sandbox = yield* sandboxes.create({ timeout: 120 });
        const result = yield* sandbox.exec("npm test", {
          cwd: "/home/user/repo",
        });
        return yield* HttpServerResponse.json(result);
      }),
    };
  }).pipe(Effect.provide(E2B.CreateSandboxHttp)),
) {}
```

warm pools that keep sandboxes ready to hand out:


```typescript
export default class Api extends Cloudflare.Worker<Api>()(

  Effect.gen(function* () {
```

### Modal

Modal builds images on its own builders from a base or another image, and
keeps persistent sandboxes whose files survive between sessions:

```typescript
// src/Sandbox.ts: built once, at deploy
export const Coder = Modal.App("Coder", {});
export const Node = Modal.Image("Node", {
  app: Coder,
  image: "node:22-bookworm",
  commands: ["RUN apt-get update && apt-get install -y git"],
});
export const Warm = Modal.Image("Warm", {
  app: Coder,
  from: Node,
  run: ["git clone --depth 1 https://github.com/sindresorhus/is /work"],
});
```

```typescript
// src/Api.ts: a Cloudflare Worker here; any Alchemy runtime works
export default class Api extends Cloudflare.Worker<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const sandboxes = yield* Modal.CreateSandbox(Warm);
    return {
      fetch: Effect.gen(function* () {
        const sandbox = yield* sandboxes.create({ timeout: "5 minutes" });
        const result = yield* sandbox.exec("npm test", {
          cwd: "/work",
        });
        return yield* HttpServerResponse.json(result);
      }),
    };
  }).pipe(Effect.provide(Modal.CreateSandboxHttp)),
) {}
```

Modal goes beyond sandboxes, with Functions, Servers, Volumes, Dicts, Queues
and model Endpoints. A `Modal.Function` holds its own code, runs on a GPU,
and binds Volumes, Dicts and other Functions like any other runtime. Callers
reach its methods by name, each with its own key, and the Function calls
Modal without a stored token
([#3137](https://github.com/alchemy-run/alchemy/pull/3137)):

```typescript
// src/Embed.ts
export default class Embed extends Modal.Function<Embed>()(
  "Embed",
  { main: import.meta.url, app: Coder, gpu: "L4" },
  Effect.gen(function* () {
    const weights = yield* Modal.MountVolume(Weights, {
      path: "/models",
      readOnly: true,
    });
    const cache = yield* Modal.ReadWriteDict(Cache);
    const model = yield* loadModel(weights.path);
    return {
      embed: Effect.fn(function* (text: string) {
        const vector = yield* model.embed(text);
        yield* cache.put(text, vector);
        return vector;
      }),
    };
  }).pipe(Effect.provide(Modal.ReadWriteDictHttp)),
) {}
```

```typescript
// src/Api.ts: a Cloudflare Worker here; any Alchemy runtime works
export default class Api extends Cloudflare.Worker<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const embed = yield* Modal.InvokeFunction(Embed);
    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const result = yield* embed.embed(yield* request.text);
        return yield* HttpServerResponse.json(result);
      }),
    };
  }).pipe(Effect.provide(Modal.InvokeFunctionHttp)),
) {}
```

### AWS ECS with Nitro Sandboxes

<!-- OUTLINE: #3242. The sixth provider, and the only one in your account:
an image as an isolated ECS Task, Managed Instances capacity, the same
CreateSandbox + handle from a Lambda. Then #3205's raw props in one line. -->

`AWS.ECS.CreateSandbox` starts sandboxes in your own account, from a Lambda,
a Task or any other AWS runtime. Each one is an ECS Task in its own
[Nitro Sandbox](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/amazon-ec2-nitro-sandboxes.html),
a child VM on the instance. The image is pushed unchanged, and the handle is
the same one every other provider returns
([#3242](https://github.com/alchemy-run/alchemy/pull/3242)):

```typescript
// src/Sandbox.ts
export const Python = AWS.ECS.Task("Python", {
  image: "python:3.12-slim", // or context: "./sandbox"
  cpu: 1024,
  memory: 2048,
  isolation: "isolated",
});

// Managed Instances; roles, security groups and instance types are created
export const Capacity = AWS.ECS.CapacityProvider("Capacity", {
  cluster: Cluster.clusterName,
  managedInstancesProvider: {
    instanceLaunchTemplate: {
      networkConfiguration: { subnets: Network.privateSubnetIds },
      nitroEnclavesEnabled: true,
    },
  },
});
```

```typescript
// src/Api.ts
export default class Api extends AWS.Lambda.Function<Api>()(
  "Api",
  { main: import.meta.url, functionUrl: true },
  Effect.gen(function* () {
    const sandboxes = yield* AWS.ECS.CreateSandbox(Capacity, Python);
    return {
      fetch: Effect.gen(function* () {
        const sandbox = yield* sandboxes.create({
          tags: { user: "user-42" },
          idleTimeout: "15 minutes",
        });
        yield* sandbox.files.write("/work/main.py", `print("hi")`);
        const result = yield* sandbox.exec("python3 main.py", {
          cwd: "/work",
        });
        return yield* HttpServerResponse.json(result);
      }),
    };
  }).pipe(Effect.provide(AWS.ECS.CreateSandboxHttp)),
) {}
```

The binding grants the host `RunTask`, `StopTask` and `DescribeTasks` on the
cluster, puts a Lambda in the capacity's subnets, and opens the sandboxes'
ports to the host only. Every call carries a token minted for that sandbox.
A Task can also be an Effect program, and its methods appear on the handle,
typed.

The Nitro Sandbox settings are props on the resources you already use,
named as in the AWS and Kubernetes APIs: `trustedExecutionConfiguration` on
an ECS task definition, `runtimeClassName: "isolated-sandbox"` on an EKS Auto
Mode Deployment, and `enclaveOptions` on an EC2 host
([#3205](https://github.com/alchemy-run/alchemy/pull/3205)).

### Create a sandbox per request

<!-- OUTLINE: the E2B Worker snippet: CreateSandbox(Template), create with
egress blocked, write the code, exec, kill on release. -->

Every provider has a `CreateSandbox` binding. A Worker creates a sandbox for
a request, runs the code with no network access, and deletes the sandbox:

```typescript
export default class Api extends Cloudflare.Worker<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const sandboxes = yield* E2B.CreateSandbox(Agent);
    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const sandbox = yield* sandboxes.create({
          timeout: 120,
          network: { allowOut: [] },
        });
        yield* sandbox.files.write("main.mjs", yield* request.text);
        const result = yield* sandbox.exec("node main.mjs");
        yield* sandbox.kill();
        return yield* HttpServerResponse.json(result);
      }),
    };
  }).pipe(Effect.provide(E2B.CreateSandboxHttp)),
) {}
```

Each binding mints its host's own key, scoped to what the binding needs.
Sandboxes a host creates are labeled with its stack and stage, and deleted
when the host is destroyed.

### One handle on every provider

<!-- OUTLINE: alchemy/Sandbox shapes (#2928): exec / start / files / pty /
getTcpPort, with getTcpPort matching Cloudflare Containers; port.fetch can
proxy the Worker's own request. -->

Every provider's handle has the same calls for what every platform does
([#2928](https://github.com/alchemy-run/alchemy/pull/2928)), plus its own
platform's calls next to them:

```typescript

// a scoped process: output, write, kill, wait

// a port, as on Cloudflare Containers: proxy the incoming request

```

### Pick a provider with a Layer

<!-- OUTLINE: the "swap it" pitch. Pattern, not a shipped tag: declare your
own service, write one Layer per provider, provide the one you want. Show
E2B and Daytona side by side; the Worker never changes. -->

A Worker uses a sandbox through a service of your own, and switching
providers is the one line that provides it:

```diff lang="typescript"
// src/Api.ts
export default class Api extends Cloudflare.Worker<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const runner = yield* Runner;
    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const result = yield* runner.run(yield* request.text);
        return yield* HttpServerResponse.json(result);
      }),
    };
-  }).pipe(Effect.provide(E2BRunner)),
+  }).pipe(Effect.provide(DaytonaRunner)),
) {}
```

The service is written once, with one Layer per provider:

```typescript
// src/Runner.ts
interface RunResult {
  exitCode: number;
  output: string;
}

export class Runner extends Context.Service<
  Runner,
  { run: (code: string) => Effect.Effect<RunResult, never, RuntimeContext> }
>()("Runner") {}

export const E2BRunner = Layer.effect(
  Runner,
  Effect.gen(function* () {
    const sandboxes = yield* E2B.CreateSandbox(NodeTemplate);
    return {
      run: Effect.fn(function* (code) {
        const sandbox = yield* sandboxes.create({ network: { allowOut: [] } });
        const r = yield* sandbox.exec(["node", "-e", code]);
        yield* sandbox.kill();
        return { exitCode: r.exitCode, output: r.stdout };
      }),
    };
  }),
).pipe(Layer.provide(E2B.CreateSandboxHttp));

export const DaytonaRunner = Layer.effect(
  Runner,
  Effect.gen(function* () {
    const sandboxes = yield* Daytona.CreateSandbox(NodeSnapshot);
    return {
      run: Effect.fn(function* (code) {
        const sandbox = yield* sandboxes.create();
        const r = yield* sandbox.exec(["node", "-e", code]);
        yield* sandboxes.delete(sandbox.sandboxId);
        return { exitCode: r.exitCode, output: r.result };
      }),
    };
  }),
).pipe(Layer.provide(Daytona.CreateSandboxHttp));
```

### Keep credentials out of the sandbox

<!-- OUTLINE: #3238 + #3231. Every platform's own way to keep a key out of
the code: placeholders swapped at egress, signed identities, proxies. -->

Every provider can hand a sandbox a placeholder and swap the real key in as
the request leaves, so the code you run never holds it. Daytona has secrets
scoped to hosts, Archil and E2B have egress rules, and E2B can route through
your own SOCKS5 proxy. A Modal sandbox can carry an identity Modal signs, so
AWS or GCP give it short-lived credentials and no key is stored
([#3238](https://github.com/alchemy-run/alchemy/pull/3238)):

```typescript
const sandbox = yield* sandboxes.create({
  image: "amazon/aws-cli",
  includeOidcIdentityToken: true,
});
```

Boat keeps AI keys and API secrets in credential profiles, and its AI
credentials proxy swaps them in for each request
([#3231](https://github.com/alchemy-run/alchemy/pull/3231)):

```typescript
export const Keys = Boat.CredentialProfile("Keys", {
  anthropic: Config.Redacted("ANTHROPIC_API_KEY"),
});
export const Proxy = Boat.AiProxy("Proxy");
export const Tenants = Boat.Environment("Tenants", {
  safeForThirdParties: true,

```

## Resource.lookup on every provider

<!-- OUTLINE: #2974 core + #3002 Cloudflare + #3076 AWS (482/723) + #3094
GCP (627/909) + #3120 Fly + #3124 the rest. Plan-time, binds and grants
like a declared resource, never writes state. Typed errors. -->

`Resource.lookup` binds a resource your stack doesn't manage. It resolves at
plan time, binds and grants like a declared resource, and never writes state
or deletes anything. Every provider has it, on every resource another
resource can point at
([#2974](https://github.com/alchemy-run/alchemy/pull/2974),
[#3002](https://github.com/alchemy-run/alchemy/pull/3002),
[#3076](https://github.com/alchemy-run/alchemy/pull/3076),
[#3094](https://github.com/alchemy-run/alchemy/pull/3094),
[#3120](https://github.com/alchemy-run/alchemy/pull/3120),
[#3124](https://github.com/alchemy-run/alchemy/pull/3124)):

```typescript
const uploads = AWS.S3.Bucket.lookup({ bucketName: "acme-uploads" });
const vpc = AWS.EC2.Vpc.lookup({ isDefault: true });
const zone = Cloudflare.Zone.lookup({ name: "example.com" });
const orders = GCP.PubSub.Topic.lookup({ topicId: "orders" });
const project = Neon.Project.lookup({ projectId: "plain-wave-12345678" });

// binds and grants like a declared bucket
const getObject = yield* AWS.S3.GetObject(uploads);
```

A missing resource fails with `LookupNotFoundError`, and a lookup of one this
stack manages fails with `LookupOfManagedResourceError`.

## Fly connects to AWS and GCP without keys

## Real SQL clients at Construction phase

<!-- OUTLINE: #3209. Building a query does no I/O; only running it connects.

`SQL.*` and `Drizzle.*` return the driver's own client when the runtime is

([#3209](https://github.com/alchemy-run/alchemy/pull/3209)):

```typescript

// a real drizzle database: no connection yet
const children = db.$with("c").as(db.select().from(items));

return {
  fetch: Effect.gen(function* () {
    // running a query opens the pool, once per request
    return yield* HttpServerResponse.json(yield* db.select().from(items));
  }),
};
```

## CLI

<!-- OUTLINE: pipeable output — json log format, status to stderr, drift
exit codes, nested outputs; plus deploy timer, program status, nuke scan
timeout, state --domain. -->

The CLI's output can be piped. `--log-format json` writes only JSON records
to stdout, and status lines go to stderr when output is piped
([#2874](https://github.com/alchemy-run/alchemy/pull/2874),
[#3041](https://github.com/alchemy-run/alchemy/pull/3041)):

```sh
alchemy dev --log-format json | jq 'select(.kind == "event") | .data.type'
alchemy state read app/prod/output > out.json # progress on stderr
```

`alchemy drift` exits `2` when it finds drift it didn't repair
([#2992](https://github.com/alchemy-run/alchemy/pull/2992)):

```sh
alchemy drift --stage prod   # 0 in sync · 1 couldn't check · 2 drifted
```

Also: the status line shows total deploy time
([#3057](https://github.com/alchemy-run/alchemy/pull/3057)), terminals that
support program status show deploy progress
([#2887](https://github.com/alchemy-run/alchemy/pull/2887)), nested stack
outputs print in full ([#3037](https://github.com/alchemy-run/alchemy/pull/3037)),
`alchemy state` takes `--domain` for a Cloudflare store on a custom domain
([#2966](https://github.com/alchemy-run/alchemy/pull/2966)), and nuke scans
have their own 60 s timeout
([#2958](https://github.com/alchemy-run/alchemy/pull/2958)). Thanks
[Rahul Mishra](https://github.com/BlankParticle) and
[gegi](https://github.com/xofromthemoon)!
