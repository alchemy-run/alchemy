beta.82 supports Cloudflare's **Birthday Week** launches. Containers can now
be **managed by Durable Objects**, which pick the image and size when they
start one. **K2** gives you durable event streams, and **Basin** turns
Pipelines and the R2 Data Catalog into one data platform. **Workers KV
Instant**, **Workers Issues**, and **vinext 1.0** work out of the box.

Outside Birthday Week, Workers can reach **private databases through
Hyperdrive and Workers VPC**, set **Workers Cache per entrypoint**, and
serve one hostname from many Workers with **federated APIs**. Durable
Objects now deploy with Cloudflare's **declarative exports**. Kubernetes resources send `Redacted`
secrets to the cluster. There is also a new **Turso** provider, **AWS console login**, **DSQL migrations**,
and **`Neon.Role`**.

:::caution
**Breaking changes**

- **Containers start explicitly**
  ([#1905](https://github.com/alchemy-run/alchemy/pull/1905)).
  `Cloudflare.Containers.layer` is removed. `yield* Sandbox` binds the
  container without starting it; call `sandbox.start()` before you use
  it:

  ```diff lang="typescript"
  const sandbox = yield* Sandbox;
  -return { ping: () => sandbox.ping() };
  +const start = sandbox.start({ enableInternet: true });
  +return { ping: () => start.pipe(Effect.andThen(sandbox.ping())) };
  ```

  A container's RPC shape can no longer declare members the handle
  already has (`start`, `exec`, `images`, `getTcpPort`, …), and RPC on a
  stopped container fails with `ContainerNotRunningError`.
- **Pipelines streams are private by default**
  ([#2010](https://github.com/alchemy-run/alchemy/pull/2010)). A
  `Pipelines.Stream` declared without `http` no longer gets a public,
  unauthenticated ingest endpoint. Set
  `http: { enabled: true, authentication: false }` to keep one.
- **Durable Objects deploy with `exports`, and you can't go back**
  ([#2135](https://github.com/alchemy-run/alchemy/pull/2135)). After a
  Worker with Durable Objects deploys on beta.82, older Alchemy releases
  can no longer deploy it. Upgrade every machine and CI job that deploys
  the stack together. The first deploy after upgrading must go out at
  100% traffic. See [below](#durable-objects-deploy-with-exports).
- **`InstanceId` is now `ResourceContext`**
  ([#2160](https://github.com/alchemy-run/alchemy/pull/2160)). Custom
  providers read the instance id from the resource context:

  ```diff lang="typescript"
  import * as Effect from "effect/Effect";
  -import { InstanceId } from "alchemy";
  -const instanceId = yield* InstanceId;
  +import { ResourceContext } from "alchemy";
  +const { instanceId } = yield* ResourceContext;
  ```

- **The CLI needs Node 24.11.1+ or Bun**
  ([#2151](https://github.com/alchemy-run/alchemy/pull/2151)). Node 22
  and 23 are no longer supported.
- **Bundles are written to `.alchemy/bundles`**
  ([#2133](https://github.com/alchemy-run/alchemy/pull/2133)), not
  `dist/`. Workers and Lambdas redeploy once after you upgrade because
  their sourcemap paths change. Set `build.output.dir` to choose a
  location.
- **`Git.BlobStoreR2` needs a `ReadWriteBucket` implementation**
  ([#2102](https://github.com/alchemy-run/alchemy/pull/2102)). Provide
  `Cloudflare.R2.ReadWriteBucketBinding` (or `ReadWriteBucketHttp`) on
  the Worker.
- **Removed GCP resources**
  ([#2159](https://github.com/alchemy-run/alchemy/pull/2159),
  [#2024](https://github.com/alchemy-run/alchemy/pull/2024)). Google
  removed the APIs behind `GCP.WorkspaceEvents.TasksPushNotificationConfig`
  and the `GCP.Dataplex` data taxonomy resources.
- **An `MtlsCertificate` in `env` is an mTLS binding**
  ([#2051](https://github.com/alchemy-run/alchemy/pull/2051)), typed as a
  `Fetcher`, instead of a JSON binding.
:::

## Cloudflare Birthday Week

### Containers managed by Durable Objects

Cloudflare rebuilt Containers so a Durable Object can start one directly.
Set `schedulingPolicy: "durable_object"` and declare named `images`
([#1905](https://github.com/alchemy-run/alchemy/pull/1905)). The Durable
Object chooses the image, instance size, and entrypoint when it calls
`start()`, then runs commands with `exec`:

```typescript
export class Sandbox extends Cloudflare.Container<Sandbox>()("Sandbox", {
  schedulingPolicy: "durable_object",
  images: { node: { image: "node:24-slim" } },
}) {}

export class Agent extends Cloudflare.DurableObject<Agent>()(
  "Agent",
  Effect.gen(function* () {
    const sandbox = yield* Sandbox;
    return Effect.succeed({
      exec: (args: string[]) =>
        Effect.gen(function* () {
          const images = yield* sandbox.images;
          yield* sandbox.start({
            image: images.node,
            instance: "lite",
            entrypoint: ["sleep", "infinity"],
            enableInternet: false,
          });
          const process = yield* sandbox.exec(args);
          const result = yield* process.output();
          return new TextDecoder().decode(result.stdout);
        }).pipe(Effect.scoped),
    });
  }),
) {}
```

Snapshots, SSH, and stdin streaming are supported, and the same code runs
under `alchemy dev`. Thanks
[Dan van der Merwe](https://github.com/danieljvdm)!

Docs: [Containers](/cloudflare/compute/containers) ·
[Container lifecycle](/cloudflare/compute/container-lifecycle).

### K2 event streams

`Cloudflare.K2.Stream` is a durable event stream stored in R2
([#2010](https://github.com/alchemy-run/alchemy/pull/2010)). A Worker
writes to it through a binding:

```typescript
export const Orders = Cloudflare.K2.Stream("Orders", {
  retention: "7 days",
});

export default class Api extends Cloudflare.Worker<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const orders = yield* Cloudflare.K2.WriteStream(Orders);
    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        yield* orders.send([{ content: yield* request.text }]);
        return HttpServerResponse.empty({ status: 202 });
      }),
    };
  }).pipe(Effect.provide(Cloudflare.K2.WriteStreamBinding)),
) {}
```

Long-running hosts consume the stream with `consumeStreamRecords`. Here a
Fly Service reviews large orders:

```typescript
yield* Cloudflare.K2.consumeStreamRecords(
  Orders,
  { startAt: "earliest", concurrency: 4 },
  (records) =>
    records.pipe(
      Stream.map((record) => record.value),
      Stream.filter((order) => order.amountCents > 100_000),
      Stream.runForEach((order) => Effect.log(`review ${order.orderId}`)),
    ),
);
```

Workers can't consume K2 streams yet.

Docs: [K2](/cloudflare/messaging/k2).

### Basin

Cloudflare renamed its data platform **Basin**: Pipelines, the R2 Data
Catalog, and SQL. The same resources are now also exported as
`Cloudflare.Basin.*` ([#2010](https://github.com/alchemy-run/alchemy/pull/2010)).
A pipeline reads a stream and writes to an Iceberg table with SQL:

```typescript
const lake = yield* Cloudflare.R2.Bucket("Lake");
const catalog = yield* Cloudflare.Basin.Catalog("Catalog", { bucket: lake });
const views = yield* Cloudflare.Basin.Stream("PageViews", { schema: PageView });

const table = yield* Cloudflare.Basin.Sink("PageViewTable", {
  type: "basin_catalog",
  catalog,
  table: { namespace: "web", name: "page_views" },
  token: yield* Config.Redacted("CATALOG_TOKEN"),
});

yield* Cloudflare.Basin.Pipeline("PageViewEtl", {
  sql: Output.interpolate`
    INSERT INTO ${table.name}
    SELECT userId, path, at FROM ${views.name}`,
});
```

Alchemy checks the SQL with Cloudflare during plan, so a bad statement fails
before anything changes.

`Basin.Table` creates an Iceberg table directly, with columns from an Effect
Schema:

```typescript
const orders = yield* Cloudflare.Basin.Table("Orders", {
  catalog,
  namespace: "sales",
  schema: Order,
  partitionBy: ["day(at)"],
});
```

Docs: [Pipelines](/cloudflare/data/pipelines) ·
[Iceberg tables](/cloudflare/data/iceberg-tables).

### Workers KV Instant

`Cloudflare.KV.InstantNamespace` creates a namespace in Cloudflare's new
Instant mode, for small configuration that is read often
([#2027](https://github.com/alchemy-run/alchemy/pull/2027)). The existing
KV capabilities accept it, and `alchemy dev` emulates it:

```typescript
const config = yield* Cloudflare.KV.InstantNamespace("Config");

// in a Worker
const kv = yield* Cloudflare.KV.ReadNamespace(config);
const enabled = yield* kv.get("feature-enabled");
```

Switching a namespace between classic and Instant replaces it and does not
copy its data. Thanks [BlankParticle](https://github.com/BlankParticle)!

Turn on Workers Issues error detection for a Worker

uploads and gradual rollouts keep the setting:

```typescript
yield* Cloudflare.Worker("Api", {
  main: "./src/worker.ts",
  observability: { issues: { enabled: true } },

```

## Private databases with Hyperdrive

A Hyperdrive connection can now reach a database that has no public
endpoint, through a Workers VPC service
([#2218](https://github.com/alchemy-run/alchemy/pull/2218)). Point the
origin at the service with `serviceId`:

```typescript
const hyperdrive = yield* Cloudflare.Hyperdrive.Connection("Hyperdrive", {
  origin: {
    scheme: "postgres",
    serviceId: service.serviceId,
    database: "app",
    user: "app",
    password: password.text,
  },
});
```

The guide connects a Worker to Aurora in private AWS subnets through a
Cloudflare Tunnel, and `examples/cloudflare-hyperdrive-aws-vpc` deploys
the whole thing.

Docs: [Private databases](/cloudflare/data/hyperdrive-private-database).

## Workers Cache per entrypoint

`entrypoints` sets Workers Cache for each entrypoint of a Worker
([#2216](https://github.com/alchemy-run/alchemy/pull/2216)). An
entrypoint you don't list uses the Worker's `cache` setting:

```typescript
yield* Cloudflare.Worker("Api", {
  main: "./src/worker.ts",
  entrypoints: {
    default: { cache: { enabled: false } },
    Public: { cache: { enabled: true } },
  },
});
```

## Durable Objects deploy with exports

Alchemy now uploads Durable Objects with Cloudflare's declarative
`exports` instead of `migrations`
([#2135](https://github.com/alchemy-run/alchemy/pull/2135)). Your code
doesn't change. Alchemy can now deploy and adopt Workers that were last
deployed by Wrangler 4.107 or later.

:::caution
This is a one-way change. Once a Worker deploys with `exports`, a release
before beta.82 can't deploy it again. Pin `alchemy@2.0.0-beta.82` or later
everywhere the stack is deployed (laptops, CI, preview jobs) before the
first deploy, and don't roll back past it.
:::

The first deploy after upgrading must go out at 100% traffic. If you use
gradual deployments, remove `version.traffic` for that one deploy;
otherwise it fails with `WorkerVersionConfigError`.

Removing a Durable Object binding no longer deletes its namespace while
the class is still exported. Remove the class from your code to delete
it. Previews still use `migrations`.

Docs: [Durable Objects](/cloudflare/compute/durable-objects) ·
[Gradual deployments](/cloudflare/compute/gradual-deployments).

## Federated APIs

Serve one hostname from several Workers, each with only the permissions
it needs, using zone `routes`
([#2088](https://github.com/alchemy-run/alchemy/pull/2088)). `alchemy dev`
applies the same routing locally:

```typescript
yield* Cloudflare.Worker("Home", {
  main: "./src/home.ts",
  domain: "api.example.com",
});

yield* Cloudflare.Worker("Orders", {
  main: "./src/orders.ts",
  routes: [{ pattern: "api.example.com/orders*" }],
});
```

Docs: [Federated APIs](/cloudflare/networking/federated-apis).

## Turso

A new **Turso** provider creates groups and databases, with migrations,
and binds them to Workers and Lambdas
([#2138](https://github.com/alchemy-run/alchemy/pull/2138)):

```typescript
import * as Turso from "alchemy/Turso";

export const Group = Turso.Group("Group", { location: "aws-us-east-1" });

export const Db = Effect.gen(function* () {
  const group = yield* Group;
  return yield* Turso.Database("Db", {
    group: group.name,
    migrations: "./migrations",
  });
});
```

Query it with Drizzle or `SQL.LibSQL`:

```typescript
const conn = yield* Turso.Connect(Db);
const db = yield* Drizzle.LibSQL(conn);
```

`Turso.ManageDatabases` creates a database per tenant at runtime:

```typescript
const tenants = yield* Turso.ManageDatabases(Tenants);
const acme = yield* tenants.create("acme");
```

Docs: [Turso](/turso) · [Tutorial](/turso/tutorial/part-1).

## AWS console login

Authenticate an AWS profile with `aws login` (AWS CLI 2.32+), with no
long-lived keys
([#1759](https://github.com/alchemy-run/alchemy/pull/1759)).
`alchemy profile refresh` signs in again when the session expires:

```sh
aws login --profile my-console
alchemy profile edit --add AWS --method console-login --set loginProfile=my-console
```

Thanks [jperezrealini](https://github.com/jperezrealini)!

Docs: [AWS setup](/aws/setup).

## DSQL migrations

`AWS.DSQL.Cluster` applies SQL migrations when it deploys
([#1544](https://github.com/alchemy-run/alchemy/pull/1544)). Each
statement runs in its own transaction, and `CREATE INDEX` becomes
`CREATE INDEX ASYNC`. SQL that DSQL can't run is rejected before the
cluster is touched:

```typescript
const database = yield* AWS.DSQL.Cluster("Database", {
  migrations: "./migrations",
});
```

Thanks [carlulsoe](https://github.com/carlulsoe)!

Docs: [Drizzle on DSQL](/aws/data/drizzle-dsql).

## Neon roles

`Neon.Role` creates a Postgres role on a branch, with a stable password
([#2078](https://github.com/alchemy-run/alchemy/pull/2078)):

```typescript
const app = yield* Neon.Role("App", { branch });
const owner = yield* Neon.Role("Owner", { branch, name: "app_owner", noLogin: true });
```

Every Neon role has owner-level access to the branch's databases.

Docs: [Roles](/neon/data/roles).

## Kubernetes secrets and drift

`Redacted` values in a `Kubernetes.Manifest` or `Kubernetes.HelmChart`
now reach the cluster as the real secret
([#1948](https://github.com/alchemy-run/alchemy/pull/1948)). Before, the
cluster stored the placeholder `<redacted>`. Plans and state still keep
the value wrapped:

```typescript
yield* Kubernetes.Manifest("Token", {
  cluster,
  manifest: {
    apiVersion: "v1",
    kind: "Secret",
    metadata: { name: "token" },
    stringData: { token: Redacted.make(token) },
  },
});

yield* Kubernetes.HelmChart("App", {
  cluster,
  chart: "./chart",
  values: { apiKey: Redacted.make(apiKey) },
});
```

API errors and Helm output are scrubbed of those secrets, including their
base64 and JSON-escaped forms. Destroy fails when the cluster refuses a
delete (403 or 5xx) instead of reporting success, and calls to an
unreachable API server time out. `alchemy drift` now reports in-cluster
edits to the fields you declared, such as an image or replica count.

`Kubernetes.Deployment` also takes the cluster resource directly, so its
props can be a plain object
([#2005](https://github.com/alchemy-run/alchemy/pull/2005)):

```diff lang="typescript"
export default Kubernetes.Deployment(
  "Api",
-  Effect.gen(function* () {
-    return { main: import.meta.url, cluster: yield* Gke, port: 3000 };
-  }),
+  { main: import.meta.url, cluster: Gke, port: 3000 },
  impl,
);
```

`Neon.Function` takes `branch` and `project` the same way.

Docs: [Kubernetes](/kubernetes).
