beta.85 moves Alchemy to **Effect 4.1** and makes **DynamoDB the default
AWS state store**, with `alchemy state migrate` to move existing stages off
S3. Bindings between AWS and GCP no longer mint long-lived keys, and **a
custom domain can live on any DNS host**: a Lambda on Cloudflare DNS, or a
Worker on Route 53.

Lambda gets **aliases, response streaming, partial batch failures and
timeout interrupts**. Cloud Run gets **sidecars with typed RPC**.
`@alchemy.run/domain` can now **publish an Api as an HTTP API with OpenAPI,
an MCP server, a CLI, or Foldkit commands**. Durable workflows wake on time,
and every workflow engine passes one conformance suite.

:::caution
**Breaking changes**

- **Effect 4.1** ([#2754](https://github.com/alchemy-run/alchemy/pull/2754)).
  Bump `effect` and `@effect/*` to `^4.1.0`. See [below](#effect-41).
- **`AWS.state()` keeps state in DynamoDB**
  ([#2691](https://github.com/alchemy-run/alchemy/pull/2691)). A stage still
  in the S3 store is refused until you run `alchemy state migrate`, or keep
  S3 with `AWS.state({ backend: "s3" })`. See [below](#dynamodb-state-store).
- **Lambda event-source handlers take the Lambda event**
  ([#2508](https://github.com/alchemy-run/alchemy/pull/2508)).
  `SQS.consumeQueueMessages`, `Kinesis.consumeStreamRecords` and
  `DynamoDB.consumeTableChanges` pass the event instead of a `Stream`:

  ```diff lang="typescript"
  yield* AWS.SQS.consumeQueueMessages(
  -  queue,
  -  (records) => records.pipe(Stream.runForEach((record) => Effect.log(record.body))),
  +  queue,
  +  Effect.fn(function* (event) {
  +    for (const record of event.Records) yield* Effect.log(record.body);
  +  }),
  );
  ```

  `consumeTableChanges` drops its row type argument; annotate
  `event: AWS.DynamoDB.StreamEvent<Row>` instead.
- **`Test.make` moved to `@alchemy.run/test`**
  ([#2621](https://github.com/alchemy-run/alchemy/pull/2621)):

  ```diff lang="typescript"
  // bun add -d @alchemy.run/test
  -import * as Test from "alchemy/Test/Alchemy";
  +import * as Test from "@alchemy.run/test/Alchemy";
  ```

  `alchemy/Test/Bun`, `Vitest`, `Core`, `Http` and `TestState` move the same way.
- **The Durable Object Domain platform and workflow engine are factories**
  ([#2601](https://github.com/alchemy-run/alchemy/pull/2601)). With no
  options they keep the same objects and data:

  ```diff lang="typescript"
  // Domain model, and Effect workflows on Durable Objects
  -Layer.provide(DomainCloudflare.DurableObjects)
  +Layer.provide(DomainCloudflare.layerDurableObjects())
  -Layer.provideMerge(Cloudflare.Workflows.DurableObjectEngine)
  +Layer.provideMerge(Cloudflare.Workflows.layerDurableObjectEngine())
  ```

- **Domain clients**: a command client takes the target, the input, then
  options ([#2561](https://github.com/alchemy-run/alchemy/pull/2561)), so
  deploy clients and servers together. `watch` streams `{ state, cursor }`,
  `events` ends its history with a `CaughtUp` frame, and cursors are numbers
  ([#2579](https://github.com/alchemy-run/alchemy/pull/2579)). `Domain.Api`
  takes `{ model }` and `.middleware()` is gone
  ([#2820](https://github.com/alchemy-run/alchemy/pull/2820)):

  ```diff lang="typescript"
  // a command call
  -yield* bank.WithdrawMoney({ target: accountId, amount: 2_000, commandId }, { headers });
  +yield* bank.WithdrawMoney(accountId, { amount: 2_000 }, { commandId, headers });
  ```

- **`foundationDns` is replaced by `nameservers`** on
  `Cloudflare.DNS.ZoneDnsSettings` and `AccountDnsSettings`, since
  Cloudflare rejects `foundation_dns` from 2026-11-23
  ([#2501](https://github.com/alchemy-run/alchemy/pull/2501)):
  `foundationDns: true` becomes `nameservers: { type: "cloudflare.advanced" }`.
- **`Cloudflare.Access.Organization` converges every setting**
  ([#2291](https://github.com/alchemy-run/alchemy/pull/2291)). A setting
  your stack doesn't declare goes back to Cloudflare's default, so copy
  dashboard settings into props before deploying an adopted organization.
- **`GCP.SQL.Instance`**: `ipv4Enabled` moved to
  `ipConfiguration.ipv4Enabled`, `backupEnabled` to `backup.enabled`, and
  `ipAddress` is only the public IP
  ([#2642](https://github.com/alchemy-run/alchemy/pull/2642)).
- **GitHub**: `GitHub.Ruleset` rules are top-level props
  ([#2582](https://github.com/alchemy-run/alchemy/pull/2582)), and the
  package uses the distilled GitHub SDK instead of Octokit, so binding
  errors are the SDK's typed errors and `GitHubCredentials` is distilled's
  `Credentials` ([#2530](https://github.com/alchemy-run/alchemy/pull/2530)).
- **Tagged error fields named `name` are renamed**, mostly to
  `resourceName`, so logs print the error type
  ([#2689](https://github.com/alchemy-run/alchemy/pull/2689)).
- **`--log-ansi` is removed**, and telemetry exports spans and metrics but
  no log records ([#2765](https://github.com/alchemy-run/alchemy/pull/2765)).

## Effect 4.1

Alchemy now runs on Effect 4.1
([#2754](https://github.com/alchemy-run/alchemy/pull/2754)):

```sh
bun add effect@^4.1.0 @effect/platform-node@^4.1.0
```

Effect 4.1 deletes `effect/Crypto`. Its `SecureRandom` and `Digest` services
replace it, and the platform layer provides them, so `StackServices` changes
with it:

```diff lang="typescript"
export type StackServices =
  | FileSystem
-  | Crypto
+  | Digest
+  | SecureRandom
  | Path
```

Foldkit projects need `foldkit@^0.170` and `@foldkit/vite-plugin@^0.29`, the
releases built for 4.1
([#2790](https://github.com/alchemy-run/alchemy/pull/2790)).

## DynamoDB state store

`AWS.state()` keeps state in one on-demand DynamoDB table per account and
region ([#2683](https://github.com/alchemy-run/alchemy/pull/2683),
[#2691](https://github.com/alchemy-run/alchemy/pull/2691)). A deploy loads
the stage with one `Query`, and records too large for an item overflow to S3:

```typescript
state: AWS.state()                        // table alchemy-state
state: AWS.state({ name: "team-a" })      // table alchemy-state-team-a
state: AWS.state({ kmsKeyId })            // table and overflow bucket under your key
state: AWS.state({ backend: "s3" })       // keep the S3 bucket
```

Existing stages move with one command. Each stage migrates on its own, older
Alchemy versions are fenced out of the S3 copy, and S3 objects are never
deleted:

```sh
$ alchemy state migrate
my-app/prod: migrated (42 records)
my-app/dev: blocked (a deploy holds the S3 state lock until …)

$ alchemy state migrate --rollback   # back to S3, before downgrading
```

Bucket stores also stop failing large deploys: a lease that lapsed while
still ours is taken back, so a 5,000-resource stack deploys on S3 or Cloud
Storage ([#2693](https://github.com/alchemy-run/alchemy/pull/2693)).

`Cloudflare.state()` now deploys with direct API calls, can pin its account
and Worker name, and can serve on your own domain
([#2385](https://github.com/alchemy-run/alchemy/pull/2385)):

```typescript
state: Cloudflare.state({
  accountId: "c8eeff0e...",
  workerName: "acme-state",
  domain: "alchemy-state.example.com", // for networks that can't reach workers.dev
}),
```

A store whose existence can't be confirmed, say from a token without
**Workers Scripts Read**, is left untouched instead of being bootstrapped
over ([#2605](https://github.com/alchemy-run/alchemy/pull/2605)). Thanks
[apostoli](https://github.com/apostolos-geyer)!

Docs: [AWS state store](/state-store#aws-state-store) ·
[Migrating from S3](/state-store#migrating-from-the-s3-store) ·
[Cloudflare state store](/state-store#cloudflare-state-store).

## Keyless bindings between AWS and GCP

A GCP binding on a Lambda, ECS task, EC2 instance or App Runner service no
longer creates a service account key. The host's IAM role impersonates the
service account through a workload identity pool that trusts your AWS
account ([#2648](https://github.com/alchemy-run/alchemy/pull/2648)). Your
code doesn't change:

```typescript
export default Worker.make(
  { main: import.meta.url, functionUrl: true },
  Effect.gen(function* () {
    const publish = yield* GCP.PubSub.Publish(yield* Events);
    return {
      fetch: publish({ body: { messages: [{ data: btoa("hello") }] } }).pipe(
        Effect.as(HttpServerResponse.text("published")),
      ),
    };
  }).pipe(Effect.provide(GCP.PubSub.PublishHttp)),
);
```

```diff lang="text"
WorkerServiceAccount         GCP.IAM.ServiceAccount
-WorkerServiceAccountKey      GCP.IAM.ServiceAccountKey
+AwsWorkloadIdentityPool      GCP.IAM.WorkloadIdentityPool
+AwsWorkloadIdentityProvider  GCP.IAM.WorkloadIdentityProvider
+WorkerWorkloadIdentityUser   GCP.IAM.Member
```

The other direction works the same way. An AWS binding on Cloud Run or Cloud
Functions no longer creates an IAM user and access key: the host assumes its
role with its Google ID token
([#2645](https://github.com/alchemy-run/alchemy/pull/2645)).

`GCP.IAM.WorkloadIdentityPool` and `WorkloadIdentityProvider` are resources
too, for keyless CI ([#2130](https://github.com/alchemy-run/alchemy/pull/2130)):

```typescript
const pool = yield* GCP.IAM.WorkloadIdentityPool("GitHub", {});

yield* GCP.IAM.WorkloadIdentityProvider("GitHubOidc", {
  workloadIdentityPoolId: pool.workloadIdentityPoolId,
  attributeMapping: { "google.subject": "assertion.sub", "attribute.repository": "assertion.repository" },
  attributeCondition: `assertion.repository == "my-org/my-repo"`,
  oidc: { issuerUri: "https://token.actions.githubusercontent.com" },
});
```

Docs: [GCP federated identity](/gcp/security/federated-identity) ·
[AWS federated identity](/aws/security/federated-identity).

## Custom domains on any DNS host

`domain.dns` names the DNS host that publishes a custom domain's records, on
every platform ([#1888](https://github.com/alchemy-run/alchemy/pull/1888)):

```typescript
yield* AWS.Website.StaticSite("Site", {
  path: "./dist",
  domain: { name: "app.example.com", dns: Cloudflare.DNS.Adapter() },
});

yield* AWS.Lambda.Function("Api", {
  main: "./src/handler.ts",
  domain: { name: "api.example.com", dns: Cloudflare.DNS.Adapter() },
});

yield* Fly.Website.Vite("Web", {
  domain: { name: "web.example.com", dns: AWS.Route53.Adapter() },
});
```

Alchemy publishes whatever the platform asks for: ACM validation records,
ACME challenges, verification TXTs and aliases. `Cloudflare.DNS.Adapter`,
`AWS.Route53.Adapter` and `Hetzner.DNS.Adapter` ship today, and an adapter
for another DNS host is three functions. Thanks
[Dan Myles](https://github.com/dan-myles), whose PR this builds on, and
[bjorntechTobbe](https://github.com/bjorntechTobbe) for the follow-ups
([#2861](https://github.com/alchemy-run/alchemy/pull/2861),
[#2860](https://github.com/alchemy-run/alchemy/pull/2860))!

Docs: [DNS adapters](/infrastructure-as-code/dns-adapters).

## Lambda aliases, streaming and partial batch failures

`alias` publishes a version on each deploy and routes every event source,
URL and integration through it, so a rollback is one `update-alias` call
([#2504](https://github.com/alchemy-run/alchemy/pull/2504),
[#2528](https://github.com/alchemy-run/alchemy/pull/2528)):

```typescript
export default class Api extends AWS.Lambda.Function<Api>()(
  "Api",
  { main: import.meta.url, alias: "live", functionUrl: true },
  Effect.gen(function* () {
    yield* AWS.SQS.consumeQueueMessages(jobs, processJob); // mapping → api:live
    return { fetch: handleHttp };                          // URL on qualifier "live"
  }),
) {}
```

A `RESPONSE_STREAM` Function URL now streams an Effect response body
instead of buffering it ([#2502](https://github.com/alchemy-run/alchemy/pull/2502)):

```typescript
export default class Events extends AWS.Lambda.Function<Events>()(
  "Events",
  { main: import.meta.url, functionUrl: { invokeMode: "RESPONSE_STREAM" } },
  Effect.succeed({
    fetch: Effect.succeed(
      HttpServerResponse.stream(
        Stream.make("data: one\n\n", "data: two\n\n").pipe(Stream.encodeText),
        { contentType: "text/event-stream" },
      ),
    ),
  }),
) {}
```

SQS, Kinesis and DynamoDB Streams handlers can return Lambda's batch
response, so only failed records are retried
([#2508](https://github.com/alchemy-run/alchemy/pull/2508)):

```typescript
yield* AWS.SQS.consumeQueueMessages(
  queue,
  Effect.fn(function* (event) {
    const failed = yield* Effect.filter(
      event.Records,
      (record) => handle(record.body).pipe(Effect.as(false), Effect.catchCause(() => Effect.succeed(true))),
    );
    return { batchItemFailures: failed.map((record) => ({ itemIdentifier: record.messageId })) };
  }),
);
```

A handler that runs past its `timeout` is now interrupted, so finalizers run
and telemetry flushes before Lambda kills the sandbox
([#2682](https://github.com/alchemy-run/alchemy/pull/2682)):

```typescript
timeout: Duration.seconds(30),      // handler interrupted at 30 s
timeoutMargin: Duration.seconds(2), // Lambda configured for 32 s (default margin: 1 s)
```

Docs: [Lambda](/aws/compute/lambda).

## Cloud Run sidecars with typed RPC

`GCP.Run.Container` runs your own Effect program, or any image, as a sidecar
of a Cloud Run service. `bindContainer` adds it to the revision, orders
startup with `dependsOn`, and hands back a typed client over `localhost`
([#2652](https://github.com/alchemy-run/alchemy/pull/2652)):

```typescript
export class Worker extends GCP.Run.Container<Worker>()(
  "Worker",
  { main: import.meta.url, port: 3000, startupProbe: { httpGet: { path: "/health" } } },
  Effect.gen(function* () {
    return {
      greet: (name: string) => Effect.succeed(`hello ${name}`),
      fetch: Effect.succeed(HttpServerResponse.text("ok")),
    };
  }),
) {}

export default class Api extends GCP.Run.Service<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const worker = yield* GCP.Run.bindContainer(Worker);
    return { fetch: worker.greet("sam").pipe(Effect.map(HttpServerResponse.text)) };
  }),
) {}
```

`InvokeService` calls the methods of a private service, signed with the
caller's ID token ([#2653](https://github.com/alchemy-run/alchemy/pull/2653)).
Pass an Effect RPC `schema` or an HttpApi `api` to either binding for a fully
typed client ([#2654](https://github.com/alchemy-run/alchemy/pull/2654)):

```typescript
const tasks = yield* GCP.Run.InvokeService(TaskBackend, { schema: TaskRpcs });
const task = yield* tasks.getTask({ id: "t1" }); // Effect<Task, TaskNotFound | …>
```

Service containers also take `startupProbe`, `livenessProbe` and `dependsOn`
([#2644](https://github.com/alchemy-run/alchemy/pull/2644)), and an image
service can list `GCP.Run.Container`s in its template
([#2657](https://github.com/alchemy-run/alchemy/pull/2657)).

Docs: [Sidecars](/gcp/compute/sidecars) · [Cloud Run](/gcp/compute/cloud-run).

## Serve a Domain Api over HTTP, MCP and the terminal

`Domain.Api` names its model and what of it a client may reach. A kind you
leave out is served whole
([#2820](https://github.com/alchemy-run/alchemy/pull/2820),
[#2865](https://github.com/alchemy-run/alchemy/pull/2865)):

```typescript
export class AgentApi extends Domain.Api("AgentApi", {
  model: Bank,
  commands: ["DepositMoney", "RequestTransfer"],
  views: ["AccountSummary"],
  streams: [],
}) {}
```

The same Api now reaches clients that aren't Effect. `toHttpApi` publishes it
as a JSON HTTP API with OpenAPI, live reads as Server-Sent Events
([#2587](https://github.com/alchemy-run/alchemy/pull/2587)):

```typescript
const PartnerHttp = DomainHttp.toHttpApi(AgentApi);
export const PartnerHttpLive = HttpApiBuilder.layer(PartnerHttp.api, { openapiPath: "/openapi.json" }).pipe(
  Layer.provide(PartnerHttp.layer),
  Layer.provide(BankLive),
);
```

`toMcp` serves it as an MCP server, and `toToolkit` gives an in-app agent the
same calls as Effect AI tools. Middleware, `validate` and rejections apply to
the agent ([#2586](https://github.com/alchemy-run/alchemy/pull/2586)):

```typescript
export const BankMcp = DomainAi.toMcp(AgentApi).pipe(
  Layer.provide(McpServer.layerHttp({ name: "bank", version: "1.0.0", path: "/mcp" })),
  Layer.provide(BankLive),
);
```

`toCli` turns it into a command-line tool for people and agents
([#2588](https://github.com/alchemy-run/alchemy/pull/2588),
[#2857](https://github.com/alchemy-run/alchemy/pull/2857)):

```sh
$ bank deposit-money --target a-1 --amount 1000
{ "reply": { "balance": 1000 }, "stream": "Account/a-1", "version": 1 }
$ bank account-summary get --key a-1
{ "balance": 1000 }
```

And `@alchemy.run/domain/Foldkit` turns it into Foldkit Commands and
Subscriptions, with typed refusals
([#2700](https://github.com/alchemy-run/alchemy/pull/2700)):

```typescript
export const Bank = DomainFoldkit.make(CustomerApi);

Bank.DepositMoney({ target: model.accountId, input: { amount: 1_000 }, commandId });
Bank.AccountSummary.watch({ key: (model) => model.accountId, toMessage: Message.ReceivedSummary });
```

Thanks [Taras Kornichuk](https://github.com/artile), who built most of this
release's Domain work!

Docs: [HTTP API](/domain/http-api) · [MCP](/domain/mcp) · [CLI](/domain/cli) ·
[Foldkit](/domain/foldkit).

## Backfill views and projections

A view or projection added in a later deploy now receives every event its
sources recorded before it existed, in the order they were recorded. Bump its
version to rebuild it from history
([#2725](https://github.com/alchemy-run/alchemy/pull/2725)):

```typescript
// deploy 2 adds two views; both fold every earlier event, with no script
class Ledger extends Domain.Model("Ledger", { aggregates: [Account], views: [Deposits, Timeline] }) {}

// rebuild a view after its evolve changed
Ledger.layer(LedgerHandlers, { versions: { Deposits: 1 } });
```

On Cloudflare, the deploy waits for the backfill and reports progress:

```sh
[DomainBackfillRun] Backfilling view:Deposits reading history 41% (1,690/4,096 subtrees, 410,211 instances) (48s) ...
[DomainBackfillRun] Backfilled view:Deposits (112.4s)
```

Each `Domain.Model` also owns its data now, so two models that list the same
aggregate get separate instances. Models deployed before this release keep
their data on upgrade ([#2560](https://github.com/alchemy-run/alchemy/pull/2560)).

Docs: [Backfill](/domain/backfill).

## Durable workflows wake on time

Wake-ups scheduled from inside a Durable Object alarm inherited its retry
backoff, so workflow sleeps and Domain projection batches ran late, each hop
later than the last ([#2916](https://github.com/alchemy-run/alchemy/pull/2916)):

```typescript
// four one-second sleeps: previously still running after 45s, now ~4s
for (let nap = 0; nap < 4; nap++) {
  yield* DurableClock.sleep({ name: `nap-${nap}`, duration: "1 second", inMemoryThreshold: 0 });
}
```

The fix comes with a conformance suite of 28 cases that every engine runs:
Durable Objects, Cloudflare Workflows and Lambda durable functions, locally
and live. It found 15 bugs, from signals that hung for three minutes to
interrupts that skipped compensations. `Activity.raceAll` now fails at once
on the two engines that can't support it, instead of hanging.

Docs: [Effect workflows on Cloudflare](/cloudflare/compute/effect-workflows) ·
[on AWS](/aws/compute/effect-workflows).

## Keep data in a jurisdiction

Workflows ([#2734](https://github.com/alchemy-run/alchemy/pull/2734)),
Queues ([#2538](https://github.com/alchemy-run/alchemy/pull/2538)), R2
buckets ([#2758](https://github.com/alchemy-run/alchemy/pull/2758)), Domain
models and the Durable Object workflow engine
([#2601](https://github.com/alchemy-run/alchemy/pull/2601)) can all stay in
a Cloudflare jurisdiction:

```typescript
yield* Cloudflare.Queues.Queue("Jobs", { jurisdiction: "eu" });
yield* Cloudflare.R2.Bucket("Records", { jurisdiction: "us" });

Layer.provide(DomainCloudflare.layerDurableObjects({ jurisdiction: "eu" }));
Layer.provideMerge(Cloudflare.Workflows.layerDurableObjectEngine({ jurisdiction: "eu" }));
```

A jurisdiction is fixed at creation, so changing it replaces the resource.
Queues also take `messageRetentionPeriod`, `deliveryDelay` and
`deliveryPaused`. Thanks [Thijs Koerselman](https://github.com/0x80)!

## Durable Object code updates

`codeUpdateStrategy` sets how long a deploy lets running Durable Objects
defer onto new code, like Wrangler's `durable_objects.code_update_strategy`
([#2863](https://github.com/alchemy-run/alchemy/pull/2863)):

```typescript
export default class Api extends Cloudflare.Worker<Api>()(
  "Api",
  {
    main: import.meta.url,
    codeUpdateStrategy: { mode: "deferred", maxDelay: "1 minute" }, // or { mode: "immediate" }
  },
  handler,
) {}
```

Docs: [Code updates](/cloudflare/compute/code-updates).

## Flagship in `alchemy dev`

Flagship apps and flags now run locally, so `env.FLAGS` evaluates on your
machine with no Cloudflare API calls
([#2746](https://github.com/alchemy-run/alchemy/pull/2746)):

```typescript
const app = yield* Cloudflare.Flagship.App("Flags", {});
yield* Cloudflare.Flagship.Flag("NewCheckout", {
  appId: app.appId,
  key: "new-checkout",
  defaultVariation: "off",
  variations: { off: false, on: true },
  rules: [{ priority: 1, conditions: [{ attribute: "country", operator: "equals", value: "US" }], serveVariation: "on" }],
});
yield* Cloudflare.Worker("Worker", { main: "./src/worker.ts", env: { FLAGS: app } });
```

A flag change applies without restarting the Worker. Pipe the app and its
flags through `Alchemy.remote()` to use real flags in dev.

## Docker builds take args and secrets

Every image built from your own Dockerfile takes build args and BuildKit
secrets: Cloudflare Containers, ECS, Kubernetes and `Docker.Image`
([#2225](https://github.com/alchemy-run/alchemy/pull/2225)). A secret never
lands in argv, an image layer or `docker history`:

```typescript
export class Api extends Cloudflare.Container<Api>()("Api", {
  context: `${import.meta.dirname}/api`,
  build: {
    args: { NODE_ENV: "production" },
    secrets: { NPM_TOKEN: Config.Redacted("NPM_TOKEN") },
  },
}) {}
```

```dockerfile
RUN --mount=type=secret,id=NPM_TOKEN,env=NPM_TOKEN npm ci
```

`Docker.Container` takes Docker Engine's hardening options
([#2623](https://github.com/alchemy-run/alchemy/pull/2623)), and
`Docker.Service` updates in place, so `updateConfig` and `rollbackConfig`
apply ([#2536](https://github.com/alchemy-run/alchemy/pull/2536)):

```typescript
yield* Docker.Container("worker", {
  image: "oven/bun:1",
  memory: "512m",
  cpus: 0.5,
  readOnlyRootFilesystem: true,
  capDrop: ["ALL"],
  noNewPrivileges: true,
  user: "1000:1000",
});
```

Thanks [Jordan](https://github.com/skusez), [Yuzu](https://github.com/Yuzu02)
and [Mycael Dias](https://github.com/KaliemSB)!

## Drift you can trust

`alchemy drift` only sees what a provider's `read` returns. Lambda, DynamoDB,
S3, SQS, EventBridge, Step Functions, WAF, ELB, ECS, EC2 networking and
more now read back every setting they manage, so out-of-band changes show
up ([#2661](https://github.com/alchemy-run/alchemy/pull/2661),
[#2705](https://github.com/alchemy-run/alchemy/pull/2705),
[#2488](https://github.com/alchemy-run/alchemy/pull/2488)). And untouched
resources stop showing up
([#2496](https://github.com/alchemy-run/alchemy/pull/2496),
[#2169](https://github.com/alchemy-run/alchemy/pull/2169),
[#2647](https://github.com/alchemy-run/alchemy/pull/2647)):

```diff lang="sh"
$ alchemy deploy && alchemy drift
-[Api] drifted
-[Db] drifted
+Plan: no changes
```

`alchemy drift --repair` recreates resources deleted out of band in
dependency order ([#2495](https://github.com/alchemy-run/alchemy/pull/2495)),
and EC2 instances and volumes send an idempotency token, so a retried create
never launches a second one

Docs: [Drift](/cli/drift).

## Cycles and replacements never take over a foreign resource

A resource in a dependency cycle is precreated before `read` can check
ownership. Providers now implement a read-only `observe` hook, and the
engine refuses an existing resource it doesn't own unless you pass
`--adopt` ([#2195](https://github.com/alchemy-run/alchemy/pull/2195),
[#2620](https://github.com/alchemy-run/alchemy/pull/2620)). Replacements are
checked before they touch anything
([#2200](https://github.com/alchemy-run/alchemy/pull/2200)):

```typescript
// another Worker already owns this script name
yield* Cloudflare.Worker("ReplacementTarget", { main, name: owner.workerName });
// before: the deploy overwrote the script
// after:  OwnedBySomeoneElse, and neither Worker changes
```

A cyclic resource can now take its name from outside its cycle
([#2643](https://github.com/alchemy-run/alchemy/pull/2643)), and a ref to a
resource in the same stack is a dependency, so destroy no longer races them
([#2913](https://github.com/alchemy-run/alchemy/pull/2913)):

```typescript
const fn = yield* AWS.Lambda.Function("Fn", {
  main,
  functionName: queue.queueName.pipe(Output.map((name) => `${name}-fn`)),
});
yield* fn.bind`Self`({ env: { SELF_NAME: fn.functionName } });
// before: Cannot coerce Output<Queue.queueName.map(...)> to a string
```

Interrupted creates are recovered without guessing
([#2199](https://github.com/alchemy-run/alchemy/pull/2199),
[#2686](https://github.com/alchemy-run/alchemy/pull/2686),
[#2534](https://github.com/alchemy-run/alchemy/pull/2534)), and
`alchemy destroy` plans from state without running your stack program, so a
dev stage tears down without cloud credentials
([#2491](https://github.com/alchemy-run/alchemy/pull/2491)). Thanks
[Nacho Vazquez](https://github.com/NachoVazquez)!

## Smaller runtime bundles

`import * as AWS from "@alchemy.run/aws"` in a runtime no longer makes the
bundler parse every AWS service, and deploy-time code stays out of Lambdas
([#2492](https://github.com/alchemy-run/alchemy/pull/2492)):

| | Before | After |
| --- | ---: | ---: |
| Lambda: modules parsed | 8,423 | 813 |
| Lambda: bytes shipped | 1.30 MB | 0.51 MB |
| MicroVM (Node): bytes shipped | 1.61 MB | 0.43 MB |
| Worker: modules parsed | 2,015 | 1,209 |

Lambdas and MicroVMs are minified by default, with source maps.

## Drive deploys from code

`alchemy/Alchemist` is the programmatic API under the CLI. Plan, apply,
drift, nuke, logs and state are each one call
([#2765](https://github.com/alchemy-run/alchemy/pull/2765)):

```typescript
import * as Alchemist from "alchemy/Alchemist";

const program = Effect.gen(function* () {
  const plan = yield* Alchemist.plan({ stack: Stack, operation: "deploy", stage: "prod" });
  if (Alchemist.hasChanges(plan)) yield* Alchemist.apply(plan);
}).pipe(
  Alchemist.onEvent((event) => Effect.log(event.type)),
  Effect.provide(Alchemist.layer()),
  Effect.scoped,
);
```

Every run writes one NDJSON log under `.alchemy/log/`, including child
processes and sidecars, and `--log-format json` prints structured logs.
Thanks [Rahul Mishra](https://github.com/BlankParticle)!

Docs: [CLI API](/cli/api).

## Migrations on every GCP database

Cloud SQL, AlloyDB and Spanner apply `migrations` on deploy, like D1, Neon,
PlanetScale, Turso, RDS and DSQL
([#2651](https://github.com/alchemy-run/alchemy/pull/2651)):

```typescript
const db = yield* GCP.SQL.Database("App", {
  instance: instance.instanceName,
  migrations: "./migrations",
  migrationsUser: user.userName,
  migrationsPassword: password.text,
});
```

Cloud SQL runs them over the data API by default, which needs no network
route, or over the Cloud SQL connector. Spanner resumes a failed migration
at the statement that failed. `GCP.SQL.Instance` can also be private-IP
only, with SSL mode and backup retention in the stack
([#2642](https://github.com/alchemy-run/alchemy/pull/2642)).

A D1 batch whose reply was lost is no longer sent twice: the engine checks
the migration ledger first ([#2720](https://github.com/alchemy-run/alchemy/pull/2720)).
Thanks [Ahmed Hesham](https://github.com/ahmedhesham6)!

Docs: [Cloud SQL](/gcp/data/cloud-sql).

## Cloudflare alerts as GitHub issues

`Cloudflare.Alerting.consumeNotifications` handles Cloudflare notifications
in code ([#2519](https://github.com/alchemy-run/alchemy/pull/2519)), and
GitHub has runtime bindings for issues and pull requests
([#2529](https://github.com/alchemy-run/alchemy/pull/2529)). Together, a
Worker files an issue for each observability alert:

```typescript
const policy = yield* IssuePolicy;
const createIssue = yield* GitHub.CreateIssue(yield* Repo);
yield* Cloudflare.Alerting.consumeNotifications(policy, (notification) =>
  createIssue({ title: notification.text.split("\n")[0], body: notification.text }),
);
```

`@alchemy.run/github` now runs on the distilled GitHub SDK, so you can call
any GitHub API with typed errors and pagination
([#2530](https://github.com/alchemy-run/alchemy/pull/2530)):

```typescript
import * as Issues from "@distilled.cloud/github/issues";

const issues = yield* Stream.runCollect(Issues.listForRepo.items({ owner: "my-org", repo: "api" }));
```

Docs: [GitHub API](/git/github-api).
