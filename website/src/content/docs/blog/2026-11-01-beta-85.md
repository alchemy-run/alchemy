beta.85 moves Alchemy to **Effect 4.1** and makes **DynamoDB the default
AWS state store**: a plan that took 21 s on S3 takes 80 ms, and
`alchemy state migrate` moves existing stages. The **Cloudflare state store**
can now pin its account and take a custom name and domain.
**A custom domain can live on any DNS host**, so a Lambda can sit on
Cloudflare DNS and a Worker on Route 53.

AWS and GCP now **bind to each other without long-lived keys**, and GCP
profiles **sign in with gcloud**. Lambda gets **aliases, response streaming,
partial batch failures and timeout interrupts**. Cloud Run gets **sidecars
with typed RPC**. `@alchemy.run/domain` can **publish an Api as an HTTP API,
an MCP server, a CLI or Foldkit commands**, predict a command's outcome on the
client, and backfill new views from history. Durable workflows wake on time,
and every workflow engine passes one conformance suite.

:::caution
**Breaking changes**

- **Effect 4.1** ([#2754](https://github.com/alchemy-run/alchemy/pull/2754)).
  Bump `effect` and `@effect/*` to `^4.1.0`. See [below](#effect-41).
- **`AWS.state()` keeps state in DynamoDB**
  ([#2691](https://github.com/alchemy-run/alchemy/pull/2691)). A stage still
  in the S3 store is refused until you run `alchemy state migrate`, or keep
  S3 with `AWS.state({ backend: "s3" })`. See [below](#dynamodb-state-store).
- **Lambda event-source handlers take the Lambda event**
  ([#2508](https://github.com/alchemy-run/alchemy/pull/2508)).
  `SQS.consumeQueueMessages`, `Kinesis.consumeStreamRecords` and
  `DynamoDB.consumeTableChanges` pass the event instead of a `Stream`:

  ```diff lang="typescript"
  yield* AWS.SQS.consumeQueueMessages(
  -  queue,
  -  (records) => records.pipe(Stream.runForEach((record) => Effect.log(record.body))),
  +  queue,
  +  Effect.fn(function* (event) {
  +    for (const record of event.Records) yield* Effect.log(record.body);
  +  }),
  );
  ```

  `consumeTableChanges` drops its row type argument; annotate
  `event: AWS.DynamoDB.StreamEvent<Row>` instead.
- **`Test.make` moved to `@alchemy.run/test`**
  ([#2621](https://github.com/alchemy-run/alchemy/pull/2621)):

  ```diff lang="typescript"
  // bun add -d @alchemy.run/test
  -import * as Test from "alchemy/Test/Alchemy";
  +import * as Test from "@alchemy.run/test/Alchemy";
  ```

  `alchemy/Test/Bun`, `Vitest`, `Core`, `Http` and `TestState` move the same way.
- **GCP profiles**: the `env` method is gone, and `gcloud` profiles name a
  gcloud configuration ([#2680](https://github.com/alchemy-run/alchemy/pull/2680)).
  Environment variables still override any profile when they carry a
  credential (`GOOGLE_ACCESS_TOKEN` or `GOOGLE_APPLICATION_CREDENTIALS`).
  A profile saved with `env` reports itself invalid; run
  `alchemy profile edit --profile <name> --reconfigure GCP`.
- **`GCP.Run.Container` is now the sidecar resource**. The container-spec
  type it used to name is `GCP.Run.ContainerSpec`
  ([#2652](https://github.com/alchemy-run/alchemy/pull/2652)).
- **The Durable Object Domain platform and workflow engine are factories**
  ([#2601](https://github.com/alchemy-run/alchemy/pull/2601)). With no
  options they keep the same objects and data:

  ```diff lang="typescript"
  // Domain model, and Effect workflows on Durable Objects
  -Layer.provide(DomainCloudflare.DurableObjects)
  +Layer.provide(DomainCloudflare.layerDurableObjects())
  -Layer.provideMerge(Cloudflare.Workflows.DurableObjectEngine)
  +Layer.provideMerge(Cloudflare.Workflows.layerDurableObjectEngine())
  ```

- **Domain clients**: a command client takes the target, the input, then
  options ([#2561](https://github.com/alchemy-run/alchemy/pull/2561)), so
  deploy clients and servers together. `watch` streams `{ state, cursor }`,
  `events` ends its history with a `CaughtUp` frame, and cursors are numbers
  ([#2579](https://github.com/alchemy-run/alchemy/pull/2579)). `Domain.Api`
  takes `{ model }`, `.middleware()` is gone, and `api.entries` is
  `api.serves` ([#2820](https://github.com/alchemy-run/alchemy/pull/2820)).
  `testClient` is `clientInProcess`
  ([#2550](https://github.com/alchemy-run/alchemy/pull/2550)):

  ```diff lang="typescript"
  // a command call
  -yield* bank.WithdrawMoney({ target: accountId, amount: 2_000, commandId }, { headers });
  +yield* bank.WithdrawMoney(accountId, { amount: 2_000 }, { commandId, headers });
  ```

- **Domain stories**: `Story.make`'s `externalSystems` is `stub`, and a
  system you don't stub now runs for real
  ([#2477](https://github.com/alchemy-run/alchemy/pull/2477)).
  `expectCall` is `call` and `resolve` is `succeed`
  ([#2481](https://github.com/alchemy-run/alchemy/pull/2481)):

  ```diff lang="typescript"
  // stub the systems a story fakes
  -Story.make(Bank, { layer: BankHandlers, externalSystems: [FraudCheck] });
  +Story.make(Bank, { layer: BankHandlers, stub: [FraudCheck] });
  -Story.expectCall(FraudCheck.score, { accountId }),
  -Story.resolve(FraudCheck.score, { risk: 0.95 }),
  +Story.call(FraudCheck.score, { accountId }),
  +Story.succeed(FraudCheck.score, { risk: 0.95 }),
  ```

- **Domain checks**: a command's `target` must be its aggregate's `id`
  schema ([#2563](https://github.com/alchemy-run/alchemy/pull/2563)), and an
  external system adapter that returns a value its schema rejects now dies
  ([#2548](https://github.com/alchemy-run/alchemy/pull/2548)).
- **`foundationDns` is replaced by `nameservers`** on
  `Cloudflare.DNS.ZoneDnsSettings` and `AccountDnsSettings`, since
  Cloudflare rejects `foundation_dns` from 2026-11-23
  ([#2501](https://github.com/alchemy-run/alchemy/pull/2501)):
  `foundationDns: true` becomes `nameservers: { type: "cloudflare.advanced" }`.
- **`Cloudflare.Access.Organization` converges every setting**
  ([#2291](https://github.com/alchemy-run/alchemy/pull/2291)). A setting
  your stack doesn't declare goes back to Cloudflare's default, so copy
  dashboard settings into props before deploying an adopted organization.
- **`GCP.SQL.Instance`**: `ipv4Enabled` moved to
  `ipConfiguration.ipv4Enabled`, `backupEnabled` to `backup.enabled`, and
  `ipAddress` is only the public IP
  ([#2642](https://github.com/alchemy-run/alchemy/pull/2642)).
- **GitHub**: `GitHub.Ruleset` rules are top-level props
  ([#2582](https://github.com/alchemy-run/alchemy/pull/2582)), and the
  package uses the distilled GitHub SDK instead of Octokit, so binding
  errors are the SDK's typed errors and `GitHubCredentials` is distilled's
  `Credentials` ([#2530](https://github.com/alchemy-run/alchemy/pull/2530)).
- **Tagged error fields named `name` are renamed**, mostly to
  `resourceName`, so logs print the error type
  ([#2689](https://github.com/alchemy-run/alchemy/pull/2689)).
- **`--log-ansi` is removed**, and telemetry exports spans and metrics but
  no log records ([#2765](https://github.com/alchemy-run/alchemy/pull/2765)).
  `alchemy/Cli/CliKit` is folded into `Interaction`
  ([#2524](https://github.com/alchemy-run/alchemy/pull/2524)).

## Effect 4.1

Alchemy now runs on Effect 4.1
([#2754](https://github.com/alchemy-run/alchemy/pull/2754)):

```sh
bun add effect@^4.1.0 @effect/platform-node@^4.1.0
```

Effect 4.1 deletes `effect/Crypto`. Its `SecureRandom` and `Digest` services
replace it, and the platform layer provides them, so `StackServices` changes
with it:

```diff lang="typescript"
export type StackServices =
  | FileSystem
-  | Crypto
+  | Digest
+  | SecureRandom
  | Path
```

Foldkit projects need `foldkit@^0.170` and `@foldkit/vite-plugin@^0.29`, the
releases built for 4.1
([#2790](https://github.com/alchemy-run/alchemy/pull/2790)).

## DynamoDB state store

`AWS.state()` keeps state in one on-demand DynamoDB table per account and
region ([#2683](https://github.com/alchemy-run/alchemy/pull/2683),
[#2691](https://github.com/alchemy-run/alchemy/pull/2691)). A deploy loads
the stage with one `Query`, and records too large for an item overflow to S3:

```typescript
state: AWS.state()                        // table alchemy-state
state: AWS.state({ name: "team-a" })      // table alchemy-state-team-a
state: AWS.state({ kmsKeyId })            // table and overflow bucket under your key
state: AWS.state({ backend: "s3" })       // keep the S3 bucket
```

The difference shows up on every command:

| 250 records | S3 | DynamoDB |
| --- | ---: | ---: |
| plan, new process | 21,640 ms | 80 ms |
| write all | 10,051 ms | 1,124 ms |
| 1,000 resources: unchanged redeploy | 195 s | 0.5 s |

Existing stages move with one command. Each stage migrates on its own, older
Alchemy versions are fenced out of the S3 copy, and S3 objects are never
deleted:

```sh
$ alchemy state migrate
my-app/prod: migrated (42 records)
my-app/dev: blocked (a deploy holds the S3 state lock until …)

$ alchemy state migrate --rollback   # back to S3, before downgrading
```

Bucket stores also stop failing large deploys: a lease that lapsed while
still ours is taken back, so a 5,000-resource stack deploys on S3 or Cloud
Storage ([#2693](https://github.com/alchemy-run/alchemy/pull/2693)).

Docs: [AWS state store](/state-store#aws-state-store) ·
[Migrating from S3](/state-store#migrating-from-the-s3-store).

## Cloudflare state store with a custom name and domain

`Cloudflare.state()` no longer deploys its store through an Alchemy stack.
Bootstrap is a few idempotent API calls, and the store can pin its account,
take any Worker name and serve on your own domain
([#2385](https://github.com/alchemy-run/alchemy/pull/2385)):

```typescript
state: Cloudflare.state({
  accountId: "c8eeff0e...",            // fail instead of using whichever account the profile resolves
  workerName: "acme-state",            // the full Worker name (or `name` for alchemy-state-store-<name>)
  domain: "alchemy-state.example.com", // for networks that can't reach workers.dev
}),
```

With no `--backend`, `alchemy state bootstrap` provisions the store your
`alchemy.run.ts` configures, options included, so CI can create it first:

```sh
alchemy state bootstrap --profile ci
```

Existing stores upgrade in place and keep their secrets and state. The store
also guards its secrets now. An older release can't overwrite them while
redeploying, a store a newer Alchemy deployed is never downgraded, and a
store whose encryption key is gone asks before making a new one (`--force`
approves; CI fails without changing anything).

A store whose existence can't be confirmed, say from a token without
**Workers Scripts Read**, is left untouched instead of being bootstrapped
over ([#2605](https://github.com/alchemy-run/alchemy/pull/2605)). Deployed
stores return a typed `StateStoreFailure` instead of a bare 500, and route
resource names longer than 100 characters
([#2512](https://github.com/alchemy-run/alchemy/pull/2512)). Thanks
[apostoli](https://github.com/apostolos-geyer)!

Docs: [Cloudflare state store](/state-store#cloudflare-state-store) ·
[Pin the account](/state-store#pin-the-account) ·
[Serve it on your own domain](/state-store#serve-it-on-your-own-domain).

## Custom domains on any DNS host

`domain.dns` names the DNS host that publishes a custom domain's records, on
every platform ([#1888](https://github.com/alchemy-run/alchemy/pull/1888)):

```typescript
yield* AWS.Website.StaticSite("Site", {
  path: "./dist",
  domain: { name: "app.example.com", dns: Cloudflare.DNS.Adapter() },
});

yield* Fly.Website.Vite("Web", {
  domain: { name: "web.example.com", dns: AWS.Route53.Adapter() },
});

yield* AWS.ECS.Service("Api", {
  cluster, image, port: 3000,
  loadBalancer: { domain: { name: "api.example.com", dns: Hetzner.DNS.Adapter() } },
});
```

A Lambda Function takes a `domain` too. An API Gateway HTTP API fronts it
(payload 2.0, so `fetch` handlers work unchanged):

```typescript
const api = yield* AWS.Lambda.Function("Api", {
  main: "./src/handler.ts",
  domain: { name: "api.example.com", dns: Cloudflare.DNS.Adapter() },
});
api.domainUrl; // "https://api.example.com"
```

A Worker on Route 53 or Hetzner DNS is served through a Cloudflare for SaaS
custom hostname, with the verification TXTs and CNAME published for you:

```typescript
yield* Cloudflare.Worker("Api", {
  main: "./src/api.ts",
  domain: {
    name: "app.example.com",
    zoneId: saasZone.zoneId,
    cnameTarget: fallback.origin,
    dns: AWS.Route53.Adapter(),
  },
});
```

Alchemy publishes whatever the platform asks for: ACM validation records,
ACME challenges, verification TXTs and aliases. An ACM certificate can also
validate through any DNS host on its own:

```typescript
const cert = yield* AWS.ACM.Certificate("Cert", { domainName: "app.example.com", dnsValidation: "external" });
yield* Cloudflare.DNS.RecordList("CertValidation", {
  records: cert.domainValidationOptions.pipe(Output.map(AWS.ACM.validationRecordsOf)),
});
const issued = yield* AWS.ACM.CertificateValidation("CertIssued", { certificateArn: cert.certificateArn });
```

`Cloudflare.DNS.Adapter`, `AWS.Route53.Adapter` and `Hetzner.DNS.Adapter`
ship today, and an adapter for another DNS host is three functions. Thanks
[Dan Myles](https://github.com/dan-myles), whose PR this builds on, and
[bjorntechTobbe](https://github.com/bjorntechTobbe) for the follow-ups
([#2861](https://github.com/alchemy-run/alchemy/pull/2861),
[#2860](https://github.com/alchemy-run/alchemy/pull/2860))!

Docs: [DNS adapters](/infrastructure-as-code/dns-adapters) ·
[AWS custom domains](/aws/networking/custom-domains#use-a-domain-on-another-dns-host).

## Keyless bindings between AWS and GCP

A GCP binding on a Lambda, ECS task, EC2 instance or App Runner service no
longer creates a service account key. The host's IAM role impersonates the
service account through a workload identity pool that trusts your AWS
account ([#2648](https://github.com/alchemy-run/alchemy/pull/2648)). Your
code doesn't change:

```typescript
export default Worker.make(
  { main: import.meta.url, functionUrl: true },
  Effect.gen(function* () {
    const publish = yield* GCP.PubSub.Publish(yield* Events);
    return {
      fetch: publish({ body: { messages: [{ data: btoa("hello") }] } }).pipe(
        Effect.as(HttpServerResponse.text("published")),
      ),
    };
  }).pipe(Effect.provide(GCP.PubSub.PublishHttp)),
);
```

```diff lang="text"
WorkerServiceAccount         GCP.IAM.ServiceAccount
-WorkerServiceAccountKey      GCP.IAM.ServiceAccountKey
+AwsWorkloadIdentityPool      GCP.IAM.WorkloadIdentityPool
+AwsWorkloadIdentityProvider  GCP.IAM.WorkloadIdentityProvider
+WorkerWorkloadIdentityUser   GCP.IAM.Member
```

The other direction works the same way. An AWS binding on Cloud Run or Cloud
Functions no longer creates an IAM user and access key: the host assumes its
role with its Google ID token
([#2645](https://github.com/alchemy-run/alchemy/pull/2645)).

`GCP.IAM.WorkloadIdentityPool` and `WorkloadIdentityProvider` are resources
too, for keyless CI ([#2130](https://github.com/alchemy-run/alchemy/pull/2130),
[#2641](https://github.com/alchemy-run/alchemy/pull/2641)):

```typescript
const pool = yield* GCP.IAM.WorkloadIdentityPool("GitHub", {});

yield* GCP.IAM.WorkloadIdentityProvider("GitHubOidc", {
  workloadIdentityPoolId: pool.workloadIdentityPoolId,
  attributeMapping: { "google.subject": "assertion.sub", "attribute.repository": "assertion.repository" },
  attributeCondition: `assertion.repository == "my-org/my-repo"`,
  oidc: { issuerUri: "https://token.actions.githubusercontent.com" },
});
```

Docs: [GCP federated identity](/gcp/security/federated-identity) ·
[AWS federated identity](/aws/security/federated-identity).

## Sign in to GCP with gcloud

A GCP profile can now sign in as your own Google account through a named
gcloud configuration, the way an AWS profile uses `aws sso login`
([#2635](https://github.com/alchemy-run/alchemy/pull/2635),
[#2680](https://github.com/alchemy-run/alchemy/pull/2680)):

```sh
gcloud auth login --configuration=work
alchemy profile edit --add GCP --method gcloud --set configuration=work
```

```jsonc
// ~/.alchemy/profiles/<name>/gcp.json
{ "method": "gcloud", "configuration": "work" }
```

`alchemy profile edit --add GCP` lists your configurations, or creates one
and opens the browser to sign in. Each run asks gcloud for a fresh token,
nothing is copied into the profile, and the project and region default to
the configuration's own.

User credentials can also create projects without an organization or
folder, which service accounts can't
([#2616](https://github.com/alchemy-run/alchemy/pull/2616)):

```typescript
const project = yield* GCP.ResourceManager.Project("Sandbox", { displayName: "Sandbox" });
project.parent; // undefined: a standalone project
```

Thanks [Johannes Schickling](https://github.com/schickling)!

Docs: [GCP credentials](/gcp/setup#credentials).

## Lambda aliases, streaming and partial batch failures

`alias` publishes a version on each deploy and routes every event source,
URL and integration through it, so a rollback is one `update-alias` call
([#2504](https://github.com/alchemy-run/alchemy/pull/2504)). Durable
workflows start their runs on the alias too
([#2528](https://github.com/alchemy-run/alchemy/pull/2528)):

```typescript
export default class Api extends AWS.Lambda.Function<Api>()(
  "Api",
  { main: import.meta.url, alias: "live", functionUrl: true },
  Effect.gen(function* () {
    yield* AWS.SQS.consumeQueueMessages(jobs, processJob); // mapping → api:live
    return { fetch: handleHttp };                          // URL on qualifier "live"
  }),
) {}
```

A `RESPONSE_STREAM` Function URL now streams an Effect response body
instead of buffering it ([#2502](https://github.com/alchemy-run/alchemy/pull/2502)):

```typescript
export default class Events extends AWS.Lambda.Function<Events>()(
  "Events",
  { main: import.meta.url, functionUrl: { invokeMode: "RESPONSE_STREAM" } },
  Effect.succeed({
    fetch: Effect.succeed(
      HttpServerResponse.stream(
        Stream.make("data: one\n\n", "data: two\n\n").pipe(Stream.encodeText),
        { contentType: "text/event-stream" },
      ),
    ),
  }),
) {}
```

SQS, Kinesis and DynamoDB Streams handlers can return Lambda's batch
response, so only failed records are retried
([#2508](https://github.com/alchemy-run/alchemy/pull/2508)):

```typescript
yield* AWS.SQS.consumeQueueMessages(
  queue,
  Effect.fn(function* (event) {
    const failed = yield* Effect.filter(
      event.Records,
      (record) => handle(record.body).pipe(Effect.as(false), Effect.catchCause(() => Effect.succeed(true))),
    );
    return { batchItemFailures: failed.map((record) => ({ itemIdentifier: record.messageId })) };
  }),
);
```

A handler that runs past its `timeout` is now interrupted, so finalizers run
and telemetry flushes before Lambda kills the sandbox
([#2682](https://github.com/alchemy-run/alchemy/pull/2682)):

```typescript
timeout: Duration.seconds(30),      // handler interrupted at 30 s
timeoutMargin: Duration.seconds(2), // Lambda configured for 32 s (default margin: 1 s)
```

An event source mapping also follows its source when the source is
replaced, for example a queue switched to FIFO
([#2535](https://github.com/alchemy-run/alchemy/pull/2535)). Thanks
[Jason Hassold](https://github.com/JasonHassold)!

Docs: [Lambda](/aws/compute/lambda).

## Cloud Run sidecars with typed RPC

`GCP.Run.Container` runs your own Effect program, or any image, as a sidecar
of a Cloud Run service. `bindContainer` adds it to the revision, orders
startup with `dependsOn`, and hands back a typed client over `localhost`
([#2652](https://github.com/alchemy-run/alchemy/pull/2652)):

```typescript
export class Worker extends GCP.Run.Container<Worker>()(
  "Worker",
  { main: import.meta.url, port: 3000, startupProbe: { httpGet: { path: "/health" } } },
  Effect.gen(function* () {
    return {
      greet: (name: string) => Effect.succeed(`hello ${name}`),
      fetch: Effect.succeed(HttpServerResponse.text("ok")),
    };
  }),
) {}

export default class Api extends GCP.Run.Service<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const worker = yield* GCP.Run.bindContainer(Worker);
    return { fetch: worker.greet("sam").pipe(Effect.map(HttpServerResponse.text)) };
  }),
) {}
```

`InvokeService` calls the methods of a private service, signed with the
caller's ID token ([#2653](https://github.com/alchemy-run/alchemy/pull/2653)).
Pass an Effect RPC `schema` or an HttpApi `api` to either binding for a fully
typed client ([#2654](https://github.com/alchemy-run/alchemy/pull/2654)):

```typescript
const tasks = yield* GCP.Run.InvokeService(TaskBackend, { schema: TaskRpcs });
const task = yield* tasks.getTask({ id: "t1" }); // Effect<Task, TaskNotFound | …>
```

Service containers also take `startupProbe`, `livenessProbe` and `dependsOn`
([#2644](https://github.com/alchemy-run/alchemy/pull/2644)), and an image
service can list `GCP.Run.Container`s in its template
([#2657](https://github.com/alchemy-run/alchemy/pull/2657)).

Docs: [Sidecars](/gcp/compute/sidecars) · [Cloud Run](/gcp/compute/cloud-run).

## Pub/Sub straight into BigQuery

`GCP.PubSub.Subscription` takes `bigqueryConfig`, so Pub/Sub writes each
message as a row in a BigQuery table with no consumer code in between
([#2213](https://github.com/alchemy-run/alchemy/pull/2213)). The subscription
creates its own writer service account and grants it access to the table:

```typescript
const subscription = yield* GCP.PubSub.Subscription("ImpressionsToBigQuery", {
  topic: topic.name,
  bigqueryConfig: { table: table.name, writeMetadata: true },
});
subscription.bigqueryConfig?.serviceAccountEmail; // the writer Pub/Sub runs as
```

Pass `serviceAccountEmail` to write as an account you declare, one another
stack owns, or one Alchemy doesn't manage. Alchemy grants it what it needs
and revokes only the grants it added. Thanks
[Lucas Duailibe](https://github.com/duailibe)!

## Migrations and private networking on GCP databases

Cloud SQL, AlloyDB and Spanner apply `migrations` on deploy, like D1, Neon,
PlanetScale, Turso, RDS and DSQL
([#2651](https://github.com/alchemy-run/alchemy/pull/2651)):

```typescript
const db = yield* GCP.SQL.Database("App", {
  instance: instance.instanceName,
  migrations: "./migrations",
  migrationsUser: user.userName,
  migrationsPassword: password.text,
});
```

Cloud SQL runs them over the data API by default, which needs no network
route, or over the Cloud SQL connector. Spanner resumes a failed migration
at the statement that failed.

`GCP.SQL.Instance` can be private-IP only, with SSL mode, backup retention
and disk auto-resize in the stack
([#2642](https://github.com/alchemy-run/alchemy/pull/2642)):

```typescript
const db = yield* GCP.SQL.Instance("Control", {
  databaseVersion: "POSTGRES_17",
  tier: "db-custom-2-8192",
  ipConfiguration: { ipv4Enabled: false, privateNetwork: psa.network, sslMode: "ENCRYPTED_ONLY" },
  backup: { enabled: true, retainedBackups: 14, transactionLogRetentionDays: 7 },
  storageAutoResize: true,
});
db.privateIpAddress;
```

A D1 batch whose reply was lost is no longer sent twice: the engine checks
the migration ledger first ([#2720](https://github.com/alchemy-run/alchemy/pull/2720)).
Thanks [Ahmed Hesham](https://github.com/ahmedhesham6)!

Docs: [Cloud SQL](/gcp/data/cloud-sql).

## Serve a Domain Api over HTTP, MCP and the terminal

`Domain.Api` names its model and what of it a client may reach. A kind you
leave out is served whole, and every aggregate that declares `read` is
served by default
([#2820](https://github.com/alchemy-run/alchemy/pull/2820),
[#2865](https://github.com/alchemy-run/alchemy/pull/2865)):

```typescript
export class AgentApi extends Domain.Api("AgentApi", {
  model: Bank,
  commands: ["DepositMoney", "RequestTransfer"],
  views: ["AccountSummary"],
  streams: [],
}) {}
```

The same Api now reaches clients that aren't Effect. `toHttpApi` publishes it
as a JSON HTTP API with OpenAPI, live reads as Server-Sent Events
([#2587](https://github.com/alchemy-run/alchemy/pull/2587)):


## Show a command's outcome before the server answers

`Aggregate.predict` runs an aggregate's own `decide` and `evolve` on the
client, so a UI can show the outcome at once. It returns the same events and
state as the server, or the same rejection instance
([#2568](https://github.com/alchemy-run/alchemy/pull/2568)):

```typescript
const outcome = Account.predict(state, new Deposit({ amount: 30 }), { id: "a-1", now, version: 3 });

switch (outcome._tag) {
  case "Accepted":      // outcome.events, outcome.envelopes, outcome.state
  case "Rejected":      // outcome.rejection, the same instance the server returns
  case "Unpredictable": // only the server can tell; outcome.cause says why
}
```

`View.evolve` folds those events into a view's state the way the server's
view will. Then `snapshot` gives a view's state with the cursor it is valid
at, so a page renders at first paint and follows the view live with no gap
and no duplicate
([#2567](https://github.com/alchemy-run/alchemy/pull/2567),
[#2579](https://github.com/alchemy-run/alchemy/pull/2579)):

```typescript
const { state, cursor } = yield* api.Totals.snapshot("c-1", {
  atLeast: { stream: receipt.stream, version: receipt.version },
});
render(state);

yield* api.Totals.events("c-1", { after: cursor }).pipe(
  Stream.runForEach((frame) => (Domain.Read.isCaughtUp(frame) ? markLive(frame.cursor) : apply(frame))),
);
```

A read with `atLeast` that the view hasn't reached within 10 seconds fails
with a typed `ConsistencyTimeout` instead of dying.

[Render a snapshot, then follow it](/domain/view#render-a-snapshot-then-follow-it).

## More of the model in Domain

A view, projection, stream or policy can be keyed by a Schema value instead
of an aggregate, so an org-wide read model needs no empty `Org` aggregate
([#2554](https://github.com/alchemy-run/alchemy/pull/2554)):

```typescript
export const OrgId = Schema.String.pipe(Schema.brand("OrgId"));

export class OrgSchedule extends Domain.View("OrgSchedule", {
  from: [Tour],
  key: OrgId,
  keyOf: { Tour: ({ event }) => event.orgId },
  state: Schema.Struct({ tours: Schema.Record(Schema.String, Schema.String) }),
  initial: { tours: {} },
  evolve: { TourBooked: (s, e, { source }) => ({ tours: { ...s.tours, [source.id]: e.unit } }) },
}) {}
```

A scheduled command can be cancelled by its id, and both sides say why when
there's nothing to do ([#2547](https://github.com/alchemy-run/alchemy/pull/2547)):

```typescript
yield* holds.schedule(source, new ExpireHold(), { after: "1 hour", commandId: `expire:${source.id}` });

yield* holds.unschedule(source, `expire:${source.id}`).pipe(
  Effect.catchTag("AlreadyExecuted", () => holds.send(source, new ReopenHold())),
  Effect.catchTag("AlreadyCancelled", () => Effect.void),
);
```

Every call through an external system adapter is checked against its
schemas, so a vendor response mapped wrong stops at the edge
([#2548](https://github.com/alchemy-run/alchemy/pull/2548)). An operation
can declare several errors
([#2553](https://github.com/alchemy-run/alchemy/pull/2553)):

```typescript
class Keypad extends Domain.ExternalSystem("Keypad", {
  setCode: { args: { code: Schema.String }, success: { codeId: Schema.String }, error: [LockOffline, CodeTaken] },
}) {}
// ExternalSystemSchemaError: Keypad.setCode returned a value its success schema rejects
```

`Domain.Rejection` is a `Schema.TaggedError` and takes its annotations, such
as `httpApiStatus`, and `rejects` takes any tagged error
([#2780](https://github.com/alchemy-run/alchemy/pull/2780)). `decide` sees
the command's id, stream and version
([#2575](https://github.com/alchemy-run/alchemy/pull/2575)).

Each `Domain.Model` also owns its data now, so two models that list the same
aggregate get separate instances. Models deployed before this release keep
their data on upgrade ([#2560](https://github.com/alchemy-run/alchemy/pull/2560)).
Definition problems fail the model's Layer with a typed `DefinitionError`,
and `Domain.verify(Model)` lists them without hosting the model
([#2612](https://github.com/alchemy-run/alchemy/pull/2612),
[#2818](https://github.com/alchemy-run/alchemy/pull/2818)).

Docs: [Key a view by a value](/domain/view#key-a-view-by-a-value) ·
[Deadlines](/domain/deadlines) ·
[External systems](/domain/external-system#calls-are-checked-against-the-schemas).

A failed story prints every step and the events committed so far

```text
StoryFailure: Then: on Counter/c-1
  ✓ 1 Clock      2026-03-01T09:00:00.000Z

    5 Replied    { total: 6 }
```

A story fails on any committed event no step asserts, on every stream
([#2551](https://github.com/alchemy-run/alchemy/pull/2551)). Its steps
type-check against the last command
([#2559](https://github.com/alchemy-run/alchemy/pull/2559)):

```typescript
story(Story.when(c1, new Increment({ by: 1 })), Story.rejected(new NotAnOperator()));

//   '"Increment does not reject with NotAnOperator"'.
```

[#2481](https://github.com/alchemy-run/alchemy/pull/2481)):

```typescript
Story.call(LockVendor.deleteCode, { codeId: "pc_1" }),
```

## Backfill views and projections

A view or projection added in a later deploy now receives every event its
sources recorded before it existed, in the order they were recorded. Bump its
version to rebuild it from history
([#2725](https://github.com/alchemy-run/alchemy/pull/2725)):

```typescript
// deploy 2 adds two views; both fold every earlier event, with no script
class Ledger extends Domain.Model("Ledger", { aggregates: [Account], views: [Deposits, Timeline] }) {}

// rebuild a view after its evolve changed
Ledger.layer(LedgerHandlers, { versions: { Deposits: 1 } });
```

```sh
[DomainBackfillRun] Backfilling view:Deposits reading history 41% (1,690/4,096 subtrees, 410,211 instances) (48s) ...
```

A view over 100,000 accounts and a million events rebuilt in 58 seconds.

## Durable workflows wake on time

Wake-ups scheduled from inside a Durable Object alarm inherited its retry
backoff, so workflow sleeps and Domain projection batches ran late, each hop
later than the last ([#2916](https://github.com/alchemy-run/alchemy/pull/2916)):

```typescript
// four one-second sleeps: previously still running after 45s, now ~4s
for (let nap = 0; nap < 4; nap++) {
  yield* DurableClock.sleep({ name: `nap-${nap}`, duration: "1 second", inMemoryThreshold: 0 });
}
```

The fix comes with a conformance suite of 28 cases that every engine runs:
Durable Objects, Cloudflare Workflows and Lambda durable functions, locally
and live. It found 15 bugs, from signals that hung for three minutes to
interrupts that skipped compensations. `Activity.raceAll` now fails at once
on the two engines that can't support it, instead of hanging.

disconnects, so its finalizers run, with the `enable_request_signal` flag

```typescript
export default class Api extends Cloudflare.Worker<Api>()(
```

([#2529](https://github.com/alchemy-run/alchemy/pull/2529)). Together, a

```typescript
yield* Effect.logError("payment declined").pipe(

const cardDeclines = yield* Cloudflare.Alerting.CustomAlert("CardDeclines", {

```

## Cycles and replacements never take over a foreign resource

A resource in a dependency cycle is precreated before `read` can check
ownership. Providers now implement a read-only `observe` hook, and the
engine refuses an existing resource it doesn't own unless you pass
`--adopt` ([#2195](https://github.com/alchemy-run/alchemy/pull/2195),
[#2620](https://github.com/alchemy-run/alchemy/pull/2620)). Replacements are
checked before they touch anything
([#2200](https://github.com/alchemy-run/alchemy/pull/2200)):

```typescript
// another Worker already owns this script name
yield* Cloudflare.Worker("ReplacementTarget", { main, name: owner.workerName });
// before: the deploy overwrote the script
// after:  OwnedBySomeoneElse, and neither Worker changes
```

A cyclic resource can now take its name from outside its cycle
([#2643](https://github.com/alchemy-run/alchemy/pull/2643)), and a ref to a
resource in the same stack is a dependency, so destroy no longer races them
([#2913](https://github.com/alchemy-run/alchemy/pull/2913)):

```typescript
const fn = yield* AWS.Lambda.Function("Fn", {
  main,
  functionName: queue.queueName.pipe(Output.map((name) => `${name}-fn`)),
});
yield* fn.bind`Self`({ env: { SELF_NAME: fn.functionName } });
// before: Cannot coerce Output<Queue.queueName.map(...)> to a string
```

Interrupted creates are recovered without guessing
([#2199](https://github.com/alchemy-run/alchemy/pull/2199),
[#2686](https://github.com/alchemy-run/alchemy/pull/2686),
[#2534](https://github.com/alchemy-run/alchemy/pull/2534)). Thanks
[Nacho Vazquez](https://github.com/NachoVazquez)!

`alchemy destroy` now plans from state without running your stack program,
so a dev stage tears down without cloud credentials
([#2491](https://github.com/alchemy-run/alchemy/pull/2491)):

```sh
alchemy dev --stage dev_sam              # every row "(local)"
alchemy destroy --stage dev_sam --yes    # deletes through the local providers, no AWS credentials needed
```

## Drive deploys from code

`alchemy/Alchemist` is the programmatic API under the CLI. Plan, apply,
drift, nuke, logs and state are each one call
([#2765](https://github.com/alchemy-run/alchemy/pull/2765)):

```typescript
import * as Alchemist from "alchemy/Alchemist";

const program = Effect.gen(function* () {
```

device and poll logins work headless

## New AWS resources and options

`AWS.EventBridge.Endpoint` is a global endpoint with failover between
regions, and `PutEvents` publishes through it with SigV4A
([#2507](https://github.com/alchemy-run/alchemy/pull/2507)):

```typescript
const endpoint = yield* AWS.EventBridge.Endpoint("Orders", {
  eventBuses: [primary.eventBusArn, secondary.eventBusArn],
  failover: { healthCheck: health.healthCheckId, secondaryRegion: "us-east-2" },
  roleArn: replication.roleArn,
});
const putEvents = yield* AWS.EventBridge.PutEvents(endpoint); // inside a Function
```

NAT gateways can be regional
([#2498](https://github.com/alchemy-run/alchemy/pull/2498)), Auto Scaling
groups can launch by instance attributes
([#2817](https://github.com/alchemy-run/alchemy/pull/2817)), and
`RDS.Connect` takes a `DBInstance` and its managed master secret
([#2756](https://github.com/alchemy-run/alchemy/pull/2756)):

```typescript
yield* AWS.EC2.NatGateway("RegionalNat", { availabilityMode: "regional", vpcId: vpc.vpcId });

yield* AWS.AutoScaling.AutoScalingGroup("Fleet", {
  launchTemplate: template,
  subnetIds,
  minSize: 1,
  maxSize: 4,
  instanceRequirements: { VCpuCount: { Min: 2, Max: 2 }, MemoryMiB: { Min: 4096, Max: 8192 } },
});

const connect = yield* AWS.RDS.Connect(instance, { database: "postgres", subnetIds, securityGroupIds });
```

Thanks [Henry Marks](https://github.com/Henrymarks1)!

## New Cloudflare resources and options

Email Routing's subaddressing and subdomains can be declared
([#2762](https://github.com/alchemy-run/alchemy/pull/2762)):

```typescript
const routing = yield* Cloudflare.Email.Routing("Routing", {
  zone: "example.com",
  subaddressing: true, // docs+anything@example.com matches the docs@ rule
});
yield* Cloudflare.Email.RoutingSubdomain("Inbound", { zoneId: routing.zoneId, name: "in.example.com" });
```

Queues take their settings, and a Queue resource can be a
`deadLetterQueue` that you consume
([#2538](https://github.com/alchemy-run/alchemy/pull/2538),
[#2510](https://github.com/alchemy-run/alchemy/pull/2510)):

```typescript
const deadLetters = yield* Cloudflare.Queues.Queue("DeadLetters", { messageRetentionPeriod: 14 * 24 * 60 * 60 });
yield* Cloudflare.Queues.consumeQueueMessages<Order>(Orders, { maxRetries: 3, deadLetterQueue: deadLetters }, handle);
```

Every Access organization setting can be declared, and identity providers
take `Redacted` client secrets
([#2291](https://github.com/alchemy-run/alchemy/pull/2291)):

```typescript
yield* Cloudflare.Access.Organization("Org", {
  authDomain: "acme.cloudflareaccess.com",
  mfaRequiredForAllApps: true,
  mfaConfig: { allowedAuthenticators: ["totp", "security_key"], sessionDuration: "12h" },
  serviceTokenInactivity: { enabled: true, action: "disable", inactivityThresholdDays: 90 },
});
```

The Artifacts binding reads a repo's history and files
([#1916](https://github.com/alchemy-run/alchemy/pull/1916)):

```typescript
const repo = yield* (yield* Cloudflare.Artifacts.ReadNamespace(Repos)).get("book");
const [head] = yield* repo.log({ ref: "main", limit: 10 });
const file = yield* repo.readFile({ ref: "main", path: "workbook.json" });
```

Thanks [Leonardo E. Dominguez](https://github.com/focux),
[Dillion Verma](https://github.com/dillionverma) and
[Matthew Aylward](https://github.com/Butch78)!

## `@alchemy.run/test` on npm

The test harness is published as `@alchemy.run/test`, and it holds
`Test.make` for alchemy-test, Bun and Vitest
([#2452](https://github.com/alchemy-run/alchemy/pull/2452),
[#2621](https://github.com/alchemy-run/alchemy/pull/2621)):

```sh
bun add -d @alchemy.run/test
bunx alchemy-test --stage test_sam_feat-x
```

`--stage` gives each git worktree its own stage, so parallel agents never
share cloud resources ([#2613](https://github.com/alchemy-run/alchemy/pull/2613)).
A test file can deploy and destroy a stack on a bucket-backed state store
without holding its lease ([#2494](https://github.com/alchemy-run/alchemy/pull/2494)).

Docs: [Test harness](/testing/test-harness) · [Worktrees](/environments/worktrees).
