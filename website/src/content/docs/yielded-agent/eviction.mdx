---
title: Surviving eviction
description: A Durable Object can be evicted or redeployed at any time. Thread history is kept in its SQLite, and a submitted run is started again from the object's alarm.
---

Cloudflare can stop a Durable Object instance at any time: when it has been idle, on a deploy, or when it moves the object. What is in memory is lost. What the object wrote to its storage is kept, and its alarm still fires.

## History is kept

`YieldedCloudflare.DurableObjectHistory` commits each successful Run to the object's SQLite. A new instance reads the Thread from there, so the next run continues the conversation.

## A run that is cut off

`harness.run` runs inside the request that called it. If the instance stops while it is running, the request fails and the Thread is left as it was before the run.

## Submit a run instead

`harness.submit` records the run in the object's storage, arms the object's alarm, and returns. The run happens in the background:

```typescript title="src/Threads.ts"
const harness = yield* YieldedAgent.Harness({
  models: [Fast],
  tools: [LookupOrder],
  agents: [Support],
});

return Effect.gen(function* () {
  return {
    ask: Effect.fn(function* (thread: string, text: string, requestId: string) {
      yield* harness.submit(Support, text, { thread, requestId });
    }, Effect.orDie),
    answer: Effect.fn(function* (requestId: string) {
      return yield* harness.submitted(Support, requestId);
    }, Effect.orDie),
  };
});
```

List the agent in `agents`: the instance that finishes a run may not be the one that accepted it, and it finds the agent there by its id.

`harness.submitted` returns `{ status: "running" }`, `{ status: "done", output }` or `{ status: "failed", message }`, and `undefined` for an id nothing was submitted under.

## What happens after a stop

If the instance stops before a submitted run ends, the alarm wakes a new instance, which starts the run again from the beginning on the Thread as it was last committed.

A tool that was running when the instance stopped is called again, so a tool that writes somewhere must be safe to repeat. A run that does not finish in three starts is recorded as failed.

## The same request twice

`requestId` identifies a submitted run. Submitting it again does not start a second run, so a caller that retries after a timeout is safe.

Yielded Agent also ships its own durable host for Cloudflare, which resumes a run where it stopped instead of starting it again. That host is its own Durable Object class and does not run inside an Alchemy Durable Object.
