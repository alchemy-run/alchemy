## Build the service URL

Inside the cluster, a Service is reachable at
`<service>.<namespace>.svc.cluster.local`. Build that URL from the
Deployment's attributes:

```diff lang="typescript"
import * as Alchemy from "alchemy";
import * as Kubernetes from "alchemy/Kubernetes";
+import * as Output from "alchemy/Output";
import * as Effect from "effect/Effect";
```

```diff lang="typescript"
const web = yield* Kubernetes.Deployment("Web", {
  // ...
});

+const webUrl = Output.interpolate`http://${web.serviceName}.${web.namespace}.svc.cluster.local:${web.port}`;
```

`Output.interpolate` builds a string from Outputs. Anything that uses
`webUrl` depends on the Deployment.

## Add a smoke test Job

A [`Kubernetes.Job`](/kubernetes/workloads/jobs) runs a container
until it exits. This one uses the `curl` image to request the
service and fails if it doesn't answer:

```diff lang="typescript"
const webUrl = Output.interpolate`http://${web.serviceName}.${web.namespace}.svc.cluster.local:${web.port}`;

+const smokeTest = yield* Kubernetes.Job("SmokeTest", {
+  cluster,
+  name: "smoke-test",
+  namespace: namespace.name,
+  image: "curlimages/curl:8.16.0",
+  args: ["--fail", "--silent", "--retry", "5", "--retry-all-errors", webUrl],
+  backoffLimit: 2,
+});
```

`args` are the container's arguments (the image's entrypoint is
`curl`). `backoffLimit` is how many times Kubernetes retries a failed
pod before marking the Job failed.

## Clean up finished Jobs

A finished Job stays in the cluster until something deletes it. Let
Kubernetes garbage-collect it ten minutes after it completes:

```diff lang="typescript"
  backoffLimit: 2,
+  ttlSecondsAfterFinished: 600,
});
```

Alchemy tracks the Job through its ServiceAccount, so a
garbage-collected Job doesn't look deleted and isn't re-run on the
next deploy.

## Return the Job name

```diff lang="typescript"
return {
+  smokeTest: smokeTest.jobName,
  namespace: web.namespace,
  service: web.serviceName,
};
```

## Why the name has a suffix

The Job is named `smoke-test-5133e709`, not `smoke-test`. Kubernetes
doesn't allow a Job's pod template to change after the Job is
created, so Alchemy names each Job after a hash of its spec. Change
the spec and you get a new Job; leave it alone and nothing re-runs.

Add `--show-error` to the arguments and deploy:

```diff lang="typescript"
-    args: ["--fail", "--silent", "--retry", "5", "--retry-all-errors", webUrl],
+    args: ["--fail", "--silent", "--show-error", "--retry", "5", "--retry-all-errors", webUrl],
```

## Run it on a schedule

Add a second Job that checks podinfo's health endpoint every five
minutes:

```diff lang="typescript"
+  const ping = yield* Kubernetes.Job("Ping", {
+    cluster,
+    name: "ping",
+    namespace: namespace.name,
+    image: "curlimages/curl:8.16.0",
+    args: ["--fail", "--silent", Output.interpolate`${webUrl}/healthz`],
+    schedule: "*/5 * * * *",
+  });
```

Setting `schedule` (a standard five-field cron expression) makes
Alchemy create a Kubernetes `CronJob` instead of a `Job`. A CronJob's
spec can change in place, so it keeps the plain name `ping`.

Deploy, then list both:

```sh
kubectl -n my-app get jobs,cronjobs
```

```text
NAME                            STATUS     COMPLETIONS   DURATION   AGE
job.batch/smoke-test-80469dd3   Complete   1/1           4s         2m

NAME                 SCHEDULE      TIMEZONE   SUSPEND   ACTIVE   LAST SCHEDULE   AGE
cronjob.batch/ping   */5 * * * *   <none>     False     0        <none>          5s
```

## Recap

You now have:

- A smoke-test Job that runs whenever its spec changes, built from
  the Deployment's attributes
- A content-addressed Job name, so changes re-run and no-op deploys
  don't
- A CronJob hitting the health endpoint every five minutes
