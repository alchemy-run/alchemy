Read env vars with [effect/Config](https://effect.website/docs/configuration)
in a [runtime](/infrastructure-as-effects/runtime), and Alchemy binds
them onto the deployed Worker or Lambda. Values come from the env of
whoever runs the deploy, so they vary per [stage](/environments/stages)
and [profile](/environments/profiles).

By default the values come from `.env` and the shell. To read them from
[Doppler](/environments/doppler), [Infisical](/environments/infisical),
or several sources in order, see [Secret providers](/environments/secret-providers).

## Bind a secret to your Worker

`yield*` a `Config` in the [Construction phase](/infrastructure-as-effects/phases)
of a Worker, and Alchemy binds it to the Worker's environment at deploy
time. The value is available right away, so you can use it to build a
client before any request arrives.

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import * as Config from "effect/Config";
import * as Effect from "effect/Effect";
import * as Redacted from "effect/Redacted";

export default Cloudflare.Worker(
  "Worker",
  { main: import.meta.url },
  Effect.gen(function* () {
    // Redacted<string>, usable now and bound as a secret for runtime
    const apiKey = yield* Config.Redacted("OPENAI_API_KEY");
    const client = createOpenAI(Redacted.value(apiKey));

    return {
      fetch: Effect.gen(function* () {
        const reply = yield* Effect.tryPromise(() => client.chat(/* ... */));
        return new Response(reply);
      }),
    };
  }),
);
```

Every value is bound as a secret (`secret_text` on Cloudflare),
whichever `Config` constructor you use. Unlike an
[Output](/infrastructure-as-code/outputs), a `Config` value needs no
deploy to resolve.

## Resolve Config during Construction

Alchemy only binds a `Config` that you `yield*` during Construction.
`fetch` does not run during deployment, so a `Config` read only there is
never bound and is missing at runtime.

```typescript
Effect.gen(function* () {
  // ✅ bound in Construction, used in Runtime
  const apiKey = yield* Config.Redacted("API_KEY");

  return {
    fetch: Effect.gen(function* () {
      // 🚫 not bound. This key won't exist at runtime.
      const other = yield* Config.Redacted("OTHER_KEY");
      return new Response(Redacted.value(apiKey));
    }),
  };
});
```

After Construction resolves a `Config`, you can `yield*` the same
`Config` again anywhere at runtime, such as in `fetch`, a nested
effect, or a service layer. It reads from the binding and returns the
same value. See [Phases](/infrastructure-as-effects/phases) for why
Construction and Runtime run separately.

## Bind Config on an async Worker

An async (non-Effect) Worker has no constructor to `yield*` in. Put
each `Config` on the resource's `env` prop, and Alchemy resolves it at
deploy time and records the same binding.

```typescript
// alchemy.run.ts
import * as Cloudflare from "alchemy/Cloudflare";
import * as Config from "effect/Config";

export const Worker = Cloudflare.Worker("Worker", {
  main: "./src/worker.ts",
  env: {
    API_KEY: Config.Redacted("API_KEY"),
    HOST: Config.String("HOST"),
    Bucket, // resource references work the same
  },
});

export type WorkerEnv = Cloudflare.InferEnv<typeof Worker>;
```

```typescript
// src/worker.ts
import type { WorkerEnv } from "../alchemy.run.ts";

export default {
  async fetch(request: Request, env: WorkerEnv) {
    // a plain string: no Redacted.value needed
    return new Response(`Bearer ${env.API_KEY}`);
  },
};
```

Cloudflare passes the `secret_text` value to the async handler directly.
Values still bind as secrets, and the rules for defaults below still
apply.

## Defaults and transformations

Any combinator works, including `withDefault`, `orElse`, and
`mapEffect`. Alchemy binds the raw source value, and the combinators
run again at runtime against that source.

```typescript
const port = yield* Config.Number("PORT").pipe(
  Config.withDefault(3000), // never bound, so it runs in both phases
);
```

- If `PORT` is set, Alchemy binds its raw value. At runtime
  `Config.Number("PORT")` reads the binding and the combinators apply
  again.
- If `PORT` is not set, nothing is bound. At runtime the source is still
  empty, and `Config.withDefault(3000)` produces `3000` again.

Keep defaults deterministic so both phases get the same value. A
`Config` with no value and no default fails the deploy with a
`ConfigError`, so use `Config.withDefault` or `Config.option` for values
that may be absent.
