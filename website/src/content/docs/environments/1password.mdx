title: 1Password
description: Read 1Password Environments and op:// vault references into Effect Config using desktop authorization or a service account token.
---

`OnePassword.Secrets` reads a complete [1Password Environment](https://www.1password.dev/sdks/environments)
through the official `@1password/sdk` and adds its variables to your stack's
[secret providers](/environments/secret-providers). It does not modify
`process.env` or write downloaded values to disk.

```sh
pnpm add @alchemy.run/1password
```

## Select an Environment

Copy the Environment ID from the 1Password desktop app under **Developer >
View Environments > View environment > Manage environment > Copy environment ID**.

```typescript
import * as Alchemy from "alchemy";
import * as OnePassword from "@alchemy.run/1password";
import * as Config from "effect/Config";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";

export default Alchemy.Stack(
  "MyApp",
  {
    providers: Layer.empty,
    state: Alchemy.localState(),
    secrets: [
      OnePassword.Secrets(({ stage }) => ({
        environmentId: stage === "prod" ? "production-id" : "development-id",
      })),
    ],
  },
  Effect.gen(function* () {
    const databaseUrl = yield* Config.Redacted("DATABASE_URL");
    // Use databaseUrl to configure your resources.
    return {};
  }),
);
```

Plain `{ environmentId, account? }` options work too. Empty values are preserved;
variables marked unmasked in 1Password are also included. Use `Config.Redacted`
for sensitive values. Later providers override earlier ones, and the stack's
implicit `Secrets.ProcessEnv()` retains its usual precedence.

## Resolve vault references

Use `references` to map config keys to fields in vault items instead of loading
an Environment. Both authentication methods and stage-dependent callbacks work
in this mode too.

```typescript
OnePassword.Secrets(({ stage }) => ({
  references: {
    DATABASE_URL: `op://${stage === "prod" ? "Production" : "Development"}/Database/url`,
    API_KEY: "op://Shared/API/credentials/key",
  },
}));
```

Read these with `Config.Redacted("DATABASE_URL")` or `Config.Redacted("API_KEY")`.
Specify exactly one of `environmentId` and `references` in each entry. To use
both, add two entries to the stack's `secrets` array. Empty maps and blank config
keys are rejected.

The exported Effect schemas `OnePassword.SecretReference` and
`OnePassword.OnePasswordOptionsSchema` enforce the syntax at runtime, including
options returned by stage callbacks, before authentication. You can also use
the reference schema independently:

```typescript
import * as Schema from "effect/Schema";

const reference = Schema.decodeUnknownSync(OnePassword.SecretReference)(
  "op://Production/Database/url",
);
```

References must use `op://vault/item/[section/]field`. Each segment must be
non-blank and contain only ASCII letters, digits, spaces, hyphens, underscores,
or periods. Use 1Password IDs for names with unsupported characters; do not
URL-encode them. The SDK query forms `?attribute=otp` and `?ssh-format=openssh`
are supported; arbitrary CLI query options are not. Validation checks syntax,
not existence or access. See [1Password's reference syntax](https://www.1password.dev/cli/secret-reference-syntax)
and [SDK reference support](https://www.1password.dev/sdks/load-secrets).

Duplicate references are deduplicated and passed to one SDK `resolveAll` call
per initialization. This does not guarantee a single underlying API request
or quota unit. Missing or failed individual results reject the entire load
with `OnePasswordReferenceError`; partial config is never installed. Errors
identify the config key without retaining the reference URI or raw SDK error.

Values containing `op://` inside an Environment are returned literally, not
recursively resolved. OTP values are snapshots at initialization and are not
refreshed on subsequent config reads.

## Authorize with the desktop app

Unlock 1Password and enable **Settings > Developer > Integrate with the
1Password SDKs > Integrate with other apps**. Select your account through an
Alchemy profile:

```sh
alchemy profile edit --add 1Password
```

Or configure the selector non-interactively:

```sh
alchemy profile edit --add 1Password --method desktop --set account="My Account"
```

The profile stores only the account name or UUID. 1Password displays its own
authorization prompt when the stack loads secrets; Alchemy does not store a
desktop session token. Removing the profile entry removes the selector, not
the desktop app's authorization; lock 1Password to end its active session.

Alternatively, pass `account: "My Account"` in `OnePassword.Secrets`. Use the
account name displayed in the app sidebar or the account UUID, not a sign-in
URL. Explicit `account` wins over the profile. `OP_SERVICE_ACCOUNT_TOKEN`, when
set, wins over all desktop selectors. A rejected token never falls back to
desktop authentication.

## In CI

Profiles are never consulted in CI; the environment decides. Set a service
account token in `OP_SERVICE_ACCOUNT_TOKEN` and grant that service account
read access to the selected Environment or referenced vaults:

```yaml
- run: bun alchemy deploy --stage prod --yes
  env:
    OP_SERVICE_ACCOUNT_TOKEN: ${{ secrets.OP_SERVICE_ACCOUNT_TOKEN }}
```

`OP_SERVICE_ACCOUNT_TOKEN` wins over all desktop account selectors and the
profile. Desktop authorization is not used when `CI=true`.
`alchemy provider check-env` lists the authentication variables.

Authentication variables are read from the process environment, independently
of the stack's secret-provider ordering. A preceding dotenv or remote secrets
provider cannot supply or override the 1Password credentials.

## Handle rate limits

1Password service accounts have both hourly limits and account-wide daily
limits. Alchemy maps the SDK's `RateLimitExceededError` during authentication
or Environment/reference reads to `OnePasswordRateLimitError`. It fails immediately
without an automatic retry or an authentication fallback. The SDK does not
expose a structured retry-after duration, so Alchemy does not guess when a
quota will reset.

Check the token's usage with the optional 1Password CLI:

```sh
op service-account ratelimit
```

Wait for the relevant quota window to reset and reduce concurrent CI jobs or
repeated deployments. Daily limits are shared across service accounts in an
account. See [1Password's rate-limit guide](https://www.1password.dev/service-accounts/rate-limits).

One Environment read populates the in-memory config for each secrets-layer
initialization. Reading additional config keys does not make additional SDK
calls. A new stack evaluation fetches fresh values; there is no persistent
cache that could hide rotations or share secrets between stages.

## Troubleshoot

An expired service-account token produces an authentication error with a token
replacement hint. An expired desktop session asks you to unlock and authorize
again. Other failures identify the Environment and whether initialization,
authentication, or reading failed, without printing raw SDK errors or values.

SDK initialization and Environment/reference reads each time out after 30 seconds.
Desktop authentication allows 60 seconds for approval; service-account
authentication allows 30 seconds. The SDK exposes no cancellation API, so a
timeout stops waiting but cannot cancel an SDK request already in progress.
Auth-provider discovery does not load the SDK, contact 1Password, or prompt.

The SDK is a deployment-time dependency. It is not intended to run in a
Cloudflare Worker or in your deployed application's config-loading path.
