Let users connect your provider's account with `alchemy profile edit`
instead of an env var. This guide starts from the Stripe provider in
[Custom Provider](/infrastructure-as-code/custom-provider), whose
[`StripeCredentials`](/infrastructure-as-code/custom-provider#credentials)
service reads `STRIPE_API_KEY` through `fromEnv()`. You replace that
layer with one backed by an [auth provider](/environments/auth-providers).

For a token-shaped credential, `makeStoredAuthProvider` generates the
whole auth provider from a field list. The in-repo
[Neon provider](https://github.com/alchemy-run/alchemy/blob/main/packages/alchemy/src/Neon/AuthProvider.ts)
has this shape.

:::note
Alchemy already ships `alchemy/Stripe` with a `Stripe` auth provider,
and this guide rebuilds it as an example. The registry is keyed by
name, and a second registration overwrites the first, so a real
integration needs a name no built-in provider uses.
:::

## Generate the auth provider

`makeStoredAuthProvider` builds interactive prompts, flag-driven setup
(`--method stored --set apiKey=...`), and the `details` that
`alchemy profile show` renders. It stores the values in
`~/.alchemy/profiles/{profile}/stripe.json`.

```typescript
// src/stripe/AuthProvider.ts
import { AuthError } from "alchemy/Auth/AuthProvider";
import {
  makeStoredAuthProvider,
  storedSecret,
} from "alchemy/Auth/StoredAuthProvider";
import { getEnvRedactedRequired } from "alchemy/Auth/Env";
import * as Effect from "effect/Effect";
import * as Redacted from "effect/Redacted";

export const STRIPE_AUTH_PROVIDER_NAME = "Stripe";

export type StripeResolvedCredentials = {
  type: "apiKey";
  apiKey: Redacted.Redacted<string>;
  source: { type: "stored" | "env" };
};

export const { layer: StripeAuth, storedSchema: StripeStoredCredentials } =
  makeStoredAuthProvider<StripeResolvedCredentials>({
    provider: STRIPE_AUTH_PROVIDER_NAME,
    // One prompt and one --set key per field, stored under the same name
    // next to method: "stored". validate applies to both paths.
    fields: [
      {
        name: "apiKey",
        label: "Stripe Secret API Key",
        secret: true,
        validate: (value) =>
          value.startsWith("sk_") ? undefined : "Expected an sk_... key",
      },
    ],
    toResolved: (values, source) => ({
      type: "apiKey",
      // storedSecret wraps a string in Redacted, and passes Redacted through
      apiKey: storedSecret(values.apiKey) ?? Redacted.make(""),
      source: { type: source },
    }),
    // CI credentials, used instead of the profile
    readEnvironment: getEnvRedactedRequired("STRIPE_API_KEY").pipe(
      Effect.map((apiKey) => ({
        type: "apiKey" as const,
        apiKey,
        source: { type: "env" as const },
      })),
    ),
    // Every variable readEnvironment consumes. Required when it is set.
    environment: [
      {
        name: "STRIPE_API_KEY",
        required: true,
        secret: true,
        description: "Stripe secret API key.",
      },
    ],
  });
```

The generated `storedSchema` validates every credential read and write.
An invalid or incomplete stored entry fails with an `AuthError` that
tells you to run `alchemy profile edit --profile <profile> --reconfigure Stripe`.
Registration fails if a provider sets `readEnvironment` without an
`environment` declaration.

## Bridge the auth provider to the credentials service

`resolveProviderConfig` looks up the registered provider and returns its
credentials as a lazy Effect. Provide that Effect as `StripeCredentials`,
next to the `fromEnv()` layer from Custom Provider:

```typescript
// src/stripe/Credentials.ts (additions)
import { resolveProviderConfig } from "alchemy/Auth";
import type { StoredAuthConfig } from "alchemy/Auth/StoredAuthProvider";
import {
  STRIPE_AUTH_PROVIDER_NAME,
  type StripeResolvedCredentials,
} from "./AuthProvider.ts";

export const fromAuthProvider = () =>
  Layer.effect(
    StripeCredentials,
    Effect.gen(function* () {
      const { resolve } = yield* resolveProviderConfig<
        StoredAuthConfig,
        StripeResolvedCredentials
      >(STRIPE_AUTH_PROVIDER_NAME);

      // Return the Effect, not its result. Nothing resolves until a handler runs it.
      return yield* resolve.pipe(
        Effect.map((creds) => ({ apiKey: creds.apiKey })),
        Effect.orDie,
        Effect.cached, // read and its file lock run at most once per process
      );
    }),
  );
```

`resolve` reads `STRIPE_API_KEY` in CI or whenever it is set, and the
selected profile otherwise, as described in
[Auth Providers › Where credentials come from](/environments/auth-providers#where-credentials-come-from).
It never prompts. An unconfigured provider fails with the
`alchemy profile edit --profile <profile> --add Stripe` command, and a
missing explicit profile fails with a command to create it.

For credentials that expire, use `cacheUntilExpiry` from
`alchemy/Auth/CredentialsCache` in place of `Effect.cached`. A long dev
session then re-resolves instead of keeping a dead token.

## Bundle into `providers()`

Swap `fromEnv()` for the auth provider in the `providers()` layer. This
mirrors [`Neon/Providers.ts`](https://github.com/alchemy-run/alchemy/blob/main/packages/alchemy/src/Neon/Providers.ts):

```diff lang="typescript"
 // src/stripe/Providers.ts
+import { CredentialsStoreLive } from "alchemy/Auth/Credentials";
+import { ProfileStoreLive } from "alchemy/Auth/Profile";
 import * as Provider from "alchemy/Provider";
 import * as Layer from "effect/Layer";
+import { StripeAuth } from "./AuthProvider.ts";
 import * as Credentials from "./Credentials.ts";
 import { StripeProduct, StripeProductProvider } from "./Product.ts";

 // ... Providers class unchanged

 export const providers = () =>
   Layer.effect(Providers, Provider.collection([StripeProduct])).pipe(
     Layer.provide(StripeProductProvider()),
-    Layer.provideMerge(Credentials.fromEnv()),
+    Layer.provideMerge(Credentials.fromAuthProvider()),
+    Layer.provideMerge(StripeAuth),           // registers "Stripe" with the CLI
+    Layer.provideMerge(ProfileStoreLive),     // file-system services for profiles
+    Layer.provideMerge(CredentialsStoreLive),
+    Layer.orDie,
   );
```

Providers that call APIs through an Effect `HttpClient` also merge
`FetchHttpClient.layer` here, as Neon does. The handlers already
double-yield `StripeCredentials`, so they need no change.

Profile commands always include Alchemy's built-in providers. They find
yours by importing `alchemy.run.ts` when it exists, or the entrypoint
passed with `--config <path>`. A missing `alchemy.run.ts` is ignored,
but an error in an existing or explicit entrypoint fails the command.

## Try it

```sh
alchemy profile edit --add Stripe            # connect the account once
alchemy deploy
alchemy profile refresh --provider Stripe    # re-authenticate without changing the method
alchemy profile edit --reconfigure Stripe    # replace the stored credentials interactively

# non-interactive (agents, scripts): value from env, stdin, or a literal
alchemy profile edit --add Stripe --method stored --set apiKey=env:STRIPE_API_KEY
op read op://vault/stripe/key | alchemy profile edit --add Stripe --method stored --set apiKey=-

alchemy profile show                           # renders your provider's details
alchemy provider check-env --provider stripe   # CI preflight for STRIPE_API_KEY
```

In CI, a pipeline only needs `STRIPE_API_KEY` set, and no profile file
is created.
