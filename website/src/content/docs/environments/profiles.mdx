A **profile** is a named bundle of provider authentication settings.
The non-secret manifest lives in `~/.alchemy/profiles.json`; secret
material lives separately under `~/.alchemy/credentials/<profile>/`.
Profiles let you:

- Keep work and personal accounts separate
- Use a different IAM role for `prod` vs `dev`
- Rotate or refresh tokens without losing other configurations

Profiles are independent from [Stages](/environments/stages). A stage
controls **what** is deployed; a profile controls **how alchemy
authenticates** to deploy it.

## Profile selection

Alchemy selects a profile in this order:

1. The command's `--profile <name>` option
2. `$ALCHEMY_PROFILE`, including values loaded from `--env-file`
3. The profile saved by `alchemy profile set-default <name>`
4. The built-in fallback name `default`

The default profile is implicit: on a fresh machine it is created
automatically the first time it's used (a deploy configuring credentials,
`alchemy profile edit`, …) and tagged as the stored default. Renaming it
re-points that tag, so the renamed profile is still selected by default.
Explicitly named profiles are the opposite — `--profile prod` fails until
you create `prod`.

```sh
alchemy profile edit
alchemy deploy
# uses profile `default`, created on first use
```

## How credentials get there

Run `alchemy profile edit`. Every available
provider is listed on one line — Space cycles a row between add,
re-configure, and remove — and on confirm alchemy walks each selected
account through its authentication flow. Pick OAuth, paste an API token,
point at an SSO profile — whatever the provider offers. The result is saved
under your current profile.

To re-run that flow at any time:

```sh
# Add, re-configure, or remove accounts in the current profile
alchemy profile edit

# Re-configure one account directly
alchemy profile edit default --re-configure Cloudflare

# Log into a separate profile
alchemy profile create prod
alchemy profile edit prod
```

Refreshing credentials is separate from reconfiguration. Refresh preserves the
selected authentication method, account, and scopes:

```sh
# Refresh every connected provider
alchemy profile refresh

# Refresh only AWS SSO
alchemy profile refresh default --provider AWS
```

Alchemy also refreshes credentials lazily when the provider supports it, such
as Cloudflare OAuth access tokens and AWS SSO role credentials. If stored
credentials are missing, an OAuth refresh fails, or the AWS SSO session has
expired, the command fails with the exact `alchemy profile refresh` invocation
to run. Deploy does not unexpectedly open a browser or start an interactive
login after configuration; refresh authentication explicitly and retry.

Profile commands include Alchemy's built-in providers even outside a project.
They also import `alchemy.run.ts`, when present, to discover custom providers.
Use `--config <path>` for another entrypoint. A missing conventional
`alchemy.run.ts` is ignored, but errors in an existing entrypoint or an explicit
custom path are surfaced instead of silently hiding its providers. Each
provider's prompts and credential resolution are implemented by its
[Auth Provider](/environments/auth-providers).

## Inspecting a profile

Use `alchemy profile show` to see what's stored (credentials are
redacted):

```sh
alchemy profile show
alchemy profile show prod
```

Sample output:

```text
Profile: default

── AWS ──
  accessKeyId:     ASIA****
  secretAccessKey: Pj5T****
  region:          us-west-2
  source: sso - default

── Cloudflare ──
  accessToken: Xl06****
  expires: in 59m 58s 999ms
  accountId: 123456789...
  source: oauth
```

## Switching profiles

Use `set-default` for your normal local choice, `--profile` for one command, or
`ALCHEMY_PROFILE` for a shell or automation environment:

```sh
alchemy profile set-default work
alchemy profile current

alchemy deploy --stage prod --profile prod
alchemy destroy --stage pr-42 --profile work

export ALCHEMY_PROFILE=work
alchemy deploy
```

Rename a profile without disconnecting its accounts:

```sh
alchemy profile rename work company
```

This moves the profile's credential directory and updates the stored default
when necessary. It does not rewrite an `ALCHEMY_PROFILE` environment variable.

A typical pairing in CI is one profile per environment:

```sh
alchemy deploy --stage staging --profile staging
alchemy deploy --stage prod --profile prod
```

## Where profiles live

Provider authentication settings are stored at
`~/.alchemy/profiles.json`. The file is plain JSON keyed by profile
name. Tokens and access keys are stored as permission-restricted JSON
under `~/.alchemy/credentials/<profile>/`.

Profile names are portable filesystem-safe identifiers: they must start
with a letter or number, may contain letters, numbers, `.`, `_`, and
`-`, and may be at most 64 characters.

You can edit the manifest manually, but
`alchemy profile edit` is usually safer because it knows the
shape each provider expects.
