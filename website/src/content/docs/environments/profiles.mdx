A **profile** is a named set of cloud credentials, such as `default`,
`work`, or `prod`. Use profiles to keep accounts apart, use a different
role for `prod`, or refresh one provider's token without touching the
others. A profile picks the credentials, and a [stage](/environments/stages)
picks what gets deployed.

## Connect an account

Run `alchemy profile edit` and follow each provider's login flow. With
no `--profile`, it edits the built-in `default` profile.

```sh
# Pick providers to add, reconfigure, or remove
alchemy profile edit

# Or change one provider directly
alchemy profile edit --add Neon
alchemy profile edit --reconfigure Cloudflare # rerun the prompt, e.g. OAuth -> API token
alchemy profile edit --remove Neon
```

Scripts and agents can skip the prompts with
`--method <m> --set <field>=<value|env:VAR|->`. `env:VAR` reads the
value from the environment, and `-` reads it from stdin. See
[CLI › profile edit](/cli/profile#profile-edit).

Only `alchemy profile edit` logs you in. A deploy with no credentials
configured fails and prints the exact `alchemy profile edit` command to
run. Each provider's prompts and credential resolution come from its
[auth provider](/environments/auth-providers).

## Use a different profile

Create a second profile, connect accounts to it, and select it per
command or per shell:

```sh
alchemy profile create work
alchemy profile edit --profile work

alchemy deploy --profile work       # one command
export ALCHEMY_PROFILE=work         # every command in this shell
alchemy profile current             # print the selected profile
```

Alchemy selects a profile in this order:

1. The `--profile <name>` option.
2. `$ALCHEMY_PROFILE`. An explicit `--env-file` comes first, then the
   process environment, then `.env` when no file is given.
3. The built-in `default` profile.

The `default` profile always exists and cannot be renamed or deleted.
Alchemy stores no "current profile" setting, so select another profile
with `--profile` or `ALCHEMY_PROFILE`.

A stack that declares `secrets` reads `ALCHEMY_PROFILE` only from
`--profile` or the shell. See
[Secret providers › What the list cannot override](/environments/secret-providers#what-the-list-cannot-override).

See [CLI › profile](/cli/profile) for `list`, `rename`, `delete`, and
the interactive dashboard.

## Refresh expired credentials

Refresh keeps the selected authentication method, account, and scopes.
Use `profile edit --reconfigure` to change them instead.

```sh
# Refresh every connected provider
alchemy profile refresh

# Refresh only AWS SSO in the work profile
alchemy profile refresh --profile work --provider AWS
```

Alchemy refreshes supported credentials lazily. When a refresh needs
you to log in again, the command prints the `alchemy profile refresh`
command to run.

## Check what a profile holds

`alchemy profile show` prints each connected provider with its
credentials redacted:

```sh
alchemy profile show --profile work
```

```text
Profile: work

── AWS ──
  accessKeyId:     ASIA****
  secretAccessKey: Pj5T****
  region:          us-west-2
  source: sso - company

── Cloudflare ──
  accessToken: Xl06****
  expires: in 59m 58s 999ms
  accountId: 123456789...
  source: oauth
```

## Environment variables outside CI

Provider credentials in the environment always win over the profile.
When every required variable for a provider is set, Alchemy resolves
that provider from the variables, even if `--profile` or
`ALCHEMY_PROFILE` selected a profile. The variables can come from the
process environment, a `.env` file, or `--env-file`.

Alchemy logs which variables it used:

```text
Cloudflare: using environment variables (CLOUDFLARE_API_TOKEN,
CLOUDFLARE_ACCOUNT_ID) instead of the profile.
```

The decision is per provider. A Cloudflare token in `.env` overrides
only Cloudflare, and AWS or Neon in the same run still resolve from the
profile. A partial set of variables is ignored, and the profile applies.

## CI

CI does not use profiles. When `CI=true`, Alchemy reads provider
credentials only from environment variables and never touches
`~/.alchemy`. See [CLI › provider](/cli/provider) for each provider's
variables, and [CI](/environments/ci) for a full workflow.

## Where profiles live

Each profile is a directory with one JSON document per connected
provider:

```text
~/.alchemy/                 # set ALCHEMY_HOME to relocate
└── profiles/
    ├── default/
    │   └── cloudflare.json # written by `alchemy profile edit --add Cloudflare`
    └── work/
        ├── aws.json        # chosen method and its values, including tokens
        └── cloudflare.json
```

Alchemy writes these files with owner-only permissions (`0600` files
in a `0700` directory). Use `alchemy profile edit` instead of editing
them by hand.
