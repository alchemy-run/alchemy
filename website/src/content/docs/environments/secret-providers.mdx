Set the `secrets` field on a stack to choose where its Effect `Config`
values come from. It takes one provider or an ordered list.

```typescript
import * as Alchemy from "alchemy";
import * as Doppler from "alchemy/Doppler";

export default Alchemy.Stack(
  "MyApp",
  {
    providers: Cloudflare.providers(),
    state: Cloudflare.state(),
    secrets: [
      Doppler.Secrets({ project: "my-app", config: "dev" }),
      Alchemy.Secrets.DotEnv(),
    ],
  },
  Effect.gen(function* () {
    const dbUrl = yield* Config.Redacted("DATABASE_URL");
    // ...
  }),
);
```

`secrets` is optional. Without it, the existing configuration stays in
place, including any injected `ConfigProvider`. The CLI then reads the
process environment and falls back to `.env`, and an explicit
`--env-file` takes precedence over the process environment.

## Precedence

Later entries override earlier ones. The process environment is the
implicit last entry, so in the example above the shell overrides
`.env`, which overrides Doppler. A one-off `DATABASE_URL=... alchemy deploy`
and a CI runner's exported tokens work with any list.

To rank the shell elsewhere, list `Secrets.ProcessEnv()` yourself:

```typescript
// Shell first: a fallback for what Doppler doesn't hold
secrets: [
  Alchemy.Secrets.ProcessEnv(),
  Doppler.Secrets({ project: "my-app", config: "prd" }),
],

// Shell left out entirely
secrets: [
  Doppler.Secrets({ project: "my-app", config: "prd" }),
  Alchemy.Secrets.ProcessEnv({ disabled: true }),
],
```

Cloud credentials such as `CLOUDFLARE_API_TOKEN` go through the same
list. With the shell disabled, they must come from a provider.

## What the list cannot override

A few keys ignore the list so that no file or secrets manager can
redirect your credentials:

- **`ALCHEMY_PROFILE`**: in a stack that declares `secrets`, the
  [profile](/environments/profiles) comes only from `--profile` or the
  real process environment. No provider can change which credentials
  every other provider uses.
- **Secrets-manager credentials**: Doppler and Infisical read
  `DOPPLER_TOKEN`, `INFISICAL_IDENTITY_ID`, `CI`, and their OIDC
  variables only from the process environment. A runner's exported
  variables always reach them, and no file can impersonate them.
- **`--env-file`**: the flag is refused when the stack declares
  `secrets`. Add `Secrets.DotEnv({ path })` to the list instead.

## Per stage

The `secrets` option and every provider's options accept a callback
instead of a value. The callback receives the
[stage](/environments/stages), the stack, and the Alchemy context:

```typescript
// Pick a provider per stage
secrets: ({ stage }) =>
  stage === "dev"
    ? Alchemy.Secrets.DotEnv()
    : Doppler.Secrets({ project: "my-app", config: stage }),

// Or narrow one provider's options
secrets: [
  Alchemy.Secrets.DotEnv(({ stage }) => ({ path: [".env", `.env.${stage}`] })),
],
```

## Load dotenv files

`Secrets.DotEnv` loads one file or an ordered list:

```typescript
Alchemy.Secrets.DotEnv({
  path: [".env", ".env.prod"], // default ".env", which may be absent. Named files must exist.
  expandVariables: true,       // expand ${OTHER} references. Default false.
});
```

Later files override earlier ones, and an empty value counts as a
value. Nothing is written to `process.env`. Values live in Effect's
[ConfigProvider](https://effect.website/docs/configuration/), so two
stacks in one process never see each other's files.

## Seeing what loaded

With `--log-level debug`, dotenv, Doppler, and Infisical report the
names of the variables they loaded, never the values. The process
environment reports only a count.

```text
Loaded 3 secrets from dotenv (.env, .env.prod): DATABASE_URL, PORT, SENTRY_DSN
Loaded 12 secrets from Doppler (project 'app' config 'prd'): API_KEY, DATABASE_URL, ...
Loaded 87 secrets from the process environment
```

These messages describe each source. Process environment overrides and
custom layers can still change the final values.

## Bring your own source

Any Effect `Layer` that provides a `ConfigProvider` is a valid entry.
Use `ConfigProvider.layerAdd` with `asPrimary` to merge with earlier
entries, as the built-in providers do. A plain `ConfigProvider.layer`
replaces everything listed before it.

```typescript
secrets: [
  ConfigProvider.layerAdd(ConfigProvider.fromUnknown(defaults), { asPrimary: true }),
  Alchemy.Secrets.DotEnv(),
],
```
