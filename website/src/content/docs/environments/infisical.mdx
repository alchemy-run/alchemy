[Infisical](https://infisical.com) keeps secrets in projects, split
into environments with folders inside each. `Infisical.Secrets`
downloads one folder, with
[secret references](https://infisical.com/docs/documentation/platform/secret-reference)
expanded on the server, into the stack's
[secret providers](/environments/secret-providers). It works like
[Doppler](/environments/doppler), and this page covers only what differs.

```typescript
import * as Infisical from "alchemy/Infisical";

secrets: [
  Infisical.Secrets(({ stage }) => ({
    project: "my-app",
    environment: stage === "prod" ? "prod" : "dev",
    path: "/api",
  })),
],
```

The options select what `Infisical.Secrets` reads:

- `project`: the project slug. With a user token, use the project ID,
  because Infisical only resolves slugs for machine identities.
- `environment`: the environment slug.
- `path`, `recursive`, `includeImports`: narrow or widen what is read.
  Imports are on by default, and a secret defined directly in the folder
  wins over an imported one.

## Connect your account

Run `alchemy profile edit --add Infisical` and pick a method. Both
accept an API URL for the [EU cloud](https://eu.infisical.com) or a
self-hosted instance.

- **Machine identity**: create a
  [machine identity](https://infisical.com/docs/documentation/platform/identities/machine-identities)
  for yourself with
  [Universal Auth](https://infisical.com/docs/documentation/platform/identities/universal-auth),
  read access to your dev project, and a client secret. Every later
  command exchanges it for a fresh access token. The client secret keeps
  its configured expiry and use limits.
- **User token**: takes the ten-day token from the dashboard's account
  menu.

```sh
alchemy profile edit --add Infisical --method universal-auth \
  --set clientId=env:INFISICAL_CLIENT_ID \
  --set clientSecret=env:INFISICAL_CLIENT_SECRET
```

## In CI

Set `INFISICAL_TOKEN` to a ready access token, or `INFISICAL_IDENTITY_ID`
to a machine identity whose
[OIDC auth](https://infisical.com/docs/documentation/platform/identities/oidc-auth/general)
trusts your platform:

```yaml
jobs:
  deploy:
    permissions:
      id-token: write   # lets the job request an OIDC token
      contents: read
    steps:
      - run: bun alchemy deploy --stage prod --yes
        env:
          INFISICAL_IDENTITY_ID: ${{ vars.INFISICAL_IDENTITY_ID }}
```

Platform detection, precedence, and the `INFISICAL_OIDC_TOKEN` and
`INFISICAL_OIDC_AUDIENCE` overrides work as they do for Doppler. See
[CLI › provider › OIDC tokens](/cli/provider#oidc-tokens) for every variable. `INFISICAL_API_URL`
selects the EU cloud or a self-hosted instance in either mode.
