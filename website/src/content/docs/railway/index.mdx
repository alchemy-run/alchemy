Railway runs containers for you. You put services in a project, your API, a worker, a Postgres database, and Railway builds each one, runs it, gives it a URL, and connects the services in a project over a private network. Databases, volumes and buckets sit beside them, and you pay for the CPU and memory you actually use.

## A taste

A project is a declaration:

```typescript title="src/project.ts"
import * as Railway from "@alchemy.run/railway";

export const Site = Railway.Project("Site");
```

A Service is your program in it:

```typescript title="src/api.ts"
import * as Railway from "@alchemy.run/railway";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/http/HttpServerResponse";
import { Site } from "./project.ts";

export default class Api extends Railway.Service<Api>()(
  "Api",
  { project: Site, main: import.meta.url, port: 3000 },
  Effect.gen(function* () {
    return {
      fetch: Effect.succeed(HttpServerResponse.text("hello from Railway")),
    };
  }),
) {}
```

And the Stack deploys it to your workspace, with a public `*.up.railway.app` URL:

```typescript title="alchemy.run.ts"
import * as Alchemy from "alchemy";
import * as Railway from "@alchemy.run/railway";
import * as Effect from "effect/Effect";
import Api from "./src/api.ts";

export default Alchemy.Stack(
  "MyApp",
  { providers: Railway.providers(), state: Alchemy.localState() },
  Effect.gen(function* () {
    const api = yield* Api;
    return { url: api.url };
  }),
);
```

## Where to start

**New to Railway?** [What is Railway?](/railway/what-is-railway) walks through workspaces, projects, environments, services, databases, volumes, variables and networking, once each, and shows how Alchemy models every one.

**Want to build one?** The [tutorial](/railway/tutorial/part-1) goes from an empty directory to a project running an HTTP Service with a Volume and a variable, one step at a time. Start with [Setup](/railway/setup) to connect your workspace.

**Want the whole picture?** The chapters follow the shape of Railway itself. Start with where services run: [Projects](/railway/compute/projects), [Environments](/railway/compute/environments), [Services](/railway/compute/services), [Functions, templates & VMs](/railway/compute/functions) and [Regions](/railway/compute/regions). Then what they store: [Postgres](/railway/data/postgres), [MySQL](/railway/data/mysql), [Mongo](/railway/data/mongo), [Redis](/railway/data/redis), [Volumes](/railway/data/volumes), [Buckets](/railway/data/buckets) and [Variables](/railway/data/variables). And how they're reached: [Custom domains, TCP & private networks](/railway/networking).

**Building a website?** [Websites](/railway/frontend/websites) covers every supported framework as a Railway service.

The `examples/railway-service` example puts every resource and binding in one Stack. Every resource is in the generated [API reference](/providers).
