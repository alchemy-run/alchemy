Boat runs sandboxes: Linux machines for agents, untrusted code and dev boxes. A **sandbox** starts in under a second, with Ubuntu, Docker, Node.js, Bun and Python, and `sudo` that needs no password. It runs until its **auto-stop** timer, then Boat stops it and saves its disk, and it picks up where it left off when you resume it. Everything belongs to your **account**, or to an organization you bill to: its sandboxes, snapshots, environments, webhooks and API keys.

Take one small app: an `Agents` environment holding an npm token, and a `Golden` snapshot of a sandbox with the project's dependencies installed. For each task, a Cloudflare Worker creates a sandbox from `Golden` on the `Agents` environment, runs the agent's commands there, and calls the dev server it starts on port 3000.

## Accounts and API keys

Your **account** owns what you create on Boat. An organization's members can bill sandboxes to it instead, and each sandbox stays private to the person who created it.

An **API key** can be narrowed. It carries a list of **actions** (create sandboxes, run commands, read files, host a port, …) and can be limited to some sandboxes or environments, and to a lifetime. A key can never do more, or live longer, than the key that created it.

```typescript
export const Ci = Boat.ApiKey("Ci", { preset: "ci" });
```

See [Account & API keys](/boat/account-and-keys).

## Sandboxes

A **sandbox** is one machine, in one of four sizes. You run commands in it, read and write its files, and call its ports. It runs for its `autoStop` (an hour unless you say otherwise), then Boat stops it and saves its disk for 14 days. A stopped sandbox resumes with its files, and any sandbox can be forked into a copy from its last snapshot. **Labels** tag a sandbox when it's created, so you can find it again.

```typescript
const sandbox = yield* sandboxes.create({ type: "small", autoStop: "10 minutes", labels: { task } });
```

See [Sandboxes](/boat/sandboxes).

## Programs

A sandbox can run your own **program**: an Effect HTTP server that Alchemy bundles, uploads and starts with Node.js, served at the sandbox's URL. A code change restarts it in place, in the same sandbox.

See [Programs](/boat/programs).

## Snapshots and forks

A **snapshot** saves a sandbox's disk under a name. New sandboxes start from it, with a repository cloned and dependencies installed. A **fork** copies a sandbox from its last snapshot, and Boat takes one whenever a sandbox stops.

```typescript
export const Golden = Boat.Snapshot("Golden", { run: ["npm ci"] });
```

See [Snapshots & forks](/boat/snapshots).

## Environments

An **environment** is what a sandbox starts with: environment variables, secret files, and which of your credentials it gets (a GitHub token, your AI logins, its own Boat key). Every change makes a new version; a running sandbox keeps the version it started on.

```typescript
export const Agents = Boat.Environment("Agents", { env: { NODE_ENV: "production" } });
```

See [Environments](/boat/environments).

## Ports

A program that listens on a port inside a sandbox answers at `https://<subdomain>-<port>.on.boat.dev`. Each port needs a token unless you make it public.

See [Ports](/boat/ports).

## Webhooks

Boat reports what happens to each sandbox (ready, stopped, failed, restored) to a **webhook**: a URL you register for the account, called with each event, signed with a secret.

See [Webhooks](/boat/webhooks).

## State: where Alchemy keeps its record

Boat has no storage for Alchemy's own record of what each Stack created. Keep it on disk with `Alchemy.localState()`, or share it with your team and CI through `Cloudflare.state()` or `AWS.state()`.

## How @alchemy.run/boat models these concepts

Your profile signs you in, and `Boat.providers()` deploys into your account. What an app shares for its whole life (an environment, a snapshot, a long-lived dev box, a webhook, a key for CI) are resources in the Stack. Sandboxes made per user or task come from bindings your Worker or Function uses while it runs (`CreateSandbox`, `ConnectSandbox`). They aren't deleted when the Stack is destroyed, but they carry their stack, stage and host as labels (`alchemy.stack`, `alchemy.stage`, `alchemy.id`), so you can find them again. Each binding gets an API key of its own, created at deploy with only the actions it needs, never yours.
