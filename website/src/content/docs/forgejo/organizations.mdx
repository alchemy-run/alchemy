---
title: Organizations & teams
description: Model Forgejo ownership as resources — organizations, teams, memberships, labels, and branch protection.
---

`Forgejo.Organization`, `Forgejo.Team`, and `Forgejo.TeamMember`
describe who owns what on your instance. `Forgejo.Label` and
`Forgejo.BranchProtection` describe the conventions inside a
repository. Together they let a stack stand up a new team's whole
workspace in one deploy.

Organizations, teams, and memberships go through Forgejo's `/admin`
endpoints, so the provider credential must belong to an
administrator. New here? [Set up credentials](/forgejo/setup) first.

## Organizations

```typescript
const org = yield* Forgejo.Organization("acme", {
  owner: "admin",
  username: "acme",
  fullName: "Acme Corporation",
  description: "Internal services",
  website: "https://acme.example",
  visibility: "private",
});
```

`owner` is the *user account under which an administrator creates the
organization*, not a parent org. An organization that already exists
is adopted and its settings converge, so declaring one you created by
hand brings it under management.

Like repositories, organizations default to the `retain` removal
policy — `alchemy destroy` leaves them in place. Opt in with
`destroy()` from `alchemy/RemovalPolicy` when the org is disposable.

Changing `owner` or `username` replaces the organization.

## Teams and members

```typescript
const platform = yield* Forgejo.Team("platform", {
  organization: "acme",
  name: "platform",
  description: "Platform engineering",
  permission: "write",
  units: ["repo.code", "repo.issues", "repo.pulls", "repo.actions"],
});

yield* Forgejo.TeamMember("alice", {
  teamId: platform.teamId,
  username: "alice",
});
```

`Team` outputs a stable numeric `teamId`, which is what `TeamMember`
binds to — pass the output rather than hardcoding an ID, and the
deploy orders itself. `includesAllRepositories` grants the team every
repository in the org, and `canCreateOrgRepo` lets its members create
new ones.

`TeamMember` is an existence-only resource: it has nothing to
converge beyond the membership itself, so a deploy either adds the
user or confirms they're already there, and a destroy removes them
from the team.

## Labels

`Label` converges a repository's issue and pull-request labels:

```typescript
yield* Forgejo.Label("bug", {
  owner: "acme",
  repository: "api",
  name: "bug",
  color: "d73a4a",
  description: "Something isn't working",
});
```

`color` is a hex value **without** the leading `#`. Set `exclusive`
for scoped labels (only one of a `scope/*` set applies at a time), or
`isArchived` to retire a label without deleting it.

## Branch protection

`BranchProtection` manages a protected-branch rule. `ruleName` is
both the rule's name and its identity in the API — changing it
replaces the rule:

```typescript
yield* Forgejo.BranchProtection("main", {
  owner: "acme",
  repository: "api",
  ruleName: "main",
  requiredApprovals: 1,
  blockOnRejectedReviews: true,
  blockOnOutdatedBranch: true,
  enableStatusCheck: true,
  statusCheckContexts: ["ci/test", "ci/lint"],
  requireSignedCommits: true,
  applyToAdmins: true,
});
```

Restrict who may push directly with `pushWhitelistUsernames` and
`pushWhitelistTeams` — both lists replace the live values on each
deploy.
