You have users signing in and pushing to their own repositories. Now
the rules: pushes to `main` should only come from the owner, and a
teammate should be able to push everywhere else. By the end of this
part the rules are one file, and the authentication from Part 3 is
untouched.

## What the engine asks

`Git.Policy` is one function. It receives three things and answers yes
or no: the principal your middleware resolved (`undefined` for
anonymous), the repository, and an action in git's own vocabulary:

```typescript
interface PolicyShape {
  authorize(input: {
    principal: Principal | undefined;
    repo: RepoContext | null;
    action: GitAction;
  }): Effect<boolean>;
}
```

The actions are facts the engine parsed, not roles: `Fetch`, `Push`
with the refs it wants to move, `ReadRepo`, `UpdateRepo`, `DeleteRepo`,
`CreateRepo` with the owner, `ListRepos`, `Maintain`, `CreatePull`,
`UpdatePull`, `MergePull`. It runs where the facts are: a push is judged
inside the repository's Durable Object, after the ref commands are
parsed.

`Git.PolicyOwners` is what you have been running: anonymous reads
public, a principal may create and list, and owns what it owns.

## Protect main

```typescript
// src/policy.ts
import * as Git from "alchemy/Git";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";

export const AppPolicy: Layer.Layer<Git.Policy> = Layer.succeed(Git.Policy, {
  authorize: ({ principal, repo, action }) =>
    Effect.succeed(
      principal === undefined
        ? repo !== null && repo.public && Git.isReadAction(action)
        : repo === null
          ? true
          : action._tag === "Push"
            ? action.updates.every((u) =>
                u.ref === "refs/heads/main" ? Git.owns(principal, repo) : true,
              )
            : Git.owns(principal, repo) ||
              (repo.public && Git.isReadAction(action)),
    ),
});
```

`Git.owns` compares the repository's owner with the principal's id,
lowercased, since owner names are. `Push` carries its `updates` twice:
empty at the ref advertisement, when the question is whether this
caller may push at all, and exact at commit, which is when the rule
above sees `refs/heads/main`.


## Try it

Push a branch with a teammate's key, then push `main`:

```sh
git push origin HEAD:feature
git push origin main
```

The branch lands. The push to `main` is refused in-band with the ref
named, the way git reports any rejected ref. The owner's key moves it.

## A team

Your data decides who is on a team. Read it in the policy:

```typescript
export const AppPolicy = Layer.effect(
  Git.Policy,
  Effect.gen(function* () {
    const teams = yield* Teams; // yours: who may write to which owner

    return {
      authorize: ({ principal, repo, action }) =>
        Effect.gen(function* () {
          if (principal === undefined) {
            return repo !== null && repo.public && Git.isReadAction(action);
          }
          if (repo === null) return true;
          const member = yield* teams.isMember(principal.id, repo.owner);
          if (action._tag === "Push") {
            return action.updates.every((u) =>
              u.ref === "refs/heads/main" ? Git.owns(principal, repo) : member,
            );
          }
          return member || (repo.public && Git.isReadAction(action));
        }),
    };
  }),
);
```

The host asks `MergePull` and `Push` with the refs that move. It never
asks what a team is.
