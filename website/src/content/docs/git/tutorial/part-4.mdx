You have a git host with your rules and users who need somewhere to
sign in. By the end of this part your application and the host share
one domain, the host is unreachable except through your app, and your
code calls it like a function.

## The front door

A second Worker owns the domain. It forwards the git paths and the API
to the host and serves your app for everything else:

```typescript
// src/worker.ts
interface Env {
  GIT: { fetch(request: Request): Promise<Response> };
  ASSETS: { fetch(request: Request): Promise<Response> };
}

const API = /^\/api\/v[13]\//;
const WIRE = /^\/[^/]+\/[^/]+\/(?:info\/refs$|git-upload-pack$|git-receive-pack$)/;

export default {
  fetch(request: Request, env: Env): Promise<Response> {
    const { pathname } = new URL(request.url);
    if (API.test(pathname) || WIRE.test(pathname)) {
      return env.GIT.fetch(request);
    }
    return env.ASSETS.fetch(request);
  },
};
```

Forward the git paths verbatim. A proxy that buffers request bodies
breaks streaming pushes, and one that rewrites `Host` makes the host
print clone URLs for the wrong domain.

## Bind the host

```diff lang="typescript"
// alchemy.run.ts
export default Alchemy.Stack(
  "GitService",
  { providers: Cloudflare.providers(), state: Cloudflare.state() },
  Effect.gen(function* () {
    const git = yield* GitHost;
-    return { url: git.url.as<string>() };
+
+    const web = yield* Cloudflare.Website.Vite("Web", {
+      main: "src/worker.ts",
+      domain: "git.example.com",
+      assets: {
+        notFoundHandling: "single-page-application",
+        runWorkerFirst: true,
+      },
+      env: { GIT: GitHost },
+    });
+
+    return { url: git.url.as<string>(), webUrl: web.url };
  }),
);
```

`env: { GIT: GitHost }` is a service binding. A request crosses to the
host inside Cloudflare with its `Host` header intact, so the host
derives clone URLs on your domain and push bodies stream through
untouched.

```sh
bun alchemy deploy
```

```sh
git clone https://git.example.com/acme/web.git
```

## Call the host from your app

Your app's server code binds the host the same way and calls it
without a network hop:

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import * as HttpClientRequest from "effect/unstable/http/HttpClientRequest";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";
import GitHost from "./git.ts";

export default Cloudflare.Worker(
  "App",
  { main: import.meta.url },
  Effect.gen(function* () {
    const git = yield* Cloudflare.Workers.Fetch(GitHost);

    return {
      fetch: Effect.gen(function* () {
        const res = yield* git(
          HttpClientRequest.get("https://git/api/v1/repos").pipe(
            HttpClientRequest.setUrlParam("owner", "acme"),
          ),
        );
        return HttpServerResponse.json(yield* res.json);
      }),
    };
  }).pipe(Effect.provide(Cloudflare.Workers.FetchBinding)),
);
```

For typed calls, `GitApi` is the REST contract and
`HttpApiClient.make(GitApi, …)` gives you every operation with its
tagged errors, as [Repositories](/git/repositories) shows.

## The host stays private

`GitHost` needs no route of its own. Leave it on its `workers.dev`
address or disable that too, and the service binding is the only way
in. Sessions, the UI, rate limits, and everything else the host does
not have live in your front door, and the host keeps the repositories
correct.
