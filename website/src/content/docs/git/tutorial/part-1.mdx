---
title: "Part 1: A Git host"
description: Add Git route and storage layers to an Effect HTTP server, then secure them with application middleware.
---

Git supplies ordinary Effect layers. Your application creates the HTTP router
and decides which routes, middleware, and platform to use.

## Register the Git routes

```typescript
import * as Git from "alchemy/Git";
import * as Http from "alchemy/Http";
import * as Layer from "effect/Layer";
import * as HttpRouter from "effect/unstable/http/HttpRouter";

const GitLive = Git.ApiLive.pipe(
  Layer.provide(Git.HandlersLive),
);
```

`ApiLive` registers the public endpoints. `HandlersLive` supplies the shared
implementation, which needs repository storage, a registry, a hasher, and blob storage.

## Supply storage and hashing

```typescript
import * as Cloudflare from "alchemy/Cloudflare";

const GitObjects = Cloudflare.R2.Bucket("GitObjects");
const GitLive = Git.ApiLive.pipe(
  Layer.provide(Git.HandlersLive),
  Layer.provide(Git.ReposDurableObject),
  Layer.provide(Git.RegistryDurableObject),
  Layer.provide(Git.HasherInline),
  Layer.provide(Git.BlobStoreR2(GitObjects)),
  Layer.provide(Http.Platform),
);
```

The repository Durable Object stores refs and object metadata. The registry
maps owner/name to a repository. The hasher verifies incoming objects, and R2
stores packs, bundles, and large blobs. Each is an independent layer.

## Build your server

```typescript
import * as Effect from "effect/Effect";

export default class GitHost extends Cloudflare.Worker<GitHost>()(
  "Git",
  { main: import.meta.url, ...Git.GIT_WORKER_OPTIONS },
  Effect.gen(function* () {
    const fetch = yield* HttpRouter.toHttpEffect(GitLive);
    return { fetch };
  }),
) {}
```

`HttpRouter.toHttpEffect` is Effect's server adapter. The same router can contain
your own routes. Git has no server service and receives no application API.

## Add authentication

Use `HttpRouter.middleware` to authenticate each request. The complete shared-secret
implementation is in [Getting Started](/git/getting-started#define-the-host).
It sends `WWW-Authenticate` with a 401 response so Git can request a password.

```typescript
const PublicRoutes = Git.ApiLive.pipe(
  Layer.provide(Authentication.layer),
);

const GitLive = Layer.mergeAll(PublicRoutes, Git.InternalApiLive).pipe(
  Layer.provide(Git.HandlersLive),
  Layer.provide(Git.ReposDurableObject),
  Layer.provide(Git.RegistryDurableObject),
  Layer.provide(Git.HasherInline),
  Layer.provide(Git.BlobStoreR2(GitObjects)),
  Layer.provide(Http.Platform),
);
```

The internal hashing route checks its own deploy-time secret. Keep it outside
application authentication. It is used by the self-binding hasher; the public
route layer does not mount it implicitly.

## Deploy and push

Use the stack and deployment commands in [Getting Started](/git/getting-started#deploy).
The stack outputs the host URL and the shared secret. [Part 2](/git/tutorial/part-2)
creates a repository, pushes it, and grants anonymous reads to public repositories.
