You have a host secured by one shared secret. Your product has users,
and they need to sign in, mint their own credentials, and reach the API
from a browser. By the end of this part the git routes sit inside your
`HttpApi` behind your authentication, git clients authenticate with API
keys, and the engine is unchanged.

## Who decides who is calling

Every git route declares one middleware, `Git.Authenticated`, and asks
it for one thing: `Git.Caller`, a principal or anonymous. The REST
plane, the git wire, the raw reads, and the GitHub facade all run
behind it, so you implement it once. Anonymous is an answer, not an
error: the policy decides what anonymous may do.

Better Auth supplies the answer. Sessions for browsers, API keys for
git.

```sh
bun add @alchemy.run/better-auth better-auth @better-auth/api-key
```

## Better Auth as a service

Better Auth is built once per Worker, so make it a service the rest of
the file can ask for:

```typescript
// src/git.ts
import { BetterAuth, type BetterAuthInstance } from "@alchemy.run/better-auth";
import { apiKey } from "@better-auth/api-key";
import * as Context from "effect/Context";
import * as Layer from "effect/Layer";

export const authOptions: {
  readonly basePath: string;
  readonly emailAndPassword: { readonly enabled: boolean };
  readonly plugins: [ReturnType<typeof apiKey>];
} = {
  basePath: "/api/auth",
  emailAndPassword: { enabled: true },
  plugins: [apiKey()],
};

export type AuthInstance = BetterAuthInstance<typeof authOptions>;

export class Auth extends Context.Service<Auth, AuthInstance>()("app/Auth") {}

export const AuthLive = Layer.effect(Auth, BetterAuth(authOptions));
```

## Who is calling

`Git.Authenticated.make` takes an Effect that produces the handler.
Resources, bindings, and the services the handler needs are declared
in that Effect; the handler runs once per request and answers with a
principal, or `undefined` for anonymous:

```typescript
import * as Git from "alchemy/Git";
import * as Effect from "effect/Effect";

export const AuthenticatedLive = Git.Authenticated.make(
  Effect.gen(function* () {
    const auth = yield* Auth;
    return Effect.fn(function* (request) {
      return undefined;
    });
  }),
);
```

Every request is anonymous so far. Better Auth fills in the two ways
a request names a user.

## API keys for git clients

A `git` client sends HTTP Basic with the key in the password field,
and `gh` sends it as a bearer token. `Git.parseSecret` reads either,
and `verifyApiKey` says whose it is:

```diff lang="typescript"
    return Effect.fn(function* (request) {
+      const key = Git.parseSecret(request.headers);
+      if (key !== undefined && key !== "") {
+        const verified = yield* auth.api
+          .verifyApiKey({ body: { key } })
+          .pipe(
+            Effect.catchTag("BetterAuthApiError", () =>
+              Effect.succeed({ valid: false as const, key: null }),
+            ),
+          );
+        return verified.valid && verified.key
+          ? { id: verified.key.referenceId }
+          : undefined;
+      }
      return undefined;
    });
```

An invalid key is anonymous, not an error. The policy decides what
anonymous may do.

## Sessions for browsers

A request without a key carries the session cookie, or nothing:

```diff lang="typescript"
+import { HttpServerRequest } from "effect/unstable/http/HttpServerRequest";

    return Effect.fn(function* (request) {
      const key = Git.parseSecret(request.headers);
      if (key !== undefined && key !== "") {
        // …
      }
-      return undefined;
+      const session = yield* auth.getSession().pipe(
+        Effect.catchTag("BetterAuthApiError", () => Effect.succeed(null)),
+        Effect.provideService(HttpServerRequest, request),
+      );
+      return session
+        ? { id: session.user.id, name: session.user.name }
+        : undefined;
    });
```

One handler now serves every git route: the REST plane, the wire,
the raw reads, and the GitHub facade.

## A route of your own

The git routes are `alchemy/Http` route classes: an `HttpApiEndpoint`
that also names the tag of its implementation. Yours are the same. `Me`
declares the middleware it relies on, so its handler can ask for
`Git.Caller`:

```typescript
import * as Http from "alchemy/Http";

export class Me extends Http.get<Me>()("me", "/api/v1/me", {
  success: Git.PrincipalSchema,
  error: Git.Unauthorized,
  middleware: [Git.Authenticated],
}) {}

export const MeLive = Me.make(
  Effect.succeed(() =>
    Effect.gen(function* () {
      const { principal } = yield* Git.Caller;
      if (principal === undefined) return yield* new Git.Unauthorized();
      return principal;
    }),
  ),
);
```

`Me.make` is the implementation as a Layer. Its `init` returns the
handler; `Effect.succeed` because this one has nothing to set up.

## Your API

A route goes in a group, a group goes in an API. `Git.Api` is the git
groups, and yours is one more:

```typescript
import * as HttpApiGroup from "effect/unstable/httpapi/HttpApiGroup";

export class AppRoutes extends HttpApiGroup.make("app").add(Me) {}

export class AppApi extends Git.Api.add(AppRoutes) {}
```

## The host

Better Auth needs a database. Declare one, and build the HTTP surface
as a Layer so the router is constructed once:

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import { CloudflareD1 } from "@alchemy.run/better-auth/CloudflareD1";
import * as HttpRouter from "effect/unstable/http/HttpRouter";
import * as HttpApiBuilder from "effect/unstable/httpapi/HttpApiBuilder";

export const GitObjects = Cloudflare.R2.Bucket("GitObjects");
export const AuthDb = Cloudflare.D1.Database("AuthDb");

export class App extends Context.Service<
  App,
  { readonly fetch: Effect.Effect<any, any, any> }
>()("app/App") {}

export const AppLive = Layer.effect(
  App,
  Effect.gen(function* () {
    const auth = yield* Auth;

    const api = yield* HttpApiBuilder.layer(AppApi).pipe(
      Layer.provide(Http.handlers(AppApi)), // every route, under its middleware
      Layer.provide(MeLive), // ours
      Layer.provide(Git.Handlers), // the engine's defaults for the rest
      Layer.provide(AuthenticatedLive),
      Layer.provide(Http.Platform),
      HttpRouter.toHttpEffect,
    );

    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        if (request.url.startsWith("/api/auth")) return yield* auth.fetch;
        return yield* api;
      }),
    };
  }),
).pipe(
  Layer.provide(AuthLive),
  Layer.provide(GitLive),
  Layer.provide(CloudflareD1(AuthDb)),
);
```

`Http.handlers(AppApi)` mounts every route group of the API under the
API's middleware and requires the routes' implementations. `MeLive`
and `Git.Handlers` are those. Leave one out and the compiler names the
route. `Http.Platform` is the platform layer Workers need, since they
have no filesystem.

The blocks lose their `AuthenticatedSecret` line and keep the rest:

```diff lang="typescript"
const GitLive = Git.ReposDurableObject.pipe(
  Layer.provideMerge(Git.RegistryDurableObject),
  Layer.provideMerge(Git.HasherInline),
  Layer.provideMerge(Git.BlobStoreR2(GitObjects)),
  Layer.provideMerge(Git.PolicyOwners),
-  Layer.provideMerge(Git.AuthenticatedSecret({ principal: "acme" })),
);
```

The Worker yields the app:

```typescript
export default class GitHost extends Cloudflare.Worker<GitHost>()(
  "Git",
  { main: import.meta.url, ...Git.GIT_WORKER_OPTIONS },
  Effect.gen(function* () {
    const app = yield* App;
    return { fetch: app.fetch };
  }).pipe(Effect.provide(AppLive)),
) {}
```

```sh
bun alchemy deploy
```

## Try it

Sign up, and Better Auth sets a session cookie:

```sh
curl -c jar -X POST "$HOST/api/auth/sign-up/email" \
  -H "Origin: $HOST" -H "Content-Type: application/json" \
  -d '{"name":"Dana","email":"dana@example.com","password":"correct-horse-battery"}'
```

Create a repository under your own id. Repositories are owned by a
principal's id, lowercased:

```sh
ME=$(curl -s -b jar "$HOST/api/v1/me" | jq -r .id | tr 'A-Z' 'a-z')
curl -b jar -X POST "$HOST/api/v1/repos" \
  -H "Origin: $HOST" -H "Content-Type: application/json" \
  -d "{\"owner\":\"$ME\",\"name\":\"web\",\"public\":true}"
```

Mint an API key. It is shown once, and it is the password of your git
remote:

```sh
KEY=$(curl -s -b jar -X POST "$HOST/api/auth/api-key/create" \
  -H "Origin: $HOST" -H "Content-Type: application/json" \
  -d '{"name":"laptop"}' | jq -r .key)

git remote add origin "https://x:$KEY@$HOST/$ME/web.git"
git push -u origin main
```

Every push and every API call went through `AuthenticatedLive`. The
engine saw a principal and asked the policy.

## Replacing one of the engine's routes

`gh` validates its credential against `GET /api/v3/user`. The engine
answers with the principal. Answer with your own user record instead by
providing another Layer for the same route, nearer the API than
`Git.Handlers`:

```typescript
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

export const GitHubUserLive = Git.GitHubUser.make(
  Effect.succeed(() =>
    Effect.gen(function* () {
      const { principal } = yield* Git.Caller;
      if (principal === undefined) return yield* new Git.Unauthorized();
      return HttpServerResponse.json({
        login: principal.id,
        name: principal.name ?? principal.id,
      });
    }),
  ),
);
```

```diff lang="typescript"
const api = yield* HttpApiBuilder.layer(AppApi).pipe(
  Layer.provide(Http.handlers(AppApi)),
-  Layer.provide(MeLive),
+  Layer.provide([MeLive, GitHubUserLive]),
  Layer.provide(Git.Handlers),
```

The nearer implementation wins. Every git route can be replaced this
way, and the group it lives in never knows.

## Your app on the same origin

Serve your UI from a front-door Worker that forwards `/api/**` and the
git paths to the host over a service binding. The session cookie is
first-party, clone URLs are on your domain, and nothing needs CORS:

```typescript
// src/worker.ts
const API = /^\/api\//;
const WIRE = /^\/[^/]+\/[^/]+\/(?:info\/refs$|git-upload-pack$|git-receive-pack$)/;

export default {
  fetch(request: Request, env: { GIT: Fetcher; ASSETS: Fetcher }) {
    const { pathname } = new URL(request.url);
    return API.test(pathname) || WIRE.test(pathname)
      ? env.GIT.fetch(request)
      : env.ASSETS.fetch(request);
  },
};
```

```typescript
// alchemy.run.ts
const web = yield* Cloudflare.Website.Vite("Web", {
  main: "src/worker.ts",
  domain: "git.example.com",
  assets: { notFoundHandling: "single-page-application", runWorkerFirst: true },
  env: { GIT: GitHost },
});
```

Forward the git paths verbatim. A proxy that buffers request bodies
breaks streaming pushes, and one that rewrites `Host` makes the host
print clone URLs for the wrong domain.
