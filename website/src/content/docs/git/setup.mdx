From an empty project to `git push`. You need a Cloudflare account with
Workers, Durable Objects, and R2 enabled — see
[Cloudflare setup](/cloudflare/setup) if you have not connected one.

## Install

Git ships inside the `alchemy` package — no extra dependency:

```sh
bun add alchemy
```

## Define the host

The package ships no Worker, so you write one. Objects live in an R2
bucket you own, and the Durable Objects come from the package as
layers:

```typescript
// src/git-host.ts
import * as Git from "alchemy/Git";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";

const GitObjects = Cloudflare.R2.Bucket("GitObjects");

const GitLive = Git.ServerLive.pipe(
  Layer.provide(Git.ReposDurableObject),
  Layer.provide(Git.RegistryDurableObject),
  Layer.provide(Git.BlobStoreR2(GitObjects)),
  Layer.provide(Git.AuthTokens),
);

export default class GitHost extends Cloudflare.Worker<GitHost>()(
  "git",
  { main: import.meta.url, ...Git.GIT_WORKER_OPTIONS },
  Effect.gen(function* () {
    const git = yield* Git.Server;
    return { fetch: git.fetch };
  }).pipe(Effect.provide(GitLive)),
) {}
```

`GIT_WORKER_OPTIONS` carries the compatibility flags and CPU limit the
service needs — pushes do real work (inflate, delta resolution,
connectivity checking) inside the Durable Object.

Add it to your stack:

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import GitHost from "./src/git-host.ts";

export default Alchemy.Stack(
  "GitService",
  { providers: Cloudflare.providers(), state: Cloudflare.state() },
  Effect.gen(function* () {
    const git = yield* GitHost;
    return { url: git.url.as<string>() };
  }),
);
```

## Set the admin secret

The bundled auth plugin reads `GIT_SERVICE_ADMIN_TOKEN` from your
environment at deploy time and binds it to the Worker as a secret. It
manages repositories, so treat it like a root credential:

```sh
export GIT_SERVICE_ADMIN_TOKEN="$(openssl rand -base64 32)"
```

## Deploy

```sh
bun alchemy deploy
```

The stack prints the Worker URL. Everything below uses it as `$HOST`.

## Create a repository

```sh
curl -X POST "$HOST/api/v1/repos" \
  -H "Authorization: Bearer $GIT_SERVICE_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"owner":"acme","name":"web","public":true}'
```

The response includes a `write` token, returned exactly once. Keep it —
only its hash is stored.

## Push

The token goes in the password field of the remote URL. The username is
ignored, so anything works:

```sh
git remote add origin "https://x:gs_YOUR_TOKEN@$HOST/acme/web.git"
git push -u origin main
```

Then clone it back to prove the round trip:

```sh
git clone "https://$HOST/acme/web.git" verify
git -C verify fsck --strict
```

Because the repo was created with `public: true`, that clone needed no
credentials at all.

## One origin (optional)

Serving a web UI from the same host keeps clone URLs on your own
domain. Put a front-door Worker on the origin, forward the git wire
paths and `/api/**` to the git host over a service binding, and serve
your app for everything else — see
[Custom domains & routes](/cloudflare/networking/custom-domains).
