---
title: Auth
description: The engine holds no users and no credentials. One middleware you implement says who is calling, and Policy answers what they may do, inside the repository with git's own facts.
---

Authentication happens outside the engine, in the HTTP middleware you
own. The engine asks one pure question per action. Three services carry
that split:

| Service | Answers | Runs |
| --- | --- | --- |
| `Git.Authenticated` | who is calling | the middleware every git route declares, at the Worker, once per request |
| `Git.Caller` | the answer, as every handler sees it | provided by `Authenticated` |
| `Git.Policy` | may they do this | where the facts are, inside the repository's Durable Object |

Shipped: `AuthenticatedSecret` and `PolicyOwners`.

## Principal

The identity your authentication resolved:

```typescript
interface Principal {
  readonly id: string;
  readonly name?: string;
}
```

Repositories are owned by a principal's id. Owner names are lowercased,
so `Git.owns(principal, repo)` compares `repo.owner` with
`principal.id.toLowerCase()`.

## Authenticated

An `HttpApi` middleware that provides `Git.Caller`. Every git route
declares it: the REST plane, the git wire, the raw reads, and the
GitHub facade, so one implementation serves them all, and `git`
clients, which can only send HTTP Basic with the credential in the
password field, go through the same code as browsers.

```typescript
class Authenticated extends HttpApiMiddleware.Service<
  Authenticated,
  { provides: Caller }
>()("alchemy/Git/Authenticated", { error: Unauthorized }) {
  static make<E, R>(init: Effect<Resolve, E, R>): Layer<Authenticated, E, R>;
}

type Resolve = (request: HttpServerRequest) => Effect<Principal | undefined>;
```

`make` takes an `init` that runs once when the layer is built and
returns the per-request resolver. `undefined` is anonymous, never a
failure. `Git.parseBasic`, `Git.parseBearer`, and `Git.parseSecret`
read the header for you. An API key verified by Better Auth:

```typescript
const AuthenticatedLive = Git.Authenticated.make(
  Effect.gen(function* () {
    const auth = yield* Auth;
    return Effect.fn(function* (request) {
      const key = Git.parseSecret(request.headers);
      if (key === undefined) return undefined;
      const verified = yield* auth.api.verifyApiKey({ body: { key } });
      return verified.valid && verified.key
        ? { id: verified.key.referenceId }
        : undefined;
    });
  }),
);
```

`AuthenticatedSecret` is the shipped starter: one secret from `Config`,
one principal.

```typescript
Layer.provide(Git.AuthenticatedSecret({ principal: { id: "acme" } }))
```

## Caller

What every handler behind `Authenticated` sees: a principal, or
anonymous, which the policy confines to public reads.

```typescript
class Caller extends Context.Service<
  Caller,
  { readonly principal: Principal | undefined }
>()("alchemy/Git/Caller") {}
```

A route of your own asks for it the same way once it declares the
middleware:

```typescript
export class Me extends Http.get<Me>()("me", "/api/v1/me", {
  success: Git.PrincipalSchema,
  error: Git.Unauthorized,
  middleware: [Git.Authenticated],
}) {}

export const MeLive = Me.make(
  Effect.succeed(() => Effect.map(Git.Caller, ({ principal }) => /* … */)),
);
```

## Policy

```typescript
interface PolicyShape {
  authorize(input: {
    principal: Principal | undefined;
    repo: RepoContext | null;
    action: GitAction;
  }): Effect<boolean>;
}
```

`repo` is `null` for registry-level actions. `action` is one of git's
own facts, not a role: `Fetch`, `Push` with the parsed ref updates,
`ReadRepo`, `UpdateRepo`, `DeleteRepo`, `CreateRepo` with its owner,
`ListRepos`, `Maintain`, `CreatePull`, `UpdatePull`, `MergePull`.

A denial for anonymous is `401` with `WWW-Authenticate`, so git
prompts. A denial for a principal is `403` naming the action, except
on reads of a private repository, which answer `401` to anyone the
policy does not admit so the repository's existence is not confirmed.

`Push` carries its `updates` twice. At the ref advertisement the list
is empty and the question is whether this caller may push at all. At
commit it is exact, so a rule can look at which refs move and to what:

```typescript
export const ProtectedMain = Layer.succeed(Git.Policy, {
  authorize: ({ principal, repo, action }) =>
    Effect.succeed(
      principal === undefined
        ? repo !== null && repo.public && Git.isReadAction(action)
        : repo === null
          ? true
          : action._tag === "Push"
            ? action.updates.every((u) =>
                u.ref === "refs/heads/main" ? Git.owns(principal, repo) : true,
              )
            : Git.owns(principal, repo) ||
              (repo.public && Git.isReadAction(action)),
    ),
});
```

`Git.PolicyOwners` is the default: anonymous reads public, a principal
may create and list, and owns what it owns. A policy may be a
`Layer.effect` that reads your own data, as the team rule in
[Part 4](/git/tutorial/part-4) does.

## What the engine keeps

The Worker resolves the principal once, strips any inbound
`x-git-principal` header, and forwards the resolved one to the Durable
Object, which trusts it because only the Worker can reach it. The push
pipeline's internal hash route is the one route without the middleware;
it authenticates with a deploy-time random secret no user holds. There
is no tokens table and no admin key. Credentials are your
authentication's, and only your authentication ever sees them.
