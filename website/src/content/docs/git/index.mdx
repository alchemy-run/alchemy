`alchemy/Git` is git hosting you run yourself. `git clone` and
`git push` over smart HTTP, a typed REST plane, pull requests, and a
GitHub-compatible API, on your own Cloudflare account. It ships as a
set of Layers, and you assemble them into a Worker you own:

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import * as Git from "alchemy/Git";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";

export const GitObjects = Cloudflare.R2.Bucket("GitObjects");

const GitLive = Git.ServerLive.pipe(
  Layer.provide(Git.ReposDurableObject), // refs, objects, pull requests
  Layer.provide(Git.RegistryDurableObject), // owner/name → repo
  Layer.provide(Git.BlobStoreR2(GitObjects)), // packs, bundles, large pushes
  Layer.provide(Git.HasherInline), // push verification
  Layer.provide(Git.AuthTokens), // who may read and write
);

export default Cloudflare.Worker(
  "Git",
  { main: import.meta.url, ...Git.GIT_WORKER_OPTIONS },
  Effect.gen(function* () {
    const git = yield* Git.Server;
    return { fetch: git.fetch };
  }).pipe(Effect.provide(GitLive)),
);
```

That is the whole deployment. `bun alchemy deploy` creates the bucket,
two Durable Object namespaces, and the Worker, then prints a URL you
can push to. [Setup](/git/setup) walks it end to end.

A git host is usually an appliance. You run the binary or rent the
service and configure it through the knobs it exposes. Here each
decision is a line in the graph above. Bytes in S3 while compute stays
on Cloudflare is one line:

```diff lang="typescript"
const GitLive = Git.ServerLive.pipe(
  Layer.provide(Git.ReposDurableObject),
  Layer.provide(Git.RegistryDurableObject),
-  Layer.provide(Git.BlobStoreR2(GitObjects)),
+  Layer.provide(Git.BlobStoreS3({ bucket: "git-objects", region: "us-east-1" })),
  Layer.provide(Git.HasherInline),
  Layer.provide(Git.AuthTokens),
);
```

Protecting `main` is a page of code around the auth Layer. Hashing
large pushes on Lambda is a hasher that runs there. Nothing else
changes, and a missing Layer is a type error, not a 500 on your first
clone.

## Blocks

Six services. Each has implementations you pick from or write:

| Block | Decides | Ships with |
| --- | --- | --- |
| [Server](/git/blocks/server) | the HTTP surface: wire, REST, GitHub facade | `ServerLive` |
| [Repositories](/git/blocks/repositories) | where refs and objects live, and the jobs that keep a repo small | `ReposDurableObject` |
| [Registry](/git/blocks/registry) | how `owner/name` resolves | `RegistryDurableObject`, `RegistryD1` |
| [Blob store](/git/blocks/blob-store) | where packs, bundles, and large pushes go | `BlobStoreR2`, `BlobStoreS3` |
| [Hasher](/git/blocks/hasher) | what verifies a push, and on which compute | `HasherInline`, `HasherWorkerLoader`, `HasherLambda` |
| [Auth](/git/blocks/auth) | who may do what | `AuthTokens` |

[The layer graph](/git/blocks) shows how they fit together and how the
one graph you write serves both the Worker and the Durable Objects.

## Assemblies

Requirements pick layers. [Choosing an assembly](/git/assemblies) maps
them, and three are written out in full:

- [Cloudflare](/git/assemblies/cloudflare) — one account, one
  bucket, dynamic Workers hashing large pushes.
- [Cloudflare + AWS](/git/assemblies/cloudflare-aws) — bytes in S3,
  pushes hashed on Lambda, compute on Cloudflare.
- [One origin](/git/assemblies/one-origin) — your app and your git
  host on the same domain.

## Scale

Reads scale like a CDN and writes scale like git. Every repository is
its own Durable Object. Clones stream from immutable bundles that never
pass through it. A push is bounded by your storage, not by isolate
memory. [Scaling model](/git/scale) gives the shape,
[Pushes](/git/scale/pushes) and [Clones](/git/scale/clones) the
measurements.

## Build on it

The service has no users, no UI, and no opinion about either. Your
Worker owns the HTTP surface, your auth Layer decides who a caller is,
and the typed client gives your code every operation the REST plane
has. [Build on it](/git/build) puts a product in front of the host.

## Proven on itself

The alchemy monorepo hosts on it: full history, 44,051 objects, a
67 MiB thin pack, cloned back byte-identical under `git fsck --strict`.
A 40 MiB delta-heavy push lands in 5.9 s against GitHub's 3.3 s on the
same client, a 44 MiB push of whole blobs in 4.8 s against 4.6 s, and
incremental pushes in 0.2–0.4 s against 1.2 s.

## Not a GitHub replacement

No issues, reviews, comments, checks, Actions, or GraphQL. `gh api`
works. `gh pr create` and the rest of the porcelain do not. What it is:
a git remote you own, with an API, that you can build on.

Looking for the GitHub *provider*, which manages repos, Actions
secrets, and webhooks on github.com? That is [GitHub](/github).
