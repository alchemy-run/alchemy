An Alchemy app on Azure is one **runtime**, usually an Azure Function,
plus the **resources** it uses: storage, databases, queues, secrets.
You connect them with typed **bindings**. Call
`Azure.Storage.BlobContainerReadWrite(container)` in your code and
Alchemy gives the Function's managed identity exactly that role on that
container. The code is the role assignment.

```typescript
// src/Api.ts
import * as Azure from "@alchemy.run/azure";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/http/HttpServerResponse";

export default class Api extends Azure.Functions.Function<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const account = yield* Azure.Storage.StorageAccount("Data");
    const container = yield* Azure.Storage.BlobContainer("Files", {
      storageAccount: account.storageAccountName,
    });
    const files = yield* Azure.Storage.BlobContainerReadWrite(container);

    return {
      fetch: Effect.gen(function* () {
        yield* files.put("hello.txt", "hi");
        const blob = yield* files.get("hello.txt");
        return HttpServerResponse.text(blob?.text() ?? "missing");
      }).pipe(Effect.orDie),
    };
  }).pipe(Effect.provide(Azure.Storage.BlobContainerReadWriteHttp)),
) {}
```

The binding assigns **Storage Blob Data Contributor** to the Function's
managed identity on the `Files` container only. No keys or connection
strings reach the app.

## Pick your runtime

- **[Azure Functions](/azure/compute/functions)** — HTTP handlers,
  timers, and queue triggers on Flex Consumption. The default, and
  what the tutorial builds on.
- **[Container Apps](/azure/compute/container-apps)** — long-running
  services and jobs from your own program or image.
- **[AKS](/azure/compute/aks)** — Kubernetes Deployments and Jobs on a
  managed cluster.
- **[Virtual machines](/azure/compute/vms)** — a long-running Node.js
  process on a VM you size.
- **[Effect workflows](/azure/compute/effect-workflows)** — durable
  workflows on Durable Task Scheduler.

Not sure? See [Choosing a runtime](/azure/compute/choosing-a-runtime).

## Data

- **[Storage](/azure/data/storage)** — blob containers with read and
  write clients.
- **[Cosmos DB](/azure/data/cosmos-db)** — documents in a serverless
  NoSQL account.
- **[PostgreSQL](/azure/data/postgres)** — a flexible server queried
  with Drizzle, migrations applied on deploy.
- **[SQL Database](/azure/data/sql)** — Azure SQL with
  `@effect/sql-mssql`.
- **[Redis](/azure/data/redis)** — Azure Managed Redis with Entra
  sign-in.

## Messaging & events

- **[Storage queues](/azure/messaging/storage-queues)** — send from one
  Function, consume in another.
- **[Service Bus](/azure/messaging/service-bus)** — queues and topics
  with sessions and dead letters.
- **[Event Hubs](/azure/messaging/event-hubs)** — high-volume event
  streams.
- **[Event Grid](/azure/messaging/event-grid)** — react to blob
  uploads and other Azure events.

## Frontend

- **[Websites](/azure/frontend/websites)** — static sites and
  server-rendered frameworks behind Front Door.

## AI, security, and operations

- **[Azure OpenAI](/azure/ai/openai)** — chat completions with no API

## Out of scope

The Azure provider covers about 1,290 Azure Resource Manager resource
types across about 165 services. Each service has a reference page,
for example [Azure.Storage](/providers/azure/storage). 510 other
resource types are deliberately not Alchemy resources:

| --- | --- | --- |

| Retired or closed to new customers | 104 | Spring Apps, Customer Insights, Time Series Insights, Data Lake Analytics, Data Lake Storage Gen1, Front Door (classic), classic CDN, HPC Cache, Disk Pools, Lab Services, Logic Apps ISE, MySQL Single Server, Orbital, Scheduler, Dev Spaces, ML Studio (classic), Maps Creator, Playwright Testing (`AzurePlaywrightService` accounts), Azure AD B2C, Recommendations (retired 2026-03-31), Cosmos DB notebook workspaces, Dedicated HSM, App Service Environment v1/v2 worker pools |

These resources are implemented but need something beyond a
subscription:

- **Dev Box** (`Azure.DevCenter`) — closed to new customers since
  2025-11-01. On a tenant that is not onboarded, Dev Box resources fail
  with `DevBoxTenantNotOnboarded`.
- **Cosmos DB for PostgreSQL** — retiring. Azure rejects new clusters
  with `CosmosPostgresProvisioningRetired`. You can still adopt and
  manage a cluster that already exists. For new workloads, use
  [PostgreSQL](/azure/data/postgres).
- **Microsoft Discovery** — an allow-listed preview.
- **Confluent** — a signed-in user token. A service principal can't
  create one.
- **Azure Stack HCI** — physical hardware.
- **VMware Solution** — host quota granted through a support ticket.
- **Power BI and Fabric capacities** — a tenant sign-up.
