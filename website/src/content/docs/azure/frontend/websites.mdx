`Azure.Website` deploys a frontend to Azure. Each resource runs your
framework's build, uploads the static assets to Blob Storage, and serves
the site through Azure Front Door. A server-rendered build also runs on a
Flex Consumption Function, which scales to zero. There is no Docker image
and no App Service plan. Your framework's own config file loads as-is.

```typescript
// alchemy.run.ts
import * as Azure from "@alchemy.run/azure";
import * as Alchemy from "alchemy";
import * as Effect from "effect/Effect";

export default Alchemy.Stack(
  "MySite",
  { providers: Azure.providers(), state: Alchemy.localState() },
  Effect.gen(function* () {
    const site = yield* Azure.Website.Astro("Website", { location: "eastus" });
    return { url: site.url };
  }),
);
```

Run `alchemy deploy`. `site.url` is the Front Door endpoint,
`https://{endpoint}.z01.azurefd.net`. A new endpoint takes 10-20 minutes
to serve everywhere.

client-only app. Use `StaticSite` for any build command that writes a
directory of files.

## Where each request goes

| Path | Origin behind Front Door |
| --- | --- |
| The client directory's top-level entries (`/assets/*`, `/favicon.ico`, …) | the storage account's static website (`$web` container) |
| Every other path, for a server build | the Flex Consumption Function |
| Every other path, for an assets-only build | the static website; a single-page app's deep links get the app shell with `200` |

## Pass environment variables

`env` reaches the build, the local dev server, and a server build's
Function as app settings. Values can be Outputs of other resources:

```typescript
const site = yield* Azure.Website.Nuxt("Website", {
  env: {
    GREETING: "Hello from Azure!",
    API_URL: api.url,
  },
});
```

Server code reads them from `process.env`.

## Size the Function

A server build's Function takes the Flex Consumption settings:

```typescript
const site = yield* Azure.Website.Nextjs("Website", {
  location: "eastus",
  instanceMemoryMB: 512,
  maximumInstanceCount: 40,
});
```

`location` must offer Flex Consumption. The defaults are 2048 MB and
100 instances.

## Share a Front Door profile

Each Front Door profile bills a monthly base fee. Share one across sites:

```typescript
const profile = yield* Azure.Cdn.Profile("Edge");
const web = yield* Azure.Website.Vite("Web", { frontDoor: { profile } });
const docs = yield* Azure.Website.Vocs("Docs", { frontDoor: { profile } });
```

## Skip Front Door

Serve an assets-only build straight from the storage endpoint:

```typescript
const preview = yield* Azure.Website.Vite("Preview", { frontDoor: false });
```

Deep links then answer `404` with the app shell. A server build needs
Front Door.

## Caching

Alchemy uploads only new and changed files and deletes removed ones.
HTML files get `max-age=0,no-cache,no-store,must-revalidate`, so a
deploy shows at once. Every other file gets
`max-age=31536000,public,immutable`. After an upload, Alchemy purges the
replaced and deleted paths from Front Door (`/*` when more than 100
paths changed).

Uploads use your deployer's Microsoft Entra token. Alchemy grants the
deployer **Storage Blob Data Contributor** on the storage account. No
account keys or SAS tokens are used.

## Bring your own storage account

Omit `storageAccount` and Alchemy creates a `Standard_LRS` account for
the site. Pass one to reuse it:

```typescript
const account = yield* Azure.Storage.StorageAccount("Sites");
const site = yield* Azure.Website.Vite("Web", { storageAccount: account });
```

Alchemy owns the account's `$web` container.

## Skip unchanged builds

Alchemy hashes your project's files and skips the build and the upload
when nothing changed. Limit the hash to the files that matter:

```typescript
const web = yield* Azure.Website.Vite("Web", {
  location: "eastus",
  memo: {
    include: ["index.html", "src/**", "package.json", "vite.config.ts"],
  },
});
```

## Local development

`alchemy dev` runs your framework's own dev server with hot reload and
creates nothing in Azure. `site.url` is the local address. Wrap the site
in `Alchemy.remote()` to deploy it for real during dev. See
[Local development](/azure/local-development).

## Destroying a site

`alchemy destroy` deletes the site's Function, and the storage account
and Front Door profile it created. A Front Door profile takes 14-30
minutes to delete.
