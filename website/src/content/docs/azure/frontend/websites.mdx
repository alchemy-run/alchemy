Alchemy deploys frontends to Azure with a family of `Azure.Website`
resources. Each one builds your project through
`@alchemy.run/frontend-frameworks/<framework>/node`, then picks the hosting
from the build output. Your framework's own config file (`vite.config.ts`,
`astro.config.*`, `nuxt.config.ts`, ...) loads natively. No Docker daemon,
image, or registry is involved.

| Build output | Hosting | URL |
| --- | --- | --- |
| Static assets (Vite, Foldkit SPA or `output: "static"`, Astro `output: "static"`, `StaticSite`) | Storage account static website (`$web` container) | `https://{account}.z13.web.core.windows.net` |
| Server (SSR frameworks, Foldkit `output: "server"`) | Linux App Service web app on the Node.js runtime, zip-deployed | `https://{app}.azurewebsites.net` |

Static builds upload only new and changed files (by MD5) and delete
removed files. HTML is served with `no-cache`; other files are immutable.
Server builds bundle the framework's Node serve entry and publish it with
Kudu zip deploy; the same process serves the client assets.

```typescript
import * as Azure from "@alchemy.run/azure";

const site = yield* Azure.Website.Vite("Web", { location: "eastus" });
```

Omit `resourceGroup`, `storageAccount`, and `plan` and Alchemy creates them
under the site's namespace (the plan defaults to `B1`). Pass them to share
infrastructure between sites.

## Front Door

The storage endpoint answers a single-page app's deep link (for example
`/counter/42`) with the app shell and a `404` status. Set `frontDoor` to
serve the site through an Azure Front Door (Standard) endpoint instead: a
rule rewrites extensionless paths to `/index.html`, so deep links return
`200`.

```typescript
const site = yield* Azure.Website.Foldkit("Web", {
  frontDoor: true,
});
```

Front Door profiles bill a monthly base fee. Pass
`frontDoor: { profile }` to share one profile across sites.

## Resources

- [`Vite`](/azure/frontend/vite) — client-only Vite apps.
- `Foldkit` — browser-only and prerendered apps on the storage endpoint;
  `output: "server"` runs Foldkit's request handler on App Service.
- `Astro`, `Nextjs`, `Vinext`, `Nuxt`, `ReactRouter`, `SolidStart`,
  `SvelteKit`, `TanStackStart`, `Waku`, `Octane`, `Vocs` — server builds
  on App Service; Astro with `output: "static"` uses the storage endpoint.
- `StaticSite` — any build command's output directory (Hugo, Zola,
  Eleventy).
- `StaticWebsite` and `AppDeployment` — the building blocks the composites
  use, for publishing your own directory or Node server.

During `alchemy dev` every site runs its framework's own dev server and no
Azure resources are created. `Alchemy.remote()` opts back into the live
deployment.
