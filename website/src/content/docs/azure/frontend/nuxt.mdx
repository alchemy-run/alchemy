`Azure.Website.Nuxt` deploys a [Nuxt](https://nuxt.com) project to Azure.
Nitro's server renders pages and `server/api` routes on a Flex Consumption
Function, which scales to zero. The client directory (`/_nuxt/*`, `public/`
files, prerendered routes) goes to the static website endpoint of an Azure
Storage account. Azure Front Door sends the client directory's paths to
Blob Storage and every other path to the Function. No Docker image and no
App Service plan are involved.

## Install

The build integration ships separately. It only runs at deploy time, so a
dev dependency is enough:

<PackageManagers dev={devDeps} />

## Configure Nuxt

Your `nuxt.config.ts` loads natively: modules and Vite plugins work as they
do outside Alchemy. Do not set `nitro.preset`. The
`@alchemy.run/frontend-frameworks/nuxt/azure` target builds with nitro's
`node` preset and fails the build with an actionable error if your config
sets another one.

## Deploy the site

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Azure from "@alchemy.run/azure";
import * as Effect from "effect/Effect";

export default Alchemy.Stack(
  "MySite",
  { providers: Azure.providers(), state: Alchemy.localState() },
  Effect.gen(function* () {
    const site = yield* Azure.Website.Nuxt("Website", { location: "eastus" });
    return { url: site.url };
  }),
);
```

Run `alchemy deploy`. `site.url` is the Front Door endpoint,
`https://{endpoint}.z01.azurefd.net`. A new endpoint takes 10-20 minutes to
serve everywhere. Pick a `location` that offers Flex Consumption.

A route with `routeRules: { "/about": { prerender: true } }` is built into
the client directory and served from Blob Storage at its directory path
(`/about/`).

## Pass environment variables

```diff lang="typescript"
-const site = yield* Azure.Website.Nuxt("Website", { location: "eastus" });
+const site = yield* Azure.Website.Nuxt("Website", {
+  location: "eastus",
+  env: { NUXT_PUBLIC_API_URL: "https://api.example.com" },
+});
```

The values are set on `process.env` for the build and become app settings
of the Function. `NUXT_*` settings override `runtimeConfig` at request
time; a server route reads any setting from `process.env`.

## Override the Nuxt config

```typescript
const site = yield* Azure.Website.Nuxt("Website", {
  nuxt: { routeRules: { "/docs/**": { prerender: true } } },
});
```

`nuxt` is merged over your `nuxt.config.ts` as the highest-priority layer.

## Share a Front Door profile

```typescript
const profile = yield* Azure.Cdn.Profile("Edge");
const web = yield* Azure.Website.Nuxt("Website", { frontDoor: { profile } });
```

Each profile bills a monthly base fee, so share one across sites. See
[Websites](/azure/frontend/websites) for caching, purges, and the other
shared settings.

## Local development

`alchemy dev` runs Nuxt's own dev server with hot reload and creates
nothing in Azure. Wrap the site in `Alchemy.remote()` to deploy it for real
during dev.

See the [`azure-website-nuxt`](https://github.com/alchemy-run/alchemy/tree/main/examples/azure-website-nuxt)
example.
