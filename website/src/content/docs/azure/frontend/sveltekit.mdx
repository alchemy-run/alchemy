`Azure.Website.SvelteKit` deploys a [SvelteKit](https://svelte.dev/docs/kit)
app to Azure. Alchemy runs kit's own Vite build with an in-memory adapter.
Kit's server (`load` functions, `+server.ts` endpoints, form actions) runs
on a Flex Consumption Function, which scales to zero. The client assets and
prerendered pages go to the static website endpoint of an Azure Storage
account. Azure Front Door sends `/_app/*` and the `static/` files to Blob
Storage and every other path to the Function. No Docker image and no App
Service plan are involved.

## Install

The build integration ships separately. It only runs at deploy time, so a
dev dependency is enough:

<PackageManagers dev={devDeps} />

Your project also needs `@sveltejs/kit`, `@sveltejs/vite-plugin-svelte`,
`svelte`, and `vite`.

## Deploy the site

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Azure from "@alchemy.run/azure";
import * as Effect from "effect/Effect";

export default Alchemy.Stack(
  "MySite",
  { providers: Azure.providers(), state: Alchemy.localState() },
  Effect.gen(function* () {
    const site = yield* Azure.Website.SvelteKit("Website", { location: "eastus" });
    return { url: site.url };
  }),
);
```

Run `alchemy deploy`. `site.url` is the Front Door endpoint,
`https://{endpoint}.z01.azurefd.net`. A new endpoint takes 10-20 minutes to
serve everywhere. Pick a `location` that offers Flex Consumption.

Your `vite.config.ts` loads natively and declares no adapter. There is no
`svelte.config.js` to write (kit v3 dropped it).

## Prerendered pages

A route with `export const prerender = true` is written to the client
directory at build time (`about.html` for `/about`) and uploaded to Blob
Storage. Kit's server answers `404` for a prerendered route, so the
Function fetches the HTML file from Blob Storage through Front Door and
returns it for `/about`.

## Pass environment variables

```diff lang="typescript"
-const site = yield* Azure.Website.SvelteKit("Website", { location: "eastus" });
+const site = yield* Azure.Website.SvelteKit("Website", {
+  location: "eastus",
+  env: { GREETING: "Hello from Azure!" },
+});
```

The values become app settings of the Function. A server `load` reads them
from `process.env` (or kit's `$env/dynamic/private`):

```typescript
// src/routes/+page.server.ts
export const load = () => ({
  greeting: process.env.GREETING ?? "Hello!",
});
```

## Override kit options

Kit options live in the `sveltekit(...)` call in your `vite.config.ts`. The
`kit` prop merges JSON-serializable overrides over them at deploy time:

```typescript
const site = yield* Azure.Website.SvelteKit("Website", {
  kit: { prerender: { handleHttpError: "warn" } },
});
```

Do not set `kit.adapter`: Alchemy injects its own.

## Size the Function

```typescript
const site = yield* Azure.Website.SvelteKit("Website", {
  instanceMemoryMB: 512,
  maximumInstanceCount: 40,
});
```

## Share a Front Door profile

```typescript
const profile = yield* Azure.Cdn.Profile("Edge");
const site = yield* Azure.Website.SvelteKit("Website", { frontDoor: { profile } });
```

Each profile bills a monthly base fee, so share one across sites. See
[Websites](/azure/frontend/websites) for caching, purges, and the other
shared settings.

## Local development

`alchemy dev` runs kit's Vite dev server with hot reload and creates
nothing in Azure. `env` reaches the dev server's `process.env`. Wrap the
site in `Alchemy.remote()` to deploy it for real during dev.

See the [`azure-website-sveltekit`](https://github.com/alchemy-run/alchemy/tree/main/examples/azure-website-sveltekit)
example.
