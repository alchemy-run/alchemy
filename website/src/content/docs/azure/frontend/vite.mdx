`Azure.Website.Vite` deploys a [Vite](https://vite.dev) project to Azure.
It runs `vite build`, uploads the output to the static website endpoint of
an Azure Storage account, and serves it through Azure Front Door. No Docker
image and no server are involved.

## Install

```sh
bun add -d @alchemy.run/frontend-frameworks
```

## Deploy

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Azure from "@alchemy.run/azure";
import * as Effect from "effect/Effect";

export default Alchemy.Stack(
  "MyApp",
  { providers: Azure.providers(), state: Alchemy.localState() },
  Effect.gen(function* () {
    const web = yield* Azure.Website.Vite("Web", { location: "eastus" });
    return { url: web.url };
  }),
);
```

`web.url` is the Front Door endpoint, `https://{endpoint}.z01.azurefd.net`.
A new endpoint takes 10-20 minutes to serve everywhere.

Unknown paths return `index.html` with a `200` status, so client-side
routes deep-link. Use `assets: { notFoundHandling: "404-page" }` for
multi-page sites with a `404.html`.

## Redeploy

A redeploy uploads only changed files and deletes removed ones. HTML is
never cached; hashed assets are cached for a year. Alchemy then purges the
paths of replaced and deleted files from Front Door.

## Share infrastructure

```typescript
const profile = yield* Azure.Cdn.Profile("Edge");
const storageAccount = yield* Azure.Storage.StorageAccount("Files");
const web = yield* Azure.Website.Vite("Web", {
  storageAccount,
  frontDoor: { profile },
});
```

Each Front Door profile bills a monthly base fee, so share one across
sites. `frontDoor: false` serves the site straight from the storage
endpoint; deep links then answer `404` with the app shell.

## Local development

Under `alchemy dev`, `web.url` is Vite's own dev server (HMR included) and
no Azure resources are created.

See the [`azure-website-vite`](https://github.com/alchemy-run/alchemy/tree/main/examples/azure-website-vite)
example.
