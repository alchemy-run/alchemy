title: Processes
description: "Declare a process with AI.Process: prose that says how to do a piece of work with the tools, models and inputs it mentions. Start sessions of it and talk to them."
---

A **process** is prose that says how to carry out a piece of work. The prose mentions what the work uses: tools, models, inputs, other processes. Mentioning something grants it to the process, and makes running the process require it. A **session** is one running instance: a conversation on a harness, with the process's prose as its instructions.

## Declare a process

A process is a class with a name, a description and its prose:

```typescript title="src/Research.ts"
import * as AI from "@alchemy.run/ai";

export class Research extends AI.Process<Research>()("Research", {
  description: "Answer a question about the code, with file paths.",
})`
  Answer questions about the repository in your working directory.
  Search with ${AI.Grep} and open what looks relevant with ${AI.Read}.
  Reply with file paths and line numbers. Never edit files.
` {}
```

The model reads the prose with each mention replaced by its name: `grep` and `read` here. A session of `Research` may call those two tools and no others.

## Mention a tool

Any [tool](/ai/tools) can be mentioned: one of yours, a [coding tool](/ai/coding-tools), or an [MCP server](/ai/mcp-servers), which stands for every tool it offers.

```typescript title="src/Release.ts"
import * as AI from "@alchemy.run/ai";
import { Deploy } from "./Deploy.ts";

export class Release extends AI.Process<Release>()("Release", {
  description: "Build the project and upload a release.",
})`
  Build the project with ${AI.Bash}, then upload the archive with ${Deploy}.
` {}
```

`Release` now requires `Deploy`'s Layer and a Layer for `AI.Bash`. Leave either out and the program that runs it does not compile.

## Take an input

An `AI.Input` is a value a session is started with: a name and a schema. Mentioning one in the prose makes it an input of the process.

```typescript title="src/Research.ts"
import * as AI from "@alchemy.run/ai";
import * as Schema from "effect/Schema";

export const question = AI.Input("question", Schema.String);

export class Research extends AI.Process<Research>()("Research", {
  description: "Answer one question about the code, with file paths.",
})`
  Answer ${question} about the repository in your working directory.
  Search with ${AI.Grep} and open what looks relevant with ${AI.Read}.
  Reply with file paths and line numbers. Never edit files.
` {}
```

The model reads the input's name in the prose, and its value in the session's first message. The prose is the same for every session, and a value never becomes part of the instructions.

## Start a session

Yielding a process gives a client. `start` takes a key and the inputs the prose mentions, typed by their schemas:

```typescript
const research = yield* Research;

yield* research.start("parser", { question: "Where is the parser?" });
```

`start` returns once the inputs are stored, and the session works on. Starting a key that already started does nothing, so code that may run twice can call it safely.

## Talk to a session

`get` reaches a session by its key. `prompt` sends a message and waits for the answer:

```typescript
const reply = yield* research.get("parser").prompt("Which file should I read first?");
// reply.text
```

`send` stores the message and returns without waiting, and `requestId` makes it exactly-once:

```typescript
yield* research.get("parser").send("Also check the tests.", { requestId: "comment-812" });
```

A session of a process with inputs has to be started before it is sent anything. Until then, `send` and `prompt` fail with `NotStarted`. A process without inputs needs no `start`: its first message starts it.

## Wait, read and stop

A session also has `wait`, which returns once it has nothing left to run, `messages`, its transcript as the harness stores it, and `abort`, which stops what is running:

```typescript
const session = research.get("parser");

yield* session.wait;
const transcript = yield* session.messages;
yield* session.abort;
```

## A process has no output

A session is not a function call. It can run for a second or for a month, and it reports through the tools it is given: a command on a [Domain model](/ai/domain), a comment on an issue, a file in a bucket. What starts it never waits for a return value.

## Separate the name from the prose

A process can be declared by its name and inputs alone. `toLayer` then gives it prose, and each Layer is one way to carry the process out.

```typescript title="src/Triage.process.ts"
import * as AI from "@alchemy.run/ai";
import * as Schema from "effect/Schema";

export const issue = AI.Input("issue", Schema.Number);

export class Triage extends AI.Process<Triage>()("Triage", { inputs: [issue] }) {}
```

```typescript title="src/Triage.ts"
import * as AI from "@alchemy.run/ai";
import { issue, Triage } from "./Triage.process.ts";

export const TriageLive = Triage.toLayer({
  description: "Say what kind of issue this is.",
})`
  Read issue ${issue} and the code it is about with ${AI.Grep} and ${AI.Read}.
  Reply with one word: bug, feature or question.
`;
```

Code that yields `Triage` depends on the name and the input alone: it never sees the prose, the tools or the models. `TriageLive` requires what its own prose mentions, and a second Layer with other words and other tools can replace it without touching that code. Prose may only mention the inputs its tag lists.

## Run it

A process names no harness. Where its Layers are provided, one more Layer says which coding agent runs it. See [Choose a harness](/ai/harnesses) and [Where sessions run](/ai/hosting).
