In [Part 2](/ai/tutorial/part-2) the Worker reported an issue and then started its session by hand. This part moves that decision into the board: a policy asks for an issue to be looked after whenever one is reported, and passes on every reply. The Worker then only turns GitHub's events into commands.

## Say what the board asks for

The board should not know that a model does this work. It declares what it asks of whatever does: start on an issue, and pass on what was said about it.

## Ask for it when an issue is reported

A policy reacts to events. `IssueWork` hands each reported issue to the triager:

```typescript title="src/Board/IssueWork.policy.ts"
import * as Domain from "@alchemy.run/domain";
import * as Effect from "effect/Effect";
import * as Match from "effect/Match";
import { Issue } from "./Issue.aggregate.ts";
import { IssueReported } from "./ReportIssue.command.ts";
import { Triager } from "./Triager.external.ts";

export class IssueWork extends Domain.Policy("IssueWork", {
  from: Issue,
  on: [IssueReported],
}) {}

export const IssueWorkLive = IssueWork.toLayer(
  Effect.gen(function* () {
    const triager = yield* Triager;
    return Effect.fn(function* ({ source, event }) {
      yield* Match.valueTags(event, {
        IssueReported: () => triager.start({ issue: source.id }),
      });
    });
  }),
);
```

## Host the board over the objects

The board is hosted in two places: in the Worker, and in each object, so a session can reach it. Both need a triager, and both have a handle on the objects. `boardOver` takes that handle. It replaces `src/Board.ts`, which you can delete.

```diff lang="typescript" title="src/Agents.ts"
import * as Cloudflare from "@alchemy.run/cloudflare";
+import * as DomainCloudflare from "@alchemy.run/domain/Cloudflare";
import * as Pi from "@alchemy.run/pi";

-import { BoardLive } from "./Board.ts";
+import { Board } from "./Board/Board.model.ts";
import type { IssueId } from "./Board/Issue.id.ts";
+import { IssueWorkLive } from "./Board/IssueWork.policy.ts";
+import { Triager } from "./Board/Triager.external.ts";

interface Agents {
  readonly getByName: (issue: string) => Agent;
}
+
+const boardOver = <R>(agents: Effect.Effect<Agents, never, R>) =>
+  Board.layer(IssueWorkLive).pipe(
+    Layer.provide(
+      Layer.mergeAll(
+        DomainCloudflare.layerDurableObjects(),
+        Triager.toLayer(
+          Effect.map(agents, (agents) => ({
+            start: ({ issue }) => agents.getByName(issue).start(issue),
+            tell: ({ issue, text, id }) => agents.getByName(issue).tell(issue, text, id),
+          })),
+        ),
+      ),
+    ),
+  );
```

`Triager.toLayer` is the adapter: each thing the board asks becomes a call to the object named after the issue.

## Answer the board

The object answers `start` and `tell`:

```diff lang="typescript" title="src/Agents.ts"
export default class IssueAgents extends Cloudflare.DurableObject<IssueAgents>()(
    return Effect.succeed({
-      start: (issue: IssueId) => triage.start(issue, { issue }).pipe(Effect.orDie),
-    });
+      start: (issue) => triage.start(issue, { issue }).pipe(Effect.orDie),
+      tell: (issue, text, id) =>
+        triage
+          .get(issue)
+          .send(text, { requestId: id })
+          .pipe(Effect.catchTag("NotStarted", () => Effect.void), Effect.orDie),
+    } satisfies Agent);
```

`send` returns once the message is stored, so the policy never waits for a model. `requestId` keeps a reply from reaching the session twice, and starting a key twice does nothing: a policy can run more than once for one event. A reply on an issue that was never reported has no session, which is `NotStarted`.

Using a session requires the runtime context, which is why `Agent` says so. A policy's handler and an external system's operations carry the same requirement, so the call type-checks all the way from the board to the session.

## Turn GitHub's events into commands

`GitHub.consumeRepositoryEvents` registers a webhook on the repository and verifies each delivery. An opened issue is reported, and a reply is recorded:

```typescript title="src/GitHubIssues.ts"
import * as GitHub from "@alchemy.run/github";
import * as Effect from "effect/Effect";
import * as Match from "effect/Match";
import { CommentOnIssue } from "./Board/CommentOnIssue.command.ts";
import { Issue } from "./Board/Issue.aggregate.ts";
import { IssueId } from "./Board/Issue.id.ts";
import { ReportIssue } from "./Board/ReportIssue.command.ts";
import { owner, repository } from "./Repo.ts";

export const GitHubIssues = Effect.gen(function* () {
  const issues = yield* Issue;

  yield* GitHub.consumeRepositoryEvents(
    { owner, repository, events: ["issues", "issue_comment"] },
    Effect.fn(function* (event) {
      const issueId = IssueId.make(String(event.payload.issue.number));
      const once = { commandId: event.id };
      yield* Match.value(event).pipe(
        Match.when({ name: "issues", payload: { action: "opened" } }, ({ payload }) =>
          issues.send(
            new ReportIssue({
              issueId,
              title: payload.issue.title,
              body: payload.issue.body ?? "",
            }),
            once,
          ),
        ),
        Match.when({ name: "issue_comment", payload: { action: "created" } }, ({ payload }) =>
          issues.send(
            new CommentOnIssue({
              issueId,
              commentId: String(payload.comment.id),
              body: payload.comment.body,
            }),
            once,
          ),
        ),
        Match.orElse(() => Effect.void),
      );
    }, Effect.orDie),
  );
});
```

GitHub's delivery id is the command id, so a delivery that arrives twice changes nothing. Nothing in this file knows a process exists.

## Serve the events from the Worker

The Worker no longer starts sessions. It consumes the events and shows the board:

```typescript title="src/Worker.ts"
import * as Cloudflare from "@alchemy.run/cloudflare";
import * as GitHub from "@alchemy.run/github";
import * as Effect from "effect/Effect";
import { HttpServerRequest } from "effect/http/HttpServerRequest";
import * as HttpServerResponse from "effect/http/HttpServerResponse";
import * as Layer from "effect/Layer";
import * as Option from "effect/Option";
import { BoardLive } from "./Agents.ts";
import { Issue } from "./Board/Issue.aggregate.ts";
import { IssueId } from "./Board/Issue.id.ts";
import { IssueDetail } from "./Board/IssueDetail.view.ts";
import { GitHubIssues } from "./GitHubIssues.ts";

const Live = Layer.mergeAll(BoardLive, GitHub.RepositoryEventSourceLive);

export default class Worker extends Cloudflare.Worker<Worker>()(
  "Worker",
  { main: import.meta.url },
  Effect.gen(function* () {
    const details = yield* IssueDetail;
    yield* GitHubIssues;

    return {
      // GET /issues/<number> shows the issue as the board has it.
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const [, area, number] = new URL(request.url, "http://board").pathname.split("/");
        if (area !== "issues" || number === undefined) {
          return HttpServerResponse.text("not found", { status: 404 });
        }
        const detail = yield* details.get(Issue.ref(IssueId.make(number)));
        return yield* HttpServerResponse.json(Option.getOrNull(detail));
      }).pipe(Effect.orDie),
    };
  }).pipe(Effect.provide(Live)),
) {}
```

## Try it

Open an issue on the repository, then read it from the board:

```sh
gh issue create -R my-org/issue-board --title "The build fails on Windows" --body "npm run build exits with code 1."

curl "$URL/issues/1"
# {"title":"The build fails on Windows","body":"npm run build exits with code 1.","label":"bug","comments":[]}
```

Reply on the issue that it was your own mistake, and the label changes to `question`.

## What you have

- A board that says what it asks for, and a policy that asks.
- An object for each issue that answers, by starting its session or sending it a message.
- GitHub's events as commands, with no knowledge of processes.

The session labels an issue it has never read the code for. [Part 4](/ai/tutorial/part-4) gives it the repository and lets it answer.
