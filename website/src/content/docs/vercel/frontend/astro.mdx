`Vercel.Website.Astro` deploys an [Astro](https://astro.build) site
to Vercel. It runs your project's own build; the
[`@astrojs/vercel`](https://docs.astro.build/en/guides/integrations-guide/vercel/)
adapter — installed and declared in your `astro.config.*` — emits a
complete `.vercel/output` tree: server-rendered pages as serverless
functions, prerendered pages and client assets as static files. The
tree deploys through the same engine as every
[`Function`](/vercel/compute/functions) — prebuilt, immutable, no
Vercel build pipeline.

## Install the adapter

Unlike [Nuxt](/vercel/frontend/nuxt), Astro needs its Vercel
adapter installed and declared. `astro add` does both:

```sh
bunx astro add vercel
```

Which leaves your config looking like this:

```typescript
// web/astro.config.mjs
import { defineConfig } from "astro/config";
import vercel from "@astrojs/vercel";

export default defineConfig({
  adapter: vercel(),
});
```

Set `output: "server"` to render pages on demand in serverless
functions; without it, Astro prerenders everything at build time
and the adapter still emits the pages as static output.

## Deploy the site

Point `rootDir` at the directory containing `astro.config.*` and
return the site's URL as a stack output:

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Vercel from "alchemy/Vercel";
import * as Effect from "effect/Effect";

export default Alchemy.Stack(
  "MyAstroSite",
  {
    providers: Vercel.providers(),
    state: Vercel.state(),
  },
  Effect.gen(function* () {
    const site = yield* Vercel.Website.Astro("Site", {
      rootDir: "./web",
    });
    return { url: site.url };
  }),
);
```

```sh
bun alchemy deploy
```

`alchemy deploy` runs `bunx astro build` in `./web`, uploads the
resulting `.vercel/output` tree as an immutable deployment, and
moves the production alias to it. `site.url` is the project's
assigned production URL — always read back from Vercel, never
computed.

## Pass environment to the build and runtime

`env` reaches both the build subprocess (`PUBLIC_*` values are
inlined into client code by Vite) and the deployed functions (as
synced project env vars in `process.env`):

```diff lang="typescript"
// alchemy.run.ts
+    const api = yield* Vercel.Function("Api", { main: "./src/api.ts" });
    const site = yield* Vercel.Website.Astro("Site", {
      rootDir: "./web",
+      env: { PUBLIC_API_URL: api.url },
    });
```

`api.url` resolves before the build runs, so client and server see
the same value. `Redacted` secrets become sensitive project env
vars — see [Secrets & env](/vercel/security/secrets-env).

## Customize the build command

`command` overrides the default `bunx astro build` — useful when
the build needs an install step or a wrapper script:

```typescript
const site = yield* Vercel.Website.Astro("Site", {
  rootDir: "./web",
  command: "npm run build",
});
```

## Rebuilds are memoized

Every non-gitignored file under `rootDir` (plus the nearest
lockfile) is content-hashed; unchanged inputs skip the build, and
an unchanged output tree skips the deploy entirely. Make sure build
output stays out of the hash:

```sh
# web/.gitignore
dist
.astro
.vercel
node_modules
```

Use `memo` to narrow the hashed scope explicitly, or `memo: false`
to rebuild on every deploy.

## Class form

Calling `Astro` with no arguments returns a constructor you can
`extend` to declare the site as a named class:

```typescript
// site.ts
import * as Vercel from "alchemy/Vercel";

export default class Site extends Vercel.Website.Astro<Site>()("Site", {
  rootDir: "./web",
}) {}
```

```typescript
// alchemy.run.ts
import Site from "./site.ts";

const site = yield* Site;
```

## Local dev

For frontend iteration, run Astro's own dev server directly — the
build is Astro's own, so nothing alchemy-specific is involved:

```sh
bunx astro dev
```

Websites have no local emulation during `alchemy dev` yet. If the
site is part of a stack you run with `alchemy dev`, pipe it through
`Alchemy.remote()` to keep deploying it live while the rest of the
stack runs locally:

```typescript
import * as Alchemy from "alchemy";

const site = yield* Vercel.Website.Astro("Site", {
  rootDir: "./web",
}).pipe(Alchemy.remote());
```
