In [Part 2](/stackit/tutorial/part-2) you deployed a Function bound to a
Bucket. Now you write tests that deploy the Stack, call the Function, and
check the result.

## Install the test harness

`Test.make` ships in `@alchemy.run/test`. Add it as a dev dependency:

```sh
bun add -d @alchemy.run/test
```

## Create the test file

`Test.make` takes the same providers and state as your Stack:

```typescript
// test/integ.test.ts
import * as Alchemy from "alchemy";
import * as Stackit from "@alchemy.run/stackit";
import * as Test from "@alchemy.run/test/Bun";
import { expect } from "bun:test";
import * as Effect from "effect/Effect";
import Stack from "../alchemy.run.ts";

const { test, beforeAll, afterAll, deploy, destroy } = Test.make({
  providers: Stackit.providers(),
  state: Alchemy.localState(),
});
```

:::note[Using Vitest or alchemy-test?]
`@alchemy.run/test/Vitest` and `@alchemy.run/test/Alchemy` have the same API.
Take `expect` from `@effect/vitest` or `@alchemy.run/test` instead. See
[Test harness → Runners](/testing/test-harness#runners).
:::

## Deploy before the tests

Deploy the Stack once, before any test runs:

```diff lang="typescript"
// test/integ.test.ts
const { test, beforeAll, afterAll, deploy, destroy } = Test.make({
  providers: Stackit.providers(),
  state: Alchemy.localState(),
});

+const stack = beforeAll(deploy(Stack), { timeout: 1_200_000 });
```

`beforeAll` returns a handle. `yield*` it inside a test to get the Stack
outputs. The first deploy builds an image and waits for a revision, so give
it a long timeout.

## Read the outputs

```diff lang="typescript"
// test/integ.test.ts
const stack = beforeAll(deploy(Stack), { timeout: 1_200_000 });

+test(
+  "stack exposes a function url",
+  Effect.gen(function* () {
+    const { url } = yield* stack;
+
+    expect(url).toBeDefined();
+  }),
+);
```

## Run the tests

Run them with your registry login set:

```sh
HARBOR_USERNAME=... HARBOR_CLI_SECRET=... bun test test/integ.test.ts
```

The first run deploys. Later runs reuse the deployment and only change what
you changed.

:::note[Which stage do tests use?]
Tests deploy to `test_$USER` (e.g. `test_sam`), apart from the `live_$USER`
stage `alchemy deploy` uses. Your working deployment is never touched. More
on stages in [Part 4](/stackit/tutorial/part-4).
:::

## Call the Function

Replace the first test with a round trip through the Bucket:

```diff lang="typescript"
// test/integ.test.ts
import * as Alchemy from "alchemy";
import * as Stackit from "@alchemy.run/stackit";
import * as Test from "@alchemy.run/test/Bun";
import { expect } from "bun:test";
import * as Effect from "effect/Effect";
+import * as HttpClient from "effect/http/HttpClient";
+import * as HttpClientRequest from "effect/http/HttpClientRequest";
+import * as Schedule from "effect/Schedule";
import Stack from "../alchemy.run.ts";

const { test, beforeAll, afterAll, deploy, destroy } = Test.make({
  providers: Stackit.providers(),
  state: Alchemy.localState(),
});

const stack = beforeAll(deploy(Stack), { timeout: 1_200_000 });

-test(
-  "stack exposes a function url",
-  Effect.gen(function* () {
-    const { url } = yield* stack;
-
-    expect(url).toBeDefined();
-  }),
-);
+test(
+  "PUT and GET round-trip an object",
+  Effect.gen(function* () {
+    const { url } = yield* stack;
+
+    const put = yield* HttpClient.execute(
+      HttpClientRequest.put(`${url}/hello.txt`).pipe(
+        HttpClientRequest.bodyText("Hello, World!"),
+      ),
+    ).pipe(
+      Effect.flatMap((response) =>
+        response.status === 204
+          ? Effect.succeed(response)
+          : Effect.fail(`HTTP ${response.status}`),
+      ),
+      Effect.retry({ schedule: Schedule.spaced("5 seconds"), times: 24 }),
+    );
+    expect(put.status).toBe(204);
+
+    const get = yield* HttpClient.execute(HttpClientRequest.get(`${url}/hello.txt`));
+    expect(yield* get.text).toBe("Hello, World!");
+  }),
+  { timeout: 300_000 },
+);
+
+test(
+  "GET a missing key returns 404",
+  Effect.gen(function* () {
+    const { url } = yield* stack;
+    const response = yield* HttpClient.execute(HttpClientRequest.get(`${url}/no-such-key`));
+    expect(response.status).toBe(404);
+  }),
+  { timeout: 120_000 },
+);
```

`HttpClient` comes with the test harness.

:::tip[Retry the first request]
A new access key and bucket policy can take a moment to apply. Retry the
first request with a bounded schedule, as above.
:::

## Let destroy empty the Bucket

The PUT test leaves `hello.txt` in the Bucket. STACKIT only deletes an empty
bucket, so destroy would fail. This Bucket only holds test data, so let
destroy empty it first:

```diff lang="typescript"
// src/resources.ts
import * as Stackit from "@alchemy.run/stackit";

-export const Files = Stackit.ObjectStorage.Bucket("Bucket", {});
+export const Files = Stackit.ObjectStorage.Bucket("Bucket", {
+  forceDestroy: true,
+});
```

Leave `forceDestroy` off for Buckets that hold data you need to keep.

Destroy reads what you last deployed, so deploy this to your own stage too. Its
Bucket still holds `hello.txt` from Part 2, and a destroy would refuse without it:

```sh
bun alchemy deploy
```

## Destroy after tests in CI

Locally, keep the Stack deployed between runs so tests start fast. In CI,
tear it down:

```diff lang="typescript"
// test/integ.test.ts
const stack = beforeAll(deploy(Stack), { timeout: 1_200_000 });

+afterAll.skipIf(!process.env.CI)(destroy(Stack), { timeout: 900_000 });
```

With `CI=true` the Stack is destroyed after the tests. Without it, `skipIf`
skips the destroy.

## Recap

You now have:

- `Test.make({ providers, state })` wiring STACKIT into the test runner
- `beforeAll(deploy(Stack))` deploying once before the tests
- HTTP assertions against the Function's URL
- `forceDestroy: true` so destroy can delete a Bucket tests wrote to
- `afterAll.skipIf(!process.env.CI)(destroy(Stack))` cleaning up in CI

In [Part 4](/stackit/tutorial/part-4), you give every developer, environment,
and pull request its own copy of the Stack.
