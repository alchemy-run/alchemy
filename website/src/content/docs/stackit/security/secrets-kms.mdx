title: Secrets Manager & KMS
description: Keep API keys in STACKIT Secrets Manager, encrypt data with KMS, know what a host's environment exposes, and protect the state store that holds your Redacted values.
---

Plain config goes in `env`. Credentials go in Secrets Manager, which a host
reads while it runs. Data you need to encrypt goes through KMS, so your code
never holds a key.

## Redacted values are stored unencrypted

`Redacted` keeps a value out of logs. It doesn't encrypt it.

:::caution
Alchemy records every prop in its state store, unencrypted, under a
`__redacted__` marker, as it does for every provider. That covers a
`SecretsManager.Secret`'s `data`, a VPN `preSharedKey`, a database password,
and the service account and access keys Alchemy creates for your hosts.
Anyone who can read the state store can read them. `alchemy state read` prints
them.
:::

## Protect the state store

Treat the state store like the secrets it holds:

- With `Alchemy.localState()`, state sits in `.alchemy/` on your disk. Add
  `.alchemy/` to `.gitignore` and don't copy it anywhere.
- For a team or CI, use a remote store and give its credentials only to the
  people and jobs that deploy. See [State Store](/state-store).
- `Cloudflare.state()` encrypts state at rest, with a key in your account's
  Secrets Store. `AWS.state({ kmsKeyId })` encrypts its table and overflow
  bucket with your own KMS key.
- Rotate a secret if the store leaks. Change the value and deploy.

## Plain config

Values that aren't secret go on the host as environment variables:

```typescript
{ main: import.meta.url, env: { LOG_LEVEL: "info" } }
```

The host reads `process.env.LOG_LEVEL`.

## Know where a host keeps its values

Hosts differ in how they keep a `Redacted` value in `env`, or a key or login
a binding puts there:

:::caution
A [Function](/stackit/compute/functions) stores its environment as plain
revision variables, including `Redacted` ones, so anyone who can call
`GetRevision` can read them. An
[Application](/stackit/compute/container-applications) keeps `Redacted`
values in its environment's secrets.
:::

That applies to the AppRole login and the service account key below too, so
limit who can read a Function's revisions.

## Create a vault

A Secrets Manager instance is a Vault-compatible KV v2 engine with its own
API URL. STACKIT only offers it in `eu01`:

```typescript
// src/resources.ts
import * as Stackit from "@alchemy.run/stackit";
import * as Alchemy from "alchemy";
import * as Effect from "effect/Effect";

export const API_KEY_PATH = "api/key";

export const Vault = Stackit.SecretsManager.Instance("Vault", {
  acls: ["0.0.0.0/0"],
});
```

Everything that reads or writes secrets has to be inside `acls`, or Vault
answers `403 permission denied`. That means the machine that runs your deploy
and each host with a binding. A Function has no fixed egress address, so this
one lets every address reach it, and Vault still asks for a login. Use a
narrower list when your hosts have known addresses.

:::caution[Cost]
STACKIT bills EUR 0.000035-0.000139 per secret version per hour, with a
minimum of 50 secrets per service, so about EUR 0.007 an hour. These rates
come from a snapshot of STACKIT's price page, so check the current one.
:::

## Write a secret

A `Secret` writes its values at deploy. This one generates a value once and
keeps it in state:

```diff lang="typescript"
// src/resources.ts
+export const ApiKeyValue = Alchemy.Random("ApiKeyValue", { bytes: 24 });
+
+export const ApiKey = Effect.gen(function* () {
+  const vault = yield* Vault;
+  const value = yield* ApiKeyValue;
+  return yield* Stackit.SecretsManager.Secret("ApiKey", {
+    instanceId: vault.instanceId,
+    path: API_KEY_PATH,
+    data: { value: value.text },
+  });
+});
```

Attributes hold the key names and the current version, never the values. A
change to `data` writes a new version. Deleting the resource removes every
version, and STACKIT can't restore a secret.

To bring your own value, read it from your environment with
`Config.Redacted("PAYMENTS_API_KEY")` and pass it in `data`.

:::caution[Pass a `Config` as the prop, don't `yield*` it]
A host records every `Config` read while its program is set up as one of its own environment
variables. If a resource a host binds yields a secret in its declaration, that secret reaches the
host, and a Function stores it as a plain revision variable. A `Config` passed as a prop is read by
the deploy, and stays out of the host.
:::

## Read it per request

`ReadSecret` returns a client whose `get` reads the latest version:

```typescript
// src/Api.ts
import * as Stackit from "@alchemy.run/stackit";
import * as Effect from "effect/Effect";
import { HttpServerRequest } from "effect/http/HttpServerRequest";
import * as HttpServerResponse from "effect/http/HttpServerResponse";
import * as Redacted from "effect/Redacted";
import { API_KEY_PATH, Vault } from "./resources.ts";

export default class Api extends Stackit.Functions.Function<Api>()(
  "Api",
  {
    main: import.meta.url,
    registry: { repository: "ghcr.io/my-org/api" },
  },
  Effect.gen(function* () {
    const secrets = yield* Stackit.SecretsManager.ReadSecret(yield* Vault);

    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const { data } = yield* secrets.get({ secretPath: API_KEY_PATH });
        const expected = data.data.value;
        const value = Redacted.isRedacted(expected) ? Redacted.value(expected) : String(expected);

        if (request.headers["x-api-key"] !== value) {
          return yield* HttpServerResponse.json({ error: "denied" }, { status: 401 });
        }
        return HttpServerResponse.text("welcome");
      }).pipe(Effect.orDie),
    };
  }).pipe(Effect.provide(Stackit.SecretsManager.ReadSecretHttp)),
) {}
```

Reading per request means a new version takes effect without a redeploy.

`ReadSecret` grants no STACKIT role. Alchemy creates a read-only AppRole per
host and instance, whose role id and secret id reach the host's environment
as a `Redacted` value.

:::caution
An AppRole **reads every secret in the instance**. STACKIT can't limit one to
a path. Use one instance per trust boundary.
:::

## Write versions from code

`WriteSecret` writes from a host. Provide
`Stackit.SecretsManager.WriteSecretHttp`:

```typescript
const secrets = yield* Stackit.SecretsManager.WriteSecret(yield* Vault);

// inside fetch:
const written = yield* secrets.put({
  secretPath: "payments/api",
  data: { apiKey: Redacted.make("not-a-real-key") },
});
```

STACKIT has no write-only access, so this binding's AppRole reads and writes
every secret in the instance, though its client only exposes writes.
`ReadWriteSecret` exposes both.

## Create a key

A key ring holds keys. A key is versioned material for encryption, signing, or
message authentication:

```diff lang="typescript"
// src/resources.ts
+export const Ring = Stackit.KMS.KeyRing("Ring", {});
+
+export const DataKey = Ring.pipe(
+  Effect.flatMap((ring) =>
+    Stackit.KMS.Key("DataKey", {
+      keyRingId: ring.keyRingId,
+      algorithm: "aes_256_gcm",
+      purpose: "symmetric_encrypt_decrypt",
+    }),
+  ),
+);
```

:::caution[Cost]
A software key version is about EUR 0.0021 an hour, billed per hour or part of
one. STACKIT doesn't say whether a key pending deletion keeps billing until its
`deletionDate`. Check this on your first destroy.
:::

## Encrypt and decrypt

Bind `Encrypt` and `Decrypt`. They take and return raw bytes, and the key
material never leaves KMS:

```typescript
// src/Crypto.ts
import * as Stackit from "@alchemy.run/stackit";
import * as Effect from "effect/Effect";
import { HttpServerRequest } from "effect/http/HttpServerRequest";
import * as HttpServerResponse from "effect/http/HttpServerResponse";
import * as Redacted from "effect/Redacted";
import { DataKey } from "./resources.ts";

export default class Crypto extends Stackit.Functions.Function<Crypto>()(
  "Crypto",
  {
    main: import.meta.url,
    registry: { repository: "ghcr.io/my-org/crypto" },
  },
  Effect.gen(function* () {
    const dataKey = yield* DataKey;
    const encrypt = yield* Stackit.KMS.Encrypt(dataKey);
    const decrypt = yield* Stackit.KMS.Decrypt(dataKey);

    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const { plaintext } = (yield* request.json) as { plaintext: string };

        const encrypted = yield* encrypt({
          plaintext: Redacted.make(new TextEncoder().encode(plaintext)),
        });
        const decrypted = yield* decrypt({
          ciphertext: encrypted.ciphertext,
          version: encrypted.version,
        });

        return yield* HttpServerResponse.json({
          version: encrypted.version,
          roundTrip: new TextDecoder().decode(Redacted.value(decrypted.plaintext)),
        });
      }).pipe(Effect.orDie),
    };
  }).pipe(Effect.provide([Stackit.KMS.EncryptHttp, Stackit.KMS.DecryptHttp])),
) {}
```

Both grant a custom role holding `kms.keyring.get` on the project. That one
permission allows encrypt, decrypt, sign, verify, and every read, on **every key
in the project**. See
[IAM & bindings](/stackit/security/iam-bindings#keep-sensitive-resources-in-their-own-project).

## Sign and verify

Use a key with the purpose `asymmetric_sign_verify`, and bind `Stackit.KMS.Sign`
and `Stackit.KMS.Verify`:

```typescript
Stackit.KMS.Key("SigningKey", {
  keyRingId: ring.keyRingId,
  algorithm: "ecdsa_p256_sha256",
  purpose: "asymmetric_sign_verify",
});
```

They grant the same `kms.keyring.get`.

## Rotate a key

STACKIT has no rotation policy to declare. `RotateKey` creates a new version
from a host, and new `"latest"` calls use it. Provide `Stackit.KMS.RotateKeyHttp`:

```typescript
const rotateKey = yield* Stackit.KMS.RotateKey(dataKey);
```

It grants `kms.keyring.update`, which allows every key and version change on
every key in the project, including `DestroyVersion`.

## Replacing and deleting keys

:::caution
STACKIT has no update for keys or key rings, so changing any prop replaces them.
The replacement is new material, and what the old key encrypted can't be
decrypted with the new one. Re-encrypt your data before the old key's deletion
date.
:::

Deleting a key only schedules its deletion for a `deletionDate` STACKIT picks.
Alchemy treats a key pending deletion as gone, and destroys no key material
itself. Only `Stackit.KMS.DestroyVersion` does.

## Check on your first deploy

- A new instance is ready within 2 minutes. Alchemy waits for
  `creationFinishedDate`.
- A just-created AppRole secret id logs in at once. A deploy doesn't retry the
  login, because repeated failures lock the role out.
- A `write: true` AppRole may write `custom_metadata`, where a secret keeps its
  ownership markers.
- What an instance with no `acls` lets in.
- What a destroyed key looks like while it is pending deletion.
