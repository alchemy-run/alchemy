[Effect Cluster](https://effect.website) is Effect's library for stateful services spread across many machines. Its center is the **entity**: a small, long-lived program with an id and its own state, like one chat room. Effect Cluster runs each entity on one machine at a time, delivers its messages in order, and moves it when machines come and go.

`@alchemy.run/effect-cluster` deploys everything Effect Cluster needs into your Stack, on the cloud you choose, and lets any runtime call your entities by id. This page introduces each concept once, with the chat rooms the [tutorial](/cluster/tutorial/part-1) builds as the example.

Here is the whole picture, which the rest of this page explains piece by piece. A caller names a room; the runners route the message to the runner that owns it; and the room answers from its own state.

## Entities: a class and its instances

An entity starts as a declaration. `Room` says which messages every room accepts, as Effect RPC schemas:

```typescript title="src/Room.ts"
import * as Cluster from "@alchemy.run/effect-cluster";
import { Rpc } from "effect/rpc";
import * as Schema from "effect/Schema";

export class Room extends Cluster.Entity<Room>()("Room", [
  Rpc.make("Join", { payload: { name: Schema.String }, success: Schema.Int }),
  Rpc.make("Members", { success: Schema.Array(Schema.String) }),
]) {}
```

An **instance** is one room: the lobby, the kitchen. Every instance runs the same code against its own state.

See [Entities](/cluster/entities).

## One instance per id, one message at a time

You never create an instance. Every id exists from the start, and the first message to an id brings its instance to life:

```typescript title="src/Api.ts"
import * as Docker from "@alchemy.run/docker";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/http/HttpServerResponse";
import { Room } from "./Room.ts";

export default class Api extends Docker.Service<Api>()(
  "Api",
  { main: import.meta.url, port: 3000 },
  Effect.gen(function* () {
    const rooms = yield* Room;
    return {
      fetch: Effect.gen(function* () {
        const lobby = yield* rooms.getByName("lobby");
        return yield* HttpServerResponse.json({ members: yield* lobby.Join({ name: "sam" }) });
      }).pipe(Effect.orDie),
    };
  }),
) {}
```

However many callers message the lobby, from however many servers, they reach the same instance, and it handles their messages one at a time. That's what lets a room keep its members in a plain `Ref` without locks: nothing else ever touches them.

## The implementation is a Layer

A room's code is its implementation, which you give the declaration with `.make`. It has two phases: the outer Effect runs once per runner and resolves bindings; the inner one runs once per instance, on its first message, and returns its handlers:

```typescript title="src/RoomLive.ts"
import * as Effect from "effect/Effect";
import * as Ref from "effect/Ref";
import { Default } from "./Cluster.ts";
import { Room } from "./Room.ts";

export default Room.make(
  { main: import.meta.url },
  Effect.gen(function* () {
    return Effect.gen(function* () {
      const members = yield* Ref.make(new Set<string>());
      return Room.of({
        Join: ({ payload }) =>
          Ref.modify(members, (all) => {
            const next = new Set(all).add(payload.name);
            return [next.size, next];
          }),
        Members: () => Effect.map(Ref.get(members), (all) => [...all]),
      });
    });
  }).pipe(Effect.provide(Default)),
);
```

An instance's state lives in memory. When it sits idle (a minute, by default), when its runner restarts, or when a deploy replaces the runners, the instance stops and its state is gone. The next message starts it fresh. Keep anything that must survive in a database the instance reads on its first message.

## Runners run the instances

**Runners** are the processes that host instances. A **pool** is a group of runners that run the same code, and `Default` is one:

```typescript title="src/Cluster.ts"
import * as ClusterDocker from "@alchemy.run/effect-cluster/Docker";
import * as Layer from "effect/Layer";

export const Database = ClusterDocker.Database("Cluster");

export const Default = ClusterDocker.SwarmPool("Default", { replicas: 2 }).pipe(
  Layer.provide(Database),
);
```

Providing `Default` to the room's implementation is what deploys it. Every class given the same pool is bundled into one program, built into one image, and run on every runner in the pool.

See [Pools](/cluster/pools).

## Shards and the database

Effect Cluster hashes each instance's id to one of 300 **shards**, and each runner owns some of the shards. A message to the lobby goes to whichever runner owns the lobby's shard.

The runners agree on who owns what through the **database**: a Postgres they all reach. Each runner registers itself there and takes locks on its shards. When a runner stops, its locks lapse, and the others take its shards over, along with the instances in them.

## Persisted messages

By default a message travels straight to its runner. Mark an RPC **persisted**, and the message is written to the database first, delivered at least once, and handled once per primary key:

```typescript title="src/Room.ts"
import * as Cluster from "@alchemy.run/effect-cluster";
import { ClusterSchema } from "effect/cluster";
import { Rpc } from "effect/rpc";
import * as Schema from "effect/Schema";

export class Room extends Cluster.Entity<Room>()("Room", [
  Rpc.make("Post", {
    payload: { messageId: Schema.String, text: Schema.String },
    primaryKey: ({ messageId }) => messageId,
  }).annotate(ClusterSchema.Persisted, true),
]) {}
```

A persisted message survives its runner restarting: whichever runner owns the shard next delivers it.

## The gateway

Callers outside the cluster, like a Worker or a Lambda function, don't reach the database or the runners. They reach the **gateway**: each pool serves its classes over HTTP, behind a token Alchemy binds into every caller. On AWS, GCP and Hetzner a load balancer puts it on the internet; on Fly it's the pool's `fly.dev` address. On [Cloudflare](/cluster/cloudflare) the pool is one Worker and each instance is a Durable Object, so there are no shards and no database.

Inside the cluster, one entity calling another skips the gateway: the call goes straight from runner to runner.

See [Calling an entity](/cluster/calling).

## Workflows, singletons and crons

Effect Cluster runs three more kinds of programs in the same pool, each declared and implemented the same way as an entity:

```typescript title="src/Invite.ts"
import * as Cluster from "@alchemy.run/effect-cluster";
import * as Schema from "effect/Schema";

export class Invite extends Cluster.Workflow<Invite>()("Invite", {
  payload: { room: Schema.String, guest: Schema.String },
  success: Schema.Boolean,
  idempotencyKey: ({ room, guest }) => `${room}/${guest}`,
}) {}
```

A **workflow** is a durable function: each step is persisted, it can sleep for days or wait for a signal, and it picks up where it left off on another runner. A **singleton** is one fiber running on exactly one runner. A **cron** is a job that runs on a schedule, once per scheduled time across the cluster.

See [Workflows](/cluster/workflows), [Singletons](/cluster/singletons) and [Crons](/cluster/crons).
