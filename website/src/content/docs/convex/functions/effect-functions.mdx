---
title: Write functions with Effect
description: Declare Convex queries, mutations and actions with Effect Schema, implement them as Layers, and call them typed from a Worker or Lambda.
---

A Convex function is a declaration and a Layer. The declaration holds the path and the schemas, so a browser, Worker or Lambda can import it to call the function. The Layer holds the code, and runs inside Convex.

Code that Convex bundles imports `@alchemy.run/convex/Server`, which leaves out everything that only runs at deploy:

```typescript
import * as Convex from "@alchemy.run/convex/Server";
```

## Declare a table

A table is an Effect Schema for its documents. Indexes use Convex's own builder:

```typescript
// src/messages.ts
export const Messages = Convex.Table(
  "messages",
  Schema.Struct({
    channel: Schema.String,
    body: Schema.NonEmptyString,
    sentAt: Schema.DateFromMillis,
  }),
  (table) => table.index("by_channel", ["channel"]),
);
```

Convex stores the encoded form, so `sentAt` is a number in the database and a `Date` in your code. Checks such as `NonEmptyString` run when a document is written or read.

## Put it in the schema

```typescript
// convex/schema.ts
import * as Convex from "@alchemy.run/convex/Server";
import { Messages } from "../src/messages.ts";

export default Convex.schema(Messages);
```

## Declare a function

A declaration names its path, arguments, result and failure:

```typescript
// src/messages.ts
export class ListMessages extends Convex.Query<ListMessages>()("messages:list", {
  args: Schema.Struct({ channel: Schema.String }),
  returns: Schema.Array(Messages.Document),
}) {}
```

`Convex.Mutation` and `Convex.Action` declare the other two kinds the same way.

## Implement it with a Layer

The handler reads the table through the transaction it runs in:

```typescript
// src/messages.live.ts
export const ListMessagesLive = Layer.succeed(
  ListMessages,
  Effect.fn(function* ({ channel }) {
    return yield* Messages.query((q) =>
      q.withIndex("by_channel", (r) => r.eq("channel", channel)),
    ).collect;
  }),
);
```

A query only reads. A handler that inserts or schedules from a query doesn't type-check.

## Construct it once

`Layer.effect` gives the handler a constructor. It runs once per Convex isolate, before the first call:

```typescript
export const AddMessageLive = Layer.effect(
  AddMessage,
  Effect.gen(function* () {
    const prefix = yield* Config.String("MESSAGE_PREFIX");
    return Effect.fn(function* ({ channel, body }) {
      return yield* Messages.insert({ channel, body: `${prefix}${body}`, sentAt: new Date() });
    });
  }),
);
```

`Config` reads the deployment's environment variables.

## Serve it

Each export in `convex/` registers one function. Its path is the file and the export name, so `messages:list` is the `list` export of `convex/messages.ts`:

```typescript
// convex/messages.ts
import * as Convex from "@alchemy.run/convex/Server";
import { MessagesLive } from "../src/messages.live.ts";
import { AddMessage, ListMessages } from "../src/messages.ts";

export const list = Convex.serve(ListMessages, MessagesLive);
export const add = Convex.serve(AddMessage, MessagesLive);
```

[Push the app](/convex/functions/functions) with `Convex.Functions`, as any Convex app.

## Fail with a typed error

Declare the failure with `error`. The caller gets the decoded value back:

```typescript
export class EmptyChannel extends Schema.TaggedError<EmptyChannel>()("EmptyChannel", {}) {}

export class AddMessage extends Convex.Mutation<AddMessage>()("messages:add", {
  args: Schema.Struct({ channel: Schema.String, body: Schema.String }),
  returns: Messages.Id,
  error: EmptyChannel,
}) {}
```

A mutation that fails writes nothing: Convex discards every write in the transaction.

## Start work after a mutation commits

A mutation can't call the outside world. It schedules an action instead, and the schedule commits with its writes:

```typescript
const id = yield* Messages.insert({ channel, body, sentAt: new Date() });
yield* Convex.schedule(Notify, { id });
```

Declare `internal: true` on a function only other functions may call.

## Call functions from an action

An action is not a transaction. Each call runs on its own:

```typescript
const messages = yield* Convex.run(ListMessages, { channel });
yield* Convex.run(AddMessage, { channel, body: `${messages.length} messages` });
```

## Bind other resources from an action

An action's constructor takes Alchemy bindings, as a Worker's does:

```typescript
// src/outbox.live.ts
export const OutboxLive = Layer.effect(
  Publish,
  Effect.gen(function* () {
    const send = yield* AWS.SQS.SendMessage(Outbox);
    return Effect.fn(function* ({ body }) {
      yield* send({ MessageBody: body }).pipe(Effect.orDie);
    });
  }),
).pipe(Layer.provide(AWS.SQS.SendMessageHttp));
```

Pass the Layer to `Convex.Functions`. It runs the constructors at deploy, creates what each binding needs, and sets the variables they read on the deployment:

```typescript
yield* Convex.Functions("Functions", {
  deployment,
  rootDir: ".",
  functions: OutboxLive,
});
```

Convex issues no identity a cloud can trust, so an AWS binding gets an IAM user that may only assume a role with the binding's permissions. A file whose actions import a cloud SDK starts with `"use node";`.

## Read the caller's identity

```typescript
const user = yield* Convex.identity;
```

It is `Option.none()` for an anonymous call.

## Call it from a Worker

Pass the declaration to a [calling binding](/convex/functions/calling-functions). Arguments, result and failure are typed by it:

```typescript
const run = yield* Convex.RunQuery(Backend);
const messages = yield* run(ListMessages, { channel: "general" });
```
