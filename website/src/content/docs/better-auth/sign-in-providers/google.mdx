## Install dependencies

```sh
bun add @alchemy.run/better-auth better-auth@1.7.5 kysely
```

Use [Bun](https://bun.sh), matching Alchemy integration releases, and a [configured Cloudflare profile](/cloudflare/setup). This complete application uses Google's server-side authorization-code flow, not the Google browser SDK.

## Define the Auth service and Worker

```typescript
// src/worker.ts
import { BetterAuth } from "@alchemy.run/better-auth";
import { CloudflareD1 } from "@alchemy.run/better-auth/CloudflareD1";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Config from "effect/Config";
import * as Context from "effect/Context";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import * as Option from "effect/Option";
import * as Redacted from "effect/Redacted";
import { HttpServerRequest } from "effect/unstable/http/HttpServerRequest";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

const AuthDb = Cloudflare.D1.Database("AuthDb");
const makeAuth = Effect.gen(function* () {
  const baseURL = yield* Config.String("AUTH_BASE_URL").pipe(Config.option);
  const enabled = yield* Config.Boolean("GOOGLE_ENABLED").pipe(
    Config.withDefault(false),
  );
  const google = enabled
    ? {
        clientId: yield* Config.String("GOOGLE_CLIENT_ID"),
        clientSecret: Redacted.value(
          yield* Config.Redacted("GOOGLE_CLIENT_SECRET"),
        ),
      }
    : undefined;

  return yield* BetterAuth({
    basePath: "/api/auth",
    baseURL: Option.getOrUndefined(baseURL),
    socialProviders: google ? { google } : {},
    account: { accountLinking: { disableImplicitLinking: true } },
  });
});

export class Auth extends Context.Service<
  Auth,
  Effect.Success<typeof makeAuth>
>()("app/Auth") {
  static readonly layer = Layer.effect(Auth, makeAuth);
}

export default class AuthWorker extends Cloudflare.Worker<AuthWorker>()(
  "AuthWorker",
  {
    main: import.meta.url,
    compatibility: { flags: ["nodejs_compat"] },
    assets: { directory: "./public", runWorkerFirst: ["/api/*"] },
  },
  Effect.gen(function* () {
    const auth = yield* Auth;
    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const path = request.url.split("?")[0];
        if (path === "/api/auth" || path.startsWith("/api/auth/")) {
          return yield* auth.fetch;
        }
        if (path === "/api/me") {
          return yield* auth.getSession().pipe(
            Effect.match({
              onFailure: () => HttpServerResponse.text("Session lookup failed", {
                status: 503, headers: { "Cache-Control": "no-store" },
              }),
              onSuccess: (session) => HttpServerResponse.text(
                session ? `Signed in as ${session.user.name}` : "Sign in required",
                { status: session ? 200 : 401, headers: { "Cache-Control": "no-store" } },
              ),
            }),
          );
        }
        return HttpServerResponse.text("Not found", { status: 404 });
      }),
    };
  }).pipe(Effect.provide(Auth.layer.pipe(Layer.provide(CloudflareD1(AuthDb))))),
) {}
```

Alchemy supplies the stable signing secret and supported D1 migrations automatically. The service reads Config during construction, unwrapping the client secret only for Better Auth.

Google starts disabled so the app can print its local URL before callback registration. Without `AUTH_BASE_URL`, Better Auth derives its origin from the request.

## Define the stack

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import AuthWorker from "./src/worker.ts";

export default Alchemy.Stack(
  "GoogleAuth",
  { providers: Cloudflare.providers(), state: Alchemy.localState() },
  Effect.gen(function* () {
    const worker = yield* AuthWorker;
    return { url: worker.url };
  }),
);
```

Preserve the local state directory so subsequent deployments retain resource identities and the signing secret.

## Define the browser actions

```typescript
// src/client.ts
import { createAuthClient } from "better-auth/client";

const authClient = createAuthClient();
const status = document.createElement("p");
status.setAttribute("role", "status");
document.body.append(status);

async function readAccount(): Promise<string> {
  const { data, error } = await authClient.getSession();
  if (error) return "Could not check your session. Try again.";
  if (!data) return "Sign in to continue.";
  const accounts = await authClient.listAccounts();
  if (accounts.error) return "Signed in, but linked accounts could not be checked.";
  return `Signed in as ${data.user.name}. Linked providers: ${
    accounts.data?.map((account) => account.providerId).join(", ") ?? "none"
  }.`;
}

async function startOAuth(link: boolean): Promise<string> {
  if (link) {
    const session = await authClient.getSession();
    if (session.error || !session.data) return "Sign in with your existing account first.";
  }
  const options = { provider: "google" as const, callbackURL: "/", disableRedirect: true };
  const { data, error } = link
    ? await authClient.linkSocial(options)
    : await authClient.signIn.social(options);
  if (error) return "Could not start Google authorization. Check your account and retry.";
  if (!data?.url) return "No authorization URL was returned.";
  window.location.assign(data.url);
  return "Redirecting to Google…";
}

async function run(action: () => Promise<string>) {
  try {
    status.textContent = await action();
  } catch {
    status.textContent = "Could not reach the server. Try again.";
  }
}

function button(label: string, action: () => Promise<string>) {
  const element = document.createElement("button");
  element.textContent = label;
  element.addEventListener("click", () => void run(action));
  document.body.append(element);
}

button("Sign in with Google", () => startOAuth(false));
button("Link Google to this account", () => startOAuth(true));
button("Check session and linked accounts", readAccount);
button("Sign out", async () => {
  const { error } = await authClient.signOut();
  return error ? "Could not sign out. Try again." : "Signed out.";
});
void run(readAccount);
```

The same-origin client creates its own controls and renders safe text for initiation or network failures. After a successful return to `/`, it checks the actual session and linked accounts.

## Discover the local origin

```sh
bun build ./src/client.ts --target browser --outdir ./public
bunx alchemy dev --stage google-guide
```

Alchemy allocates an available port and prints the URL; open it, but wait to start sign-in until Google is configured. Rebuild the browser module after editing it.

## Configure the consent screen

In the [Google Cloud console](https://console.cloud.google.com/), select your project and open **Google Auth platform → Branding → Get started**. Enter the app name, support email, and developer contact information, then supply the production homepage, privacy policy, and authorized domain before publishing.

In **Audience**, use **Internal** only for an eligible Workspace organization whose users should have access; otherwise choose **External**. For an External app in testing, add the accounts that will exercise the integration under **Audience → Test users**.

In **Data Access**, configure only `openid`, `email`, and `profile` for ordinary sign-in. Before public launch, review publishing status and any required brand or scope verification; Workspace administrators can impose additional restrictions.

Google's [OAuth consent guide](https://developers.google.com/workspace/guides/configure-oauth-consent) describes these settings. Testing-mode access is not a production rollout.

## Register a web client

```text
/api/auth/callback/google
```

Append this path to the printed local origin for the **Authorized redirect URI**. Under **Google Auth platform → Clients → Create client**, choose **Web application**, register that exact URI, and securely copy the client ID and secret.

Authorized JavaScript origins are not a substitute for redirect URIs, and this flow does not need the Google browser SDK. Google's [web-server OAuth guide](https://developers.google.com/identity/protocols/oauth2/web-server) documents exact redirect matching.

## Supply server configuration

```dotenv
# .env.local
GOOGLE_ENABLED=true
GOOGLE_CLIENT_ID=replace-with-your-client-id
GOOGLE_CLIENT_SECRET=replace-with-your-client-secret
```

Keep this file gitignored and replace the values with your web client's credentials. Stop the first dev process and restart with the server-side configuration:

```sh
bunx alchemy dev --stage google-guide --env-file .env.local
```

If the printed origin changes, update Google's redirect registration before signing in. An optional `AUTH_BASE_URL` override must match that origin without a trailing slash or `/api/auth`.

In production, use separate credentials and set `AUTH_BASE_URL` to the actual HTTPS Worker origin. For a Worker at `https://auth.example.com`, register `https://auth.example.com/api/auth/callback/google`; `baseURL` alone does not attach that domain.

Never put secrets in `VITE_*`, browser code, source control, or logs. Better Auth supplies `openid`, `email`, and `profile` by default; do not add API scopes or force consent merely to create a session.

## Keep account linking explicit

The Link button first checks for a session and then uses `linkSocial`; the returned page confirms linked providers with `listAccounts`. When adding other sign-in methods, require existing users to authenticate with their original method before linking Google.

Keep `disableImplicitLinking: true`, verified-email checks, and the same-email restriction. Do not add `trustedProviders`, enable `allowDifferentEmails`, or manually merge rows to suppress a collision.

Google's stable subject identifies the provider account; an email suffix or hosted-domain login hint alone is not an application authorization policy. Keep a working sign-in method before unlinking an account.

## Diagnose failures

Better Auth displays callback failures on its built-in `/api/auth/error` page. Do not add a custom error query flag or disable state, PKCE, origin, or CSRF checks.

For `redirect_uri_mismatch`, compare the registered URI with the current origin and `/api/auth/callback/google`. For `access_denied` or `org_internal`, check audience, test users, publishing status, and Workspace policy.

For `invalid_client`, verify the credential pair and rotate revoked or expired secrets. Restart sign-in after fixing configuration, and never log credentials, tokens, or complete callback URLs.
