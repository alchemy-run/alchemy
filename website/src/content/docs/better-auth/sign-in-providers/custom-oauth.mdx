## Create the project

```sh
mkdir company-auth
cd company-auth
bun init -y
bun add alchemy @alchemy.run/better-auth better-auth@1.7.5 "effect@4.0.0-rc.115" kysely
mkdir -p src public
```

Use [Bun](https://bun.sh), matching Alchemy integration releases, and a [configured Cloudflare profile](/cloudflare/setup). Better Auth 1.7.5 registers `genericOAuth` providers as social providers, using `signIn.social` and `/api/auth/callback/company`, not the older `signIn.oauth2` flow.

## Define the Auth service and Worker

```typescript
// src/worker.ts
import { BetterAuth } from "@alchemy.run/better-auth";
import { CloudflareD1 } from "@alchemy.run/better-auth/CloudflareD1";
import * as Cloudflare from "alchemy/Cloudflare";
import { genericOAuth } from "better-auth/plugins/generic-oauth";
import * as Config from "effect/Config";
import * as Context from "effect/Context";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import * as Option from "effect/Option";
import * as Redacted from "effect/Redacted";
import { HttpServerRequest } from "effect/unstable/http/HttpServerRequest";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

const AuthDb = Cloudflare.D1.Database("AuthDb");
const makeAuth = Effect.gen(function* () {
  const baseURL = yield* Config.String("AUTH_BASE_URL").pipe(Config.option);
  const enabled = yield* Config.Boolean("OIDC_ENABLED").pipe(
    Config.withDefault(false),
  );
  const provider = enabled
    ? genericOAuth({
        config: [{
          providerId: "company",
          clientId: yield* Config.String("OIDC_CLIENT_ID"),
          clientSecret: Redacted.value(yield* Config.Redacted("OIDC_CLIENT_SECRET")),
          discoveryUrl: yield* Config.String("OIDC_DISCOVERY_URL"),
          scopes: ["openid", "profile", "email"],
          pkce: true,
          authentication: "basic",
          requireIdTokenVerification: true,
          requireEmailVerification: true,
          disableProviderLogout: true,
        }],
      })
    : undefined;

  return yield* BetterAuth({
    basePath: "/api/auth",
    baseURL: Option.getOrUndefined(baseURL),
    plugins: provider ? [provider] : [],
    account: { accountLinking: { disableImplicitLinking: true } },
  });
});

export class Auth extends Context.Service<
  Auth,
  Effect.Success<typeof makeAuth>
>()("app/Auth") {
  static readonly layer = Layer.effect(Auth, makeAuth);
}

export default class AuthWorker extends Cloudflare.Worker<AuthWorker>()(
  "AuthWorker",
  {
    main: import.meta.url,
    compatibility: { flags: ["nodejs_compat"] },
    assets: { directory: "./public", runWorkerFirst: ["/api/*"] },
  },
  Effect.gen(function* () {
    const auth = yield* Auth;
    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const path = request.url.split("?")[0];
        if (path === "/api/auth" || path.startsWith("/api/auth/")) {
          return yield* auth.fetch;
        }
        if (path === "/api/me") {
          return yield* auth.getSession().pipe(
            Effect.match({
              onFailure: () => HttpServerResponse.text("Session lookup failed", {
                status: 503, headers: { "Cache-Control": "no-store" },
              }),
              onSuccess: (session) => HttpServerResponse.text(
                session ? `Signed in as ${session.user.name}` : "Sign in required",
                { status: session ? 200 : 401, headers: { "Cache-Control": "no-store" } },
              ),
            }),
          );
        }
        return HttpServerResponse.text("Not found", { status: 404 });
      }),
    };
  }).pipe(Effect.provide(Auth.layer.pipe(Layer.provide(CloudflareD1(AuthDb))))),
) {}
```

Alchemy provisions the stable signing secret and supported D1 migrations automatically. Config is read at service construction, and OIDC starts disabled so you can discover the local origin before registering its callback.

This configuration uses HTTP Basic client authentication at the token endpoint, which Keycloak supports for client-secret clients. Match the registered authentication method when adapting it to another vendor.

`requireIdTokenVerification` fails closed when discovery lacks verification metadata, and nonce binding remains enabled. `disableProviderLogout` keeps application sign-out local rather than terminating a shared Keycloak SSO session.

## Define the stack

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import AuthWorker from "./src/worker.ts";

export default Alchemy.Stack(
  "CompanyAuth",
  { providers: Cloudflare.providers(), state: Alchemy.localState() },
  Effect.gen(function* () {
    const worker = yield* AuthWorker;
    return { url: worker.url };
  }),
);
```

Preserve the local state directory so later deployments retain resource identities and the signing secret.

## Define the browser actions

```typescript
// src/client.ts
import { createAuthClient } from "better-auth/client";

const authClient = createAuthClient();
const status = document.createElement("p");
status.setAttribute("role", "status");
document.body.append(status);

async function readAccount(): Promise<string> {
  const { data, error } = await authClient.getSession();
  if (error) return "Could not check your session. Try again.";
  if (!data) return "Sign in to continue.";
  const accounts = await authClient.listAccounts();
  if (accounts.error) return "Signed in, but linked accounts could not be checked.";
  return `Signed in as ${data.user.name}. Linked providers: ${
    accounts.data?.map((account) => account.providerId).join(", ") ?? "none"
  }.`;
}

async function startOAuth(link: boolean): Promise<string> {
  if (link) {
    const session = await authClient.getSession();
    if (session.error || !session.data) return "Sign in with your existing account first.";
  }
  const options = { provider: "company" as const, callbackURL: "/", disableRedirect: true };
  const { data, error } = link
    ? await authClient.linkSocial(options)
    : await authClient.signIn.social(options);
  if (error) return "Could not start company authorization. Check your account and retry.";
  if (!data?.url) return "No authorization URL was returned.";
  window.location.assign(data.url);
  return "Redirecting to company sign-in…";
}

async function run(action: () => Promise<string>) {
  try {
    status.textContent = await action();
  } catch {
    status.textContent = "Could not reach the server. Try again.";
  }
}

function button(label: string, action: () => Promise<string>) {
  const element = document.createElement("button");
  element.textContent = label;
  element.addEventListener("click", () => void run(action));
  document.body.append(element);
}

button("Sign in with company", () => startOAuth(false));
button("Link company to this account", () => startOAuth(true));
button("Check session and linked accounts", readAccount);
button("Sign out", async () => {
  const { error } = await authClient.signOut();
  return error ? "Could not sign out. Try again." : "Signed out.";
});
void run(readAccount);
```

No `genericOAuthClient` plugin is needed for this 1.7.5 flow. The same-origin client creates its controls and checks the session and linked providers on the returned `/` page.

## Discover the local origin

```sh
bun build ./src/client.ts --target browser --outdir ./public
bunx alchemy dev --stage company-guide
```

Alchemy allocates an available port and prints the URL; use this actual origin when registering Keycloak. Rebuild the browser module after editing it, and wait to start sign-in until the provider is configured.

## Create the Keycloak client

```text
/api/auth/callback/company
```

Append this path to the printed origin for the redirect URI. In Keycloak, select your application realm rather than the administration realm, then open **Clients → Create client** and select **OpenID Connect**.

Set a client ID such as `alchemy-auth`, enable **Client authentication** and **Standard flow**, and leave implicit flow and direct access grants disabled. In **Login settings**, set the home URL to the printed origin and add the exact callback to **Valid redirect URIs**, without wildcards.

Save the client and copy the secret from **Credentials**. Keep code exchange on the server; never provide the client secret to the browser.

## Configure identity claims

Require S256 PKCE in the client's advanced settings where available, and ensure the `profile` and `email` scopes supply `sub`, `name`, `email`, and `email_verified`. Configure real realm email delivery and verification before relying on `email_verified`, rather than marking arbitrary addresses verified.

Use verified realm users for this configuration. Keycloak's [server administration guide](https://www.keycloak.org/docs/latest/server_admin/#_oidc_clients) covers clients, and its [OIDC guide](https://www.keycloak.org/securing-apps/oidc-layers) describes discovery endpoints.

## Supply server configuration

```dotenv
# .env.local
OIDC_ENABLED=true
OIDC_CLIENT_ID=alchemy-auth
OIDC_CLIENT_SECRET=replace-with-your-client-secret
OIDC_DISCOVERY_URL=https://identity.example.com/realms/my-app/.well-known/openid-configuration
```

Keep this file gitignored and replace the client values and discovery URL with your real realm configuration. Discovery must be reachable from the Worker and publish the expected issuer, authorization/token endpoints, signing algorithms, and `jwks_uri`.

```sh
bunx alchemy dev --stage company-guide --env-file .env.local
```

Stop the first dev process before restarting with configuration, and update Keycloak's callback if the printed origin changes. Without `AUTH_BASE_URL`, the request origin is used; an override must match that origin without a trailing slash or `/api/auth`.

Use HTTPS and separate clients or realms in production, with `AUTH_BASE_URL` set to the actual Worker origin. A Worker served at `https://auth.example.com` requires `https://auth.example.com/api/auth/callback/company`; `baseURL` does not attach that domain.

Keep all secrets out of `VITE_*`, browser bundles, source control, and logs. Do not disable ID-token verification, nonce binding, state, or origin checks to accommodate broken discovery or callback registration.

## Preserve identity and linking safety

The provider ID `company` determines the callback path and stored provider identity; do not rename it or point it at an unrelated issuer after users link accounts. Discovery-based OIDC uses the verified provider profile's `sub` as the account subject, not a mutable email address.

The Link button requires an existing session and confirms linked providers on return. When adding another sign-in method, have users authenticate with their existing method before explicitly linking `company`.

Keep `disableImplicitLinking: true`, verified-email checks, and the same-email restriction. Do not add `company` to `trustedProviders`, enable different-email linking, or merge rows just to bypass an ownership failure.

Retain a working sign-in method before unlinking. Remove `disableProviderLogout` only after deliberately configuring and reviewing provider-wide logout and its registered return URLs.

## Adapt another provider

The complete Worker above is the configuration point for other providers; preserve existing plugins when adding `genericOAuth` to an application. For plain OAuth, use reviewed `authorizationUrl`, `tokenUrl`, and `userInfoUrl` settings rather than OIDC discovery.

Plain OAuth defaults to the raw profile's immutable `id`; nonstandard identity fields require an `accountSubject` resolver and possibly `getUserInfo` or `mapProfileToUser`. Do not merely remove verification from the OIDC example: review token authentication, PKCE, profile identity, and email trust for the vendor first.

## Diagnose failures

Better Auth displays callback failures on its built-in `/api/auth/error` page, without an application error query flag. For an unknown provider, check discovery reachability and issuer/JWKS metadata; for callback mismatches, compare the exact `/api/auth/callback/company` registration.

`requireEmailVerification` checks local user verification and can leave a created or linked account without a session. An existing unverified local user needs a real local email-verification flow before retrying, not a database edit to mark the user verified.

For `email_not_verified`, review both issuer and local verification state; for token-exchange failures, compare the secret and authentication method. Restart sign-in after a fix instead of replaying codes, and never log secrets, ID tokens, or full callback URLs.
