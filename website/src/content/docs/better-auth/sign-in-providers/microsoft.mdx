## Install dependencies

```sh
bun add @alchemy.run/better-auth better-auth@1.7.5 kysely
```

Use [Bun](https://bun.sh), matching Alchemy integration releases, and a [configured Cloudflare profile](/cloudflare/setup). The complete application below uses Better Auth 1.7.5's built-in `microsoft` provider, including for Microsoft Entra ID.

## Define the Auth service and Worker

```typescript
// src/worker.ts
import { BetterAuth } from "@alchemy.run/better-auth";
import { CloudflareD1 } from "@alchemy.run/better-auth/CloudflareD1";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Config from "effect/Config";
import * as Context from "effect/Context";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import * as Option from "effect/Option";
import * as Redacted from "effect/Redacted";
import { HttpServerRequest } from "effect/unstable/http/HttpServerRequest";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

const AuthDb = Cloudflare.D1.Database("AuthDb");
const makeAuth = Effect.gen(function* () {
  const baseURL = yield* Config.String("AUTH_BASE_URL").pipe(Config.option);
  const enabled = yield* Config.Boolean("MICROSOFT_ENABLED").pipe(
    Config.withDefault(false),
  );
  const microsoft = enabled
    ? {
        clientId: yield* Config.String("MICROSOFT_CLIENT_ID"),
        clientSecret: Redacted.value(
          yield* Config.Redacted("MICROSOFT_CLIENT_SECRET"),
        ),
        tenantId: yield* Config.String("MICROSOFT_TENANT_ID"),
        disableProfilePhoto: true,
        disableDefaultScope: true,
        scope: ["openid", "profile", "email"],
      }
    : undefined;

  return yield* BetterAuth({
    basePath: "/api/auth",
    baseURL: Option.getOrUndefined(baseURL),
    socialProviders: microsoft ? { microsoft } : {},
    account: { accountLinking: { disableImplicitLinking: true } },
  });
});

export class Auth extends Context.Service<
  Auth,
  Effect.Success<typeof makeAuth>
>()("app/Auth") {
  static readonly layer = Layer.effect(Auth, makeAuth);
}

export default class AuthWorker extends Cloudflare.Worker<AuthWorker>()(
  "AuthWorker",
  {
    main: import.meta.url,
    compatibility: { flags: ["nodejs_compat"] },
    assets: { directory: "./public", runWorkerFirst: ["/api/*"] },
  },
  Effect.gen(function* () {
    const auth = yield* Auth;
    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const path = request.url.split("?")[0];
        if (path === "/api/auth" || path.startsWith("/api/auth/")) {
          return yield* auth.fetch;
        }
        if (path === "/api/me") {
          return yield* auth.getSession().pipe(
            Effect.match({
              onFailure: () => HttpServerResponse.text("Session lookup failed", {
                status: 503, headers: { "Cache-Control": "no-store" },
              }),
              onSuccess: (session) => HttpServerResponse.text(
                session ? `Signed in as ${session.user.name}` : "Sign in required",
                { status: session ? 200 : 401, headers: { "Cache-Control": "no-store" } },
              ),
            }),
          );
        }
        return HttpServerResponse.text("Not found", { status: 404 });
      }),
    };
  }).pipe(Effect.provide(Auth.layer.pipe(Layer.provide(CloudflareD1(AuthDb))))),
) {}
```

Alchemy provisions the stable signing secret and supported D1 migrations automatically. The service reads Config during construction, and Microsoft stays disabled until credentials and an explicit tenant are supplied.

This sign-in-only configuration omits Graph photos and offline access. The defaults also request `User.Read` and `offline_access`; enable those features only with the corresponding delegated permissions and consent.

## Define the stack

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import AuthWorker from "./src/worker.ts";

export default Alchemy.Stack(
  "MicrosoftAuth",
  { providers: Cloudflare.providers(), state: Alchemy.localState() },
  Effect.gen(function* () {
    const worker = yield* AuthWorker;
    return { url: worker.url };
  }),
);
```

Preserve the local state directory so later deployments retain resource identities and the signing secret.

## Define the browser actions

```typescript
// src/client.ts
import { createAuthClient } from "better-auth/client";

const authClient = createAuthClient();
const status = document.createElement("p");
status.setAttribute("role", "status");
document.body.append(status);

async function readAccount(): Promise<string> {
  const { data, error } = await authClient.getSession();
  if (error) return "Could not check your session. Try again.";
  if (!data) return "Sign in to continue.";
  const accounts = await authClient.listAccounts();
  if (accounts.error) return "Signed in, but linked accounts could not be checked.";
  return `Signed in as ${data.user.name}. Linked providers: ${
    accounts.data?.map((account) => account.providerId).join(", ") ?? "none"
  }.`;
}

async function startOAuth(link: boolean): Promise<string> {
  if (link) {
    const session = await authClient.getSession();
    if (session.error || !session.data) return "Sign in with your existing account first.";
  }
  const options = { provider: "microsoft" as const, callbackURL: "/", disableRedirect: true };
  const { data, error } = link
    ? await authClient.linkSocial(options)
    : await authClient.signIn.social(options);
  if (error) return "Could not start Microsoft authorization. Check your account and retry.";
  if (!data?.url) return "No authorization URL was returned.";
  window.location.assign(data.url);
  return "Redirecting to Microsoft…";
}

async function run(action: () => Promise<string>) {
  try {
    status.textContent = await action();
  } catch {
    status.textContent = "Could not reach the server. Try again.";
  }
}

function button(label: string, action: () => Promise<string>) {
  const element = document.createElement("button");
  element.textContent = label;
  element.addEventListener("click", () => void run(action));
  document.body.append(element);
}

button("Sign in with Microsoft", () => startOAuth(false));
button("Link Microsoft to this account", () => startOAuth(true));
button("Check session and linked accounts", readAccount);
button("Sign out", async () => {
  const { error } = await authClient.signOut();
  return error ? "Could not sign out. Try again." : "Signed out.";
});
void run(readAccount);
```

The same-origin client creates its own buttons and displays results as text. A successful callback returns to `/`, where the module checks the session and linked accounts.

## Discover the local origin

```sh
bun build ./src/client.ts --target browser --outdir ./public
bunx alchemy dev --stage microsoft-guide
```

Alchemy allocates an available port and prints the URL; use that actual origin for registration. Rebuild the browser module after editing it, and wait to start sign-in until Microsoft is configured.

## Register the Entra application

Open the [Microsoft Entra admin center](https://entra.microsoft.com/) in the intended directory and select **Entra ID → App registrations → New registration**. Choose a name and supported account types deliberately, then record **Application (client) ID** and **Directory (tenant) ID** from **Overview**.

For a company-only app, choose the single-tenant option and use the directory's tenant GUID. For a multitenant product, choose organizational accounts, organizational plus personal accounts, or personal accounts to match the intended audience.

Microsoft's [app registration guide](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app) describes the registration process. A multitenant endpoint is not an allowlist of customer organizations: enforce tenant authorization and application membership on the server.

## Register Web callbacks

```text
/api/auth/callback/microsoft
```

Append this path to the printed local origin and register it under **Authentication → Add a platform → Web**. Use **Web**, not **Single-page application**, because Better Auth exchanges the code on the server with a client secret.

Do not enable implicit grants for this authorization-code flow. Register exact callbacks rather than wildcards and use a separate application registration for production isolation.

## Supply server configuration

```dotenv
# .env.local
MICROSOFT_ENABLED=true
MICROSOFT_CLIENT_ID=replace-with-application-client-id
MICROSOFT_CLIENT_SECRET=replace-with-secret-value
MICROSOFT_TENANT_ID=replace-with-directory-tenant-guid
```

Under **Certificates & secrets → Client secrets → New client secret**, copy the secret **Value**, not its **Secret ID**, into this gitignored file. Choose an expiry and arrange rotation before it expires.

For a matching multitenant registration, `organizations` admits work/school accounts, `consumers` admits personal accounts, and `common` admits both classes. The code requires an explicit `MICROSOFT_TENANT_ID` rather than silently using `common`.

```sh
bunx alchemy dev --stage microsoft-guide --env-file .env.local
```

Stop the first dev process before restarting with configuration, and update the registered callback if the printed origin changes. Without `AUTH_BASE_URL`, the request origin is used; an override must match the actual origin without a trailing slash or `/api/auth`.

For production, use separate credentials and set `AUTH_BASE_URL` to the actual HTTPS Worker origin. A Worker at `https://auth.example.com` requires `https://auth.example.com/api/auth/callback/microsoft`; `baseURL` does not attach a Worker domain.

Keep credentials server-only, outside `VITE_*`, browser bundles, source control, and logs. Email domains and login hints are not proof of tenant membership.

## Preserve identity and linking safety

The built-in 1.7.5 provider derives the account subject from Microsoft's `oid`. Do not substitute mutable email addresses or `preferred_username`, or assume one person has the same identity in every tenant.

Microsoft does not always supply an email or a trustworthy verification signal. Do not fabricate an address, map all emails to `emailVerified: true`, or add Microsoft to `trustedProviders` to bypass a failure.

The Link button requires an existing session and confirms linked providers after returning. When adding another sign-in method, have an existing user authenticate with it first, then link Microsoft deliberately.

Keep `disableImplicitLinking: true`, provider-email verification, and the same-email restriction. If linking checks cannot be satisfied, use an audited ownership-verification flow rather than enabling different-email linking or merging rows by email.

Keep a working sign-in method before unlinking an account. Session presence alone also does not authorize access to a particular tenant's data.

## Diagnose failures

Better Auth handles callback failures on its built-in `/api/auth/error` page. Keep state, PKCE, origin, and CSRF protections enabled rather than introducing custom error query flags or bypasses.

For `AADSTS50011`, compare the exact Web callback registration with the origin and `/api/auth/callback/microsoft`. For client failures, check the secret value, matching client ID, and expiry.

For tenant or consent errors, check supported account types, tenant configuration, user assignment, and administrator consent before widening access. For missing email, inspect your tenant's claim configuration without logging tokens or full callback URLs.
