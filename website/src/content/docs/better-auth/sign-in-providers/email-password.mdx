## Define the Auth service and mail transport

```typescript
// src/worker.ts
import { BetterAuth } from "@alchemy.run/better-auth";
import { CloudflareD1 } from "@alchemy.run/better-auth/CloudflareD1";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Config from "effect/Config";
import * as Context from "effect/Context";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import * as Option from "effect/Option";
import * as FetchHttpClient from "effect/unstable/http/FetchHttpClient";
import * as HttpClient from "effect/unstable/http/HttpClient";
import * as HttpClientRequest from "effect/unstable/http/HttpClientRequest";
import * as HttpClientResponse from "effect/unstable/http/HttpClientResponse";
import { HttpServerRequest } from "effect/unstable/http/HttpServerRequest";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

const AuthDb = Cloudflare.D1.Database("AuthDb");
const makeAuth = Effect.gen(function* () {
  const baseURL = yield* Config.String("AUTH_BASE_URL").pipe(Config.option);
  const from = yield* Config.String("AUTH_EMAIL_FROM");
  const apiKey = yield* Config.Redacted("RESEND_API_KEY");
  const http = yield* HttpClient.HttpClient;

  const sendMail = (to: string, subject: string, text: string) =>
    Effect.gen(function* () {
      const response = yield* http.execute(
        HttpClientRequest.post("https://api.resend.com/emails").pipe(
          HttpClientRequest.bearerToken(apiKey),
          HttpClientRequest.bodyJsonUnsafe({ from, to: [to], subject, text }),
        ),
      );
      yield* HttpClientResponse.filterStatusOk(response);
      yield* response.text;
    }).pipe(
      Effect.timeout("10 seconds"),
      Effect.mapError(() => new Error("Email delivery failed")),
      Effect.scoped,
      Effect.runPromise,
    );

  return yield* BetterAuth({
    basePath: "/api/auth",
    baseURL: Option.getOrUndefined(baseURL),
    account: { accountLinking: { disableImplicitLinking: true } },
    emailAndPassword: {
      enabled: true,
      requireEmailVerification: true,
      revokeSessionsOnPasswordReset: true,
      sendResetPassword: ({ user, url }) =>
        sendMail(user.email, "Reset your password", `Reset your password: ${url}`),
    },
    emailVerification: {
      sendOnSignUp: true,
      autoSignInAfterVerification: false,
      sendVerificationEmail: ({ user, url }) =>
        sendMail(user.email, "Verify your email", `Verify your email: ${url}`),
    },
  });
});

export class Auth extends Context.Service<
  Auth,
  Effect.Success<typeof makeAuth>
>()("app/Auth") {
  static readonly layer = Layer.effect(Auth, makeAuth);
}

export default class AuthWorker extends Cloudflare.Worker<AuthWorker>()(
  "AuthWorker",
  {
    main: import.meta.url,
    compatibility: { flags: ["nodejs_compat"] },
    assets: { directory: "./public", runWorkerFirst: ["/api/*"] },
  },
  Effect.gen(function* () {
    const auth = yield* Auth;
    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const path = request.url.split("?")[0];
        if (path === "/api/auth" || path.startsWith("/api/auth/")) {
          return yield* auth.fetch;
        }
        if (path === "/api/me") {
          return yield* auth.getSession().pipe(
            Effect.match({
              onFailure: () => HttpServerResponse.text("Session lookup failed", {
                status: 503, headers: { "Cache-Control": "no-store" },
              }),
              onSuccess: (session) => HttpServerResponse.text(
                session ? `Signed in as ${session.user.name}` : "Sign in required",
                { status: session ? 200 : 401, headers: { "Cache-Control": "no-store" } },
              ),
            }),
          );
        }
        return HttpServerResponse.text("Not found", { status: 404 });
      }),
    };
  }).pipe(
    Effect.provide(Auth.layer.pipe(
      Layer.provide(CloudflareD1(AuthDb)),
      Layer.provide(FetchHttpClient.layer),
    )),
  ),
) {}
```

Alchemy supplies the stable signing secret and supported D1 migrations automatically. The host supplies both the database and HTTP layers; no service or transport from another page is required.

Each upstream mail hook bridges one bounded Effect request to a Promise, without retaining a connection or in-flight request between Worker events. The bearer-token helper accepts the redacted key directly, and generated verification/reset URLs are sent unchanged as plain text.

Verification is required before a session is issued, and users sign in after verifying. Better Auth's default password length range is 8–128 characters; keep server-side validation authoritative.

## Define the stack

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import AuthWorker from "./src/worker.ts";

export default Alchemy.Stack(
  "EmailAuth",
  { providers: Cloudflare.providers(), state: Alchemy.localState() },
  Effect.gen(function* () {
    const worker = yield* AuthWorker;
    return { url: worker.url };
  }),
);
```

Preserve the local state directory so subsequent deployments retain resource identities and the signing secret.

## Define the browser actions

```typescript
// src/client.ts
import { createAuthClient } from "better-auth/client";

const authClient = createAuthClient();
const form = document.querySelector<HTMLFormElement>("#credentials")!;
const nameInput = document.querySelector<HTMLInputElement>("#name")!;
const emailInput = document.querySelector<HTMLInputElement>("#email")!;
const passwordInput = document.querySelector<HTMLInputElement>("#password")!;
const status = document.createElement("p");
status.setAttribute("role", "status");
document.body.append(status);
form.addEventListener("submit", (event) => event.preventDefault());

const query = new URLSearchParams(window.location.search);
let resetToken = query.get("token");
const invalidEmailLink = query.has("error");
window.history.replaceState(null, "", window.location.pathname);

async function readAccount(): Promise<string> {
  const { data, error } = await authClient.getSession();
  if (error) return "Could not check your session. Try again.";
  return data ? `Signed in as ${data.user.name}.` : "Verify your email, then sign in.";
}

async function run(action: () => Promise<string>) {
  const buttons = document.querySelectorAll<HTMLButtonElement>("button");
  buttons.forEach((element) => { element.disabled = true; });
  try {
    status.textContent = await action();
  } catch {
    status.textContent = "Could not reach the server. Try again.";
  } finally {
    passwordInput.value = "";
    buttons.forEach((element) => { element.disabled = false; });
  }
}

function button(label: string, action: () => Promise<string>) {
  const element = document.createElement("button");
  element.type = "button";
  element.textContent = label;
  element.addEventListener("click", () => void run(action));
  document.body.append(element);
}

button("Register", async () => {
  const { error } = await authClient.signUp.email({
    name: nameInput.value,
    email: emailInput.value,
    password: passwordInput.value,
    callbackURL: "/",
  });
  return error
    ? "Could not register. Check your details and try again."
    : "Check your inbox to verify your email, then sign in.";
});

button("Sign in", async () => {
  const { data, error } = await authClient.signIn.email({
    email: emailInput.value,
    password: passwordInput.value,
  });
  if (error?.code === "EMAIL_NOT_VERIFIED") return "Verify your email first.";
  if (error) return "Could not sign in. Check your email and password.";
  if (!data?.user) return "Sign-in did not finish. Try again.";
  return readAccount();
});

let nextVerificationRequest = 0;
button("Resend verification", async () => {
  if (Date.now() < nextVerificationRequest) return "Wait a minute before requesting another email.";
  nextVerificationRequest = Date.now() + 60_000;
  const { error } = await authClient.sendVerificationEmail({
    email: emailInput.value,
    callbackURL: "/",
  });
  return error
    ? "Could not request verification. Try again later."
    : "If this address needs verification, check its inbox.";
});

button("Request password reset", async () => {
  const { error } = await authClient.requestPasswordReset({
    email: emailInput.value,
    redirectTo: "/",
  });
  return error
    ? "Could not request a reset. Try again later."
    : "If this email has an account, check its inbox for a reset link.";
});

button("Save new password", async () => {
  if (invalidEmailLink || !resetToken) return "Open a new password reset link first.";
  const { error } = await authClient.resetPassword({
    token: resetToken,
    newPassword: passwordInput.value,
  });
  if (error) return "Could not reset your password. Request a new link.";
  resetToken = null;
  return "Password reset. Sign in with your new password.";
});

button("Check session", readAccount);
button("Sign out", async () => {
  const { error } = await authClient.signOut();
  return error ? "Could not sign out. Try again." : "Signed out.";
});

if (invalidEmailLink) {
  status.textContent = "This email link is invalid or expired. Request a new verification or reset message.";
} else if (resetToken) {
  status.textContent = "Enter your new password and choose Save new password.";
} else {
  void run(readAccount);
}
```

The same-origin client imports no server credentials and renders fixed error messages as text. The Worker checks `/api/me` independently, so a browser status message never grants access to private data.

Verification links pass through `/api/auth/verify-email`, while reset links pass through `/api/auth/reset-password/<token>` before returning to `/`. The browser removes reset tokens from the address bar and retains them only in memory; reloading requires reopening the email link.

Reset tokens are single-use, and the server configuration revokes existing sessions after a reset. Never persist passwords or tokens in browser storage, and keep server rate limiting enabled; the resend cooldown is only a UI convenience.

## Configure real email delivery

```dotenv
# .env.local
RESEND_API_KEY=replace-with-your-sending-key
AUTH_EMAIL_FROM="Auth <auth@your-verified-domain.example>"
```

In [Resend](https://resend.com/docs/api-reference/emails/send-email), add a domain, publish its DNS records, and wait for verification. Create a key with sending access to that domain, then replace both values in this gitignored file with the real key and verified sender.

Use a real verified sender for external recipients, not a sandbox sender with restricted recipients. Keep the key server-only, outside `VITE_*`, browser bundles, source control, and logs.

## Start the application

```sh
bun build ./src/client.ts --target browser --outdir ./public
bunx alchemy dev --stage email-guide --env-file .env.local
```

Alchemy allocates an available port and prints the URL; open it and register with an inbox you control. Leave the server running while opening the verification email, then sign in and check `/api/me`.

Without `AUTH_BASE_URL`, Better Auth derives the origin from the request, so no fixed development port is needed. If you set an override, use the actual printed origin without a trailing slash or `/api/auth`, and update it if the local origin changes.

In production, set `AUTH_BASE_URL` to the real HTTPS Worker origin, such as `https://auth.example.com` only after that hostname serves the Worker. This option does not provision DNS or attach a domain; keep production configuration separate from local credentials.

Rebuild the browser module after editing it. After an origin change, request fresh verification or reset emails instead of reusing links to the old origin.

## Keep account ownership explicit

The configured `disableImplicitLinking: true` policy prevents automatic email-based linking if you later add social providers. Existing users should authenticate with their original method before explicitly linking another provider, retaining verified-email and same-email checks.

Password recovery can establish a password for an existing social-only account, so email delivery and ownership are security boundaries. Never merge users by email, enable different-email linking to suppress a collision, or manually mark an address verified to unblock sign-in.

Do not disable verification in production to work around delivery failures. Monitor delivery status without recording mail bodies, generated links, request headers, API keys, or passwords, and keep recovery messages from disclosing whether an account exists.
