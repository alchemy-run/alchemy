## Read sessions inside each request

```typescript
// worker.ts
import { BetterAuth } from "@alchemy.run/better-auth";
import { CloudflareD1 } from "@alchemy.run/better-auth/CloudflareD1";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Data from "effect/Data";
import * as Effect from "effect/Effect";
import * as Result from "effect/Result";
import * as HttpServerRequest from "effect/unstable/http/HttpServerRequest";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

class AuthenticationUnavailable extends Data.TaggedError("AuthenticationUnavailable") {}

const AuthDb = Cloudflare.D1.Database("AuthDb");

export default class AuthApi extends Cloudflare.Worker<AuthApi>()(
  "AuthApi",
  { main: import.meta.url, compatibility: { flags: ["nodejs_compat"] } },
  Effect.gen(function* () {
    const auth = yield* BetterAuth({
      basePath: "/api/auth",
      emailAndPassword: { enabled: true },
      session: {
        expiresIn: 60 * 60 * 24 * 7,
        updateAge: 60 * 60 * 24,
        freshAge: 60 * 10,
        cookieCache: { enabled: false },
      },
    });
    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest.HttpServerRequest;
        const path = request.url.split("?")[0];
        if (path === "/api/auth" || path.startsWith("/api/auth/")) {
          return yield* auth.fetch;
        }
        if (path !== "/api/me" && path !== "/api/sensitive-me") {
          return HttpServerResponse.text("Not found", { status: 404 });
        }
        if (request.method !== "GET") {
          return HttpServerResponse.text("Method not allowed", { status: 405 });
        }
        const lookup = Effect.gen(function* () {
          if (path === "/api/sensitive-me") {
            const webRequest = yield* HttpServerRequest.toWeb(request);
            return yield* auth.api.getSession({
              headers: webRequest.headers,
              query: { disableCookieCache: true },
            });
          }
          return yield* auth.getSession();
        });
        const session = yield* lookup.pipe(
          Effect.mapError(() => new AuthenticationUnavailable()),
          Effect.catchDefect(() => Effect.fail(new AuthenticationUnavailable())),
          Effect.result,
        );
        if (Result.isFailure(session)) {
          return yield* HttpServerResponse.json(
            { _tag: "AuthenticationUnavailable" }, { status: 503 },
          );
        }
        if (session.success === null) {
          return yield* HttpServerResponse.json(
            { _tag: "Unauthorized" }, { status: 401 },
          );
        }
        const { id, name, email } = session.success.user;
        return yield* HttpServerResponse.json({ id, name, email });
      }),
    };
  }).pipe(Effect.provide(CloudflareD1(AuthDb))),
) {}
```

`/api/me` uses `auth.getSession()`, which reads the ambient request headers; `/api/sensitive-me` explicitly forwards headers and bypasses any cookie cache. Both resolve the session per request and return `401` only for `null`, while lookup failures become `503`.

The explicit `auth.getSession(headers)` overload also accepts a web `Headers` object when no ambient HTTP request is available. It does not accept a bare token or require inventing another authentication scheme.

The lifetime values are seconds: sessions expire after seven days, eligible activity refreshes them after one day, and sensitive built-in operations require a session created within ten minutes. `freshAge` does not automatically impose reauthentication on your application routes.

## Run the standalone host

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import AuthApi from "./worker.ts";

export default Alchemy.Stack(
  "AuthSessions",
  { providers: Cloudflare.providers(), state: Alchemy.localState() },
  Effect.gen(function* () {
    const api = yield* AuthApi;
    return { url: api.url };
  }),
);
```

Use Bun, matching `alchemy` and `@alchemy.run/better-auth` releases, Better Auth 1.7.5, Effect 4, and `kysely`, with Cloudflare credentials configured. This stack provisions D1, schema migrations, and a stable signing secret; preserve its local state.

```sh
bunx alchemy dev
```

Use Alchemy's printed origin, not a fixed local port. D1 stores sessions here; adding secondary storage changes which server store an authoritative lookup reads.

## Manage browser sessions through the auth routes

```typescript
// sessions.ts — browser only
import { createAuthClient } from "better-auth/client";

const authClient = createAuthClient();

export async function signIn(email: string, password: string) {
  const { data, error } = await authClient.signIn.email({ email, password });
  if (error) throw error;
  return data;
}

export async function currentUser() {
  const { data, error } = await authClient.getSession();
  if (error) throw error;
  return data?.user ?? null;
}

export async function listSessions() {
  const { data, error } = await authClient.listSessions();
  if (error) throw error;
  return data;
}

export async function revokeSession(token: string) {
  const { error } = await authClient.revokeSession({ token });
  if (error) throw error;
}

export async function revokeOtherSessions() {
  const { error } = await authClient.revokeOtherSessions();
  if (error) throw error;
}

export async function signOut() {
  const { error } = await authClient.signOut();
  if (error) throw error;
}
```

This module is for a frontend served on the API's origin; the Worker above does not bundle a frontend. `signIn` takes an existing user's form credentials, and `revokeSession` takes the token of a session returned by `listSessions`, whose ownership Better Auth checks.

A failed browser request is not an anonymous session, and browser session data is UI state rather than server authorization. Session tokens are credentials: do not log the device list or send it to analytics.

The mounted `auth.fetch` returns Better Auth's response cookies, including refresh cookies. A server-only `auth.getSession()` call returns data and does not itself forward `Set-Cookie` to the browser.

## Understand cookie-cache staleness

To opt in, replace the `BetterAuth` call in `worker.ts` above with:

```typescript
const auth = yield* BetterAuth({
  basePath: "/api/auth",
  emailAndPassword: { enabled: true },
  session: {
    expiresIn: 60 * 60 * 24 * 7,
    updateAge: 60 * 60 * 24,
    freshAge: 60 * 10,
    cookieCache: {
      enabled: true,
      maxAge: 60,
      refreshCache: false,
    },
  },
});
```

With `refreshCache: false`, a valid cache can still show revoked sessions or stale user data for up to 60 seconds without reading the store.

`refreshCache: true` can renew cached data without consulting the store, so `maxAge` alone does not bound staleness in that mode. The example's `/api/sensitive-me` route continues bypassing the cache regardless of this option; a browser-only bypass would not protect another server route.

## Verify revocation separately from cookie clearing

`revokeOtherSessions` keeps the current session, while `signOut` clears this browser's cookies and attempts to delete its server session. Neither can erase a valid cookie cache already copied elsewhere.

Better Auth's sign-out handler can return success even if session deletion fails. A cleared cookie jar proves browser sign-out, not server-side revocation; test copied credentials through an authoritative lookup and investigate storage failures independently.
