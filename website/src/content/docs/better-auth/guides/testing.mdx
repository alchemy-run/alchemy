## Deploy a disposable authentication boundary

```typescript
// worker.ts
import { BetterAuth } from "@alchemy.run/better-auth";
import { CloudflareD1 } from "@alchemy.run/better-auth/CloudflareD1";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Data from "effect/Data";
import * as Effect from "effect/Effect";
import * as Result from "effect/Result";
import { HttpServerRequest } from "effect/unstable/http/HttpServerRequest";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

class AuthenticationUnavailable extends Data.TaggedError("AuthenticationUnavailable") {}

const AuthDb = Cloudflare.D1.Database("AuthDb");

export default class AuthApi extends Cloudflare.Worker<AuthApi>()(
  "AuthApi",
  { main: import.meta.url, compatibility: { flags: ["nodejs_compat"] } },
  Effect.gen(function* () {
    const auth = yield* BetterAuth({
      basePath: "/api/auth",
      emailAndPassword: { enabled: true },
      session: { cookieCache: { enabled: false } },
    });
    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const path = request.url.split("?")[0];
        if (path === "/api/auth" || path.startsWith("/api/auth/")) {
          return yield* auth.fetch;
        }
        if (path === "/api/health") {
          return yield* HttpServerResponse.json({ ok: true });
        }
        if (path !== "/api/me") {
          return HttpServerResponse.text("Not found", { status: 404 });
        }
        const session = yield* auth.getSession().pipe(
          Effect.mapError(() => new AuthenticationUnavailable()),
          Effect.catchDefect(() => Effect.fail(new AuthenticationUnavailable())),
          Effect.result,
        );
        if (Result.isFailure(session)) {
          return yield* HttpServerResponse.json(
            { _tag: "AuthenticationUnavailable" }, { status: 503 },
          );
        }
        if (session.success === null) {
          return yield* HttpServerResponse.json(
            { _tag: "Unauthorized" }, { status: 401 },
          );
        }
        const { id, name, email } = session.success.user;
        return yield* HttpServerResponse.json({ id, name, email });
      }),
    };
  }).pipe(Effect.provide(CloudflareD1(AuthDb))),
) {}
```

The fixture keeps auth routes public, reads sessions per request, and distinguishes anonymous `401` responses from lookup failures with `503`. Cookie caching is disabled so the copied-cookie test below checks authoritative server-side revocation.

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import AuthApi from "./worker.ts";

export default Alchemy.Stack(
  "AuthAcceptance",
  { providers: Cloudflare.providers(), state: Alchemy.localState() },
  Effect.gen(function* () {
    const api = yield* AuthApi;
    return { url: api.url };
  }),
);
```

Use Bun, matching `alchemy` and `@alchemy.run/better-auth` releases, Better Auth 1.7.5, Effect 4, and `kysely`, with Cloudflare credentials configured. The stack creates D1, applies migrations, and generates a stable signing secret; use a fresh disposable database, not production or a shared application.

```sh
bunx alchemy deploy --stage auth-guide-test
```

Keep the local state directory until cleanup so Alchemy can destroy exactly these resources. For local simulator feedback, use `bunx alchemy dev --stage auth-guide-local` instead; a local pass does not validate cloud bindings or credentials.

## Run the cookie-jar acceptance test

```bash
#!/usr/bin/env bash
# test-auth.sh
set -euo pipefail
umask 077
read -r BASE_URL
BASE_URL=${BASE_URL%/}
WORK=$(mktemp -d)
COOKIE_JAR="$WORK/cookies"
trap 'rm -rf "$WORK"' EXIT

curl --silent --show-error --fail-with-body \
  --output "$WORK/health.json" "$BASE_URL/api/health"
jq -e '.ok == true' "$WORK/health.json" >/dev/null

test "$(curl --silent --show-error \
  --output "$WORK/anonymous.json" --write-out '%{http_code}' \
  "$BASE_URL/api/me")" = 401
jq -e '._tag == "Unauthorized"' "$WORK/anonymous.json" >/dev/null

curl --silent --show-error --fail-with-body \
  --output "$WORK/no-session.json" "$BASE_URL/api/auth/get-session"
jq -e '. == null' "$WORK/no-session.json" >/dev/null

openssl rand -base64 24 | jq -R '{
  name: "Guide Session",
  email: "guide-session@example.com",
  password: .
}' > "$WORK/signup.json"
curl --silent --show-error --fail-with-body \
  --output "$WORK/signup-response.json" \
  --header 'Content-Type: application/json' \
  --header "Origin: $BASE_URL" \
  --data-binary @"$WORK/signup.json" \
  "$BASE_URL/api/auth/sign-up/email"
jq -e '.user.id | type == "string"' "$WORK/signup-response.json" >/dev/null

jq '{email, password}' "$WORK/signup.json" > "$WORK/signin.json"
curl --silent --show-error --fail-with-body \
  --output "$WORK/signin-response.json" --cookie-jar "$COOKIE_JAR" \
  --header 'Content-Type: application/json' \
  --header "Origin: $BASE_URL" \
  --data-binary @"$WORK/signin.json" \
  "$BASE_URL/api/auth/sign-in/email"
USER_ID=$(jq -er '.user.id' "$WORK/signin-response.json")

curl --silent --show-error --fail-with-body \
  --output "$WORK/session.json" \
  --cookie "$COOKIE_JAR" --cookie-jar "$COOKIE_JAR" \
  "$BASE_URL/api/auth/get-session"
jq -e --arg id "$USER_ID" '.user.id == $id' "$WORK/session.json" >/dev/null

curl --silent --show-error --fail-with-body \
  --output "$WORK/me.json" --cookie "$COOKIE_JAR" "$BASE_URL/api/me"
jq -e --arg id "$USER_ID" \
  '.id == $id and .email == "guide-session@example.com" and (has("session") | not)' \
  "$WORK/me.json" >/dev/null
cp "$COOKIE_JAR" "$WORK/copied-cookies"

curl --silent --show-error --fail-with-body \
  --output "$WORK/signout.json" \
  --cookie "$COOKIE_JAR" --cookie-jar "$COOKIE_JAR" \
  --header 'Content-Type: application/json' \
  --header "Origin: $BASE_URL" --data '{}' \
  "$BASE_URL/api/auth/sign-out"
jq -e '.success == true' "$WORK/signout.json" >/dev/null

for JAR in "$COOKIE_JAR" "$WORK/copied-cookies"; do
  test "$(curl --silent --show-error \
    --output "$WORK/signed-out.json" --write-out '%{http_code}' \
    --cookie "$JAR" "$BASE_URL/api/me")" = 401
  jq -e '._tag == "Unauthorized"' "$WORK/signed-out.json" >/dev/null
done
```

Save this as `test-auth.sh`, run `bash test-auth.sh`, and enter Alchemy's printed origin after the script waits at `read`. It needs `curl` with `--fail-with-body` support, `jq`, and `openssl`; success is a zero exit status, and any failed assertion stops the script.

The private temporary directory keeps passwords, response bodies, and cookie jars out of terminal output. Do not enable shell tracing or print request headers; the exit trap removes those files even on failure.

Sign-up must succeed on the fresh database; an existing-user response is not permission to ignore failures. The real sign-in route writes cookies to the jar, and the session request captures any refreshed cookies before calling the protected endpoint.

The final loop checks both browser cookie clearing and the credential copied before sign-out. Better Auth can clear cookies even when server-side deletion fails, so passing only the cleared-jar assertion would not prove revocation.

## Clean up the disposable deployment

```sh
bunx alchemy destroy --stage auth-guide-test
```

Run cleanup from this example's directory using the same profile as deployment, and retain state until it completes. This deletes the test database and user; deleting the temporary cookie jar alone does not remove server-side data.

## Test failures and integrations separately

In an isolated environment, make the session backend unavailable and request `/api/me` with a valid session cookie; expect `503`, not `401` or successful anonymous data. Keep this outage test separate from the healthy cookie-jar flow, and restore the backend before cleanup.

Email/password tests do not verify OAuth state, redirect registrations, or third-party account linking. Exercise the actual provider redirect when those features are enabled, and test secondary storage's concurrency and TTL guarantees against its real backend.

## Run the repository's live D1 suite

```sh
timeout 240 pnpm test ../better-auth/test/Cloudflare/D1.test.ts \
  --profile testing --retry 0
```

Run this separate command from the Alchemy repository root with its dependencies, testing profile, and GNU `timeout` installed. The suite owns its fixture and deployment; its `/auth` and `/me` routes differ from this guide's `/api/auth` and `/api/me`.

The Memory suite checks wrapper API and plugin behavior in process, but cannot establish that a deployed database binding works. A green local or in-memory test is not a substitute for the live acceptance flow.
