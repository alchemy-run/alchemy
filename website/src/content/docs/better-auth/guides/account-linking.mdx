## Require an explicit link

```typescript
// worker.ts
import { BetterAuth, type BetterAuthProps } from "@alchemy.run/better-auth";
import { CloudflareD1 } from "@alchemy.run/better-auth/CloudflareD1";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Config from "effect/Config";
import * as Effect from "effect/Effect";
import * as Redacted from "effect/Redacted";
import { HttpServerRequest } from "effect/unstable/http/HttpServerRequest";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

const AuthDb = Cloudflare.D1.Database("AuthDb");

export const authOptions = {
  basePath: "/api/auth",
  emailAndPassword: { enabled: true },
  account: {
    accountLinking: {
      enabled: true,
      disableImplicitLinking: true,
      allowDifferentEmails: false,
      allowUnlinkingAll: false,
    },
  },
} satisfies BetterAuthProps;

export default class AuthApi extends Cloudflare.Worker<AuthApi>()(
  "AuthApi",
  { main: import.meta.url, compatibility: { flags: ["nodejs_compat"] } },
  Effect.gen(function* () {
    const clientId = yield* Config.String("GITHUB_CLIENT_ID");
    const clientSecret = yield* Config.Redacted("GITHUB_CLIENT_SECRET");
    const auth = yield* BetterAuth({
      ...authOptions,
      socialProviders: {
        github: { clientId, clientSecret: Redacted.value(clientSecret) },
      },
    });
    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        const path = request.url.split("?")[0];
        if (path === "/api/auth" || path.startsWith("/api/auth/")) {
          return yield* auth.fetch;
        }
        return HttpServerResponse.text("Account linking API");
      }),
    };
  }).pipe(Effect.provide(CloudflareD1(AuthDb))),
) {}
```

A user is the application's identity; an account is one sign-in method attached to it. This configuration requires signing in to the existing user before linking GitHub, rather than implicitly linking ordinary OAuth sign-ins by matching email.

`GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET` are server-side credentials from a GitHub OAuth App, not a personal access token. Supply them through a protected deployment environment; the wrapper generates its own stable signing secret.

## Run the standalone host

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import AuthApi from "./worker.ts";

export default Alchemy.Stack(
  "AccountLinking",
  { providers: Cloudflare.providers(), state: Alchemy.localState() },
  Effect.gen(function* () {
    const api = yield* AuthApi;
    return { url: api.url };
  }),
);
```

Use Bun, matching `alchemy` and `@alchemy.run/better-auth` releases, Better Auth 1.7.5, Effect 4, and `kysely`, with Cloudflare credentials configured. D1 and its schema are provisioned by this stack; preserve its local state.

```sh
bunx alchemy dev
```

After startup, register the printed origin as the GitHub OAuth App's homepage and that origin followed by `/api/auth/callback/github` as its authorization callback. Update the registration if the local origin changes; use a separate OAuth App and matching credentials for production.

## Link and manage accounts from the browser

```typescript
// accounts.ts — browser only
import { createAuthClient } from "better-auth/client";

const authClient = createAuthClient();

export async function signUp(name: string, email: string, password: string) {
  const { data, error } = await authClient.signUp.email({ name, email, password });
  if (error) throw error;
  return data;
}

export async function signIn(email: string, password: string) {
  const { data, error } = await authClient.signIn.email({ email, password });
  if (error) throw error;
  return data;
}

export async function currentUser() {
  const { data, error } = await authClient.getSession();
  if (error) throw error;
  return data?.user ?? null;
}

export async function linkGitHub() {
  const { error } = await authClient.linkSocial({
    provider: "github",
    callbackURL: "/",
  });
  if (error) throw error;
}

export async function listAccounts() {
  const { data, error } = await authClient.listAccounts();
  if (error) throw error;
  return data;
}

export async function unlinkAccount(id: string) {
  const { error } = await authClient.unlinkAccount({ accountId: id });
  if (error) throw error;
}
```

This module is for an account-settings frontend served on the same origin as the API; the Worker above supplies the API, not a frontend bundle. Form values are inputs to `signUp` and `signIn`; call `linkGitHub` only after authenticating the existing user.

The client follows GitHub's redirect and returns to `/` after Better Auth completes its callback. That post-login destination is distinct from the OAuth App's `/api/auth/callback/github` registration.

In Better Auth 1.7.5, pass the selected account's **`id`** from `listAccounts()` to `unlinkAccount`. Its provider-side `accountId` and `providerId` are not substitutes for the local row ID.

Unlinking requires a fresh session and cannot remove the last account with this configuration. Ask the user to sign in again on `SESSION_NOT_FRESH` rather than weakening the protection.

## Preserve verification and ownership checks

Better Auth 1.7.5 requires the existing local user's email to be verified before implicit linking, in addition to the provider-side verification or trust requirement. Keep those defaults if you later enable implicit linking.

Do not add a provider to `trustedProviders` just to suppress a linking error. It relaxes the provider-email verification check; it does not prove that two existing application users should be merged.

If the provider identity already belongs to another user, linking must fail. Do not rewrite `userId`, change verification flags, or delete an account to force the operation through.

## Verify identity stays stable

Compare `currentUser()` before and after completing the redirect: the user ID should stay the same while `listAccounts()` gains a sign-in method. Also verify signed-out linking fails, different-email linking is rejected, and unlinking the last account fails.

Keep application ownership keyed by user ID, not email or provider account ID. Recovery between two existing users requires a separate ownership-verification and data-transfer process, not an email comparison.
