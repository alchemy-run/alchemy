Start with the Cloudflare + D1 application in [Part 1](/better-auth/tutorial/part-1) and [Part 2](/better-auth/tutorial/part-2). Keep auth options in `src/auth.ts`, separate from the host's database layer.

## Keep the inferred options

The tutorial's `src/auth.ts` follows this shape:

```typescript
import { BetterAuth, type BetterAuthProps } from "@alchemy.run/better-auth";
import * as Context from "effect/Context";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";

export const authOptions = {
  basePath: "/api/auth",
  emailAndPassword: { enabled: true },
} satisfies BetterAuthProps;

const makeAuth = BetterAuth(authOptions);

export class Auth extends Context.Service<
  Auth,
  Effect.Success<typeof makeAuth>
>()("app/Auth") {
  static readonly layer = Layer.effect(Auth, makeAuth);
}
```

`satisfies BetterAuthProps` checks the options without widening away plugin-specific types. The wrapper owns `database` and `secondaryStorage`; neither belongs in this object.

## Supply the database from the host

Keep this composition in the tutorial's Worker, where `AuthDb` is the D1 resource:

```typescript
Auth.layer.pipe(Layer.provide(CloudflareD1(AuthDb)))
```

Import `CloudflareD1` from `@alchemy.run/better-auth/CloudflareD1`. Other hosts can provide a different [database layer](/better-auth/databases) without changing the application service.

## Start without a URL override

Leave `baseURL` unset so Better Auth derives the origin from the incoming request:

```sh
bunx alchemy dev
```

Alchemy selects an available port and prints the local URL. Open that URL; no URL configuration is required before the server can start.

## Add an optional URL override

For deployments that need an explicit origin, add these imports to `src/auth.ts`:

```diff lang="typescript"
 import * as Context from "effect/Context";
+import * as Config from "effect/Config";
+import * as Option from "effect/Option";
```

Replace only `makeAuth`:

```diff lang="typescript"
-const makeAuth = BetterAuth(authOptions);
+const makeAuth = Effect.gen(function* () {
+  const baseURL = yield* Config.String("AUTH_BASE_URL").pipe(Config.option);
+  return yield* BetterAuth({
+    ...authOptions,
+    baseURL: Option.getOrUndefined(baseURL),
+  });
+});
```

When `AUTH_BASE_URL` is absent, request-origin detection still works. Resolve `Config` here, not in `fetch`, so Alchemy discovers and binds configured values during construction.

## Use the printed local origin

If you need a local override, leave the dev server running and paste its printed origin into another shell, without a trailing slash:

```sh
read -r BASE_URL
printf 'AUTH_BASE_URL=%s\n' "$BASE_URL"
```

Copy the printed configuration line into a gitignored `.env.local`. On a subsequent start, load it explicitly:

```sh
bunx alchemy dev --env-file .env.local
```

If the printed origin changes, update the override and any provider callbacks to match. Omit the local override when you want Better Auth to keep following the incoming request origin.

## Set the production origin

Create a gitignored `.env.production`:

```dotenv
AUTH_BASE_URL=https://auth.example.com
```

After configuring that hostname on the tutorial's Worker, deploy with the production values:

```sh
bunx alchemy deploy --stage prod --env-file .env.production
```

`baseURL` configures Better Auth; it does not provision DNS or attach a Worker domain. See [Part 6](/better-auth/tutorial/part-6) for deployment.

## Distinguish stage from profile

`--stage prod` selects the stack instance; `--profile prod` selects cloud credentials. A profile name does not select an application URL or load `.env.production` automatically.

```sh
bunx alchemy profile create prod
bunx alchemy profile edit --profile prod
bunx alchemy deploy --stage prod --profile prod --env-file .env.production
```

An explicit stage wins over `ALCHEMY_STAGE`; otherwise deploy uses `live_$USER` and dev uses `dev_$USER`. An explicit profile wins over `ALCHEMY_PROFILE`; otherwise it is `default`.

Do not point local development at the production stage. See [stages](/environments/stages), [profiles](/environments/profiles), and [configuration binding](/environments/secrets) for the full rules, including credential environment overrides and CI.

## Keep the automatic signing secret

Omit `secret` for a new application. Alchemy provisions a random signing secret once and preserves it across deployments of that resource.

Keep the auth instance's `id`, resource namespace, and state stable. A new stage or replacement secret resource is not the same signing identity.

## Import an existing signing secret

Only when moving an existing application, extend the optional-URL `makeAuth` above in `src/auth.ts`:

```diff lang="typescript"
 const makeAuth = Effect.gen(function* () {
   const baseURL = yield* Config.String("AUTH_BASE_URL").pipe(Config.option);
+  const secret = yield* Config.Redacted("BETTER_AUTH_SECRET");
   return yield* BetterAuth({
     ...authOptions,
     baseURL: Option.getOrUndefined(baseURL),
+    secret,
   });
 });
```

Supply the existing secret through your deployment's protected environment; do not print it or commit it. `Config.Redacted` is accepted directly, and preserving the secret alone does not migrate users, sessions, or cookies.

## Keep the browser client same-origin

The tutorial's `src/client.ts` needs no server configuration:

```typescript
import { createAuthClient } from "better-auth/client";

export const authClient = createAuthClient();
```

It calls `/api/auth` on the page's origin. Do not import `src/auth.ts` into browser code or expose provider credentials there.

## Trust only intended origins

For the same-origin tutorial, the resolved auth origin is already trusted. If an additional frontend is intentional, add its exact origin to `trustedOrigins` in `src/auth.ts`:

```diff lang="typescript"
 export const authOptions = {
   basePath: "/api/auth",
   emailAndPassword: { enabled: true },
+  trustedOrigins: ["https://app.example.com"],
 } satisfies BetterAuthProps;
```

This is an origin-security allowlist, not CORS or cookie-sharing configuration. Do not disable origin or CSRF checks to fix a URL mismatch.
