---
title: Deploy to Cloudflare
description: Deploy a standalone Better Auth endpoint on a Cloudflare Worker with D1 and automatic migrations.
---

Deploy an email/password authentication API backed by D1. This example includes the complete Worker and stack; it does not require the tutorial application.

## Create the project

```sh
mkdir cloudflare-auth
cd cloudflare-auth
bun init -y
mkdir src
bun add alchemy "effect@4.0.0-rc.115" @alchemy.run/better-auth better-auth@^1.7.5 kysely
```

Configure a [Cloudflare profile](/cloudflare/setup) with your account credentials. `kysely` is required by the Better Auth SQL adapter even though D1 uses a native binding.

## Define the Worker

```typescript title="src/worker.ts"
import { BetterAuth } from "@alchemy.run/better-auth";
import { CloudflareD1 } from "@alchemy.run/better-auth/CloudflareD1";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Config from "effect/Config";
import * as Effect from "effect/Effect";
import * as Option from "effect/Option";

const database = Cloudflare.D1.Database("AuthDb");

export default class AuthApi extends Cloudflare.Worker<AuthApi>()(
  "AuthApi",
  {
    main: import.meta.url,
    compatibility: { flags: ["nodejs_compat"] },
  },
  Effect.gen(function* () {
    const baseURL = yield* Config.String("AUTH_BASE_URL").pipe(Config.option);
    const auth = yield* BetterAuth({
      basePath: "/api/auth",
      baseURL: Option.getOrUndefined(baseURL),
      emailAndPassword: { enabled: true },
    });
    return { fetch: auth.fetch };
  }).pipe(Effect.provide(CloudflareD1(database))),
) {}
```

Alchemy supplies the database binding, schema migrations, and a stable signing secret. The optional `AUTH_BASE_URL` is read during Worker construction so Alchemy can bind it into the deployed environment.

## Define the stack

```typescript title="alchemy.run.ts"
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import AuthApi from "./src/worker.ts";

export default Alchemy.Stack(
  "CloudflareAuth",
  { providers: Cloudflare.providers(), state: Alchemy.localState() },
  Effect.gen(function* () {
    const api = yield* AuthApi;
    return { url: api.url };
  }),
);
```

Preserve and protect `.alchemy`: this local state directory tracks resource identities and the generated signing secret. Keep the stack name and state backend stable across deployments.


## Run locally

```sh
bunx alchemy dev --stage dev
```

Alchemy chooses an available port and prints the local URL. Keep `AUTH_BASE_URL` unset locally to use the request origin.

## Deploy

```sh
bunx alchemy deploy --stage prod
```

Deployment creates D1, applies the auth schema, and deploys the Worker. Later deployments retain the secret and skip unchanged migrations.

## Set the production origin

Paste the deployed Worker origin when prompted, then redeploy with that origin bound into the Worker:

```sh
read -r AUTH_BASE_URL
export AUTH_BASE_URL
bunx alchemy deploy --stage prod
```

Use your configured custom domain instead if it already routes to this Worker. Setting `AUTH_BASE_URL` does not create DNS or a custom domain.

## Verify sessions

Paste the deployed origin without a trailing slash:

```sh
read -r AUTH_ORIGIN
curl -i "$AUTH_ORIGIN/api/auth/get-session"
```

An anonymous request returns `null`. Create a disposable account and retain its session cookie:

```sh
curl --fail-with-body -c cookies.txt \
  -H 'Content-Type: application/json' \
  -H "Origin: $AUTH_ORIGIN" \
  -d '{"name":"Auth Check","email":"auth-check@example.com","password":"local-check-password-123"}' \
  "$AUTH_ORIGIN/api/auth/sign-up/email"
curl --fail-with-body -b cookies.txt "$AUTH_ORIGIN/api/auth/get-session"
```

The second response contains the new user and session. Sign out, then confirm that the original cookie no longer authenticates:

```sh
curl --fail-with-body -b cookies.txt \
  -H 'Content-Type: application/json' \
  -H "Origin: $AUTH_ORIGIN" -d '{}' \
  "$AUTH_ORIGIN/api/auth/sign-out"
curl --fail-with-body -b cookies.txt "$AUTH_ORIGIN/api/auth/get-session"
rm cookies.txt
```

Use a disposable stage for this check; the account remains in its database after sign-out. Treat the cookie file and session response as credentials.

## Add application features

The [email/password guide](/better-auth/sign-in-providers/email-password) covers browser clients, and [HTTP API middleware](/better-auth/guides/http-api-middleware) covers protected application routes. Use the [GitHub guide](/better-auth/sign-in-providers/github) for OAuth registration and credentials.

For a frontend on another origin, configure [trusted origins and credentialed CORS](/better-auth/guides/configuration) separately. Read [migrations](/better-auth/guides/migrations) and the [1.6 upgrade guide](/better-auth/upgrades/from-1-6-to-1-7) before changing an existing installation.
