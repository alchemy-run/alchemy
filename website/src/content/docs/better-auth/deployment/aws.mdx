description: Deploy a standalone Better Auth endpoint behind a Lambda Function URL with Neon.

Deploy an email/password authentication API on Lambda with a Neon database. The complete function and stack below run independently of the tutorial application.

## Create the project

```sh
mkdir lambda-auth
cd lambda-auth
bun init -y
mkdir src
bun add alchemy "effect@4.0.0-rc.115" @alchemy.run/better-auth better-auth@^1.7.5 kysely @neondatabase/serverless
```

Configure AWS and Neon using [Alchemy profiles](/environments/profiles). Supply your own AWS credentials and Neon API key; Alchemy does not create account credentials.

## Define the function

```typescript title="src/function.ts"
import { BetterAuth } from "@alchemy.run/better-auth";
import { Neon as NeonDatabase } from "@alchemy.run/better-auth/Neon";
import * as AWS from "alchemy/AWS";
import * as Neon from "alchemy/Neon";
import * as Config from "effect/Config";
import * as Duration from "effect/Duration";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import * as Option from "effect/Option";

const database = Neon.Project("AuthDb");
const DatabaseLive = Layer.unwrap(
  Effect.map(database, (project) => NeonDatabase(project.connectionUri)),
);

export default class AuthApi extends AWS.Lambda.Function<AuthApi>()(
  "AuthApi",
  {
    main: import.meta.url,
    functionUrl: true,
    memorySize: 512,
    timeout: Duration.seconds(30),
  },
  Effect.gen(function* () {
    const baseURL = yield* Config.String("AUTH_BASE_URL").pipe(Config.option);
    const auth = yield* BetterAuth({
      basePath: "/api/auth",
      baseURL: Option.getOrUndefined(baseURL),
      emailAndPassword: { enabled: true },
    });
    return { fetch: auth.fetch };
  }).pipe(Effect.provide(DatabaseLive)),
) {}
```

`functionUrl: true` creates a public endpoint; Better Auth handles application authentication instead of AWS IAM request signing. The database URI binds into Lambda automatically, and the Neon pool opens and closes per invocation.

## Define the stack

```typescript title="alchemy.run.ts"
import * as Alchemy from "alchemy";
import * as AWS from "alchemy/AWS";
import * as Neon from "alchemy/Neon";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import AuthApi from "./src/function.ts";

export default Alchemy.Stack(
  "LambdaAuth",
  {
    providers: Layer.mergeAll(AWS.providers(), Neon.providers()),
    state: Alchemy.localState(),
  },
  Effect.gen(function* () {
    const api = yield* AuthApi;
    return { url: api.functionUrl };
  }),
);
```

Preserve and protect `.alchemy`: this local state directory tracks resource identities and the generated signing secret. Keep the stack name and state backend stable across deployments.

## Deploy

```sh
bunx alchemy deploy --stage prod
```

Alchemy creates the Neon project, applies the auth schema, and deploys Lambda with a stable signing secret. Neon uses its serverless driver, so the function does not need `pg` or a VPC connection to the database.

## Set the production origin

Paste the printed Function URL origin without a trailing slash, then redeploy:

```sh
read -r AUTH_BASE_URL
export AUTH_BASE_URL
bunx alchemy deploy --stage prod
```

The function above reads this optional configuration during construction so Alchemy discovers the binding. If a custom domain already routes to the function, use its origin instead; this setting does not create DNS or a proxy.

## Verify sessions

Paste the externally visible origin:

```sh
read -r AUTH_ORIGIN
curl -i "$AUTH_ORIGIN/api/auth/get-session"
```

An anonymous request returns `null`. Create a disposable account and retain its cookie:

```sh
curl --fail-with-body -c cookies.txt \
  -H 'Content-Type: application/json' \
  -H "Origin: $AUTH_ORIGIN" \
  -d '{"name":"Auth Check","email":"auth-check@example.com","password":"local-check-password-123"}' \
  "$AUTH_ORIGIN/api/auth/sign-up/email"
curl --fail-with-body -b cookies.txt "$AUTH_ORIGIN/api/auth/get-session"
```

The second response contains the new user and session. Sign out and confirm that the original cookie no longer authenticates:

```sh
curl --fail-with-body -b cookies.txt \
  -H 'Content-Type: application/json' \
  -H "Origin: $AUTH_ORIGIN" -d '{}' \
  "$AUTH_ORIGIN/api/auth/sign-out"
curl --fail-with-body -b cookies.txt "$AUTH_ORIGIN/api/auth/get-session"
rm cookies.txt
```

Use a disposable stage for this check; sign-out leaves the account in its database. Treat the cookie file and session response as credentials.

## Add application features

For an AWS-only database, the [Aurora Data API guide](/better-auth/databases/aurora-data-api) provides a separate complete deployment. For browser authentication and protected routes, see [email/password](/better-auth/sign-in-providers/email-password) and [HTTP API middleware](/better-auth/guides/http-api-middleware).

A frontend on another origin needs explicit [trusted origins and credentialed CORS](/better-auth/guides/configuration). Read [migrations](/better-auth/guides/migrations) and the [1.6 upgrade guide](/better-auth/upgrades/from-1-6-to-1-7) before changing an existing installation.
