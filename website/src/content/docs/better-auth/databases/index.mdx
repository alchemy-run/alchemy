Keep authentication options in `src/auth.ts`; choose the database in the host. These pages reuse the `Auth` service from the [tutorial](/better-auth/tutorial/part-1).

## Choose a layer

| Database | Host | Layer | Automatic schema migrations |
| --- | --- | --- | --- |
| [Cloudflare D1](/better-auth/databases/cloudflare-d1) | Worker | `CloudflareD1` | Yes, over the D1 API |
| [Hyperdrive](/better-auth/databases/cloudflare-hyperdrive) | Worker | `CloudflareHyperdrive` | With an explicit origin URL |
| [Neon](/better-auth/databases/neon) | Worker or Lambda | `Neon` | With a deploy-resolvable URL |
| [Aurora PostgreSQL](/better-auth/databases/aurora-data-api) | Lambda | `AuroraDataApi` | Yes, over the Data API |
| [Postgres](/better-auth/databases/postgres) | Host with TCP access | `Postgres` | With a deploy-resolvable URL |
| [MySQL](/better-auth/databases/mysql) | Host with TCP access | `MySQL` | With a deploy-resolvable URL |
| [Drizzle](/better-auth/databases/drizzle) | Depends on your driver | `Drizzle` | No; use your migration workflow |
| [SQLite](/better-auth/databases/sqlite) | Bun process | `SQLite` | Against the same local file |
| [Memory](/better-auth/databases/memory) | Disposable development or tests | `Memory` | Not needed |

## Install the integration

```sh
bun add alchemy "effect@4.0.0-rc.115" @alchemy.run/better-auth better-auth@^1.7.5 kysely
```

`kysely` is the optional SQL peer used by the D1 example below and the other direct SQL layers. Install the driver listed on your database's page; Drizzle and Memory use their own adapters instead.

## Supply the database from the host

Reuse the tutorial's `AuthDb` from `src/database.ts` and compose the service in `src/auth-database.ts`:

```typescript
import { CloudflareD1 } from "@alchemy.run/better-auth/CloudflareD1";
import * as Layer from "effect/Layer";
import { Auth } from "./auth.ts";
import { AuthDb } from "./database.ts";

export const AuthLive = Auth.layer.pipe(
  Layer.provide(CloudflareD1(AuthDb)),
);
```

## Replace the host pipeline

In the [Part 1 Worker](/better-auth/tutorial/part-1), replace the inline database wiring in `src/worker.ts`:

```diff lang="typescript"
-import { CloudflareD1 } from "@alchemy.run/better-auth/CloudflareD1";
-import * as Layer from "effect/Layer";
-import { AuthDb } from "./database.ts";
+import { AuthLive } from "./auth-database.ts";

   }).pipe(
-    Effect.provide(Auth.layer.pipe(Layer.provide(CloudflareD1(AuthDb)))),
+    Effect.provide(AuthLive),
   ),
```

Changing this database layer leaves `Auth`, `auth.fetch`, and the `/api/auth` routes unchanged.

## Distinguish provisioning from connecting

`Cloudflare.D1.Database`, `Neon.Project`, and `AWS.RDS.Aurora` create infrastructure. The Better Auth layers connect to that infrastructure; passing an existing Postgres or MySQL URL does not create a database or credentials.

Resource connection-string Outputs are bound into the host environment. Resolve external credentials during host construction using [Effect configuration](/environments/secrets), not only inside the request handler.

## Keep connections request-scoped

The host builds the service layer once, but Better Auth acquires its database on the first auth operation in each request or invocation. Connection pools close when that execution settles; never create a Worker socket or pool at module scope or during layer construction.

## Keep the signing secret stable

Omitting `secret` provisions a stable `Alchemy.Random` signing secret and binds it to the host. Preserve the secret when migrating an existing application; see [configuration](/better-auth/guides/configuration).

## Apply the schema

Supported layers run additive migrations during deployment, before the new host is deployed; they do not move records between databases. Read [migrations](/better-auth/guides/migrations) before changing schema or opting out with `migrate: false`.

For existing users, follow [the 1.6 to 1.7 upgrade guide](/better-auth/upgrades/from-1-6-to-1-7). Full layer signatures are in the [generated Better Auth reference](/providers/betterauth/cloudflared1).
