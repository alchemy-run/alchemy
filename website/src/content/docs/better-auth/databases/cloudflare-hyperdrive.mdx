---
title: Cloudflare Hyperdrive
description: Connect a Worker to Postgres or MySQL through Hyperdrive without caching auth reads.
---

Use Hyperdrive when a Worker needs pooled TCP access to Postgres or MySQL. Hyperdrive connects to an origin database; it does not create that database.

## Install the Postgres driver

```sh
bun add alchemy "effect@4.0.0-rc.115" @alchemy.run/better-auth better-auth@^1.7.5 kysely pg
```

The example uses a Neon origin to show resource wiring. For Neon alone, the [Neon layer](/better-auth/databases/neon) is simpler and does not need Hyperdrive.

## Create the origin database

Create `src/database.ts`:

```typescript
import * as Neon from "alchemy/Neon";

export const AuthDb = Neon.Project("AuthDb");
```

This resource creates the origin database. Authenticate to Neon with your own API key, and include `Neon.providers()` alongside `Cloudflare.providers()` in the stack.

## Disable Hyperdrive caching

Create `src/hyperdrive.ts`:

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import { AuthDb } from "./database.ts";

export const AuthConnection = Effect.gen(function* () {
  const db = yield* AuthDb;
  return yield* Cloudflare.Hyperdrive.Connection("AuthConnection", {
    origin: db.origin,
    caching: { disabled: true },
  });
});
```

Auth reads must not return cached sessions or verification records. Keep caching disabled even if other application queries use a cached Hyperdrive connection.

## Supply the runtime and migration connections

Create `src/auth-database.ts`:

```typescript
import { CloudflareHyperdrive } from "@alchemy.run/better-auth/CloudflareHyperdrive";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import { Auth } from "./auth.ts";
import { AuthDb } from "./database.ts";
import { AuthConnection } from "./hyperdrive.ts";

const AuthDatabase = Layer.unwrap(
  Effect.gen(function* () {
    const db = yield* AuthDb;
    const connection = yield* AuthConnection;
    return CloudflareHyperdrive(connection, {
      migrate: db.connectionUri,
    });
  }),
);

export const AuthLive = Auth.layer.pipe(Layer.provide(AuthDatabase));
```

## Replace the Worker pipeline

Replace D1's inline wiring in the [Part 1 Worker](/better-auth/tutorial/part-1):

```diff lang="typescript"
 // src/worker.ts
-import { CloudflareD1 } from "@alchemy.run/better-auth/CloudflareD1";
-import * as Layer from "effect/Layer";
-import { AuthDb } from "./database.ts";
+import { AuthLive } from "./auth-database.ts";

   }).pipe(
-    Effect.provide(Auth.layer.pipe(Layer.provide(CloudflareD1(AuthDb)))),
+    Effect.provide(AuthLive),
   ),
```

Keep `nodejs_compat` enabled. The layer opens its driver pool within each request, never during Worker construction.

## Apply the schema through the origin

```sh
bunx alchemy deploy
```

Hyperdrive's connection string exists only inside the Worker, so migrations use the explicit origin URL. The deploying machine must reach that origin; omitting `migrate` disables automatic migration support.

With no migration source, leave Better Auth's `migrate` unset or false; explicitly requesting `migrate: true` fails. See [migrations](/better-auth/guides/migrations) for manual schema ownership.

## Use a MySQL origin

Install `mysql2` instead of `pg`:

```sh
bun add kysely mysql2
```

For a Hyperdrive connection configured with a MySQL origin, select `dialect: "mysql"` and supply that origin's deploy-resolvable URL as `migrate`. A dialect change alone does not convert a Postgres origin or move auth records.

The signing secret remains automatic regardless of the origin. See [configuration](/better-auth/guides/configuration), [Cloudflare deployment](/better-auth/deployment/cloudflare), and the [`CloudflareHyperdrive` reference](/providers/betterauth/cloudflarehyperdrive).
