Docker packages a program with everything it needs, its runtime, libraries and files, into an image, and runs images as isolated containers. The same image runs the same way on your laptop, in CI and on a server, which is why images are what most platforms deploy. An engine on each machine builds images and runs containers, attached to networks and volumes.

## A taste

Postgres with a named volume, a network alias and a published port:

```typescript title="alchemy.run.ts"
const image = yield* Docker.RemoteImage("postgres-image", { name: "postgres", tag: "18-alpine" });
const network = yield* Docker.Network("app-network");
const data = yield* Docker.Volume("postgres-data");

const postgres = yield* Docker.Container("postgres", {
  image,
  environment: { POSTGRES_DB: "app", POSTGRES_PASSWORD: password },
  ports: [{ external: 15432, internal: 5432 }],
  volumes: [{ hostPath: data.name, containerPath: "/var/lib/postgresql/data" }],
  networks: [{ name: network.name, aliases: ["postgres"] }],
  start: true,
});
```

`password` can be `Redacted`. It reaches the container through its environment, never on the command line.

## Where to start

**New to Docker?** [What is Docker?](/docker/what-is-docker) walks through the engine, contexts, images, registries, containers, networks, volumes and Swarm, once each, and shows how Alchemy models every one.

**Ready to go?** [Setup](/docker/setup) connects Alchemy to your engine. Then [Run local services](/docker/local-services) builds the Postgres above step by step, [Build & push images](/docker/build-and-push) builds an image and pushes it to a registry, and [Docker Swarm](/docker/swarm) runs replicated services on one engine or a remote server.

Most changes to a Network, Volume or Container replace it: the old one is removed before the new one is created. A container, network or volume of the same name that Alchemy didn't create fails the deploy until you opt in to adopting it with `--adopt`.

Every resource is in the generated [API reference](/providers).
