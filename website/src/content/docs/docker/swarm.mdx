Docker Swarm is an orchestration solution when regular Docker is not enough, but
Kubernetes is an overkill.

Alchemy orchestrates an **existing** swarm. `Docker.Service` wraps
`docker service` — swarm mode's orchestration API — so the engine it targets
must be a swarm manager. Cluster membership itself is one-time host setup with
the Docker CLI (resources for it, like `Docker.Swarm`, may come later).

## Setting up the swarm

### Local development

Turn your local engine into a single-node swarm. The node becomes both manager
and worker, and regular `docker run`/`docker build` usage is unaffected:

```sh
docker swarm init
```

Undo it at any time with `docker swarm leave --force`.

### Remote single node

Run the same init on the server through a Docker context (or plain ssh):

```sh
docker context create vps --docker "host=ssh://deploy@example.com"
docker --context vps swarm init
```

### Multi-node cluster

On the manager, advertise a reachable address. Init prints a join token:

```sh
docker swarm init --advertise-addr <manager-ip>
```

On each worker, join with that token:

```sh
docker swarm join --token <token> <manager-ip>:2377
```

Label nodes to target them with `placement.constraints`
(e.g. `"node.labels.zone==eu"`):

```sh
docker node update --label-add zone=eu <node>
```

Once the swarm exists, Alchemy connects to a **manager** node via
`Docker.Context` — every `Docker.Service` and overlay `Docker.Network`
operation runs against it.

## Deploying to a Swarm cluster

This example shows how to deploy a service to an existing Docker Swarm cluster.
It supports both local development and production deployment.

It uses local Docker during `alchemy dev`, and a Docker-over-SSH context for
production deployment. Remote context runs all commands on the remote server,
including building the image.

```typescript
import * as Alchemy from "alchemy";
import * as Docker from "alchemy/Docker";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";

export default Alchemy.Stack(
  "DockerSwarmExample",
  {
    providers: Layer.merge(Docker.providers()),
    state: Alchemy.localState(),
  },
  Effect.gen(function* () {
    const dev = yield* Alchemy.ALCHEMY_DEV;

    const context = yield* Docker.Context("docker-context", {
      name: dev ? "local" : "vps",
      docker: dev ? undefined : "host=ssh://user@hostname",
    });
    const network = yield* Docker.Network("docker-network", {
      context,
      driver: "overlay",
    });
    const image = yield* Docker.Image("docker-image", {
      context,
      tag: "latest",
      build: {
        context: ".",
        dockerfile: "./Dockerfile",
      },
    });
    const service = yield* Docker.Service("docker-service", {
      context,
      image,
      replicas: dev ? 1 : 3,
      networks: [network],
      ports: [
        {
          external: 8080,
          internal: 80,
        },
      ],
      ...(dev && {
        command: ["pnpm", "dev"],
        volumes: [
          {
            hostPath: `${process.cwd()}/app`,
            containerPath: "/app",
          },
        ],
      }),
    });

    return {
      container: service.name,
      port: service.ports,
    };
  }),
);
```

## Effectful services

`Docker.Service` is also a platform, like `AWS.ECS.Service`. Pass `main` and
an implementation instead of a pre-built image and Alchemy bundles the Effect
program, builds a content-addressed image against the service's Docker
context, and deploys it as a swarm service.

```typescript
import * as Docker from "alchemy/Docker";
import { ServerHost } from "alchemy/Server/Process";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

export default class Api extends Docker.Service<Api>()(
  "Api",
  {
    main: import.meta.url,
    port: 3000,
    ports: [{ external: 8080, internal: 3000 }],
    replicas: 2,
  },
  Effect.gen(function* () {
    const host = yield* ServerHost;
    yield* host.run(myBackgroundLoop);

    return {
      fetch: Effect.gen(function* () {
        return yield* HttpServerResponse.json({ ok: true });
      }),
    };
  }),
) {}
```

The returned `fetch` handler is served by a Bun HTTP server inside the
container on `port`, and `host.run` registers long-running background loops.
The image is rebuilt only when the bundled program changes.

The image is built on the target engine's local store, so a single-node swarm
runs it as-is. Multi-node swarms need the image on a registry every node can
reach: build with `Docker.Image` and a `registry`, then pass the pushed
reference as `image`.
