title: Stack References
description: Read the deployed outputs of another stage or Stack — Resource.ref by Logical ID, with optional stack/stage props, or import a Stack tag and depend on its outputs.

A reference reads an already-deployed Resource or Stack from the
state store at plan time. Three forms, smallest first.

## `Resource.ref` by Logical ID

Reference a Resource in this stack by its Logical ID:

```typescript
const project = yield* Neon.Project.ref("app-db");
```

Same type as `yield* Neon.Project("app-db", { … })` — pass it
anywhere the real thing is accepted.

## Reference another stage

Pass `stage` to read a different stage of the same stack:

```typescript
const { stage } = yield* Alchemy.Stack;

const project = stage.startsWith("pr-")
  ? yield* Neon.Project.ref("app-db", { stage: "staging" })
  : yield* Neon.Project("app-db", { region: "aws-us-east-1" });
```

`staging` owns the database; `pr-*` stages borrow it. Destroying
a borrower never touches the Resources it references.

Pass `stack` too for a Resource in a different Stack:

```typescript
const db = yield* Neon.Project.ref("app-db", {
  stack: "SharedInfra",
  stage: "prod",
});
```

Anything you omit defaults to the current stack/stage. Pin `stage`
when the stacks' stages don't line up — `pr-147` has no counterpart
in `SharedInfra`.

## Depend on a Stack's outputs

When the unit you consume is a whole Stack, import its tag and
yield it:

```typescript
// backend/src/Stack.ts
export class Backend extends Alchemy.Stack<
  Backend,
  {
    url: string;
  }
>()("Backend") {}
```

```typescript
// frontend/alchemy.run.ts
import { Backend } from "backend";

const backend = yield* Backend; // outputs of the matching stage

const website = yield* Cloudflare.Website.Vite("Website", {
  env: { VITE_API_URL: backend.url },
});
```

`yield* Backend` reads the matching stage; `Backend.stage.prod`
pins one. Full two-package walkthrough:
[Multiple Stacks](/guides/monorepo-multi-stack).

## Deploy order

The upstream must already be deployed to the exact
`{ stack, stage }` the reference names, or the plan fails fast
with `InvalidReferenceError`:

```sh
alchemy deploy --stage staging   # creates app-db
alchemy deploy --stage pr-147    # borrows staging's app-db
```

Destroy in reverse order.
