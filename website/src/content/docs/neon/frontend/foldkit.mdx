`Neon.Website.Foldkit` supports browser-only SPAs, server rendering, and
prerendered pages with request-time fallback. It packages Foldkit's assets and
optional generated handler as a Node 24 Fetch module in a Neon Function ZIP.

## Prepare the app

Use an existing Foldkit app or the
[runnable Foldkit example](https://github.com/alchemy-run/alchemy/tree/main/examples/neon-website-foldkit).
Configure [deployment credentials](/neon/setup), then install in the app directory:

Install [Alchemy and its matching Effect dependencies](/getting-started) first;
use Node 24 for this build toolchain.

```sh
pnpm add -D @alchemy.run/frontend-frameworks @vercel/nft
```

Keep the `foldkit()` plugin from `@foldkit/vite-plugin` in `vite.config.*` and
retain your application's normal entry configuration. No application adapter or
server wrapper is required.

## Define the stack

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Neon from "alchemy/Neon";
import * as Effect from "effect/Effect";

export default Alchemy.Stack(
  "NeonFoldkit",
  { providers: Neon.providers(), state: Alchemy.localState() },
  Effect.gen(function* () {
    const site = yield* Neon.Website.Foldkit("Web", {
      rootDir: ".",
    });
    return { url: site.url };
  }),
);
```

Unmatched GET/HEAD paths fall back to `index.html` for client-side routes.
For a multi-page build with a `404.html`, set `assets.notFoundHandling` to
`"404-page"`. Like Vite, `vite.outDir` and `vite.base` are supported overrides.

`env` values with Vite's `VITE_*` prefix are embedded into the browser build.
Server-rendered apps read private runtime values from `process.env`. Keep secrets
out of `VITE_*` keys because those values reach the browser.

## Server rendering and prerendering

Use Foldkit 0.167.0, `@foldkit/vite-plugin` 0.27.0 and Effect 4.0.0. Keep rendering
configuration in your app's `vite.config.ts`:

```typescript
import { foldkit } from "@foldkit/vite-plugin";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [foldkit({
    ssr: {
      serverEntry: "/src/entry.server.ts",
      clientEntry: "/src/entry.ts",
      build: { prerender: true },
    },
  })],
});
```

Import CSS from the client entry and export `renderDocument = Server.renderDocument`
alongside `renderPage` in the server entry. SSR/SSG builds generate their complete
HTML documents from code; remove the source `index.html`. Export `prerenderPaths`
when prerendering is enabled. Use `build: true` for SSR without prerendering. See
[Foldkit's server rendering guide](https://foldkit.dev/core/server-rendering)
for the application contract.

The same Website declaration detects the generated handler automatically.
GET and HEAD requests serve assets and prerendered pages first, including `/`
when it was prerendered. Remaining requests go to Foldkit's handler; POST
requests bypass static assets. SSG deployments retain the generated handler
for paths that were not prerendered, matching the SvelteKit/TanStack Start path.

Browser-only builds keep SPA fallback. An explicit `assets.notFoundHandling`
override takes precedence. Avoid SPA fallback on SSR apps unless intentional:
a prerendered `index.html` would then answer unmatched page requests.

Server code reads private runtime values from `process.env`; `VITE_*` values
remain public build-time browser configuration. Custom Foldkit client/server
output directories are read from the completed build metadata and packaged
together. `vite.outDir`, when supplied, places SSR outputs under `client/` and
`server/` in that directory.

## Develop and deploy

```sh
pnpm exec alchemy dev
pnpm exec alchemy deploy
pnpm exec alchemy destroy
```

Run separately, destroying when finished. Dev uses Vite's native server with Foldkit live reload,
returns a local URL, and creates no implicit Neon resources. Append
`.pipe(Alchemy.remote())` to the Website Effect to use live deployment during dev.

Live deploy creates an Ohio Project if no scope is supplied. Pass either
`project` or `branch` for an existing backend; choose Ohio for combined storage
use. Read [scope and credentials](/neon/frontend/vite#scope-and-credentials):
account keys and privileged branch tokens must not reach this browser bundle.

:::caution[Deployment limits]
Complete live framework acceptance remains unverified. Neon probes have served
old code/env after new deployment metadata became active. Static assets are
served inside the Function without an added CDN, and domain registration does
not validate TLS. See the
[shared deployment limits](/neon/frontend/vite#environment-and-deployment-limits).
:::
