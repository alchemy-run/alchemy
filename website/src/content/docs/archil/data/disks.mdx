title: Disks

A disk is an elastic POSIX file system. It has no size to provision:
it appears in milliseconds and bills for the bytes stored.

```typescript
const disk = yield* Archil.Disk("scratch");
```

The name defaults to `${app}-${stage}-${id}`. Names are account-global
per region, so let the engine generate them unless you have a reason
not to.

## Attributes

```typescript
disk.diskId;     // dsk-0123456789abcdef
disk.name;
disk.region;     // aws-us-east-1
disk.endpoint;   // that region's control plane
disk.status;     // available | creating | deleting | deleted | failed
disk.diskToken;  // Redacted — the one-time mount credential
```

`diskToken` is captured at creation and never returned by Archil
again. It is absent on adopted disks, because there was no creation
response to capture it from.

## What forces a replacement

Archil has no update API for a disk. Name, region, and storage mount
are all fixed at creation, so changing any of them replaces the disk —
and replacing a disk destroys its contents. Only `commands` can change
in place (see [Base images](/archil/compute/base-images)).

## Storage backends

A disk can sync with object storage instead of using Archil-managed
storage. Five backends:

```typescript
const data = yield* Archil.Disk("data", {
  mount: {
    type: "s3",
    bucketName: "my-bucket",
    bucketPrefix: "datasets/",
  },
});
```

`s3` (access keys optional — public buckets and IAM roles work),
`gcs` (HMAC keys), `r2` (endpoint + keys), `s3-compatible` (MinIO,
Backblaze), and `azure-blob` (tenant, client, secret).

A synced disk cannot use branches and checkpoints. Archil supports one
or the other, not both.

## Mount credentials

`Archil.DiskUser` authorizes a client to mount the disk. Two kinds:

```typescript
// a shared token, generated by Archil and returned once
const token = yield* Archil.DiskUser("ci-token", {
  disk,
  user: { type: "token", nickname: "ci" },
});

// an IAM principal that mounts via STS role assumption
const role = yield* Archil.DiskUser("ec2-role", {
  disk,
  user: {
    type: "awssts",
    principal: "arn:aws:iam::123456789012:role/app",
  },
});
```

The `awssts` form is how EC2, ECS, and EKS workloads mount without a
shared secret. Hand `token.diskToken` to `archil mount` or the CSI
driver out-of-band; it is `Redacted`, so it never lands in a log by
accident.

Changing the user replaces it — Archil has no update path, so the old
one is removed and a new one added.

## Control-plane tokens

`Archil.ApiToken` creates account-level API keys:

```typescript
const token = yield* Archil.ApiToken("ci", {
  description: "GitHub Actions",
});
```

The plaintext value is returned only at creation and is persisted as a
`Redacted` attribute for downstream consumers — a GitHub secret, say.
The `*Http` binding layers mint one of these per host automatically, so
you rarely declare one by hand.
