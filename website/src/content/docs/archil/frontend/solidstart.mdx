`Archil.Website.SolidStart` deploys a [SolidStart](https://start.solidjs.com) app to an Archil
sandbox, with nitro's `node` preset appended to your `vite build`; client assets and prerendered pages are served first. The site is the
[program](/archil/compute/programs) of its own sandbox, on port 3000, at a public
`https://3000-…archil.app` URL. A stopped sandbox starts again on the next
request.


## Install

The build integration is not bundled with alchemy. Install
`@alchemy.run/frontend-frameworks`; the resource loads its
`/solidstart` and `/solidstart/node` exports from your project at
deploy time. It is only used at build time, so a dev dependency is
enough:

<PackageManagers dev={devDeps} />

`@solidjs/vite-plugin-nitro-2` is the server half of a SolidStart
build and must be a project dependency too:

<PackageManagers add="@solidjs/vite-plugin-nitro-2" />

## Configure Vite

Your `vite.config.ts` is the SolidStart plugin — no adapter, no
nitro wiring. Vite plugins like Tailwind go in `plugins` as usual:

```typescript
// vite.config.ts
import { solidStart } from "@solidjs/start/config";
import tailwindcss from "@tailwindcss/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [solidStart(), tailwindcss()],
});
```

Alchemy appends its own `nitroV2Plugin()` instance at build time,
carrying nitro's `node` preset. Don't register `nitroV2Plugin()`
yourself — the appended instance would discard its options, so the
build fails with an actionable error instead. Pass nitro options
through the resource's `nitro` prop; see [Prerendering](#prerendering)
below.

## Declare the Website

Declare the site as a module-level const:

```typescript
// alchemy.run.ts
import * as Archil from "@alchemy.run/archil";

export const Website = Archil.Website.SolidStart("Website");
```

`sandbox` sizes the site's sandbox and sets its image, timeouts, disks and network policy:

```diff lang="typescript"
// alchemy.run.ts
export const Website = Archil.Website.SolidStart("Website", {
+  sandbox: { vcpuCount: 2, memSizeMiB: 4096, idleTtlSeconds: 600 },
});
```

## Add it to the Stack

Yield the site from your Stack and return its URL:

```typescript
// alchemy.run.ts
import * as Archil from "@alchemy.run/archil";
import * as Alchemy from "alchemy";
import * as Effect from "effect/Effect";

export const Website = Archil.Website.SolidStart("Website");

export default Alchemy.Stack(
  "MySolidStartSite",
  {
    providers: Archil.providers(),
    state: Alchemy.localState(),
  },
  Effect.gen(function* () {
    const site = yield* Website;
    return { url: site.url };
  }),
);
```

Run `alchemy deploy`. `url` is the site's `https://3000-…archil.app` URL.
`site.sandbox` is the sandbox behind it, and `undefined` under
`alchemy dev`.

See
[examples/archil-website-solidstart](https://github.com/alchemy-run/alchemy/tree/main/examples/archil-website-solidstart)
for the checked-in example.

## Add environment variables

Process environment is a top-level `env` map — plain strings, or
`Redacted` values:

```diff lang="typescript"
// alchemy.run.ts
export const Website = Archil.Website.SolidStart("Website", {
+  env: {
+    API_BASE: "https://api.example.com",
+  },
});
```

The values are copied onto `process.env` before the build and the
dev server, and onto the program at deploy time, so server
code reads the same keys in both modes. Client inlining is whatever
Vite does (`VITE_` prefixes).

An output from another resource only exists once that resource is
yielded, so declare the site inside the Stack generator instead:

```typescript
// alchemy.run.ts
Effect.gen(function* () {
  const api = yield* Api;

  const site = yield* Archil.Website.SolidStart("Website", {
    env: { API_BASE: api.url },
  });

  return { url: site.url };
});
```

## Read the environment in server code

The SolidStart server is a plain Node process, so API routes,
server functions, and SSR read the environment from `process.env`:

```typescript
// src/routes/api/hello.ts
export function GET() {
  return new Response(process.env.API_BASE ?? "unset");
}
```

Values prefixed `VITE_` are inlined into the client bundle at build
time instead, as `import.meta.env.VITE_*` — set those in the shell
that runs `alchemy deploy`, not in `env`.

## Prerendering

Nitro renders the routes you list at build time into `.output/public`.
They are uploaded with the program and served as static files with no
handler invocation:

```typescript
export const Website = Archil.Website.SolidStart("Website", {
  nitro: { prerender: { routes: ["/", "/about"] } },
});
```

`prerender` takes the routes to render (`routes`) and can crawl links
from prerendered pages to prerender them too (`crawlLinks`). The
`nitro` prop is the home for all nitro options (route rules, storage,
...) — the integration owns the plugin instance, so they cannot live
in `vite.config.ts`. Values must be JSON-serializable; `preset` is
owned by the Node deploy target, and a foreign preset is a hard error.

## Local dev

```sh
bun alchemy dev
```

`alchemy dev` runs SolidStart's own Vite dev server (native HMR)
instead of deploying; `site.url` is the local address and no Archil
resources are created. Nitro plays no part in dev. Wrap the site in
`Alchemy.remote()` to deploy the live sandbox even during
dev:

```typescript
export const Website = Archil.Website.SolidStart("Website").pipe(
  Alchemy.remote(),
);
```

SolidStart's plugin resolves its app root and route directory from
the process working directory, so one `alchemy dev` process serves
one SolidStart app at a time.

:::caution[Run `alchemy dev` under Node]
SolidStart 2's dev server answers requests through `srvx/node`, which
returns the string `[object Object]` instead of the rendered document
when it runs under Bun. Production builds are unaffected — only the
dev server is. Until that upstream gap closes, run `alchemy dev` with
Node (`npx alchemy dev`) for SolidStart projects.
:::
