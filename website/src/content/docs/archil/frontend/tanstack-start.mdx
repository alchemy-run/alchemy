`Archil.Website.TanStackStart` deploys a [TanStack Start](https://tanstack.com/start) app to an Archil
sandbox, (React or Solid), built through your own `vite build`. The site is the
[program](/archil/compute/programs) of its own sandbox, on port 3000, at a public
`https://3000-…archil.app` URL. A stopped sandbox starts again on the next
request.


## Install

The build integration is not bundled with alchemy. Install
`@alchemy.run/frontend-frameworks`; the resource loads its
`/tanstack-start` and `/tanstack-start/node` exports from your project
at deploy time. It is only used at build time, so a dev dependency is
enough:

<PackageManagers dev={devDeps} />

## Configure Vite

Your `vite.config.ts` stays what TanStack Start's scaffold gives
you — no adapter, no deployment preset. Vite plugins like Tailwind
go in `plugins` as usual:

```typescript
// vite.config.ts
import tailwindcss from "@tailwindcss/vite";
import { tanstackStart } from "@tanstack/react-start/plugin/vite";
import viteReact from "@vitejs/plugin-react";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [tailwindcss(), tanstackStart(), viteReact()],
});
```

Alchemy drives that config's `builder.buildApp()` and forces the SSR
bundle to be self-contained, then wraps its fetch handler as a Node
HTTP server on port 3000.

:::caution[Remove @cloudflare/vite-plugin if present]
The TanStack CLI adds `@cloudflare/vite-plugin` when scaffolding a new
app. It builds for workerd, not Node, so a Archil deploy needs it
gone:

```diff lang="typescript"
// vite.config.ts
-import { cloudflare } from "@cloudflare/vite-plugin";
import { tanstackStart } from "@tanstack/react-start/plugin/vite";
import viteReact from "@vitejs/plugin-react";
import { defineConfig } from "vite";

export default defineConfig({
-  plugins: [
-    cloudflare({ viteEnvironment: { name: "ssr" } }),
-    tanstackStart(),
-    viteReact(),
-  ],
+  plugins: [tanstackStart(), viteReact()],
});
```

:::

## Declare the Website

Declare the site as a module-level const:

```typescript
// alchemy.run.ts
import * as Archil from "@alchemy.run/archil";

export const Website = Archil.Website.TanStackStart("Website");
```

`sandbox` sizes the site's sandbox and sets its image, timeouts, disks and network policy:

```diff lang="typescript"
// alchemy.run.ts
export const Website = Archil.Website.TanStackStart("Website", {
+  sandbox: { vcpuCount: 2, memSizeMiB: 4096, idleTtlSeconds: 600 },
});
```

## Add it to the Stack

Yield the site from your Stack and return its URL:

```typescript
// alchemy.run.ts
import * as Archil from "@alchemy.run/archil";
import * as Alchemy from "alchemy";
import * as Effect from "effect/Effect";

export const Website = Archil.Website.TanStackStart("Website");

export default Alchemy.Stack(
  "MyTanStackStartSite",
  {
    providers: Archil.providers(),
    state: Alchemy.localState(),
  },
  Effect.gen(function* () {
    const site = yield* Website;
    return { url: site.url };
  }),
);
```

Run `alchemy deploy`. `url` is the site's `https://3000-…archil.app` URL.
`site.sandbox` is the sandbox behind it, and `undefined` under
`alchemy dev`.

See
[examples/archil-website-tanstack-start](https://github.com/alchemy-run/alchemy/tree/main/examples/archil-website-tanstack-start)
for the checked-in example.

## Add environment variables

Process environment is a top-level `env` map — plain strings, or
`Redacted` values:

```diff lang="typescript"
// alchemy.run.ts
export const Website = Archil.Website.TanStackStart("Website", {
+  env: {
+    API_BASE: "https://api.example.com",
+  },
});
```

The values are copied onto `process.env` before the build and the
dev server, and onto the program at deploy time, so server
code reads the same keys in both modes. Client inlining is whatever
Vite does (`VITE_` prefixes).

An output from another resource only exists once that resource is
yielded, so declare the site inside the Stack generator instead:

```typescript
// alchemy.run.ts
Effect.gen(function* () {
  const api = yield* Api;

  const site = yield* Archil.Website.TanStackStart("Website", {
    env: { API_BASE: api.url },
  });

  return { url: site.url };
});
```

## Read the environment in a server function

The TanStack Start server is a plain Node process, so server
functions read the environment from `process.env`:

```typescript
// src/routes/index.tsx
import { createServerFn } from "@tanstack/react-start";

const getApiBase = createServerFn({ method: "GET" }).handler(() => ({
  apiBase: process.env.API_BASE ?? "unset",
}));
```

Values prefixed `VITE_` are inlined into the client bundle at build time
instead, as `import.meta.env.VITE_*` — set those in the shell that runs
`alchemy deploy`, not in `env`.

## Read the environment in a server route

Server routes run on the same Node process and read `process.env` the
same way:

```typescript
// src/routes/api.hello.ts
import { createFileRoute } from "@tanstack/react-router";

export const Route = createFileRoute("/api/hello")({
  server: {
    handlers: {
      GET: () => new Response(process.env.API_BASE ?? "unset"),
    },
  },
});
```

## Build configuration

The build runs through your project's own `vite.config.ts` — the
`tanstackStart()` plugin and everything else in it apply as-is. Keep
vite's default `build.outDir` (`dist`); the integration reads the
server and client output from `dist/server` and `dist/client`.

## Local dev

```sh
bun alchemy dev
```

`alchemy dev` runs TanStack Start's own Vite dev server (native HMR)
instead of deploying; `site.url` is the local address and no Archil
resources are created. Wrap the site in `Alchemy.remote()` to deploy
the live sandbox even during dev:

```typescript
export const Website = Archil.Website.TanStackStart("Website").pipe(
  Alchemy.remote(),
);
```

## Solid variant

TanStack Start's Solid flavor works the same way — swap the plugins in
`vite.config.ts` and keep the identical `alchemy.run.ts`:

```typescript
// vite.config.ts
import { tanstackStart } from "@tanstack/solid-start/plugin/vite";
import { defineConfig } from "vite";
import viteSolid from "vite-plugin-solid";

export default defineConfig({
  plugins: [tanstackStart(), viteSolid({ ssr: true })],
});
```

`@tanstack/solid-start` exposes the same `tanstackStart()` plugin entry
point and the same `client`/`ssr` build environments, so the deploy is
identical.
