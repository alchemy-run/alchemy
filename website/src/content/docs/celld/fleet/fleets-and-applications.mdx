On Cloudflare, your Workers run on machines you never see. Celld gives you
the same programming model on machines you own. The **fleet** is those
machines: a group of nodes that run Workers and Durable Objects, and one
bucket that holds everything they store.

This chapter explains what a fleet is made of, why its nodes can come and go
without losing anything, and how your Workers get onto it. The rest of this
section builds on it: where the nodes run, how deploys reach them, and how
the fleet scales, upgrades and keeps its data.

## A fleet is nodes and a bucket

Each node is a process running Celld, which embeds V8 to run Workers. Nodes
keep nothing of their own. Every Durable Object, KV namespace, D1 database,
R2 bucket, queue and workflow run lives in the fleet's bucket, and so does
the code of every Worker you publish.

That split is what makes a fleet easy to operate. A Durable Object writes its
SQLite changes to the bucket before it acknowledges them, so a node can stop
at any moment and another node picks up where it left off. Adding a node,
replacing one, or upgrading all of them never moves data.

## Declare it

A fleet is a class, like a Worker, but it carries no code. Its props describe
the nodes: how many, how big, and whether the internet can reach them.

```typescript title="src/fleet.ts"
import * as Celld from "@alchemy.run/celld";

export class Cells extends Celld.Fleet<Cells>()("Cells", {
  instances: 2,
  ingress: true,
}) {}
```

The declaration says nothing about AWS. Where the nodes actually run is
decided by a host Layer you provide next to your providers, which the next
chapter, [Hosting on ECS](/celld/fleet/ecs), covers.

Keep the logical ID, `Cells`, stable. It names the bucket, and a new ID means
a new, empty fleet.

## Workers are staged, not served

A Celld Worker is declared the same way as a Cloudflare one.

```typescript title="src/api.ts"
export default class Api extends Celld.Worker<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    return { fetch: Effect.succeed(HttpServerResponse.text("ok")) };
  }),
) {}
```

Deploying it bundles the code and uploads it to the fleet's bucket. That's
all. Nothing serves it yet, because a fleet doesn't serve Workers one at a
time. It serves one graph of Workers at a time: the one that answers HTTP
requests, and every Worker, queue consumer and cron trigger behind it.

## An Application is what the fleet serves

The Application names that graph and turns it on.

```typescript title="alchemy.run.ts"
const app = yield* Celld.Application("App", {
  entrypoint: Api,
  workers: [Jobs],
});
```

`entrypoint` is the Worker the fleet's listener sends requests to. `workers`
lists the rest. The Application publishes all of them, attaches their queue
consumers and cron triggers, and activates the result as one revision.

Activating them together means a deploy changes the whole graph in one
revision, and the deploy waits until the nodes have loaded it. If they can't,
the deploy fails, `app.url` is never returned, and your next deploy with a
fixed graph replaces the failed revision. So use `app.url`, not a Worker's
URL, as the sign that a deploy is live.

A fleet runs one Application.

## Select the fleet for everything inside

Celld declarations don't take a fleet as a prop. Instead, `Fleet.layer`
selects one for everything in its scope.

```typescript title="alchemy.run.ts"
Effect.gen(function* () {
  const app = yield* Celld.Application("App", { entrypoint: Api });
  return { url: app.url };
}).pipe(Effect.provide(Celld.Fleet.layer(Cells)));
```

The Application, its Workers, and the KV namespaces, D1 databases, R2 buckets
and queues they bind all land in `Cells`. A binding that reaches for a
resource in another fleet is refused when you deploy, because the two
buckets can't see each other.

A Worker implemented with `.make()` is provided in the same Layer, so other
Workers can import its class without bundling its code.

```typescript title="alchemy.run.ts"
Effect.provide(JobsLive.pipe(Layer.provideMerge(Celld.Fleet.layer(Cells))));
```
