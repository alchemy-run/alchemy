---
title: Management runners
description: Choose how a Celld fleet's management runner is hosted — an on-demand Fargate task, an always-on service, or a VPC Lambda — and what each costs.
---

A deploy calls the fleet's nodes to activate a revision, reload Workers and run
D1 migrations. The nodes accept those calls only on a private operator listener,
so the deploy sends them through a management runner inside the fleet's network.

`CelldAWS.EcsFleet()` requires a Layer that decides how that runner is hosted.
Leaving it out is a type error, and only the Layer you provide, with its runner
code, ends up in your program:

```ts
CelldAWS.EcsFleet().pipe(Layer.provide(CelldAWS.EcsTaskManagement()));
```

## Start a task on demand

`CelldAWS.EcsTaskManagement()` runs the runner as a small Fargate task that reads
requests from an SQS queue. The deploy's first management call starts the task
and waits for it, typically about a minute. Later calls reuse it, and it stops
after `idleSeconds` without work (five minutes by default):

```ts
CelldAWS.EcsFleet().pipe(Layer.provide(CelldAWS.EcsTaskManagement({ idleSeconds: 900 })));
```

Nothing runs between deploys, and a running task costs under two cents an hour.
A task releases its network interface as soon as it stops, so destroying the
fleet takes a few minutes. This is the right default for most stacks.

## Keep a task running

`CelldAWS.EcsServiceManagement()` keeps one runner task up with an ECS service, so
management calls never wait for it to start:

```ts
CelldAWS.EcsFleet().pipe(Layer.provide(CelldAWS.EcsServiceManagement()));
```

The task (0.25 vCPU, 0.5 GB, ARM) and its public IPv4 address cost about $11 a
month in us-east-1. Choose it when you deploy often enough, from CI for example,
that a minute per deploy matters more than the bill.

## Invoke a VPC Lambda

`CelldAWS.EcsLambdaManagement()` runs the runner as a Lambda inside the fleet's
subnets, invoked directly over IAM:

```ts
CelldAWS.EcsFleet().pipe(Layer.provide(CelldAWS.EcsLambdaManagement()));
```

It costs nothing between deploys, and calls wait only for a Lambda cold start.
AWS releases a VPC Lambda's network interfaces slowly, though, so destroying the
fleet takes around 20 minutes. The Lambda reaches the fleet bucket privately: in
your own VPC it adds an S3 gateway endpoint to the subnets' route tables when
they don't have one. Choose it for a long-lived fleet you rarely destroy.

## Runtime behavior

The runner only handles deploy-time calls; requests to your Workers never go
through it. Its IAM role reaches the fleet bucket and its own queue,
and its security group is the only one the nodes' operator listener admits.
