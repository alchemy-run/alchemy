---
title: Workers
description: Compose an HTTP Worker and its durable objects, then publish them as a Celld Application.
---

Start with the Fleet and Stack from [Setup](/celld/setup). A Celld Worker stages
code and bindings; an Application publishes and activates the selected graph.

## Declare a Worker

```typescript
// src/worker.ts
import * as Celld from "alchemy/Celld";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

export default class Api extends Celld.Worker<Api>()(
  "Api",
  { main: import.meta.url, expose: "public" },
  Effect.gen(function* () {
    return { fetch: Effect.succeed(HttpServerResponse.text("Hello from Celld")) };
  }),
) {}
```

The outer Effect assembles the handler. It can resolve services and register
bindings; request I/O belongs in `fetch`, not in construction.

## Register a durable object

Create the [Counter](/celld/compute/durable-objects) first, then add its class to
the Worker's construction Effect:

```diff lang="typescript"
+import Counter from "./counter.ts";

   Effect.gen(function* () {
+    const counters = yield* Counter;
     return { fetch: Effect.succeed(HttpServerResponse.text("Hello from Celld")) };
   }),
```

Yielding the class registers its namespace on this Worker. It does not select
or activate any particular Counter instance.

## Call a named instance

```diff lang="typescript"
-    return { fetch: Effect.succeed(HttpServerResponse.text("Hello from Celld")) };
+    return {
+      fetch: Effect.gen(function* () {
+        const count = yield* counters.getByName("visits").increment();
+        return HttpServerResponse.text(String(count));
+      }),
+    };
```

`"visits"` selects one durable identity. Every request to this example increments
the same counter; a real application should authorize any user-selected name.

## Declare a service Worker

```typescript
// src/jobs.ts
import * as Celld from "alchemy/Celld";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";

export default class Jobs extends Celld.Worker<Jobs>()(
  "Jobs",
  { main: import.meta.url },
  Effect.gen(function* () {
    return { fetch: Effect.succeed(HttpServerResponse.text("Jobs ready")) };
  }),
) {}
```

This secondary Worker does not request public ingress. Service and queue-consumer
Workers are separate graph members even though they share a fleet.

## Publish the Worker graph

Update the Setup stack:

```diff lang="typescript"
+import Jobs from "./src/jobs.ts";

-    const app = yield* Celld.Application("App", { entrypoint: Api });
+    const app = yield* Celld.Application("App", {
+      entrypoint: Api,
+      workers: [Jobs],
+    });
```

Only the entrypoint may request public ingress. List each Worker exactly once,
and keep service-binding and queue-consumer Workers in the same fleet. Staging a
Worker without publishing the Application does not activate a new revision.

## Runtime behavior

Construction is reused by the runtime. Each HTTP event gets its own request
scope; acquire disposable resources lazily there. Durable Object instance
initialization is a separate inner Effect, which runs on activation. Provide
implementation dependencies once with `Effect.provide`; combine independent
layers with `Layer.mergeAll`.

## Limit dynamically loaded Workers

Register the loader in the Worker's initialization Effect:

```typescript
const loader = yield* Celld.WorkerLoader();
```

Load the code inside a request, where the runtime supplies the scope that disposes
an anonymous loaded Worker:

```typescript
const loaded = yield* loader.load({
  compatibilityDate: "2026-09-01",
  mainModule: "main.js",
  modules: {
    "main.js": "export default { fetch() { return new Response('ok'); } }",
  },
  globalOutbound: null,
  limits: { cpuMs: 50, subRequests: 10 },
});
```

`cpuMs` bounds CPU time per invocation. `subRequests` bounds outbound subrequests.
Celld validates and enforces these limits in the loaded isolate.

## Select stricter invocation limits

```typescript
const entrypoint = yield* loaded.getEntrypoint(null, {
  limits: { cpuMs: 20, subRequests: 2 },
});
```

The selected limits apply to fetch and direct RPC calls. For each field, Celld
uses the lower value from the loaded code and the entrypoint selection. Class
selectors and `ctx.exports` loopbacks accept `props` only.

## Receive loaded Worker reports

A same-fleet Worker can receive completed fetch reports through an Effect-native
`tail` handler:

```typescript
// src/logs.ts
import * as Celld from "alchemy/Celld";
import * as Effect from "effect/Effect";

export default class Logs extends Celld.Worker<Logs>()(
  "Logs",
  { main: import.meta.url },
  Effect.succeed({
    tail: (events: readonly Celld.TailEvent[]) =>
      Effect.forEach(
        events,
        (event) => Effect.logInfo({
          outcome: event.outcome,
          status: event.event.response?.status,
        }),
        { discard: true },
      ),
  }),
) {}
```

Each report includes request metadata, response status, console records, uncaught
exceptions, and an outcome. The handler runs with the usual request scope.
Request metadata can include sensitive headers and query parameters; choose the
fields you retain.

## Attach the tail Worker

With `logs` referencing the same-fleet Logs Worker, bind it in the caller's
initialization Effect and provide `Celld.FetchBinding` on that Effect:

```typescript
const tail = yield* Celld.Fetch(logs);
```

Inside the request, pass the original native capability when loading the code:

```typescript
const loaded = yield* loader.load({ ...source, tails: [tail.raw] });
```

Include the Logs Worker in `Application.workers`. The `raw` getter preserves the
native capability identity required by Celld. Tail delivery follows completion
of the loaded fetch and its background work; a tail-handler failure leaves the
response unchanged. Native console capture is capped at 256 KiB per invocation.
Tails currently report fetch invocations; direct RPC calls receive the configured
limits but produce no tail report.

## Limitations

Celld's Worker surface is provider-owned. Cloudflare-only bindings do not become
available by changing an import. Public ingress is an application decision;
management traffic stays on the host's private control path.

Celld v0.6.0 runs cron triggers only on the Application entrypoint and cannot
safely retire a previous root's persisted cron cell. Once the root has cron
triggers, Application rejects changing its script identity or removing all
triggers before native publication writes. Keep the same root script and a
nonempty schedule; changing cron expressions remains supported. Replacing that
root or removing its entire schedule requires verified native cron retirement
support.
