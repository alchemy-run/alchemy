[Celld](https://github.com/denoland/celld) runs V8 Workers and SQLite-backed
Durable Objects on infrastructure you own. Alchemy deploys a Celld **Fleet**
onto AWS ECS and publishes your Workers to it as an **Application**. The
Workers use the same Effect APIs and Cloudflare-style bindings as
[Cloudflare Workers](/cloudflare).

```typescript
// alchemy.run.ts
export default Alchemy.Stack(
  "App",
  {
    providers: Layer.mergeAll(
      AWS.providers(),
      Celld.providers(),
      Celld.EcsFleet().pipe(Layer.provide(Celld.EcsTaskManagement())),
    ),
    state: AWS.state(),
  },
  Effect.gen(function* () {
    const app = yield* Celld.Application("App", { entrypoint: Api });
    return { url: app.url };
  }).pipe(Effect.provide(Celld.Fleet.layer(Cells))),
);
```

## How it differs from Cloudflare

Celld embeds V8, not workerd, and runs where you deploy it: there's no global
edge, no Cloudflare product integrations, and no `alchemy dev` emulator yet.
Data lives in your fleet's S3 bucket, and you pay AWS for the nodes, load
balancer and storage. The guides mirror their Cloudflare counterparts, but
check each page's limitations before you port code.
