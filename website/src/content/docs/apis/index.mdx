Every Function and Server returns `{ fetch, ...rpcs }` from its
[Effectful Constructor](/infrastructure-as-effects/runtime#the-effectful-constructor).
Alchemy gives you three ways to expose that surface to callers. This
page explains how they differ and when to use each one.

## The three modalities

- **[Schemaless RPC](/apis/schemaless)**: plain functions that return an `Effect` or a `Stream`, with no schema.
  - Internal pairings include Worker → Worker, Worker → Durable Object, Durable Object → Container, and Lambda → MicroVM.
  - Any resource that binds the class gets a typed client. MicroVMs connect explicitly with `connectMicrovm`. [The typed client](/apis/schemaless#the-typed-client) lists the binders.
  - Each call costs a proxy dispatch, a structured clone (native bindings) or JSON arguments (fetch transport), and an envelope-tag check. Nothing is validated.
- **[Effect RPC](/apis/effect-rpc)**: procedures declared in an `RpcGroup` schema.
  - A client is the schema plus a Fetcher, which is a binding or a URL.
  - Each request costs a frame parse, a schema decode of the payload, the handler, and a schema encode of the result, mirrored on the client.
- **[Effect HTTP](/apis/effect-http)**: REST endpoints declared in an `HttpApi` schema.
  - Clients use plain HTTP, with real URLs, path params, query strings, headers, content types, and `curl`.
  - Each request costs the same as Effect RPC.

## Trust boundaries

A trust boundary is where data arrives from code you don't deploy
yourself, such as a web app, a partner service, or an external caller.
That data needs validating and sanitizing, so Effect RPC and Effect
HTTP decode and encode every request against a schema on both sides.

Internal calls skip that cost. You control both ends, deploy them
together, and the client type is the class you bound. A schema decode
there adds time to every request and catches nothing the types don't.

## Choosing

Pick by who calls the API:

- **Code you deploy with this stack**: [Schemaless RPC](/apis/schemaless).
- **An external Effect or TypeScript program**: [Effect RPC](/apis/effect-rpc).
- **Any other external consumer**: [Effect HTTP](/apis/effect-http).

The schema'd modalities build an `HttpEffect` that you return as
`fetch`, so one Worker or Function can serve both surfaces:

```typescript
return {
  // Schemaless RPC for internal callers that bind this class
  ping: () => Effect.succeed("pong"),
  // Effect RPC or Effect HTTP for external callers
  fetch: yield* ApiHttpEffect,
};
```

[Effect RPC › Serve it](/apis/effect-rpc#serve-it) builds `ApiHttpEffect`.

## Where next

- [Schemaless RPC](/apis/schemaless): typed clients, Streams, and error propagation with no schema.
- [Effect RPC](/apis/effect-rpc): `RpcGroup` schemas, handler layers, and clients built from the schema and a Fetcher.
