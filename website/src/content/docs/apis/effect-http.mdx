Effect HTTP (`effect/unstable/httpapi`) works like
[Effect RPC](/apis/effect-rpc). You define a schema, construct handler
layers, return an `HttpEffect` from `fetch`, and call it through an
rpc-like typed interface.

What goes on the wire differs. Effect HTTP serves real HTTP endpoints,
with URLs, path params, query strings, headers, bodies, and content
types. Use it at a [trust boundary](/apis#trust-boundaries) when the
consumers aren't Effect or TypeScript programs and want a plain HTTP
client.

## The pieces

An Effect HTTP API is four files:

```sh
src/
├── Task.ts        # domain model + typed 404 (Schema.Class, TaggedErrorClass)
├── ApiSchema.ts   # endpoint declarations, one HttpApi value imported by server AND clients
├── ApiService.ts  # the host, a Worker or Lambda Function wired on the hub pages, returns { fetch }
└── ApiClient.ts   # typed client derived from ApiSchema, no codegen, no string URLs
```

`src/ApiSchema.ts` is the contract. The server implements it, every
typed client derives from it, and plain HTTP consumers get its
validation.

## The domain types

`src/Task.ts` owns the value that crosses the wire and the error that
crosses with it:

```typescript
// src/Task.ts
import * as Schema from "effect/Schema";

export class Task extends Schema.Class<Task>("Task")({
  id: Schema.String,
  title: Schema.String,
  completed: Schema.Boolean,
}) {}

export class TaskNotFound extends Schema.TaggedErrorClass<TaskNotFound>()(
  "TaskNotFound",
  { id: Schema.String },
  { httpApiStatus: 404 }, // a real 404 over plain HTTP instead of a generic 500
) {}
```

`Schema.Class` gives you a runtime-validated class with an inferred
TypeScript type. Both sides import the one definition.

## The endpoints

`src/ApiSchema.ts` declares the endpoints, a group, and the API value:

```typescript
// src/ApiSchema.ts
import * as Schema from "effect/Schema";
import * as HttpApi from "effect/unstable/httpapi/HttpApi";
import * as HttpApiEndpoint from "effect/unstable/httpapi/HttpApiEndpoint";
import * as HttpApiGroup from "effect/unstable/httpapi/HttpApiGroup";
import { Task, TaskNotFound } from "./Task.ts";

export const getTask = HttpApiEndpoint.get("getTask", "/:id", {
  params: Schema.Struct({ id: Schema.String }), // params.id is a typed string
  success: Task,
  error: TaskNotFound,
});

export const createTask = HttpApiEndpoint.post("createTask", "/", {
  payload: Schema.Struct({ title: Schema.String }), // decoded before the handler runs
  success: Task,
});

export class TasksGroup extends HttpApiGroup.make("Tasks")
  .add(getTask)
  .add(createTask) {}

export class TaskApi extends HttpApi.make("TaskApi").add(TasksGroup) {}
```

Endpoints are pure declarations of `(method, path, schemas)`. A body
that doesn't match `payload` gets an automatic 400 with a structured
validation error. `TaskApi` is a plain value, so the server and every
client import it without pulling in runtime code.

## Handlers

`HttpApiBuilder.group` wires one handler per endpoint:

```typescript
// src/ApiService.ts, inside the host's construction phase
import * as Effect from "effect/Effect";
import * as HttpApiBuilder from "effect/unstable/httpapi/HttpApiBuilder";
import { TaskApi } from "./ApiSchema.ts";
import { Task, TaskNotFound } from "./Task.ts";

const tasksGroup = HttpApiBuilder.group(TaskApi, "Tasks", (handlers) =>
  handlers
    .handle("getTask", ({ params }) =>
      // look up the task in storage, the hub guides wire R2 or DynamoDB
      Effect.fail(new TaskNotFound({ id: params.id })),
    )
    .handle("createTask", ({ payload }) =>
      Effect.succeed(
        new Task({
          id: crypto.randomUUID(),
          title: payload.title,
          completed: false,
        }),
      ),
    ),
);
```

Each handler receives the typed request its endpoint declared. The
handler must return a `Task`, and the only allowed failure is
`TaskNotFound`, so a wrong shape or an undeclared error fails at
compile time.

`HttpApiBuilder.group` constructs a handler layer and runs nothing. It
is safe in the construction phase, which also runs at deploy time
([Phases](/infrastructure-as-effects/phases)).

## Serve it

Assemble the API layer and convert it into the `HttpEffect` that
`fetch` expects:

```typescript
// src/ApiService.ts, end of the construction phase
import * as Http from "alchemy/Http";
import * as Layer from "effect/Layer";
import * as HttpRouter from "effect/unstable/http/HttpRouter";

return {
  fetch: yield* HttpRouter.toHttpEffect(
    HttpApiBuilder.layer(TaskApi).pipe(
      Layer.provide(tasksGroup),
      // HttpPlatform, Etag, Path, and a no-op FileSystem for Workers and
      // Lambda. File responses die there.
      Layer.provide(Http.Platform),
    ),
  ),
};
```

`HttpRouter.toHttpEffect` builds the layer once at boot and yields the
request handler, the same `{ fetch }` shape a Worker or a Lambda
Function serves. `Http.Platform` supplies the services
`HttpApiBuilder.layer` needs on runtimes without a filesystem.

Authentication, CORS, storage bindings, and deploy are host-specific:

- [Effect HTTP on Workers](/cloudflare/apis/effect-http-api): a Worker host with R2 storage. CORS is in [Enable CORS](/cloudflare/apis/effect-http-api#3d-enable-cors).
- [Effect HTTP on Lambda](/aws/apis/effect-http-api): a Lambda host with DynamoDB storage. The Function URL is on and public by default, so see [Restrict access to the URL](/aws/apis/effect-http-api#restrict-access-to-the-url) for auth and CORS.

## Plain HTTP for everyone else

The wire format is ordinary REST, so consumers need nothing but an
HTTP client:

```sh
curl -X POST https://<your-api-url>/ \
  -H "Content-Type: application/json" \
  -d '{"title": "Write docs"}'
# → {"id":"...","title":"Write docs","completed":false}

curl https://<your-api-url>/<id>
# → {"id":"...","title":"Write docs","completed":false}
```

Invalid payloads get automatic 400 responses with structured
validation errors. A missing task comes back as a real 404 from the
`httpApiStatus` on `TaskNotFound`. This holds in any language, with
any HTTP library.

## A typed client

For consumers that are Effect programs, the same `TaskApi` value
drives a typed client with no codegen and no string URLs:

```typescript
// src/ApiClient.ts
import * as Effect from "effect/Effect";
import * as FetchHttpClient from "effect/unstable/http/FetchHttpClient";
import * as HttpApiClient from "effect/unstable/httpapi/HttpApiClient";
import { TaskApi } from "./ApiSchema.ts";

const program = Effect.gen(function* () {
  const client = yield* HttpApiClient.make(TaskApi, {
    baseUrl: process.env.TASK_API_URL!,
  });

  // `payload` is for bodies
  const created = yield* client.Tasks.createTask({
    payload: { title: "Write docs" },
  });

  // `params` is for path parameters
  // Effect<Task, TaskNotFound | HttpClientError | SchemaError>
  const task = yield* client.Tasks.getTask({
    params: { id: created.id },
  });
  console.log(task.title);
});

// HttpApiClient.make needs an HttpClient
Effect.runPromise(program.pipe(Effect.provide(FetchHttpClient.layer)));
```

The 404 arrives as a typed `TaskNotFound` you pattern-match on, with
no status code to interpret. `SchemaError` is raised when a payload
fails to encode or a response fails to decode.

The client can also use a binding instead of a URL. See the
[Durable Object bridge](/cloudflare/apis/effect-http-api#bridge-the-do-into-a-typed-client)
on the Workers page.
