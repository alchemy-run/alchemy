Effect RPC is schema-first. Every procedure declares `payload`,
`success`, and `error` schemas, and every request and response is
validated against them. Use it at a [trust boundary](/apis#trust-boundaries)
when the consumers are Effect or TypeScript programs, and
[Schemaless RPC](/apis/schemaless) for internal calls.

## The pieces

An RPC API is five small files:

```sh
src/
├── Task.ts        # domain model + tagged errors, imported by server AND client
├── ApiSchema.ts   # one Rpc.make per procedure, collected into an RpcGroup
├── ApiHandlers.ts # RpcGroup.toLayer handlers + the HttpEffect, host-agnostic
├── ApiService.ts  # the host, a Lambda Function or Cloudflare Worker, wired on the hub pages
└── ApiClient.ts   # a typed client, the same schema + a Fetcher
```

The schema files are plain values with no runtime concerns, so the
server and every client import them directly. Only `ApiService.ts`
names a cloud.

## The domain types

The domain model and error types are pure schemas:

```typescript
// src/Task.ts
import * as Schema from "effect/Schema";

export class Task extends Schema.Class<Task>("Task")({
  id: Schema.String,
  title: Schema.String,
  completed: Schema.Boolean,
}) {}

export class TaskNotFound extends Schema.TaggedClass<TaskNotFound>()(
  "TaskNotFound",
  { id: Schema.String },
) {}

export class CreateTaskFailed extends Schema.TaggedClass<CreateTaskFailed>()(
  "CreateTaskFailed",
  { message: Schema.String },
) {}
```

RPC errors are schema-backed tagged classes. The client receives them
as typed values it can `catchTag` on, with no HTTP status codes to
interpret.

## The procedures

Each `Rpc.make` declares one procedure. `RpcGroup.make` collects them
into the single value that the server and the client share:

```typescript
// src/ApiSchema.ts
import * as Schema from "effect/Schema";
import { Rpc, RpcGroup } from "effect/unstable/rpc";
import { CreateTaskFailed, Task, TaskNotFound } from "./Task.ts";

const getTask = Rpc.make("getTask", {
  payload: { id: Schema.String },
  success: Task,
  error: TaskNotFound,
});

const createTask = Rpc.make("createTask", {
  payload: { title: Schema.String },
  success: Task,
  error: CreateTaskFailed,
});

export class TaskRpcs extends RpcGroup.make(getTask, createTask) {}
```

`TaskRpcs` is a value-level description. Nothing executes yet.

## Handlers

`TaskRpcs.toLayer` takes one handler per procedure and produces a
`Layer`:

```typescript
// src/ApiHandlers.ts
import * as Effect from "effect/Effect";
import { TaskRpcs } from "./ApiSchema.ts";
import { Task, TaskNotFound } from "./Task.ts";

export const TaskRpcsLive = TaskRpcs.toLayer({
  // stubs, the per-cloud guides back these with real storage bindings
  getTask: ({ id }) => Effect.fail(new TaskNotFound({ id })),
  createTask: ({ title }) =>
    Effect.succeed(
      new Task({ id: crypto.randomUUID(), title, completed: false }),
    ),
});
```

Each handler receives the decoded payload and returns an `Effect` that
succeeds or fails with the declared schemas. `toLayer` builds a value
and never runs the server, so it is safe in a host's construction
phase, which also runs at deploy time ([Phases](/infrastructure-as-effects/phases)).

The storage-backed handlers live on the hub pages, with R2 in
[Effect RPC on Workers](/cloudflare/apis/effect-rpc) and DynamoDB in
[Effect RPC on Lambda](/aws/apis/effect-rpc).

## Serve it

`RpcServer.toHttpEffect` needs two layers, the handlers and a
serialization:

```typescript
// src/ApiHandlers.ts (continued)
import * as Layer from "effect/Layer";
import { RpcSerialization, RpcServer } from "effect/unstable/rpc";

export const ApiHttpEffect = RpcServer.toHttpEffect(TaskRpcs).pipe(
  Effect.provide(Layer.mergeAll(TaskRpcsLive, RpcSerialization.layerJson)),
);
```

`toHttpEffect` returns an Effect that starts the RPC server and yields
the request handler. It imports nothing cloud-specific. The host
returns that handler as `fetch`:

```typescript
// src/ApiService.ts, inside the host's Effectful Constructor
return { fetch: yield* ApiHttpEffect };
```

`yield*` it once in the constructor so the server is built at boot.
`fetch` also accepts the un-yielded Effect, but then the server is
rebuilt on every request.

The host can be a Cloudflare Worker or a Lambda Function. Each hub
covers host wiring, storage binding layers, authentication, and deploy:

- [Effect RPC on Workers](/cloudflare/apis/effect-rpc): a Worker host with R2 storage.
- [Effect RPC on Lambda](/aws/apis/effect-rpc): a Lambda host with DynamoDB storage. The Function URL is on and public by default, so see [Require signed callers](/aws/apis/effect-rpc#require-signed-callers).

## Streaming

A procedure streams its results when you add `stream: true`. Its
handler returns a `Stream` of `Task` values, and the client method
returns a `Stream` too:

```typescript
// src/ApiSchema.ts
const watchTasks = Rpc.make("watchTasks", { success: Task, stream: true });

export class TaskRpcs extends RpcGroup.make(getTask, createTask, watchTasks) {}

// src/ApiHandlers.ts: serve it (and call it) with a framed serialization
export const ApiHttpEffect = RpcServer.toHttpEffect(TaskRpcs).pipe(
  Effect.provide(Layer.mergeAll(TaskRpcsLive, RpcSerialization.layerNdjson)),
);
```

- `RpcSerialization.layerJson` buffers one body per request. It collects a streamed procedure into that body, so nothing arrives until the stream ends.
- `RpcSerialization.layerNdjson` writes one frame per line, so stream elements arrive as they are produced.
- The client's serialization layer must match the server's.

## A typed client

A client is the schema combined with a **Fetcher**. The Fetcher is a
URL for external consumers, or a platform binding when the caller
lives in the same account (see the Workers page). This is the URL
form:

```typescript
// src/ApiClient.ts
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import * as FetchHttpClient from "effect/unstable/http/FetchHttpClient";
import { RpcClient, RpcSerialization } from "effect/unstable/rpc";
import { TaskRpcs } from "./ApiSchema.ts";

const program = Effect.gen(function* () {
  const client = yield* RpcClient.make(TaskRpcs);

  const task = yield* client.createTask({ title: "Write the docs" });

  // Effect<Task, TaskNotFound | RpcClientError>
  const fetched = yield* client.getTask({ id: task.id });
  console.log(fetched.title);
});

Effect.runPromise(
  program.pipe(
    Effect.scoped, // the client needs a Scope
    Effect.provide(
      RpcClient.layerProtocolHttp({ url: process.env.TASK_API_URL! }).pipe(
        Layer.provide(FetchHttpClient.layer),
        Layer.provide(RpcSerialization.layerJson), // must match the server
      ),
    ),
  ),
);
```

`RpcClient.make(TaskRpcs)` derives the whole client from the same
group value with no codegen. `TaskNotFound` is your declared error,
and `RpcClientError` covers transport and protocol failures.
