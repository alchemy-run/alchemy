## Organizations

An **organization** holds your sandboxes, snapshots, volumes, secrets and API keys, the people who may use them, and the bill. Nothing in one organization can see another's.

You sign in to Daytona once, and pick the organization your profile deploys to. See [Organizations and API keys](/daytona/organizations-and-keys).

## API keys

Every call to Daytona carries an **API key**. A key belongs to one organization and holds permissions per kind of object: `write:sandboxes` lets it create any sandbox in the organization, `manage:secrets` any secret.

Each binding creates a key of its own for its Worker or Lambda, with only the permissions its calls need:

```typescript
const sandboxes = yield* Daytona.CreateSandbox(Base);
```

See [Organizations and API keys](/daytona/organizations-and-keys).

## Regions and runners

A **region** is where sandboxes run, such as `us` or `eu`. Inside it, **runners** are the machines that host sandboxes. Daytona runs shared regions for everyone, and you can add a region of your own and run its runners on your machines.

See [Regions and runners](/daytona/sandboxes/runners).

## Snapshots

A **snapshot** is the image a sandbox boots from, plus its size: CPU, memory, disk and GPUs. Daytona builds it from an image, a Dockerfile, or another snapshot with commands run in it.

```typescript title="src/Images.ts"
export const Base = Daytona.Snapshot("Base", { image: "node:22-bookworm-slim", cpu: 1, memory: 1, disk: 3 });
```

See [Snapshots](/daytona/sandboxes/snapshots).

Create sandboxes per request or per user from a Worker, or declare a long-lived one in your Stack. See [Sandboxes](/daytona/sandboxes/sandboxes).

## The toolbox

The **toolbox** is the API inside every sandbox. Alchemy hands you a sandbox as a handle with all of it:

```typescript
const result = yield* sandbox.exec("npm test", { cwd: "/home/daytona/repo" });
```

See [Toolbox](/daytona/sandboxes/toolbox).

## Previews

A **preview URL** reaches a port inside a sandbox from outside, through Daytona's proxy. It needs the sandbox's preview token unless the sandbox is `public`. See [Network and previews](/daytona/networking/network).

## Volumes

A **volume** is a persistent disk, backed by object storage, that sandboxes mount at a path. Its files outlive every sandbox that mounts it, so a user's home can survive their sandbox.

```typescript title="src/Storage.ts"
export const Cache = Daytona.Volume("Cache", {});
```

See [Volumes](/daytona/sandboxes/volumes).

## Network limits

Daytona controls what a sandbox can reach, outside the sandbox. Your organization's tier sets the default: below Tier 3, sandboxes reach only an allowlist of essential services, such as package registries, GitHub and AI APIs. On top of that, a sandbox can allow only some domains or ranges, or no network at all. See [Network and previews](/daytona/networking/network).

## Secrets

A **secret** is a value a sandbox can use but not read. The sandbox sees a placeholder, and Daytona's egress proxy swaps in the real value only on requests to the hosts you name. See [Secrets](/daytona/security/secrets).

## How @alchemy.run/daytona models these concepts

Snapshots, volumes, secrets, registries, warm pools, regions, runners, roles and organization settings are resources you declare in a Stack. A sandbox is a resource too when it should live as long as the Stack, like a dev box, or a sandbox that runs a program you write. Sandboxes, volumes, secrets and snapshots that come and go per request or per user are created at runtime through bindings (`CreateSandbox`, `CreateVolume`, `CreateSecret`, `CreateSnapshot`), each with its own API key. Your [profile](/environments/profiles) signs you in to Daytona and picks the organization.
