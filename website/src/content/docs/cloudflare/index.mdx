An alchemy app on Cloudflare is one **Worker** runtime plus the
building blocks it talks to — databases, object storage, queues,
stateful objects — all declared in the same TypeScript program and
wired together by typed bindings. Deploy the whole thing with
`bun alchemy deploy`; Alchemy figures out what changed.

New here? [Set up your account](/cloudflare/setup), then start the
[tutorial](/cloudflare/tutorial/part-1).

## Building blocks

### Compute

- [Workers](/cloudflare/workers) — the compute runtime; every app has
  at least one.
- [Durable Objects](/cloudflare/durable-objects) — globally-unique
  stateful instances with transactional storage and typed RPC.

### Data

- [D1](/cloudflare/d1) — serverless SQLite with migrations managed as
  part of the deploy.
- [R2](/cloudflare/r2) — object storage with read/write-scoped
  bindings.
- [Hyperdrive](/cloudflare/hyperdrive) — edge connection pooling for
  external Postgres and MySQL.

### Messaging

- [Queues](/cloudflare/queues) — at-least-once message delivery
  between Workers.

## What are you building?

| App shape | Stack |
| --- | --- |
| HTTP API | [Worker](/cloudflare/workers) + [D1](/cloudflare/d1) — see [Effect HTTP API](/cloudflare/guides/effect-http-api) |
| Typed RPC API | [Worker](/cloudflare/workers) — see [Effect RPC](/cloudflare/guides/effect-rpc) |
| Real-time / WebSockets | [Durable Objects](/cloudflare/durable-objects) — see [Accept WebSockets](/cloudflare/guides/hibernatable-websockets) |
| Full-stack app | [Worker](/cloudflare/workers) + Vite SPA — see [Add a Vite SPA](/cloudflare/guides/vite-spa) or [Frontend frameworks](/cloudflare/guides/frontends) |
| Background jobs | [Queues](/cloudflare/queues) |
| Postgres-backed API | [Hyperdrive](/cloudflare/hyperdrive) + [Drizzle](/cloudflare/guides/drizzle) |
| Durable multi-step jobs | [Workflows](/cloudflare/guides/workflows) |
| AI apps | [AI Gateway](/cloudflare/guides/ai-gateway), [Effect AI](/cloudflare/guides/effect-ai), [AI Search](/cloudflare/guides/ai-search) |
