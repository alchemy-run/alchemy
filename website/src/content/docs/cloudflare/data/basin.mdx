**Basin** is Cloudflare's analytics stack on R2. It has three parts:

- **Pipelines** ingests JSON events through a **stream**, transforms them with
  SQL, and writes them to a **sink**.
- **Catalog** (formerly R2 Data Catalog) turns an R2 bucket into an Apache
  Iceberg warehouse.
- **SQL** queries the tables in that warehouse.

In Alchemy these are the `Cloudflare.Basin` resources. They are the same
resources as `Cloudflare.Pipelines.*` and `Cloudflare.R2.DataCatalog`, which
keep working under their old names.

Reach for Basin when events should end up as tables you query. Reach for
[K2](/cloudflare/messaging/k2) or [Queues](/cloudflare/messaging/queues) when
your own code consumes them.

By the end of this page, a Worker sends page views to a stream, and a SQL
pipeline writes them to an Iceberg table in your bucket.

## Enable the catalog on a bucket

```typescript
// src/Lake.ts
import * as Cloudflare from "alchemy/Cloudflare";

export const Lake = Cloudflare.R2.Bucket("Lake");

export const Catalog = Cloudflare.Basin.Catalog("Catalog", {
  bucketName: Lake.bucketName,
});
```

`Basin.Catalog` enables the Iceberg catalog on the bucket. It outputs the
catalog URI and the warehouse name that Iceberg clients connect with.

## Create a typed stream

Declare the stream with an Effect Schema. Alchemy converts it into the stream's
field list, which Cloudflare enforces.

```typescript
// src/Lake.ts
import * as Schema from "effect/Schema";

export const PageView = Schema.Struct({
  userId: Schema.String,
  path: Schema.String,
  at: Schema.Date,
  tags: Schema.optional(Schema.Array(Schema.String)),
});

export const PageViews = Cloudflare.Basin.Stream("PageViews", { schema: PageView });
```

Arrays become `list` fields, nested structs become `struct` fields, and
`Schema.optional` fields are not required. A schema with no stream
representation, such as a union, fails when the program is built.

A stream's schema can't change after it is created. Changing it replaces the
stream, which drops events it hasn't processed yet and deletes the pipelines
that read from it. Writing the same schema as an Effect Schema or as an
explicit `{ fields }` list is the same stream and causes no change.

## Write to an Iceberg table

A catalog sink writes the pipeline's output to an Iceberg table. Declare it in
your stack's Effect, and pass the catalog resource so the sink is created after
the catalog is enabled:

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Config from "effect/Config";
import * as Effect from "effect/Effect";
import { Catalog, PageViews } from "./src/Lake.ts";

export default Alchemy.Stack(
  "Analytics",
  {
    providers: Cloudflare.providers(),
    state: Cloudflare.state(),
  },
  Effect.gen(function* () {
    const catalog = yield* Catalog;
    const views = yield* PageViews;

    const table = yield* Cloudflare.Basin.Sink("PageViewTable", {
      type: "basin_catalog",
      catalog,
      table: { namespace: "web", name: "page_views" },
      token: yield* Config.Redacted("CATALOG_TOKEN"),
    });
  }),
);
```

The sink creates the namespace and table on its first write. The `token` is a
Cloudflare API token with access to R2 and the catalog. Rotating it updates the
sink without replacing it.

:::caution
A catalog sink can't be created for a table that already exists. Changing the
sink's other settings replaces the sink, and the replacement fails once the
table exists. Choose the table and format before the first deploy.
:::

## Connect them with SQL

Add the pipeline in the same Effect:

```diff lang="typescript"
// alchemy.run.ts
+import * as Output from "alchemy/Output";

    const table = yield* Cloudflare.Basin.Sink("PageViewTable", { /* ... */ });
+
+    yield* Cloudflare.Basin.Pipeline("PageViewEtl", {
+      sql: Output.interpolate`
+        INSERT INTO ${table.name}
+        SELECT userId, path, at FROM ${views.name}
+        WHERE path NOT LIKE '/health%'`,
+    });
```

Alchemy validates the SQL with Cloudflare during plan, so a bad statement fails
before anything is replaced. Reformatting the SQL is not a change.

## Send events from a Worker

`Cloudflare.Basin.WriteStream` is typed by the stream's schema. The client
encodes each value with the schema before sending it.

```typescript
// src/Api.ts
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
import { HttpServerRequest } from "effect/http/HttpServerRequest";
import * as HttpServerResponse from "effect/http/HttpServerResponse";
import { PageViews } from "./Lake.ts";

export default class Api extends Cloudflare.Worker<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const views = yield* Cloudflare.Basin.WriteStream(PageViews);

    return {
      fetch: Effect.gen(function* () {
        const request = yield* HttpServerRequest;
        yield* views.send([{ userId: "anon", path: request.url, at: new Date() }]);
        return HttpServerResponse.text("ok");
      }),
    };
  }).pipe(Effect.provide(Cloudflare.Basin.WriteStreamBinding)),
) {}
```

Cloudflare accepts events that don't match a stream's schema and drops them
later during processing, so the client-side encoding is the only validation.

To drain an Effect `Stream` into the pipeline, use `Cloudflare.Basin.StreamSink`.
It packs events into requests of up to 5 MB:

```typescript
const sink = yield* Cloudflare.Basin.StreamSink(PageViews);
yield* Stream.fromIterable(views).pipe(Stream.run(sink));
```

Provide `Cloudflare.Basin.StreamSinkBinding` alongside `WriteStreamBinding`.

## Send events from outside a Worker

The producer code stays the same on every host. Only the layer changes:

- `WriteStreamBinding` and `StreamSinkBinding` run in Cloudflare Workers and
  send through the native `pipelines` binding.
- `WriteStreamHttp` and `StreamSinkHttp` run on any host. They send to the
  stream's HTTP endpoint with a scoped "Pipelines Send" token that Alchemy mints
  at deploy.
- `WriteStreamLocal` and `StreamSinkLocal` run in scripts and Actions. They
  send to the stream's HTTP endpoint with your current Cloudflare credentials.

The HTTP and local layers need the stream's HTTP endpoint turned on.

## The HTTP endpoint is off by default

A stream gets an HTTP ingest endpoint only when you ask for one:

```typescript
Cloudflare.Basin.Stream("PageViews", { http: true });                            // authenticated
Cloudflare.Basin.Stream("PageViews", { http: { enabled: true, authentication: false } }); // public
```

:::caution
Earlier versions of Alchemy left a stream declared without `http` with
Cloudflare's default, a public endpoint that anyone can write to. The next
deploy now closes that endpoint in place, without replacing the stream. If
external producers post to it, keep it public with
`http: { enabled: true, authentication: false }`.
:::

## Own a table directly

`Cloudflare.Basin.Table` creates and manages an Iceberg table through the
catalog's Iceberg REST API. Use it for tables your own code writes, or when you
want table settings in your program:

```typescript
const Order = Schema.Struct({
  orderId: Schema.String,
  amountCents: Schema.Number,
  at: Schema.Date,
});

const orders = yield* Cloudflare.Basin.Table("Orders", {
  catalog,
  namespace: "sales",
  schema: Order,
  partitionBy: ["day(at)"],
  properties: { "write.format.default": "parquet" },
  maintenance: {
    compaction: { targetSizeMb: "256" },
  },
});
```

Adding an optional column to `schema` evolves the table in place. A change that
would lose data, such as dropping or narrowing a column, fails the plan.
Changing `namespace`, `name`, or `partitionBy` also fails the plan, because each
would mean dropping the table.

`maintenance.snapshotExpiration` works only after snapshot expiration is enabled
on the catalog.

Destroying the resource leaves the table and its data in place. Set
`delete: "drop"` to drop the table, or `delete: "purge"` to also delete its data
files.

## React to new files

Pipelines has no event source of its own, because its consumer is the sink. To
process the files a sink writes, listen for object events on the bucket with
`Cloudflare.R2.BucketEventNotification`.
