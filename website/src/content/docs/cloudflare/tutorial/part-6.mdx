In [Part 5](/cloudflare/tutorial/part-5) you set up CI/CD. Now you'll watch
your Worker run in production. Every Alchemy runtime ships with
OpenTelemetry built in: each request is wrapped in an `http.server`
span, every `Effect.log` is a log record, and setting the standard
`OTEL_*` environment variables is all it takes to export them. In
this part you'll provision the receiving end — an
[Axiom](/axiom) dataset per signal and a least-privilege ingest
token — in the same Stack as the Worker, then wire the two together.

:::note
Cloudflare also has built-in tracing for Workers (automatic runtime
spans, exported via
[ObservabilityDestination](/providers/cloudflare/workers/observabilitydestination)).
That system ingests spans only from the workerd runtime itself — it
has no OTLP ingest endpoint — so your application-level Effect spans
export directly to an OTLP backend instead. Axiom is the one we'll
use here; any OTLP endpoint works the same way.
:::

## Add the Axiom provider

Axiom resources deploy alongside your Cloudflare ones. Merge the
provider layers in `alchemy.run.ts`:

```diff lang="typescript"
// alchemy.run.ts
import * as Alchemy from "alchemy";
+import * as Axiom from "alchemy/Axiom";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
+import * as Layer from "effect/Layer";

export default Alchemy.Stack(
  "MyApp",
  {
-   providers: Cloudflare.providers(),
+   providers: Layer.mergeAll(Cloudflare.providers(), Axiom.providers()),
    state: Cloudflare.state(),
  },
  // ...
);
```

If you haven't connected an Axiom account yet, run through
[Axiom setup](/axiom/setup) first — `alchemy login` picks up
`AXIOM_TOKEN` or a stored credential.

## Create a dataset for traces

A `Dataset` is Axiom's storage container. Following the same
one-resource-per-file pattern as the Bucket, create
`src/observability.ts`:

```typescript
// src/observability.ts
import * as Axiom from "alchemy/Axiom";

export const Traces = Axiom.Dataset("Traces", {
  name: "myapp-traces",
  kind: "otel:traces:v1",
});
```

The `kind` tells Axiom this dataset stores OTel trace data — it
determines the schema and how spans render in the Axiom UI.

## Add one for logs

Each OTel signal gets its own dataset:

```diff lang="typescript"
// src/observability.ts
import * as Axiom from "alchemy/Axiom";

export const Traces = Axiom.Dataset("Traces", {
  name: "myapp-traces",
  kind: "otel:traces:v1",
});

+export const Logs = Axiom.Dataset("Logs", {
+  name: "myapp-logs",
+  kind: "otel:logs:v1",
+});
```

:::note
Dataset names are global to your Axiom org, and renaming one is a
replacement that deletes its data. If you deploy multiple stages
(like the PR previews from Part 5), give each stage its own dataset —
see [per-stage datasets](/axiom/data/ingest#per-stage-datasets).
:::

## Mint an ingest token

An `ApiToken` scoped with `datasetCapabilities` can ingest into
exactly the datasets you list and nothing else:

```diff lang="typescript"
// src/observability.ts
+export const Ingest = Axiom.ApiToken("Ingest", {
+  name: "myapp-ingest",
+  datasetCapabilities: {
+    "myapp-traces": { ingest: ["create"] },
+    "myapp-logs": { ingest: ["create"] },
+  },
+});
```

Axiom returns the bearer value exactly once, at create time. Alchemy
captures it into `Ingest.token` as a `Redacted<string>` so it can be
wired into consumers without ever appearing in plaintext.

## Wire the env vars into the Worker

The built-in telemetry configures itself from the standard
OpenTelemetry environment variables. Pass each dataset's OTLP
endpoint and headers through the Worker's `env` prop:

```diff lang="typescript"
// src/worker.ts
import * as Cloudflare from "alchemy/Cloudflare";
+import * as Axiom from "alchemy/Axiom";
import * as Effect from "effect/Effect";
import { HttpServerRequest } from "effect/unstable/http/HttpServerRequest";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";
import { Bucket } from "./bucket.ts";
+import { Ingest, Logs, Traces } from "./observability.ts";

export default Cloudflare.Worker(
  "Worker",
- { main: import.meta.url },
+ {
+   main: import.meta.url,
+   env: {
+     OTEL_EXPORTER_OTLP_TRACES_ENDPOINT: Traces.otelTracesEndpoint,
+     OTEL_EXPORTER_OTLP_TRACES_HEADERS: Axiom.otlpHeaders(Ingest, Traces),
+     OTEL_EXPORTER_OTLP_LOGS_ENDPOINT: Logs.otelLogsEndpoint,
+     OTEL_EXPORTER_OTLP_LOGS_HEADERS: Axiom.otlpHeaders(Ingest, Logs),
+   },
+ },
  Effect.gen(function* () {
    // ...
  }).pipe(Effect.provide(Cloudflare.R2.ReadWriteBucketBinding)),
);
```

`Axiom.otlpHeaders(Ingest, Traces)` composes the
`Authorization=Bearer <token>,X-Axiom-Dataset=<name>` header string
Axiom expects. Because the token is `Redacted`, the header binds as a
`secret_text` var — and because the values are Outputs, the datasets
and token deploy before the Worker, automatically.

## Deploy and generate a trace

Deploy, then hit the Worker to produce telemetry:

```sh
bun alchemy deploy

curl -X PUT https://myapp-worker-dev-you-abc123.workers.dev/hello.txt \
  -d 'Hello, observability!'
curl https://myapp-worker-dev-you-abc123.workers.dev/hello.txt
```

There is no exporter code and nothing to instrument: the Worker's
runtime builds the OTLP exporters from those env vars for each
request, and flushes them when the request's scope closes — after
the response is sent, via `waitUntil`, so export never adds latency.

## See it in Axiom

Open your Axiom org and query the `myapp-traces` dataset. Each
request appears as an `http.server` span carrying the method, URL,
status, and headers, with `service.name` set to the Worker's deployed
name. The `myapp-logs` dataset has a log record for every
`Effect.log` your handler ran, linked to its span.

## Add a custom span

The root span shows *that* a request happened. To see *where the
time went*, wrap the R2 read in its own span:

```diff lang="typescript"
// src/worker.ts
        if (request.method === "PUT") {
          // ...
        }

-       const object = yield* bucket.get(key);
+       const object = yield* bucket
+         .get(key)
+         .pipe(Effect.withSpan("bucket.get", { attributes: { key } }));
```

`Effect.withSpan` opens a child span under whatever span is current —
here, the request's `http.server` root — so the R2 read shows up as
a nested bar in the trace waterfall, with the object key attached as
an attribute.

## Log with context

Logs emitted inside a span are exported with that span's trace and
span IDs, so Axiom can jump from a log line to its trace:

```diff lang="typescript"
// src/worker.ts
        const text = yield* object.text();
+       yield* Effect.log("served object", { key });
        return HttpServerResponse.text(text);
```

Deploy again, make a few requests, and the waterfall in Axiom now
shows the nested `bucket.get` span with your log line attached.

## Turning it off

Telemetry is on by default but exports nothing until an endpoint is
configured — with no `OTEL_*` vars set, Effect's no-op tracer makes
every span free. To force it off even when the env vars are present,
set `OTEL_SDK_DISABLED=true`, or provide the override in code:

```typescript
import * as Alchemy from "alchemy";

export default Cloudflare.Worker(
  "Worker",
  { main: import.meta.url },
  Effect.gen(function* () {
    // ...
  }).pipe(Effect.provide(Alchemy.Telemetry.disabled)),
);
```

The same mechanism swaps the whole exporter:
`Alchemy.Telemetry.otlp({ baseUrl, headers })` configures the
built-in OTLP exporter explicitly, and `Alchemy.Telemetry.layer(...)`
installs any custom exporter Layer. See
[Telemetry](/infrastructure-as-effects/telemetry) for the full
mechanics.
