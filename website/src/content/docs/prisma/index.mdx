Prisma's data platform runs two things: Prisma Postgres, a serverless Postgres database, and Prisma Compute, a runtime for the apps that use it. A project holds both, so an app and its database run side by side and the app finds its database without any configuration.

## A taste

A project with a database, and an app deployed next to it:

```typescript title="alchemy.run.ts"
const project = yield* Prisma.Project("app", { region: "us-east-1" });

const app = yield* Prisma.Compute("api", {
  project,
  path: "./app",
  build: "auto",
  healthCheck: { path: "/api/health" },
});
```

The app receives the database's `DATABASE_URL` automatically. From any other runtime, bind a connection with `Prisma.Connect` and hand its URL to Prisma ORM, Effect SQL or Drizzle:

```typescript title="src/worker.ts"
const db = yield* Prisma.Connect(connection);
const sql = yield* SQL.Postgres({ url: db.databaseUrl });
```

## Where to start

**New to Prisma's platform?** [What is Prisma?](/prisma/what-is-prisma) walks through projects, Prisma Postgres, connections, branches, Compute apps and deployments, once each, and shows how Alchemy models every one.

**Want to build one?** The [tutorial](/prisma/tutorial/part-1) deploys a project, an Effect API, Postgres and a Vite frontend, one step at a time. Start with [Setup](/prisma/setup) to connect your workspace.

**Want the whole picture?** Start with the database: [Postgres](/prisma/data/postgres), [Connections](/prisma/data/connections), [Branches](/prisma/data/branches), [Buckets](/prisma/data/buckets) and [Drizzle + Postgres](/prisma/data/drizzle-postgres). Then the apps that use it: [Apps](/prisma/compute/apps) and [Deployments](/prisma/compute/deployments).

**Using Cloudflare?** [Connect from Workers](/prisma/guides/cloudflare-workers) puts Hyperdrive in front of the database. **Building a website?** [Websites](/prisma/frontend/websites) runs every supported framework on Compute.

Every resource is in the generated [API reference](/providers).
