## A service token decides the workspace

Alchemy deploys with a **service token**, created in the [Prisma Console](https://console.prisma.io) under workspace settings. A service token belongs to the workspace, not to a person, and Alchemy deploys into the workspace it belongs to. Store it in a [profile](/environments/profiles):

```sh
alchemy profile edit --add Prisma
```

See [Setup](/prisma/setup).

## One workspace per environment

A [stage](/environments/stages) decides what you deploy. A profile decides where. To keep production's members and bill apart, give it its own workspace, token and profile:

```sh
alchemy profile create prod
alchemy profile edit --profile prod --add Prisma
alchemy deploy --stage prod --profile prod
```

## Apps don't hold the service token

The service token manages the workspace. An app only connects to its database, with a connection string that reaches that one database. See [Connections](/prisma/data/connections).

## In CI

With `CI=true`, Alchemy skips the profile and reads `PRISMA_SERVICE_TOKEN` from the environment. See [CI](/environments/ci).
