[Foldkit](https://foldkit.dev) is an Elm-architecture frontend framework
built on Effect. This integration supports browser-only SPAs, server rendering,
and prerendered pages with request-time fallback. Foldkit's Vite plugin generates
the handler and assets; Alchemy packages them for Prisma Compute.

## Install

Install the build-time integration; the resource loads `/foldkit` and
`/foldkit/node` from your frontend project:

## Configure Vite

Keep Foldkit's Vite setup and your existing plugins:

```typescript
// vite.config.ts
import { foldkit } from "@foldkit/vite-plugin";
import tailwindcss from "@tailwindcss/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [foldkit(), tailwindcss()],
  optimizeDeps: { entries: ["src/entry.ts"] },
});
```

:::note[Pinned Effect versions]
Foldkit pins its Effect peer to an exact version. Alchemy uses your
frontend project's own Vite and dependencies; keep Foldkit's peer
versions aligned in that project rather than replacing them with the
Stack's Effect version.
:::

## Declare the Website

```typescript
// alchemy.run.ts
import * as Prisma from "alchemy/Prisma";

export const Website = Prisma.Website.Foldkit("Website", {
  rootDir: "applications/web",
});
```

Omit `rootDir` for an app at `.`. Omit `project` to create a
database-less Prisma project on live deploy, or pass an existing project.

## Add it to the Stack

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Effect from "effect/Effect";

export default Alchemy.Stack(
  "MyFoldkitSite",
  { providers: Prisma.providers(), state: Alchemy.localState() },
  Effect.gen(function* () {
    const site = yield* Website;
    return { url: site.url };
  }),
);
```

`site.url` is the Compute endpoint on deploy and Vite's local URL in dev.

## Add environment variables

```diff lang="typescript"
export const Website = Prisma.Website.Foldkit("Website", {
  rootDir: "applications/web",
+  env: {
+    VITE_API_URL: "https://api.example.com",
+  },
});
```

`env` is applied before build and dev, and passed to Compute. The SPA
only sees values Vite inlines at build time. `VITE_*` keys are public,
so never put secrets in them.

## Read the environment

```typescript
// src/vite-env.d.ts
/// <reference types="vite/client" />

interface ImportMetaEnv {
  readonly VITE_API_URL: string;
}
```

This declares the client-visible key for TypeScript.

```typescript
const apiUrl = import.meta.env.VITE_API_URL;
```

Vite replaces the lookup with the build-time value.

## Deep links

For browser-only builds, `assets.notFoundHandling` defaults to `"single-page-application"`.
A path like `/counter/42` returns `index.html` with status 200, letting
Foldkit's client router resolve it. For real 404 responses instead:

```typescript
export const Website = Prisma.Website.Foldkit("Website", {
  assets: { notFoundHandling: "404-page" },
});
```

## Server rendering and prerendering

Use Foldkit 0.164.0 and `@foldkit/vite-plugin` 0.25.0 or newer. Keep rendering
configuration in your app's `vite.config.ts`:

```typescript
import { foldkit } from "@foldkit/vite-plugin";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [foldkit({
    ssr: {
      serverEntry: "/src/entry.server.ts",
      build: { prerender: true },
    },
  })],
});
```

The server entry exports `renderPage` and, when prerendering is enabled,
`prerenderPaths`. Use `build: true` for SSR without prerendering. See
[Foldkit's server rendering guide](https://foldkit.dev/core/server-rendering)
for the application contract.

The same Website declaration detects the generated handler automatically.
GET and HEAD requests serve assets and prerendered pages first, including `/`
when it was prerendered. Remaining requests go to Foldkit's handler; POST
requests bypass static assets. SSG deployments retain the generated handler
for paths that were not prerendered, matching the SvelteKit/TanStack Start path.

Browser-only builds keep SPA fallback. An explicit `assets.notFoundHandling`
override takes precedence. Avoid SPA fallback on SSR apps unless intentional:
a prerendered `index.html` would then answer unmatched page requests.

Server code reads private runtime values from `process.env`; `VITE_*` values
remain public build-time browser configuration. Custom Foldkit client/server
output directories are read from the completed build metadata and packaged
together. `vite.outDir`, when supplied, places SSR outputs under `client/` and
`server/` in that directory.

## Local dev

`bun alchemy dev` runs Vite with Foldkit live reload and devtools. The Website
creates no Prisma resources. `.pipe(Alchemy.remote())` selects the live
path during dev. Pin the local address when running several apps:

```typescript
export const Website = Prisma.Website.Foldkit("Website", {
  dev: { host: "127.0.0.1", port: 5180, strictPort: true },
});
```

## Custom domain

```typescript
const site = yield* Prisma.Website.Foldkit("Web", {
  domain: "app.example.com",
});
```

This creates `Prisma.CustomDomain`; the app must be on the project's
current default branch. Configure the returned DNS records yourself
and verify status before cutover. See
[Custom domains](/prisma/frontend/websites#custom-domains).
