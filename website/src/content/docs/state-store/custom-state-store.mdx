Write your own state store when you want Alchemy to keep state in a
backend the [built-in stores](/state-store#choose-a-store) don't cover,
such as Redis or DynamoDB. This guide builds a simplified Postgres store,
`myPostgresState()`, tests a round-trip through it, and plugs it into a
stack.

You need a Postgres database you can write to and the
[`postgres`](https://github.com/porsager/postgres) package. For a
production Postgres store, use the built-in `postgresState()` from
`alchemy/State/PostgresState`, which also locks each stack and stage
during a run.

## Scaffold the layer

A state store is a `Layer.Layer<State, never, R>`, where `R` is any
services your implementation needs. The `State` service holds an
`Effect<StateService>` that builds the store lazily:

```typescript
class State extends Context.Service<State, Effect.Effect<StateService>>()(
  "alchemy/State",
) {}
```

Commands like `alchemy profile show` build the state layer but never
touch state, so a store must not connect to its backend when the layer
is built. Wrap the builder in
[`Effect.cached`](https://effect.website/docs/getting-started/control-flow/#caching)
to defer that work to the first `yield* State` and reuse the result
afterward.

Start with a `StateService` whose methods all die, so the types compile.
Then fill it in one method at a time. Create `src/postgres-state.ts`:

```typescript
// src/postgres-state.ts
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import {
  STATE_STORE_VERSION,
  State,
  type StateService,
} from "alchemy/State";

export interface PostgresStateProps {
  connectionString: string;
}

export const myPostgresState = (props: PostgresStateProps) =>
  // Effect.cached hands State a memoized initializer.
  // The body below runs only on the first `yield* State`.
  Layer.effect(State, Effect.cached(makePostgresState(props)));

const makePostgresState = (_props: PostgresStateProps) =>
  Effect.gen(function* () {
    const service: StateService = {
      // short, stable, kebab-case name reported in telemetry
      id: "my-postgres",
      // state-store contract version the CLI was built against
      getVersion: () => Effect.succeed(STATE_STORE_VERSION),
      listStacks: () => Effect.die("not implemented"),
      listStages: () => Effect.die("not implemented"),
      list: () => Effect.die("not implemented"),
      get: () => Effect.die("not implemented"),
      set: () => Effect.die("not implemented"),
      delete: () => Effect.die("not implemented"),
      deleteStack: () => Effect.die("not implemented"),
      getReplacedResources: () => Effect.die("not implemented"),
      getOutput: () => Effect.die("not implemented"),
      setOutput: () => Effect.die("not implemented"),
    };
    return service;
  });
```

Alchemy accepts this layer, but every state operation dies. Next, wire
up the database.

## Connect to Postgres

Create two tables. `alchemy_state` holds one row per resource, keyed by
`(stack, stage, fqn)`. `alchemy_stack_output` holds one row per
`(stack, stage)` for the stack's output, which
[`getOutput` and `setOutput`](#implement-getoutput-and-setoutput) use.

Open the connection with `Effect.acquireRelease` so it closes when the
stack tears down. `acquireRelease` needs a `Scope`, so capture the
layer's scope and provide it to the lazy initializer:

```diff lang="typescript"
+import * as Scope from "effect/Scope";
+import postgres from "postgres";
// ...

export const myPostgresState = (props: PostgresStateProps) =>
-  Layer.effect(State, Effect.cached(makePostgresState(props)));
+  Layer.effect(
+    State,
+    Effect.gen(function* () {
+      // the layer's scope, so the deferred initializer can register the release on it
+      const context = yield* Effect.context<Scope.Scope>();
+      const make = makePostgresState(props).pipe(
+        Effect.provideContext(context),
+      );
+      return yield* Effect.cached(make);
+    }),
+  );

-const makePostgresState = (_props: PostgresStateProps) =>
+const makePostgresState = (props: PostgresStateProps) =>
  Effect.gen(function* () {
+    const sql = yield* Effect.acquireRelease(
+      Effect.sync(() => postgres(props.connectionString)),
+      (sql) => Effect.promise(() => sql.end()),
+    );
+
+    yield* Effect.promise(
+      () => sql`
+        create table if not exists alchemy_state (
+          stack text not null,
+          stage text not null,
+          fqn   text not null,
+          value jsonb not null,
+          primary key (stack, stage, fqn)
+        )
+      `,
+    );
+    yield* Effect.promise(
+      () => sql`
+        create table if not exists alchemy_stack_output (
+          stack text not null,
+          stage text not null,
+          value jsonb not null,
+          primary key (stack, stage)
+        )
+      `,
+    );
+
    const service: StateService = {
      // ...
```

The connection opens on first use, and its release runs when the layer's
scope closes.

## Implement `set` and `get`

Alchemy calls these two methods throughout every deploy. Follow these
rules when you write them:

- **Encode on write, revive on read.** `encodeState`, `reviveState`, and
  `reviveStateRecursive` from `alchemy/State` preserve values that plain
  JSON loses, such as `Redacted`, `Duration`, and `Date`. Pass
  `reviveState` to `JSON.parse` for a JSON string. Call
  `reviveStateRecursive` on an already-parsed object, such as a `jsonb`
  column read without `::text`.
- **Protect the store.** A `Redacted` value is written in plaintext
  inside a `__redacted__` marker.
- **Return `undefined` from `get` for a missing row.** Keep
  `StateStoreError` for transport failures.
- **Map thrown errors to `StateStoreError`** so Alchemy can report them
  with context.
- **Return the written `value` from `set`**, as the interface requires.

```diff lang="typescript"
import {
  STATE_STORE_VERSION,
  State,
+  StateStoreError,
+  encodeState,
+  reviveState,
  type StateService,
} from "alchemy/State";

// ... inside makePostgresState, after the tables are created:

+    const run = <A>(thunk: () => Promise<A>) =>
+      Effect.tryPromise({
+        try: thunk,
+        catch: (cause) =>
+          new StateStoreError({
+            message: cause instanceof Error ? cause.message : String(cause),
+            cause: cause instanceof Error ? cause : undefined,
+          }),
+      });
+
    const service: StateService = {
      // ...
-      get: () => Effect.die("not implemented"),
-      set: () => Effect.die("not implemented"),
+      get: ({ stack, stage, fqn }) =>
+        run(
+          () => sql<{ value: string }[]>`
+            select value::text from alchemy_state
+            where stack = ${stack} and stage = ${stage} and fqn = ${fqn}
+          `,
+        ).pipe(
+          Effect.map((rows) =>
+            rows.length === 0
+              ? undefined
+              : JSON.parse(rows[0].value, reviveState),
+          ),
+        ),
+
+      set: ({ stack, stage, fqn, value }) =>
+        run(
+          () => sql`
+            insert into alchemy_state (stack, stage, fqn, value)
+            values (${stack}, ${stage}, ${fqn}, ${JSON.stringify(encodeState(value))}::jsonb)
+            on conflict (stack, stage, fqn)
+            do update set value = excluded.value
+          `,
+        ).pipe(Effect.as(value)),
      // ...
    };
```

## Implement `getOutput` and `setOutput`

Alchemy calls `setOutput` with the stack's resolved output after a deploy
succeeds. [Cross-stack references](/infrastructure-as-code/references)
call `getOutput` to read it back. The output can hold the same non-JSON
values as resource state, so encode and revive it the same way:

```diff lang="typescript"
-  getOutput: () => Effect.die("not implemented"),
-  setOutput: () => Effect.die("not implemented"),
+  // undefined when the stack has no output at this stage (never deployed, or destroyed)
+  getOutput: ({ stack, stage }) =>
+    run(
+      () => sql<{ value: string }[]>`
+        select value::text from alchemy_stack_output
+        where stack = ${stack} and stage = ${stage}
+      `,
+    ).pipe(
+      Effect.map((rows) =>
+        rows.length === 0
+          ? undefined
+          : JSON.parse(rows[0].value, reviveState),
+      ),
+    ),
+
+  setOutput: ({ stack, stage, value }) =>
+    run(
+      () => sql`
+        insert into alchemy_stack_output (stack, stage, value)
+        values (${stack}, ${stage}, ${JSON.stringify(encodeState(value))}::jsonb)
+        on conflict (stack, stage)
+        do update set value = excluded.value
+      `,
+    ).pipe(Effect.as(value)),
```

## Implement `list`, `listStacks`, `listStages`

These power `alchemy destroy`, drift detection, and the CLI's inspection
commands. `list` returns the resource FQNs in one stage. `listStacks` and
`listStages` also include stacks and stages that have only an output
row, so they `union` both tables:

```diff lang="typescript"
-  listStacks: () => Effect.die("not implemented"),
-  listStages: () => Effect.die("not implemented"),
-  list: () => Effect.die("not implemented"),
+  listStacks: () =>
+    run(() => sql<{ stack: string }[]>`
+      select stack from alchemy_state
+      union
+      select stack from alchemy_stack_output
+      order by stack
+    `).pipe(Effect.map((rows) => rows.map((r) => r.stack))),
+
+  listStages: (stack) =>
+    run(() => sql<{ stage: string }[]>`
+      select stage from alchemy_state where stack = ${stack}
+      union
+      select stage from alchemy_stack_output where stack = ${stack}
+      order by stage
+    `).pipe(Effect.map((rows) => rows.map((r) => r.stage))),
+
+  list: ({ stack, stage }) =>
+    run(() => sql<{ fqn: string }[]>`
+      select fqn from alchemy_state
+      where stack = ${stack} and stage = ${stage} order by fqn
+    `).pipe(Effect.map((rows) => rows.map((r) => r.fqn))),
```

## Implement `delete` and `deleteStack`

`delete` removes one resource record. `deleteStack` removes a whole
stack when `stage` is omitted, or one stage when it's set. It removes
the output rows too, so a destroyed stack disappears from `listStacks`:

```diff lang="typescript"
-  delete: () => Effect.die("not implemented"),
-  deleteStack: () => Effect.die("not implemented"),
+  delete: ({ stack, stage, fqn }) =>
+    run(() => sql`
+      delete from alchemy_state
+      where stack = ${stack} and stage = ${stage} and fqn = ${fqn}
+    `).pipe(Effect.asVoid),
+
+  deleteStack: ({ stack, stage }) =>
+    run(() =>
+      stage === undefined
+        ? sql`delete from alchemy_state where stack = ${stack}`
+        : sql`delete from alchemy_state where stack = ${stack} and stage = ${stage}`,
+    ).pipe(
+      Effect.andThen(
+        run(() =>
+          stage === undefined
+            ? sql`delete from alchemy_stack_output where stack = ${stack}`
+            : sql`delete from alchemy_stack_output where stack = ${stack} and stage = ${stage}`,
+        ),
+      ),
+      Effect.asVoid,
+    ),
```

## Implement `getReplacedResources`

When Alchemy replaces a resource, it keeps the old one in the record's
`old` field. After the new resource exists, the record's status stays
`replaced` until the old one is deleted. `getReplacedResources` returns
the records in that state, so the next deploy can finish cleanup.

A resource replaced several times nests earlier generations in the `old`
chain, so return only the top-level records. You can build this on
`list` and `get`, but filtering in Postgres is cheaper:

```diff lang="typescript"
-  getReplacedResources: () => Effect.die("not implemented"),
+  getReplacedResources: ({ stack, stage }) =>
+    run(
+      () => sql<{ value: string }[]>`
+        select value::text from alchemy_state
+        where stack = ${stack}
+          and stage = ${stage}
+          and value->>'status' = 'replaced'
+      `,
+    ).pipe(
+      Effect.map((rows) =>
+        rows.map((r) => JSON.parse(r.value, reviveState)),
+      ),
+    ),
```

## Test the round-trip

Before you use the store in a stack, check that a resource and a stack
output round-trip through it. Point the test at a throwaway Postgres,
such as a Docker container, Testcontainers, or a local instance.

The test yields `State` twice. The first `yield*` returns the
`Effect<StateService>` initializer, and the second runs it. The fixture
is a real `ResourceState` record for a created resource:

```typescript
// test/postgres-state.test.ts
import { describe, expect, it } from "vitest";
import * as Effect from "effect/Effect";
import { State, type ResourceState } from "alchemy/State";
import { myPostgresState } from "../src/postgres-state.ts";

const layer = myPostgresState({
  connectionString: process.env.TEST_DATABASE_URL!,
});

const bucket: ResourceState = {
  kind: "resource", // action records use kind: "action"
  resourceType: "Cloudflare.R2.Bucket",
  namespace: undefined,
  fqn: "Bucket",
  logicalId: "Bucket",
  instanceId: "abc123",
  providerVersion: 0,
  status: "created", // "created" requires both props and attr
  downstream: [],
  bindings: [],
  props: { name: "my-bucket" },
  attr: { name: "my-bucket" },
};

describe("myPostgresState", () => {
  it("round-trips a resource and a stack output", () =>
    Effect.gen(function* () {
      const state = yield* yield* State;

      yield* state.set({
        stack: "Test",
        stage: "dev",
        fqn: "Bucket",
        value: bucket,
      });

      const got = yield* state.get({
        stack: "Test",
        stage: "dev",
        fqn: "Bucket",
      });
      expect(got?.logicalId).toBe("Bucket");

      const fqns = yield* state.list({ stack: "Test", stage: "dev" });
      expect(fqns).toContain("Bucket");

      yield* state.setOutput({
        stack: "Test",
        stage: "dev",
        value: { url: "https://example.com" },
      });
      const output = yield* state.getOutput({ stack: "Test", stage: "dev" });
      expect(output).toEqual({ url: "https://example.com" });

      yield* state.deleteStack({ stack: "Test" });
      const after = yield* state.list({ stack: "Test", stage: "dev" });
      expect(after).toEqual([]);
      expect(yield* state.listStacks()).not.toContain("Test");
    }).pipe(Effect.provide(layer), Effect.scoped, Effect.runPromise));
});
```

## Plug it into a stack

Pass your layer as the stack's `state` option, the same way as a
built-in store:

```diff lang="typescript"
// alchemy.run.ts
+import { myPostgresState } from "./src/postgres-state.ts";
// ...

export default Alchemy.Stack(
  "MyApp",
  {
    providers: Cloudflare.providers(),
-    state: Cloudflare.state(),
+    state: myPostgresState({
+      connectionString: process.env.DATABASE_URL!,
+    }),
  },
  // ...
);
```

Changing `state` does not move existing state. See
[Switching state stores](/state-store#switching-state-stores). To run a
real stack against your store end to end, see
[Test a Stack](/testing).

## Production concerns

The interface doesn't show these details, but they matter in production:

- **FQNs are arbitrary strings** that can contain `/` and other
  characters. Postgres handles them as parameterized values. If your
  backend puts FQNs in keys, such as filenames, S3 keys, or Redis keys,
  escape them with `encodeFqn` and `decodeFqn` from `alchemy/FQN`.
- **Writes arrive concurrently** because Alchemy applies resources in
  parallel. Your backend needs row-level, or equivalent, consistency on
  the `(stack, stage, fqn)` key.
- **Nothing stops two deploys of the same stage** from running at once
  with this store. The built-in `postgresState()` adds a
  per-`(stack, stage)` advisory lock. See
  [Concurrent deploys](/state-store#concurrent-deploys).
- **State persists between deploys**, so a change to the encoded
  `ResourceState` shape is a migration. Keep the shape stable, and use
  `reviveState` so future Alchemy versions can read what you wrote.
