A state store is an Effect `Layer` that provides Alchemy's
`State` service. The built-in stores are `localState()` (disk),
`Cloudflare.state()` (Worker + Durable Object), `AWS.state()` (S3)
and `postgresState()` (Postgres, with locking). Write your own when
you want another backend, such as Redis or DynamoDB.

This guide builds a simplified Postgres-backed store from scratch to
teach the interface. By the end you'll have a `myPostgresState()`
layer you can drop into any `Alchemy.Stack`, and a test that
round-trips a resource through it. If you only need a Postgres store,
use the built-in `postgresState()` from `alchemy/State/PostgresState`.
It also locks each stack and stage during a run.

See [State Store](/state-store) for an overview of what
state Alchemy persists and why.

## Scaffold the layer

A state store is a `Layer.Layer<State, never, R>` where `R` is any
ambient services your implementation needs. The `State` service does
not hold a `StateService` directly. It holds an
`Effect<StateService>` that lazily builds one:

```typescript
class State extends Context.Service<State, Effect.Effect<StateService>>()(
  "alchemy/State",
) {}
```

The indirection exists because commands like `alchemy profile show`
provide the state layer but never touch state. A store must not
connect to its backend (open a DB connection, deploy a worker, prompt
for credentials) only because the layer was built. Wrapping the builder
in [`Effect.cached`](https://effect.website/docs/getting-started/control-flow/#caching)
defers initialization until the first `yield* State`. It also caches
the result so later accesses reuse the same `StateService`.

Start with a `StateService` whose methods all die, so the types
compile, then fill it in one method at a time. Two members are
complete from the start:

- `id` is a short, stable, kebab-case name for your store. Alchemy
  reports it in telemetry.
- `getVersion` returns the state-store contract version. Local,
  in-process stores return `STATE_STORE_VERSION`, the version the
  CLI was built against.

Create `src/postgres-state.ts`:

```typescript
// src/postgres-state.ts
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import {
  STATE_STORE_VERSION,
  State,
  type StateService,
} from "alchemy/State";

export interface PostgresStateProps {
  connectionString: string;
}

export const myPostgresState = (props: PostgresStateProps) =>
  // `Effect.cached` returns an `Effect<Effect<StateService>>`; yielding
  // it inside `Layer.effect` hands `State` the deferred, memoized
  // initializer. The body below only runs on first `yield* State`.
  Layer.effect(State, Effect.cached(makePostgresState(props)));

const makePostgresState = (_props: PostgresStateProps) =>
  Effect.gen(function* () {
    const service: StateService = {
      id: "my-postgres",
      getVersion: () => Effect.succeed(STATE_STORE_VERSION),
      listStacks: () => Effect.die("not implemented"),
      listStages: () => Effect.die("not implemented"),
      list: () => Effect.die("not implemented"),
      get: () => Effect.die("not implemented"),
      set: () => Effect.die("not implemented"),
      delete: () => Effect.die("not implemented"),
      deleteStack: () => Effect.die("not implemented"),
      getReplacedResources: () => Effect.die("not implemented"),
      getOutput: () => Effect.die("not implemented"),
      setOutput: () => Effect.die("not implemented"),
    };
    return service;
  });
```

Alchemy accepts this layer, but it dies on every state operation.
Next, wire up the database.

## Connect to Postgres

Use the [`postgres`](https://github.com/porsager/postgres)
package and create two tables. `alchemy_state` holds one row per
resource, keyed by `(stack, stage, fqn)`. `alchemy_stack_output`
holds one row per `(stack, stage)` for the stack's output, which the
[`getOutput` and `setOutput`](#implement-getoutput-and-setoutput)
step uses.

Acquire the connection with `Effect.acquireRelease` so it's released
when the stack tears down. `acquireRelease` needs a `Scope`.
`Layer.effect` runs its body with the layer's Scope, so the layer can
capture that scope and provide it to the lazily run initializer. The
connection opens on first use, and its release is registered on the
layer's scope:

```diff lang="typescript"
// src/postgres-state.ts
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
+import * as Scope from "effect/Scope";
+import postgres from "postgres";
import {
  STATE_STORE_VERSION,
  State,
  type StateService,
} from "alchemy/State";

export interface PostgresStateProps {
  connectionString: string;
}

export const myPostgresState = (props: PostgresStateProps) =>
-  Layer.effect(State, Effect.cached(makePostgresState(props)));
+  Layer.effect(
+    State,
+    Effect.gen(function* () {
+      // Capture the layer's scope so the deferred initializer can
+      // register the connection's release on it.
+      const context = yield* Effect.context<Scope.Scope>();
+      const make = makePostgresState(props).pipe(
+        Effect.provideContext(context),
+      );
+      return yield* Effect.cached(make);
+    }),
+  );

const makePostgresState = (props: PostgresStateProps) =>
  Effect.gen(function* () {
+    const sql = yield* Effect.acquireRelease(
+      Effect.sync(() => postgres(props.connectionString)),
+      (sql) => Effect.promise(() => sql.end()),
+    );
+
+    yield* Effect.promise(
+      () => sql`
+        create table if not exists alchemy_state (
+          stack text not null,
+          stage text not null,
+          fqn   text not null,
+          value jsonb not null,
+          primary key (stack, stage, fqn)
+        )
+      `,
+    );
+    yield* Effect.promise(
+      () => sql`
+        create table if not exists alchemy_stack_output (
+          stack text not null,
+          stage text not null,
+          value jsonb not null,
+          primary key (stack, stage)
+        )
+      `,
+    );
+
    const service: StateService = {
      id: "my-postgres",
      // ...
    };
    return service;
  });
```

## Implement `set` and `get`

These are the two hot-path methods Alchemy calls during every
deploy.

A few things to know before writing them:

- **Use `encodeState` when writing** and a reviver when reading, all
  from `alchemy/State`. They preserve values plain JSON would lose:
  Effect `Redacted` values, `Duration`s and `Date`s. A `Redacted`
  value is written in plaintext inside a `__redacted__` marker, so
  protect the store itself. When you read a JSON string, pass
  `reviveState` to `JSON.parse`. When your driver returns
  already-parsed objects (for example a `jsonb` column read without
  `::text`), call `reviveStateRecursive` on the value instead.
- **Return `undefined` from `get`** for missing rows. Don't error.
  `StateStoreError` is for transport failures only.
- **Map thrown errors** through `StateStoreError` so Alchemy can
  surface them with context.
- **Return the written `value` from `set`**. The interface returns it.

```diff lang="typescript"
// src/postgres-state.ts
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import * as Scope from "effect/Scope";
import postgres from "postgres";
import {
  STATE_STORE_VERSION,
  State,
+  StateStoreError,
+  encodeState,
+  reviveState,
  type StateService,
} from "alchemy/State";

// ...

const makePostgresState = (props: PostgresStateProps) =>
  Effect.gen(function* () {
    const sql = yield* Effect.acquireRelease(
      Effect.sync(() => postgres(props.connectionString)),
      (sql) => Effect.promise(() => sql.end()),
    );

    // ... create tables ...

+    const run = <A>(thunk: () => Promise<A>) =>
+      Effect.tryPromise({
+        try: thunk,
+        catch: (cause) =>
+          new StateStoreError({
+            message: cause instanceof Error ? cause.message : String(cause),
+            cause: cause instanceof Error ? cause : undefined,
+          }),
+      });
+
    const service: StateService = {
      id: "my-postgres",
      getVersion: () => Effect.succeed(STATE_STORE_VERSION),
      listStacks: () => Effect.die("not implemented"),
      listStages: () => Effect.die("not implemented"),
      list: () => Effect.die("not implemented"),
-      get: () => Effect.die("not implemented"),
-      set: () => Effect.die("not implemented"),
+      get: ({ stack, stage, fqn }) =>
+        run(
+          () => sql<{ value: string }[]>`
+            select value::text from alchemy_state
+            where stack = ${stack} and stage = ${stage} and fqn = ${fqn}
+          `,
+        ).pipe(
+          Effect.map((rows) =>
+            rows.length === 0
+              ? undefined
+              : JSON.parse(rows[0].value, reviveState),
+          ),
+        ),
+
+      set: ({ stack, stage, fqn, value }) =>
+        run(
+          () => sql`
+            insert into alchemy_state (stack, stage, fqn, value)
+            values (${stack}, ${stage}, ${fqn}, ${JSON.stringify(encodeState(value))}::jsonb)
+            on conflict (stack, stage, fqn)
+            do update set value = excluded.value
+          `,
+        ).pipe(Effect.as(value)),
+
      delete: () => Effect.die("not implemented"),
      deleteStack: () => Effect.die("not implemented"),
      getReplacedResources: () => Effect.die("not implemented"),
      getOutput: () => Effect.die("not implemented"),
      setOutput: () => Effect.die("not implemented"),
    };
    return service;
  });
```

## Implement `getOutput` and `setOutput`

After a deploy succeeds, Alchemy calls `setOutput` with the stack's
resolved output. [Cross-stack references](/infrastructure-as-code/references)
call `getOutput` to read it back. Return `undefined` when the stack
has no output at that stage (never deployed, or destroyed). The
output can hold the same non-JSON values as resource state, so encode
and revive it the same way:

```diff lang="typescript"
const service: StateService = {
  // ...

-  getOutput: () => Effect.die("not implemented"),
-  setOutput: () => Effect.die("not implemented"),
+  getOutput: ({ stack, stage }) =>
+    run(
+      () => sql<{ value: string }[]>`
+        select value::text from alchemy_stack_output
+        where stack = ${stack} and stage = ${stage}
+      `,
+    ).pipe(
+      Effect.map((rows) =>
+        rows.length === 0
+          ? undefined
+          : JSON.parse(rows[0].value, reviveState),
+      ),
+    ),
+
+  setOutput: ({ stack, stage, value }) =>
+    run(
+      () => sql`
+        insert into alchemy_stack_output (stack, stage, value)
+        values (${stack}, ${stage}, ${JSON.stringify(encodeState(value))}::jsonb)
+        on conflict (stack, stage)
+        do update set value = excluded.value
+      `,
+    ).pipe(Effect.as(value)),
};
```

## Implement `list`, `listStacks`, `listStages`

These power `alchemy destroy`, drift detection, and the CLI's
inspection commands. `list` returns the resource FQNs in one stage.
`listStacks` and `listStages` should also include stacks and stages
that only have an output row, so they `union` both tables:

```diff lang="typescript"
const service: StateService = {
-  listStacks: () => Effect.die("not implemented"),
-  listStages: () => Effect.die("not implemented"),
-  list: () => Effect.die("not implemented"),
+  listStacks: () =>
+    run(() => sql<{ stack: string }[]>`
+      select stack from alchemy_state
+      union
+      select stack from alchemy_stack_output
+      order by stack
+    `).pipe(Effect.map((rows) => rows.map((r) => r.stack))),
+
+  listStages: (stack) =>
+    run(() => sql<{ stage: string }[]>`
+      select stage from alchemy_state where stack = ${stack}
+      union
+      select stage from alchemy_stack_output where stack = ${stack}
+      order by stage
+    `).pipe(Effect.map((rows) => rows.map((r) => r.stage))),
+
+  list: ({ stack, stage }) =>
+    run(() => sql<{ fqn: string }[]>`
+      select fqn from alchemy_state
+      where stack = ${stack} and stage = ${stage} order by fqn
+    `).pipe(Effect.map((rows) => rows.map((r) => r.fqn))),
+
  // get / set / getOutput / setOutput unchanged ...
  delete: () => Effect.die("not implemented"),
  deleteStack: () => Effect.die("not implemented"),
  getReplacedResources: () => Effect.die("not implemented"),
};
```

## Implement `delete` and `deleteStack`

`delete` removes one resource record. `deleteStack` deletes the
entire stack when `stage` is omitted, or only one stage when
provided. It removes the stack output rows too, so a destroyed stack
no longer shows up in `listStacks`:

```diff lang="typescript"
const service: StateService = {
  // listStacks / listStages / list / get / set / getOutput / setOutput unchanged ...

-  delete: () => Effect.die("not implemented"),
-  deleteStack: () => Effect.die("not implemented"),
+  delete: ({ stack, stage, fqn }) =>
+    run(() => sql`
+      delete from alchemy_state
+      where stack = ${stack} and stage = ${stage} and fqn = ${fqn}
+    `).pipe(Effect.asVoid),
+
+  deleteStack: ({ stack, stage }) =>
+    run(() =>
+      stage === undefined
+        ? sql`delete from alchemy_state where stack = ${stack}`
+        : sql`delete from alchemy_state where stack = ${stack} and stage = ${stage}`,
+    ).pipe(
+      Effect.andThen(
+        run(() =>
+          stage === undefined
+            ? sql`delete from alchemy_stack_output where stack = ${stack}`
+            : sql`delete from alchemy_stack_output where stack = ${stack} and stage = ${stage}`,
+        ),
+      ),
+      Effect.asVoid,
+    ),
+
  getReplacedResources: () => Effect.die("not implemented"),
};
```

## Implement `getReplacedResources`

When Alchemy replaces a resource, it keeps the old one in the
record's `old` field. Once the new resource exists, the record's
status is `replaced` until the old one is deleted. `getReplacedResources` returns the records still in that
state so the next deploy can finish cleanup. A resource replaced
several times keeps the earlier generations in a nested `old` chain,
so return only the top-level records.

You can implement this on top of `list` + `get`, but it's cheaper to
push the filter into Postgres:

```diff lang="typescript"
const service: StateService = {
  // ...

-  getReplacedResources: () => Effect.die("not implemented"),
+  getReplacedResources: ({ stack, stage }) =>
+    run(
+      () => sql<{ value: string }[]>`
+        select value::text from alchemy_state
+        where stack = ${stack}
+          and stage = ${stage}
+          and value->>'status' = 'replaced'
+      `,
+    ).pipe(
+      Effect.map((rows) =>
+        rows.map((r) => JSON.parse(r.value, reviveState)),
+      ),
+    ),
};
```

## Plug it into a stack

Pass your layer as the `state` option, exactly like the built-in
stores:

```diff lang="typescript"
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Effect from "effect/Effect";
+import { myPostgresState } from "./src/postgres-state.ts";

export default Alchemy.Stack(
  "MyApp",
  {
    providers: Cloudflare.providers(),
-    state: Cloudflare.state(),
+    state: myPostgresState({
+      connectionString: process.env.DATABASE_URL!,
+    }),
  },
  Effect.gen(function* () {
    // resources...
  }),
);
```

Switching the `state` option does not move existing state. See
[Switching state stores](/state-store#switching-state-stores).

## Test the round-trip

Spin up a throwaway Postgres (Docker, Testcontainers, or a local
instance) and verify that a resource and a stack output round-trip
through your store. The test uses a double `yield*`. The first
resolves the `State` service to its `Effect<StateService>`
initializer. The second runs it to get the `StateService`.

The fixture is a real `ResourceState` record for a created resource.
`kind: "resource"` marks it as a resource (action records use
`kind: "action"`), and `status: "created"` requires both `props` and
`attr`:

```typescript
// test/postgres-state.test.ts
import { describe, expect, it } from "vitest";
import * as Effect from "effect/Effect";
import { State, type ResourceState } from "alchemy/State";
import { myPostgresState } from "../src/postgres-state.ts";

const layer = myPostgresState({
  connectionString: process.env.TEST_DATABASE_URL!,
});

const bucket: ResourceState = {
  kind: "resource",
  resourceType: "Cloudflare.R2.Bucket",
  namespace: undefined,
  fqn: "Bucket",
  logicalId: "Bucket",
  instanceId: "abc123",
  providerVersion: 0,
  status: "created",
  downstream: [],
  bindings: [],
  props: { name: "my-bucket" },
  attr: { name: "my-bucket" },
};

describe("myPostgresState", () => {
  it("round-trips a resource and a stack output", () =>
    Effect.gen(function* () {
      const state = yield* yield* State;

      yield* state.set({
        stack: "Test",
        stage: "dev",
        fqn: "Bucket",
        value: bucket,
      });

      const got = yield* state.get({
        stack: "Test",
        stage: "dev",
        fqn: "Bucket",
      });
      expect(got?.logicalId).toBe("Bucket");

      const fqns = yield* state.list({ stack: "Test", stage: "dev" });
      expect(fqns).toContain("Bucket");

      yield* state.setOutput({
        stack: "Test",
        stage: "dev",
        value: { url: "https://example.com" },
      });
      const output = yield* state.getOutput({ stack: "Test", stage: "dev" });
      expect(output).toEqual({ url: "https://example.com" });

      yield* state.deleteStack({ stack: "Test" });
      const after = yield* state.list({ stack: "Test", stage: "dev" });
      expect(after).toEqual([]);
      expect(yield* state.listStacks()).not.toContain("Test");
    }).pipe(Effect.provide(layer), Effect.scoped, Effect.runPromise));
});
```

For end-to-end testing of a real stack against your store, see
[Testing a Stack](/testing/testing-a-stack).

## Things to know

A few details that aren't obvious from the interface but matter in
production:

- **FQNs are arbitrary strings** containing `/` and other
  characters. Postgres handles them fine as parameterized values,
  but if your backend uses FQNs in keys (filenames, S3 keys, Redis
  keys) you'll need to escape them. Alchemy ships
  `encodeFqn` / `decodeFqn` from `alchemy/FQN`.
- **Concurrent writes happen** during a deploy as Alchemy applies
  resources in parallel. Your backend needs row-level (or
  equivalent) consistency on the `(stack, stage, fqn)` key.
- **Nothing stops two deploys of the same stage** from running at
  once with this store. The built-in `postgresState()` adds a
  per-`(stack, stage)` advisory lock. See
  [Concurrent deploys](/state-store#concurrent-deploys).
- **State persists between deploys**, so schema changes to
  `ResourceState` are effectively migrations. Be conservative with
  the encoded shape, and use `reviveState` so future Alchemy
  versions can deserialize what you wrote.

## Reference implementations

To start from one of the built-ins:

- [`LocalState.ts`](https://github.com/alchemy-run/alchemy/blob/main/packages/alchemy/src/State/LocalState.ts): filesystem-backed, the simplest end-to-end example

- [`InMemoryState.ts`](https://github.com/alchemy-run/alchemy/blob/main/packages/alchemy/src/State/InMemoryState.ts): minimal in-process map, useful as a template
