## Effect SQL

A provider binding supplies the connection string; the query stays ordinary SQL:

```typescript
import * as SQL from "alchemy/SQL/Postgres";

const sql = yield* SQL.Postgres({ url: connectionString });
const rows = yield* sql`SELECT id, name FROM users WHERE id = ${userId}`;
```

[Postgres](/sql/effect-sql/postgres), [MySQL](/sql/effect-sql/mysql), and [D1](/sql/effect-sql/d1) document their client setup.

## Drizzle

Use the same connection with your schema:

```typescript
import * as Drizzle from "alchemy/Drizzle/Postgres";
import { users } from "./schema.ts";

const db = yield* Drizzle.Postgres(connectionString);
const rows = yield* db.select().from(users);
```

See [Postgres](/sql/drizzle/postgres), [MySQL](/sql/drizzle/mysql), or [D1](/sql/drizzle/d1).

## Commit migrations before deployment

Generate and review SQL when the schema changes, then commit it with the schema:

```sh
pnpm exec drizzle-kit generate
git diff -- drizzle
git add src/schema.ts drizzle
git commit -m "Add schema migration"
```

Follow the provider's guide to apply the committed SQL and deploy the application. Use the [Drizzle migration guide](/sql/drizzle/migrations) for generated SQL, [Effect SQL migrations](/sql/effect-sql/migrations) for handwritten files, or the [Prisma migration workflow](/sql/prisma/migrations) for contracts.

## Connection lifecycle

```typescript
fetch: Effect.gen(function* () {
  const rows = yield* db.select().from(users);
  return yield* HttpServerResponse.json(rows);
});
```

Connections are acquired lazily for an execution and closed with its scope. See [Connection lifecycle](/sql/effect-sql/lifecycle) for handlers, workflows, and scoped queries.
