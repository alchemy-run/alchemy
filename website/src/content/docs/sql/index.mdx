Use SQL from a Lambda, Worker, container service, or an application you run
yourself. Choose a query client independently of where your application and
database are hosted. Alchemy provides database resources, runtime connection
bindings, and migration tooling; the available combination depends on the
database and runtime.

## Choose a client

| Client | Use it for | Guides |
| --- | --- | --- |
| Effect SQL | Tagged-template SQL with Effect errors and transactions | [Postgres](/sql/effect-sql/postgres), [MySQL](/sql/effect-sql/mysql), [D1](/sql/effect-sql/d1) |
| Drizzle | TypeScript schemas, query builders, and relational queries | [Postgres](/sql/drizzle/postgres), [MySQL](/sql/drizzle/mysql), [D1](/sql/drizzle/d1) |
| Prisma ORM v8 | PSL or TypeScript contracts with Effect-native queries | [Contracts](/sql/prisma/contracts), [Postgres](/sql/prisma/postgres) |

Prisma ORM v8 currently targets PostgreSQL 17+. A Postgres-compatible protocol
does not guarantee that every ORM feature or migration works on a particular
database. D1 is Cloudflare's SQLite-based database and uses its own binding.

## Already have a database?

Alchemy's SQL clients also accept a connection Effect. You can obtain the
redacted URL from configuration instead of provisioning the database with
Alchemy:

```typescript
import * as SQL from "alchemy/SQL/Postgres";
import * as Config from "effect/Config";
import * as Effect from "effect/Effect";

const query = Effect.gen(function* () {
  const sql = yield* SQL.Postgres({ url: Config.Redacted("DATABASE_URL") });
  return yield* sql`SELECT 1 AS value`;
});
```

Run database work in the scope supplied by your application's runtime, or use
`Effect.scoped` in a standalone program. Your application still needs network
access, database credentials, and the correct driver. See
[Connection lifecycle](/sql/effect-sql/lifecycle) for acquisition and cleanup.

## Manage schema changes

Schema generation and migration application are separate responsibilities.
Some database resources accept migrations directly; private databases may need
a migration runner inside their network. Follow your provider's integration
rather than assuming every database has a `migrations` property.

- [Effect SQL migrations](/sql/effect-sql/migrations) — hand-written SQL files.
- [Drizzle migrations](/sql/drizzle/migrations) — generate SQL from TypeScript schemas.
- [Prisma ORM migrations](/sql/prisma/migrations) — emit contracts and plan/apply migration packages.
