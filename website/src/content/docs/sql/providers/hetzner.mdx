Alchemy deploys application [Services](/hetzner/compute/services) to
Hetzner [Servers](/hetzner/compute/servers). The existing SQL example uses
**Neon Postgres as an external database**; it does not provision a managed
Hetzner Postgres product.

## Service + Neon + Drizzle

The [hetzner-website-vite example](https://github.com/alchemy-run/alchemy/tree/main/examples/hetzner-website-vite)
contains a Vite frontend and an Effect API Service. Its shared infrastructure
creates a Neon project and branch, supplies a database URL to the API, and
queries it with `Drizzle.Postgres`.

the hosting components rather than a separate SQL tutorial.

## Other database choices

Use an [existing Postgres or MySQL connection](/sql#already-have-a-database)
when your Service can reach it. Supply credentials only to the backend Service,
not browser-side Vite variables. The database's authentication, TLS, and
network policy still apply.

Running Postgres yourself on a Hetzner Server is a separate operational choice.
A Server or Volume resource does not by itself provide database backups,
replication, upgrades, or a managed SQL lifecycle. This page does not present
the external-Neon example as a self-managed database deployment.

## Before deploying

Choose nearby application/database regions, configure outbound connectivity,
and determine where migrations will execute. Keep application credentials in
the Service configuration and preserve TLS verification for remote databases.
Use the [connection lifecycle guide](/sql/effect-sql/lifecycle) for scoped
connections rather than sharing disposable clients across request scopes.

[Prisma ORM v8](/sql/prisma/contracts) requires PostgreSQL 17+ and its own
migration flow; the Drizzle example does not establish that combination's
runtime validation.
