Neon supplies the Postgres database. Choose the application runtime separately:
the examples below run on Cloudflare and Hetzner. Neon's project, branch,
connection, and migration documentation is shared across those integrations.

## Configure the database

Start with [Neon setup](/neon/setup), then choose a project and branch.
[Connection URLs](/neon/data/connections) distinguish direct and pooled
connections, while [branching](/neon/data/branching) covers preview databases.
The database URL belongs in your backend, not your browser application.

| Database task | Guide |
| --- | --- |
| Get a direct or pooled connection | [Connections](/neon/data/connections) |
| Apply SQL migrations | [Neon migrations](/neon/data/migrations) |
| Generate migrations with Drizzle | [Drizzle with Neon](/neon/guides/drizzle) |
| Create a branch per preview | [Preview branches](/neon/guides/preview-branches) |

runtime. Follow your host's packaging, secrets, and network requirements.

## Before deploying

Choose the connection endpoint for its purpose. Hyperdrive already supplies
pooling; the Cloudflare guide uses Neon's direct origin. Migration tools may
need a direct connection even when application queries use a pooled endpoint.
Keep schema generation separate from provider-specific migration application.

For [Prisma ORM v8](/sql/prisma/contracts), verify PostgreSQL 17+ and use
[Prisma migration packages](/sql/prisma/migrations). A Drizzle migration
resource is not a substitute for that contract-based workflow.
