AWS hosts both application runtimes and databases. Start with your runtime—
[Lambda](/aws/compute/lambda) or [ECS](/aws/compute/ecs)—then choose the
database and connection method. The integrations below describe Lambda;
ECS deployment and connection setup should not be assumed identical.

## Aurora PostgreSQL and Drizzle

Aurora PostgreSQL connections use the Postgres wire protocol. The application
needs network access to the cluster or proxy, a database user, and password
or IAM authentication. `AWS.RDS.Connect` supplies connection information;
`Drizzle.Postgres` consumes the URL Effect.

Start with the standalone example for a complete deployment. Its Data API
bootstrap uses deployment credentials; the application receives only a
restricted database login. Use the [Drizzle client guide](/sql/drizzle/postgres)
for the portable query API.

## Aurora DSQL

Aurora DSQL is a separate database with its own connection binding and SQL
restrictions. `AWS.DSQL.Connect` produces an IAM-authenticated connection URL.
It is not the same deployment as an Aurora PostgreSQL cluster in a VPC.

The [AWS full-stack Drizzle guide](/aws/frontend/full-stack-tanstack-rpc-drizzle)
shows Lambda + Drizzle + DSQL within a TanStack Start/RPC application. The
[DSQL connection suite](https://github.com/alchemy-run/alchemy/blob/main/packages/alchemy/test/AWS/DSQL/Connect.test.ts)
also contains deployment fixtures. These are distinct from a standalone
minimal example. The guide explains schema restrictions and its demonstration
bootstrap; do not assume a `migrations` property or general Prisma support.

## RDS Data API

The [RDS Data API](/aws/data/rds#the-data-api) runs SQL over HTTPS through
`AWS.RDSData` bindings. It does not return a socket connection for
`Drizzle.Postgres`. Choose the Data API intentionally rather than substituting
it into a connection-string example.

## Before deploying

- Configure [AWS credentials](/aws/setup), database access, and the runtime's permissions separately.
- For private clusters, ensure the Lambda and migration runner can reach the database. See [Networking](/aws/networking).
- Database IAM permission does not create a database user or grant SQL table privileges.
- Keep token generation lazy so a later invocation does not reuse an expired authentication token.
- Package the driver as required by the chosen Lambda integration; server runtimes do not automatically inherit Worker bundling behavior.
- Review costs, deletion behavior, and cleanup before provisioning Aurora.
