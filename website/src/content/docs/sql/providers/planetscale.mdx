PlanetScale provides both Postgres and MySQL/Vitess. Pick the database product
before choosing the driver, credentials, or migration flow; the two products
are not interchangeable variants of one connection API.

## Choose an application integration

The [Cloudflare Drizzle guide](/cloudflare/data/drizzle) shows a Worker with
Hyperdrive and includes PlanetScale Postgres wiring. The
[cloudflare-planetscale-postgres-drizzle example](https://github.com/alchemy-run/alchemy/tree/main/examples/cloudflare-planetscale-postgres-drizzle)
is the complete runnable project for that combination.

Other backends can use an accessible connection URL with the matching client:

- Postgres: [Effect SQL](/sql/effect-sql/postgres) or [Drizzle](/sql/drizzle/postgres).
- MySQL: [Effect SQL](/sql/effect-sql/mysql) or [Drizzle](/sql/drizzle/mysql).

These client links describe the API, not a verified deployment on every cloud.
Use your [runtime provider's guide](/sql#find-your-provider) for environment
binding, driver packaging, and connection lifetime.

## Before deploying

Choose the database branch and credentials deliberately, especially for
previews. Verify network access from both the application and the migration
runner. Follow the product-specific migration instructions rather than
assuming Postgres and Vitess accept identical schema changes.

Prisma ORM v8 currently supports PostgreSQL 17+ only, not PlanetScale's
MySQL/Vitess product. A Postgres connection URL alone does not establish
full Prisma migration/runtime compatibility for a given deployment.
