Choose either engine below, with `Planetscale.providers()` and `Cloudflare.providers()` registered in the [Stack](/planetscale/setup). The `migrations` prop explicitly opts into Alchemy-managed application: keep an existing `drizzle-kit migrate` workflow and omit that prop unless deliberately switching owners ([one-way adoption caveats](/sql/effect-sql/migrations#adopting-an-existing-database)).

## Postgres

**Resources — `src/Db.ts`, including branch credentials and the Hyperdrive origin.**

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import * as Planetscale from "alchemy/Planetscale";
import * as Effect from "effect/Effect";

export const Hyperdrive = Effect.gen(function* () {
  const database = yield* Planetscale.PostgresDatabase("Database", {
    region: { slug: "us-east" },
    clusterSize: "PS_10",
  });
  const branch = yield* Planetscale.PostgresBranch("App", {
    database,
    migrations: "./migrations",
  });
  const role = yield* Planetscale.PostgresRole("AppRole", {
    database,
    branch,
    inheritedRoles: ["postgres"],
  });
  return yield* Cloudflare.Hyperdrive.Connection("DatabaseConnection", {
    origin: role.origin,
    dev: role.pooledOrigin,
    caching: { disabled: true },
  });
});
```

**Binding — Cloudflare Worker runtime (`nodejs_compat`).**

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import * as Drizzle from "alchemy/Drizzle/Postgres";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";
import { Hyperdrive } from "./Db.ts";
import { Users } from "./schema.ts";

Effect.gen(function* () {
  const hd = yield* Cloudflare.Hyperdrive.Connect(Hyperdrive);
  const db = yield* Drizzle.Postgres(hd.connectionString);
  return {
    fetch: Effect.gen(function* () {
      const users = yield* db.select().from(Users);
      return yield* HttpServerResponse.json(users);
    }).pipe(Effect.orDie),
  };
}).pipe(Effect.provide(Cloudflare.Hyperdrive.ConnectBinding));
```

This `src/Api.ts` excerpt shows module imports and the Effect passed to [`Cloudflare.Worker`](/cloudflare/data/drizzle#open-the-connection-with-drizzlepostgres), configured with `compatibility.flags: ["nodejs_compat"]`.

**Migrations — on schema changes, using the [schema and generator configuration](/planetscale/guides/drizzle#define-the-schema): `dialect: "postgresql"`, `out: "./migrations"`.**

```sh
pnpm exec drizzle-kit generate
git add src/schema.ts drizzle.config.ts migrations
git diff --cached
git commit -m "Add Postgres migration"
pnpm alchemy deploy
```

Review and commit the schema, SQL, and snapshots before deploying; the configured branch applies those files transactionally without generating SQL. The [role's direct origin](/planetscale/data/postgres#origin-vs-pooledorigin) feeds Hyperdrive while the pooled origin is for local development; see [migration credentials and history](/planetscale/data/migrations).

## MySQL / Vitess

**Resources — alternative `src/Db.ts`, using a non-production branch and its password.**

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import * as Planetscale from "alchemy/Planetscale";
import * as Effect from "effect/Effect";

export const Hyperdrive = Effect.gen(function* () {
  const database = yield* Planetscale.MySQLDatabase("Database", {
    region: { slug: "us-east" },
    clusterSize: "PS_10",
  });
  const branch = yield* Planetscale.MySQLBranch("App", {
    database,
    isProduction: false,
    migrations: "./migrations",
  });
  const password = yield* Planetscale.MySQLPassword("AppPassword", {
    database,
    branch,
    role: "readwriter",
  });
  return yield* Cloudflare.Hyperdrive.Connection("DatabaseConnection", {
    origin: password.origin,
    caching: { disabled: true },
  });
});
```

**Binding — Cloudflare Worker runtime (`nodejs_compat`).**

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import * as Drizzle from "alchemy/Drizzle/MySQL";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";
import { Hyperdrive } from "./Db.ts";
import { Users } from "./schema.ts";

Effect.gen(function* () {
  const hd = yield* Cloudflare.Hyperdrive.Connect(Hyperdrive);
  const db = yield* Drizzle.MySQL(hd.connectionString);
  return {
    fetch: Effect.gen(function* () {
      const rows = yield* db.select().from(Users);
      return yield* HttpServerResponse.json(rows);
    }).pipe(Effect.orDie),
  };
}).pipe(Effect.provide(Cloudflare.Hyperdrive.ConnectBinding));
```

This alternative `src/Api.ts` excerpt shows module imports and the MySQL Effect passed to [`Cloudflare.Worker`](/cloudflare/data/drizzle#select-the-mysql-client), configured with `compatibility.flags: ["nodejs_compat"]`.

**Migrations — on schema changes, using a [MySQL schema and generator configuration](/sql/drizzle/mysql#define-the-schema): `dialect: "mysql"`, `out: "./migrations"`.**

```sh
pnpm exec drizzle-kit generate
git add src/schema.ts drizzle.config.ts migrations
git diff --cached
git commit -m "Add MySQL migration"
pnpm alchemy deploy
```

Generate MySQL SQL rather than reusing Postgres files, then review and commit the schema, SQL, and snapshots before deploying those files without generation. MySQL DDL can partially apply ([migration caveats](/planetscale/data/migrations#engine-differences)); prefer one schema change per file and consult [production branches and safe migrations](/planetscale/data/mysql#branch-the-database) before promoting changes.
