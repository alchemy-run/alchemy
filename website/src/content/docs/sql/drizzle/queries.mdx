`Drizzle.Postgres` and `Drizzle.D1` open a
[drizzle-orm](https://orm.drizzle.team) database whose queries are
Effects. Yield a query and you get typed rows; errors land in the
typed error channel; the connection follows the
[per-execution lifecycle](/sql/effect-sql/lifecycle).

Install `drizzle-orm` plus the driver for your database —
`@effect/sql-pg` and `pg` for Postgres, `@effect/sql-d1` for D1. All
are optional peers of alchemy.

## Open a client

Postgres takes a connection string — Hyperdrive's resolves from the
Worker environment at runtime:

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import * as Drizzle from "alchemy/Drizzle";
import * as Effect from "effect/Effect";
import { relations } from "./schema.ts";
import { Hyperdrive } from "./db.ts";

export default class Api extends Cloudflare.Worker<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const hd = yield* Cloudflare.Hyperdrive.Connect(Hyperdrive);
    const db = yield* Drizzle.Postgres(hd.connectionString, { relations });
    // ...
  }).pipe(Effect.provide(Cloudflare.Hyperdrive.ConnectBinding)),
) {}
```

D1 takes the `Cloudflare.D1.QueryDatabase` client instead:

```typescript
const d1 = yield* Cloudflare.D1.QueryDatabase(Database);
const db = yield* Drizzle.D1(d1, { relations });
```

Both are recipes at init — nothing connects until the first query of
an event, and plan/deploy never connect at all.

## Queries are Effects

Every builder yields directly:

```typescript
fetch: Effect.gen(function* () {
  const users = yield* db.select().from(Users);

  const [created] = yield* db
    .insert(Users)
    .values({ name, email })
    .returning();

  const [removed] = yield* db
    .delete(Users)
    .where(eq(Users.id, id))
    .returning();
}),
```

## Relational queries

Passing `relations` unlocks the typed `db.query.*` API:

```typescript
// schema.ts
export const relations = defineRelations({ Users, Posts }, (r) => ({
  Users: { posts: r.many.Posts() },
  Posts: { author: r.one.Users() },
}));

// handler
const user = yield* db.query.Users.findFirst({
  where: { id },
  with: { posts: true },
});
```

## Errors and transactions

Query failures are `SqlError` values in the error channel — catch
them with `Effect.catchTag`, or let them propagate as typed
failures.

On Postgres, wrap a group of queries in
`sql.withTransaction` using the client drizzle exposes as
`db.$client`. D1 has no session transactions; for atomic
multi-statement writes use the native binding's `batch` through
`Cloudflare.D1.QueryDatabase` — see
[driver differences](/sql/effect-sql/clients#driver-differences).

## Under the hood

`Drizzle.Postgres` drives drizzle's `effect-postgres` driver over
`@effect/sql-pg`; `Drizzle.D1` drives `effect-d1` over
`@effect/sql-d1`. They are the same clients documented in
[Clients](/sql/effect-sql/clients), reachable from your own layer
stack via [`SQL.PostgresLayer` / `SQL.D1Layer`](/sql/effect-sql/layers#two-tags-one-client)
when you want to assemble the pieces yourself.
