---
title: The migrationsDir contract
description: A directory of ordered .sql files is the one migration contract every alchemy database speaks — hand-written or generated, applied as part of deploy.
---

Every alchemy database resource applies migrations the same way: you
point `migrationsDir` at a directory of `.sql` files, and each
deploy applies the pending ones. The contract is deliberately plain —
it does not know or care whether the files were written by hand,
generated by [`Drizzle.Schema`](/sql/drizzle/migrations), or checked
in from `drizzle-kit generate`.

## The contract

- The directory is scanned recursively for `.sql` files.
- Files are ordered by numeric prefix (`0001_init.sql`,
  `0002_users.sql`), then by name. Nested layouts like
  `{timestamp}_migration/migration.sql` order by the directory's
  prefix.
- Each file is content-hashed. Applied files are recorded, so a
  deploy only runs what's new — an unchanged directory is a noop.
- Application is ordered and stops on the first failure; the failed
  file is retried on the next deploy.

## Hand-written migrations

No ORM required — commit `.sql` files and wire the directory in:

```typescript
const db = yield* Cloudflare.D1.Database("app-db", {
  migrationsDir: "./migrations",
});
```

```sql
-- migrations/0001_init.sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  email TEXT NOT NULL UNIQUE
);
```

The same prop exists on `Neon.Branch` and
`Planetscale.PostgresBranch`.

## Generated migrations

[`Drizzle.Schema`](/sql/drizzle/migrations) emits into the same
contract: its `out` output is a migrations directory, and passing it
as `migrationsDir` adds the dependency edge that orders generation
before application in one deploy:

```typescript
const schema = yield* Drizzle.Schema("app-schema", {
  schema: "./src/schema.ts",
  dialect: "sqlite",
});

const db = yield* Cloudflare.D1.Database("app-db", {
  migrationsDir: schema.out,
});
```

A future ORM integration targets this same contract — any tool that
writes ordered `.sql` files into a directory already works.

## Per-provider notes

Each database documents its own application mechanics — tracking
table, transactionality, and quirks:

| Database | Mechanics |
| --- | --- |
| Cloudflare D1 | [D1 migrations](/cloudflare/data/d1#migrations) — wrangler-compatible tracking table, `migrationsTable` for drizzle compatibility |
| Neon | [Neon migrations](/neon/data/migrations) — applied transactionally on the branch |
| PlanetScale | [PlanetScale migrations](/planetscale/data/migrations) — the same contract on Postgres and MySQL branches |
