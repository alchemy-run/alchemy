`SQL.MySQL` opens an `@effect/sql-mysql2` client (a connection pool)
from a connection URL. Queries are Effects: they carry `SqlError` in
the error channel, participate in interruption, and trace like
everything else in your program.

Install the driver — both are optional peers of alchemy:

## Connect

```typescript
import * as SQL from "alchemy/SQL/MySQL";
import * as Config from "effect/Config";
import * as Effect from "effect/Effect";

const listUsers = Effect.gen(function* () {
  const sql = yield* SQL.MySQL({ url: Config.Redacted("DATABASE_URL") });
  return yield* sql<{ id: number; name: string }>`SELECT id, name FROM users`;
});
```

The URL can be a redacted value or an Effect that resolves it, including a
runtime binding. Client options pass through to `@effect/sql-mysql2`.

The first query opens the pool in the current execution scope; later queries
reuse it until that scope closes. Alchemy runtimes provide the scope, while
standalone programs use `Effect.scoped`. See [Connection lifecycle](/sql/effect-sql/lifecycle).

## Connection options

```typescript
const sql = yield* SQL.MySQL({
  url: Config.Redacted("DATABASE_URL"),
  poolConfig: { ssl: { rejectUnauthorized: true } },
});
```

`SQL.MySQL` parses URL fields and query parameters into the driver configuration,
including `poolConfig`. Explicit configuration overrides detected defaults.

## Workers defaults

The [Hyperdrive guide](/cloudflare/data/hyperdrive#workers-defaults) documents
workerd's text-protocol and eval-free parser defaults. Direct connections from
Node or Bun retain prepared statements and mysql2's normal parsers by default.

## Queries

Interpolated values are parameters, never string concatenation:

```typescript
const user = yield* sql`SELECT * FROM users WHERE id = ${id}`;

yield* sql`INSERT INTO users ${sql.insert({ name, email })}`;

const rows = yield* sql`
  SELECT * FROM users WHERE id IN ${sql.in(ids)}
`;
```

Rows come back as plain objects typed by your annotation:
`sql<{ id: number; name: string }>\`...\``. The full statement API —
fragments, `sql.csv`, `sql.and`, identifier escaping (backticks on
MySQL) — is
[`effect/unstable/sql/Statement`](https://effect.website).

## Errors

Failures surface as `SqlError` in the typed error channel:

```typescript
const users = yield* sql`SELECT * FROM users`.pipe(
  Effect.catchTag("SqlError", (e) =>
    Effect.succeed([]).pipe(Effect.tap(() => Effect.logWarning(e))),
  ),
);
```

Uncaught, the error propagates like any Effect failure — no
try/catch, no unhandled rejection.

## Transactions

Wrap a group of queries in `sql.withTransaction` — the whole effect
commits or rolls back together:

```typescript
yield* sql.withTransaction(
  Effect.gen(function* () {
    yield* sql`UPDATE accounts SET balance = balance - ${amount} WHERE id = ${from}`;
    yield* sql`UPDATE accounts SET balance = balance + ${amount} WHERE id = ${to}`;
  }),
);
```

## Provide as a service

For services that shouldn't know which database they run on, depend
on the generic `SqlClient` tag and provide the database with
`SQL.MySQLLayer`:

```typescript
import * as SqlClient from "effect/unstable/sql/SqlClient";

const makeUsers = Effect.gen(function* () {
  const sql = yield* SqlClient.SqlClient;
  return {
    find: (id: number) => sql<User>`SELECT * FROM users WHERE id = ${id}`,
  };
});

const users = yield* makeUsers.pipe(
  Effect.provide(SQL.MySQLLayer({ url: Config.Redacted("DATABASE_URL") })),
);
```

The layer provides two tags from one per-execution pool: the generic
`SqlClient.SqlClient`, and `@effect/sql-mysql2`'s `MysqlClient` for
code that needs MySQL-specific capabilities — including drizzle's
`effect-mysql2` driver. Swapping `SQL.MySQLLayer` for
[`SQL.PostgresLayer`](/sql/effect-sql/postgres#provide-as-a-service)
or [`SQL.D1Layer`](/sql/effect-sql/d1#provide-as-a-service) reuses
the service interface. Check SQL syntax and database-specific behavior before
changing dialects.
