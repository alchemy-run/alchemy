---
title: Effect SQL clients
description: SQL.Postgres and SQL.D1 turn a connection string or D1 binding into an @effect/sql client — tagged-template queries with typed errors, built per execution.
---

`alchemy/SQL` wraps the `@effect/sql` drivers so a client resolves
once at init and connects lazily per execution. Queries are Effects:
they carry `SqlError` in the error channel, participate in
interruption, and trace like everything else in your program.

## SQL.Postgres

`SQL.Postgres` takes a pool config whose `url` may be a plain
`Redacted` string or an Effect of one — Hyperdrive's
`connectionString` resolves from the Worker environment at runtime,
so it slots straight in:

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import * as SQL from "alchemy/SQL";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";
import { Hyperdrive } from "./db.ts";

export default class Api extends Cloudflare.Worker<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const hd = yield* Cloudflare.Hyperdrive.Connect(Hyperdrive);
    const sql = yield* SQL.Postgres({ url: hd.connectionString });

    return {
      fetch: Effect.gen(function* () {
        const users = yield* sql`SELECT * FROM users`;
        return yield* HttpServerResponse.json({ users });
      }),
    };
  }).pipe(Effect.provide(Cloudflare.Hyperdrive.ConnectBinding)),
) {}
```

Everything else in `@effect/sql-pg`'s pool config passes through —
`maxConnections`, `idleTimeout`, `types`, and friends.

## SQL.D1

`SQL.D1` takes the client returned by
`Cloudflare.D1.QueryDatabase(db)` — or its `raw` effect directly —
and returns a `D1Client` over the native binding:

```typescript
import * as Cloudflare from "alchemy/Cloudflare";
import * as SQL from "alchemy/SQL";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/unstable/http/HttpServerResponse";
import { Database } from "./db.ts";

export default class Api extends Cloudflare.Worker<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const d1 = yield* Cloudflare.D1.QueryDatabase(Database);
    const sql = yield* SQL.D1(d1);

    return {
      fetch: Effect.gen(function* () {
        const users = yield* sql`SELECT * FROM users`;
        return yield* HttpServerResponse.json({ users });
      }),
    };
  }).pipe(Effect.provide(Cloudflare.D1.QueryDatabaseBinding)),
) {}
```

## Queries

Interpolated values are parameters, never string concatenation:

```typescript
const user = yield* sql`SELECT * FROM users WHERE id = ${id}`;

yield* sql`INSERT INTO users ${sql.insert({ name, email })}`;

const rows = yield* sql`
  SELECT * FROM users WHERE id IN ${sql.in(ids)}
`;
```

Rows come back as plain objects typed by your annotation:
`sql<{ id: number; name: string }>\`...\``. The full statement API —
fragments, `sql.csv`, `sql.and`, identifier escaping — is
[`effect/unstable/sql/Statement`](https://effect.website).

## Errors

Failures surface as `SqlError` in the typed error channel:

```typescript
const users = yield* sql`SELECT * FROM users`.pipe(
  Effect.catchTag("SqlError", (e) =>
    Effect.succeed([]).pipe(Effect.tap(() => Effect.logWarning(e))),
  ),
);
```

Uncaught, the error propagates like any Effect failure — no
try/catch, no unhandled rejection.

## Driver differences

| | `SQL.Postgres` | `SQL.D1` |
| --- | --- | --- |
| Transactions (`sql.withTransaction`) | yes | no |
| Streaming queries | yes | no |
| Prepared statements | pool-managed | cached per execution |

D1 has no session transactions; for atomic multi-statement writes use
the native binding's [`batch`](/cloudflare/data/d1#query-from-a-worker)
via `Cloudflare.D1.QueryDatabase`, which executes statements in one
atomic round trip.
