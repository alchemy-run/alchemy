This page shows the end-to-end pattern for integration-testing a deployed Stack against the real cloud. You deploy once in `beforeAll`, drive the live URL from Effect-aware tests, and optionally destroy the Stack in `afterAll`. [Test harness](/testing/test-harness) documents the harness API, and [Testing](/testing) explains the model. For cloud-specific step-by-step guides, see [Cloudflare Tutorial Part 3](/cloudflare/tutorial/part-3) and [AWS Tutorial Part 3](/aws/tutorial/part-3).

## Set up the harness

Configure Providers and state once per file. `Test.make` returns everything the file needs:

```typescript
import * as Alchemy from "alchemy";
import * as Cloudflare from "alchemy/Cloudflare";
import * as Drizzle from "alchemy/Drizzle";
import * as Neon from "alchemy/Neon";
import * as Test from "alchemy/Test/Bun";
import { expect } from "bun:test";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import Stack from "../alchemy.run.ts";

const { test, beforeAll, afterAll, deploy, destroy } = Test.make({
  providers: Layer.mergeAll(
    Cloudflare.providers(),
    Drizzle.providers(),
    Neon.providers(),
  ),
  state: Alchemy.localState(),
});
```

Switching between Bun and Vitest is a two-line import change. See [Bun vs Vitest](/testing/test-harness#bun-vs-vitest).

## Deploy once with beforeAll

`beforeAll(deploy(Stack))` deploys once for the whole file and returns a lazy accessor every test can `yield*`:

```typescript
const stack = beforeAll(deploy(Stack));

test(
  "worker returns a url",
  Effect.gen(function* () {
    const { url } = yield* stack;

    expect(url).toBeString();
  }),
);
```

The default hook timeout is 120s. Give slow stacks more time:

```typescript
// This stack deploys a Container whose image build + push can take
// well over the default 120s hook budget.
const stack = beforeAll(deploy(Stack), { timeout: 600_000 });
```

`beforeAll` accessors compose. You can seed data in a second `beforeAll` that tests `yield*` alongside the stack. See [Hooks](/testing/test-harness#hooks).

## Run it

Run the suite with your runner:

```sh
bun test test/integ.test.ts
```

The first run deploys. Re-runs diff and skip unchanged Resources. Tests default to the isolated `test_$USER` [stage](/environments/stages), so they never overwrite your `live_$USER` or `dev_$USER` deployments.

## Run it locally with dev mode

The same suite can run entirely on your machine. `dev: true` gives the file [`alchemy dev`](/environments/local-development) semantics. Workers, Durable Objects, KV, R2, D1, Queues, and Workflows run in workerd. AWS Lambda and its emulated services run in Docker. `deploy(Stack)` boots local simulators, and the `url` output points at `http://localhost:<port>`:

```typescript
const { test, beforeAll, afterAll, deploy, destroy } = Test.make({
  providers: Cloudflare.providers(),
  dev: true,
});
```

Every assertion below works unchanged against the local stack. To keep one file that runs locally on your laptop and live in CI, omit the flag and set `ALCHEMY_DEV=1` in your shell. See [Test harness → dev](/testing/test-harness#dev) for the full semantics and [Tutorial Part 4](/cloudflare/tutorial/part-4) for the walkthrough.

## Drive the live URL

`HttpClient` is already in scope in every test Effect:

```typescript
import * as HttpBody from "effect/unstable/http/HttpBody";
import * as HttpClient from "effect/unstable/http/HttpClient";

test(
  "PUT and GET round-trip an object",
  Effect.gen(function* () {
    const { url } = yield* stack;

    const put = yield* HttpClient.put(`${url}/hello.txt`, {
      body: HttpBody.text("Hello, World!"),
    });
    expect(put.status).toBe(201);

    const get = yield* HttpClient.get(`${url}/hello.txt`);
    expect(yield* get.text).toBe("Hello, World!");
  }),
);
```

[Test harness](/testing/test-harness#httpclient-is-in-scope) covers how the client is wired.

## Retry the first request

Fresh `workers.dev` URLs and Lambda Function URLs briefly return 404 or 5xx while routes, bindings, DNS, and IAM propagate. Retry the first request of each test to wait out this cold-start window:

```typescript
const { getWhenReady } = Test;

test(
  "worker answers once the edge converges",
  Effect.gen(function* () {
    const { url } = yield* stack;

    const response = yield* getWhenReady(url);
    expect(response.status).toBe(200);
  }),
);
```

`getWhenReady` retries only 404 and 5xx responses, and `executeWhenReady` does the same for arbitrary requests. The default is 20 attempts with exponential backoff starting at 500ms. Because only 404 and 5xx are retried, deliberate `400`, `401`, or `403` assertions observe those statuses immediately. For arbitrary effects, use a bounded manual retry:

```typescript
import * as Schedule from "effect/Schedule";

const response = yield* HttpClient.get(`${url}/health`).pipe(
  Effect.retry({ schedule: Schedule.exponential("500 millis"), times: 10 }),
);
```

## Poll async effects

Queues drain, workflows complete, and crons fire asynchronously. Never poll them with a deadline loop. Use a bounded declarative schedule:

```typescript
const status = yield* HttpClient.get(`${url}/workflow/status/${instanceId}`).pipe(
  Effect.flatMap((res) => res.json),
  Effect.map((body) => body as { status: string }),
  Effect.repeat({
    schedule: Schedule.spaced("2 seconds"),
    until: (s) => s.status === "complete",
    times: 30,
  }),
);
```

A bounded `times` fails fast and does not run into the runner timeout. `while (Date.now() < deadline)` loops ignore interruption.

## Tear down — or don't

Destroy the Stack on CI. Keep it alive locally for fast iteration:

```typescript
afterAll.skipIf(!!process.env.NO_DESTROY)(destroy(Stack)); // keep alive with NO_DESTROY=1
afterAll.skipIf(!process.env.CI)(destroy(Stack));          // destroy on CI only
```

Locally, the deployed Stack and cached state make re-runs near-instant. [Hooks](/testing/test-harness#hooks) describes hook semantics.

## Run against an existing deployment

If you already ran `alchemy deploy` and want to hit the URL, replace the deploy with a read of the outputs:

```typescript
const stack = beforeAll(
  process.env.SKIP_DEPLOY
    ? Effect.succeed({ url: process.env.STACK_URL! })
    : deploy(Stack),
);
```

## Share one Stack across files

Give every file's `Test.make` the same remote state and the same stage. With identical state and stage, the second file's `deploy(Stack)` is a no-op diff. The default `test_$USER` stage already does this for a single developer. Pin an explicit stage when files must share a stack across users or CI jobs:

```typescript
// test/api.integ.test.ts AND test/queue.integ.test.ts
const { test, beforeAll, afterAll, deploy, destroy } = Test.make({
  providers: Cloudflare.providers(),
  state: Cloudflare.state(), // remote, shared across files and runners
  stage: "shared",           // same stage → same Stack instance
});
```

See [State store](/state-store) for choosing a remote store.

## CI

Give every PR its own stage so suites run in parallel against one account:

```typescript
const { test, beforeAll, afterAll, deploy, destroy } = Test.make({
  providers: Cloudflare.providers(),
  stage: `pr-${process.env.PR_NUMBER}`,
});
```

The harness `deploy` and `destroy` never prompt for approval. `--yes` is only for CI workflows that invoke the CLI (`alchemy deploy --stage pr-42 --yes`). See [Stage](/testing/test-harness#stage) and the [CI guide](/environments/ci) for full workflow YAML.
