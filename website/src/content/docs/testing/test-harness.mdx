`alchemy/Test/Bun` and `alchemy/Test/Vitest` expose the same
Effect-aware harness. For the end-to-end walkthrough, see
[Testing a Stack](/testing/testing-a-stack). For provider-lifecycle
testing, see [Testing Providers](/testing/testing-providers).

## What Test.make returns

One call returns a self-contained API for the file:

```typescript
const { test, beforeAll, beforeEach, afterAll, afterEach, deploy, destroy } =
  Test.make({
    providers: Cloudflare.providers(),
  });
```

| Helper | Purpose |
|---|---|
| `test(name, effect, options?)` | Effect-aware test. `HttpClient` is in scope. |
| `test.skip` / `test.skipIf` / `test.only` / `test.todo` | Skip, focus, and todo modifiers (same shape as `bun.test`). |
| `test.provider(name, fn, options?)` | [Provider-lifecycle test](/testing/testing-providers) against a private scratch stack. |
| `beforeAll(effect)` | Run an Effect once. Returns a lazy accessor (`yield* result`) that tests can use. |
| `beforeEach(effect)` | Run an Effect before every test. |
| `afterAll(effect)` / `afterAll.skipIf(predicate)` | Cleanup hook with conditional teardown. |
| `afterEach(effect)` | Run an Effect after every test. |
| `deploy(Stack, opts?)` | Plan and apply a stack, then resolve to its outputs. |
| `destroy(Stack, opts?)` | Plan and apply against an empty desired state. |

Only `test.provider` bodies get the `providers` Layer, so SDK calls
such as `DynamoDB.describeTable` work there. In a plain `test` or
hook, `deploy(Stack)` uses the Stack's own providers, and any other
SDK call must provide the services it needs itself. The optional
`options` argument sets a per-test timeout. See [Timeouts](#timeouts).

`Test.getWhenReady`, `Test.executeWhenReady`, and the RPC transport
`Test.rpcClientLayer` are module-level helpers that ride out a fresh
URL's cold-start window. [Testing a Stack](/testing/testing-a-stack#retry-the-first-request)
covers them.

`expect` and `describe` come directly from the underlying runner,
`bun:test` or `@effect/vitest`.

## Test.make options

```typescript
Test.make({
  providers,   // required
  state,       // optional
  profile,     // optional
  stage,       // optional
  dev,         // optional — run the suite against local emulators
  adopt,       // optional
  sidecar,     // optional — defaults to dev
});
```

### `providers` (required)

The provider Layer that `test.provider` scratch stacks and test
bodies use to resolve resource implementations and SDK clients.
`deploy(Stack)` uses the providers declared on the Stack instead.
It is usually the same Layer your `Stack` uses:

```typescript
providers: Cloudflare.providers(),
// or merge multiple:
providers: Layer.mergeAll(Cloudflare.providers(), Stripe.providers()),
```

Credentials resolve through the same `AuthProviders` registry as
`alchemy deploy`, so tests pick up stored profiles or
the env-var auth methods registered by each provider.

### `state`

The state store that test bodies and hooks see when they
`yield* State`. Defaults to `localState()`, which stores state in
`.alchemy/` on disk. Most files leave it out.

`deploy(Stack)` and `destroy(Stack)` do not use this option. They
record state in the store declared on the Stack's own required
`state` option, which takes precedence. `test.provider` uses its own
scratch store.

```typescript
// alchemy.run.ts: the store deploy(Stack) and destroy(Stack) use
export default Alchemy.Stack(
  "MyApp",
  {
    providers: Cloudflare.providers(),
    state: Cloudflare.state(), // Durable Object-backed, shared across CI runners
  },
  Effect.gen(function* () { /* ... */ }),
);
```

The Stack's persistent store lets `deploy(Stack)` skip recreating
unchanged resources between runs. See [State store](/state-store)
for the available stores, and
[Testing a Stack](/testing/testing-a-stack#share-one-stack-across-files)
for sharing one deployment across files.

### `profile`

Override `ALCHEMY_PROFILE` for this file only. Use it to pin
tests to a sandbox profile regardless of what the environment
sets:

```typescript
Test.make({
  providers: AWS.providers(),
  profile: "test-sandbox",
});
```

When omitted, the harness reads `ALCHEMY_PROFILE` from env or `.env`
the same way the CLI does.

### `stage`

Default stage for `deploy(Stack)` / `destroy(Stack)`. Defaults to
`test_$USER` (e.g. `test_sam`) so two people running the same suite
against one account don't collide. Override it per file or per call:

```typescript
Test.make({ providers, stage: "ci-pr-42" });

// or per-call:
beforeAll(deploy(Stack, { stage: "ci-pr-42" }));
afterAll.skipIf(!process.env.CI)(destroy(Stack, { stage: "ci-pr-42" }));
```

A unique stage per PR or test run lets multiple suites run in
parallel against the same provider account without colliding.

When `stage` is omitted, the harness uses `ALCHEMY_TEST_STAGE` if it
is set. Otherwise it uses `test_$USER` (`$USERNAME` on Windows, or
`test_unknown` if neither is set). It does not read `ALCHEMY_STAGE`,
which is the CLI's deploy and dev stage. The env var isolates
concurrent CI jobs or worktrees without editing any file:

```sh
ALCHEMY_TEST_STAGE=pr-42 bun test
```

### `dev`

Off by default, so tests deploy to the real cloud. `dev: true` runs
the whole file in local-dev mode with the same wiring as
[`alchemy dev`](/environments/local-development). Cloudflare
Workers, Durable Objects, KV, R2, D1, Queues, and Workflows run in
workerd with local simulators. AWS Lambda/ECS and the emulated AWS
surface run in a local Docker emulator. Emulated resources do not
touch any cloud account.

```typescript
Test.make({
  providers: Cloudflare.providers(),
  dev: true,  // deploy(Stack) boots workerd / Docker simulators
});
```

The rest of the file stays the same. `beforeAll(deploy(Stack))`
boots the stack locally. The outputs (`url`, ids) point at the
local instances, so the same HTTP assertions run against
`http://localhost:<port>`. Local resource ids are `dev:`-prefixed,
which also proves no cloud call ran. `Alchemy.remote()` still
pins individual resources live, as it does under `alchemy dev`.

When omitted, the flag falls back to the `ALCHEMY_DEV` env var.
Leave it out of the file and set `ALCHEMY_DEV=1` locally to run the
same suite against emulators while CI runs it live. Separately,
`ALCHEMY_TEST_DEV=1` overrides the option in both directions.
Use it to force an entire existing suite through local providers
without editing each `Test.make`.

[Cloudflare local development](/cloudflare/local-development) and
[AWS local development](/aws/local-development) cover what each
cloud emulates. The step-by-step walkthrough is
[Cloudflare Tutorial Part 4](/cloudflare/tutorial/part-4).

### `adopt`

Engine-level adoption policy for the run. It matches the CLI's
`--adopt` flag. When `true`, a resource with no prior state whose
physical counterpart already exists in the cloud is adopted via
`provider.read` instead of failing. Defaults to `false`.

### `sidecar`

It only applies in dev mode and defaults to the resolved `dev` flag,
so dev tests run local providers behind the same RPC sidecar
process the real `alchemy dev` command uses. `sidecar: false` runs
them in-process. This helps when debugging provider code, since
no child process sits between you and the breakpoint.

## Hooks

### `beforeAll(effect) → Effect.Effect<A>`

Runs the Effect once before any test in the file. It stores the
result and returns a lazy accessor. `yield* accessor` inside any
test or other hook returns the resolved value:

```typescript
const stack = beforeAll(deploy(Stack));
const seed = beforeAll(Effect.gen(function* () {
  const { url } = yield* stack;
  yield* HttpClient.post(`${url}/seed`);
  return Date.now();
}));

test(
  "uses both",
  Effect.gen(function* () {
    const { url } = yield* stack;
    const startedAt = yield* seed;
    /* ... */
  }),
);
```

The second hook can `yield* stack` because hooks run in registration
order. It seeds data through the deployed stack's HTTP API because a
plain hook has no providers Layer in scope.

The default timeout is 120s. Override it with the second argument:

```typescript
beforeAll(deploy(Stack), { timeout: 300_000 });
```

### `beforeEach(effect)`

Runs the Effect before every test. It returns no accessor, so use
it for side-effect setup only (truncate a table, reset a feature
flag, …).

### `afterAll(effect)` and `afterAll.skipIf(predicate)`

Cleanup hook with conditional teardown:

```typescript
afterAll(destroy(Stack));                          // always destroy
afterAll.skipIf(!process.env.CI)(destroy(Stack));  // CI only
afterAll.skipIf(true)(destroy(Stack));             // never (debugging)
```

`afterAll.skipIf(true)` short-circuits without registering a
hook, so an `Effect` is never constructed and then dropped.

### `afterEach(effect)`

Runs after every test. Combine with `beforeEach` for
test-isolated fixtures.

## Test variants

```typescript
test.skip("not ready yet", Effect.gen(function* () { /* ... */ }));

test.skipIf(process.env.CI)(
  "local-only smoke test",
  Effect.gen(function* () { /* ... */ }),
);

test.only(
  "the one I'm debugging",
  Effect.gen(function* () { /* ... */ }),
);

test.todo("backfill once R2 has multipart helper");
```

`test.provider` mirrors the same shape. Its semantics are in
[Testing Providers](/testing/testing-providers):

```typescript
test.provider.skip(name, fn);
test.provider.skipIf(condition)(name, fn);
```

:::note[Vitest differences]
On Vitest, `test.only` is supported. `test.todo` is a stub that
maps to `it.todo`. `test.skip` / `test.skipIf` work identically.
:::

## Timeouts

`beforeAll` and `afterAll` default to 120s. `test`, `test.provider`,
`beforeEach`, and `afterEach` get no default from the harness, so
the runner's own default applies. Both `bun:test` and Vitest time
out a test after 5s. Vitest gives hooks 10s. A test that deploys
through `test.provider` or polls for longer than that fails with a
timeout.

Pass a timeout as the third argument:

```typescript
test(
  "waits for the queue to drain",
  Effect.gen(function* () { /* ... */ }),
  { timeout: 90_000 },
);

test.provider(
  "create, update, delete",
  (stack) => Effect.gen(function* () { /* ... */ }),
  { timeout: 180_000 },
);
```

On Bun the adapter types this argument as `bun.TestOptions`, so use
the object form. On Vitest a plain number (`90_000`) also works.
`beforeEach` and `afterEach` take the same options as their second
argument. To raise the default for a whole Bun run, pass
`bun test --timeout <ms>`.

## HttpClient is in scope

`HttpClient` is wired into every `test` Effect, so you can call
it directly:

```typescript
import * as HttpClient from "effect/unstable/http/HttpClient";

test(
  "health check",
  Effect.gen(function* () {
    const { url } = yield* stack;
    const res = yield* HttpClient.get(`${url}/health`);
    expect(res.status).toBe(200);
  }),
);
```

The implementation comes from
`effect/unstable/http/FetchHttpClient`, the same client the CLI
uses. For a full PUT/GET round-trip against a deployed stack,
see [Testing a Stack → Drive the live URL](/testing/testing-a-stack).

## Bun vs Vitest

The two adapters expose the same API:

```diff lang="typescript"
-import * as Test from "alchemy/Test/Bun";
-import { expect } from "bun:test";
+import * as Test from "alchemy/Test/Vitest";
+import { expect } from "@effect/vitest";

const { test, beforeAll, afterAll, deploy, destroy } = Test.make({
  providers: Cloudflare.providers(),
});
```

- **Bun** uses `bun:test` directly. Every `test(...)` becomes a
  `bun.test(...)` call wrapped with `Effect.runPromise`.
- **Vitest** uses `@effect/vitest`'s `it.live`, so tests stay
  Effect-aware. The `beforeAll`/`afterAll` default timeout is the
  same (120s).

Pick whichever runner your project already uses. The test code
does not change, with two small differences:

- On Vitest, a failed `test.provider` body still destroys its
  scratch stack. On Bun it does not, so wrap the body yourself. See
  [Cleanup when a test fails](/testing/testing-providers#cleanup-when-a-test-fails).
- On Vitest, a per-test timeout can be a plain number. On Bun it
  must be `{ timeout }`. See [Timeouts](#timeouts).
