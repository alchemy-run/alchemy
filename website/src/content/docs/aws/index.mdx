Amazon Web Services is the largest public cloud, with services for compute, storage, databases, networking, analytics, machine learning and security, in regions around the world.

Everything you create lives in an account and a region, and IAM decides what may call what. Most apps combine a handful of services: a place for code to run, like Lambda or ECS, and the S3 Buckets, DynamoDB Tables and SQS Queues it uses.

## A taste

A Queue is a declaration:

```typescript title="src/jobs.ts"
import * as AWS from "@alchemy.run/aws";

export const Jobs = AWS.SQS.Queue("Jobs");
```

A Lambda Function binds it and sends to it. The binding gives the Function `sqs:SendMessage` on that one Queue, and `SendMessageHttp` is the client that makes the call:

```typescript title="src/api.ts"
import * as AWS from "@alchemy.run/aws";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/http/HttpServerResponse";
import { Jobs } from "./jobs.ts";

export default class Api extends AWS.Lambda.Function<Api>()(
  "Api",
  { main: import.meta.url },
  Effect.gen(function* () {
    const send = yield* AWS.SQS.SendMessage(Jobs);
    return {
      fetch: send({ MessageBody: "hello" }).pipe(
        Effect.as(HttpServerResponse.text("queued")),
        Effect.orDie,
      ),
    };
  }).pipe(Effect.provide(AWS.SQS.SendMessageHttp)),
) {}
```

And the Stack deploys it to the account your profile signs in to:

```typescript title="alchemy.run.ts"
import * as Alchemy from "alchemy";
import * as AWS from "@alchemy.run/aws";
import * as Effect from "effect/Effect";
import Api from "./src/api.ts";

export default Alchemy.Stack(
  "MyApp",
  { providers: AWS.providers(), state: AWS.state() },
  Effect.gen(function* () {
    const api = yield* Api;
    return { url: api.functionUrl };
  }),
);
```

## Where to start

**New to AWS?** [What is AWS?](/aws/what-is-aws) walks through accounts, regions, IAM, runtimes, event sources, networks and the edge, once each, and shows how Alchemy models every one.

**Want to build one?** The [tutorial](/aws/tutorial/part-1) goes from a single Bucket to a Lambda Function with tests and CI, one step at a time. Start with [Setup](/aws/setup) to connect your account.

**Want the whole picture?** The chapters follow the shape of AWS itself. Start with where things live and who may touch them: [Accounts and regions](/aws/accounts-and-regions) and [IAM and bindings](/aws/iam). Then where code runs: [Choosing a runtime](/aws/compute/choosing-a-runtime), [Lambda](/aws/compute/lambda), [Lambda Web Functions](/aws/compute/web-functions), [ECS](/aws/compute/ecs), [EKS](/aws/compute/eks) and [EC2](/aws/compute/ec2). Then what it stores: [S3](/aws/data/s3), [DynamoDB](/aws/data/dynamodb) and [RDS & Aurora](/aws/data/rds). Then how work flows between them: [SQS](/aws/messaging/sqs), [SNS](/aws/messaging/sns), [Kinesis](/aws/messaging/kinesis) and [EventBridge](/aws/messaging/eventbridge). And finally how traffic reaches it and how you watch it: [VPC & networking](/aws/networking), [Custom domains](/aws/networking/custom-domains) and [CloudWatch](/aws/observability/cloudwatch).

**Building a website or an API?** [Websites](/aws/frontend/websites) covers static sites and every supported framework on S3 and CloudFront. [Effect HTTP API](/aws/apis/effect-http-api) and [Effect RPC](/aws/apis/effect-rpc) serve typed APIs from Lambda.

**Working offline?** [Local development](/aws/local-development) runs the whole Stack on your machine.

Every resource is in the generated [API reference](/providers), including the hundreds of services these chapters don't cover.
