---
title: Lambda Web Functions
description: Run an HTTP server on AWS Lambda Web Functions — an Effect fetch handler or any Node server, with streaming responses, many concurrent requests per environment, and a built-in HTTPS endpoint.
---

A **Lambda Web Function** runs your HTTP server on Lambda. Each execution
environment serves many requests at once (up to 128), responses stream to
the client as you produce them, and every function gets an HTTPS endpoint.
It scales to zero when idle.

Use it for anything that answers HTTP: APIs, server-rendered apps, AI
responses streamed token by token. For queues, streams, schedules, and
other event sources, use a [Lambda Function](/aws/compute/lambda).

:::caution
Web Functions run Node.js 24 on Arm64 and are available in `us-east-1`,
`us-east-2`, `us-west-2`, `eu-west-1`, and `ap-northeast-1`. Code ships
through the Alchemy assets bucket, so run `alchemy provider aws bootstrap`
once per account and Region.
:::

## Declare a Web Function

Create `src/api.ts` and return a `fetch` handler:

```typescript
// src/api.ts
import * as AWS from "alchemy/AWS";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/http/HttpServerResponse";

export default class Api extends AWS.Lambda.WebFunction<Api>()(
  "Api",
  { main: import.meta.url, authType: "ApplicationManaged" },
  Effect.gen(function* () {
    return {
      fetch: Effect.succeed(HttpServerResponse.text("Hello from Lambda!")),
    };
  }),
) {}
```

Your `fetch` handler runs on a Node HTTP server inside the Web Function, so
the same `effect/http` code you'd run anywhere else works unchanged.
`authType: "ApplicationManaged"` makes its endpoint public: every request
reaches your code.

## Deploy it

Yield the class in your Stack and return its `url`:

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as AWS from "alchemy/AWS";
import * as Effect from "effect/Effect";
import Api from "./src/api.ts";

export default Alchemy.Stack(
  "MyApp",
  {
    providers: AWS.providers(),
    state: AWS.state(),
  },
  Effect.gen(function* () {
    const api = yield* Api;
    return { url: api.url };
  }),
);
```

```sh
bun alchemy deploy
```

The `url` looks like `https://<id>.<shard>.lambda-web.us-west-2.on.aws`.
Every deploy publishes a new revision and moves all traffic to it.

## Stream a response

Return a streamed body and the client receives each chunk as soon as you
produce it:

```diff lang="typescript"
// src/api.ts
import * as AWS from "alchemy/AWS";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/http/HttpServerResponse";
+import * as Stream from "effect/Stream";

export default class Api extends AWS.Lambda.WebFunction<Api>()(
  "Api",
  { main: import.meta.url, authType: "ApplicationManaged" },
  Effect.gen(function* () {
    return {
-      fetch: Effect.succeed(HttpServerResponse.text("Hello from Lambda!")),
+      fetch: Effect.succeed(
+        HttpServerResponse.stream(
+          Stream.make("Hello", " from", " Lambda!").pipe(
+            Stream.tap(() => Effect.sleep("200 millis")),
+            Stream.encodeText,
+          ),
+          { contentType: "text/plain" },
+        ),
+      ),
    };
  }),
) {}
```

## Use AWS resources

Bindings work the same as on a Lambda Function. Binding an operation
grants the function's role exactly that permission:

```diff lang="typescript"
// src/api.ts
import * as AWS from "alchemy/AWS";
import * as Effect from "effect/Effect";
import * as HttpServerResponse from "effect/http/HttpServerResponse";

export default class Api extends AWS.Lambda.WebFunction<Api>()(
  "Api",
  { main: import.meta.url, authType: "ApplicationManaged" },
  Effect.gen(function* () {
+    const bucket = yield* AWS.S3.Bucket("Uploads");
+    const putObject = yield* AWS.S3.PutObject(bucket);
    return {
-      fetch: Effect.succeed(HttpServerResponse.text("Hello from Lambda!")),
+      fetch: Effect.gen(function* () {
+        yield* putObject({ Key: "hello.txt", Body: "Hello!" });
+        return HttpServerResponse.text("Saved");
+      }).pipe(Effect.orDie),
    };
-  }),
+  }).pipe(Effect.provide(AWS.S3.PutObjectHttp)),
) {}
```

## Bring an existing server

You don't need Effect. Point `main` at a module that default-exports a
`fetch` method, the shape Hono and Cloudflare Workers use:

```typescript
// src/server.ts
export default {
  async fetch(request: Request) {
    return new Response(`Hello from ${new URL(request.url).pathname}`);
  },
};
```

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as AWS from "alchemy/AWS";
import * as Effect from "effect/Effect";

export default Alchemy.Stack(
  "MyApp",
  { providers: AWS.providers(), state: AWS.state() },
  Effect.gen(function* () {
    const api = yield* AWS.Lambda.WebFunction("Api", {
      main: "./src/server.ts",
      authType: "ApplicationManaged",
    });
    return { url: api.url };
  }),
);
```

A server that listens on its own works too. Listen on `PORT` and `HOST`,
which Alchemy sets to the address Lambda expects:

```typescript
// src/server.ts
import express from "express";

const app = express();
app.get("/", (_req, res) => res.send("Hello from Express"));
app.listen(Number(process.env.PORT), process.env.HOST!);
```

For a framework's standalone build output, set `bundle: false` to deploy
the directory as it is:

```typescript
const site = yield* AWS.Lambda.WebFunction("Site", {
  main: "./.output/server/index.mjs",
  bundle: false,
  authType: "ApplicationManaged",
});
```

## Tune concurrency and traffic

Set how many requests one environment serves, the per-request timeout,
and caps on environments and requests per second:

```typescript
const api = yield* AWS.Lambda.WebFunction("Api", {
  main: "./src/server.ts",
  authType: "ApplicationManaged",
  maxConcurrencyPerEnvironment: 128,
  timeout: Duration.minutes(5),
  maxEnvironments: 10,
  rateLimit: 500,
});
```

`maxConcurrencyPerEnvironment` is a cap per environment, not a total: at
most `maxEnvironments × maxConcurrencyPerEnvironment` requests are in
flight. Lower it for CPU-heavy servers. Requests beyond `rateLimit` get
HTTP 429.

Each environment has 2 GB of memory and 2 vCPUs, and you can't change
that. Node's heap defaults to 1 GB; raise it with
`env: { NODE_OPTIONS: "--max-old-space-size=1536" }`.

## Serve from several Regions

List extra Regions to get one global domain that routes each request to
the nearest Region:

```typescript
const api = yield* AWS.Lambda.WebFunction("Api", {
  main: "./src/server.ts",
  authType: "ApplicationManaged",
  regions: ["us-east-1", "eu-west-1"],
});
```

Changing `regions` gives the endpoint a new URL.

## Require signed requests

Set `authType: "IamAuth"` to accept only SigV4-signed requests from
callers allowed to call `lambda:InvokeWebFunctionEndpoint`, such as a
CloudFront distribution:

```typescript
const internal = yield* AWS.Lambda.WebFunction("Internal", {
  main: "./src/server.ts",
  authType: "IamAuth",
});
```

## Reach private resources

Set `vpc` to send the server's outbound traffic through your VPC, for
example to reach a database in private subnets:

```typescript
const api = yield* AWS.Lambda.WebFunction("Api", {
  main: "./src/server.ts",
  authType: "ApplicationManaged",
  vpc: {
    subnetIds: network.privateSubnetIds,
    securityGroupIds: [appSg.groupId],
  },
});
```

Use at least two subnets in different Availability Zones, and allow the
security group on the database. Private subnets need a NAT gateway to
reach the internet. A function with `vpc` can't also use `regions`.

## Add another endpoint

Each endpoint is a separate way in, with its own URL, auth, and limits.
Add one with `WebFunctionEndpoint`, for example a public endpoint for
webhooks next to a private one:

```typescript
const api = yield* AWS.Lambda.WebFunction("Api", {
  main: "./src/server.ts",
  authType: "IamAuth",
  maxEnvironments: 50,
});

const webhooks = yield* AWS.Lambda.WebFunctionEndpoint("Webhooks", {
  function: api,
  authType: "ApplicationManaged",
  rateLimit: 100,
  maxEnvironments: 2,
});
```

`api.url` is the function's own endpoint and `webhooks.url` is the new
one. Both serve the same code and follow every deploy, but each scales on
its own, so a webhook burst can't use up the other endpoint's capacity.

For a Web Function declared as a class, like `Api` above, pass the class
itself:

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as AWS from "alchemy/AWS";
import * as Effect from "effect/Effect";
import Api from "./src/api.ts";

export default Alchemy.Stack(
  "MyApp",
  { providers: AWS.providers(), state: AWS.state() },
  Effect.gen(function* () {
    const api = yield* Api;
    const webhooks = yield* AWS.Lambda.WebFunctionEndpoint("Webhooks", {
      function: Api,
      authType: "ApplicationManaged",
    });
    return { url: api.url, webhooks: webhooks.url };
  }),
);
```

Your server sees which endpoint a request came through in the
`lambda-web-endpoint-name` header. Use it to keep each endpoint to its own
routes:

```typescript
// src/server.ts
export default {
  async fetch(request: Request) {
    const endpoint = request.headers.get("lambda-web-endpoint-name");
    const { pathname } = new URL(request.url);
    if (endpoint === "Webhooks" && !pathname.startsWith("/webhooks/")) {
      return new Response("Not Found", { status: 404 });
    }
    return new Response("ok");
  },
};
```

## Shutdown

Lambda stops idle environments with `SIGTERM` and gives them 1 second.
In-flight responses finish first, then init-level finalizers run, so keep
them short.
